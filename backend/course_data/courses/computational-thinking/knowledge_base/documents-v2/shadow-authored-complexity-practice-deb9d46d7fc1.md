## 真实问题情境
某电商平台每日产生海量订单日志，需开发一个脚本检测“异常重复订单”。系统要求：给定一个包含订单 ID 的列表，找出所有重复出现的 ID。若数据量较小（<1000），简单方法即可；但若数据量达到百万级（$10^6$），必须考虑算法效率，否则处理任务将超时。

## 输入输出与材料
**输入**：一个整数列表 `order_ids`，长度记为 $n$。
**输出**：一个包含所有重复 ID 的列表（不含重复项）。
**材料**：Python 运行环境，可生成随机数据的辅助函数。
```python
import random
def generate_data(n, duplicate_rate=0.1):
    base = list(range(n))
    duplicates = random.sample(base, int(n * duplicate_rate))
    return base + duplicates  # 制造重复
```

## 参考实现与推导
**方案 A（暴力法）**：
```python
def find_duplicates_naive(ids):
    duplicates = []
    for i in range(len(ids)):
        for j in range(i + 1, len(ids)):
            if ids[i] == ids[j] and ids[i] not in duplicates:
                duplicates.append(ids[i])
    return duplicates
```
**复杂度推导**：外层循环 $n$ 次，内层循环平均 $n/2$ 次，且 `not in duplicates` 在最坏情况下需遍历结果列表。总体接近 $O(n^2)$ 甚至更高。

**方案 B（哈希集合法）**：
```python
def find_duplicates_optimized(ids):
    seen = set()
    duplicates = set()
    for id in ids:
        if id in seen:
            duplicates.add(id)
        else:
            seen.add(id)
    return list(duplicates)
```
**复杂度推导**：遍历列表一次 $O(n)$。集合的 `in` 操作和 `add` 操作平均时间复杂度为 $O(1)$。总时间复杂度为 $O(n)$。空间复杂度为 $O(n)$，用于存储 `seen` 集合。

## 测试与边界情况
为确保代码健壮性，必须覆盖以下测试用例：
1. **空列表**：输入 `[]`，预期输出 `[]`，程序不崩溃。
2. **无重复**：输入 `[1, 2, 3]`，预期输出 `[]`。
3. **全重复**：输入 `[1, 1, 1]`，预期输出 `[1]`（顺序不限）。
4. **大规模数据**：输入 $10^6$ 级数据，方案 B 应在秒级完成，方案 A 应显著超时或极慢。
5. **数据类型**：验证是否支持字符串 ID（如 "ORD-001"），上述代码均支持。
