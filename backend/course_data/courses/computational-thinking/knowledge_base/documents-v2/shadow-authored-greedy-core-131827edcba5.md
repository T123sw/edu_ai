## 学习目标
1. 理解贪心算法的核心思想：通过局部最优选择期望达到全局最优。
2. 掌握贪心策略适用的两个关键条件：贪心选择性质与最优子结构。
3. 学会使用“交换论证”思想简单验证贪心策略的正确性。
4. 能够识别不适用贪心算法的问题场景，避免盲目套用。

## 概念与边界
贪心算法（Greedy Algorithm）是指在每一步选择中都采取在当前状态下最好或最优（即最有利）的选择，从而希望导致结果是最好或最优的算法。其核心在于“短视”，即不考虑子问题的求解结果对以后子问题的影响，仅关注当前利益最大化。

然而，局部最优并不总能导致全局最优。贪心算法适用的问题必须具备以下两个关键性质：
1. **贪心选择性质**：所求问题的整体最优解可以通过一系列局部最优的选择来达到。这意味着，当我们做出贪心选择时，不需要考虑子问题的解，因为当前的选择已经包含了通往最优解的路径。
2. **最优子结构**：当一个问题的最优解包含其子问题的最优解时，称此问题具有最优子结构性质。

**边界说明**：若问题具有最优子结构但不具备贪心选择性质（如 0/1 背包问题），则不能使用贪心算法，通常需采用动态规划。若问题既无贪心选择性质也无最优子结构，则可能需要搜索或近似算法。

## 算法机制与步骤
贪心算法的求解过程通常遵循以下迭代步骤：
1. **建立数学模型**：将问题抽象为可通过序列决策求解的形式。
2. **确定贪心策略**：定义什么是“当前最优”，例如“结束时间最早”、“单位价值最高”等。
3. **迭代选择**：从初始状态出发，依据策略选择一个局部最优解，并将原问题简化为规模更小的子问题。
4. **可行性检查**：确保当前选择满足约束条件。
5. **终止条件**：当子问题为空或无法继续选择时停止，汇总所有选择作为解。

伪代码框架如下：
```python
def greedy_solve(problem_data):
    solution = []
    while not is_solved(problem_data):
        choice = select_best_local_option(problem_data)
        if is_feasible(choice, solution):
            solution.append(choice)
            problem_data = reduce_problem(problem_data, choice)
        else:
            discard(choice)
    return solution
```

## 经典案例：区间调度问题
**问题描述**：给定一组任务，每个任务有开始时间 $s_i$ 和结束时间 $f_i$。任务之间若时间重叠则不能同时进行。目标是选择尽可能多的互不冲突的任务。

**贪心策略**：每次选择**结束时间最早**且与已选任务不冲突的任务。
**直觉**：结束越早，留给后续任务的时间资源越多。

**算法实现**：
```python
def interval_scheduling(tasks):
    # tasks 为列表，元素为 (start, finish)
    # 按结束时间升序排序
    tasks.sort(key=lambda x: x[1])
    
    selected = []
    last_finish_time = -float('inf')
    
    for start, finish in tasks:
        if start >= last_finish_time:
            selected.append((start, finish))
            last_finish_time = finish
            
    return selected
```

## 正确性证明思路：交换论证
为何“结束最早”策略是正确的？我们使用**交换论证（Exchange Argument）**。
假设贪心算法产生的解为 $G = \{g_1, g_2, ..., g_k\}$，按结束时间排序。假设存在一个最优解 $O = \{o_1, o_2, ..., o_m\}$，也按结束时间排序。
1. 若 $k=m$ 且 $G=O$，则贪心解即为最优。
2. 若 $G \neq O$，设 $r$ 是第一个不相同的位置，即 $g_1=o_1, ..., g_{r-1}=o_{r-1}$，但 $g_r \neq o_r$。
3. 由于贪心策略选择的是结束时间最早的任务，必然有 $finish(g_r) \le finish(o_r)$。
4. 我们可以用 $g_r$ 替换 $o_r$ 构造一个新的解 $O' = \{o_1, ..., o_{r-1}, g_r, o_{r+1}, ..., o_m\}$。
5. 因为 $g_r$ 结束得更早，它不会与 $o_{r+1}$ 冲突（原 $o_r$ 都不冲突，$g_r$ 更不可能冲突）。
6. 因此 $O'$ 也是一个最优解，且与 $G$ 的前 $r$ 项一致。重复此过程，最终可将 $O$ 转换为 $G$，证明 $G$ 也是最优解。

## 复杂度与权衡
- **时间复杂度**：主要消耗在排序上，为 $O(N \log N)$，其中 $N$ 为任务数量。后续遍历为 $O(N)$。
- **空间复杂度**：$O(1)$ 或 $O(N)$，取决于是否存储结果。
- **权衡**：贪心算法效率极高，但适用范围窄。在设计算法时，应优先尝试验证贪心策略的正确性。若无法证明或发现反例，应及时转向动态规划，以免陷入局部最优陷阱。

## 常见误区
1. **盲目贪心**：认为所有最优化问题都能用贪心解决。例如在 0/1 背包问题中，按“单位重量价值”贪心选择往往得不到最优解。
2. **策略混淆**：在同一问题中存在多种贪心策略（如区间调度中可选“开始最早”、“持续时间最短”、“结束最早”），仅有一种通常正确，需严格验证。
3. **忽略约束**：在选择局部最优时忘记检查是否满足全局约束条件（如资源限制）。

## 自测题与答案
**题目**：设有任务集合 [(1, 4), (3, 5), (0, 6), (5, 7), (8, 9), (5, 9)]，括号内为 (开始，结束)。
1. 若采用“持续时间最短”策略，会选择哪些任务？数量是多少？
2. 若采用“结束时间最早”策略，会选择哪些任务？数量是多少？
3. 哪种策略得到了全局最优解？

**答案**：
1. 持续时间排序：(1,4)[3], (3,5)[2], (5,7)[2], (0,6)[6], (5,9)[4], (8,9)[1]。
   选 (8,9)，剩余可选 (3,5) 或 (5,7)。若选 (3,5)，冲突 (1,4)。若选 (5,7)，冲突 (3,5)。
   典型路径可能选 (8,9), (5,7), (3,5) -> 冲突。正确贪心执行：选 (8,9)，剩 (5,7) 可行，剩 (3,5) 与 (5,7) 冲突。
   实际上“持续时间最短”策略在此例易出错，可能选 (8,9), (5,7), (1,4) 共 3 个，或 (8,9), (3,5) 共 2 个。此策略不保证最优。
2. 结束时间排序：(1,4), (3,5), (0,6), (5,7), (5,9), (8,9)。
   选 (1,4)，排除 (3,5), (0,6)。
   选 (5,7)，排除 (5,9)。
   选 (8,9)。
   结果：[(1,4), (5,7), (8,9)]，数量 3。
3. “结束时间最早”策略得到 3 个，为全局最优。此例验证了不同贪心策略效果不同，需依据理论选择。
