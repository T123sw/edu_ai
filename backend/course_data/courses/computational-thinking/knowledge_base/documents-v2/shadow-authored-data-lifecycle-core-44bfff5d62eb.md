## 学习目标
1. 理解数据生命周期的各个阶段及其核心任务。
2. 掌握“问题驱动”分析方法的逻辑流程，区别于单纯的“数据堆积”。
3. 能够识别数据分析过程中的常见逻辑谬误与伦理权衡。

## 准确概念与边界
**数据生命周期**是指数据从产生到销毁的全过程，通常包含六个阶段：生成（Generation）、采集（Collection）、处理（Processing）、分析（Analysis）、解释（Interpretation）与归档/销毁（Archiving/Destruction）。在计算思维中，我们重点关注“采集”到“解释”的闭环。

**问题驱动分析**强调分析活动必须始于明确的业务问题或科学假设，而非始于手头现有的数据。其边界在于：若分析结果无法回扣到初始问题或无法指导决策，则视为无效分析。这与“数据驱动”（有什么数据算什么）形成对比，前者注重目的性，后者注重可能性。

## 机制与步骤
问题驱动的数据分析遵循以下标准流程：
1. **定义问题**：将模糊的需求转化为可验证的假设。例如，将“提高成绩”转化为“睡眠时长是否与 GPA 正相关”。
2. **数据映射**：确定验证假设所需的变量及其来源。
3. **采集与清洗**：获取数据并处理缺失值、异常值。
4. **探索性分析**：使用统计量或可视化发现模式。
5. **解释与验证**：将数据模式转化为自然语言结论，并检查因果倒置等逻辑错误。

## 完整示例
**场景**：某课程助教希望验证“课后作业完成时长”是否影响“期末考试成绩”。
**假设**：$H_0$: 作业时长与成绩无关；$H_1$: 作业时长与成绩正相关。
**数据**：5 名学生的抽样数据（时长小时，成绩百分制）：$(2, 60), (3, 65), (5, 80), (8, 85), (10, 88)$。
**分析**：观察趋势，计算相关系数。
**解释**：数据显示正相关，但需注意样本量过小，可能存在“学习能力强导致做得快且分高”的混淆变量。

## 代码实现
以下 Python 代码演示了基本的计算逻辑：
```python
def analyze_correlation(time_list, score_list):
    n = len(time_list)
    if n == 0: return 0
    mean_t = sum(time_list) / n
    mean_s = sum(score_list) / n
    numerator = sum((t - mean_t) * (s - mean_s) for t, s in zip(time_list, score_list))
    denom_t = sum((t - mean_t) ** 2 for t in time_list) ** 0.5
    denom_s = sum((s - mean_s) ** 2 for s in score_list) ** 0.5
    if denom_t * denom_s == 0: return 0
    return numerator / (denom_t * denom_s)

# 测试数据
times = [2, 3, 5, 8, 10]
scores = [60, 65, 80, 85, 88]
r = analyze_correlation(times, scores)
print(f"相关系数：{r:.2f}")
```

## 权衡与复杂度
在数据生命周期中，主要存在以下权衡：
1. **精度与成本**：高精度传感器采集的数据更准确，但存储和计算成本呈 $O(N)$ 增长。
2. **隐私与效用**：脱敏处理保护隐私，但可能丢失关键关联信息（如移除地理位置导致无法分析区域偏好）。
3. **时效性与完整性**：实时分析要求低延迟，往往需要牺牲部分数据清洗步骤，可能引入噪声。

## 常见误区
1. **相关即因果**：数据显示冰淇淋销量与溺水事故正相关，实则是夏季高温这一混淆变量导致，而非冰淇淋导致溺水。
2. **数据客观论**：认为数据本身不含偏见。实际上，采集样本的选择（如仅调查在线用户）会引入选择偏差。
3. **过度拟合**：在解释阶段，为匹配数据而构建过于复杂的理论，导致泛化能力差。

## 自测题与答案
1. **问**：在数据生命周期中，哪个阶段决定了分析的伦理边界？
   **答**：采集阶段（涉及隐私授权）与解释阶段（涉及结论的社会影响）。
2. **问**：若相关系数 $r=0$，是否意味着两个变量完全独立？
   **答**：不一定，仅意味着无线性相关，可能存在非线性关系。
3. **问**：问题驱动分析的第一步是什么？
   **答**：定义问题或提出假设，而非收集数据。
