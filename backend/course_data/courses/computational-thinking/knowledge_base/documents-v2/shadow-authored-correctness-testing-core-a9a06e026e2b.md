## 学习目标
本讲义旨在帮助学生建立关于程序正确性的严谨认知，掌握系统性测试方法与科学调试流程。学习完成后，学生应能区分“验证”与“确认”的差异，理解边界条件对正确性的影响，并能独立设计测试用例以暴露潜在缺陷，而非仅用于证明程序无误。

## 准确概念与边界
**正确性（Correctness）** 指程序行为严格符合形式化规约的程度。在理论计算机科学中，完全正确性需通过数学证明（如霍尔逻辑）确立，满足前置条件 $P$ 执行后必满足后置条件 $Q$。然而在实际工程中，我们通常依赖**测试（Testing）** 这一经验主义手段来评估正确性。测试的本质是证伪，即试图发现错误，而非证明无错。正如 Dijkstra 所言：“测试只能显示 bug 的存在，而不能显示 bug 的不存在。”

**调试（Debugging）** 是在测试发现失败后，定位错误根源并修复的过程。它不同于测试，测试是发现问题，调试是解决问题。

**边界（Boundary）** 指输入域中等价类的边缘值。大多数错误发生在输入空间的边界上，例如循环的起止点、数组的首尾索引、数值类型的最大最小值。边界值分析是测试设计的核心策略。

## 机制与步骤
### 1. 测试设计机制
有效的测试遵循“等价类划分”与“边界值分析”原则。
- **等价类划分**：将输入域划分为若干子集，认为同一子集内的数据测试效果等效。
- **边界值分析**：针对每个等价类的边缘选取测试点。若输入范围为 $[a, b]$，则重点测试 $a, b, a-1, b+1$ 等点。

### 2. 调试循环步骤
调试是一个假设 - 验证的循环过程：
1.  **复现**：确保能稳定重现错误现象。
2.  **定位**：通过日志、断点或二分法缩小错误代码范围。
3.  **假设**：提出导致错误的根本原因假设。
4.  **修复**：修改代码以消除原因。
5.  **回归**：运行原有测试集，确保修复未引入新错误。

## 完整示例：二分查找中的边界陷阱
以下 Python 代码试图在有序列表 `arr` 中查找目标值 `target`。这是一个典型的边界敏感场景。

```python
def binary_search(arr, target):
    low = 0
    high = len(arr) - 1
    # 错误点：循环条件若为 low < high，可能漏掉最后一个元素
    while low <= high: 
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1
```
**正确性分析**：
若循环条件写为 `while low < high`，当搜索范围缩小至只有一个元素（`low == high`）时，循环会提前终止，导致漏检。此外，计算 `mid` 时若 `low + high` 超出整数范围可能溢出（虽 Python 自动处理大整数，但在其他语言需注意）。
**测试用例设计**：
- 正常情况：`arr=[1,3,5], target=3`
- 边界情况 1：`arr=[1], target=1`（单元素）
- 边界情况 2：`arr=[1,3,5], target=5`（末尾元素）
- 异常情况：`arr=[], target=1`（空列表）

## 复杂度与权衡
测试覆盖率与成本之间存在权衡关系。100% 的分支覆盖通常成本极高且收益递减。工程上常采用风险驱动测试，对核心算法和高危模块投入更多测试资源。形式化验证虽然能保证正确性，但学习曲线陡峭且耗时，通常仅用于安全关键系统（如航空控制）。

## 常见误区
1.  **“测试通过即正确”**：测试通过仅代表未发现错误，不代表程序逻辑无误。
2.  **“调试即修改”**：盲目修改代码而不理解根源会导致“补丁叠加”，增加系统熵值。
3.  **“忽略空值”**：未处理空列表、空字符串或 null 指针是边界错误的常见来源。

## 自测题与答案
**问题 1**：若函数定义域为整数 $[1, 100]$，根据边界值分析，至少应测试哪几个数值？
**问题 2**：调试过程中，若修改代码后错误消失，但未运行回归测试，可能带来什么风险？

**答案**：
1.  应测试 $0, 1, 2, 99, 100, 101$。重点在于边界及其邻域。
2.  可能引入回归缺陷（Regression Bug），即修复旧问题的同时破坏了原有功能，导致系统其他部分失效。
