## 学习目标
本讲义旨在帮助学生建立“现实问题计算模型”的核心认知。学习完成后，学生应能够：
1. 准确区分现实问题与计算模型的边界，理解模型是对现实的简化而非复刻。
2. 识别问题中的关键变量与不变量，并能提出合理的假设以降低问题复杂度。
3. 掌握构建计算模型的标准步骤，并能评估模型的适用性与局限性。

## 准确概念与边界
计算模型（Computational Model）是指利用数学符号、逻辑规则或算法结构，对现实世界中的系统进行抽象描述的形式化表达。其核心在于“抽象”，即保留关键特征，忽略次要细节。

**概念边界：**
*   **是：** 对问题本质关系的映射，用于预测、解释或优化。
*   **不是：** 现实本身，也不等同于具体的代码实现。代码是模型的实例化，模型是代码的逻辑骨架。
*   **边界条件：** 任何模型都有适用范围。超出边界（如极端数据、环境突变），模型可能失效。例如，牛顿力学在宏观低速下有效，但在微观高速下需量子模型。

## 机制与建模步骤
构建计算模型通常遵循以下四步机制：
1.  **问题定义：** 明确输入是什么，期望输出是什么。
2.  **假设提出：** 为了可计算，必须对现实进行简化。例如假设“用户到达率是均匀的”。
3.  **变量提取：** 确定状态变量（随时间变化）与参数（固定值）。
4.  **关系构建：** 用公式或逻辑连接变量，形成可执行的规则。

## 完整示例：电梯调度模型
**情境：** 设计一个单电梯系统的平均等待时间模型。
**变量定义：**
*   $N$：候梯人数。
*   $C$：电梯最大容量。
*   $V$：电梯运行速度（层/秒）。
*   $T_{load}$：开关门及上下客固定耗时。

**假设：**
1.  乘客均匀分布在各楼层。
2.  电梯满载即走，不等待后续乘客。
3.  忽略加减速过程，视为匀速。

**模型公式：**
单次运行周期 $T_{cycle}$ 可近似为：
$$ T_{cycle} = 2 \times H_{max} \times \frac{1}{V} + K \times T_{load} $$
其中 $H_{max}$ 为最高请求楼层，$K$ 为停靠次数。
平均等待时间 $E[W]$ 与发车间隔有关，简化模型下：
$$ E[W] \approx \frac{T_{cycle}}{2} $$

**伪代码实现：**
```python
def calculate_wait_time(floor_count, speed, load_time, passengers):
    # 边界检查
    if speed <= 0: return float('inf')
    
    # 假设最高楼层为请求中的最大值
    max_floor = max(passengers) if passengers else 0
    stops = len(set(passengers))
    
    cycle_time = 2 * max_floor / speed + stops * load_time
    avg_wait = cycle_time / 2
    return avg_wait
```

## 复杂度与权衡
在建模过程中，存在**精度与复杂度**的权衡。
*   **高精度模型：** 考虑加减速、乘客体重分布、心理等待阈值。优点是预测准，缺点是计算成本高，参数难以获取。
*   **低精度模型：** 如上例，仅考虑匀速和停靠。优点是易于分析和优化，缺点是极端情况下误差大。
教学重点在于让学生明白，没有“最好”的模型，只有“最适合当前目标”的模型。

## 常见误区
1.  **模型即现实：** 认为模型输出绝对正确，忽略假设失效的风险。
2.  **变量遗漏：** 忘记定义边界变量（如电梯容量 $C$），导致模型计算出负数或无穷大。
3.  **过度拟合：** 引入过多无关变量，导致模型无法推广到新场景。

## 自测题与答案
1.  **问：** 在电梯模型中，若忽略“最大容量”这一边界，会导致什么后果？
    **答：** 模型会预测电梯能一次性运载无限多人，导致等待时间被严重低估，实际系统会崩溃。
2.  **问：** “假设乘客均匀分布”属于建模的哪一步？
    **答：** 属于假设提出步骤，用于简化概率计算。
3.  **问：** 模型验证失败时，首先应检查什么？
    **答：** 首先检查假设是否在实际场景中成立，其次检查变量定义是否完整。
