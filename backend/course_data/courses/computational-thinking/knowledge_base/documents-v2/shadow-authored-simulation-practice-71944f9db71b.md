## 学习目标
1. 能够在真实情境中抽象出离散模拟所需的输入参数与状态变量。
2. 掌握参数扫描（Parameter Sweeping）实验设计方法，寻找最优配置。
3. 学会制定测试用例与评价量规，确保模拟软件的质量与结论的可信度。

## 真实问题情境
某大学食堂高峰期排队严重，学生抱怨等待时间过长。食堂经理计划调整窗口开放策略。现有 3 个打饭窗口，学生到达具有随机性。经理希望知道：在总人力不变的情况下，是开设 3 个普通窗口快，还是开设 1 个快速窗口（服务时间短但只限单菜）加 2 个普通窗口更优？这需要通过对不同配置进行模拟实验来决策。

## 输入输出与材料
**输入参数**：
- 学生到达率 $\lambda$（人/分钟），高峰期约为 2.0。
- 普通窗口服务率 $\mu_{normal}$（人/分钟），约为 0.8。
- 快速窗口服务率 $\mu_{fast}$（人/分钟），约为 1.5。
- 模拟时长 $T$ = 120 分钟。
- 窗口配置方案（如 [3 个普通] 或 [1 快 2 普通]）。

**输出指标**：
- 平均等待时间（Average Wait Time）。
- 队列最大长度（Max Queue Length）。
- 窗口利用率（Utilization Rate）。

**材料**：Python 编程环境，随机数生成库。

## 分步任务
1. **模型抽象**：定义学生对象（到达时间、服务需求类型）和窗口对象（状态、服务速率）。
2. **基线运行**：实现 3 个普通窗口的模拟，运行 5 次，记录平均等待时间作为基准。
3. **实验设计**：设计对照实验，改变窗口配置为 [1 快 2 普通]，保持到达率不变，同样运行 5 次。
4. **数据分析**：对比两组实验的平均等待时间，计算改进百分比。若改进超过 10%，则建议采纳新方案。
5. **报告撰写**：总结实验过程，附上关键数据图表。

## 参考实现与推导
以下是实验循环的核心逻辑，用于对比不同配置：

```python
def run_experiment(config, arrival_rate, duration, trials=5):
    results = []
    for i in range(trials):
        random.seed(i) # 每次试验不同种子
        # 此处调用具体的模拟引擎函数 simulate_cafeteria(...)
        # 为简洁省略内部逻辑，假设返回平均等待时间
        wait_time = simulate_cafeteria(config, arrival_rate, duration) 
        results.append(wait_time)
    return sum(results) / len(results)

# 实验执行
baseline = run_experiment(config=[0.8, 0.8, 0.8], arrival_rate=2.0, duration=120)
optimized = run_experiment(config=[1.5, 0.8, 0.8], arrival_rate=2.0, duration=120)

improvement = (baseline - optimized) / baseline * 100
print(f"方案改进率：{improvement:.2f}%")
```
推导逻辑：若 $\lambda < \sum \mu$，系统稳定。实验目的是在稳定前提下最小化等待时间 $W_q$。根据排队论近似公式，服务率方差越小，等待时间越短，快速窗口引入了服务率差异，需通过模拟验证实际效果。

## 测试与边界情况
为确保模拟健壮性，必须测试以下边界：
1. **零到达**：设置 $\lambda = 0$，验证等待时间是否为 0，程序是否崩溃。
2. **过载情况**：设置 $\lambda > \sum \mu$，验证队列是否无限增长，程序是否有保护机制（如最大队列长度限制）。
3. **单窗口退化**：设置窗口数为 1，验证逻辑是否退化为单队列单服务台模型。
4. **瞬时高峰**：模拟前 10 分钟到达率极高，随后降低，观察系统恢复能力。

## 评价量规
| 维度 | 优秀 (A) | 良好 (B) | 合格 (C) |
| :--- | :--- | :--- | :--- |
| **模型准确性** | 状态转移逻辑严密，符合现实约束 | 主要逻辑正确， minor 细节忽略 | 基本流程跑通，但逻辑有漏洞 |
| **实验设计** | 有多次重复试验，控制变量严格 | 有对照实验，但重复次数不足 | 仅单次运行，无对照 |
| **数据分析** | 计算均值方差，有统计结论 | 仅计算均值，有简单对比 | 仅输出原始数据，无分析 |
| **代码质量** | 模块化好，有注释，处理边界 | 代码可读，无明显错误 | 代码混乱，难以维护 |

## 拓展问题
1. **多队列 vs 单队列**：如果 3 个窗口共用一个排队队列（蛇形队），与每个窗口独立排队相比，模拟结果会有什么差异？请设计实验验证。
2. **动态调整**：如果允许根据当前队列长度动态开关窗口，如何设计控制算法？模拟中需要增加哪些状态监测变量？
3. **非指数分布**：现实中服务时间可能服从正态分布或对数正态分布，修改分布模型后，最优配置是否会发生改变？
