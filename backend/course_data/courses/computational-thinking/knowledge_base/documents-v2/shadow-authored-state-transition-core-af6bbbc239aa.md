## 概念与边界
在计算思维中，**状态（State）** 并非简单的变量值，而是系统在某一时刻所有相关信息的快照，它总结了过去的输入历史，并决定了系统对当前输入的响应。若系统未来的行为仅取决于当前状态和当前输入，而与达到该状态的路径无关，则该系统具有“马尔可夫性”。

**规则（Rule）** 是约束状态变化的逻辑条件，通常表现为“若处于状态 A 且收到输入 X，则转移至状态 B"。**状态转移（State Transition）** 是状态随输入发生离散变化的过程。

形式化地，一个确定性有限状态机可定义为五元组 $M = (Q, \Sigma, \delta, q_0, F)$：
- $Q$：有限状态集合。
- $\Sigma$：有限输入字母表。
- $\delta: Q \times \Sigma \rightarrow Q$：状态转移函数。
- $q_0 \in Q$：初始状态。
- $F \subseteq Q$：接受状态集合（可选，用于识别特定结束条件）。

边界在于：状态必须是离散且有限的。连续变化的变量（如温度读数 25.1℃）通常被视为数据而非状态，除非将其划分为区间（如“正常”、“高温”）。

## 机制与步骤
构建状态模型通常遵循以下步骤：
1. **识别状态**：列出系统所有可能的稳定模式，确保互斥且完备。
2. **定义输入**：明确触发状态变化的外部事件或条件。
3. **构建转移表**：枚举所有“状态 - 输入”组合，确定下一状态。
4. **处理非法输入**：定义在特定状态下收到无效输入时的行为（如保持原状或报错）。

## 完整例子：自动turnstile 闸机
考虑地铁进站闸机，其核心逻辑如下：
- **状态**：`LOCKED`（锁定）、`UNLOCKED`（解锁）。
- **输入**：`COIN`（投币）、`PUSH`（推杆）。

| 当前状态 | 输入 | 下一状态 | 行为说明 |
| :--- | :--- | :--- | :--- |
| LOCKED | COIN | UNLOCKED | 解锁，允许通行 |
| LOCKED | PUSH | LOCKED | 拒绝通行，报警 |
| UNLOCKED | COIN | UNLOCKED | 忽略多余投币 |
| UNLOCKED | PUSH | LOCKED | 通行后重新锁定 |

## 代码实现
以下 Python 代码实现了上述逻辑，展示了状态封装与转移验证：

```python
class Turnstile:
    def __init__(self):
        self.state = "LOCKED"
    
    def on_event(self, event):
        if self.state == "LOCKED":
            if event == "COIN":
                self.state = "UNLOCKED"
                return "Access Granted"
            elif event == "PUSH":
                return "Access Denied"
        elif self.state == "UNLOCKED":
            if event == "PUSH":
                self.state = "LOCKED"
                return "Passed"
            elif event == "COIN":
                return "Ignore"
        return "Unknown Event"

# 验证运行
machine = Turnstile()
print(machine.on_event("PUSH"))  # Access Denied
print(machine.on_event("COIN"))  # Access Granted
print(machine.on_event("PUSH"))  # Passed
```

## 复杂度与权衡
状态机的时间复杂度通常为 $O(1)$，因为转移仅取决于当前状态和输入。然而，空间复杂度随状态数量线性增长。主要权衡在于**状态爆炸（State Explosion）**：当系统变量增多时，组合状态数呈指数级上升（$N^M$）。为避免此问题，应采用分层状态机或将部分数据剥离出状态定义，仅保留控制逻辑作为状态。

## 常见误区
1. **混淆数据与状态**：将计数器值视为状态。修正：计数器是数据，"计数已满"才是状态。
2. **遗漏转移路径**：未定义某状态下的特定输入行为，导致程序崩溃。
3. **隐含状态**：依赖布尔标志位（如 `is_paid`）而非显式状态枚举，导致逻辑分散难以维护。

## 自测题与答案
1. **问**：若系统有 3 个布尔变量，理论上最多有多少种组合状态？
   **答**：$2^3 = 8$ 种。
2. **问**：状态转移函数 $\delta$ 是否可以是多对多的？
   **答**：在确定性有限状态机（DFA）中必须是单值的；非确定性（NFA）允许多值，但实现时需回溯或并行。
3. **问**：为何不建议用大量 if-else 嵌套代替状态机？
   **答**：if-else 难以维护状态历史逻辑，易产生逻辑漏洞，且复杂度随条件增加呈指数上升。
