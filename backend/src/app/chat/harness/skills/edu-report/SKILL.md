# 报告生成与审阅流程

备课讨论本身不等于要求创建报告：用户只谈教学安排时，直接提供专业建议，不展示本 Skill 的流程菜单。用户明确要求报告后才执行以下流程。已识别主题直接使用，不要求用户手动切换知识点。

## 1. 确定完成目标

区分新建、修改、只要大纲、确认正文、查看结果。沿用已有主题、受众、长度和资料范围，仅在重要信息缺失或冲突时澄清。知识讲解型重概念依赖、推理、例子与误区；调研型重证据比较与结论边界；总结型重已给内容与学习达成。
完整报告的终点是经过审阅的正文，大纲和提交任务都是中间状态。

## 2. 检索与证据

指定课程资料且允许时先 rag_search；明确联网、最新事实或外部论据时 web_search。基础概念未要求检索时可不检索，但不伪称有外部依据。
查询包含主题与关键问题，优先教材、大学课程、官方资料。domains 可严格限定来源；已知真实权威链接可通过 reference_urls 读取工具支持的页面。无结果时最多修正两次；不得编造链接、证据 ID 或绕过禁用范围。
区分来源事实、教学设计和推导。网页摘要或截取不是完整事实核验。强制来源无法满足时说明缺口，不能用不相关资料填充引用。

Embedding / 检索额度不足等工具错误不是空搜索结果，不应反复重试。准确说明无法读取资料；由你结合用户约束判断能否用已有证据或基础知识继续。明确要求基于指定资料时不得擅自换成无资料报告；无法满足时保留任务并说明阻塞。
提交报告默认 source_mode=planned_evidence，后台沿用已收集证据而不自行追加检索。只有你判断需要在后台补充课程或选中文档检索时，才显式传 course_auto 或 selected_documents；RAG / Web 按钮开启时必须调用对应检索工具；未开启由模型决定是否调用，不能视为禁止。

## 3. 内容组织与大纲

调用 organize_report_content，传主题、受众、要求、真实 evidence_ids。它组织范围、先修、可观察目标、模块依赖、例子、误区、自检和证据映射，并独立检查内容。依据 content_quality_failed 的具体问题修正，不能跳过组织。
调用 draft_report_outline，传一致的主题、受众、要求、evidence_ids 与 organization_id。修改时传 revise_outline_id；需求或证据变更须重新组织。按 references/knowledge-outline.md 检查知识点大纲。
对外大纲只展示章节标题和每章 1–3 个小节标题（名词性主题名称，不是摘要或结论句），让用户看清报告结构。解释、例子、误区和练习保留在内部 organization，正文阶段再展开。
只要大纲：展示工具保存的版本，到此结束。完整报告：必须先展示当前版本大纲并等待用户后续确认，才能提交正文。本轮新建或修改的大纲不能同轮提交；不能把最初“生成报告”的请求视为对未展示大纲的确认。不要强制固定口令，不因语言不同重复确认。用户对当前结构表示继续时直接 submit_report；用户同时提出修改时先处理修改，再判断其是否已授权继续。

## 4. 正文生成、审阅与修订

由你判断用户是否要求推进正文，再使用当前 outline_id 和 revision 调用 submit_report。代码不分析用户措辞。基于 report_states 的 confirmed 状态恢复中断提交，submitted 状态关联已有任务；不得退回要求同一版本再次确认。
用 update_working_memory 保存已确认事实、计划和阻塞原因，真实任务状态以工具返回为准。提交会快照章节、结构化组织和证据，后台任务依据这些输入生成完整正文。
正文必须展开概念、解释因果与推理、给出具体示例和自检，保持确认章节顺序与受众要求；不能把大纲复制成正文。引用须对应实际提供资料，原创教学例子需与来源事实区分。
审阅标准见 references/report-review.md。后台对正文进行独立审阅，覆盖六项：需求覆盖、事实与推理、例子与边界、教学结构、来源引用、正文完整性。真实错误和重要遗漏阻断；风格建议不阻断。存在阻断问题时自动按意见修订，再审阅新版本，最多两次修订。
只有通过检查的正文才保存为完成报告，审阅记录绑定正文摘要与版本。不能用旧版本审阅批准修改后的正文，也不能通过工具参数自授通过。

## 5. 查询与最终交付

submit_report 返回 submitted 仅表示已提交“生成与审阅”任务，告知后台处理，不轮询等待长任务。用户查结果时调用 query_report_job。
查询范围是当前用户、当前课程，可跨对话。先结合 report_discovery 或 find_report_jobs 定位用户所指任务；多个合理候选先澄清，不选最新任务代替用户判断。当前会话没有任务不能推断报告未完成；未找到或查询失败只能说明无法确定，不能重建或重复提交。跨对话查询只保存只读引用，不复制大纲确认或取消权限。
只有返回 verification.decision=pass 且包含 artifact 才交付该产物；说明已通过模型审阅，可提示非阻断建议和资料限制，不称人工审阅或全面事实核验。
任务未结束只报状态。审阅失败、记录缺失或摘要不一致时说明未完成，不把正文片段、旧报告或大纲冒充最终报告。预算耗尽后停止重试；需求变更走新的组织、大纲和确认流程。取消使用 cancel_report_job。任何阶段允许用户切换话题。

用户确认后的回复只告知正在生成，不展示 outline_id、task_id、版本标识或原始状态；任务结果由系统在当前对话呈现。
