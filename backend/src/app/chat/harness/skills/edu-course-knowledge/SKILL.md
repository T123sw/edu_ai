---
name: edu-course-knowledge
description: 创建或补充正式课程知识库，生成可比较课程目录或基于现有资料的补充清单。仅解释知识点、报告大纲或个人知识导图不使用此流程。
---

用当前认证课程调用 `plan_course_knowledge`。首次省略 build_id；修改已有方案必须带工具返回的 build_id 和 revision，并明确教师最新要求。该工具会先把教师语言编译为 intent 需求合同，再生成方案；模型不能确认或发布方案。

返回后先依据 `intent` 向教师概括系统实际理解到的教学对象、前置知识、课时、范围、深度、来源约束、交付物数量和增量保护。必须区分 hard 与 preference；不把“优先官方来源”说成“已经找到官方来源”。如果工具返回需要澄清，不要猜测答案或继续规划，直接转述至多 3 个具体问题。

没有现有目录时比较简明、标准、完整三种课程大纲；已有目录时先评估资料覆盖，提出具体补充项目，默认保留所有旧节点。不要要求教师填写固定模块数量，也不把三档方案当成三种固定节点数。
规划原则和数据结构见 [planning.md](references/planning.md)。缺少资料证据时标注“根据目录和资料标题推断”，不能谎称已读全文。教材未解析完成时先告知等待。

向教师简要说明工具返回的方案差异或缺口，提供 review_url。教师在该页面先核对需求合同，再选择、编辑并确认当前版本，确认前不提交检索、生成或入库。来源域名、教学深度、案例/练习/实验数量必须进入执行和质量检查，不能仅写在说明文字中。

教师询问进度、是否完成、内容质量或失败原因时，使用 `query_course_knowledge_build` 查询指定 build_id；不要根据对话历史猜测状态。解释 `quality_checks` 时逐项对应需求合同；`needs_teacher_decision` 表示偏好来源不足，必须由教师决定是否降级。只有真实状态为 succeeded 且 `published_version` 非空，才可以宣称知识库已更新。

只有教师明确要求重试，并且查询结果为 failed 或 blocked 时，才使用 `retry_course_knowledge_build`。重试沿用已确认版本和稳定检查点；不得自动重试，也不得把重新排队说成已经完成。
