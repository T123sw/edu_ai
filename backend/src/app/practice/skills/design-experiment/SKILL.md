# 先动作，后讲解

服务流程：科学建模 → 完整实验 HTML → 本 Skill 设计动作 → 实现原理演示页面（探索页直接复用完整实验） → 浏览器记录实际演示动作及状态 → 单独调用模型生成讲解 → 按动作 ID 绑定。

本次动作设计调用只输出服务提供的 DemonstrationPlan JSON。输入为用户需求、科学模型、完整实验 HTML。不要提前写 before/after、成功/失败反馈、教学提示或探索问题，这些由最后的讲解调用负责。

滚动升级兼容：如果调用附带的是旧 TeachingPlan schema（含 demo_steps.before/after，且没有 demo_actions），按该旧 schema 输出完整教学拆分及讲解，逐项对应原 HTML 的实际操作；不要返回 ActionPlan。只有新版 DemonstrationPlan 调用使用下述“先动作、后讲解”流程。

尚未重启的旧进程也可能附带 ActionPlan schema（同时包含 demo_actions 和必填 tasks）；这种情况下以调用的 schema 为准，补齐历史任务的 title、initial、interaction、completion，遵循页面接入约定中的历史 guided 规则。仅当 schema 没有 tasks 时使用当前两阶段设计，不生成独立任务。这是升级期兼容，不向新两阶段产物添加第三阶段。

1. 阅读原 HTML 的实际算法与操作能力，保留科学假设、算法变体和绘图。描述动作类型、执行条件和停止边界，不预测每一步结果，不生成动作引用网络或验收测试集。
2. 演示选最小非平凡且确定的初始场景（如需多轮处理的 3 个乱序元素）。完整执行到算法或实验目标真实结束；学生只用下一步、回看、重播。一个动作是一对元素的比较、一次交换或一次边界推进，不能把剩余算法打包成一步。demo_actions 是供页面实现的动作方案，实际步骤数由浏览器执行决定。连续系统采用有限观察区间或明确结束目标。
   演示只选一组初始条件完整运行一次，不切换多组参数、不安排演示后的重置和重复运行；参数比较留给自由探索。连续物理过程按少量有意义的观察时刻推进（如开始、滑行中、停止），不要把动画帧或 0.02 秒积分步当作学生必须点击的教学步骤；观察时刻的状态必须用原科学模型真实计算，最后一个观察点达到实际结束条件。算法仍保留逐次比较等离散动作。
3. 当前流程只有原理演示和自由探索，不设计独立动手任务、正确/错误判定、通关步骤或练习页。自由探索保留完整实验的真实控件与状态记录。
4. 探索建议由最后的讲解调用根据完整实验已实现的控件生成，本次动作设计不生成建议。

页面实现按 [页面接入约定](references/pages-runtime.md) 和 [状态含义与结束依据](references/state-evidence.md)，只生成可执行操作、图形、必要状态与控件标签，并保留关键字段的范围、重置前值和实际结束分支。讲解阶段单独使用 [动作讲解规范](references/narration.md)，输入已经完成的页面与真实执行记录；生成讲解后不再修改页面动作。

宿主负责三栏、阶段切换、反馈、事件和保存。未来教学 Skill 独立消费科学背景、动作目录、实际用户历史及当前状态，回答用户提问，不与本设计 Skill 混用。旧 edu-experiment/1 排队任务仍使用 [历史规格生成指令](references/legacy-design.md) 和旧 references/output.md。
