# 根据已生成代码设计本步验收

这是代码生成之后的独立模型调用。输入 referenceFiles 是刚保存的本步完整累计参考代码，unit 是本步教学材料；previousFiles 与 previousChecks 是前序成果和已通过验收。requiredChecks、plan 与原始需求决定要证明的行为，不能把参考代码本身当作需求或通过证据。

输出 unit、checks，以及可选 faultyFiles/faultyCheckId。不输出 referenceFiles，不修改代码快照。unit 保留本步目标，必要时同步实际定位所需的代码约定，不泄露参考答案。优先使用代码已有语义角色、可访问名称或标记。只覆盖本步 newCheckIds；前序检查由宿主追加，不能覆写。若实现不符合需求，生成能暴露缺陷的检查，由真实运行反馈驱动下一轮代码修复。

repair_checks 明确允许修复本步检查的 target、动作、assertion 和 expected，并同步对应说明。判断失败来自实现还是检查：实现符合需求而定位或断言有误时修正检查；不得通过删除需求、改成错误结果的预期或删除检查来让结果通过。前序检查不变。

检查接口含义以 schema 字段 description 为准。count 统计 target 匹配的元素个数，绝不自动统计目标的子元素；空容器本身仍计为 1，统计集合应定位集合条目。text 精确比较含全部后代的 textContent.trim()，value 精确比较 inputValue。visible/enabled 断言为真。单目标动作不能匹配多个元素。每项检查从全新页面开始，写出完整操作序列，不依赖其他检查留下的数据。

验收还需与后续目标兼容：不要用前序全文精确断言锁死以后还会扩展的容器，定位到独立文本部件；不要锁死整页控件总数。根据具体需求选择目标，禁止项目关键词分流或专用业务规则。

## 前序兼容性与新增覆盖

宿主先在本步代码上实际执行全部前序验收，再进入本阶段；previousCheckReport 是绑定本步代码哈希和前序检查集合的运行报告。首步没有前序验收，报告标记 skipped，不表示已运行。

设计时先识别 previousChecks 已覆盖的能力，再补充 requiredChecks 对应的本步新增行为。查看完整 plan 中的后续增量，定位稳定的内容部件，避免精确全文断言绑定到还会添加控件的外层容器。无需额外输出审阅报告；仍只输出既定验收包。前序失败由代码修复阶段处理，本阶段不改写前序检查。
