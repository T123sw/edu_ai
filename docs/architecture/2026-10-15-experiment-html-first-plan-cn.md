# 先生成实验，再拆分教学：实施计划

状态：已部署，生产端到端主要通路通过；演示粒度与探索参数控件仍有生成内容缺口，详见验收记录。采用用户确认的六步流程，替代新生成实验的整包规格优先方案；旧产物继续兼容。

1. 用户输入直接进入 MAIC-UI ScientificEngine 科学建模，再由原生 VisualEngine 生成完整交互 HTML。完整实验作为自由探索页。
2. 设计 Skill 读取基础 HTML、科学模型和教学要求，仅输出简短演示步骤、代表性练习、预生成讲解和反馈。程序分配步骤 ID；不要求状态表、动作权限引用和验收用例。
3. 分别调用 MAIC-UI VisualEngine，基于同一完整 HTML 改造演示页、练习页，沿用算法和绘图。演示仅下一步/回看/重播，练习在页内操作并本地判断，正确自动推进、错误提示并重试。每个任务显式初始化，避免隐式继承。
4. 三栏宿主加载三个独立沙箱页面。统一小型注册/操作上报接口，宿主管理阶段、步骤、日志、保存和恢复；页面负责学科算法与本地判定。自由探索保留完整功能。
5. 复用账号隔离、追加式操作记录、快照和冻结教学上下文。教学 Agent 继续预留，不模拟模型答疑。新协议 edu-experiment/2，旧 v1 生成/阅读保留，新的首页请求使用 v2。
6. 每阶段保存中间产物与诊断。本地检查 HTML 可加载、接口注册、演示可执行、练习判定接入、重置恢复；拼装后用最终配置再核对。不以模型预测的最终状态逐字段比对阻断交付。没有新增模型审查或整套生成测试题。结构/运行失败最多局部修复一次，不重写已完成阶段。

2026-10-15 后续确认：算法演示必须完整执行至终止；动手实践不固定题数，可将完整执行一次算法作为一个连续任务，中间正确操作反馈并继续，错误只撤销本次操作，任务完成后保留最终结果。演示步骤数由完整过程决定，缩小输入规模而非截断过程。用户在快速排序被误判后明确要求优先生成稳定性：取消 `demo_result` 必填输出与终态严格比对，旧计划含该字段也不用于阻断生成。探索页配置隔离教学初始说明，使用自身真实参数。设计与页面接口要求放入 system 指令，基础 HTML 作为参考输入，避免自动单步控件覆盖人工判断要求。

实施顺序：后端生成与 Skill → 沙箱协议与三页切换 → 持久化兼容 → 自动回归与真实主题生成。

验证：调用顺序及输入传递、阶段失败与取消；真实浏览器演示/错误重试/正确推进/探索/刷新恢复；旧 v1 回归；类型与构建；使用现有用户模型配置做隔离真实生成，避免改写历史失败任务。

交付边界：先完成功能，不增加独立审查 Agent。检查通过仅表示基本运行可用，不代表所有学科正确性经独立认证。无数据库迁移；代码完成和生产部署分开记录，部署前保留同期页面修改。

实施结果与已知内容质量问题见[验收记录](../acceptance/2026-10-15-experiment-pages/README.md)。
