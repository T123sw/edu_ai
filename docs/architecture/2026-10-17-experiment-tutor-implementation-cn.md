## 设计与交付顺序

1. **冻结操作证据**：发送时提交不可变 RunView，核对版本、序号及服务器已有历史的共同前缀；允许后台保存已推进。保存独立教学上下文，不覆盖运行进度。保留失败动作、失败反馈和回滚后的当前状态。默认焦点为最近有意义动作，支持显式选择历史动作。连续动画期间定时同步，避免防抖饥饿。
2. **持久教学会话**：以用户＋实验归属存储，每条消息携带 revision/run/seq/context。request_id 幂等；先保存问题和证据再调用模型。reply_to 关联原教学回复及其原始证据，不能被最新状态替换。分页历史保留跨阶段/新一轮消息，但模型输入明确作用域。执行令牌和超时阻止迟到结果覆盖重试；失败和中断可以重试原问题。
3. **独立 Skill 与 Agent**：新增 teach-experiment，按演示/实践/探索提供教学行为；区分操作判定与理解评价，数据不足时说明。复用模型配置、密钥切换，普通问答一次调用；需要历史时调用已有只读证据工具，限制工具轮次，无额外审阅模型。上下文包含背景、科学模型、当前任务、焦点动作前后状态/实际 facts/反馈、相关历史、原问题及用户回答。长历史不声称全部已读，按需分页原始记录。
4. **真实流式对话**：模型 SSE 转发逐段文本，完成后持久化；工具读取期间只显示真实等待状态。右侧保留预生成反馈、预告和按钮，替换保存问题占位区。支持当前操作提问、回复教学消息、历史动作提问、分页、恢复和重试。聊天忙状态与实验忙状态独立；迟到回复留在原问题下，不修改进度。文本安全渲染，不执行模型 HTML。
5. **验证与交付**：隔离存储中验证权限、幂等、冲突、旧问题关联、失败回滚、工具读取、流式中断/重试；浏览器验证桌面/手机、等待时继续实验、刷新恢复、布局无溢出；用真实模型检查冒泡排序与非算法实验，记录实际输出及边界。运行必要类型/Lint/构建及已有协议回归，更新地图和验收记录。

## API 与内部边界

- GET `/api/practice/{id}/experiment/tutor`：分页读取教学消息。
- GET `/tutor/{request_id}`：读取自己的一条历史消息，恢复分页范围之外的回应对象。
- POST 同路径：`request_id/question/view/reply_to?/focus_event_id?`，冻结后返回 SSE：accepted、status、delta、done 或 error。
- POST `/tutor/{request_id}/retry`：复用持久问题与原始证据重试；已完成直接返回，执行中拒绝重复调用。
- 模型证据工具限定在请求冻结上下文；回复旧问题时可读取原问题证据。工具不能指定其他用户、实验或任意上下文。
- 默认按需调用，无每次操作自动推理，不把模型“回答正确”写成实验通过。首版不支持教学 Agent 改参数、执行动作或修改实验。

## 验收场景

- 错误交换已回滚，解释仍引用错误交换的前后数值及正确规则。
- Agent 追问后用户继续实验，再回答旧问题，评估针对原问题；最新状态单独标注。
- 明确系统演示与用户操作，阶段变化/新一轮不串用证据。
- 连续操作完整保留；长记录可分页读取，提示模型输入是否为部分历史。
- 同一请求重复发送不重复回复；失败保留原问题；刷新/断开后可恢复或重试。
- 超时、模型错误、过期执行不锁住实验，不显示假通过。
- 权限、版本、历史改写检查有效；旧协议仍可操作。

## 已知容量边界

现有运行记录上限为 2000 个事件、约 1.5 MB，本次保持兼容，到上限继续使用现有新一轮入口；不宣称无限历史或已捕获生成页面未上报的内部动作。提问附完整快照用于可靠冻结，模型按需读取；增量传输优化不作为首版教学能力前置条件。课程内跨资料统一会话另按课程教学基线对接，本次独立实验不创建课程专用依赖。
