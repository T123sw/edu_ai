# HyperFrames 接入边界修正

用户确认：平台只负责需求梳理；视频创作交给 HyperFrames 原生工作流。

1. 移除平台自行组织讲稿 JSON、逐段配音、整页 HTML 生成及修复的生产路径。入口只交付需求、资料、受众、时长、原始要求和已选素材，不预先决定分镜、风格、讲稿或练习。
2. 在隔离的持久工程目录运行通用 Agent，加载 vendor/hyperframes 的完整原生技能树。由原生 router/workflow 决定 BRIEF、frame.md、STORYBOARD、SCRIPT、audio_meta、分镜、组装、检查、截图及渲染；保留工程和工具执行记录以恢复、审计。
3. 适配层只提供文件/命令/预览/Agent 执行能力。现有中文 TTS 通过原生 HF_MEDIA_ENGINE 扩展协议提供声音，不决定文案或分段。保持原仓库文件不变。
4. 视频交付后确定性读取原生工程、音频及分镜时间，适配现有 hyperframes/v1 播放、下载、位置问答接口；保留完整工程包，不再要求模型生成平台专有课件 schema。
5. 视频需求不再默认捆绑 report/quiz。显式要求的其他课程资源仍独立生成。
6. 覆盖原生技能执行、需求原文传递、真实音频接口、原生工程导入、恢复与取消的测试；使用真实模型生成新样片并保存。仅在具备服务管理权限时重启生产后端，不能把待重启的代码称为已上线。

原生工作流通常由宿主 Agent 执行，并非一个可直接请求的 HyperFrames 文生视频 HTTP API。宿主提供运行能力，原生技能负责创作步骤。按用户已有授权自动完成制作，需求已明示的内容不再重复询问，不额外增加模型审核或人为关卡。

## 实现边界

- `integrations/hyperframes/workflow.py`：需求、资料和已选素材交接；持久工程、恢复与最终保存。
- `workflow_agent.py`：通用编码 Agent 宿主，完整加载原仓库角色与工作流；文件、异步命令、分镜工作者与真实截图查看工具。
- `workflow_audio.py` / `host_audio_engine.mjs`：通过原生 `HF_MEDIA_ENGINE` 扩展接入现有语音服务，保留原生背景音乐和音效接口；宿主不编写文案。语音服务当前不提供逐词时间戳，不伪造；字幕能力由原生工作流依据可用信息选择。
- `workflow_import.py`：读取原生 SCRIPT、STORYBOARD、audio_meta 和实际 composition 起止时间；保存 MP4/SRT/ZIP，并适配现有播放位置问答协议。导入回执明确标记为媒体探测与结构校验，不冒称内容审核。
- 新生成器标识为 `hyperframes-native-workflow`。课程交付认可视频独立交付，不要求为其补齐习题、报告或虚构目标定位；历史课堂继续可读。
- 前端去掉隐藏的 6 场景、25 分钟、引导式教学以及默认受众/目标；后端相应字段可缺省。明确的用户约束仍传入简报。
- 仅视频请求的课程节点只保存主题范围和资料；未要求多视频时不自动拆分，不预写教学活动或自测。旧字段使用明确的交接说明且不传给原生创作器。
- 旧聊天入口直接保存需求，移除逐场景 schema、讲稿生成和额外内容审阅；没有用户明确要求时不设置片段数、配音或时长。旧独立课堂入口中的模型配图规划已移除；课程需求、交付审阅及通用资源技能中的默认报告/习题和平台预写分镜指令同步清理。

## 恢复与执行

每次请求由需求摘要确定持久工作目录；原生 BRIEF、分镜、讲稿、音频与动画文件原样保留。重新执行会读取已有文件继续；原生渲染完成后的导入重试不重复制作。任务租约保活仍由课程准备层负责。命令进程由持久线程启动，避免 HTTP 请求线程结束时触发 bubblewrap 父进程死亡信号。原生分镜工作者与父任务共享执行窗口，退出时清理命令进程。工具线程和语音线程继承本次用户的运行配置。

原仓库完整保留在 `vendor/hyperframes`；不修改其脚本以迁就平台 JSON。模型选用、任务生命周期、语音服务凭据和成品权限仍由宿主管理。
