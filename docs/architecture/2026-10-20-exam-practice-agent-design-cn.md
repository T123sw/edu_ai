# 独立试卷作答页与问答 Agent 设计

日期：2026-10-20。状态：已实施并发布；实际验证范围见[验收记录](../acceptance/2026-10-20-exam-practice/verification.json)。依据用户要求：查看试卷进入独立页面；支持直接作答并保存记录；右侧提供可提问的 Agent，复用 AI 课堂习题交互与答疑能力。

2026-10-20 界面精简更新：移除顶部作答记录、整卷完成与重新练习入口，继续使用已有自动草稿保存；不删除已存作答。新作答持续在当前轮次中保存，历史已结束轮次仍按原有只读约定展示。删除“看看我的思路”快捷按钮；点击题卡正文、空白、输入区或“关联此题”均可切换问答引用，不要求整题进入视口。答题卡通过题号样式实时区分作答状态，按用户后续要求删除底部“未答、已填写、已提交”图例；选项采用整行布局。此更新替代下文相应的首版界面描述。

## 1. 产品定位

生成首页负责出题和管理试卷，独立试卷页负责作答、查看记录与答疑。普通出题和参考试卷仿题共用此页面。

首版采用可随时求助的练习方式：逐题提交、即时反馈、随时退出后继续。默认不计时、不做防作弊限制；不增加计时考试/练习双模式。答疑与作答可独立使用，模型响应不阻塞换题、保存和继续练习。

已有生成流程保持“抽取题型 → 生成 → 结构检查”。下面的作答评价发生在用户提交答案之后，不是重新审查试卷。

## 2. 页面与导航

- 列表页 `/#/exam`：点击“查看试卷”、已完成卡片或生成完成弹窗按钮，均导航到 `/#/exam/{generation_id}`；在当前浏览器标签进入独立页面，支持后退、刷新和直接访问。
- 详情页：顶部为返回我的试卷、试卷标题、已提交题数、保存状态、作答记录入口和“完成本次练习”。
- 桌面主体：左侧窄答题卡，中间试卷正文，右侧问答 Agent。大约为 180px / 弹性主体 / 340px；中等宽度将答题卡折叠，优先保证题干可读。
- 试卷保留原卷题组、公共题干和子题层级；答题卡点击定位，正文整卷滚动，支持上一题/下一题。
- 手机采用“作答 / 问答”切换，答题卡以抽屉打开；切换不销毁作答或聊天状态。输入框固定在问答面板底部，消息区独立滚动。
- 试卷未生成成功时显示真实任务状态及返回入口；没有访问权或已删除时显示不可用状态，不进入空作答页。

布局示意：

```text
← 我的试卷     数据结构模拟练习     已提交 8/20 · 已保存     作答记录
┌──────────┬────────────────────────────┬──────────────────────┐
│ 答题卡    │ 第 9 题 · 选择题            │ 学习 Agent            │
│ 1 2 3 4  │ 题干、图片、公式              │ 当前关联：第 9 题       │
│ 5 6 7 8  │ ○ A …  ○ B …               │ 历史问答              │
│ 9 …      │ ○ C …  ○ D …               │                      │
│          │ [提交答案]                   │ [给我提示] [讲解本题]   │
│ 未答/草稿 │ [提示] [讲解] [看看我的思路]   │ 输入问题…       [发送] │
│ 已提交    │ 下一题…                     │                      │
└──────────┴────────────────────────────┴──────────────────────┘
```

## 3. 题目交互与评价

| 题型 | 作答方式 | 提交后的反馈 |
| --- | --- | --- |
| 单选 / 多选 | 单选框 / 复选框，复用课堂选项样式 | 按本卷参考答案比较选项集合，显示结果与解析 |
| 判断 | 正确 / 错误 | 按参考答案比较，显示解析 |
| 填空 | 每个空一个输入框，顺序编号 | 明确匹配规则的答案本地比较；涉及表达等价时给一次 AI 参考评价 |
| 简答 / 论述 | 多行输入，保留换行 | 一次 AI 参考评价，指出符合与待补充的要点 |
| 代码题 | 保留缩进的代码输入 | 首版给 AI 参考评价；没有执行器时不展示“运行通过” |
| 综合题 | 公共题干 + 可独立作答的子题 | 按叶子子题保存、提交和评价，父题汇总状态 |

题型直接读取已有生成结果，不再让模型重写或重新提取题目。使用稳定 `question_id` 标识，题号只负责展示。综合题显示“大题数 / 作答小题数”，提交进度按实际作答单元计算，避免重复计数。

每题提交后显示用户答案、评价和可展开的参考解析；“重新作答”创建新的提交记录，保留上次记录。答题卡区分未答、草稿、已提交；评价尚未完成、失败及已完成分别展示，不将等待或失败涂成错误。

普通题面接口不提前返回标准答案和解析。用户提交后可查看本题反馈；明确点击“讲解本题”或主动索要完整答案时，Agent 正常讲解，不人为限制求助。

填空不能仅因文本不一致判错：只做必要的空白等格式归一化，不随意删除数学符号、忽略单位或修改代码大小写。复杂等价表达走一次模型评价。模型输出只进行结构检查；失败显示“答案已保存，评价暂不可用”，允许重试该次评价，不重复提交作答。

首版不虚构原卷未给出的分值。汇总分别显示已提交/总数、客观题答对数、主观题评价状态；AI 评价不合并成确定性总分。

## 4. 草稿、提交与整卷记录

保存分三层：

1. **草稿**：输入立即写账号隔离的本地缓存，停止输入约 600ms 后同步服务端；切题时立即尝试同步。仅服务端确认后显示“已保存”；断网显示“待同步”，继续保留草稿。
2. **单题提交**：先持久化不可覆盖的答案快照，再执行评价。刷新可恢复已提交答案与评价状态；重复点击、网络重试使用同一请求 ID，不生成重复记录。
3. **整卷练习**：首次开始/继续时，通过显式写接口创建或恢复一轮练习；打开历史记录的 GET 不创建新轮次。“完成本次练习”先提交本轮未提交的有效草稿，保留空题为未作答，然后结束本轮。评价可以继续完成，不需要等待全部模型响应。

每轮记录开始时间、结束时间、试卷版本、逐题提交及汇总。用户可随时继续未完成练习、回看历史，或“重新练习”开启新轮；旧轮次与旧答案不被清空。首版不把起止时间差称为真实专注时长。

历史查看默认只读。换设备恢复服务端草稿和提交；不同设备同时编辑时，通过草稿 revision 检测冲突，保留待同步内容，提示选择本地或最新版本，不静默覆盖。

首页卡片增加“未开始 / 已提交 8/20 / 已完成一轮”等真实状态；“继续作答”进入当前轮次，“作答记录”进入历史轮次。

## 5. 右侧 Agent 的上下文

复用课堂的辅导方式、消息展示、引用、持久会话、轮次重试/取消、历史分页和模型网关，新增试卷上下文适配。

会话归属为 **用户 + 试卷版本**。同一试卷内切题、刷新和重新练习沿用该会话；每条消息标明发送时的题目及练习轮次。查看历史练习时，后续问题绑定被查看的历史作答，而不是最新答案。

每轮请求包含：

| 内容 | 来源与用途 |
| --- | --- |
| 试卷标题、生成要求、题型概要 | 说明本次练习范围 |
| 当前题目 ID、题号、题干、选项、公共题干和子题路径 | 确定本轮正在讨论的题目 |
| 当前轮次、具体提交 ID 或用户主动引用的草稿 | 区分“正在想”与“已经提交” |
| 对应提交的评价及评价状态 | 解释已有反馈，不把失败视为答错 |
| 本卷参考答案与解析 | 服务端按解题意图提供；提示模式避免直接揭底 |
| 当前试卷最近对话与有来源的历史摘要 | 支持连续追问 |
| 必要的原材料片段及页码 | 按需读取与当前题相关的内容，不默认塞入全部文件 |

当前题通过答题卡选择、输入焦点或题内求助按钮明确确定。输入框上方始终显示“关联第 N 题”，可取消关联。普通滚动不触发模型，也不让模糊的“这题”自动落到第一题。

快捷操作：

- **给我提示**：填入“先给我一个提示，不直接告诉我答案。”
- **讲解本题**：填入“请讲解这道题的思路、步骤和易错点。”
- **看看我的思路**：明确引用当前草稿或选中的已提交记录，填入对应问题。

快捷操作填入并聚焦输入框，由用户点击发送。发送时冻结上下文；等待回答期间切到另一题，回复仍标注原题，点击题号可回到原位置。聊天输入示例：“这道题哪里没想明白？可以问思路，也可以让我看看你的作答。”

Agent 以提示、解答和分析为主。沿用课堂关于“不编造用户作答、不把草稿当提交、不推断整体掌握”的规则。答案有疑问时可讨论理由，但聊天回复不会直接覆盖原题、参考答案或作答记录。

## 6. 现有实现与复用边界

2026-10-20 源码核对：

| 现有组件 / 服务 | 已有能力 | 本次适配 |
| --- | --- | --- |
| `frontend/src/liveLearning/Quiz.tsx`、`CheckCard.tsx` | 题面、逐题提交、选择题反馈、AI 参考评价、题目引用 | 抽出通用题卡与操作接口；新增多空、综合题层级和历史提交入口 |
| `frontend/src/liveLearning/QuizMarkdown.tsx`、`quiz.css` | Markdown、公式、习题视觉样式 | 直接复用 |
| `frontend/src/selfLearning/LearningAgent.tsx` | 对话面板、引用、快捷填入、历史加载 | 抽出展示层和会话接口，增加试卷场景文案与题目引用 |
| `backend/src/app/self_learning/check_service.py` | 不可覆盖的提交快照、幂等、客观判定、模型评价 | 复用判断与评价函数；用试卷自己的归属和记录服务承接 |
| `self_learning/agent_runtime.py` 及相关轮次服务 | 工具执行、预算、模型调用、持久轮次 | 复用公共运行能力，注入试卷上下文与工具，保留课堂适配 |
| `frontend/src/exam/ExamHome.tsx` | 首页生成、列表、内嵌预览 | 将查看动作改为路由导航，移除首页题目正文 |

课堂现有草稿仅保存在 localStorage；跨设备草稿需新增服务端能力。现有 `CheckCard` 和 Agent 的 API、权限与数据结构均绑定课程/知识点，不能仅改标题后直接挂载，也不应创建虚假课程来绕过这些约束。

先提取必要的展示组件、服务接口和纯判断函数，避免为一次适配改写整套课堂。课堂 API 与已有记录保持兼容。试卷的 Agent 工具只包括读取本卷题目、指定作答和授权参考片段，不默认暴露课程改写、资源生成或长期记忆写入操作。

## 7. 数据与接口建议

试卷版本使用冻结的结构化结果及其内容摘要。已生成试卷以稳定 ID 和版本读取；旧试卷没有显式版本时建立 v1 快照，不重新生成题目。参考答案保存在服务端私有投影，浏览器读取题面公开投影。

数据实体：

- `exam_practice_runs`：用户、试卷 ID/版本、轮次、进行中/已结束、起止时间。
- `exam_answer_drafts`：用户、轮次、题目 ID、结构化答案、revision、保存时间。
- `exam_answer_attempts`：不可覆盖的提交答案、请求 ID、题目版本、提交时间。
- `exam_answer_evaluations`：对应提交、评价方式/版本、等待/完成/失败、反馈；评价重试更新状态但不改原作答。
- `exam_agent_sessions / turns / messages`：试卷会话和逐轮不可变的题目、练习轮次、作答引用。

答案结构分别支持 `option_ids`、按空编号的 `blank_values`、`text`；父综合题本身无答案输入，子题继承公共题干。不将多空答案拼成无定位的长字符串。

建议接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/exam-generations/{id}/paper` | 公开题面、版本、题目层级、作答类型；补充现有接口 |
| `POST /api/exam-generations/{id}/practice-runs` | 幂等地恢复进行中轮次或显式开启新轮 |
| `GET /api/exam-generations/{id}/practice-runs` | 轮次历史 |
| `GET /api/exam-practice-runs/{run_id}` | 当前/历史轮次的草稿、提交和汇总 |
| `PUT /api/exam-practice-runs/{run_id}/drafts/{question_id}` | 带 expected_revision 保存草稿 |
| `POST /api/exam-practice-runs/{run_id}/answers/{question_id}` | 幂等提交答案，返回已保存事实及评价状态 |
| `POST /api/exam-practice-runs/{run_id}/finish` | 幂等批量保存待提交答案并结束本轮 |
| `POST /api/exam-answer-attempts/{attempt_id}/evaluate` | 重试单次评价 |
| `GET /api/exam-generations/{id}/agent/messages` | 当前试卷历史分页 |
| `POST /api/exam-generations/{id}/agent-turns` | 冻结题目及作答上下文，创建问答轮次 |
| `GET /api/exam-agent-turns/{turn_id}` | 查询答案、引用和真实状态；控制接口复用重试/取消语义 |

提交接口先落库并返回，再异步执行主观题评价；“保存成功”不依赖模型是否可用。首次打开题页不调用模型。整卷统计由已保存记录计算，Agent 不负责写进度。

所有写入校验用户、试卷版本、轮次和题目归属；请求 ID 与载荷绑定。删除试卷时同时删除其草稿、作答、评价和聊天，并停止对应未结束任务，避免后台完成后恢复已删内容。

## 8. 实施与验收

实施顺序：

1. 独立路由、题面适配和三栏/手机布局，所有查看入口统一导航。
2. 作答草稿、逐题提交、评价与整卷记录；复用课堂样式和判断函数。
3. 提取 Agent 公共展示/运行接口，接入试卷上下文、历史及题目引用。
4. 完成列表状态、删除联动及真实页面回归。

验收重点：

- 查看后地址变化；刷新、浏览器后退和直接链接正确。
- 默认 20 题和仿卷综合题均能作答，多空位置、单选/多选及公共题干正确。
- 输入离开再回来可恢复；换设备看到已同步草稿；重复提交只有一条记录。
- 评价失败仍保留答案，可重试；重做本题/整卷不覆盖旧记录。
- 请求第 3 题讲解后切到第 8 题，返回结果仍引用第 3 题及发送时的作答。
- 用户、试卷、轮次之间不混用答案或对话；历史上下文不偷换成最新作答。
- 手机端换题、切换问答、长回复和键盘打开时可以正常操作。
- AI 课堂原有作答与 Agent 流程回归通过；不新增生成阶段的内容复审。
