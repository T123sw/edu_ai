# 互动实验三栏与教学 Skills 后续计划

状态：2026-10-13。三栏前端已实现；本文的阶段契约、事件处理、工具与 Skills 工作流程均是设计草案，尚未实现。用户要求先完成前端，再讨论 Skills，故本轮撤回提前添加且未部署的后端辅导与事件代码。

## 1. 本轮前端范围

- 左栏：有序步骤、当前选择、实验简介、前后切换。当前选择只表示浏览位置，不显示未经定义的完成率或掌握标记。
- 中栏：交互实验；观察指标、笔记和历史移到“观察记录”页签。切换时保留实验 iframe、操作状态和未保存笔记。
- 右栏：当前步骤、本步任务参考和已有问答。任务参考标为“实验设计”，不是伪造的 Agent 发言。保留现有提问接口。
- 桌面三栏分别滚动，窄屏使用“步骤／实验／问答”面板切换。无自动发问、自动切阶段或完成检测。

## 2. 什么算“一步”

需要区分三层，避免界面导航、运行事件和学习判断混为一谈。

| 层次 | 定义 | 快速排序例子 | 是否直接触发引导 |
| --- | --- | --- | --- |
| 教学阶段（左栏的一步） | 围绕一个明确学习目标组织若干轮操作、观察与解释 | 比较不同基准策略的影响 | 进入阶段时可导学；切换不表示完成 |
| 完整操作 | 本阶段定义的一个有起点、终点、可观察产物的交互单元 | 固定输入数组，选择策略，运行到排序结束并得到统计 | 形成候选教学事件，仍需判断是否值得介入 |
| 原始动作 | 构成操作过程的点击、拖动、输入或动画帧 | 改策略、比较一次、交换一次 | 通常只更新状态，不直接调用模型 |

“完整操作”不是全站统一的一次点击，也不必总是整个实验结束。它应由生成时的教学目标和实验实现共同定义，运行时按契约验证。

| 实验类型 | 候选操作单元 | 结束证据 | 不能当作结束的信号 |
| --- | --- | --- | --- |
| 算法全程观察 | 一次排序运行 | 本轮算法终态、最终数组及统计 | 单个比较/交换动画帧 |
| 算法分区练习 | 一次分区 | 当前区间分区结束、基准位置和区间结果 | 任意一次“下一步”点击 |
| 参数模拟 | 一组参数下的规定观察周期 | 本轮运行结束及测量结果，或该实验明确定义的采样确认 | 任意拖动事件或通用的“静默几秒” |
| 连续探索 | 一次有明确观察意图的采样 | 用户确认采样，或实验声明的稳定条件及有效窗口 | 仅仅松开鼠标；值不再更新也可能是异常 |
| 编码/PBL | 一次阶段成果验证 | 对应代码版本的构建/测试/预览结果或明确提交物 | 每次按键、保存文件、生成了代码 |

一次阶段可能需要“基线运行 → 改一个变量 → 对照运行 → 解释差异”多轮操作。操作已结束、阶段目标已覆盖、用户表现出理解，分别保存，不互相推断。PBL 目前未实现，表中仅作为后续协议的适用性检查。

## 3. 先设计契约，再设计 Skills

现有 `plan.steps` 只有 title/instruction/question，不足以可靠判断交互边界。下一阶段先为少量实验样例设计并检验以下信息，再推广生成：

- 阶段：稳定标识、目标、允许操作、需要比较的变量、应收集的证据、可选反思点与进入下一阶段的规则。
- 操作：类型、开始条件、明确结束条件、取消/失败条件、观测项与单位、前后结果是否可比。
- 事件：事件编号、实验版本、操作编号、开始时所属阶段、参数快照、结果快照、时间与实际终态。
- 上下文：当前阶段、操作发生的阶段、最近有效对照、用户发言、先前问题和反馈；区别“未回答”和“回答错误”。

事件运行时负责排序、去重、版本核对和有界持久化。实验代码报告运行事实，模型负责教学判断，模型不能凭自然语言把运行状态或掌握状态改为完成。用户与浏览器内容均是观察材料，应用事件也不能被拼成高权限系统指令。

已有实验缺乏结束契约时，明确提供主动回顾入口或后续版本适配；不按按钮文字和一次结果更新就宣称完整操作成功。

## 4. Skills 是带状态和证据的教学流程

复用项目已有 [教学 Skill](../../backend/src/app/self_learning/skills/teach-current-topic/SKILL.md) 的加载、场景参考、来源和上下文边界思路；实验单独定义流程和工具适配，不把课堂阅读状态直接当作实验状态，也不只是把现有问答提示词移进一个文件。

建议使用一个实验教学入口 Skill，按场景加载必要子流程；不要求每个子流程都是独立 Agent 或每个环节都调用模型。

| 工作环节 | 输入与动作 | 产出和退出条件 |
| --- | --- | --- |
| 接收与校验 | 用户消息或阶段/操作事件；核对身份、版本、阶段归属、去重 | 一条可处理输入，或静默忽略重复/无效事件 |
| 装配现场 | 读取阶段目标、真实控件、操作前后状态、可比较的历史结果和最近对话 | 有界上下文与证据缺口；不拼全量聊天 |
| 选择教学流程 | 判断是首次进入、操作回顾、用户追问、解释反馈还是阶段衔接 | 加载对应 Skill 参考和允许工具；用户问题优先 |
| 执行教学动作 | 先读证据，再选择说明、提示、比较、反问或安静等待 | 一条有事实依据的教学回应，或明确保持安静 |
| 接收后续反馈 | 区分用户在回答问题、另提问题或继续操作 | 承接其推理；不因为没回答就打断后续实验 |
| 记录与衔接 | 保存本轮证据引用、发问、用户反馈和未解决事项 | 更新阶段工作状态；切换仍由用户控制 |

拟定的场景参考：

1. **阶段导学**：读取目标和可用操作 → 判断是否已介绍 → 给一个可执行起点 → 等待用户操作。刷新不重复开场。
2. **操作回顾**：确认完整操作有效 → 读取前后快照/可比历史 → 找到值得讨论的变化 → 只提出一个贴合证据的问题 → 等待反馈或下一次操作。
3. **追问与解释反馈**：解析用户问题/上一问的回答 → 有缺口时读取当前实验规则 → 回答或指出推理中的具体问题 → 按需提出下一次可验证的尝试。
4. **阶段衔接**：读取该阶段的操作与反馈记录 → 区分已观察事实、用户解释和仍未知之处 → 简短总结并建议下一阶段；不自动切换或宣称掌握。

所需工具能力先定义为接口：读取当前实验上下文、读取有编号的操作证据、比较可比结果、读取科学模型/控件说明、记录带来源的教学观察。工具应执行真实读取和确定性检查，不能让模型用编造字段代替工具结果。工具名称、schema 和复用哪个运行器，要在下一阶段审查现有学习 Agent 执行链后定稿。

## 5. 干预节奏和失败处理

- 完整操作结束只产生候选事件。没有新变化、同一轮已回应、用户正在输入或已有问题待讨论时，可以合并记录或保持安静。
- 一次通常只提一个问题。用户要求直接解释时先回答，不强行套反问模板。
- 用户继续操作无需先回复；新操作与用户问题有明确顺序和归属，避免旧回答被当作新阶段指令。
- 取消、重置、错误、重复通知不触发“你已完成……”；旧操作的迟到结果不能覆盖新操作。
- 模型失败时保留操作事实，展示真实失败并允许重试。事件幂等和教学回应幂等分别处理。

## 6. 后续实施顺序与验收

1. **当前：完成三栏页面**。本轮完成布局、状态保留和已有问答回归。
2. **定义一步和事件契约**。用快速排序、参数模拟各一个样例列清阶段、操作、前后证据和终态；先回放事件证明无误报，再改生成协议。
3. **接入 Skills 与工具**。明确根角色、Skill 加载、上下文、读证据工具、状态记录与退出条件，复用可靠的运行基础设施。
4. **真实教学闭环验收**。覆盖进入、运行、提问、反思反馈、再次运行、跳步、刷新、重复通知、取消、模型失败及迟到回答。既验证不会刷屏/丢失状态，也用真实模型核对回应是否引用本轮实际证据。

本轮不会把上述规划描述为已上线能力。
