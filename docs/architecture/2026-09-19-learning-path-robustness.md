# 学习路径总控 Skill：覆盖、预算与不足退出

在[连续 Harness 会话](2026-09-19-continuous-learning-path-harness.md)基础上优化五项审查发现。仍使用单个总控 Skill 和真实 MCP 工具，沿用独立审阅，不增加模型复审层。

## 多附件与网络预算

`reads` 保留累计读取次数，新增 `upload_reads`。上传材料和网络正文分开计量：附件额度 `max(8, 2 × 附件数)`，网页额度 8；仍受任务 SQL 总预算、60 个研究动作及会话时间限制。旧检查点根据已保存上传片段推导计数下界，不退还已发生的总读取。

30 份附件不再占满所有候选位置：候选上限为附件数加 30，保留网络搜索结果。该调整解决 9 份以上核心附件无法全部读取的固定数量冲突，不表示任意长度的 30 份文档都能在上下文/时间预算内完整处理。

## 服务异常

HTTP 408/429/5xx 与连接/超时错误转换为 `RecoverableSourceError`。工具向同一会话返回可恢复错误；同查询或来源最多连续失败两次，之后拒绝再次实际调用，模型可换查询/来源或报告不足。失败同样计入来源、动作和 SQL 账本。

计数随检查点保存，进程恢复不清零；成功调用清除对应连续失败计数，用户显式开启新 attempt 时清除这些连续失败限制，保留已消耗总预算。缺少 API key、认证/权限拒绝、无效服务响应、租约失效和总预算耗尽仍停止执行。

## 需求覆盖

`finalize_research_summary.coverage` 按需求逐项输出：

- requirement_id：真实需求 ID，必须完整且唯一。
- kind：knowledge 或 constraint；语言、时间和教学顺序等约束可以不引用知识结论。
- status：covered、partial、missing。
- finding_ids：已保存并选入本次汇总的结论 ID；covered 的知识需求必须有证据结论。
- reason：证据支持范围、约束落实方式或具体缺失。

新连续流程提交路径前要求 coverage 完整且全部 covered，路径节点需使用覆盖表中支持其知识需求的结论。旧 schema 保留缺省空 coverage 以读取历史数据，但新连续流程不允许空表提交；恢复旧汇总时复用已有 findings，重新完成覆盖判断。

这些是结构与关联检查，不代表程序证明了论断正确。Skill 明确禁止把知识目标改标 constraint，或把可运行程序降为伪代码后宣称 covered；已有独立审阅检查这些语义问题。Skill 同时补充岗位/背景材料与教材的用途区别、版本适用范围、冲突来源比较及无法解决争议的缺口表达。

## 资料不足退出

新增 `report_research_blocker`，接收 reason、完整 coverage、suggested_actions；至少一条需求 partial/missing。保存后停止工具执行，清除旧路径与过时汇总，保留正文、结论和覆盖原因以便恢复。

Runner 使用现有失败状态和明确的 `RESEARCH_INSUFFICIENT` 错误码，不新增数据库状态。`intermediates` API 返回 `research_blocker`，包含缺口与建议，不进入材料生成。该字段已接入后端 API；本次没有增加前端专用展示组件。

正常路径与资料不足报告保存成功后，provider transport 直接向 SDK 返回程序生成的终态结束消息，不再为收尾调用外部模型。这不是模型输出，也不记为模型 API 调用；避免已完成业务因最后一次无必要请求的累计上下文超限而失败。

上下文或硬预算在业务完成前耗尽仍会明确失败，不通过静默丢失必要证据或增大模型窗口掩盖。
