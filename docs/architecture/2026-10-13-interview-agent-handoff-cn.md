## 产品背景与价值主张

本轮讨论始于 Edu_AI 缺少让学习者主动使用的吸引力。用户多次指出：生成课程、学习资料、学习路径和普通辅导，如果没有明显的体验优势，不如直接与通用模型对话。

用户对“提前经历一次现实考验”产生了明确兴趣，并进一步把它收敛为求职面试项目。因此，后续设计应围绕一场能实际参加的模拟招聘展开，交付真实作答记录和有依据的复盘。

可采用的产品表述：

> 带着你的简历和目标岗位，提前经历一次完整面试，找出回答、项目经历和现场解题中的不足，再针对性重练。

完整招聘流程可以分场次进行，也允许单独练某一轮。具体公司流程需要来自用户材料或可靠来源；未提供时使用明确标注的模拟模板，不声称复现某公司内部题库或真实录用决策。

## 建议的使用流程

本节为接续设计建议，尚未由用户逐项确认。

| 阶段 | 用户操作 | 系统应交付的体验 |
| --- | --- | --- |
| 准备求职材料 | 上传简历，粘贴岗位描述，可选添加项目说明 | 显示解析出的经历、目标岗位和缺失信息，允许更正识别错误 |
| 选择模拟 | 选择完整流程或单轮，设定语言、时长及模式 | 清楚展示本次包含哪些环节，内部形成考查范围与评价依据 |
| 设备检查 | 测试麦克风、扬声器，确认语音可用 | 能听到面试官、看到自己的识别结果，失败时有明确恢复入口 |
| 参加模拟 | 自我介绍、回答追问、完成笔试或算法题、反问 | 面试官根据材料和实际回答推进，作答和语音共享同一个场次上下文 |
| 查看复盘 | 回看回答、代码和评价 | 每项反馈定位到具体证据，给出可执行的改进建议 |
| 针对性重练 | 选择薄弱环节重试 | 使用新的追问或同类题验证改进，保留与上次的比较 |

建议的计算机岗位流程模板为：材料准备 → 笔试或算法测评 → 自我介绍 → 项目深挖 → 技术问题与现场编码 → 用户反问 → 复盘。实际顺序和是否包含某轮由模板及用户选择决定，不要求所有岗位共用同一流程。

简历解析应区分原文事实、用户补充与模型推断。模型发现简历中的技术点可以据此提问，不能虚构用户做过的项目、指标或工作经历。

## 建议的面试现场交互

现场根据环节变化，保持同一场次连续性：

- 语音面试：面试官状态、当前问题、可选字幕、麦克风与结束回答操作。保留用户思考空间，避免短暂停顿就抢话。
- 笔试：题目、答题区、题目导航和剩余时间；结束后统一评价。
- 算法题：题面、约束、样例、代码编辑器、运行输出与提交入口，同时保留语音讨论思路的能力。
- 项目深挖：问题绑定简历或项目材料中的具体内容；必要时展示原文位置。
- 复盘：原回答或代码、发现的问题、评价依据、改进示范和重练入口并排呈现。

示例：用户简历写“通过缓存优化提升接口性能”。面试官应围绕优化前指标、瓶颈定位、缓存策略、失效与一致性、验证方式持续追问；问题应受到用户实际回答约束。

建议区分两种模式：

| 模式 | 现场行为 | 评价方式 |
| --- | --- | --- |
| 正式模拟 | 按约定规则进行，通常不现场讲解答案 | 结束后复盘；记录独立完成情况 |
| 辅导训练 | 可以暂停、请求提示、查看局部示范和重做 | 标记使用过的帮助，不与正式模拟成绩直接混比 |

实时追问可以检验边界条件、具体贡献、原理和取舍，但不需要以无依据的打压制造“真实感”。用户反问环节也应有明确的模拟身份与信息边界。

## 实时语音设计要点

TTS 负责面试官发声。完整体验还需要音频采集、语音识别、用户是否说完的判断、轮次编排，以及用户插话时停止旧音频和处理旧回答。

建议的逻辑链路：

```text
用户音频 → 识别与轮次判断 → 面试 Agent → 文本与语音生成 → 播放
                         ↓
              场次记录、环节状态、作答证据
```

下一窗口应比较“流式 ASR + 文本模型 + 流式 TTS”与端到端实时语音方案，结合可用服务、中文识别、技术术语、延迟和成本选择。当前没有确定供应商、模型、音色或传输协议。

必须在设计中覆盖：

- 区分识别中的临时文本与用户已提交的回答；临时识别结果不能直接计入最终评价。
- 用户插话时立即停止播放，取消或丢弃旧轮次迟到的音频与回答，保留合理的已发生记录。
- 区分模型已生成、语音已合成与用户实际已听到的内容，避免取消后仍假设用户听完问题。
- 长回答、思考停顿、麦克风静音和明确结束回答的处理，提供手动结束回答的兜底操作。
- 在编码环节允许安静思考，避免把无语音持续解释为结束作答。
- 断线后恢复场次；ASR、模型或 TTS 失败时显示真实状态，可重试或切换文字继续，不能伪装成语音已成功。
- 评估回声、噪声、技术缩写和中英文混说。低置信度的关键识别内容应能澄清或更正，避免识别错误被当作知识错误。

可先做文字流程验证和可中断语音小样，再扩展完整体验；这只是开发顺序，实时语音仍属于目标交付。延迟目标与验收阈值需要实测后确定，不在本文虚构承诺。

## Agent 如何推进面试

建议由服务维护明确的场次与环节状态，Agent 在当前环节内决定提问、追问、澄清、转题或建议结束。

每次决策读取必要上下文：简历事实、岗位要求、当前环节、已考查能力、尚缺的证据、近期回答、相关代码运行结果和剩余时间。

| 动作 | 典型依据 |
| --- | --- |
| 提出主问题 | 当前环节有尚未覆盖的目标 |
| 追问 | 回答缺少依据、出现矛盾，或有值得深入的具体细节 |
| 澄清 | 用户表述或语音识别存在歧义 |
| 切换问题 | 当前能力已有足够观察，或剩余时间需要重新分配 |
| 切换环节 | 当前轮次完成，满足流程条件 |
| 结束并复盘 | 流程结束、时间到达或用户结束模拟 |

避免固定题单机械轮播，也避免无界追问。流程服务验证状态转换、保存结果和控制计时；模型不能仅凭一句“已经提交”代替实际作答记录。

第一版可从一个面试官 Agent 和单独的复盘评价步骤开始。“多轮面试”和“多个面试官角色”不要求同时运行多个 Agent。是否进一步拆分由实际需要决定。

建议的数据对象包括：候选人材料及版本、岗位目标、模拟流程、场次、环节、问题及追问关联、回答及语音轮次、代码提交、执行结果、评价依据与重练记录。答案、评分规则与隐藏测试应由服务端按环节控制可见性。

## 笔试与算法题的边界

用户明确提到笔试和算法题，不能在首版规划中无说明地遗漏。首版支持哪类题、哪种编程语言，需要结合目标岗位确定。

建议优先采用经过验证的题目或题目模板，保存题面、约束、样例、参考解法与测试版本。自动生成题目也需要校验可解性、答案与测试一致性。

代码运行与评价应分开记录：

- 样例运行用于调试，正式提交使用服务端测试。
- 运行事实包括退出状态、测试通过情况、执行限制和错误输出，不能由模型编造。
- 思路、复杂度和表达评价可以由模型辅助，但应引用用户实际解释和代码。
- 区分学生代码错误、题目问题与运行服务故障；不能把基础设施失败算成答错。
- 使用隔离执行环境，设定资源、时间和网络边界，避免直接在应用服务主机执行用户代码。

## 复盘与重练建议

每条关键反馈应包含“证据 → 判断 → 改进动作”。例如指出用户回答中的一句话、遗漏的边界条件、未通过的测试，而不是只有一个总分或“基础需要加强”。

客观结果与 AI 评价分别展示。允许用户更正语音转写、指出简历解析问题和对评价提出异议，并保留修订记录。模拟表现不等同实际录用概率。

建议保存以下复盘信息：

- 各环节表现、覆盖的能力和未充分考查的部分。
- 值得保留的回答、具体不足，以及对应的时间或文本位置。
- 算法题运行结果、代码版本和思路评价。
- 需要补充的知识、需要重新组织的项目讲述，以及下一次重练内容。
- 使用提示、重做或中途改动的记录，便于解释比较结果。

原始音频的保存策略和期限尚未确定。简历、录音、代码与评价默认按个人私有材料设计，后续需明确查看、更正和删除行为。模拟求职不包含真实投递简历、联系招聘方或代发消息。

## 首版实施建议与待定事项

建议先做一个指定计算机岗位的完整样例，打通“简历与岗位 → 语音面试 → 一道算法题 → 证据复盘 → 重练”，再扩展笔试规模、岗位和多轮模板。最终首版范围由后续设计确定。

接续窗口优先处理以下决策，已有明确答案的不要反复询问：

| 待定事项 | 建议的处理方式 |
| --- | --- |
| 新项目位置与复用边界 | 明确新仓库路径、账号与服务是否独立；在此之前不大规模改动 Edu_AI |
| 首发岗位与目标用户 | 从用户最熟悉或最容易验证的计算机岗位切入，确定校招或社招场景 |
| 首发语言与流程 | 确定中文或双语，以及笔试、算法与技术面覆盖到什么程度 |
| 语音方案 | 审核现有能力与可用服务，用真实音频验证后选择，不只看接口名称 |
| 编码环境 | 选择首个语言、运行沙箱和题目来源，明确部署资源 |
| 界面与账号 | 建议桌面 Web 优先以支持编码；具体视觉与登录方式尚未确认 |

推荐推进顺序：

1. 阅读本文，提炼已确定事项，检查工作目录与可复用代码。
2. 形成可讨论的首版用户流程和页面草图，收敛少量影响架构的选择。
3. 验证实时语音的识别、首音、打断与恢复，以及代码沙箱运行。
4. 按一个岗位实现完整场次的纵向流程，再扩展题型与招聘轮次。
5. 用真实简历样例、岗位材料和真实音频验收，验证用户能完整参加并获得有依据的反馈。

建议验收至少包括：简历事实准确引用；追问与回答相关；笔试与代码作答可靠保存；打断后旧音频不继续播放；断线恢复无重复提问或提交；运行故障与答错区分；复盘可定位证据；重练保留可解释的比较；不同账号材料隔离。具体性能阈值需另行确定。
