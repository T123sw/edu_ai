# 基于上传资料与参考试卷的模拟考试调研

日期：2026-10-15。范围：需求整理、开源项目与现有源码核查；尚未实施考试功能或运行真实试卷生成评测。面试 Agent 方向暂放。

2026-10-16 更新：按用户“保留 DeepTutor 核心逻辑、尽量不要过度筛减”的要求，进一步完成[DeepTutor 迁移评估](2026-10-16-deeptutor-exam-migration-assessment-cn.md)。DeepTutor 的接入边界与迁移顺序以该文档为准；本篇保留项目对照和需求研究。

结论：本功能的核心是识别参考试卷并保持其结构，生成可作答的新卷。DeepTutor 的逐题仿题路径最值得参考；Exameow 适合参考资料出题与考试交互。建议在 Edu_AI 现有 React、FastAPI、文档解析和测评能力上增加独立的模拟考试流程，先验证整卷结构保真和答案质量，再决定借用哪些外部代码。

## 用户已确认的需求

- 用户上传资料，并通过提示描述本次考试要求。
- 资料不包含具体试卷时，将其作为出题上下文。
- 资料包含具体试卷时，分析原卷，以原卷为模板生成相似新卷。
- 默认保持题型、题量和相应排列结构。例如原卷为 10 道选择题、5 道填空题，新卷也应如此。
- 可以参考对应原题的考点。例如原卷第一题考快速排序，新卷第一题也可以围绕快速排序生成新题。
- 交付用于模拟考试的新题，不是仅提取或重复展示原题。

逐题考点是否必须完全一致、难度是否严格跟随原卷、分值和时长是否沿用原卷，尚未确定。下文关于这些事项的处理均为建议，不是已确认规则。用户当前要求是调研，不是启动实现。

相关旧设计为[学习任务强制测评闭环](../superpowers/specs/2026-08-12-learning-task-assessment-loop-design-cn.md)，可复用其版本、作答与评分思路，但不能直接沿用教师审核和课程任务发布流程。新模拟考试入口目前仍为[占位页](../../frontend/src/practice/PracticeHome.tsx)。

## DeepTutor 的实现与缺口

其 PDF 仿题路径为：解析试卷 → 提取逐题内容、题型、估计难度和可用参考答案 → 转成逐题模板 → 每个模板生成一道新题。模板携带原题，生成提示要求参考原题风格和难度。相比把整份原卷仅作为背景材料，这一结构更接近本需求。

源码依据：[试卷到模板的转换](https://github.com/HKUDS/DeepTutor/blob/6cf793bd868ba5ecbe64722936d4be8fab5a01df/deeptutor/agents/question/mimic_source.py)、[逐题生成管线](https://github.com/HKUDS/DeepTutor/blob/6cf793bd868ba5ecbe64722936d4be8fab5a01df/deeptutor/agents/question/pipeline.py)、[中文生成提示](https://github.com/HKUDS/DeepTutor/blob/6cf793bd868ba5ecbe64722936d4be8fab5a01df/deeptutor/agents/question/prompts/zh/pipeline.yaml)。

不能原样接入的原因：

| 源码观察 | 对我们需求的影响 |
| --- | --- |
| 仿题入口 `max_questions` 默认值为 10，模板转换按该值截取题目 | 15 题原卷走默认路径可能只生成前 10 题，不能作为完整仿卷 |
| 抽题提示只传入解析正文前 15,000 个字符 | 长卷后半部分可能没有进入抽题步骤；调大题数上限也无法修复这一遗漏 |
| 选择题要求 A–D 四个选项和单个答案字母 | 不能完整表达多选题或不同选项数量的原卷 |
| 未识别题型降级为 `written` | 模板题型可能悄悄改变，不适合对题型一致性作承诺 |
| 当前 `QuizTemplate` 没有专门的分区、分值、小问层级和逐题考点字段 | 要支持整卷结构、复合题和考点逐项对照，需要补充数据模型 |
| 完成数量与已提取模板数量比较 | 即使生成阶段全部成功，也不代表原卷已经被完整提取 |

数量默认值见[能力入口](https://github.com/HKUDS/DeepTutor/blob/6cf793bd868ba5ecbe64722936d4be8fab5a01df/deeptutor/agents/question/capability.py#L221)；正文截断见[题目抽取器](https://github.com/HKUDS/DeepTutor/blob/6cf793bd868ba5ecbe64722936d4be8fab5a01df/deeptutor/tools/question/question_extractor.py#L202)；模板和选择题规则见上述生成管线。它提供了实现参考，但还不能据此认为任意原卷都能完整、准确仿写。

## Exameow 的适用范围

它的出题参数支持用户补充要求和各题型数量，适合“普通资料作为上下文”的路径。已查看的 Rust 生成提示没有先抽取原卷逐题结构，而是根据资料和用户设置生成题目。其默认规则还要求不同题目不要考查同一概念；如果原卷多次考查快速排序，这一规则可能与忠实跟随原卷的目标冲突。

因此，手工设置“10 道选择、5 道填空”不等于系统已经自动识别和还原原卷。它的模拟考试组件主要按题库中的可用题型和数量配置组卷，适合借鉴作答体验，不宜作为仿卷引擎的直接替代。

源码依据：[出题参数与提示](https://github.com/heshengtao/exameow/blob/960edd5718846acb1266e3fc4c56b5e1725714a5/packages/core/src/exam/prompt.rs)、[模拟考试配置](https://github.com/heshengtao/exameow/blob/960edd5718846acb1266e3fc4c56b5e1725714a5/frontend/src/components/practice/MockExamConfig.vue)。

## 建议的功能流程

用户入口维持简单：上传文件、填写要求、开始生成。系统内部区分“出题依据”和“试卷模板”，无需强迫用户先理解两套模式。

```text
上传资料和要求
  → 解析文件，识别资料用途
  → 无参考卷：依据资料和要求拟定试卷结构
    有参考卷：抽取并核对完整原卷结构
  → 为每道新题确定题型、对应考点和出题要求
  → 逐题或分批生成题目、答案与解析
  → 核对整卷结构，定向修正有问题的题目
  → 进入模拟考试
  → 提交后查看评分、解析与复盘
```

建议将教材中的零散练习与完整参考卷区分开。遇到“教材＋试卷＋答案册”的组合时，教材用于知识依据，试卷提供结构，答案册只关联对应原题。若上传多套卷，应根据用户提示确定主模板；选择多套分别仿写还是合成一套，需要在后续产品设计中明确，不能无提示地将其题量相加。

### 先建立逐题结构

试卷结构至少记录：章节/大题、原题编号与顺序、具体题型、选项数量、子题关系、考点、原文位置及图片关联。原卷明确给出的分值和时长可记录；缺失信息和模型估计应分开。

| 原卷位置 | 提取出的约束 | 新卷中的对应内容 |
| --- | --- | --- |
| 第 1 题 | 单选、4 个选项、快速排序一次划分 | 更换输入数组，保留明确的划分规则，生成新选项与答案 |
| 第 2 题 | 单选、二分查找边界 | 更换场景或数据，考查相应边界处理 |
| 第 11 题 | 填空、栈的性质 | 改写情境，生成新的填空题 |
| 全卷 | 10 道选择＋5 道填空 | 总计 15 道，题型和排列对应 |

考点一致还不足以保证相似：把“手算一次快速排序划分结果”改成“背诵平均时间复杂度”，虽然同属快速排序，所需能力已经变化。建议同时分析任务动作，如记忆、解释、计算、执行追踪、证明或设计。难度相近只能作为待验证目标，不应宣称精确等难。

### 保证整卷完整与新题可解

- 题型、题量、顺序、选项数量和子题完整性用程序核对，不能仅依赖生成提示中的一句要求。
- 长卷按页或题组解析并处理跨页衔接，最后核对题号和分区统计；不静默截断原卷。
- 对扫描件、表格、公式和图题保留原文位置与图像对应。无法识别的题应明确标出，不能自动改成文字题充数。
- 更换参数后重新求解。例如快速排序应明确枢轴与划分方法，不能沿用原题答案。
- 单选检查唯一正确答案，多选保留多答案结构；填空支持必要的等价答案和多个空位。
- 缺少原卷答案不阻止分析结构，但新卷答案须独立生成和核查。原卷已有答案也只是参考，不能无条件照用。
- 只重试失败题目并保留已完成结果；整卷条件满足后再标为可考试，避免把部分成功显示成完整交付。

### 作答与结果

建议首版具备题目导航、作答自动保存、刷新恢复、交卷和解析。若采用限时模式，应保存服务端截止时间，刷新不能重置计时；计时、自动交卷和重考规则仍需在产品设计阶段明确。

答案与评分依据保留在服务端，考试前不随试题响应发给客户端。每次作答绑定不可变的新卷版本；重新生成新卷不得继承旧卷答案。

客观题优先确定性评分。主观题可在个人模拟场景提供按评分要点给出的 AI 参考评价，并展示对应回答证据；不要直接套用旧教师体系中“必须教师复核才能完成”的流程。

## 建议先验证的样本

先用真实材料验证以下场景，再选择正式集成方案：

| 样本 | 核查重点 |
| --- | --- |
| 无试卷的讲义＋用户提示 | 资料作为上下文，题量与类型符合要求 |
| 10 道单选＋5 道填空的完整试卷 | 原卷识别出 15 道，新卷同结构，逐题对应无漏项 |
| 含多选和重复考点的试卷 | 不合并成单选，不因去重而删除原卷应有的考点覆盖 |
| 超过 15,000 字符的长卷与跨页题 | 后半部分、跨页选项和子题完整 |
| 扫描件、公式和图题 | 题面与配图完整，不凭空补题 |
| 无答案卷、单独答案册、教材与试卷混传 | 文件角色与答案归属正确 |
| 用户要求改变难度或题量 | 显式要求如何覆盖模板默认值有清晰规则 |
| 刷新恢复、交卷与生成第二套卷 | 考试状态可靠，新旧题目和作答隔离 |

结构准确性可以逐项统计；考点对应、任务相似性、答案正确性和题目歧义需要人工抽查与适用的计算验证。尚无这些实测结果，因此暂不估计稳定成功率或承诺任意学科都适用。

优先验证“完整读懂一套原卷并生成结构一致的新卷”。待这个核心成立，再扩充考试设置、结果统计和错题训练。
