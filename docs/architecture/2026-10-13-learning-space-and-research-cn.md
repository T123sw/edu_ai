# 学习空间与科研实践衔接

日期：2026-10-13。状态：前端入口和本地项目草稿已实现；科研 Agent、实验执行、成果同步仍为后续建议。面试 Agent 按独立产品推进，见[交接文档](2026-10-13-interview-agent-handoff-cn.md)。本次未部署业务站点。

## 产品主线

主体围绕“学一个主题 → 找到一个问题 → 亲手验证 → 留下有依据的成果”组织。课程提供知识和资料，实践承接用户自己的问题，作品保存可以回看、修改和展示的结果。用户也可以直接发起独立实践，不强制先完成课程。

例如：学习过拟合 → 提出“模型越复杂越好吗” → 固定数据划分、比较不同复杂度模型 → 保存训练与验证结果 → 写出结论及局限 → 回到课程查阅正则化。科研模块的价值应来自可恢复的项目、实验和证据记录。

## 本轮实现

| 入口 | 当前行为 |
| --- | --- |
| 学习空间首页 | 学习目标输入、课程创建原流程、模块入口、继续最近课程、最近学习与共享课堂 |
| 科研实践 `#/research` | 建立、编辑、保存、删除个人实践草稿；项目名称、研究问题、期望成果、已有准备 |
| 课堂“以本节发起实践” | 带入课程、知识点、当前资料及可用版本号；草稿可回到对应资料 |
| 个人作品 | 复用现有资源中心；本轮未将草稿伪装为已完成作品 |
| 面试 Agent `#/interview` | 独立产品的筹备说明；没有真实面试启动或外部地址 |

预览入口和登录后的 `LiveApp` 使用同一组首页、导航和实践组件。已有课堂学习、课程准备、原工作台、资源中心仍走原有服务。

草稿保存在当前浏览器的 localStorage，键为 `edu-ai:research-drafts:v1:<owner>`，区分真实账号、预览身份和审阅身份；这只是界面数据隔离，不是服务端访问控制。换设备或清理浏览器数据无法恢复。保存失败会保留输入并展示错误；来源不可用时保留原引用文字，资料版本变化时提示正在返回当前版本。

## 科研 Agent 后续如何融入

以一个“实践项目”为独立工作单元，关联一个或多个课程知识点。不要直接把课程的完整聊天历史搬入项目；仅引用用户选择的资料、问题和必要学习摘要。课程中的知识点会话继续独立存在。

建议实践工作区包含三块：左侧项目阶段和产物目录，中间当前实验/笔记/结果，右侧科研导师。用户提交回答、修改方案、运行实验、查看失败日志都属于项目事件，聊天只是交互方式之一。

| 阶段 | 用户在做什么 | Agent 的下一步依据 |
| --- | --- | --- |
| 明确问题 | 写出问题、目标与限制 | 缺少可验证问题时澄清；信息充分时给出可编辑假设 |
| 设计验证 | 选择数据、对照、指标 | 检查方案能否回答问题；依据用户修改更新计划 |
| 执行与观察 | 写代码、运行、记录现象 | 只根据真实执行状态、日志和产物判断；失败时定位原因 |
| 解释与复盘 | 对照结果，写结论和局限 | 检查结论是否有证据，提示补充实验或回查知识 |
| 保存成果 | 选择报告、代码与结果 | 用户选择后写入个人作品，保留来源与实验版本 |

实现上可采用明确的项目阶段和受控动作，由 Agent 在当前阶段提出下一步，服务端校验动作、保存事件和产物。先做一个导师 Agent；课程准备、资料检索和代码执行作为能力调用，避免首版承担多个角色间的复杂协作。

需要补课时，科研导师给出“回看这节资料”的明确入口；原课程缺少材料时，再调用课程准备能力补充指定主题。补充学习后回到同一个实践项目。科研产物可以作为学习证据，但“做完实验”“用户自评掌握”“系统有证据支持某能力”必须分开记录，不能自动互相替代。

## 建议实施顺序（尚未实现）

1. 服务端项目 CRUD、鉴权、版本冲突处理，支持用户主动迁移本地草稿。
2. 问题澄清、实验方案和项目独立会话；先让一个真实主题的学习与项目往返顺畅。
3. 加入一种有限的实验执行环境，保存输入、环境、运行状态、日志和产物；未运行不能显示执行成功。
4. 结果复盘与作品入库，建立项目产物到课程知识点的证据引用。

首个候选样例可选“小型机器学习对照实验”，用于验证这条流程，不代表已确定仅支持这一学科。面试产品保持自己的简历、岗位、会话和评分数据；未来用户可主动导出作品作为求职材料，本轮不自动跨产品传输。
