# 模拟实验分步操作与反馈实施设计

日期：2026-10-14。状态：原方案留档，发布暂停。用户重新明确了原理演示、手动练习、性能测试、自由探索的教学形式，后续以[四阶段教学实施计划](2026-10-14-experiment-teaching-phases-plan-cn.md)为准。已有存储和恢复能力作为复用基础，本文不再作为当前教学交互的实施基线。

继续复用 MAIC-UI 原生生成与视觉能力，为一个实验增加统一的步骤控制与操作反馈协议。引导阶段按学习目标开放操作，末项“完整实验 · 自由探索”开放全部实验配置；两个模式共用实验模型，分别保存运行状态。每次操作必须产生可见响应和可解释的结果。

本设计细化并替代[此前教学 Skills 后续计划](2026-10-13-practice-skills-plan-cn.md)中的步骤控制与事件契约草案。即时反馈使用本地规则；自动模型介入与 Skills 调度不作为本轮分步实验的前置条件。

## 用户流程与界面

左侧按顺序列出引导步骤，最后固定显示“完整实验 · 自由探索”。步骤状态显示“未开始、进行中、操作完成”；不会把点击步骤或操作完成显示为知识掌握。默认进入第一步；后续引导步骤依赖前一步的有效结果，暂不可进入时说明还缺什么。自由探索入口始终可用，进入它不会补齐引导步骤进度，也不要求用户先回答 AI。

中间从上到下保留展示区、操作反馈条、本步按钮与配置。不相关控件隐藏，本步相关但当前条件不足的控件置灰并给出理由。画布点选、拖动、键盘操作与按钮遵循同一动作规则。左侧负责教学目录，不在原生文档中再生成第二套教学导航。

反馈条包含“刚才做了什么、发生什么变化、为什么、下一步可以做什么”。正常操作用简短就地反馈；错误操作突出原因并允许重试；阶段完成展示完成依据及“进入下一步”，不强制自动跳转。历史反馈可展开查看，不把每次反馈都追加为 AI 聊天。

右侧保留当前任务、思考问题和问答。AI 根据当前步骤、最近动作与反馈、实际状态解释原因；只有用户提问或点击提示才请求模型。即时反馈不依赖网络与模型响应。

## 快速排序首个实现样例

首版固定使用 Lomuto 分区规则：当前基准移到区间末尾，扫描元素小于等于基准时进入左侧，其他元素留在右侧。界面明确这是一种分区实现。重复值按同一规则处理，动画、计数、反馈与验证器保持一致。

| 阶段 | 可执行操作 | 操作反馈 | 操作完成依据 |
| --- | --- | --- | --- |
| 选择基准 | 点击元素、确认基准、重选 | 高亮选择；确认后解释基准角色并演示移至末尾；重复选择提示未变化 | 有效基准已确认，工作数组与基准索引一致 |
| 完成一次分区 | 判断当前元素归左或归右、执行下一动作、重试本步 | 判断正确后执行对应扫描或交换；判断错误保留数组，解释比较关系；无需交换时明确说明原因 | 扫描结束、基准归位、左右区间满足规则，且实际完成本步操作 |
| 处理子区间 | 选择待处理区间、单步、播放本区间、暂停、调整速度 | 高亮当前递归区间；比较与交换同步解释；单元素区间提示无需继续拆分 | 待处理区间为空，结果有序且元素及重复次数与初始数组一致 |
| 完整实验 · 自由探索 | 修改数组与规模、选择基准策略、运行、单步、暂停、速度、重置、保存对比 | 修改后说明哪些结果已失效；运行后展示真实计数与变化；可比较相同初始数组下不同策略 | 无教学通关要求；每次运行保存独立结果 |

判断题是操作预测，不计入算法比较次数。程序每实际执行一次比较或交换才更新算法计数。不得根据预测对错虚增计数，也不得在预计算动作序列时提前排序显示数组。更换速度只改变播放节奏，提示“不改变排序规则或操作次数”。

算法样例中的可执行动作可以由生成器调用我们的适配接口实现；MAIC-UI 的页面和绘图继续保留。首版用独立参考实现核验排序与分区，避免让同一段生成代码同时充当执行者和正确性裁判。

## 操作事件与反馈契约

一次完整处理顺序为：接收意图 → 校验当前步骤权限与前置条件 → 执行实验动作 → 获取真实状态变化 → 选择反馈规则 → 重绘并显示反馈 → 检查本步完成条件 → 保存操作与状态。

每个动作声明以下内容：

| 字段 | 用途 |
| --- | --- |
| action_id 与输入结构 | 稳定动作标识及有效输入，例如 choose_pivot(index) |
| allowed_steps 与 preconditions | 在哪些步骤开放，以及基准是否已选等前提 |
| expected_effect | 应改变什么；允许合法不变化的情况及原因 |
| feedback_cases | 成功、判断错误、输入无效、条件不足、无变化、执行异常时的反馈 |
| evidence_fields | 支撑反馈与完成判断的实际字段，例如比较值、交换索引、分区边界 |

动作结果结构包括 action_id、action_instance_id、outcome、before_revision、after_revision、evidence、feedback 和状态快照引用。outcome 使用 applied、incorrect、blocked、invalid、no_change、error。权限拒绝、重复选择和未变化操作也必须返回回执，不能静默忽略。

动作执行前保存稳定快照，完成状态变更及校验后再提交新的 revision。中途异常恢复前一快照并显示失败；禁止留下半次交换、重复计数或把异常状态标为完成。异步动画只表现已经确认的动作或在原子提交点更新模型，暂停与切步恢复到最近提交点。

反馈由规则模板结合实际 evidence 生成，包含 summary、explanation、next_hint、highlight_targets。高亮目标采用稳定对象标识，例如元素 ID 和区间 ID；值相同的两个元素不能共用一个对象 ID。模板只能引用声明过且存在的证据字段，缺少证据时不得填造结果。

按钮即时显示执行中状态，教学动作结束后给出结果反馈。播放时每个算法动作都产生事件，画布跟随当前事件；反馈条只展示当前解释，历史按批次保存，不反复抢占焦点。拖动滑块时本地显示连续变化，释放、键盘提交或短暂停顿后形成一条带 before/after 的配置事件。读屏区域合并高频播报，但不丢弃已提交动作的回执。界面响应目标是下一绘制帧，普通动作反馈目标为 100ms 量级，作为待测指标。

## 生成产物与运行模块

保留现有 presentation 标记，新增独立的 guidance_version=2 与 artifact_revision。布局版本、教学协议版本和实验内容版本分别管理。生成产物增加 manifest，包含 state_schema、动作目录、参数目录、步骤列表、自由探索设置及反馈模板。

每一步包含：step_id、title、objective、instruction、question、depends_on、entry、allowed_actions、parameter_policy、feedback_rules、completion。entry 声明使用固定初始状态还是某个依赖步骤的输出；parameter_policy 明确参数的可见性、可编辑性、有效范围及改变后的状态失效范围。

完成条件使用受限的结构化规则，例如 all、any、eq、lte、event_seen、registered_check。不接受模型生成的任意字符串表达式，不通过 eval 执行。条件既检查结果，也检查必要动作，例如仅因初始数组已经有序不能算完成分区练习。registered_check 引用已注册的领域检查器，不能由生成页面自行宣告可信通过。

MAIC-UI 生成一个实验文档及对应适配器，适配器提供 initialize、dispatch、snapshot、restore、render、dispose。snapshot 必须包含恢复需要的完整领域状态：初始输入、工作数据、随机种子及随机序列位置、动作游标、子任务栈、参数与计数；不保存 DOM、定时器或函数。restore 后统一暂停，重新绘图，用户主动继续。

项目提供版本化 EduPractice SDK，负责步骤控制、动作权限、反馈选择、事件序列、状态校验和通信。生成代码注册动作处理器与绘图函数，所有改变模型的路径都经过 dispatch；原生按钮和画布交互绑定稳定动作 ID，禁止自行绕过调度器修改模型。自动播放也逐次调用允许的动作，播放权限包含可展开动作及停止边界，不能跨入尚未开放的教学阶段。

这是生成代码必须遵守并接受测试的工程约束，不把同一 iframe 内的 JavaScript 调度器当作对恶意代码的安全边界。仍沿用现有 sandbox、CSP、离线资源与无网络运行方式。学习完成证据需要服务端检查，不能仅信任客户端传来的 completed=true。

## 宿主与实验的双向通信

| 方向 | 消息 | 作用 |
| --- | --- | --- |
| 实验到宿主 | runtime_ready | 上报协议版本、实验版本与能力列表 |
| 宿主到实验 | initialize_session | 注入当前 manifest、步骤、模式及恢复快照 |
| 宿主到实验 | enter_step、retry_step、enter_explore、restore_snapshot | 改变教学上下文或恢复状态 |
| 实验到宿主 | command_result | 确认切换结果，返回最新状态；失败时保留原步骤 |
| 实验到宿主 | action_result、feedback、step_status、snapshot | 上报动作、解释、完成候选与状态 |
| 宿主到实验 | pause | 切换、离开与恢复前终止运行中的动作循环 |

消息包含 protocol_version、artifact_revision、session_id、step_id、attempt_id、request_id 或 event_id、递增 seq。宿主校验 event.source 是当前 iframe，实验校验 event.source 是 parent；opaque origin 环境继续使用必要的星号目标，但通过本次初始化的通道标识和能力校验隔离旧会话消息。序列、长度与字段结构均有校验。

宿主等待 ready 后再初始化，实验收到 initialize_session 前禁止操作。切步采用命令与回执：先暂停并记录旧状态，加载目标快照，重绘并核对步骤，再更新左侧选中项。超时显示可重试状态，不盲目重复一个已执行但回执丢失的命令；同 request_id 查询或重发返回原结果。

每次模式或步骤切换增加执行代次，取消旧动画与定时器，迟到回调在执行前核对代次。状态上报可节流，动作回执和完成证据不得用现有 500ms 状态合并逻辑覆盖。发现 seq 缺口时暂停完成判定并请求快照或补发事件。

## 状态继承与自由探索

每个步骤、每次尝试分别保存入口快照、当前快照和完成快照。第一次进入后续步骤时从有效依赖结果初始化，再次进入恢复本步当前状态，不重新执行旧动作。

回看已完成步骤默认恢复其完成状态并暂停；开始重新操作时创建新的 attempt_id。修改上游输入或重新尝试会使依赖旧结果的后续步骤标记为“需要重做”；旧证据、问答和观察仍保留在历史尝试下。只调整播放速度或展示选项不使后续步骤失效。

“重试本步”恢复该步入口，取消在途动作，清理本次执行计数，并按参数策略恢复本步参数。“重置完整实验”只影响自由探索会话，不能清除引导步骤记录。

首次进入自由探索复制引导实验的原始数据、当前参数与当前模型状态到独立会话。如果引导已经排完，明确显示“当前已完成排序”，提供“从初始数组重新运行”；不把已排序数据当作新的对比基线。后续返回恢复自由探索会话。策略对比要求初始数据、区间规则和计数口径一致，每条结果显示策略与输入摘要。

## 保存与问答接口

继续使用现有生成任务及个人实验归属校验。新增以下接口，不改变旧详情、观察和问答请求的兼容行为。

| 接口 | 请求与结果 |
| --- | --- |
| POST /api/practice/{id}/sessions | 按 request_id 幂等创建 guidance 或 explore 会话，返回 session_id 与初始 revision |
| GET /api/practice/{id}/sessions/{session_id} | 恢复版本、当前步骤、尝试状态及最近已保存快照 |
| POST /api/practice/{id}/sessions/{session_id}/events | 提交有序事件批次、预期 revision、幂等 batch_id；返回已保存序号、revision 与检查结果 |
| POST /api/practice/{id}/sessions/{session_id}/transitions | 幂等记录进入步骤、创建新尝试及切换模式；检查依赖，返回允许的目标上下文 |
| 现有 observations 与 ask | v2 请求携带 artifact_revision、session_id、step_id、attempt_id、state_revision |

新增 practice_sessions、practice_events 专用存储与数据库迁移。session 保存当前快照和版本，events 按 session_id 与 event_id 唯一去重；同一事务写事件、更新快照和完成证据。事务内按 expected_revision 检查并锁定会话，冲突返回 409，避免两个标签页静默覆盖。现有 LearningStore 的 get/put 与进程内 RLock 不承担这项跨进程并发保证。

协议限制事件、状态与批次大小，按 schema 检查数值及字段。默认按动作小批量保存，切步、完成、暂停时提交剩余事件；不逐帧写库。断网时继续本地反馈并显示“未同步”，将待保存事件与快照暂存 IndexedDB。恢复网络使用同一 batch_id 重发；清理浏览器数据会丢失未同步进度，界面不得把它显示为已保存。较长操作记录采用分段事件与检查点，不能直接套用现有 journal 最近 40 条聊天或 50 条观察的截断规则。

离线期间可按已下载规则继续实验与本地步骤切换，完成候选显示“待同步验证”；重连按事件与转换的原始顺序提交，服务端拒绝或遇到版本冲突时保留本地分支供恢复，不自动覆盖服务器进度。未初始化且缺少有效缓存的会话不能凭空创建离线恢复状态。

step_status 从运行时上报的是完成候选。服务端先检查权限、动作次序、状态版本和声明式条件；已支持的快速排序适配器使用独立参考实现重放动作并核验关键状态，再保存“操作完成”。其他领域无独立检查器时，只能记录用户已操作或运行时检查结果，不能伪装为已验证完成；引导式自动完成能力只为通过相应验证器的实验开放。

右侧问答按步骤与尝试检索，默认仅使用当前会话及必要的上游结果摘要。请求发出时固定其上下文，迟到回答仍保存到原步骤和原尝试，不覆盖当前面板。切换步骤后只展示属于目标步骤的聊天；旧版无步骤标记的消息保留为“历史实验问答”。AI 不能改变步骤完成状态，不能要求用户必须对话才能继续。

## 生成与验证流程

1. 从用户教学要求生成结构化步骤，明确每步目标、动作、参数权限、反馈和完成条件。用户指定的顺序优先；生成器不得自行替换或新增必经教学步骤。
2. 校验 manifest 的 ID 唯一性、引用完整性、依赖无环、动作可达性以及每个动作的反馈覆盖。自由探索作为独立模式附在目录末尾，不伪装为必须完成的教学步骤。
3. 将同一份 manifest 传给原生 ScientificEngine 和 HeavyGenerator，生成画面、操作绑定与适配器；视觉润色阶段不得改动作 ID、步骤规则或反馈证据定义。原生仓库保持固定版本与原样，协议适配写在本项目。
4. 打包 SDK 与现有 Tailwind、KaTeX，运行真实浏览器逐步操作。进入每步后检查开放控件、允许动作、错误输入反馈、完成证据及切换状态。
5. 运行领域检查器与独立样例；快速排序覆盖重复值、负数、有序、逆序、单元素子区间、不同基准、暂停和重试后的计数。
6. 有界定向修复生成代码并重跑受影响检查；仍失败就明确生成失败，不能把没有教学协议的完整页面标为分步实验成功。

新校验器分为 manifest 检查、SDK 合同检查、教学流程检查、领域检查和展示检查。旧校验器要求默认就能点击 run、至少两个可改参数，与分步限制冲突，须按 guidance_version 分流：完整运行与参数探针放在自由探索模式；引导步骤按 manifest 的本步动作检查。逐步检查采用明确的总时限与每步时限，现有 55 秒单进程时限不能直接假定足够；取消时继续回收浏览器进程组。

生成器可以提供覆盖脚本，但不能只跑生成器自己的“正确样例”。平台固定的越权、重复、乱序、错误动作与恢复场景必须执行；领域参考结果与生成逻辑独立。

## 验收与兼容

上线前至少覆盖以下场景：

| 场景 | 必须满足 |
| --- | --- |
| 本步未开放动作，包括画布、键盘与自动播放 | 状态不变，返回原因，不能通过隐藏控件绕过 |
| 正确、错误、条件不足、无变化与执行失败 | 均有对应反馈，错误预测不改变数组或算法计数 |
| 调整速度、参数或初始数据 | 说明实际影响；旧结果该失效时失效，无变化不伪造差异 |
| 完成任务与点击下一步 | 完成有操作轨迹和状态依据，导航不写完成 |
| 动画中切步、快速连点与迟到消息 | 旧动作不污染新步骤，重复命令不执行两次 |
| 回看、重试、修改上游 | 正确恢复状态，依赖结果失效范围正确，历史记录可查 |
| 自由探索与引导往返 | 状态互不覆盖，开放完整操作，反馈继续有效 |
| 刷新、断网重连、重复提交、双标签页 | 恢复最近保存状态，未同步状态有提示，冲突可见且无静默覆盖 |
| 提问后切步 | 回答归属原步骤与尝试，不出现在新步骤会话 |
| 桌面、手机、键盘与读屏 | 控件可达、反馈可感知、画布清晰且无横向溢出 |
| 旧实验 | 原有操作与历史记录仍可使用，不虚构分步限制或完成状态 |

没有 guidance_version=2 的历史实验继续走原生完整实验与说明目录。需要升级时创建新产物版本并保留旧实验与记录；不能靠 DOM 猜测或只隐藏按钮把旧实验宣称为新协议。发布时先完成存储迁移与后端兼容，再发布前端；开关关闭后仍可读取已保存 v2 会话，进行中的旧版本会话按其 artifact_revision 恢复。
