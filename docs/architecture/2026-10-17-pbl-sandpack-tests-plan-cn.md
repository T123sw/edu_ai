# PBL 接入 Sandpack Tests 实施计划

状态：实现、上线与正式环境端到端验证完成，见[上线记录](../acceptance/2026-10-17-pbl-sandpack-online/README.md)。用户已同意先写计划再执行。本轮接入前端标准测试，继续使用现有服务端通关核验；后端项目和 Python 运行环境另行扩展。

## 目标与分工

复用 Sandpack 的文件、依赖、浏览器测试执行与结果展示。需求分析、逐步代码生成、验收生成、历史回归、学习记录与 AI 反馈由 PBL 保留。新验收优先使用标准 Jest 测试文件；布局和真实页面场景保留 Playwright。旧项目的声明式检查继续可运行，不批量重写历史产物。

官方入口：[Sandpack Tests](https://sandpack.codesandbox.io/docs/advanced-usage/components#tests)。已安装 sandpack-react 2.20.0 提供 SandpackTests、watchMode 和 onComplete。浏览器中的 Jest 并非完整 Node Jest；以实际兼容性实验决定首批开放的测试 API。

## 实施步骤

1. **运行实验**：实际启动原生 Sandpack Tests，验证纯函数、React 渲染与交互、异步断言、失败与编译错误、修改后重跑和结果结构。确认当前 bundler 的可用性与依赖组合；记录无法复用的边界。
2. **验收协议**：在旧 UiCheck 旁新增带执行器标识的标准测试检查，保持稳定检查 ID。测试源码与学生源码分开保存；前端只编辑学生工程。服务端选用可信产物中的测试，绑定代码哈希、产物版本、任务和运行 ID。零测试、未执行、编译失败或超时不得计为通过。
3. **执行与界面**：接入 SandpackTests 学习反馈；服务端使用同一份标准测试与兼容运行环境执行核验。保留旧 Playwright 检查与布局检查。防止自动运行和旧代码结果误写通关状态；测试运行与预览分离、反馈标注清楚。
4. **生成链路**：保持代码与验收两次调用。验收读取当前完整代码、前序代码和测试、前序执行结果及后续计划；按需求生成测试，允许修复本步测试。使用标准测试替代受限动作字段表达逻辑和组件行为；删除不必要的断言类型门槛，不增加模型审阅或项目专用规则。
5. **验证与交付**：旧项目回归、生成中断恢复、当前与历史测试累计执行、测试失败与错误代码拦截、页面编辑后运行、服务端真实核验。覆盖表单禁用/空集合、列表重复项、状态切换和纯函数等不同类型，并做真实模型生成实验。记录实际通过项目、失败原因和未完成边界。

## 完成标准

- 至少一个真实生成的分步项目在页面执行标准测试，并通过服务端核验；故意破坏行为后失败。
- 历史测试在后续步骤继续执行；失败证据可用于生成修复和 AI 辅导。
- 前端原生测试结果仅作即时反馈，不直接作为可信通关记录。
- 旧声明式项目、版本/CAS/权限/重试行为不退化。
- 测试环境使用 scripts/pbl/isolated.py 或同等隔离启动，不读写生产业务存储。
- 记录实际部署状态，不将本地实现或测试通过描述为已上线。

## 风险与处理

Sandpack 原生运行依赖浏览器 bundler 服务；先实测再选接入方式。组件测试库按实测固定版本，生成提示只开放已验证 API。自定义测试代码只在隔离浏览器运行，不在业务宿主直接执行。标准测试改善表达能力，但需求误解仍需靠上下文和失败反馈修正，不能宣称消除所有模型错误。
