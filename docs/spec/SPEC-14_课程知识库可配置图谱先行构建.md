# SPEC-14 课程知识库可配置、图谱先行构建

> **状态**：实现完成，核心真实 E2E 通过；ACC-14 扩展运维场景待最终签收
> **日期**：2026-08-12
> **验收文档**：[ACC-14](../acceptance/ACC-14_课程知识库可配置图谱先行构建_验收.md)
> **实施计划**：[2026-08-12-configurable-graph-first-course-knowledge-build.md](../superpowers/plans/2026-08-12-configurable-graph-first-course-knowledge-build.md)
> **关联规格**：SPEC-00、SPEC-03、SPEC-05、SPEC-06
> **覆盖设计**：2026-04-21 教材知识图谱前端集成、2026-08-07 课程工作区“图谱只读且一键构建”相关约定

## 1. 背景与问题

当前课程知识库构建链路已经具备构建计划、网络候选、后台任务、模型补充、图谱版本和回滚能力，但实机使用暴露出以下结构性问题：

1. 前端在同一个点击事件中先创建预览，再立即启动任务；用户看不到也无法修改构建配置、图谱草案、网络候选和警告。
2. 图谱草案并非模型生成，而是把课程目标的前 12 项直接变成同一模块下的叶节点；无意义课程目标会直接产生无意义图谱。
3. 新课程知识页的普通文件上传与知识库构建器彼此独立，上传教材不会参与图谱规划、教材拆分、节点映射和覆盖率计算。
4. 旧教材导入接口能够解析教材并生成图谱，但属于旁路：它会直接保存图谱，没有新的配置、确认、版本发布和质量门禁流程。
5. 网络候选必须匹配少量固定许可域名才能入库，导致已经搜索到的相关页面全部被拒绝。
6. 构建器允许零网络来源启动，并用 AI 资料补足每个叶节点；纯 AI 结果仍可能获得 100 分质量评分。
7. 页面在后台任务成功后不会重新读取图谱，用户可能继续看到构建前的“知识图谱”占位节点。
8. 构建规模由 `topics[:12]`、`topics[:6]`、每叶 3 份资料等硬编码控制，无法表达不同课程的真实规模。

2026-08-11 的“古诗文鉴赏”实机记录验证了以上问题：网络搜索产生 20 个候选、0 个候选入库、3 份资料全部为 AI 生成，系统仍发布了只有一个“1”知识点的图谱并给出 100 分。

## 2. 覆盖关系

本规格生效后，以下旧行为停止作为产品主线：

| 旧行为 | SPEC-14 新约定 |
| --- | --- |
| 点击“一键构建”后预览并立即启动 | 配置、教材处理、模型图谱、用户确认、资料构建是可见且不可跨越的阶段 |
| 根据课程目标硬编码三层图谱 | 无论有无教材，图谱草案必须调用配置的 LLM 生成 |
| 普通上传资料与构建器分离 | 教材作为构建输入保存、解析、拆分并映射到已确认图谱 |
| 教材导入后直接覆盖知识图谱 | 教材只产生构建草案输入；用户确认且整次构建通过后才发布新版本 |
| 未验证开放许可的网络候选自动拒绝 | 许可不再是候选筛选、抓取、质量门禁或发布门槛 |
| 纯 AI 补充也可获得满分 | 质量门禁按用户配置分别核验教材、网络和 AI 数量及比例 |
| 构建成功后依赖手工刷新 | 任务终态触发图谱、资料、版本和统计重新读取 |

2026-08-07 设计中“知识图谱不提供结构编辑”的约定仍适用于日常浏览页；SPEC-14 只在“构建草案确认”工作流中提供结构编辑，不把日常知识图谱浏览页改成无版本约束的自由编辑器。

## 3. 目标与非目标

### 3.1 目标

- 教师在正式构建前配置规模、资料目标、网络要求和 AI 补充上限。
- 教材可选；有教材时先解析教材，再由模型参考教材与课程信息生成图谱。
- 无教材时仍由模型根据课程元数据与规模配置生成图谱，禁止确定性模板冒充模型结果。
- 教师能够检查、修改并明确确认图谱草案；确认前不得开始网络发现、网页抓取、正式索引和发布。
- 已上传教材在图谱确认后按章节/内容块拆分，映射到知识节点并参与课程知识库索引。
- 网络来源不再执行开放许可验证，主要按相关性、可访问性、内容有效性和去重结果处理。
- 教材、网络和 AI 资料分别统计；AI 只能在配置允许的范围内补缺。
- 每次构建形成可恢复的后台任务和不可变发布版本，失败不破坏当前已发布版本。
- 初次构建、增量补充、合并重构和全量重建具有明确语义。

### 3.2 非目标

- 不保证任意网页都能成功抓取；登录、验证码、反自动化、超时、空正文和不支持的内容类型仍可失败。
- 不在本期实现商业版权合规系统、许可法律判断或付费内容绕过。
- 不把知识图谱日常浏览页变成多人实时协同编辑器。
- 不让模型自行突破用户配置的规模、网络最低数量或 AI 比例上限。
- 不在本期支持扫描图片教材的人工 OCR 校对工作台；PDF 解析继续复用现有 MinerU 能力。
- 不迁移或删除现有已发布图谱、知识库文档和历史版本。

## 4. 核心术语

| 术语 | 定义 |
| --- | --- |
| 构建草案 `build draft` | 尚未启动正式资料构建的持久记录，包含配置、教材输入、图谱草案和修订号 |
| 教材输入 `textbook input` | 属于某次构建的原始教材、解析结果和拆分候选；发布前处于暂存状态 |
| 图谱草案 `graph draft` | 模型生成且可由用户编辑的结构，不等同于当前已发布图谱 |
| 图谱确认 `graph confirmation` | 用户确认某个草案修订；确认后结构和节点 ID 对本次构建冻结 |
| 正式构建 | 图谱确认后执行网络发现、网页抓取、教材拆分映射、索引、AI 补缺和质量检查 |
| 非 AI 资料 | 来源类型为 `textbook` 或 `web` 的资料 |
| 发布版本 | 通过全部硬门禁后原子发布的图谱与文档集合，可回滚 |

## 5. 用户流程与状态机

### 5.1 标准流程

```text
创建构建草案
  → 填写规模与资料配置
  → 可选上传并解析教材
  → 调用模型生成图谱草案
  → 用户编辑、重新生成局部或全量草案
  → 用户确认图谱
  → 搜索网络候选
  → 抓取与清洗网页
  → 拆分教材并映射节点
  → 建立索引
  → 按配置补充 AI 资料
  → 质量检查
  → 原子发布新版本
```

### 5.2 状态

```text
draft_config
  → textbook_processing（可选）
  → graph_generating
  → graph_review
  → graph_confirmed
  → queued
  → source_discovery
  → acquiring
  → textbook_mapping
  → indexing
  → model_fallback（可选）
  → quality_check
  → publishing
  → succeeded
```

终态还包括 `failed`、`blocked`、`canceled`。`graph_review` 是持久等待用户的业务状态，不是进行中的后台 job；处于该状态时不得显示为后台任务“卡住”。

### 5.3 不可跨越门禁

- `graph_confirmed_at`、`confirmed_graph_revision` 和确认人缺一不可，`start` 必须返回 422。
- 确认后修改配置、教材集合或图谱结构必须创建新修订并回到 `graph_review`。
- 网络搜索、网页抓取、正式教材切片入库和 AI 补充不得发生在 `graph_confirmed` 之前。
- 解析教材可以发生在确认前，因为解析结果是模型生成图谱的输入；解析产物只能处于暂存区。

## 6. 构建配置

### 6.1 预设与高级配置

首屏提供三个可编辑预设，选择预设后所有字段仍可修改：

| 预设 | 模块目标 | 每模块知识点目标 | 预计叶节点 | 每叶资料目标 |
| --- | ---: | ---: | ---: | ---: |
| 小型 | 3 | 3 | 约 9 | 3 |
| 标准（默认） | 4 | 4 | 约 16 | 3 |
| 大型 | 6 | 6 | 约 36 | 3 |

高级配置契约：

```json
{
  "preset": "standard",
  "graph_depth": 3,
  "target_module_count": 4,
  "target_points_per_module": 4,
  "target_materials_per_leaf": 3,
  "minimum_web_materials_per_leaf": 1,
  "maximum_ai_materials_per_leaf": 1,
  "max_search_results_per_leaf": 8,
  "ai_supplement_enabled": true,
  "content_language": "zh-CN",
  "update_strategy": "merge_rebuild"
}
```

字段约束：

- `graph_depth`：3～5；课程根节点计为第 1 层。
- `target_module_count`：1～12。
- `target_points_per_module`：2～20。
- `target_materials_per_leaf`：1～10。
- `minimum_web_materials_per_leaf`：0～`target_materials_per_leaf`，默认 1。
- `maximum_ai_materials_per_leaf`：0～`target_materials_per_leaf`，默认 1。
- `max_search_results_per_leaf`：1～20，默认 8。
- `ai_supplement_enabled=false` 时，`maximum_ai_materials_per_leaf` 规范化为 0。
- 用户可以把网络最低数量设为 0；只有显式配置为 0 时，零网络来源才不构成硬门禁失败。

### 6.2 更新策略

| 策略 | 语义 |
| --- | --- |
| `incremental` | 保持当前图谱节点，模型只建议新增节点和缺失资料；不删除既有节点 |
| `merge_rebuild` | 默认；模型参考当前图谱、课程信息和新教材生成可编辑新草案，并尽量保留可匹配节点 ID |
| `full_rebuild` | 生成全新草案；旧版本继续可回滚，发布前不影响现网 |

首次构建忽略更新策略差异，按全新草案处理。

## 7. 模型生成知识图谱

### 7.1 强制模型调用

每次全量生成图谱草案必须调用当前用户运行配置解析出的 LLM。输入至少包含：

1. 课程名称、简介、教学对象、课程目标、语言和难度；
2. 构建规模配置；
3. 可选的当前已发布图谱摘要与更新策略；
4. 可选教材的目录、章节标题、摘要和受限长度正文样本；
5. 稳定 JSON Schema 和节点命名约束。

禁止在 LLM 不可用、输出错误或超时时发布 `_fallback_graph`、课程目标平铺图或空占位图。失败应保持草案可重试并显示稳定错误码 `GRAPH_MODEL_UNAVAILABLE`、`GRAPH_SCHEMA_INVALID` 或 `GRAPH_SCALE_UNSATISFIED`。

### 7.2 输出结构

模型输出必须满足：

- 每个节点具有稳定且唯一的 `id`、`label`、`type`、`summary` 和 `children`。
- 根节点类型为 `course`；中间节点为 `knowledge_module` 或 `knowledge_unit`；叶节点为 `knowledge_point`。
- 叶节点不得使用“1”“第一章”“知识点”等缺少语义的孤立名称。
- 不得存在重复 ID、循环、空标签、同级重复标签或超出配置深度的节点。
- 实际模块数和知识点数允许相对目标上下浮动 20%；超出时触发模型修复，而不是静默接受。
- 教材存在时，每个教材一级章节必须被映射为图谱节点或列入 `unmapped_outline_items`，不得静默丢失。

### 7.3 校验与修复

模型首次输出后执行确定性结构校验。失败时最多进行 2 次带错误明细的模型修复；仍失败则返回 `graph_review` 的错误状态，不进入正式构建。

局部重新生成以一个模块为边界。未选择模块及其节点 ID 保持不变；重新生成模块的资料尚未正式构建，因此无需迁移发布数据。

## 8. 图谱草案确认界面

构建向导必须展示：

- 当前配置摘要和预计资料量；
- 教材解析状态、章节数、警告和未映射目录；
- 可展开的完整图谱树；
- 模块数、叶节点数、深度及与目标规模的偏差；
- 节点增删、重命名、说明编辑和父子移动；
- 全量重新生成、局部重新生成、撤销未保存修改；
- “确认图谱并开始构建”明确主操作。

保存草案使用 `revision` 乐观并发控制。旧 revision 更新返回 409，不得覆盖较新的浏览器或用户修改。

确认操作必须展示以下不可省略提示：确认后系统将按该结构搜索网络、拆分教材和建立索引；若再次修改结构，需要重新确认。

## 9. 教材输入、拆分与节点映射

### 9.1 支持范围

首期产品明确支持 `.pdf`、`.docx`、`.txt`、`.md`。前端 `accept` 与后端解析器必须一致；`.doc`、`.ppt`、`.pptx` 在解析器未实现前不得宣称支持。

### 9.2 暂存与解析

- 上传原始教材后立即保存不可变原文件、内容哈希、文件名、大小、上传人和 build ID。
- 相同 build 内按内容哈希去重。
- PDF 使用 MinerU；DOCX 使用现有 Word 文本解析；TXT/Markdown 使用安全编码读取。
- 解析结果保存目录候选、结构化章节、正文块、页码/标题定位和解析警告。
- 解析失败不得删除原文件；用户可以重试、替换或移除该教材。
- 发布前教材输入和解析产物不进入当前课程公共 RAG 检索结果。

### 9.3 确认后的拆分与映射

图谱确认后，系统使用教材结构、节点语义和正文内容把教材拆成可检索块并映射到叶节点。每个映射保存：

- `document_id`、`chunk_id`、`knowledge_node_id`；
- 章节/页码定位；
- `mapping_method`；
- `mapping_confidence`；
- 内容哈希和教材输入 ID。

置信度低于配置阈值的块进入 `unmapped_textbook_chunks`，不自动挂到错误节点。构建结果必须展示未映射数量；未映射内容不计入叶节点覆盖率。

### 9.4 发布语义

教材原文件可作为课程级来源文档发布；教材拆分块作为知识点级索引证据。列表展示时避免把每个向量块显示为独立文件卡片，但预览必须能回到原教材的章节或页码。

## 10. 网络资料发现与抓取

### 10.1 启动顺序

网络发现只在图谱确认后执行，并以每个已确认叶节点为检索单元。查询由课程语义、节点标题、节点说明、语言和教学对象组成，不再只搜索前 6 个主题。

### 10.2 候选筛选

候选按以下条件处理：

- 与叶节点的语义相关性；
- URL 和内容哈希去重；
- 页面技术可访问性；
- 正文是否达到最低有效长度；
- 内容语言与配置的匹配程度；
- 抓取、清洗和索引是否成功。

开放许可、许可证名称、许可证 URL、固定域名白名单和 `authority_tier` 不得作为自动拒绝或发布门槛。系统可以在来源明确提供时记录许可元数据，但缺失值必须允许继续。

### 10.3 溯源与抓取边界

每份网络资料仍保存来源标题、URL、域名、抓取时间、内容哈希、查询、最终重定向 URL 和抓取结果。系统不得绕过登录、验证码、付费墙或访问控制；失败应保留可解释原因并继续处理其他候选。

默认不要求第二次人工来源确认。用户可以在配置阶段排除域名，在构建结果中删除不合适来源并执行增量补充。

## 11. AI 补充

- AI 补充发生在教材和网络资料完成并计算真实缺口之后。
- `ai_supplement_enabled=false` 时不得调用补充模型。
- 每个叶节点 AI 资料数不得超过 `maximum_ai_materials_per_leaf`。
- AI 资料必须继续显式标记 `source_type=model_generated`，保存生成模型、prompt 版本、生成时间和独立审查结果。
- AI 资料不计入 `minimum_web_materials_per_leaf`，也不得伪装成外部来源。
- 达到 AI 上限后仍未满足总资料目标时，构建进入 `blocked`，不得为了发布继续生成。

## 12. 质量门禁与评分

### 12.1 强制门禁

每次发布必须同时通过：

1. `graph_schema`：图谱结构、ID、深度和节点类型合法；
2. `graph_scale`：规模位于配置允许偏差内，或有用户手工确认的偏差记录；
3. `textbook_mapping`：所有计入覆盖率的教材块有有效节点映射和索引；
4. `web_minimum`：每个叶节点的网络资料数达到用户配置；配置为 0 时自动通过；
5. `material_coverage`：每叶总资料数达到目标；
6. `ai_limit`：每叶 AI 数量不超过上限；
7. `index_integrity`：发布引用的所有文档和索引记录完整；
8. `publication_atomicity`：失败构建未改变当前发布版本。

许可信息不出现在强制门禁列表中。

### 12.2 结果展示

质量结果不得只显示一个总分。必须逐节点展示：教材数、网络数、AI 数、抓取失败数、未映射教材块数和未满足项。可以保留总分作为摘要，但任一强制门禁失败时总分不得把结果描述为“质量通过”。

当 `minimum_web_materials_per_leaf > 0` 且实际网络资料为 0 时：

- 构建必须 `blocked`；
- `web_minimum` 必须失败；
- 不得发布；
- 不得得到 100 分；
- UI 提供“重新搜索”“调整配置”或“显式将网络最低数量改为 0”三种操作。

## 13. API 契约

建议在现有 `/api/courses/{course_id}/knowledge-builds` 下收口：

| 方法与路径 | 作用 |
| --- | --- |
| `POST /knowledge-builds` | 使用配置创建持久构建草案，不搜索网络 |
| `GET /knowledge-builds/{build_id}` | 读取配置、教材、图谱修订、状态、指标和错误 |
| `PATCH /knowledge-builds/{build_id}` | 在 `draft_config/graph_review` 更新配置，要求 revision |
| `POST /knowledge-builds/{build_id}/textbooks` | 上传并提交教材解析任务 |
| `DELETE /knowledge-builds/{build_id}/textbooks/{input_id}` | 在确认前移除教材输入 |
| `POST /knowledge-builds/{build_id}/graph/generate` | 调用模型生成或全量重生成图谱草案 |
| `POST /knowledge-builds/{build_id}/graph/modules/{node_id}/regenerate` | 局部重生成一个模块 |
| `PUT /knowledge-builds/{build_id}/graph` | 保存用户编辑后的图谱草案，要求 revision |
| `POST /knowledge-builds/{build_id}/graph/confirm` | 确认当前图谱修订 |
| `POST /knowledge-builds/{build_id}/start` | 仅对已确认修订创建正式后台任务 |
| `POST /knowledge-builds/{build_id}/cancel` | 取消可取消阶段 |
| `POST /knowledge-builds/{build_id}/retry` | 从稳定检查点重试失败/阻塞步骤 |

旧 `POST /knowledge-builds/preview` 在迁移期可转发到创建草案，但不得自动调用 `start`。旧 `/knowledge-graph/textbook-import` 从当前主界面移除；兼容期调用必须返回弃用提示，最终由本流程替代。

构建响应至少增加：

## 14. 持久化与版本

- `knowledge_builds.plan_snapshot` 保存规范化配置、课程快照、图谱修订摘要和迁移兼容字段。
- 新增教材输入/解析记录的持久模型，禁止只把临时路径放在浏览器或进程内存。
- 每次图谱编辑递增 `revision`；确认记录确认 revision、用户和时间。
- 网络候选表保留，`review_status` 改为相关性/抓取状态语义；许可字段可空且不参与决策。
- 构建产生的文档在发布前标记 build ID 和暂存状态；只有 `publish_build` 原子提升为 ready。
- 图谱版本、参与发布的文档 ID、构建配置、质量检查和来源指标必须能由 build ID 回溯。
- 取消或失败构建的暂存资产采用可恢复清理策略，不删除原始教材和错误诊断；清理必须是单独、可审计操作。

## 15. 前端信息架构

课程知识库主卡不再只有“一键构建”按钮，改为：

1. 无活动草案：显示“新建构建方案”；
2. 草案配置：规模预设、详细字段、教材上传；
3. 教材处理中：逐文件进度和错误；
4. 图谱审核：全屏或大尺寸结构编辑器与确认操作；
5. 正式构建：阶段进度、按来源类型计数、失败原因和取消入口；
6. 构建完成：版本、质量明细、图谱与资料刷新；
7. 构建阻塞：缺口、调整配置、重新搜索和重试入口。

刷新或离开页面后，活动草案由后端 course/build 查询恢复；`localStorage` 只能缓存最近 build ID，不能作为草案事实源。

## 16. 后台任务、并发与恢复

- 教材解析和正式知识库构建都是统一平台任务；图谱审核等待本身不是运行任务。
- 同一课程默认只允许一个处于 `queued/running/publishing` 的正式构建；可以同时存在一个未确认草案。
- 所有长任务有 deadline、租约、稳定 checkpoint 和幂等键。
- 重试不得重复发布文档、重复图谱版本或重复生成已通过审查的 AI 资料。
- 取消在发布事务开始前有效；发布中取消请求在原子发布完成后以明确结果返回。
- 浏览器通过统一 job store 获得终态；终态后刷新图谱、文档、版本和构建详情。

## 17. 权限、安全与数据保护

- 创建、编辑、确认、启动、取消和回滚要求课程 generate/edit 权限；只读角色只能查看已发布图谱和资料。
- 教材文件名、解析路径和预览下载继续执行路径 containment、文件大小和类型校验。
- 模型输入中的课程文本、教材文本和网页正文全部视为不可信内容，不得覆盖系统 JSON Schema、规模和安全约束。
- 浏览器不能提交模型 API key、搜索 key、base URL 或任意本地文件路径。
- 取消许可验证只移除产品筛选门槛，不授权绕过网站访问控制。
- 实施和测试不得修改或提交现有运行期课程数据；使用临时课程、临时数据库和测试存储。

## 19. 错误处理

| 场景 | 行为 |
| --- | --- |
| 课程信息不足 | 配置页提示补充，不调用图谱模型；不得以占位图继续 |
| 教材解析失败 | 保留原文件和错误；允许替换/重试/移除后继续 |
| 图谱模型失败 | 保持草案阶段，显示稳定错误；不进入网络搜索 |
| 图谱不符合规模 | 自动修复最多 2 次；仍失败回到审核并显示偏差 |
| 未确认直接 start | 422 `GRAPH_CONFIRMATION_REQUIRED` |
| 搜索无结果 | 继续统计缺口；按网络最低配置决定 blocked 或 AI 补充 |
| 页面抓取失败 | 记录 URL 和可行动原因，继续其他候选 |
| 教材块无法映射 | 进入未映射列表，不计覆盖率 |
| AI 达上限仍缺资料 | blocked，不继续生成、不发布 |
| 发布失败 | 当前版本保持不变；重试发布事务不得重复版本 |
| 前端刷新 | 从后端恢复草案/任务，不重复创建构建 |

## 21. 完成定义

只有同时满足以下条件，SPEC-14 才能标记为完成：

1. ACC-14 的全部强制项通过并记录真实证据。
2. 使用一门无教材课程完成“配置—模型图谱—人工确认—网络资料—发布”。
3. 使用一门含教材课程证明教材目录影响图谱，教材拆分内容按节点进入 RAG。
4. 使用一个缺少许可元数据但相关、可访问的网页证明其不会因许可被拒绝。
5. 使用一个网络搜索失败场景证明网络最低数和 AI 上限能够阻止错误发布。
6. 构建前后的当前版本、失败回滚、刷新恢复和历史版本可追溯。
7. 当前课程知识页不再调用旧的预览后立即启动逻辑，旧教材旁路从主界面移除。
8. 规格索引、验收索引、项目地图和验收结果同步更新。

## 22. 2026-08-31 教材优先采集增量

正式构建在 `prefer_complete_textbooks=true` 且 `COURSE_KB_TEXTBOOK_FIRST_ENABLED` 未关闭时，执行顺序调整为：课程级教材发现、PDF/HTML 安全采集、MinerU/结构化 HTML 解析、教材多叶映射、叶节点缺口补搜、AI 最后兜底、质量门禁、原子发布。历史 build 缺少新字段时继续走原链路。

新增配置：

- `prefer_complete_textbooks=true`
- `max_online_textbooks=2`，范围 0～5
- `max_search_rounds_per_leaf=2`，范围 1～3

`target_materials_per_leaf` 在新链路中解释为有效覆盖单位。教材章节组正文达到 800 字且映射置信度不低于 0.25 时计 1 unit，达到 4000 字时计 2 units；网页正文达到 600 字计 1 unit；AI 审查通过计 1 unit。同一内容 hash 不重复计分，同一教材每叶最多 2 units，上传教材不计入外部非 AI 来源下限，在线教材计入。

在线 PDF 下载强制执行 HTTPS、公网地址、逐跳重定向校验、robots、50 MB 上限和 `%PDF-` 签名校验。PDF 只调用一次 MinerU；原文件作为可见 artifact 保存，叶节点索引使用解析后聚合 Markdown，不再次导入原 PDF。低置信度和 top-2 分差小于 0.05 的歧义映射不计覆盖。

新链路的 AI 文档必须记录 `fallback_reason=non_ai_search_exhausted`、非 AI 尝试次数和补充前覆盖快照。质量门禁升级为 9 项：图谱结构、图谱规模、教材映射质量、外部非 AI 覆盖、内容充分性、AI 兜底策略、来源完整性、索引完整性和发布原子性。
