## 1. 验收结论

课程资源学习记录已完成实现并通过后端、前端和真实浏览器三类证据验证。

资源学习与教师任务保持独立：学生完成 AI 课堂后会形成按课程、资源和版本保存的学习事实；同版本任务可以读取该事实作为资源条件证据，但任务仍保持“未开始”，不会被资源学习自动完成。不同版本之间不复用证据。

AI 课堂完成口径为：

1. 仅 `explanation` 讲解场景按有效时间线覆盖区间计算完整度，达到 80%；
2. 所有必答题至少提交一次；
3. 不设置正确率通过线，三题全部答错仍可完成；
4. `demo` 演示只记录课堂学习行为，不进入讲解完整度。

## 2. 真实浏览器验收

确定性测试资源为 `computational-thinking / standard-sequence-selection-loop-classroom / v3`，包含三个讲解场景、三道必答题和一个互动演示。测试使用真实 FastAPI、React 页面、独立 SQLite worker 数据库、生产仓储和审核服务，不增加测试专用生产接口。

```powershell
pnpm exec playwright test tests/e2e/resource-learning.spec.ts --project=desktop1440
```

结果：`1 passed`，真实浏览器闭环通过。最终复验中的场景执行时间为 29.3 秒。

覆盖的浏览器行为：

- 快速翻页不增加讲解完整度；
- 演示交互只增加行为计数；
- 课堂问答中断期间不累计讲解时长；
- 讲解完整度达到 80% 以上、习题仍为 0/3 时保持“学习中”；
- 三道必答题全部提交且全部答错后显示 3/3 和“已完成”，`correct_count_latest=0`；
- 重放相同事件批次不重复累计；
- 客户端附带伪造 `progress_percent` 返回 422；
- 教师资源分析读取到完成人数和演示行为；
- 同版本 v3 任务显示“资源条件已满足”，任务状态仍为“未开始”；
- 服务重启并重新登录后恢复相同完成事实；
- 发布 v4 后，v3 证据不能满足 v4 任务。

## 5. 关键实现边界

- 数据库只保存原始事件、合并区间、题目尝试和服务端投影，客户端不能直接写完成状态。
- manifest 在标准课堂审核通过时冻结，历史版本不随新版本变化。
- 问答中断、隐藏页面、暂停、快速翻页和超出场景上限的停留不能刷讲解完整度。
- 任务证据是只读投影，不复制或覆盖资源学习原始记录，也不反向修改任务进度。
- 互动演示与课堂提问可进入行为分析，但不进入完成百分比。
