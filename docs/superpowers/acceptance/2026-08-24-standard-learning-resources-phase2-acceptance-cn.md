## 1. 验收范围

本阶段实现叶子知识点标准资源、教师审核、阅读型/测评型学习任务、不可变资源快照和基于资源完成事件的学习进度。使用当前“数据库”课程的六个叶子知识点作为最小验证结构。旧课程共享资源仅标记为 `legacy_shared`，待真实数据库迁移后再核对和清理；分层 RAG 不在本阶段范围内。

## 2. 功能验收清单

### A. 最小课程知识结构

- [x] `ACC-STRUCT-01` 测试脚本只允许默认测试课程，其他课程必须显式确认。
- [x] `ACC-STRUCT-02` 课程结构包含“关系模型、SQL 查询、事务管理”三个章节和六个叶子知识点。
- [x] `ACC-STRUCT-03` 脚本支持 dry-run，并对同一图结构和测试讲义保持幂等。
- [x] `ACC-STRUCT-04` 当前 Docker 数据库已写入该结构和一份覆盖六个知识点的测试讲义。

### B. 标准学习资源

- [x] `ACC-STD-01` 仅叶子知识点可生成标准资源；每个叶子固定包含 AI 课堂、学习指南、练习三种槽位。
- [x] `ACC-STD-02` 稳定资源 ID 与知识点、资源种类绑定；重新生成产生新版本而不是新的逻辑槽位。
- [x] `ACC-STD-03` 教师可查看待审核版本、单项通过/驳回、批量通过和仅失败项重试。
- [x] `ACC-STD-04` 学生接口仅返回已审核通过的版本。
- [x] `ACC-STD-05` 前端课程知识页按章节和叶子知识点展示三种资源状态，不恢复独立知识图谱页面。

### C. 学习任务与学习证据

- [x] `ACC-TASK-01` 教师创建任务时可选择“阅读学习”或“测评任务”。
- [x] `ACC-TASK-02` 阅读任务无需测评草稿即可发布；测评任务继续执行原有校验。
- [x] `ACC-TASK-03` 可选资源仅包括已审核标准资源、教师自己的个人资源及迁移兼容的旧共享资源。
- [x] `ACC-TASK-04` 任务创建时固化资源版本、受控内容和安全相对文件引用；源资源后续更新不改变任务内容。
- [x] `ACC-TASK-05` 学生从任务快照打开资源并记录事件，完成全部快照资源后任务进入完成状态。
- [x] `ACC-TASK-06` 教师端继续通过现有学习分析读取学生进度和证据等级。

### D. 数据库与兼容性

- [x] `ACC-DB-01` Alembic 唯一 head 为 `20260824_0017`，当前 Docker 数据库已升级到该版本。
- [x] `ACC-DB-02` 新增标准资源批次、批次项和任务资源快照表，并为来源、审核状态和任务类型建立约束。
- [x] `ACC-DB-03` 既有课程可见资源迁移为 `legacy_shared`，个人资源保持 `personal`。
- [x] `ACC-DB-04` 执行迁移前已生成可恢复的 PostgreSQL dump。

## 4. 运行态验收路径

1. 教师进入“课程知识”，确认三个章节、六个叶子知识点及每点三个标准资源槽位。
2. 选择一个叶子知识点发起生成，观察批次状态和失败项重试。
3. 预览生成结果，分别验证驳回原因必填、单项通过和批量通过。
4. 创建阅读任务，选择已通过标准资源或教师个人资源，直接发布。
5. 学生打开任务快照，完成资源；教师端确认进度和 `activity_evidenced` 证据。
6. 创建测评任务，确认没有有效测评时仍不能发布。
