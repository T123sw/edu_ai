# AI 修改统一后台任务与原版副本

日期：2026-09-07。用户确认：修改生成新版本并保留原版本副本；统一作为后台任务管理；修改理解能力另行优化。

## 实现

- 资料定位、权限与基准版本先校验，随后进入现有 TaskStore 持久化队列和 EduJob 任务中心。新增 revise_artifact 任务类型／artifact_revision handler；没有新建独立线程任务管理器或另一套任务数据库。
- 模型理解、补丁生成、结构校验及保存由现有 durable worker 执行。入队后聊天返回 task_id，离开页面不取消任务；失败重试沿用原操作和基准版本，资料已变化时报告冲突。
- 资料 ID 稳定，成功生成 vN+1，保留 vN 完整快照。JSON 使用既有 revision_history，PostgreSQL 使用 MaterialVersion。成功任务同时回读原版和新版，校验 operation_id；不把原生成 source_job_id 改成修改任务 ID。
- 后台任务结果带资料 ID、原版／新版编号和结果入口。聊天历史留下版本及资料链接；资源页展示版本号和“历史版本与原版副本”入口，读取旧版或恢复为另一个新版本。
- 只读问答或澄清也是资料处理任务，处理完成不意味着已修改；分别显示回答／需要补充信息，不宣称保存。澄清回答继续原修改操作，作为后续处理任务提交。
- 同一请求重复提交不重复入队。保存阶段禁用任务取消并在写入前复核取消状态。继续使用现有任务重试、租约和重启恢复机制。
