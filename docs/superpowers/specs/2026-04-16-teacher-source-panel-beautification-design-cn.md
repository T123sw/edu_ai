# 教师工作台左侧知识库美化设计

## 1. 设计目标

本次设计面向教师问答工作台左侧知识库面板的整体美化，目标不是重做上传、删除、预览、深度研究等业务逻辑，而是在保留现有功能结构的前提下，把左侧面板从“功能可用”提升为“更像成熟资料工作台的一部分”。

本次设计确认的核心目标如下：

1. 保留现有左侧知识库的主要能力，包括文档列表、勾选、深度研究、上传、预览、重命名和删除。
2. 将左侧面板从零散的控件堆叠，整理为更清楚的“资料工作台”结构。
3. 强化头部、搜索区、列表区、底部上传区之间的节奏关系。
4. 提升文档列表的品质感、层次感和操作清晰度。
5. 控制改动边界，不进入数据流、接口和右侧预览机制的深层重构。

## 2. 项目上下文

结合项目既有设计上下文，本次升级继续遵循以下原则：

- 用户是处在课程语境中的教师。
- 左侧知识库是教师组织资料、挑选问答语料、补充教学素材的工作区，不只是文件列表。
- 风格应继续保持浅色优先、专业、清晰、低认知负担。
- 重点是提升资料管理和检索体验的秩序感，而不是做成复杂后台。

## 3. 当前问题

当前左侧知识库面板主要存在以下问题：

1. 头部只是“标题 + 折叠按钮”，身份感较弱。
2. 搜索与深度研究入口更像单个功能按钮，缺少明确的检索工作区语义。
3. 列表区虽然可用，但头部控制、列表主体、底部操作之间的分区关系不够清楚。
4. 文档项视觉节奏偏平，图标、标题、勾选和更多操作之间的对齐关系不够精致。
5. 底部上传按钮与上方滚动区之间的边界较弱，整体起承转合不够完整。

## 4. 范围界定

### 4.1 本次范围

本次设计与实现只包含以下内容：

1. `SourcePanel.tsx` 的表现层结构优化。
2. 左侧知识库头部、搜索区、列表区、底部上传区的节奏重组。
3. 文档列表项的视觉层次、对齐关系和操作露出方式优化。
4. 左侧知识库局部样式的统一化整理。
5. 必要的页面级或源码级回归测试补充。

### 4.2 不在本次范围

以下内容不纳入本轮：

1. 上传、删除、重命名、预览、深度研究等业务逻辑重写。
2. 接口、状态管理、数据获取方式的重构。
3. 右侧预览视图的大规模改版。
4. 中间聊天区和右侧生成工坊的同步调整。

## 5. 目标体验

教师看到左侧知识库时，应感知到它是一个资料工作区，而不只是文件堆叠区。

理想体验如下：

1. 第一眼知道这是“知识库工作区”。
2. 能快速识别哪里在检索、哪里在浏览、哪里在新增资料。
3. 列表阅读更轻松，文档项信息更清楚，交互关系更稳定。
4. 底部上传入口像固定操作带，而不是漂在底部的独立按钮。
5. 整个左栏与当前工作台外壳风格统一，但保有自己的资料面板气质。

## 6. 设计方案

### 6.1 整体方向

本次采用“资料工作台型”方向，而不是后台管理型方向。

原则如下：

1. 保留现有功能顺序和核心使用路径。
2. 强化面板结构感，而不是增加更多控制项。
3. 让左栏更像一个围绕资料组织、检索和选择的工作区。
4. 避免把左栏做得过硬、过重、过像管理后台。

### 6.2 三段式结构

左侧知识库面板整理为三段式：

1. 顶部知识库头部
2. 中部检索与列表主体
3. 底部上传操作区

这样可以建立更清楚的阅读顺序：

- 先识别面板身份
- 再进入检索与浏览
- 最后看到新增资料入口

### 6.3 知识库头部

头部不增加复杂信息，但需要强化面板身份感。

设计要求：

1. “知识库”标题更稳，更像一个工作区标题，而不是普通文本。
2. 折叠按钮不再像角落里的附属按钮，而是与头部形成完整关系。
3. 头部整体留白更清楚，和下方检索区之间形成自然分隔。

### 6.4 搜索与研究区

搜索与深度研究入口整理成更明确的检索操作区。

设计要求：

1. 检索区在视觉上形成轻容器感。
2. 搜索/深度研究入口要像资料检索工具，而不是一个孤立按钮。
3. 该区域不增加新的复杂筛选逻辑，但允许更好地组织当前已有入口。
4. 检索区与列表主体之间应有明确但克制的分区关系。

### 6.5 列表主体

列表区是左侧面板的视觉主体。

设计重点：

1. 列表上方的“选择所有来源”控制要和文档滚动区分开。
2. 列表项之间的节奏要更清楚，不只是重复的默认行。
3. 图标、标题、更多操作按钮、勾选框之间的对齐要更准确。
4. hover、选中、勾选状态要有更明确的层级反馈。
5. 文档名过长时要继续优雅截断，不能破坏布局稳定。

### 6.6 底部上传区

底部上传入口调整为稳定操作带。

设计要求：

1. 上传区与上方列表滚动区域形成明确边界。
2. 上传按钮成为左侧面板的固定收尾操作，而不是漂浮结尾按钮。
3. 整体更像“已有资料在上，新资料入口在下”的稳定结构。

### 6.7 视觉语言

本次左侧知识库沿用当前工作台的轻控制台气质，重点通过以下方式提质：

1. 更稳的边界和内部分区。
2. 更清楚的背景层次。
3. 更统一的间距与节奏。
4. 更克制的蓝色强调，只用于关键状态和重要交互。

明确避免：

1. 做成很重的后台管理面板。
2. 使用大面积强色块。
3. 过度卡片化、强玻璃感和装饰性渐变。

## 7. 实现边界

建议实现主要落在以下文件：

- `frontend/src/components/teacher/SourcePanel.tsx`

如果需要补充样式承载，优先采用以下方式之一：

1. 在 `SourcePanel.tsx` 中引入更清楚的类名并整理现有内联样式。
2. 新增一个只服务于教师知识库面板的局部样式文件。

实现时不应无节制扩散到其他面板文件。

## 8. 响应式原则

本次左侧知识库美化不能破坏现有折叠和预览逻辑。

要求如下：

1. 折叠态仍保持清晰、可识别。
2. 预览态仍保持当前覆盖式查看逻辑。
3. 窄屏下不因局部美化而导致文本溢出、按钮错位或滚动异常。
4. 文档项、上传区、控制区应保持布局稳定，不因内容变化跳动。

## 9. 验收标准

### 9.1 视觉验收

1. 左侧面板更像资料工作台而不是文件列表容器。
2. 头部、搜索区、列表区、底部上传区形成清楚的三段式节奏。
3. 文档列表更整齐、更耐看、更容易扫读。
4. 列表项的操作关系更清楚，勾选与更多操作不再显得挤。
5. 整体与当前工作台外壳风格统一。

### 9.2 行为验收

1. 折叠与展开不受影响。
2. 预览打开与关闭不受影响。
3. 上传、删除、重命名、深度研究等功能入口不受影响。
4. 勾选文档和“选择所有来源”行为不受影响。

### 9.3 回归关注点

1. 文档名长文本场景不应溢出遮挡。
2. 列表滚动区高度关系不应被破坏。
3. 底部上传区不应在滚动时消失或错位。
4. 折叠态图标列表仍需可用、清晰。

## 10. 成功标准

本轮完成后，应达到以下结果：

1. 左侧知识库成为更完整的资料工作区。
2. 教师更容易理解左栏的结构和使用顺序。
3. 列表的品质感、节奏感和可读性明显提升。
4. 整体工作台进一步统一，但左栏仍保有自己的资料属性。
5. 为后续继续优化中间聊天区和右侧生成工坊留出一致的设计语言基础。
