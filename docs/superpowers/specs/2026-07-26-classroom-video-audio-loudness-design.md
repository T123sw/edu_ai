# AI 课堂 MP4 旁白音量修复设计

日期：2026-07-26

## 1. 背景与问题

AI 课堂的 MP4 导出采用无头 Chromium 录制每个场景的视频画面，再由 FFmpeg 拼接场景并混入逐句生成的旁白音频。

当前导出结果中，旁白的主观音量明显偏小。对现有“快速排序算法原理”导出物进行分析后得到：

- 视频时长：12 分 34.5 秒；
- 旁白片段：47 段；
- 整体综合响度约为 `-32.97 LUFS`；
- 最大真峰值约为 `-5.18 dBTP`；
- 当前 FFmpeg `amix` 未显式设置 `normalize`，因此使用默认的 `normalize=1`。

每段旁白在时间轴上先通过 `adelay` 延迟，再作为一个独立输入送入 `amix`。虽然不同旁白在听感上并不重叠，但延迟区间仍属于各输入流的一部分。`amix` 默认归一化会按照全部 47 个输入分摊增益，理论衰减约为：

```text
-20 × log10(47) ≈ -33.4 dB
```

这与实际测得的低响度基本吻合，因此问题的根因不是 TTS 原始音频过小，而是多路旁白混音时发生了错误的整体衰减。

## 2. 目标

本次修复需要达到以下结果：

1. 消除旁白数量增加导致的系统性音量衰减；
2. 将最终 MP4 的课堂旁白调整到适合网页课程视频播放的稳定响度；
3. 防止响度提升后发生削波或明显失真；
4. 保留现有 `narrationGain` 配置的语义；
5. 不改变课堂生成、场景录制、视频拼接和 PPTX 导出流程。

## 3. 非目标

本次不处理以下内容：

- 不修改 OpenMAIC 的 TTS 服务或声音模型；
- 不改变网页课堂实时播放时的音量；
- 不增加背景音乐；
- 不重新设计浏览器播放器的音量控件；
- 不调整场景时长、旁白时间轴或生成内容；
- 不引入两遍式离线响度扫描流程。

## 4. 当前导出链路

```text
课堂数据
  → 无头 Chromium 按场景录屏
  → FFmpeg 将场景转为 H.264
  → FFmpeg 拼接无声视频
  → 下载每段旁白音频
  → adelay 对齐旁白时间轴
  → amix 混合全部旁白
  → AAC 封装进最终 MP4
```

画面确实由 Playwright 启动的无头 Chromium 录制；声音不是浏览器录音，而是后续由 FFmpeg 单独混入。这使音量问题可以在音频混合层独立修复，不影响页面渲染。

## 5. 方案设计

### 5.1 单路旁白处理

每个旁白输入继续使用现有顺序：

```text
adelay=<开始时间>|<开始时间>,volume=<narrationGain>
```

这样可以继续支持现有的旁白时间轴和用户配置增益。

### 5.2 关闭 amix 默认归一化

混音滤镜显式改为：

```text
amix=inputs=<N>:duration=longest:dropout_transition=0:normalize=0
```

课堂时间轴校验已禁止旁白片段互相重叠，因此关闭 `amix` 的输入数归一化符合当前数据模型。它会让任意时刻实际播放的单段旁白保持原始增益，不再因整节课包含 10 段或 50 段旁白而改变音量。

### 5.3 最终响度标准化

在 `amix` 后增加单遍 `loudnorm`：

```text
loudnorm=I=-16:TP=-1.5:LRA=11
```

目标含义：

- `I=-16`：综合响度目标为 `-16 LUFS`，适合网页和移动端以人声为主的视频；
- `TP=-1.5`：真峰值上限为 `-1.5 dBTP`，为 AAC 编码留出余量；
- `LRA=11`：限制过大的响度范围，同时保留自然的语音动态。

首版不额外叠加压缩器或限制器。`loudnorm` 已负责响度与真峰值约束，避免重复动态处理造成“广播腔”、泵动或失真。如果实际语音素材仍出现局部忽大忽小，再以测量结果决定是否增加轻量压缩。

### 5.4 输出音频参数

最终 AAC 输出固定为：

```text
-ar 48000 -b:a 128k
```

原因：

- `loudnorm` 内部处理可能提升采样率，显式输出为 48 kHz 可避免异常或不可预期的输出采样率；
- 128 kbps 对课堂人声有充足余量，并保持广泛播放器兼容性；
- 继续沿用 AAC，避免改变现有 MP4 容器和前端下载方式。

### 5.5 无旁白场景

如果整节课没有旁白输入，维持现有行为：直接复制无声视频为最终导出物，不执行音频滤镜，也不人为创建静音音轨。

  - 更新音频滤镜图；

- `Edu_AI/scripts/videoPipeline.test.ts`

不修改后端 API 契约、数据库、课堂生成任务格式或前端路由。

## 7. 错误处理与兼容性

- FFmpeg 运行失败时继续沿用现有导出失败处理和错误回传；
- `narrationGain` 仍在混音前应用，不改变配置含义；
- 时间轴重叠继续由现有校验拒绝，不在混音阶段隐式修复；
- 旧的课堂数据无需迁移，重新导出即可获得修复后的音量；
- 已经生成的 MP4 不会被自动覆盖或批量重制。

## 8. 测试策略

### 8.1 单元测试

验证生成的 FFmpeg 参数满足：

1. 每个旁白仍包含正确的 `adelay` 和 `volume`；
2. `amix` 明确包含 `normalize=0`；
3. 混音后只追加一次目标为 `-16 LUFS` 的 `loudnorm`；
4. 输出包含 48 kHz 与 128 kbps AAC 参数；
5. 无旁白输入时保持原有快速复制逻辑。

测试应先以旧实现运行并失败，再实施代码修改。

### 8.2 构建与回归

至少执行：

- 视频管线聚焦测试；
- 前端完整构建；
- 与视频导出相关的现有测试。

### 8.3 实际音频验收

使用短课堂样例完成一次真实 MP4 导出，并通过 FFmpeg 响度分析确认：

- 综合响度位于 `-18 LUFS` 至 `-14 LUFS`；
- 真峰值不高于 `-1.0 dBTP`；
- 多段旁白之间没有因片段数量增加而整体变小；
- 无削波、明显泵动或可闻失真；
- 画面、时长和音画同步未发生回归。
