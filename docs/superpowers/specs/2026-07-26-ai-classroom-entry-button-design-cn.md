# 对话工作台「AI 课堂」生成入口设计

日期：2026-07-26

## 目标

在教师前端对话页的右侧「生成式工厂」工作台中提供清晰、常驻的 AI
课堂生成入口。教师输入本节课主题后，系统在后台生成课件并持续反馈进度；生成完成
后自动进入播放器并开始课堂教学。

## 现状

- 对话页由 `AIWorkspacePage` 组织为知识源、对话、生成式工厂三栏。
- 右侧工作台由 `components/teacher/StudioPanel.tsx` 渲染。
- AI 课堂已有正式路由 `#classroom-studio`。
- 当前选中课程由 `AppShellProvider` 持有，并写入 `stitch-course` 本地存储；AI 课堂页面读取同一课程上下文，因此跳转时无需新增 URL 参数或状态同步。

## 方案比较

### 方案 A：标题栏常驻主按钮

在「生成式工厂」标题栏右侧、折叠按钮左侧放置主按钮「进入 AI 课堂」。

- 优点：入口始终可见，符合“进入”这一跨页面动作的重要级别；改动范围小。
- 缺点：只表达导航，不能自然承载“输入主题后开始生成”的任务语义；窄面板标题区域也容易拥挤。

### 方案 B：新增全宽课堂功能卡片（采用）

在「生成式工厂」标题与分隔线下方、其它生成入口上方新增一张醒目的全宽「AI
课堂」卡片。点击卡片中的「开始备课」按钮后打开主题输入弹窗。

- 优点：与报告、教案等生成任务处于同一工作流；有足够空间解释“输入主题—后台生成—自动开课”；视觉层级明确。
- 缺点：占用一行垂直空间，需要保持卡片信息精简。

### 方案 C：放在最近产物区域

在「最近产物」标题附近提供入口。

- 优点：靠近已生成内容。
- 缺点：入口位置偏下，空状态和长列表下的可发现性不足。

## 交互设计

1. 展开状态下，在工作台标题分隔线之后显示第一张全宽「AI 课堂」卡片；原有标题和折叠按钮保持不变。
2. 卡片说明教师可根据当前课程与知识库生成一节可播放、可导出的 AI 课堂。
3. 点击卡片按钮后打开主题输入弹窗；主题必填，提交期间禁止重复提交。
4. 提交调用现有 `POST /api/courses/{course_id}/classrooms/generate`，保持默认真人配音开启。
5. 后端返回 `202 + EduJob` 后，弹窗切换为任务进度状态，并轮询现有 `GET /api/jobs/{edu_job_id}`。
6. 轮询期间展示步骤、百分比和后端消息；偶发轮询失败继续下一轮，任务失败时保留错误并允许重试。
7. 任务成功后从 `result_ref.classroom_id` 取得课堂 ID，自动跳转到
   `#classroom-player?course_id=...&classroom_id=...`。
8. 播放器现有 `SlidePlayer` 默认 `autoPlay=true`，因此课件加载后自动从第一幕开始并逐场景推进。
9. 如果浏览器阻止有声自动播放，播放器沿用现有音频 → 浏览器 TTS → 阅读停留三级降级，不阻断课堂。
10. 组件卸载或导航离开时停止轮询并忽略晚到响应，避免状态泄漏。
11. 未选择课程时卡片按钮禁用并提示先选择课程；面板折叠状态不显示卡片。

## 代码边界

- 复用 `stitch/api/classroom.ts` 的 `generateClassroom` 与 `getJobStatus`，不复制 HTTP 请求。
- 抽取可测试的课堂生成任务轮询与播放器地址构造能力，组件只负责表单和状态展示。
- `StudioPanel` 渲染入口卡片、主题弹窗和任务进度，并在成功后导航。
- CSS 仅补充全宽入口卡片的视觉与响应式表现。
- 后端接口和数据模型已经满足流程，不新增重复路由；实现阶段以接口回归测试确认契约。
- 不修改 AI 课堂列表、播放器核心、PPTX 导出或视频导出流程。

## 测试与验收

1. 先添加失败单元测试，覆盖成功、失败、偶发轮询错误、取消与结果缺失。
2. 测试播放器地址正确编码 `course_id` 和 `classroom_id`。
3. 验证 `StudioPanel` 使用共享生成/轮询能力并呈现全宽「AI 课堂」卡片。
4. 运行前端测试、构建和 lint，以及课堂生成/任务路由后端回归。
5. 在浏览器中确认：
   - 卡片位于生成式工厂标题下方和其它生成入口上方；
   - 点击后弹出主题输入框；
   - 提交后能看到实时步骤和进度；
   - 成功后自动进入当前课程的新课堂并开始播放；
   - 失败可重试，折叠与其它生成入口未回归；
   - 课堂页仍可导出 PPTX、MP4 和 SRT。
