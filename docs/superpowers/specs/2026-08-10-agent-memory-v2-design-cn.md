# Agent Memory V2：课程协作场景下的长期记忆设计

日期：2026-08-10  
状态：已确认的架构记录，尚未进入实施计划  
适用范围：教师端 Agent、学生端 Agent、课程任务与学习反馈链路

## 1. 决策摘要

当前 Agent 记忆只能支撑同一对话中的上下文连续性和生成任务续跑，不能支撑“学生—课程—任务—知识点—学习证据”维度的长期学习记忆。

本项目采用以下方向：

1. 保留 LangGraph 作为 Agent 工作流与会话内短期记忆底座；
2. 建立以结构化学习事实为核心的教育记忆服务；
3. 使用事件日志记录学习过程，使用结构化状态表达进度和掌握度；
4. 使用向量/混合检索召回对话摘要、典型错误和重要反馈，但不让向量记忆成为完成率、得分和掌握度的事实源；
5. 教师 Agent 读取课程范围内的学习聚合与可授权证据，默认不读取学生私人 Agent 对话全文；
6. 第一阶段不引入 Graphiti 等时间知识图谱框架，先完成课程身份、学习事件和结构化记忆基础。

优先级结论：**Agent Memory V2 是高优先级基础能力，整体定为 P1；其中当前记忆可靠性、标识体系和学习事件契约属于 P0/P0.5。** 它不能先于课程身份与学习事件独立建设，但必须早于教师分析看板、高级个性化推荐和大规模教学洞察。

## 2. 当前实现

### 2.1 对话消息与对话状态

当前对话存储以 `conversation_id` 为核心，将消息和状态写入 `conversations.json`。每次构建上下文时加载最近 20 条消息。

对话结束后，系统使用规则从用户问题和 Agent 回答中抽取：

- 当前主题；
- 用户目标与约束；
- 教学问题；
- 学生信号；
- 用户陈述事实；
- 助手候选推测；
- 外部证据；
- 对话摘要。

默认配置下还会异步调用模型增强部分语义字段，但受保护的运行事实仍由规则和业务逻辑维护。

相关实现：

- `Edu_AI/api/src/core/conversation_storage.py`
- `Edu_AI/api/src/app/chat/persistence/conversation_store_adapter.py`
- `Edu_AI/api/src/app/chat/orchestrator/conversation_memory_extractor_v2.py`
- `Edu_AI/api/src/app/chat/orchestrator/llm_enhancement_router.py`

### 2.2 ReAct Agent 工作记忆

ReAct Agent 维护三类状态：

- `working_memory`：当前主题、资源类型、约束、来源选择和活动大纲；
- `task_ledger`：生成任务、工作流状态和材料引用；
- `conversation_summary`：有长度上限的轮次摘要。

LangGraph `MemorySaver` 保存进程内 checkpoint；允许持久化的工作流字段另外写入 SQLite `agent_runs.db`，用于服务重启后的状态恢复。

相关实现：

- `Edu_AI/api/src/app/chat/runtime/memory/manager.py`
- `Edu_AI/api/src/app/chat/runtime/graph/builder.py`
- `Edu_AI/api/src/app/chat/persistence/agent_run_store.py`
- `Edu_AI/api/src/app/chat/runtime/react_agent.py`

### 2.3 当前 RAG 的边界

项目已使用 Chroma 和混合检索处理课程文档、知识库与生成内容的知识来源。当前没有将学生长期记忆写入该向量存储，也没有基于用户、课程、任务、知识点和权限检索历史学习记忆。

因此，当前 RAG 是“课程知识检索”，不是“用户长期记忆检索”。

## 3. 现有能力的主要缺口

### 3.1 记忆作用域不正确

当前主要作用域是：

```text
conversation_id → 最近说了什么、当前正在生成什么
```

目标作用域应当是：

```text
student_id × course_id × knowledge_point_id × task_id × time
→ 学习行为
→ 学习结果
→ 掌握状态变化
→ 教师反馈
→ 后续学习建议
```

### 3.2 缺少学习事件

系统尚未统一记录以下行为：

- 开始、暂停和完成学习；
- 文档阅读与视频观看进度；
- 测验作答、正确率和重试；
- 作业提交、退回和补交；
- 与 Agent 的学习型对话、求助和复习；
- 教师评价、批注和干预；
- 自主学习与教师任务学习的来源区别。

### 3.3 缺少结构化掌握状态

当前 `student_signals` 是从对话中抽取的短文本信号，不能等价为知识点掌握度。系统需要可追溯、可重新计算、带置信度的掌握状态。

### 3.4 缺少跨会话记忆实现

代码中存在 `MemoryReader`、`MemoryWriter` 和 `ConversationSummarizer` 协议，但生产链路没有接入跨会话实现。新对话无法自动召回同一学生在同一课程下的历史学习状态。

### 3.5 两套运行记忆存在一致性风险

LangGraph checkpoint 与 SQLite 快照分别保存状态。当前 `agent_memory` 在图执行完成后更新到 SQLite，但下一轮合并时进程内 checkpoint 对同名字段具有更高覆盖优先级，可能造成工作记忆恢复滞后。实施 Memory V2 前必须统一权威来源并补充端到端恢复测试。

### 3.6 存储方式不适合多人协作

JSON 文件整文件重写适合单机开发，不适合多教师、多学生和多进程并发。长期学习数据需要数据库事务、索引、权限过滤和可审计迁移。

## 4. 设计原则

### 4.1 结构化事实优先

任务状态、提交状态、得分、截止时间、学习进度和掌握度必须存储为结构化数据。模型摘要和向量记忆只能作为派生信息。

### 4.2 证据与推断分离

每个掌握度或风险判断至少包含：

- 结论；
- 证据来源；
- 证据时间；
- 计算或模型版本；
- 置信度；
- 是否允许教师或学生查看。

“连续三次同类题错误”是事实，“学习动力不足”是推断，两者不得混存。

### 4.3 记忆按角色和作用域授权

- 学生 Agent 可读取本人的课程学习状态和私人学习记忆；
- 教师 Agent 可读取其任教课程内的任务表现、知识点状态和教学所需摘要；
- 学生私人 Agent 对话全文默认不向教师开放；
- 教师端优先读取派生教学信号、相关证据和班级聚合；
- 所有跨角色读取都必须经过课程成员关系和权限校验。

### 4.4 写入与读取解耦

高频学习事件先可靠落库；掌握度更新、对话归纳、向量化和班级聚合可以异步执行。异步失败不得丢失原始学习事实。

### 4.5 可删除、可更正、可重算

用户更正、课程退出、数据删除和模型升级后，系统应能够撤销派生记忆并从原始事件重新计算。

## 5. 目标记忆架构

```text
L0 会话工作记忆
  当前消息、活动任务、活动大纲、工具状态

L1 学习事件记忆
  阅读、观看、答题、提交、反馈、复习、Agent 学习互动

L2 学习状态记忆
  课程进度、任务进度、知识点掌握度、误区、复习计划

L3 语义与情节记忆
  重要对话摘要、典型错误、关键反馈、学习偏好、成功学习经历

L4 教师聚合记忆
  班级趋势、薄弱知识点、任务完成情况、风险信号、干预效果

L5 程序性记忆
  Agent 教学策略、课程规则、隐私策略和工具使用约束
```

L0 使用 LangGraph checkpoint。L1、L2 和 L4 使用结构化数据库。L3 使用结构化元数据加向量/关键词混合检索。L5 由版本化配置、提示词和策略代码管理，不与学生事实混写。

## 6. 核心数据模型

### 6.1 `learning_events`

记录不可丢失的原始学习行为：

- `event_id`
- `student_id`
- `course_id`
- `task_id`
- `resource_id`
- `knowledge_point_id`
- `event_type`
- `learning_mode`：`self_directed` 或 `teacher_assigned`
- `payload`
- `occurred_at`
- `source`
- `schema_version`

### 6.2 `task_progress`

记录学生在任务维度的确定性状态：

- 未开始、进行中、已完成、逾期、已提交、已退回；
- 完成比例；
- 最近活动时间；
- 尝试次数；
- 得分与教师评价引用。

### 6.3 `knowledge_mastery`

记录学生在课程知识点下的当前状态：

- `mastery_score`
- `confidence`
- `evidence_count`
- `last_practiced_at`
- `next_review_at`
- `misconception_codes`
- `calculation_version`
- `updated_from_event_id`

掌握度不得直接由页面停留时间推导。第一版使用可解释的规则加权模型，后续再通过离线评估升级算法。

### 6.4 `memory_items`

保存可供 Agent 检索的长期语义和情节记忆：

- 记忆所有者与可见范围；
- 用户、课程、任务和知识点作用域；
- 记忆类型；
- 文本内容与结构化载荷；
- 来源事件或消息引用；
- 重要度、置信度和有效期；
- embedding；
- 创建、更新、失效和删除状态。

### 6.5 `course_learning_insights`

保存教师可读取的课程聚合结果：

- 知识点掌握分布；
- 任务完成与逾期分布；
- 高频误区；
- 需要关注的学生；
- 教师干预前后的变化；
- 生成时间、数据范围和计算版本。

## 7. 写入链路

```text
学生行为或教师反馈
→ 权限与标识校验
→ learning_events 原子写入
→ task_progress 确定性更新
→ knowledge_mastery 增量更新
→ 异步记忆归纳与向量化
→ 班级聚合刷新
```

聊天本身不是学习完成的充分证据。只有满足明确规则的 Agent 学习互动，才生成学习事件；例如完成诊断问题、通过知识点检查或主动请求复习。

## 8. 读取链路

### 8.1 学生 Agent

根据当前 `student_id + course_id + task_id/knowledge_point_id` 读取：

1. 当前任务和知识点结构化状态；
2. 最近有效证据；
3. 相关误区和教师反馈；
4. 语义相关的少量历史记忆；
5. 当前课程允许使用的学习资源。

### 8.2 教师 Agent

根据当前 `teacher_id + course_id` 读取：

1. 班级聚合；
2. 指定任务或知识点分布；
3. 指定学生的授权学习状态；
4. 支撑风险判断的学习证据；
5. 已采取的教学干预及后续变化。

上下文组装器应先查询结构化事实，再检索语义记忆，最后按 token 预算和权限生成 Agent 上下文。

## 9. 技术选择

### 9.1 采用

- LangGraph：保留现有 Agent 工作流和会话短期状态；
- PostgreSQL：生产环境中的课程、成员、任务、事件、掌握度和聚合事实源；
- pgvector：长期记忆的向量检索，与结构化权限过滤放在同一数据库；
- SQLite：仅用于本地开发和单元测试适配；
- 现有 Chroma：第一阶段继续服务课程文档 RAG，不与用户长期记忆强行混库。

### 9.2 暂不采用

- Mem0：可在后续作为对话记忆抽取、去重和检索适配器，但不成为教育事实源；
- Graphiti：待课程事件与掌握模型稳定后，再评估是否需要时间知识图谱；
- Letta：不替换现有 LangGraph/ReAct Agent Runtime。

## 10. 优先级与实施顺序

### P0：交互链路前置基础

1. 统一 `course_id`、课程加入码和课程成员关系；
2. 拆分课程资源与学习任务；
3. 统一 `task_id`、`resource_id`、`knowledge_point_id`；
4. 定义学习事件契约与权限模型。

没有这些稳定标识，任何长期记忆都会混入无法归属、无法聚合的数据。

### P0.5：当前记忆可靠性

1. 修复 LangGraph checkpoint 与 SQLite `agent_memory` 的权威来源和合并顺序；
2. 为同进程多轮、服务重启、跨课程和跨用户隔离补端到端测试；
3. 将生产对话状态从整文件 JSON 写入迁移到数据库；
4. 接通生产级跨会话 MemoryReader/Writer 接口。

### P1：Memory V2 核心能力

1. 建立 `learning_events`；
2. 建立 `task_progress`；
3. 建立可解释的 `knowledge_mastery`；
4. 完成学生 Agent 结构化记忆读取；
5. 完成教师 Agent 班级聚合读取；
6. 完成可见范围、来源追踪、删除和更正。

### P2：语义长期记忆

1. 建立 `memory_items`；
2. 异步归纳重要对话、误区和反馈；
3. 向量、关键词、时间衰减和元数据过滤混合检索；
4. 建立记忆召回质量评估集。

### P3：高级记忆

1. 时间知识图谱；
2. 干预效果因果分析；
3. 跨课程能力迁移；
4. 自动遗忘和长期记忆压缩策略。

## 11. 验收标准

Memory V2 核心阶段完成时，应满足：

1. 学生换一个新对话后，Agent 仍能读取其当前课程、任务进度和知识点状态；
2. 自主学习与教师任务学习能够分别记录和联合分析；
3. 每个掌握度结论能够展示来源证据、时间和置信度；
4. 教师能够查看班级与学生维度反馈，但无法读取未授权的私人对话；
5. 学生更正事实或删除记忆后，后续 Agent 不再召回失效内容；
6. 服务重启不丢失工作流状态和长期学习状态；
7. 同一用户不同课程、不同用户同一课程之间不存在记忆串线；
8. 检索不到可靠记忆时，Agent 明确表示缺少依据，不自行补造学习历史；
9. 所有派生掌握状态都可以从原始学习事件重算；
10. 教师端聚合数据与学生端个人进度使用同一套事实源。

## 12. 风险控制

- **错误记忆固化**：保存来源、置信度和有效期，支持更正和撤回；
- **隐私越权**：读取前执行课程成员和字段级权限检查，不依赖提示词约束；
- **向量召回污染**：先按用户、课程、角色和有效状态过滤，再进行相似度排序；
- **掌握度误判**：第一版使用可解释规则，避免直接用模型给出不可复核分数；
- **异步任务失败**：原始学习事件先落库，派生状态可重放；
- **系统过度设计**：第一阶段不引入时间图数据库，不实现跨课程迁移和复杂遗忘算法。

## 13. 后续拆分

该架构记录不直接对应一次性大改。正式实施前应拆分为四个独立规格与计划：

1. 课程身份、成员与学习任务基础；
2. 学习事件与任务进度；
3. 掌握度与双端结构化记忆；
4. 语义长期记忆与检索评估。

每个子项目独立设计、测试和验收，避免同时重写课程、Agent、RAG 和分析看板。
