# 叶子知识点标准学习资源与学习闭环（阶段二）设计

**日期：** 2026-08-24

**状态：** 产品方案已确认，待书面审阅后实施

**前置设计：** `docs/superpowers/specs/2026-08-24-course-content-frontend-phase1-design-cn.md`

## 1. 背景与现状证据

阶段一已经完成双端知识图谱页面收口、个人资源单空间和主题入口迁移。知识结构后端继续保留，用于文档作用域、标准资源、学习任务、测评统计和后续分层检索。

当前 PostgreSQL 中教师账号实际可访问的测试课程是：

- `course_id=course-a385a289be0d44e480e343472f6cc8cd`
- 名称为“数据库”，教师 `teacher` 是 `owner`
- 课程知识图只有空根节点，没有叶子知识点
- 课程知识库没有文档
- 没有材料、学习任务或学习进度
- 课程描述、受众和目标是占位值 `1`

因此本阶段先以该课程建立可重复的最小测试基线，再实现标准资源生成、审核发布、任务快照和学习证据闭环。明天导入正式数据库与文件目录后，使用同一验收流程做真实数据回归。

## 2. 目标

1. 课程级一键生成只处理当前已发布知识结构中的叶子知识点。
2. 每个叶子知识点固定维护三类标准资源：AI课堂、学习讲义、练习测评。
3. 标准资源与用户个人资源、旧课程共享副本在数据上明确区分。
4. 标准资源支持批次状态、失败重试、单项审核、批量通过和版本替换。
5. 学生只能看到已经审核通过的标准资源。
6. 教师可以使用已通过标准资源或自己的个人资源创建学习任务，不再要求发布个人资源到课程共享空间。
7. 学习任务保存不可变资源快照，源资源后续更新或删除不改变已发布任务。
8. 阅读活动、学生自报和测评通过使用不同的完成证据，不把“打开过资源”等同于掌握知识点。
9. 教师能够按任务、学生和知识点查看学习进度及测评掌握情况。

## 3. 非目标

本阶段不处理：

1. 自动删除或转换明天迁入的旧课程共享副本。
2. 将旧共享资源自动认定为标准资源。
3. 修改 RAG 检索策略、实现分层 RAG 或 Agentic RAG。
4. 用浏览器活动数据证明学生绝对理解了内容；活动证据只代表完成了可观测学习行为。
5. 非叶子知识点的标准资源生成。
6. 所有者转移、跨课程复用或标准资源市场。

## 4. 方案选择

采用“扩展现有材料体系”的方案，不建立第二套内容存储。

原因：现有 `materials`、`material_versions`、`artifact_files`、后台任务、资源预览和生成器已经覆盖内容落库及文件管理。新增标准资源领域元数据和批次编排即可复用这些能力，同时避免单独建立标准资源表后重复实现版本、文件、权限和预览。

不采用仅写入 `raw_payload` 的方案。来源、审核状态、批次和已批准版本必须能够被数据库索引、迁移和权限查询可靠使用。

## 5. 最小测试课程基线

新增幂等种子脚本，只允许显式传入课程 ID，不在应用启动时自动执行。脚本对目标课程执行前先检查知识图、文档、材料和任务；发现非测试内容时默认拒绝覆盖。

知识结构：

```text
数据库
├─ 关系模型
│  ├─ 关系与键
│  └─ 完整性约束
├─ SQL 查询
│  ├─ 单表查询
│  └─ 多表连接
└─ 事务管理
   ├─ ACID
   └─ 并发控制
```

六个叶子知识点使用稳定 ID。脚本同时写入一份课程级“数据库基础测试讲义”，用六个二级标题分别覆盖六个叶子知识点。标准资源生成器优先读取叶子作用域文档；叶子没有独立文档时，允许回落到课程级文档，并使用叶子 ID、标题和标题对应章节限定生成上下文。只有当描述、受众和目标仍精确等于占位值 `1` 时，脚本才将其替换为数据库基础课程的测试元数据。

执行真实写入前创建 PostgreSQL 备份。脚本重复执行不得重复创建图版本、知识文档或课程目标。

## 6. 标准资源数据模型

### 6.1 材料主记录

`materials` 增加：

- `origin_type`: `personal | standard | legacy_shared`
- `standard_kind`: `classroom | study_guide | practice | null`
- `generation_batch_id`: 最近一次生成该资源的批次 ID，可为空
- `current_review_status`: `not_required | pending | approved | rejected`
- `approved_version`: 当前对学生可见的已批准版本，可为空
- `approved_by`、`approved_at`

标准资源固定满足：

- `origin_type=standard`
- `scope_type=knowledge_point`
- `scope_id=<leaf_node_id>`
- `material_id=standard-<leaf_node_id>-<standard_kind>` 的稳定逻辑 ID

标准类型与现有生成材料类型的映射：

| 标准类型 | 现有材料类型 | 生成能力 |
| --- | --- | --- |
| `classroom` | `classroom` | 现有 OpenMAIC AI课堂生成 |
| `study_guide` | `report` | 现有报告生成器，使用学习讲义预设 |
| `practice` | `quiz` | 现有习题生成器，使用练习测评预设 |

### 6.2 材料版本审核

`material_versions` 增加：

- `origin_type`
- `standard_kind`
- `generation_batch_id`
- `review_status`
- `reviewed_by`、`reviewed_at`
- `rejection_reason`

重新生成标准资源时增加材料版本并将新版本设为 `pending`，但不立即改变 `approved_version`。学生继续读取旧批准版本；只有新版本审核通过后，主记录的 `approved_version` 才原子切换。首次生成尚未审核时学生不可见。

### 6.3 生成批次

新增 `standard_resource_batches`：

- `batch_id`、`course_id`
- `graph_version`
- `idempotency_key`
- `status`: `queued | running | review_pending | completed | partially_failed | failed`
- `triggered_by`
- 计划数、成功数、失败数、待审核数、已通过数
- 创建、开始、完成和更新时间

新增 `standard_resource_batch_items`：

- `batch_item_id`、`batch_id`
- `knowledge_node_id`、`knowledge_node_title`
- `standard_kind`、目标材料类型
- `status`: `queued | running | pending_review | approved | rejected | failed`
- `job_id`、`material_id`、`material_version`
- 稳定错误码、用户可读错误、重试次数和时间字段

同一批次中 `(knowledge_node_id, standard_kind)` 唯一。创建批次时只读取指定图版本的叶子节点；非叶子节点不产生明细。

## 7. 生成与审核流程

```text
教师点击“一键生成标准资源”
→ 服务读取当前发布知识图版本
→ 计算叶子知识点 × 三种标准类型
→ 以幂等键创建批次与明细
→ 每条明细提交到现有后台任务系统
→ 生成器优先读取知识点作用域资料，缺失时读取课程级资料中的对应章节
→ 成功内容保存为标准材料的新待审核版本
→ 教师预览并单项通过/驳回，或批量通过全部待审核项
→ approved_version 原子切换
→ 学生端出现已通过版本
```

批次允许部分成功。一个生成任务失败不会回滚其他任务；教师可只重试失败项。重复点击相同幂等键返回已有批次，不创建重复材料或后台任务。

审核接口必须验证课程 `owner/editor` 权限、资源属于该课程、作用域节点仍存在且版本仍是待审核版本。驳回必须保存原因。批量通过只处理调用时仍为 `pending` 的版本，不覆盖并发产生的新版本。

## 8. API 边界

新增课程标准资源 API：

- `GET /api/courses/{course_id}/standard-resources`
- `POST /api/courses/{course_id}/standard-resource-batches`
- `GET /api/courses/{course_id}/standard-resource-batches/{batch_id}`
- `POST /api/courses/{course_id}/standard-resource-batches/{batch_id}/retry`
- `POST /api/courses/{course_id}/standard-resources/{material_type}/{material_id}/review`
- `POST /api/courses/{course_id}/standard-resource-batches/{batch_id}/approve-pending`

教师响应包含当前版本、批准版本、审核状态和批次状态。学生响应只返回 `approved_version` 对应内容，不返回待审核版本、错误详情或后台任务标识。

旧 `GET .../materials?space=course` 保留兼容，但新标准资源页面和新学习任务选择器不得依赖旧共享空间。

## 9. 前端信息架构

课程知识页不恢复“知识图谱”页签。在现有课程知识库中增加“标准学习资源”区域：

- 按叶子知识点折叠分组。
- 每个知识点固定显示 AI课堂、学习讲义、练习测评三个资源位。
- 空缺、生成中、失败、待审核、已通过和已驳回使用明确文字状态，不能只依赖颜色。
- 教师顶部提供“一键生成标准资源”，确认框显示叶子数、总资源位、缺失数和将重新生成的数量。
- 教师可以预览、审核、批量通过和重试。
- 学生只看到已通过资源；没有已通过资源的知识点显示明确空状态。

后台任务中心继续展示生成任务。标准资源区域展示领域状态，任务中心展示执行状态，两者使用 `job_id` 关联但不复制轮询器。

## 10. 学习任务快照

`learning_tasks` 增加 `task_type`: `reading | assessed`。旧任务按现有强制测评行为回填为 `assessed`。

新增 `learning_task_resource_snapshots`，每条快照保存：

- `snapshot_id`、`task_id`、顺序
- 源材料的课程、类型、ID、版本和内容哈希
- `origin_type`、`standard_kind`、知识点 ID
- 创建任务时的标题和经过安全过滤的完整内容负载
- 复制到任务快照目录后的文件引用
- 创建时间

`learning_tasks.resource_refs` 继续保留用于兼容旧客户端，但新任务以快照表为权威来源。任务创建事务先校验资源权限，再保存数据库快照和任务文件副本；任一步失败都不创建半成品任务。

教师可选择：

- 已审核通过的课程标准资源；
- 当前教师自己的个人资源。

学生通过任务资源端点读取快照。个人资源不需要变成课程共享资源，源资源后续更新、删除或失去批准状态也不影响已经发布的任务快照。

## 11. 学习证据与掌握度

继续复用现有 `learning_events`、`learning_progress`、测评和教师分析能力，并扩展事件校验：

- `self_reported`：学生主动点击完成，仅表示自报。
- `activity_evidenced`：资源活动达到规则，例如 AI课堂/视频有效播放进度、讲义阅读时长与页面进度达到阈值。
- `assessment_verified`：测评提交并达到任务通过线。

证据强度只允许单向提升：`none < self_reported < activity_evidenced < assessment_verified`。事件必须引用当前任务的快照，使用稳定事件 ID 幂等写入，进度不可倒退。

阅读型任务可以由活动证据完成；学生自报完成仍保留为较弱口径。测评型任务只有达到测评通过线才能形成 `assessment_verified`。知识点“掌握”只使用测评证据；阅读活动只计入学习完成情况。

教师端展示：

- 任务报名、开始、完成和证据口径分布；
- 每名学生的任务进度和最后活动；
- 每个知识点的测评样本数、通过率和待人工批改数；
- 没有测评样本时显示“暂无掌握证据”，不得显示 0% 掌握误导用户。

## 12. 权限

- 课程 `owner/editor`：创建批次、重试、审核标准资源、创建及发布任务、查看课程学习统计。
- 课程 `viewer` 和学生系统角色：读取已批准标准资源、读取分配给自己的任务快照、提交自己的学习事件和测评。
- 个人资源：仍只有资源所有者可管理。
- 任务快照：课程教师可审阅；学生只能读取自己可见的已发布任务快照。
- 标准资源写操作不能复用“个人资源所有者”判断，必须使用课程管理权限。

## 13. 迁移与旧数据

Alembic 迁移采用先新增可空字段、回填、再收紧约束的顺序：

1. 私有材料回填 `origin_type=personal`、`current_review_status=not_required`。
2. 课程可见材料回填 `origin_type=legacy_shared`、`current_review_status=not_required`。
3. 不根据标题、创建者或作用域猜测旧资源是标准资源。
4. 旧任务回填 `task_type=assessed`，已有 `resource_refs` 保持可读；不伪造缺失快照。
5. 新任务必须写快照，旧任务继续走兼容读取路径并在界面标注“历史任务引用”。

明天迁入正式数据库后先执行只读审计：课程数、成员、图版本、文档、材料来源、任务引用、文件存在性和内容哈希。只有确认个人原件、任务引用和文件完整后，才能另行决定旧共享副本的归档或清理。

## 14. 错误处理

1. 没有发布知识图、没有叶子节点或没有可用知识文档时拒绝创建生成批次，并返回可操作提示。
2. 外部模型失败、超时或输出不合法时保存稳定错误码和可重试状态，不伪造成功资源。
3. 图版本在批次执行期间变化时，批次继续绑定原快照；新图需要新批次。
4. 节点在后续图版本中消失时，其标准资源标记归档并从学生新列表隐藏，不物理删除。
5. 审核新版本失败时，旧 `approved_version` 继续可读。
6. 任务快照文件复制失败时回滚任务及临时文件。
7. 学习事件伪造非任务资源、其他学生身份或倒退进度时拒绝写入。

## 15. 测试与验收

### 15.1 自动化

- Alembic 升级、回填、降级边界和修订链测试。
- PostgreSQL 材料版本审核、批次幂等和任务快照仓储测试。
- 叶子节点识别、稳定材料 ID、部分失败和重试服务测试。
- 教师/学生权限与批准版本读取 API 测试。
- 阅读型、测评型任务及证据强度单向提升测试。
- 前端资源覆盖矩阵、审核操作、任务选择器和知识点统计测试。
- 完整前后端测试、lint、生产构建。

生成器自动化测试使用可注入的确定性实现，验证状态机而不依赖外部模型。运行态验收使用当前配置的真实后台任务；真实模型失败必须进入可重试失败状态。

## 16. 完成标准

只有同时满足以下条件，才能宣称阶段二完成：

1. 标准资源、个人资源和旧共享资源可被数据库稳定区分。
2. 一键生成只覆盖叶子节点，批次可追踪、可幂等、可部分重试。
3. 新版本待审核期间旧批准版本持续可用。
4. 学生无法读取待审核或已驳回版本。
5. 个人资源无需发布即可通过不可变任务快照分配给学生。
6. 阅读活动、学生自报和测评验证在界面及统计中明确区分。
7. 教师按任务、学生和知识点查看的数据与数据库证据一致。
8. 当前测试课程完成端到端验收，并留下明日正式数据库回归清单。
9. 旧共享资源未被误删，RAG 未被混入本阶段。
