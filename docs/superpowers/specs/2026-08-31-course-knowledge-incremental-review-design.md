# 课程知识库增量更新与图谱审核界面设计

日期：2026-08-31  
状态：已完成方案确认，等待用户审阅

## 1. 背景与目标

当前课程已有知识库时，再次进入“知识库生成”仍会创建一份不含当前图谱的草案，默认更新策略也是 `merge_rebuild`。因此生成流程可能重新组织甚至遗漏已有节点，不符合用户对“更新”的预期。

第三阶段把整棵图谱的所有节点同时渲染为连续表单。节点较多时页面极长、文字和操作密集，用户难以定位当前节点、问题节点和未保存修改。

本次改造有两个目标：

1. 已有知识库再次生成时，默认在当前已发布图谱上增量追加，强制保留全部已有节点。
2. 第三阶段改为顶部状态区、左侧可折叠树和右侧单节点编辑器，提升大图谱审核效率与可读性。

## 2. 已确认的产品决策

- 增量更新保留全部已有节点及其稳定 ID、名称、层级和父子关系。
- 同名知识点不创建重复节点；允许补充说明、教材映射和资料覆盖。
- 新知识点追加到匹配的已有父节点下。
- 增量流程不允许自动删除、改名或移动已有节点。
- 默认更新策略为 `incremental`。
- `merge_rebuild` 和 `full_rebuild` 放入高级设置；`full_rebuild` 必须二次确认。
- 审核页采用左侧可折叠图谱树、右侧当前节点编辑器、顶部统计与问题提醒。
- 窄屏下不强行并排，改为“图谱 / 节点详情”分页切换。

## 3. 范围与非目标

### 3.1 本次范围

- 创建草案时载入当前已发布图谱及其版本号。
- 生成候选图谱后执行确定性的保留式合并。
- 在保存、确认和发布前校验基线节点不变量。
- 调整默认更新策略和高级重建入口。
- 重构第三阶段审核组件与样式。
- 增加后端单元测试、前端状态测试和端到端流程测试。

### 3.2 非目标

- 不引入画布式或力导向图谱编辑器。
- 不实现批量拖拽、多人实时协作或自动冲突合并。
- 不改变知识资料抓取、Rerank、质量门禁和版本回滚的核心机制。
- 不允许增量模式自动清理“低质量旧节点”；清理必须进入显式重建流程。

## 4. 数据模型与草案上下文

创建知识库草案时，服务端读取该课程最新的 `KnowledgeGraphVersion`。若存在已发布图谱，在构建草案的计划数据中保存：

- `baseline_graph_version`：基线版本号。
- `baseline_graph`：创建草案时的完整图谱快照。
- `current_graph_summary`：供模型理解现有结构的紧凑摘要。
- `config.update_strategy`：默认值为 `incremental`。

这些字段保存在现有构建记录的计划 JSON 中，不要求新增数据库列。草案始终绑定创建时的基线版本，避免用户审核期间当前图谱被其他发布操作替换而不自知。

首次构建没有基线图谱，仍使用相同流程，只是保留式合并的基线为空。

## 5. 增量生成与保留式合并

### 5.1 模型输入

图谱生成器接收课程信息、配置、教材信息、当前图谱摘要和更新策略。增量模式下提示模型：

- 优先复用已有节点 ID。
- 对已有节点仅提出说明或教材映射补充。
- 只生成真正缺失的节点。
- 不建议删除、改名或移动已有节点。

提示词约束只负责提高候选质量，最终保证由后端确定性合并完成。

### 5.2 节点匹配

候选节点按以下顺序匹配基线节点：

1. 稳定 ID 完全一致。
2. 在同一已匹配父节点下，规范化名称一致。
3. 无法匹配时视为新增节点。

规范化名称只处理首尾空白、连续空白、大小写和常见全半角差异，不进行模糊语义合并，避免误合并不同知识点。

### 5.3 合并规则

对已匹配的旧节点：

- 保留原 ID、名称、类型、父节点和子节点顺序。
- 说明为空时可采用候选说明；说明非空时只追加去重后的补充信息。
- 教材映射与来源引用做集合并集。
- 保留所有旧子节点，再按候选顺序追加新子节点。

对新增节点：

- 使用候选稳定 ID；若发生冲突则生成确定性新 ID。
- 父节点必须能匹配到基线或已接受的新增节点。
- 无法确定父节点时标记为 `needs_parent`，进入“待确认新增节点”，不得直接确认发布。

草案节点使用临时审核元数据标记 `existing`、`new`、`needs_review` 和 `needs_parent`。发布时可以移除纯 UI 元数据。

### 5.4 不变量校验

保存图谱、确认图谱和正式发布前都执行同一组校验：

- 基线中每个节点 ID 都仍然存在。
- 基线节点名称、类型和父节点没有变化。
- 基线父子关系和原有子节点相对顺序没有变化。
- 新节点 ID 唯一，且父节点存在。
- 不存在 `needs_parent` 节点。

校验失败时返回结构化错误，不允许静默降级为重新建库。

## 6. 更新策略界面

配置步骤默认展示说明：“增量追加：保留现有知识结构，只补充新节点与资料。”

常规界面只展示增量策略。高级设置折叠区提供：

- 合并重建：允许模型重组结构，但保留历史版本。
- 完全重建：从空图谱生成新结构。

选择完全重建后，继续按钮触发二次确认，明确说明现有结构可能被替换，但历史版本仍可回滚。

已有知识库时主按钮文案为“增量更新知识库”；首次构建仍为“一键构建知识库”。

## 7. 第三阶段审核界面

### 7.1 顶部状态区

顶部显示六项核心指标：全部节点、模块、知识点、教材映射、本次新增、待完善。正文使用不低于 16px 的可读字号，普通文本对比度不低于 4.5:1。

问题提醒按严重程度排列，并提供以下筛选：

- 全部
- 本次新增
- 待完善
- 已映射教材

保存状态持续显示“已保存”或“有未保存修改”，不只使用颜色表达。

### 7.2 左侧图谱树

左栏约占可用宽度的 35%，包含：

- 搜索框。
- 全部展开、全部折叠。
- 可折叠层级树。
- 节点类型、名称、直属子节点数量。
- “新增”“待完善”“待选择父节点”“教材已映射”等文字标签。

树支持键盘导航，焦点顺序与视觉顺序一致。打开审核页时优先选中第一个问题节点；没有问题时选中课程根节点。

### 7.3 右侧节点编辑器

右栏只渲染当前选中节点，包含：

- 节点名称与类型。
- 内容说明。
- 父节点。
- 教材映射和来源引用。
- 直属子节点摘要。

增量模式下，旧节点的名称、类型、父节点、移动和删除操作禁用，并显示原因。旧节点仍可补充说明和教材映射。新增节点可正常编辑、移动和删除。

“重新生成当前模块”“移动”“删除”等低频或高风险操作放入“更多操作”，避免每个节点同时展示大量按钮。

### 7.4 固定操作区与响应式布局

底部操作栏固定在审核区域内，始终提供：

- 返回教材步骤
- 保存草案
- 确认图谱并开始构建

桌面端采用两栏布局。宽度不足 768px 时使用“图谱 / 节点详情”分页切换；375px、768px、1024px 和 1440px 宽度下不得产生页面级横向滚动。

## 8. 状态与组件边界

审核步骤维护以下界面状态：

- `selectedNodeId`
- `expandedNodeIds`
- `treeQuery`
- `activeFilter`
- `mobilePane`
- `impactAccepted`

图谱数据修改继续通过纯函数完成。建议拆分为：

- `CourseKnowledgeGraphReviewStep`：数据编排、保存和确认。
- `KnowledgeGraphReviewSummary`：指标、警告和筛选。
- `KnowledgeGraphTree`：搜索、折叠和选择。
- `KnowledgeGraphNodeEditor`：单节点编辑与保护规则。
- `KnowledgeGraphReviewActions`：固定底部操作区。

组件通过节点 ID 和回调通信，不在子组件中复制整棵图谱状态。

## 9. 错误处理与并发

- 当前图谱读取失败：阻止创建增量草案并提示重试。
- 基线版本已变化：保存或确认返回版本冲突；保留本地草案，提示刷新并重新合并。
- 同名但父节点不同：不自动合并，标记为待确认。
- 旧节点不变量被破坏：返回具体节点和违反规则，审核页自动定位该节点。
- 保存失败：保持未保存状态和本地编辑内容，错误区域使用 `role="alert"`。
- 重建操作：必须显式选择，完全重建必须二次确认。

## 10. 测试与验收

### 10.1 后端

- 创建增量草案时包含最新基线版本和完整基线图谱。
- 稳定 ID 匹配保留旧节点。
- 同父节点同名候选合并而不重复创建。
- 所有旧节点、名称和父子关系在合并后保持不变。
- 新节点正确追加到匹配父节点。
- 无法确定父节点的新节点阻止确认。
- 旧节点缺失、改名或移动时校验失败。
- 首次构建在空基线上正常工作。

### 10.2 前端

- 已有知识库时按钮显示“增量更新知识库”。
- 默认配置为 `incremental`。
- 高级设置可选择重建，完全重建触发二次确认。
- 树支持展开、折叠、搜索、筛选和键盘选择。
- 右侧只渲染当前节点编辑器。
- 增量模式正确锁定旧节点结构操作，并允许编辑补充字段。
- 新增节点可以编辑、移动和删除。
- 问题提醒可定位到对应节点。
- 未保存状态和保存错误对辅助技术可见。

### 10.3 端到端

- 基于已有图谱再次生成后，旧节点集合、名称和父子关系完全一致。
- 新知识点被追加并标记为“本次新增”。
- 确认后发布新版本，旧版本仍可查看和回滚。
- 大图谱审核不再渲染连续长表单。
- 375px、768px、1024px、1440px 下无页面级横向溢出。

## 11. 交付判定

只有同时满足以下条件才视为完成：

1. 增量更新具备后端不变量保证，而不是仅依赖提示词。
2. 已有知识库再次生成不会删除、改名或移动任何旧节点。
3. 审核页实现左树右编辑器，并在窄屏切换为分页视图。
4. 相关后端、前端和端到端测试通过。
5. 完全重建保留历史回滚能力，并有明确二次确认。
