# 学习任务强制测评闭环设计

日期：2026-08-12

状态：已实现并通过自动化端到端验收；安全代码执行器按 D-003 留待后续

前置交付：

- `2026-08-10-teacher-student-interaction-loop-phase2-design-cn.md`

## 0. 决策摘要

每个学习任务都必须包含一份经过教师确认的正式测评；没有正式测评版本的任务不得发布。

测评来源分为两条路径：

1. 教师选中的材料已经包含习题时，系统抽取并标准化已有题目，教师审核后生成不可变测评快照。
2. 选中材料没有习题或题目不足时，系统依据材料、任务说明和知识点生成测评草稿，教师审核后生成不可变测评快照。

采用独立测评域，不把题目、作答和成绩直接塞进 `LearningTask`，也不把可变课程资源直接当作正式测评。学习任务只绑定已发布的 `AssessmentVersion`；学生所有作答、自动评分、AI 初评、教师复核和反馈都有独立、可追溯的结构化记录。

默认规则：

- 及格线 60 分，教师可调整。
- “掌握良好”参考线 80 分，教师可调整，且不得低于及格线。
- 最多作答 3 次，教师可调整为 1–10 次。
- 任务结果取最高一次最终成绩，所有作答记录永久保留。
- 仍有重做机会时不直接展示完整标准答案；达到及格线后学生可结束计分周期并揭示解析，次数用尽后按教师设置揭示答案与解析。
- 客观题由服务端确定性评分。
- 主观题、成果提交和本期的编程实现题只允许 AI 给出建议分，必须经教师确认后才能形成最终成绩。
- 安全代码运行与隐藏测试用例判题预留接口，本期不实现。

## 1. 背景与问题

现有学习回环已经能记录 `started`、`resource_opened`、`completed` 和 `assessment_scored` 等学习事件，并区分自报、活动证据和测评证据。但是当前系统还缺少真正的测评业务：

- `LearningTask` 没有测评配置或正式测评版本。
- 教师创建任务时只选择资源和知识点，不审核题目、评分标准与发布策略。
- 学生端只有“开始学习”“我已完成”，没有正式作答与提交过程。
- 现有习题主要用于内容预览，部分答案检查发生在浏览器中，缺少服务端提交与判分记录。
- 当前学生事件接口理论上可以提交 `assessment_scored`，无法作为可信成绩来源。
- 教师只能看到进度、完成口径和最近活动，不能看到提交率、通过率、错题和薄弱知识点。
- 对没有习题的学习任务，系统只能留下自报或活动证据，无法判断学生是否达到学习目标。

本设计补齐“材料 → 测评 → 作答 → 评分/复核 → 补学 → 重做 → 教师反馈”的完整闭环。

## 2. 目标与成功定义

### 2.1 产品目标

1. 每个已发布学习任务都有且只有一个当前生效的正式测评版本。
2. 已有习题优先复用，没有习题时自动生成草稿，避免重复制作。
3. 发布前由教师确认题目、答案、评分量规、通过线、作答次数和答案揭示策略。
4. 学生的每次作答可恢复、可提交、可评分、可复核、可追溯。
5. 学习参与、任务提交和测评结果分开记录，不再用一个“已完成”掩盖事实差异。
6. 未通过学生获得针对材料和知识点的补学建议，并能在规则允许时重做。
7. 教师获得班级、题目、知识点和学生四个层级的可行动反馈。
8. UI、HTTP API 和双端 Agent 读取同一结构化事实源。

### 2.2 成功定义

以下条件必须同时成立：

- 无测评的草稿不能发布，API 直接发布也被服务端拒绝。
- 选中已有习题材料时不会无条件重复生成题目，而是进入导入、校验和教师确认流程。
- 选中不含习题的材料时能生成带材料依据、答案和评分标准的测评草稿。
- 发布后修改源材料或原习题不会改变已经开始作答的测评版本。
- 学生端在揭示条件满足前拿不到标准答案、评分键或教师量规私有字段。
- 学生不能通过学习事件接口伪造成绩或 `assessment_verified` 证据。
- 客观题由服务端评分；主观题未经教师确认时保持“待复核”，不能判定通过。
- 学生未通过后能看到薄弱知识点、对应材料和下一步建议，并可按规则重做。
- 教师能看到参与率、提交率、通过率、掌握良好率、分数分布、高频错题、薄弱知识点和待复核队列。
- 刷新、重新登录和后端重启后，草稿答案、作答次数、成绩和反馈保持一致。

## 3. 非目标

本期不包含：

- 在服务器直接运行学生提交的不可信代码。
- Docker、Firecracker、Judge0、Piston、Pyodide 或其他代码判题沙箱接入。
- 编程题隐藏测试用例、资源限制、反作弊运行监控和多语言编译环境。
- 远程监考、摄像头监考、浏览器锁定或抄袭检测。
- 自适应题库、IRT 能力估计、跨课程综合排名或不可解释的能力分。
- 学校级成绩单、学分、证书或教务系统同步。
- 家长端、管理端和跨课程学生个人画像。

本期会为代码判题保留题型、评分提供者和运行结果接口边界，但任何未接入可信执行器的编程实现题都必须走 AI 建议加教师复核。

## 4. 统一术语与领域规则

### 4.1 核心对象

| 对象 | 建议 ID | 含义 |
| --- | --- | --- |
| 学习任务 | `lt_...` | 教师发布给课程学生的学习安排 |
| 测评定义 | `asmt_...` | 与学习任务一一对应的测评聚合根 |
| 测评版本 | `asv_...` | 一次可发布、不可变的题目与策略快照 |
| 测评题目 | `asi_...` | 版本内的题目、评分规则和知识点映射 |
| 学生作答 | `att_...` | 一名学生对一个测评版本的一次尝试 |
| 题目答案 | `ans_...` | 某次作答中对某道题的回答 |
| 复核决定 | `rvw_...` | 教师对主观评分的确认或调整记录 |

### 4.2 强制规则

1. 本能力上线后新发布的 `LearningTask` 必须存在一个 `AssessmentVersion.status=published` 的有效绑定；迁移前遗留任务只能以 `legacy_unassessed` 兼容状态继续展示，不能作为新的无测评发布旁路。
2. 一个任务同一时刻只有一个当前正式测评版本。
3. 已发布版本不可原地修改；修改题目或策略必须创建新版本。
4. 已有作答始终绑定当时的版本，不因后续版本发布而重算。
5. 新版本默认只对尚未开始测评的学生分配生效；已有作答学生继续原版本。教师若要求重测，必须发起显式重测动作，创建新的测评周期并留下审计记录。
6. 学生提交的答案永远不能携带最终成绩、正确性或完成证据；这些字段只由服务端评分与教师复核产生。
7. `assessment_verified` 只能由 `AssessmentService` 在作答最终通过后写入学习事实源，公共学习事件 API 不接受该事件。
8. AI 输出只是一种候选内容或建议评分，不能绕过教师确认与确定性规则。

## 5. 状态模型

### 5.1 三条事实轴必须分开

#### 学习参与状态

```text
not_started → learning → activity_completed
```

表示学生是否开始浏览材料和完成学习活动，不表达测评结果。

#### 测评作答状态

```text
not_attempted
  → in_progress
  → submitted
  → pending_review | graded
  → not_passed | passed | mastery
```

`submitted` 是提交事实；`passed` 才是达到任务及格线；`mastery` 表示达到教师设置的掌握良好线。

#### 任务结果

```text
pending | learning | awaiting_assessment | awaiting_review | needs_retry | verified_completed
```

任务结果由学习参与和测评事实派生，不允许客户端直接写入：

- 没有开始：`pending`
- 已有学习活动但尚未提交测评：`learning` 或 `awaiting_assessment`
- 最佳作答待教师复核：`awaiting_review`
- 最终成绩低于及格线且仍可重做：`needs_retry`
- 任一次最终成绩达到及格线：`verified_completed`

### 5.2 与现有完成口径的关系

- `self_reported`：保留历史兼容，只表示学生自报学习活动完成。
- `activity_evidenced`：表示系统记录了受支持的学习活动完成。
- `assessment_verified`：仅在最终成绩达到及格线且所有必需复核结束后产生。

“自报完成”与“活动完成”不再把任务结果显示为无条件的“已完成”；教师端应显示“已完成学习活动，尚未通过测评”。

## 6. 测评载体与题型

### 6.1 题型分类

本期正式支持：

| 分类 | 题型 | 评分方式 |
| --- | --- | --- |
| 客观题 | 单选、多选、判断、结构化填空 | 服务端确定性评分 |
| 计算机理解题 | 代码运行结果、执行轨迹、错误定位、结构化代码补全 | 能结构化判定时服务端评分，否则转主观复核 |
| 主观题 | 简答、算法解释、方案比较、调试说明 | AI 建议评分，教师确认 |
| 成果型评测 | 文本说明、文件、截图、代码文件、项目链接 | 按教师确认的量规，AI 建议评分，教师确认 |
| 编程实现题 | 源代码或代码文件 | 本期不执行代码，AI 建议评分，教师确认 |

### 6.2 未来代码判题扩展点

`grading_provider` 预留以下值：

```text
deterministic
rubric_ai_teacher
code_runner
```

本期只能创建前两类正式评分器。`code_runner` 仅允许出现在能力声明和接口枚举中，不得在未配置可信执行器时发布为自动评分题。

未来执行结果通过独立的 `CodeExecutionResult` 进入评分服务，至少包含语言、编译状态、测试用例汇总、资源使用、执行器版本和签名；学习服务不直接启动进程或容器。

## 7. 测评来源与生成流程

### 7.1 统一流水线

```text
教师选择任务材料
  → 内容解析与习题探测
  → 测评覆盖规划
  → 导入已有题目 / 生成缺失题目
  → 自动质量校验
  → 教师审核编辑
  → 发布前校验
  → 生成不可变 AssessmentVersion
  → 与 LearningTask 原子发布
```

### 7.2 已有习题材料

系统从以下来源探测题目：

- `material_type=quiz` 的课程材料；
- AI 课堂中的 Quiz 场景；
- 后续注册的、实现统一 `AssessmentItemExtractor` 接口的材料类型。

导入流程：

1. 抽取题干、选项、答案、解析、分值、题型、材料来源和知识点。
2. 标准化题型和答案结构；无法确定答案或量规的题目标记为“需教师补充”。
3. 多份习题材料同时存在时，教师勾选计入正式测评的题目并调整顺序、分值和权重。
4. 系统不因为发现已有题目就自动发布，仍需完成质量校验与教师确认。
5. 原材料只作为来源；发布时复制为不可变版本，保留来源 ID、来源版本和内容哈希。

### 7.3 无习题或覆盖不足

系统根据以下输入生成测评草稿：

- 教师选中的材料内容快照；
- 学习任务标题和说明；
- 教师选择的知识点；
- 学生层级、难度和题量；
- 已导入题目的覆盖情况。

生成过程先产出“测评蓝图”，再生成具体题目。蓝图至少包含每个知识点的题型、分值、认知层级和材料依据。系统只补齐缺口，不重复生成已经充分覆盖的知识点。自动生成至少需要一份可解析的选中材料；没有材料的任务可以保存草稿，但只能由教师手工完成正式测评后发布。

### 7.4 质量门禁

发布前必须完成以下自动校验：

- 所有题目结构合法，分值总和大于 0。
- 至少存在一道可以形成最终成绩的题目或一个完整成果量规。
- 客观题具有合法且可确定的答案。
- 主观题和成果型题目具有明确量规、维度和分值。
- 每道题至少映射一个任务知识点；每个必测知识点至少被一道题覆盖。
- 题目能追溯到选中材料或被教师显式标记为允许的扩展背景。
- 无重复题、明显同义重复、题干歧义、选项数量错误或答案冲突。
- 难度与教师设置基本一致。
- 学生投影不包含答案、解析、评分键、教师备注或隐藏字段。

自动校验失败时展示具体问题并阻止发布；教师可以修改题目，但不能通过一个笼统的“忽略全部”绕过结构、答案和隐私门禁。

### 7.5 已公开答案的处理

正式测评与练习资源必须区分用途：

- 学生正式测评接口在揭示条件满足前永不返回答案和解析。
- 如果导入的原习题已作为带答案练习公开给学生，发布页必须标记“答案可能已公开”。
- 教师可选择把该测评标记为开卷测评，或者让系统依据原题生成等价变式。
- 开卷测评仍可验证任务完成，但教师反馈和 Agent 回答必须保留 `assessment_mode=open_book`，不得把它表达成闭卷掌握证据。

## 8. 教师端产品流程

### 8.1 创建任务

“新建学习任务”改为四步：

1. **任务目标**：标题、说明、知识点、学生层级。
2. **学习材料**：选择课程共享材料。
3. **正式测评**：探测已有习题，导入或生成题目，编辑题目与量规。
4. **发布设置**：及格线、掌握良好线、作答次数、答案揭示、题序/选项随机化和开卷标记。

教师可保存草稿并稍后继续。前三步可以部分完成，但第四步发布必须通过完整门禁。

### 8.2 测评编辑器

编辑器展示：

- 题型、题干、选项、答案、解析、分值；
- 主观题或成果型题目的评分量规；
- 映射知识点和材料来源；
- AI 生成、已有习题导入或教师手工创建的来源标记；
- 覆盖率、难度分布和质量问题；
- 学生视图预览，确保答案没有泄露。

教师可以增删改题、重新生成单题或某个知识点的题目，但重新生成不会覆盖教师已经手工修改且锁定的内容。

### 8.3 发布前确认

发布确认页明确显示：

- 题目数和总分；
- 客观题、待人工复核题和成果题比例；
- 知识点覆盖；
- 及格线 60、掌握良好线 80 或教师调整值；
- 最多 3 次或教师调整值；
- 计分方式为最高最终成绩；
- 答案揭示策略；
- 已公开答案风险；
- 预计需要教师复核的作答量。

任务与测评版本必须在同一事务中发布。任一失败，二者都保持草稿状态。

## 9. 学生端产品流程

### 9.1 学习与进入测评

学生任务卡同时展示：

- 学习参与状态；
- 测评状态；
- 剩余作答次数；
- 当前最佳成绩；
- 是否等待教师复核。

学生可以先学习材料，再进入测评。教师本期不配置强制材料浏览门槛，避免用点击或时长假装掌握；系统仍记录真实学习活动供教师参考。

### 9.2 作答草稿

- 开始测评创建新的 `AssessmentAttempt`。
- 答案自动保存到服务端，并使用乐观版本号防止多标签页覆盖。
- 刷新、重新登录或设备切换后可继续未提交作答。
- 同一学生、同一测评版本同时只能有一个 `in_progress` 作答。
- 未提交草稿不占用作答次数；正式提交后才增加次数。

### 9.3 提交与即时结果

提交后：

- 客观题立即由服务端评分。
- 仅包含客观题的测评立即产生最终成绩。
- 含主观题、成果提交或编程实现题时，先显示客观题结果与“待教师复核”，不得提前判定通过或未通过。
- 文件或链接上传失败时不能把不完整作答提交为成功。

### 9.4 重做与补学

默认最多提交 3 次；任务计入所有最终作答中的最高分。每次作答保留独立答案、评分和反馈。

未通过且仍可重做时，学生看到：

- 当前分数与距离及格线的差距；
- 错误类型，不直接泄露完整答案；
- 薄弱知识点；
- 任务内对应材料与定位信息；
- 针对性学习建议；
- 剩余作答次数。

达到及格线后任务结果立即变为 `verified_completed`；达到掌握良好线时额外显示“掌握良好”。学生尚有次数时可以选择“继续挑战”并暂不查看完整答案，也可以选择“结束测评并查看解析”。一旦主动揭示完整答案，该测评周期不再允许新的计分作答。后续低分重做不降低已经取得的最佳结果。

### 9.5 答案揭示

默认策略为 `after_finish_or_exhausted`：

- 仍未通过且还有次数：不展示完整标准答案和完整解析。
- 已通过时先让学生选择继续挑战或结束测评；选择结束，或次数用尽后，展示教师允许公开的答案与解析。
- 主观题展示最终量规得分和教师可见性为“可给学生”的评语。

这里的“达到及格线”表示获得揭示资格，不是自动揭示。教师还可选择 `after_exhausted` 或 `never`；本期不支持“每次提交后展示完整答案”，以免与多次计分作答冲突。

## 10. 评分、复核与任务结果计算

### 10.1 评分策略

每道题保存：

- `max_score`
- `grading_provider`
- 客观评分键或主观评分量规
- 知识点映射
- 材料来源

最终分统一归一化到 0–100：

```text
final_score = round(sum(item_final_score) / sum(item_max_score) * 100, 2)
```

缺少最终分的必答题存在时，作答状态为 `pending_review`，不得计算最终通过结果。

### 10.2 AI 建议评分

AI 初评保存为独立建议，不覆盖学生答案：

- 建议分；
- 分维度评分；
- 评分理由；
- 置信度；
- 使用的量规版本；
- 模型与提示版本；
- 生成时间。

AI 建议分不是最终分。教师可以接受或修改，修改时必须填写或选择原因。教师决定保存为追加式审计记录，原始建议不能被静默覆盖。

### 10.3 最佳成绩

- 只比较状态为 `graded` 的最终成绩。
- 最高最终成绩为任务成绩。
- 同分时保留更早达到该分数的作答作为最佳作答，同时仍展示完整时间线。
- 教师复核导致历史作答分数变化时，服务端重新计算最佳成绩和任务结果。
- 已经通过后不会因后续较低成绩回退。
- 已通过但尚未揭示完整答案时，可以在剩余次数内继续挑战；揭示后只能进行不计分练习。

### 10.4 人工调整

教师可以调整单题分、最终评语或将异常作答标记为无效。所有操作必须保存操作者、时间、原值、新值和原因。无效作答不参与最高分计算，但仍保留在审计时间线中。

## 11. 教师反馈与干预

### 11.1 任务级概览

教师任务页新增：

- 课程学生数；
- 学习参与率；
- 测评提交率；
- 测评通过率；
- 掌握良好率；
- 平均分、中位数和分数分布；
- 平均提交次数；
- 待复核人数；
- 最近学习与提交时间。

所有比例必须显示分母和统计口径，不能只显示一个百分比。

### 11.2 学生状态队列

教师可按以下队列筛选：

- 未开始；
- 已学习未提交；
- 已提交待复核；
- 未通过且仍可重做；
- 次数已用尽仍未通过；
- 已通过；
- 掌握良好。

学生明细展示学习活动、历次作答、每题得分、薄弱知识点、教师评语和进步趋势。姓名取课程成员资料，资料不可用时降级为学生 ID。

### 11.3 题目与知识点分析

题目分析至少包含：

- 作答人数；
- 客观题正确率；
- 主观题平均最终得分率；
- 空答率；
- 高频错误选项或错误类型；
- 是否疑似题目歧义。

知识点分析从题目最终得分聚合，展示覆盖题数、参与人数、平均得分率和未通过人数。没有测评证据的知识点不得生成掌握百分比。

### 11.4 教师行动建议

系统可以依据结构化统计生成建议，例如“集中讲解”“补充示例”“安排重做”或“复核疑似歧义题”。建议必须附带支持它的题目、知识点和人数，教师可以忽略；建议不是成绩事实。

## 12. Agent 集成

### 12.1 学生 Agent

学生 Agent 只读取本人：

- 任务学习状态；
- 测评状态、剩余次数和最佳最终成绩；
- 已公开的错题类型、薄弱知识点和补学建议；
- 教师允许学生查看的最终评语。

在答案揭示条件满足前，Agent 不得从课程材料、历史对话或工具结果泄露标准答案。

### 12.2 教师 Agent

教师 Agent 默认只读取当前课程的聚合统计：

- 参与、提交、通过、掌握良好和待复核人数；
- 分数分布；
- 高频错题和薄弱知识点；
- 统计时间与口径。

逐人明细继续由教师页面或显式授权的明细接口承载，不进入长期 system prompt。

### 12.3 回答约束

- “完成任务”必须说明是完成学习活动、提交测评还是通过测评。
- “掌握”只能基于最终测评证据，并说明及格线、掌握良好线和开卷模式。
- 待复核作答不能被表述为已通过。
- AI 建议评分不能被表述为教师最终评分。

### 13.1 组件

| 组件 | 单一职责 | 依赖 |
| --- | --- | --- |
| `AssessmentAuthoringService` | 题目探测、导入、生成草稿和编辑 | 材料读取、生成模型、质量校验 |
| `AssessmentQualityService` | 结构、覆盖、答案、重复和泄露校验 | 题型注册表、材料快照 |
| `AssessmentPublicationService` | 版本冻结并与任务原子发布 | 测评仓储、学习任务仓储、事务 |
| `AssessmentDeliveryService` | 生成角色安全的学生/教师投影 | 测评版本、揭示策略、权限 |
| `AssessmentAttemptService` | 草稿、自动保存、提交和次数控制 | 作答仓储、身份与课程成员关系 |
| `AssessmentGradingService` | 确定性评分、AI 建议、最终分计算 | 评分器注册表、复核仓储 |
| `AssessmentReviewService` | 教师复核、调整和审计 | 评分服务、课程权限 |

### 13.2 依赖方向

`LearningService` 不解析答案、不调用模型、不运行代码。测评域在最终作答通过后，通过一个内部、幂等的 `AssessmentOutcomePort` 提交可信结果；学习域据此提升 `completion_basis` 并更新任务投影。

材料域不感知学生作答。测评创作服务只读取材料快照，发布后测评版本不再依赖材料实时内容。

## 16. 权限、隐私与安全

| 能力 | 教师 owner/editor | 学生 viewer |
| --- | --- | --- |
| 编辑测评草稿 | 允许 | 拒绝 |
| 查看答案与私有量规 | 允许 | 仅按揭示策略获得学生投影 |
| 发布任务与测评版本 | 允许 | 拒绝 |
| 创建作答 | 拒绝代答 | 仅本人 |
| 查看班级分析 | 允许，仅本课程 | 拒绝 |
| 查看作答明细 | 允许，仅本课程 | 仅本人 |
| 最终复核 | 允许 | 拒绝 |
| 写入测评验证证据 | 仅内部服务 | 拒绝 |

安全要求：

- 标准答案和评分键静态加密，并与学生投影查询路径隔离。
- 日志不记录完整学生答案、标准答案、文件内容或私有教师评语。
- 学生上传成果沿用受控对象存储，保存大小、类型和病毒扫描状态；未通过扫描的文件不进入复核界面。
- 任何 `student_id` 都由认证上下文确定，学生请求中的其他学生 ID 被拒绝。
- 评分与复核操作使用幂等键，重复提交不得重复扣次数或追加成绩。
- 题序和选项随机化只改变学生投影，评分始终使用稳定题目和选项 ID。

## 17. 错误处理与降级

- 材料解析失败：标记具体材料，允许教师移除或重试；没有完整测评时不能发布。
- AI 生成失败：保留已生成且通过校验的题目，允许单知识点重试；不自动发布半成品。
- 质量校验服务失败：返回“暂无法验证”，禁止发布，不把失败解释为通过。
- 自动保存冲突：返回最新修订并提示学生合并，不静默覆盖。
- 重复提交：返回第一次提交结果，不重复占用次数。
- 提交时已达次数上限：返回 `ATTEMPT_LIMIT_REACHED`，不创建额外作答。
- 已揭示完整答案后再次创建计分作答：返回 `ANSWERS_ALREADY_REVEALED`，仅允许进入不计分练习。
- 主观评分 AI 不可用：作答保持 `pending_review`，教师仍可直接人工评分。
- 分析聚合失败：不影响作答与评分；教师页面局部降级并提供重试。
- 学习证据同步暂时失败：使用内部事件表重试，测评最终成绩不丢失，也不由客户端补写。
- 新版本发布冲突：比较内容哈希和草稿修订，返回 409，不覆盖另一位教师的修改。

- `assessment_publication_total{result}`

## 19. 迁移与兼容

1. 新建独立测评表，不把测评 JSON 塞入现有 `learning_tasks`。
2. `learning_tasks` 增加当前测评版本引用或使用唯一绑定表；PostgreSQL 使用外键，SQLite 保持等价约束。
3. 现有已发布任务没有正式测评版本时，标记为 `legacy_unassessed`，继续允许学生查看，但不再允许新任务按此方式发布。
4. 迁移期教师必须为 `legacy_unassessed` 任务补建测评后，才能获得“测评验证完成”数据。
5. 旧 `completed` 学习事件继续映射为 `self_reported`，不得迁移成通过测评。
6. 从公共学生学习事件 schema 中移除 `assessment_scored`；内部结果同步使用不可伪造的服务调用或 outbox 事件。
7. 前端在测评能力未就绪时，对新任务隐藏发布按钮并显示服务不可用；不得退回旧的无测评发布路径。
8. 现有习题和 AI 课堂 Quiz 适配器只负责抽取，不修改原资源格式。

## 20. 测试策略

### 20.1 单元测试

- 题型标准化、答案校验和学生投影脱敏。
- 知识点覆盖、重复题、歧义字段和公开答案风险校验。
- 客观题评分、归一化、阈值边界和最高分计算。
- 3 次提交限制、草稿不占次数和重复提交幂等。
- 主观题待复核与教师决定重算。
- 任务状态、测评状态和完成口径派生。

### 20.2 服务与仓储测试

- 测评版本不可变。
- 任务与测评原子发布。
- 新版本不影响历史作答。
- SQLite 与 PostgreSQL 行为一致。
- 并发自动保存冲突和并发提交只成功一次。
- 内部测评结果到学习证据的 outbox 重试与幂等。
- 学生越权、跨课程访问和答案字段泄露测试。

### 20.3 前端测试

- 四步任务创建与发布门禁。
- 已有习题探测、选择、编辑和来源展示。
- 自动生成失败、质量问题和教师修复流程。
- 学生自动保存、恢复、提交、待复核和重做流程。
- 答案揭示前后的字段与界面变化。
- 教师统计、状态筛选、复核和成绩调整。

### 20.4 真实 E2E

至少覆盖：

1. 已有习题材料 → 导入 → 教师确认 → 发布 → 学生通过 → 教师看到通过率。
2. 无习题材料 → 自动生成 → 质量校验 → 教师确认 → 发布。
3. 第一次 50 分、补学后第二次 75 分；学生选择暂不揭示答案并继续挑战，第三次 65 分，最终成绩保持 75 分，三次记录完整。
4. 含主观题的作答提交后保持待复核，教师确认后才通过。
5. 学生抓取测评接口和课程材料接口，揭示前均不能获得正式测评答案。
6. 学生伪造 `assessment_scored` 或其他学生 ID 被拒绝。
7. 后端重启后恢复作答草稿、次数、最终成绩与教师反馈。

## 22. 建议实施分片

该能力保持一个统一领域设计，但实施按可独立验收的四个分片推进：

1. **测评创作与发布门禁**：领域表、已有习题抽取、无习题生成、质量门禁、教师编辑和原子发布。
2. **学生作答与客观评分**：学生安全投影、服务端草稿、提交、确定性评分、三次作答、最高分和答案揭示。
3. **主观复核与教师反馈**：AI 建议评分、教师复核、成果提交、班级/题目/知识点/学生分析和补学建议。
4. **Agent、迁移与上线加固**：双端 Agent、遗留任务迁移、SQLite/PostgreSQL 一致性、安全测试、可观察性和真实 E2E。

每个分片完成后都运行已有学习任务回归；只有四个分片全部通过，才能宣称强制测评闭环完成。

## 23. 完成定义

本能力完成必须同时满足：

1. ASMT-FR-001 至 ASMT-FR-015、ASMT-NFR-001 至 ASMT-NFR-007 均有自动化测试或真实浏览器验收证据。
2. 服务端不存在新任务无测评发布旁路。
3. 学生不能通过任何学生可调用接口获得未揭示答案或写入可信成绩。
4. 已有习题和无习题两条创作路径均真实贯通。
5. 三次作答、最高分计入、主观题复核和补学重做闭环真实贯通。
6. 教师页面、学生页面和双端 Agent 对同一任务的状态、分数与统计口径一致。
7. SQLite 与 PostgreSQL 支持范围、迁移行为和事务语义一致。
8. 现有课程资源、习题生成、AI 课堂、学习任务和 Agent 主链路无 P0/P1 回归。
