# 教师问答工作台中间对话区整体美化设计

## 1. 设计目标

本次设计面向教师问答工作台的中间对话区，目标不是增加新功能，也不是重写聊天业务逻辑，而是在保留现有问答、历史对话、流式返回、附件输入与引用机制的前提下，把中间区从“可用的聊天模块”提升为“教师问答主工作区”。

本次设计确认的核心目标如下：

1. 删除中间区顶部已经显得冗余的对话信息卡片，让消息流重新成为主舞台。
2. 把中间区整体气质定为“工作台秩序 + 对话主场感”的平衡型，而不是普通聊天框或重控制台。
3. 弱化顶部操作栏的存在感，但保留其控制效率。
4. 强化消息流的连续阅读体验，让教师能更自然地感知对话推进。
5. 把底部输入区做成稳定、明确的下一步入口，但不压过消息流主体。

## 2. 项目上下文

结合当前项目上下文，本次升级继续遵循以下原则：

- 用户是处于课程语境中的教师，不是泛聊天用户。
- 中间区承担的是“围绕课程与知识点推进问答任务”的主工作现场。
- 风格应继续保持浅色、专业、清晰、低认知负担。
- 不能为了“高级感”引入社交聊天软件式的强气泡风格。
- 不能为了“工作台感”把中间区做成工具栏压倒内容的控制台。

## 3. 当前问题

当前中间对话区主要存在以下问题：

1. 顶部状态卡占据了中间区最宝贵的首屏空间，打断了消息流连续性。
2. 顶部操作栏虽然功能完整，但视觉角色还不够清楚，容易和主内容争抢注意力。
3. 消息流本身是主任务区，但视觉节奏还不够稳定，阅读连续性一般。
4. 底部输入区虽然可用，但“持续可操作的下一步入口”感不够明确。
5. 中间区整体仍更像一个聊天模块，而不是教师问答主工作区。

## 4. 范围界定

### 4.1 本次范围

本次设计与实现只包含以下内容：

1. `ChatPanel.tsx` 的整体结构层优化。
2. 中间区顶部操作栏、消息流区域、底部输入区三者的主次关系重排。
3. 用户消息、AI 消息、头像、消息间距、消息容器外壳的统一美化。
4. 输入区外壳、工具按钮区、发送按钮视觉角色的整体梳理。
5. 必要的中间区样式文件更新与回归测试补充。

### 4.2 不在本次范围

以下内容不纳入本轮：

1. 聊天发送、流式返回、历史对话、RAG/Web 开关等业务逻辑重写。
2. 引用来源卡片、图片/视频消息卡、复杂附件卡片的大重构。
3. 左侧知识库与右侧生成工坊的同步美化。
4. 新增对话能力、新工作流入口或新的状态中心。

## 5. 目标体验

教师进入中间区后，应先自然进入对话进展，再感知自己可以如何继续推进。

理想体验如下：

1. 第一眼重点落在消息流，而不是顶部控制项。
2. 第二眼能清楚看到底部输入区，知道自己可以继续提问或补充条件。
3. 顶部操作栏始终存在，但像轻量控制层，而不是一块重工具条。
4. 消息区更适合长时间阅读，不因冗余卡片和杂乱分区打断。
5. 整个中间区更像教师问答主工作区，而不是普通聊天页。

## 6. 设计方案

### 6.1 整体方向

本次采用“教师问答主工作区型”方向：

1. 顶部操作栏清楚可见，但只承担辅助控制角色。
2. 消息流成为绝对主舞台。
3. 输入区作为稳定的下一步入口长期存在。
4. 整体气质偏现代、克制、专业，不走社交聊天或重后台风格。

### 6.2 中间区结构

中间区重构为三层关系：

1. 顶部轻控制层
2. 中部消息主舞台
3. 底部持续可操作输入区

结构目标如下：

- 上轻：顶部栏保留控制效率，但不占视觉主位。
- 中稳：消息区最大、最连续、最适合阅读。
- 下清楚：输入区始终明确可用，但不形成厚重面板。

### 6.3 顶部操作栏

顶部操作栏保留现有能力：

1. `RAG`
2. `Web`
3. `新建对话`
4. `历史对话`

但视觉角色调整为“轻控制层”：

1. 不再像一条完整的工具条。
2. 开关与按钮的视觉重量低于消息流和输入区。
3. 更依赖对齐、间距和轻边界建立秩序，而不是靠重背景或厚容器。
4. 顶部栏与消息区之间需要明确但克制的垂直过渡。

### 6.4 消息流

消息流是本次美化重点。

设计要求如下：

1. 删除对话信息卡片后，消息区直接承接顶部控制层。
2. 用户消息与 AI 消息继续保留明显区分，但对比度不做得过重。
3. 消息气泡保留现代聊天感，但要弱化社交属性。
4. 长文本阅读节奏优先，控制过度圆角、厚背景与过强颜色对比。
5. 消息与消息之间的垂直节奏需要更稳定，适合长时间使用。

### 6.5 头像与消息容器

头像继续保留角色区分功能，但存在感降低。

要求如下：

1. 头像尺寸和颜色不再成为视觉焦点。
2. 头像与气泡之间间距统一。
3. AI 与用户侧消息容器保持平衡，而不是一边明显更重。
4. 整体更像专业协作工具，而不是社交 IM。

### 6.6 输入区

底部输入区定义为“平时克制，但始终有可操作感”的下一步入口。

设计要求如下：

1. 输入框本体需要更稳、更清晰。
2. 输入区与上方消息流之间要有明确但不厚重的边界关系。
3. 底部工具按钮区和发送按钮需要统一视觉语言。
4. 输入区不能弱到像普通页脚，也不能重到像独立控制面板。
5. 用户看完回复后，应自然意识到可以继续提问、补充条件、发送附件。

### 6.7 视觉语言

中间区整体视觉语言定义为“克制的现代对话工作区”。

要求如下：

1. 保持浅色、干净、稳定。
2. 减少无效边框、小盒子和多余容器。
3. 强调高级感主要靠留白、节奏和轻重关系，而不是装饰。
4. 颜色继续以中性浅色为主，强调色只用于关键交互与当前动作。
5. 避免把聊天区做成花哨 AI 风、强渐变风或社交 IM 风。

## 7. 实现边界

建议实现主要落在以下文件：

- `frontend/src/components/teacher/ChatPanel.tsx`
- `frontend/src/components/teacher/StatusCardV2.tsx`（仅当需要彻底移除引用或停用残留逻辑时）
- `frontend/src/components/teacher/StatusCard.css`（仅在清理残留依赖时触及）

实现中优先原则如下：

1. 先完成中间区整体结构和视觉主次梳理。
2. 再做消息区、输入区、顶部操作栏的统一化。
3. 不在本轮把来源引用、图片视频卡片等深层组件全部重做。

## 8. 响应式原则

本次中间区美化不能破坏现有响应式降级逻辑。

要求如下：

1. 桌面端保持顶部轻控制层 + 消息流 + 输入区三段关系。
2. 中小屏下继续优先保证消息流和输入区的可读、可用。
3. 顶部控制栏在窄屏下允许更紧凑，但不能变成多行混乱按钮堆。
4. 输入区在小屏下仍需保持可操作感，不因视觉收敛而变得难点。

## 9. 验收标准

### 9.1 视觉验收

1. 中间区不再出现冗余对话信息卡片。
2. 顶部控制栏显著变轻，不再压住消息流。
3. 消息流成为中间区最自然的视觉主舞台。
4. 输入区成为稳定、清楚的下一步入口。
5. 中间区整体更像教师问答主工作区，而不是普通聊天页。

### 9.2 行为验收

1. 新建对话、历史对话、RAG/Web 开关行为不受影响。
2. 聊天发送与流式返回不受影响。
3. 消息滚动、历史恢复、附件输入与发送不受影响。
4. 输入区按钮与快捷交互不受影响。

### 9.3 回归关注点

1. 删除状态卡后，不应出现顶部空白塌陷或间距异常。
2. 长消息文本不能因气泡样式变化而溢出或换行异常。
3. 输入区与消息区之间不能因样式调整出现遮挡或滚动问题。
4. 与 `ChatPanel` 相关的现有测试若基于旧结构断言，需要同步收敛到新结构。

## 10. 成功标准

本轮完成后，应达到以下结果：

1. 中间区从“普通聊天模块”提升为“教师问答主工作区”。
2. 用户一进入中间区就会先关注对话进展，而不是顶部工具层。
3. 用户在读完回复后，会自然看到底部输入区并理解下一步如何行动。
4. 整个中间区与外层教师工作台风格统一，但保留对话主场感。
5. 为后续继续精修消息附件、引用样式和输入区细节打下统一视觉基础。
