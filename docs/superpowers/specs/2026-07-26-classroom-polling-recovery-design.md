# AI 课堂轮询恢复设计

## 问题

课堂生成任务提交后，后端和 OpenMAIC 会继续执行，但工作台入口只在 React
组件内存中保存 `edu_job_id`。页面刷新、Vite 热更新、路由切换或组件卸载会终止
当前浏览器轮询；组件重新挂载后没有任务 ID，因此用户看不到原任务进度，也不会在
完成后自动进入课堂。

## 方案

在浏览器 `localStorage` 中按课程保存一条待完成课堂任务：

- `courseId`
- `topic`
- 最后一次收到的完整 `EduJob`
- `savedAt`

组件重新挂载或切回对应课程时：

1. 读取该课程的待完成任务；
2. 自动打开原进度弹窗；
3. 从最后一个 `EduJob` 继续调用现有 `/api/jobs/{edu_job_id}`；
4. 成功后清理记录并自动进入课堂；
5. 明确失败时清理记录并允许重新生成；
6. 临时网络、鉴权或页面卸载不清理记录，下次挂载继续恢复。

同一课程发起新任务时覆盖旧记录；清理操作必须同时匹配课程 ID 和任务 ID，避免
旧轮询结束时误删新任务。

## 边界

- 本次解决浏览器轮询中断后的恢复。
- 后端任务在 FastAPI 进程存活时独立于浏览器轮询继续执行。
- FastAPI 自身重启后的 sidecar 任务接管属于另一层服务端恢复，不在本次范围。

## 验收

- 存储记录可跨组件重新挂载读取。
- 多课程记录互不覆盖。
- 同课程新任务替换旧任务。
- 旧任务不能清除已替换的新任务。
- 损坏的存储数据安全忽略。
- 组件挂载后自动恢复轮询，成功后自动跳转。
