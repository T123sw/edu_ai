# 启动脚本前端依赖与就绪检查设计

日期：2026-07-26

## 背景

`backend/src/start_api.bat` 目前用 `Edu_AI/node_modules` 是否存在来判断前端依赖是否完整。现场状态中该目录存在，但 `node_modules/.bin/vite.cmd` 缺失，因此脚本跳过安装步骤，随后 `npm run dev` 报错找不到 `vite`。脚本没有等待前端真正启动，仍继续启动后端，最终形成 OpenMAIC 与后端正常、前端未运行的半启动状态。

控制台中另有一条 `'frontend' is not recognized`。单独验证现有 `start` 命令语法时未能复现该报错，因此本次不对未经证实的来源做猜测性修改；前端就绪检查会捕获其造成的实际启动失败，并给出统一、明确的错误。

## 目标

1. 前端依赖不完整时自动修复，而不是只依据 `node_modules` 目录存在与否。
2. 后端启动前确认前端 HTTP 服务已经可以访问。
3. 前端启动失败时停止统一启动流程并给出可操作的错误信息。
4. 不修改用户现有的 `frontend/package.json` 本地改动。
5. 不扩大现有端口进程处理策略，不停止无法确认身份的额外进程。

## 方案

### 依赖完整性

脚本以 `node_modules/.bin/vite.cmd` 作为前端可启动的最小依赖探针：

- 探针存在：依赖检查通过。
- 探针缺失：在 `FRONTEND_DIR` 执行现有的 `npm.cmd install`。
- 安装命令失败：输出错误并结束。
- 安装命令成功但探针仍缺失：输出“Vite launcher is still missing”并结束，避免继续启动一个必然失败的窗口。

这种检查既覆盖首次安装，也覆盖 `node_modules` 存在但命令链接损坏的情况。

### 前端启动与就绪检查

启动前端窗口后，主脚本轮询 `http://127.0.0.1:5173/`：

- 使用与 OpenMAIC 健康检查一致的 PowerShell HTTP 请求方式。
- 每 2 秒检查一次，最多 45 次，总等待上限约 90 秒。
- 任意 HTTP 响应状态小于 500 即视为 Vite 已经可用。
- 就绪后再进入后端启动步骤。
- 超时后输出明确错误，提示查看 `edu-ai-frontend` 窗口，并结束脚本。

### 启动顺序

统一启动顺序保持为：

1. 检查端口；
2. 检查后端依赖；
3. 检查并修复前端依赖；
4. 检查 OpenMAIC 依赖；
5. 启动并等待 OpenMAIC；
6. 启动并等待前端；
7. 启动后端。

## 错误处理

- 依赖安装失败、Vite 启动器仍缺失、前端就绪超时均返回非零退出码。
- 错误信息包含失败组件和下一步检查位置。
- 已经健康的 OpenMAIC 不重复启动。
- 本次不自动关闭启动失败后遗留的终端窗口，避免误杀用户正在检查的进程。

## 测试

在现有 `tests/chat/test_start_api_bat.py` 中增加源码约束测试：

1. 前端依赖探针必须指向 `.bin/vite.cmd`，不能只检查 `node_modules`。
2. 安装后必须再次验证 Vite 启动器。
3. 前端启动后必须调用就绪等待逻辑。
4. 前端等待必须发生在启动后端之前。
5. 就绪失败路径必须返回非零状态。

随后运行：

- `pytest tests/chat/test_start_api_bat.py -q`
- `start_api.bat --check`
- 前端测试与后端相关回归测试
- 在不打断现有服务的前提下，使用独立端口或受控命令验证 Vite 可以启动

## 验收标准

- 缺失 `.bin/vite.cmd` 时，脚本不会输出“Frontend node_modules found”并直接继续。
- 依赖修复后 `npm run dev` 能找到 Vite。
- 5173 未就绪时后端不会启动。
- 5173 就绪时统一启动流程继续进入后端。
- 所有新增与相关既有测试通过。
- Git 最终只包含本次脚本、测试和设计/计划文档；用户原有 `frontend/package.json` 修改保持未提交。
