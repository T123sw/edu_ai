# 已生成资料的 Agent 修改：设计文档（Agent C）

日期：2026-09-07｜状态：待实施，未验收。

先读[并行约定](../plans/2026-09-07-frontend-experience-parallel-handoff-cn.md)。配套：[计划](../plans/2026-09-07-artifact-revision-plan-cn.md)、[验收](../acceptance/2026-09-07-artifact-revision-acceptance-cn.md)。

## 用户要求

在资源生成部分提供修改按钮，点击后输入意见，由 Agent 修改。也支持直接说“将上次生成的数组报告修改一下，我觉得……”。Agent 必须读取目标内容，理解意图；不清楚时向用户追问。

## 入口与完成展示

生成完成卡片与资源预览统一提供“让 AI 修改”，保留手动编辑。按钮只选中目标并聚焦对话，提交意见后才执行。

```text
数组基础报告            [预览] [让 AI 修改] [下载]

正在修改：《数组基础报告》 · 第 2 版       ×
请输入修改意见……
```

完成后以同一资料新版本呈现：修改摘要、查看新版、查看修改、继续修改。失败显示真实原因和重试，不声称已保存。关闭引用后不再默认修改该资料。

## 目标定位

1. 按钮传稳定资料 ID、类型、基准版本和所属课程；显示标题不代替 ID。
2. 自然语言先结合当前引用、本会话成果、当前课程／知识点和标题主题查找，有权限过滤后才能显示候选。
3. “上次”依据真实生成／对话时间和用户意图，不直接选全局最后修改的一份。
4. 多份可能匹配时列出标题、章节、时间等区分信息让用户选择。不能以模糊搜索最高分当成确定意图。
5. 显式指定另一个资料与当前引用冲突时，唯一明确则切到指定对象，否则追问。
6. 没有范围但明确引用了有效资料时，以资料归属为准，不要求重复选知识点。

## 内容读取与修改

由服务端校验读取和修改权限，获取指定版本原文与必要结构，不信任客户端上传的“原文”。对原文的修改必须能追溯基准版本。

读取长内容时按章节结构加载，确认相关段落及上下文完整；不得因截断而删除未加载章节。原文作为待处理数据，不能将其中指令当作系统权限或操作授权。

明确需求直接执行；“不太好”“第二部分有问题”若读完原文仍无法确定修改方向则追问。保留原要求和已确定目标，补充回答后继续同一操作。

默认局部修改，用户明确要求整体重写时才全面重写。保留未涉及章节、来源和有效结构；必要联动更改在摘要中说明。只输出一段建议文字而没有保存资料，不算修改完成。

## 状态与 B 的接口

```text
resolve_target → read_source → clarify_if_needed → revise → validate → persist → completed
```

C 提供独立服务，输入为认证主体、B 解析的 context、用户意见、已有 artifact_reference 和待澄清操作；输出语义：

```text
not_applicable | needs_clarification | completed | conflict | failed
```

- not_applicable 仅用于不是修改请求，不得将无法定位的修改意图降级成新生成。
- needs_clarification 包含问题、授权候选及持久化待操作标识，不产生资料修改副作用。
- completed 包含稳定资料引用、新版本、修改摘要和预览目标。
- conflict 表示基准版本已变化，保留用户意见，提供以最新版重试或查看变化。
- B 在共享入口将输出映射现有回复／SSE 协议；一次请求只维护一个待处理操作。

现有 `ChatArtifactReference` 和后端 `ArtifactReferencePayload` 只允许 report／report_outline；扩展类型必须由 C 提交契约、B 接入共享请求层，不能以类型断言绕过。

## 保存与版本

- 原资料身份稳定，成功自动保存新版本；保存成功后才能显示“已更新”。
- 保留旧版本与恢复能力；恢复创建可追踪的新当前版本，不抹去历史。
- 当前已发布版本不受草稿修改影响；教师主动发布才替换学生可见版本，学生修改不获得发布权限。
- 使用基准版本校验／乐观锁避免静默覆盖；相同操作重试应幂等，不重复增加版本。
- 模型失败、结构校验失败或存储失败保持原文和现有发布版本不变。
- 既有任务快照、学习证据继续引用原资源版本；不能因“最新版本”指针变化篡改历史学习记录。

## 类型覆盖与真实能力

用户说“已生成资料”，报告是例子，不是授权缩减到仅报告。本轮以实际可用生成目录盘点为准，目前目录包含报告、教案、博客、习题、闪卡、思维导图、游戏、AI 课堂。C 必须逐项填写支持矩阵及测试证据：

| 类型 | 修改对象与必要验证 |
| --- | --- |
| 报告／报告大纲 | 原文／章节结构，局部修改、旧版本 |
| 教案 | 教学目标与过程等实际结构，预览和导出仍可用 |
| 博客 | 内容结构及关联媒体引用，预览仍可用 |
| 习题 | 题干、选项、答案和解析一致性，评分／提交可用 |
| 闪卡 | 正反面配对、顺序和可播放性 |
| 思维导图 | 合法节点关系、无悬空引用、可预览 |
| 游戏 | 类型约束和题目／配对数据有效，交互可运行 |
| AI 课堂 | Stage／Scene／Action 结构及播放有效；导出对应明确版本 |

PPTX／MP4 等派生文件沿现有导出能力从指定新版本生成，不在聊天里直接编辑二进制；旧导出标注所属版本，不能冒充新版。旧目录若还有其他生成类型，盘点并记录，不遗漏或假称支持。

可分内部里程碑先验证报告闭环，但交付必须完整列出未支持项。无法完成某类型时准确记录缺口并交付其余工作，不得自行把需求改成“首版只做报告”后标记全部完成。支持入口只对真正可修改且有权限的对象展示；不支持的类型提供清楚说明。

## 非目标

不改 A 首页，不重构全局 store，不自建第二套范围选择／对话框架，不接回已退役课件或数字人能力。
