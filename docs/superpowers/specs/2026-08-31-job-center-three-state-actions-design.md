# 后台任务中心三状态与真实重试设计

日期：2026-08-31

## 目标

精简后台任务中心的信息与操作，使教师只看到有决策价值的状态和操作，并保证“重试”会真实创建并提交一项新的后台任务。

## 状态口径

任务中心只展示三个业务状态：

- 已完成：底层状态为 `succeeded`。
- 进行中：底层状态为 `queued`、`running` 或 `cancel_requested`。
- 失败：底层状态为 `failed` 或 `partially_succeeded`。

底层状态为 `canceled` 的任务仍保留在后台任务台账中，但不进入任务中心列表，也不计入顶部统计。

顶部概览固定为“已完成”“进行中”“失败”三个数字，不再展示需关注率或平均耗时。

## 列表与操作

课程分组保持不变，每个课程内按“进行中”“失败”“已完成”三个分组展示任务。

每条任务只显示与当前状态匹配的主操作：

- 进行中：仅在任务可取消时显示“取消”。
- 失败：仅在任务可重试时显示“重试”。
- 已完成：仅在任务有可打开结果时显示“打开结果”。
- 不再提供“复制任务 ID”。

操作执行期间按钮禁用并显示处理中状态，失败时保留原任务并展示明确错误信息。

## 重试数据流

重试继续采用“从原失败任务创建新任务”的模式，保留原任务历史和 `retry_of_job_id` 关系，不复用原任务 ID。

后端收到重试请求后：

1. 校验任务归属、任务状态和 `retryable` 标记。
2. 若原任务具有持久化命令，则复制原命令并将新任务真实写入持久化队列。
3. 否则根据任务类型恢复原输入并调用对应业务提交器。
4. 只有新任务成功进入可执行状态时才返回 HTTP 202。
5. 不支持的任务类型、缺失重试输入、入队失败或业务分发失败均返回明确的非 2xx 响应；新建的重试任务同步标记为失败，前端不将其误报为重试成功。

前端收到成功响应后，将新任务加入任务仓库并触发轮询；收到失败响应时显示后端可读错误，不创建成功假象。

## 测试与验收

前端测试覆盖：

- 顶部只出现三个状态统计，且映射与数量正确。
- 已取消任务不出现在列表和统计中。
- 复制任务 ID 不存在。
- 进行中、失败、已完成任务分别只出现取消、重试、打开结果操作。
- 重试失败时展示错误，重试成功时登记新任务。

后端测试覆盖：

- 持久化任务重试会复制命令并创建 `pending` 任务。
- 支持的非持久化任务会调用真实业务提交器。
- 不支持类型、缺少输入、入队失败或分发失败不会返回 202。
- 新任务保留 `retry_of_job_id`，原失败任务不被覆盖。

验收以相关前后端测试、前端完整测试集和生产构建均通过为准。
