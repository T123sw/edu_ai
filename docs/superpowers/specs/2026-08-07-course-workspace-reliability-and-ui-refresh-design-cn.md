# 课程工作区可靠性与界面重构设计

**日期：** 2026-08-07

**状态：** 已确认，进入实施计划

**范围：** `Edu_AI` 教师端课程工作区、资源生成、后台任务、课程知识图谱与 RAG 选择链路
**交付方式：** 所有阶段连续实施；每阶段完成自动化验收并记录结果，全部完成后由用户统一检查前端效果。

---

## 1. 背景与已确认问题

本轮不是单纯换皮。实机和代码审查确认，当前问题同时存在于界面信息架构、前后端数据契约和后台任务生命周期：

1. 课程页面存在重复课程信息、过小文字、冗余说明和不一致的顶栏操作。
2. 课程概览部分统计和最近资源没有形成明确、稳定的后端数据契约。
3. 问答页知识库、对话和生成工厂布局拥挤，生成工厂四步向导不符合高频使用方式。
4. 课程知识仍按材料类型组织，和知识图谱节点这一课程主结构不一致。
5. 父节点 RAG 选择目前主要依赖前端展开文档 ID，无法保证以后新增的子节点资料自动参与。
6. AI 课堂首屏暴露大量配置，而后端真正必填的核心信息只有研究主题/生成要求。
7. 课程资源“最近更新”会被置顶规则覆盖，并非严格时间排序；分类中还存在“互动”这一非真实生成类型。
8. 已生成资源后仍持续轮询，是长期停留在排队态的后台任务导致；任务错误原文直接显示英文技术信息。
9. 报告生成曾因 `selected_doc_ids is required` 失败，需要审查全部资源类型的来源选择和后台任务闭环。

## 2. 目标

1. 形成统一、清晰、可读的课程工作区框架。
2. 所有页面显示真实后端数据，不用静态占位替代业务状态。
3. 九类真实资源都能完成“配置—提交—后台执行—终态—课程资源展示—点击查看”的闭环。
4. 后台任务必定收敛到成功、失败或取消，不允许永久排队并驱动无限轮询。
5. 课程知识以知识图谱节点组织，节点选择和 RAG 检索语义由后端统一保证。
6. 配置入口简洁，默认值承担复杂度，避免让用户面对长表单。
7. 所有面向用户的错误简洁、中文、可行动；技术详情保留在日志中。

## 3. 非目标

1. 不重写整个 React 应用架构或替换现有 hash 路由。
2. 不引入新的设计框架或虚构后端不支持的配置项。
3. 不改变学生端页面。
4. 不删除用户课程、知识库、生成资源或后台任务历史。
5. 不在本轮重构所有旧代码；只处理当前课程工作区可达路径及其依赖。

## 4. 核心决策

### 4.1 采用契约优先的纵向分阶段改造

先修复任务、资源、排序和 RAG 契约，再改造依赖这些数据的页面。每个阶段必须形成可运行闭环，不能只完成静态界面。

### 4.2 真实资源类型是唯一来源

生成入口、任务标签、资源筛选和资源详情统一使用现有注册表中的九类类型：

- `report`：教学报告
- `lesson_plan`：教案
- `blog`：教学博客
- `quiz`：习题
- `ppt`：PPT
- `flashcard`：闪卡
- `mind_map`：思维导图
- `game`：课堂小游戏
- `classroom`：AI 课堂

不得再展示“互动”之类并不存在的合并生成类型。历史存储中的兼容别名只能在适配层转换，不能泄漏到界面。

### 4.3 生成配置采用“必需信息优先”

每个工具点击后打开独立配置弹窗：

1. 首屏只展示真正必需和高频的字段。
2. 后端已有可靠默认值的字段不要求用户重复填写。
3. 确实有价值的低频字段收进“高级设置”。
4. 字段、默认值和校验必须来自现有前后端契约，不新增想象中的选项。
5. AI 课堂首屏只要求研究主题；其余现有配置使用默认值或高级设置。

### 4.4 RAG 节点选择由后端在请求时解析

新增第一等的知识节点选择字段 `selected_knowledge_point_ids`，与单文档选择 `selected_doc_ids` 并存。

后端在每次问答或生成请求时执行：

1. 校验节点属于当前课程且用户有读取权限。
2. 对每个已选节点递归取得自身和全部后代节点。
3. 取得这些节点下当前存在且可检索的课程资料。
4. 与显式选择的文档合并并按稳定文档标识去重。
5. 保存原始节点选择和本次实际解析到的证据清单，便于恢复与审计。

因此：

- 勾选父节点：父节点自身及所有层级子节点资料参与检索。
- 勾选子节点：仅该节点自身及其后代参与，不包含父节点和兄弟节点。
- 同时勾选父子节点：文档只参与一次。
- 后续新增到子节点的资料：下一次请求自动参与，无需重新勾选父节点。

### 4.5 节点资料上传规则

1. 课程资料上传仅允许课程负责人或编辑者。
2. 所有知识节点都允许挂载资料，界面优先引导教师选择叶子节点。
3. 父节点资料视图默认聚合自身与全部后代资料，并标明资料实际所属节点。
4. 上传、深度研究导入和从个人库加入课程库都必须保存节点范围。
5. 同一列表严格按创建时间倒序，新资料位于最上方。

### 4.6 后台任务必须终态收敛

1. 所有生成任务创建时都必须带有限期限；沿用当前默认 300 秒，可按任务类型配置但不得为空。
2. 过期租约可以重试，但不得无限恢复为排队态。
3. 达到截止时间、最大重试次数或检测到不可恢复错误时，任务转为明确失败并写入稳定错误码。
4. 工作线程循环必须捕获顶层异常并继续运行，同时暴露线程健康状态，避免单次异常静默杀死 worker。
5. 服务启动时协调任务账本与持久任务库；无执行实体或已过期的幽灵任务必须转为可解释终态。
6. 前端只在存在 `queued`、`running` 或 `cancel_requested` 任务时轮询；全部终态后停止定时请求。

### 4.7 用户错误与技术错误分层

后端输出稳定 `error_code` 和可选用户上下文；原始异常、堆栈和供应商响应只进入日志。前端集中映射为：

- 简短中文标题；
- 一句原因；
- 可执行建议，如重新选择资料、重试或联系管理员；
- 必要时显示可复制任务 ID。

未知错误统一降级为“任务暂时未完成，请稍后重试；如持续发生，请提供任务 ID”，不得直接显示英文异常。

### 4.8 资源排序由服务端定义，前端不二次改序

课程资源接口增加显式排序参数：

- `updated_desc`：更新时间倒序；
- `updated_asc`：更新时间正序；
- `name_asc`：中文名称自然升序；
- `name_desc`：中文名称自然降序。

“最近更新”使用 `updated_desc`。置顶是独立筛选/标记，不覆盖用户选择的排序。相同主键时使用创建时间和资源 ID 做稳定兜底。

## 5. 全局界面框架

### 5.1 顶栏

所有课程页面共享同一个固定顶栏：

- 左侧：全部课程 / 当前课程面包屑和当前页面标题；
- 右侧：后台任务按钮、个人中心按钮；
- 不允许页面内部再次复制课程名称或个人中心入口。

### 5.2 左侧导航

- 删除“当前课程”卡片。
- 删除每个菜单项的说明小字。
- 保留图标和单行名称，增大字号、点击区域和行距。
- 保留返回全部课程入口。
- 当前页面状态、悬停状态和键盘焦点统一。

### 5.3 字体与密度

- 正文默认不小于 14px；主要卡片正文建议 15–16px。
- 导航和主要操作不小于 15px。
- 页面标题、卡片标题和关键数字建立清晰层级。
- 9–11px 字体只用于非关键辅助标记，不承载业务含义。

## 6. 页面设计

### 6.1 课程概览

- 删除课程角色提示。
- 放大课程详情和课程目标文字。
- 统计区改为五张清晰的小卡片：课程资料、课程资源、已完成任务、进行中任务、失败任务；宽屏单排展示，较窄屏响应式换行。
- 删除课程版本卡。
- 课程资料同时显示总数和可检索数，状态来自真实知识库接口。
- 最新课程资源显式请求最近数据，只显示固定数量，卡片区域固定高度；点击带资源标识跳到课程资源详情。
- 常用入口删除“课程概览”，其余入口放大字体。

### 6.2 问答与生成

- 删除页面内部“当前课程/当前知识点”横条和生成工厂按钮。
- 左侧使用“课程知识库/个人知识库”顶部标签切换。
- 删除文档“已接收”状态；资料按最新在前。
- 中间对话区扩大，输入区始终可见。
- 右侧顶部为九个工具卡片，桌面端一行三个，仅显示大号工具名称和图标。
- 点击卡片弹出配置；提交后立即进入后台任务，不进入上一步/下一步向导。
- 工具区下方是固定高度的最近生成列表，包含进行中和终态任务，最新在前。
- 页面占满顶栏以下可用高度，页面本身不纵向滚动，三栏内部按需滚动。

### 6.3 课程知识

- 标签顺序改为“知识图谱、课程知识库”，默认进入知识图谱。
- 删除“计算思维 课程知识库”等重复标题行。
- 知识图谱删除左侧课程学时/设置区域，只保留图谱画布和右侧节点资料。
- 图谱不提供上传和结构编辑；点击节点后右侧显示聚合资料。
- 节点资料框固定高度并内部滚动。
- “和 AI 聊一聊”跳转问答页并预选当前知识节点。
- 课程知识库页面以节点选择器代替材料类型选择，上传入口只对教师显示。

### 6.4 AI 课堂

- 删除返回课程详情、右侧课程名、AI 课件生成标题。
- 首屏展示简洁说明、研究主题输入和开始生成按钮。
- 删除历史残留的内嵌完成进度块；状态统一进入后台任务和最近生成列表。
- 已生成课堂通过课程资源或页面历史列表打开播放器。

### 6.5 课程资源

- 删除“课程资源中心”等重复大标题。
- 分类与九类真实资源一致。
- “最近更新”和“按名称”调用服务端显式排序。
- 左侧资源列表和右侧预览各自滚动，不拉长整体布局。
- 资源点击、任务结果跳转和概览最近资源跳转共用同一资源目标协议。

### 6.6 课程设置

- 删除重复课程名称英雄区。
- 使用清晰的分组表单与固定保存操作区。
- 保留真实 PUT 更新、版本冲突处理和重新加载能力。
- 字段级校验和保存失败使用简洁中文提示。

## 7. 阶段与验收门槛

### 阶段 0：基线与契约

- 记录工作区已有修改和运行数据文件。
- 建立任务状态、资源类型、排序、节点递归和页面壳层测试基线。
- 已知基线：相关前端测试 14 项通过；后端相关测试 12 项通过，1 项因测试仍使用旧 `current_user` 参数失败。

**通过条件：** 新增契约测试先能准确暴露当前问题；不得覆盖已有课程资料或运行数据。

### 阶段 1：任务与资源可靠性

- 修复报告和其他资源的来源选择契约。
- 修复幽灵任务、worker 健康、终态收敛和轮询停止。
- 完成错误中文化和资源排序。
- 建立九类资源可靠性矩阵。

**通过条件：** 九类资源均完成端到端闭环；所有任务终态后停止轮询；模拟租约过期和 worker 异常后任务必定恢复或失败；用户界面无原始英文错误。

### 阶段 2：全局框架与基础页面

- 完成共享顶栏、导航、概览、课程资源和课程设置。

**通过条件：** 六个课程入口共享一致顶栏和导航；统计与接口数据一致；课程信息修改刷新后仍一致；长列表只滚动局部区域。

### 阶段 3：知识图谱与 RAG

- 完成节点资料组织、后端递归解析、双知识库切换和图谱跳转问答。

**通过条件：** 三层节点树中父、子、兄弟和重叠选择均符合规则；父节点能自动检索之后新增的子节点资料；非教师不能上传。

### 阶段 4：问答、生成工厂与 AI 课堂

- 完成固定三栏、工具弹窗、最近生成列表和单主题 AI 课堂入口。

**通过条件：** 九个入口均使用真实配置并能提交；1366×768 及以上桌面视口中问答页无页面级纵向滚动；AI 课堂只填主题即可生成。

### 阶段 5：整体验收

- 执行前后端测试、构建、浏览器逐页检查和多视口检查。
- 检查空、加载、成功、失败、无权限和长文本状态。

**通过条件：** 自动化测试通过；1920、1440、1366 和 1024 宽度无关键遮挡或非预期页面滚动；形成供用户次日统一检查的页面清单和已知限制清单。

## 8. 安全与数据保护

1. `backend/course_data/.../knowledge_base/index.json` 和 `backend/data/` 属于用户/运行数据，不纳入代码提交。
2. 现有未提交的生成修复代码先审查、测试，再作为阶段 1 的起始补丁处理。
3. 不通过删除任务库来“修复”幽灵任务；必须修复生命周期并保留历史可解释性。
4. 不使用破坏性 Git 操作，不覆盖与本设计无关的工作区修改。

## 9. 完成定义

只有同时满足以下条件才算完成：

1. 本文所有页面要求均已实现。
2. 九类资源可靠性矩阵通过。
3. RAG 父子节点规则由后端测试证明。
4. 任务不再无限轮询或永久排队。
5. 用户可见错误完成中文化。
6. 所有阶段验收结果已记录。
7. 用户次日能够一次性检查完整前端，而不是半成品阶段。
