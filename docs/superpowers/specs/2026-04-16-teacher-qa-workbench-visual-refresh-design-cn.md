# 教师问答工作台整体美化设计

## 1. 设计目标

本次设计面向教师端问答工作台的整体视觉升级，目标不是重做交互体系，也不是深入改造三栏内部功能，而是在保留现有三栏结构的前提下，让页面更像一个现代、稳定、清晰的教学工作台。

本次设计确认的目标如下：

1. 保留教师端现有的三栏式工作台结构，继续明确区分左侧知识源、中间问答、右侧生成工坊。
2. 在页面最上端增加极简上下文栏，明确当前基于哪门课程、哪个知识点开展问答工作。
3. 将整体风格从当前偏装饰性、偏漂浮的视觉感受，调整为更克制、更统一、更有秩序的现代工作台风格。
4. 优先改善整体界面的观感、信息重心和工作流语境表达，不在本轮重做三栏内部深层结构。

## 2. 当前上下文

当前教师端实际入口为 `frontend/src/pages/teacher/AiStudioPage.tsx`，路由位于 `/course/:courseId/studio`。

页面当前特征如下：

1. 顶部缺少清晰的课程语境表达，用户进入后会直接落入三栏操作区。
2. 三栏结构本身清楚，但页面更像三个并列卡片，整体工作台语义不够强。
3. 页面背景和面板样式偏装饰性，存在一定的漂浮感和“展示型界面”倾向。
4. 中间聊天区虽然是实际主任务区，但整体视觉主次还不够稳定。

结合项目既有设计上下文，本次升级继续遵循以下方向：

- 面向课程语境中的教师用户
- 轻模式优先
- 专业、可信、清晰
- 低认知负担
- 强调任务上下文和工作流秩序，而不是炫技感

## 3. 范围界定

### 3.1 本次范围

本次只设计并实现以下内容：

1. `AiStudioPage` 的整体页面框架调整
2. 页面最上端极简上下文栏
3. 三栏区域的整体视觉体系重做，包括：
   - 页面背景
   - 页面边距与三栏间距
   - 面板圆角、边框、阴影
   - 三栏视觉主次与比例
4. 页面级样式统一，使其更接近现代工作台型产品界面

### 3.2 不在本次范围

以下内容明确不纳入本轮：

1. 左中右三栏内部的深层结构调整
2. 每栏顶部统一标题区设计
3. 复杂的新交互入口、新功能、新状态面板
4. 状态管理重构
5. 生成工坊、知识源面板、聊天区内部组件的细粒度改版

## 4. 目标体验

教师进入工作台后，应首先感知到：

1. 当前正在基于哪门课程工作
2. 当前问答围绕哪个知识点展开
3. 页面是一个清晰、稳定、专业的三栏工作台

在此基础上，页面需要满足以下体验目标：

1. 顶部语境明确，但不杂乱，不做复杂状态仪表盘
2. 三栏结构一眼可读，信息分工保持清楚
3. 中间问答区自然成为操作重心
4. 左右两栏存在感清楚，但不争抢主任务注意力
5. 整体视觉更现代、更整洁，但不过度强调 AI 产品感

## 5. 设计方案

### 5.1 页面总体结构

页面调整为两层结构：

1. 顶部极简上下文栏
2. 下方三栏主工作区

不引入额外的大型头部卡片、工作台摘要看板、统一标题带或复杂状态区。页面主体仍然是现有三栏，只是在三栏上方补一层简洁的课程语境说明。

### 5.2 顶部极简上下文栏

顶部上下文栏只承担一件事：定义当前问答工作的课程语境。

其内容固定为两项：

1. 当前课程
2. 当前知识点

#### 信息优先级

- `当前课程` 为主信息，视觉权重更高
- `当前知识点` 为辅信息，视觉更轻

#### 展示原则

1. 不展示资料数、对话数、产出数、RAG 状态、Web 状态等统计和开关
2. 不承担筛选、切换、管理等复杂操作
3. 不做大卡片化设计，避免与三栏主体争夺注意力
4. 只做为页面语境签名条存在

#### 知识点的来源策略

为避免产生“看起来聪明但实际不稳定”的推断，本次设计明确采用保守规则：

1. 若已有显式的当前知识点上下文，则直接展示
2. 若当前没有稳定的知识点来源，则显示 `未指定知识点`
3. v1 不根据最近一条聊天消息自动猜测知识点

#### 课程来源策略

1. 优先展示当前课程上下文中的课程名称
2. 若暂时拿不到课程名称，则退化为课程 ID 或占位文本

### 5.3 三栏主工作区

本次保留当前三栏架构，不改为单壳体工作台，也不模糊三栏边界。

三栏职责继续保持：

1. 左栏：知识源与语料上下文
2. 中栏：教师与 AI 的问答主任务区
3. 右栏：生成工坊与产出预览

#### 三栏关系

本次强化的是“三栏秩序”，不是“三栏融合”。

设计要求如下：

1. 三栏继续清晰分栏
2. 三栏风格统一，但保持各自边界
3. 中间栏是主要视觉重心
4. 左右栏作为辅助区，视觉分量略低于中间栏

### 5.4 视觉语言

#### 背景

页面背景从当前偏蓝雾感、偏装饰性的渐变背景，调整为更干净的浅灰白基底。

目标：

1. 降低背景存在感
2. 让三栏本身成为视觉主体
3. 减少“展示型界面”观感

#### 面板风格

三栏容器继续保留独立面板感，但视觉上更利落、更克制：

1. 圆角收敛，不再强调过软的卡片气质
2. 边框更清楚、更薄
3. 阴影更浅，降低漂浮感
4. 取消或弱化明显玻璃感、强模糊和高装饰性高光

#### 留白与节奏

页面留白改为秩序型，而不是展示型：

1. 顶部上下文栏与三栏主区之间保留明确但克制的呼吸区
2. 三栏之间使用统一间距
3. 页面四周边距收敛，避免无意义的大面积空白
4. 通过对齐和比例形成高级感，而不是依赖装饰背景

#### 色彩策略

1. 页面以中性浅色为主
2. 强调色只用于关键交互或状态，不作为大面积背景色
3. 避免整页泛蓝、泛紫、玻璃高光等典型 AI 产品配色倾向

### 5.5 三栏比例与重心

本次继续保持“中间最大、两侧辅助”的关系，但控制差距不要过大。

目标如下：

1. 左栏足够承载知识源列表与预览入口
2. 中栏保证连续的问答阅读和输入空间
3. 右栏足够容纳生成区与结果预览入口
4. 页面整体看起来是稳定分工，而不是中间过挤、两边过飘

### 5.6 响应式原则

本次不重新设计移动端复杂结构，但页面级调整需要继续兼容现有响应式行为：

1. 桌面端保持三栏工作台
2. 中等屏幕下优先保证中栏可用性
3. 小屏继续沿用当前“侧栏隐藏、中栏优先”的降级逻辑
4. 顶部上下文栏在窄屏下允许换行，但不应变成多行信息堆叠区

## 6. 组件与实现边界

本次设计的实现边界控制在页面壳层，不深入业务组件内部。

建议主要触达以下文件：

- `frontend/src/pages/teacher/AiStudioPage.tsx`
- `frontend/src/pages/teacher/AiStudioPage.css`

如确有必要，可增加很轻量的页面级上下文展示辅助逻辑，但不应扩散到三栏内部大规模改造。

## 7. 数据流与状态约束

本次页面级新增的上下文栏需要消费以下两类信息：

1. 课程信息
2. 当前知识点信息

### 7.1 课程信息

课程信息应来自现有课程上下文，而不是在页面内自行拼装业务语义。

优先顺序：

1. 已存在的课程名称
2. 路由中的 `courseId`
3. 占位文本

### 7.2 当前知识点信息

本次只接入“显式当前知识点”数据，不引入消息推断。

优先顺序：

1. 已存在的显式知识点上下文
2. 无值时显示 `未指定知识点`

这样可以保证顶部上下文栏始终稳定、可解释、不会因为聊天内容变化而抖动。

## 8. 错误处理与退化策略

顶部上下文栏必须支持优雅退化：

1. 课程名缺失时，不阻断页面渲染
2. 知识点缺失时，显示 `未指定知识点`
3. 页面不因缺少上下文数据而隐藏三栏工作区

页面级样式调整也不应改变以下行为：

1. 左右栏折叠与展开
2. 预览状态带来的栏宽变化
3. 现有三栏内部滚动逻辑

## 9. 测试与验收

本次重点做页面级验收，而非业务逻辑验收。

### 9.1 视觉验收

1. 页面最上端出现极简上下文栏
2. 上下文栏只展示课程与知识点，不出现信息堆叠
3. 三栏布局仍然清楚可辨
4. 中间栏为主要视觉重心
5. 背景、边框、阴影、留白整体更克制、更统一

### 9.2 行为验收

1. 左右栏折叠/展开不受影响
2. 预览态带来的宽度变化不受影响
3. 小屏下现有降级逻辑不受影响
4. 顶部上下文缺失时页面仍可正常使用

### 9.3 回归关注点

1. `AiStudioPage` 样式修改不能破坏 `SourcePanel`、`ChatPanel`、`StudioPanel` 的既有功能
2. 页面整体高度和滚动容器关系保持稳定
3. 文本在窄屏和课程名较长时不得溢出遮挡

## 10. 成功标准

本次改版完成后，应达到以下结果：

1. 用户一进入页面，就知道当前基于哪门课程、哪个知识点开展问答
2. 页面整体观感明显比当前版本更整洁、更现代、更稳定
3. 三栏结构仍保持清晰，不因统一风格而失去分栏辨识度
4. 中间问答区的主任务地位更明确
5. 本轮改动仍然保持足够收敛，为后续三栏内部深化优化留出空间
