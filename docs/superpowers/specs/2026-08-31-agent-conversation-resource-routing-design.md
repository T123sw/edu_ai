# Agent 普通对话与资源生成路由设计

日期：2026-08-31

## 1. 背景与目标

当前教师端流式对话原本采用统一 ReAct Agent：每条用户消息先进入 Agent，再由任务契约与计划决定直接回答、检索资料或调用资源工具。近期为隔离普通问答污染而增加的 FastChat 提前分流偏离了该架构，并造成大纲确认消息“开始”在不同层被不一致识别，最终出现“文本声称报告已启动，但后台没有任务”的问题。

本次目标是恢复统一 Agent 入口，并建立清晰、可验证的意图、提示词和工具权限边界：

1. 每条对话都进入 ReAct Agent。
2. 普通问答允许使用用户已启用的 RAG、Web，以及用户明确请求的图片检索。
3. 普通问答不得调用大纲或资源生成工具，不得主动把问答转成资源制作。
4. 资源生成、修改、确认、状态和取消任务按各自计划开放最小工具权限。
5. 只有生成工具真实返回 `task_id` 后，系统才能声明任务已提交或启动。

## 2. 不在本次范围

- 不新增第二个 LLM 意图分类器。
- 不修改报告、教案、PPT 等生成引擎内部内容质量逻辑。
- 不重构前端页面布局或后台任务中心。
- 不允许模型绕过已编译计划直接获得资源生成权限。

## 3. 总体架构

```text
用户消息
  -> MainOrchestrator
  -> ReActAgent
  -> TeachingTaskContract
       qa
         -> 允许直接回答 / RAG / Web / 明确请求的图片检索
         -> 禁止 draft_outline / generate_* / cancel_task
       generate_single / prepare_bundle / modify / confirm
         -> 编译资源计划
         -> 按当前步骤开放对应工具
       status / cancel
         -> 只开放任务查询或取消工具
  -> Executor
  -> 工具结果与真实性校验
  -> 用户可见回答
```

所有流式消息在没有显式页面级 `action_hint` 时继续进入 ReAct Agent。FastChat 只保留为 Agent 不可用或模型网关不支持工具协议时的降级路径，不再承担普通问答的正常分流。

## 4. 意图契约

`TeachingTaskContract` 继续作为唯一计划输入，保留以下意图：

- `qa`：知识问答、解释、比较、闲聊，以及仅提到资源名但没有要求创建资源的咨询。
- `generate_single`：明确要求生成一种或多种资源。
- `prepare_bundle`：明确要求准备教学材料包。
- `modify`：修改当前大纲或已有资源任务。
- `confirm`：确认待处理大纲并进入真实生成。
- `status`：查询任务状态。
- `cancel`：取消生成任务。

资源名本身不能构成生成意图。例如“教案通常包含哪些部分”必须为 `qa`；“生成一份链表教案”才是 `generate_single`。

### 4.1 跨轮确认

仅当存在 `active_draft_outline` 时，以下短回复可识别为 `confirm`：

- `开始`
- `好的`
- `可以`
- `确认`
- `没问题`
- `按这个生成`
- `开始生成`
- `继续生成`

短确认采用规范化后的整句匹配，不能使用任意子串匹配。以下消息即使包含确认词，也必须继续按其完整语义判断：

- `可以解释一下链表吗`
- `开始节点是什么`
- `好的教案通常有哪些特点`

## 5. 工具权限策略

工具权限由服务端根据任务契约和当前计划步骤裁剪，Prompt 只负责行为引导，不能充当唯一安全边界。

### 5.1 普通问答

允许：

- 直接回答
- `rag_search`（用户启用课程资料或选择文档时）
- `web_search`（用户启用 Web 时）
- `image_search`（用户当前消息明确要求图片时）

禁止：

- `draft_outline`
- 所有 `generate_*`
- `cancel_task`
- 任何会创建、修改或取消资源与后台任务的工具

即使普通问答不需要 Planner，也必须把已抽取的 `task_contract` 注入 Agent 状态，使 Executor 能执行同样的服务端工具过滤。

### 5.2 资源与控制任务

- 资源任务只按当前计划步骤开放对应 `generate_*`。
- 大纲确认前不得开放最终生成工具。
- 状态查询只开放查询工具。
- 取消任务只开放取消工具。
- 当前步骤没有工具权限时，模型只能输出文本。

## 6. Agent Prompt 设计

Prompt 分为四个稳定区块。

### 6.1 角色定位

教师端 Agent 是教师的教学与备课助手。它优先完成当前问题，表达简洁、直接，不把教师当学生教学，不连续反问，不展示内部推理。

### 6.2 意图边界

- 当前契约为普通问答时，只回答当前问题。
- 不把检索结果当成待评审的教案、报告或 PPT。
- 不主动评价普通回答是否缺少图片、图表或教学环节。
- 不主动建议生成教案、PPT、报告或其他资源。
- 用户明确要求资源生成时，才进入资源工作流。

### 6.3 工具边界

- 只能使用当前计划明确授权的工具。
- RAG/Web 是回答依据，不代表用户要求资源生成。
- 配图完整性检查只适用于明确的资源生成步骤。
- 不得通过文本模拟工具调用或扩大任务范围。

### 6.4 真实性约束

- 只有当前轮成功执行 `generate_*`，且工具结果包含非空 `task_id`，才能说“已提交”“已启动”或“正在后台生成”。
- 未执行生成工具时，必须明确资源任务尚未提交。
- 工具提交失败时，直接说明失败原因，不得使用成功措辞。
- 普通问答不得声称创建了任何资源或后台任务。

Executor 在当前计划提示中追加当前 `intent` 与 `internal_action`，让模型明确本轮是回答问题还是执行资源步骤。

## 7. 数据流与状态

1. ReAct Agent 恢复会话 checkpoint 和持久 Agent 状态。
2. Agent 使用当前消息、活动大纲和会话状态抽取 `TeachingTaskContract`。
3. 契约写入本轮初始 Agent 状态，无论是否需要 Planner。
4. 需要检索、资源、控制或跨轮确认时编译计划；简单问答可直接进入 Executor。
5. Executor 按契约与当前步骤过滤工具。
6. 工具执行结果写入 trace；资源工具成功结果必须包含 `task_id`。
7. 模型依据工具结果组织回答；服务端保留任务事件与最终结果的一致性检查。

## 8. 错误处理

- RAG/Web 被用户明确启用但没有证据时，返回检索不足边界，不虚构资料依据。
- 生成工具未开放时，模型不能声称任务已提交。
- 生成工具返回失败时，保留失败事件并向用户提供可重试说明。
- 生成工具成功但缺少 `task_id` 时，视为协议错误，不输出成功文案。
- Agent 网关不支持工具调用时可降级到 FastChat，但降级路径仍不得创建资源。

## 9. 测试与验收

### 9.1 普通问答

- `链表如何实现`：进入 ReAct Agent；允许 RAG；没有 `generate_*`。
- `教案通常包含哪些部分`：`intent=qa`；不生成教案。
- `PPT 和教案有什么区别`：`intent=qa`；不创建资源。
- 普通问答 Prompt 不包含主动配图检查或资源推荐要求。

### 9.2 资源生成

- `生成一份链表报告`：进入报告大纲流程。
- 待确认报告大纲后发送 `开始`：`intent=confirm`，计划包含 `generate_report`。
- `generate_report` 成功时产生 `task_submitted` 和真实 `task_id`。
- 后台 Job 账本存在与 `task_id` 对应的 `generate_report` 记录。

### 9.3 防误判与真实性

- 活动大纲存在时，`开始节点是什么`仍为普通问答。
- 没有成功生成工具结果时，回答不得包含“任务已启动/已提交”。
- 生成工具失败时，回答不得使用成功措辞。
- 普通问答不触发资源生成、取消或大纲工具。
