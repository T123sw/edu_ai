# AI 课堂视频渲染端口修复设计

## 背景

Edu-AI 的统一启动脚本在 `5173` 端口启动 Vite 前端，但课堂视频导出后端和环境示例仍将渲染页地址默认为 `http://127.0.0.1:4173`。视频导出任务因此无法打开 `#video-render` 路由，并以 `ERR_CONNECTION_REFUSED` 失败。

## 目标

- 让本地统一启动环境中的课堂 MP4 导出复用现有 `5173` 前端。
- 保证启动脚本、后端默认值和环境示例使用同一个渲染地址。
- 不新增第二个前端进程，不引入端口自动探测。
- 保留 `CLASSROOM_VIDEO_FRONTEND_URL` 环境变量作为部署时的显式覆盖入口。

## 设计

1. 将 `classroom_video_export.py` 的本地默认渲染地址改为 `http://127.0.0.1:5173`。
2. 将 `api/src/.env.example` 中的 `CLASSROOM_VIDEO_FRONTEND_URL` 同步为 `http://127.0.0.1:5173`。
3. 在 `start_api.bat` 中根据 `FRONTEND_PORT` 显式设置 `CLASSROOM_VIDEO_FRONTEND_URL`，让后端与脚本配置保持一致。
4. 扩展后端与启动脚本测试，断言默认地址和统一启动地址均为 `5173`，防止以后再次漂移。

## 数据流

用户点击“导出 MP4”后，Edu 后端创建视频任务，启动 Node 导出器，并把 `http://127.0.0.1:5173` 作为 `--base-url`。Playwright 打开该前端的 `#video-render` 路由，逐场景录制后通过 FFmpeg 合成为 MP4、SRT 和时间轴文件。

## 错误处理

本次只修复已确认的端口配置根因。现有任务失败状态、错误记录与临时目录清理逻辑保持不变；不添加静默端口探测，以免错误配置被隐藏。

## 验证

- 新增或调整测试，并先确认其在旧配置下失败。
- 运行课堂视频导出后端测试。
- 运行前端视频管线测试和完整前端测试。
- 运行生产构建。
- 在 `5173` 前端存活时重新导出本次课堂，确认生成：
  - `classroom.mp4`
  - `classroom.srt`
  - `timeline.json`

## 非目标

- 不启动额外的 `4173` Vite Preview 服务。
- 不实现多个端口的自动探测。
- 不修改课堂播放器或视频编码参数。
