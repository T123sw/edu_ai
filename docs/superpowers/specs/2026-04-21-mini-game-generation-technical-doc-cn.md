# 小游戏生成功能说明

日期：2026-04-21  
范围：教师 AI 工作台中的小游戏生成与预览功能

---

## 1. 功能定位

小游戏生成是教师工作台「生成式工厂」中的一个互动教学资源生成能力。

教师可以基于已选知识库资料，快速生成一个可直接预览和课堂播放的小游戏，用于课堂导入、知识点复习、概念巩固或课后练习。

该功能的目标不是生成普通文本内容，而是把课程资料转化成可交互的小游戏，让学生通过拖拽、分类、翻牌等方式参与学习。

---

## 2. 使用入口

入口位于教师 AI 工作台右侧的「生成式工厂」区域。

当前「小游戏生成」卡片放在「思维导图」旁边，方便教师在知识整理类资源和互动小游戏之间快速切换。

使用前，教师需要先在左侧知识库中勾选至少一份资料。系统会基于这些资料生成小游戏内容。

---

## 3. 支持的小游戏类型

当前版本支持 3 种小游戏。

### 3.1 分类归纳

分类归纳用于让学生把知识点、概念或材料拖入正确类别中。

适合场景：

- 概念分类
- 章节知识点整理
- 历史事件归类
- 语法或规则分组

示例：

教师选择一份关于变量基础概念的资料后，系统可以生成「变量命名规则」「变量赋值方式」「变量使用场景」等分类，让学生把具体说明拖入对应类别。

### 3.2 拖拽配对

拖拽配对用于让学生把两组相关内容进行匹配。

适合场景：

- 术语与定义配对
- 人物与事件配对
- 公式与含义配对
- 原因与结果配对

示例：

系统可以根据资料生成「变量」与「用于存储可变化数据的命名容器」这样的配对，让学生完成匹配。

### 3.3 翻牌记忆

翻牌记忆用于让学生通过翻牌找到对应关系，加强记忆。

适合场景：

- 术语记忆
- 英汉对应
- 定义复习
- 基础概念巩固

示例：

系统可以生成一组卡片，一张写「变量」，另一张写「保存程序运行中可变化的数据」，学生需要翻牌找到正确组合。

---

## 4. 基本使用流程

1. 教师进入 AI 工作台。
2. 在左侧知识库中勾选相关资料。
3. 在右侧「生成式工厂」点击「小游戏生成」。
4. 在弹窗中选择小游戏类型。
5. 点击「生成小游戏」。
6. 系统自动生成小游戏并在右侧预览区打开。
7. 教师可以直接预览，也可以点击「全屏播放」用于课堂展示。

如果未选择知识库资料，系统会提示先选择资料，避免生成内容没有依据。

---

## 5. 生成结果

小游戏生成完成后，会作为一个独立的课程资源出现在工作台中。

生成结果包括：

- 小游戏标题
- 小游戏类型
- 可交互的游戏页面
- 可在工作台中预览的内容
- 可全屏播放的页面

教师无需手动整理题目或卡片，系统会根据选中的知识库资料自动提取适合做成游戏的概念、定义、关系或分类。

---

## 6. 预览与播放

生成成功后，小游戏会在工作台右侧打开预览。

教师可以：

- 在工作台内直接试玩。
- 点击「返回」回到生成式工厂。
- 点击「全屏播放」打开更适合课堂投屏的播放视图。

当前预览已经处理了登录态和页面加载问题，避免小游戏预览时误打开系统首页。

---

## 7. 课程资料保存

小游戏生成后会保存为课程资料。

保存后，教师可以在后续课程中再次打开小游戏，不需要重新生成。

这使小游戏可以像其他课程资源一样沉淀下来，用于：

- 课堂活动
- 复习环节
- 学生练习
- 教师二次备课

---

## 8. 简要实现说明

### 8.1 输入

小游戏生成主要依赖 3 类输入：

- 已选知识库资料：教师在左侧知识库中勾选的文档。
- 小游戏类型：分类归纳、拖拽配对或翻牌记忆。
- 当前课程上下文：用于把生成结果保存到对应课程资料中。

前端提交时，会把这些信息传给后端。后端根据选中的文档内容生成小游戏数据。

### 8.2 输出

生成完成后，系统会输出一个小游戏资源。

资源中主要包含：

- 小游戏标题。
- 小游戏类型。
- 小游戏结构化数据。
- 可预览的 HTML 页面。
- 课程资料保存信息。

教师看到的是一个可以直接打开的小游戏，而不是一段普通文本。

### 8.3 生成方式

生成时，系统不会直接把整篇文档塞进小游戏，而是先把教师选中的知识库资料整理成适合游戏使用的知识素材。

整理时主要关注：

- 核心概念：适合做成卡片、选项或配对左侧内容。
- 概念解释：适合做成定义、提示或配对右侧内容。
- 分类关系：适合做成分类归纳中的类别和条目。
- 对应关系：适合做成拖拽配对或翻牌记忆中的一组关系。
- 表述较短、边界清晰的知识点：更适合小游戏呈现。

不同小游戏会使用不同的数据结构：

- 分类归纳：生成标题、分类列表和待归类条目，每个条目会标记它属于哪个分类。
- 拖拽配对：生成标题和若干组左右配对，例如“术语 - 定义”“问题 - 答案”。
- 翻牌记忆：生成标题和若干组卡片对，例如“概念 - 解释”“英文 - 中文”。

这些内容最终会整理成一份小游戏 JSON。JSON 可以理解为“小游戏说明书”：它不负责页面样式，只描述小游戏里有哪些类别、卡片、配对和正确答案。

例如翻牌记忆大致会生成这样的数据：

```json
{
  "title": "变量基础概念记忆翻牌",
  "matches": [
    {
      "pair_id": "m1",
      "card_a": "变量",
      "card_b": "保存程序运行中可变化的数据"
    }
  ]
}
```

后端会先检查这份 JSON 是否符合当前小游戏的要求。检查通过后，再把 JSON 注入对应的 HTML 模板中。

小游戏 HTML 模板里会预留一个数据占位符：

```js
const GAME_DATA = __GAME_DATA_JSON__;
```

生成时，系统会把 `__GAME_DATA_JSON__` 替换成真正的小游戏 JSON，例如：

```js
const GAME_DATA = {
  "title": "变量基础概念记忆翻牌",
  "matches": [...]
};
```

这样生成出的 HTML 文件就同时包含了页面结构、交互逻辑和本次生成的小游戏数据。前端预览时打开的就是这个已经注入数据的 HTML 页面。

### 8.4 预览方式

小游戏生成后，前端会在工作台右侧加载小游戏页面。

为了避免预览时打开到系统首页，前端不会直接让 iframe 跳转到小游戏地址，而是先从后端读取小游戏 HTML，再放入 iframe 中显示。

这样可以保证：

- 预览区域显示的是小游戏本身。
- 已登录用户可以正常访问受保护的小游戏资源。
- 「全屏播放」和工作台预览展示的是同一份小游戏内容。

### 8.5 保存方式

生成成功后，小游戏会作为课程资料保存。

保存后，教师后续重新进入课程时，可以从课程资料中再次打开该小游戏，不需要重新生成。

---

## 9. 使用建议

为了获得更好的生成效果，建议：

- 选择内容明确、知识点集中的资料。
- 如果要生成分类归纳，资料中最好包含多个可区分的类别。
- 如果要生成拖拽配对，资料中最好包含术语、定义、人物、事件或因果关系。
- 如果要生成翻牌记忆，资料中最好包含适合记忆的短概念和解释。

如果资料过少或内容过散，生成的小游戏可能会比较简单。

---

## 10. 当前版本边界

当前版本已经支持从知识库资料直接生成、预览、全屏播放和保存小游戏。

暂未包含：

- 生成后手动编辑小游戏内容。
- 学生端分享链接。
- 学生答题数据统计。
- 更多小游戏模板。
- 游戏结果分析。

这些能力可以作为后续优化方向逐步加入。

---

## 11. 总结

小游戏生成功能让教师可以把静态知识库资料快速转成互动课堂活动。

它适合用于课堂中的轻量互动、知识巩固和复习练习，能够降低教师准备互动素材的成本，并提升学生参与感。
