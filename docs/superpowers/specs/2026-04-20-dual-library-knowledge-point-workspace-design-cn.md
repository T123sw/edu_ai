# 知识点双知识库与目录化问答工作域设计

## 1. 目标

在教师 AI 工作台中，将原来“按课程区分”的问答、资料、生成物和历史会话，升级为“按课程总目录 / 知识点节点区分”的工作域。

本轮新增设计重点是：每个知识点下同时存在两类知识库。

- 课程知识库：正式教学资料，主要在知识图谱界面维护，按照知识点目录结构组织。
- 个人知识库：教师在问答界面上传或爬取的个人资料，只归属于当前进入的节点，不展示子节点个人资料。

这样可以同时满足两个目标：课程资料形成稳定、可复用的目录化知识体系；个人资料保持轻量、私有、隔离，不因为父子节点聚合而混在一起。

## 2. 核心概念

- 工作域：教师当前所在的 AI 问答上下文，可以是课程总目录，也可以是某个知识点节点。
- 课程总目录：课程级工作域，不归属于任何具体知识点。
- 知识点节点：知识图谱中的一个节点，可以是叶子节点，也可以是非叶子节点。
- 叶子节点：没有子知识点的节点。
- 非叶子节点：有子知识点的节点，包括课程总目录和中间层知识点。
- 课程知识库：面向课程建设的正式资料库，支持按知识图谱目录树展示。
- 个人知识库：面向教师个人探索、临时上传、爬取沉淀的资料库，只展示当前节点直属个人资料。
- 直属资料：直接挂在当前工作域节点下的资料。
- 子节点资料：挂在当前节点的后代知识点下的资料。

## 3. 前端展示规则

### 3.1 叶子节点

进入叶子知识点后，左侧资料列表展示两个知识库分区。

- 课程知识库：展示当前叶子节点的课程资料。
- 个人知识库：展示当前叶子节点的个人资料。

叶子节点没有子节点，因此两个分区都可以使用平铺列表。

推荐交互：

- 顶部显示当前工作域，例如“当前知识点：计算思维与程序设计”。
- 左侧资料区提供“课程知识库 / 个人知识库”切换或双分区折叠展示。
- 个人知识库中的资料支持“转入课程知识库”操作。
- 转入后，该资料复制到当前知识点的课程知识库中，个人知识库中可保留原资料。

### 3.2 非叶子节点

进入非叶子知识点后，课程知识库和个人知识库采用不同展示策略。

课程知识库按目录树展示。

- 当前节点下显示“当前节点资料”。
- 子知识点按知识图谱结构展开。
- 每个子知识点下面展示该节点的课程资料。
- 子节点继续有后代时，继续按树结构展开。

个人知识库直接平铺。

- 只展示当前节点直属个人资料。
- 不展示子知识点个人资料。
- 不把子节点教师个人上传或爬取的资料聚合到父节点。

这样可以避免个人资料在父子节点之间互相污染，同时保留课程知识库的结构化聚合能力。

### 3.3 课程总目录

课程总目录可以理解为整门课程的根工作域。

课程知识库：

- 展示课程总目录直属资料。
- 展示整棵知识图谱下所有知识点的课程资料。
- 使用目录树组织，避免一次性铺满列表。

个人知识库：

- 只展示课程总目录直属个人资料。
- 不展示任何知识点节点下的个人资料。

历史遗留的课程级文档，如果没有知识点归属，应默认放在课程总目录直属资料下。

## 4. 父节点检索规则

父节点检索要区分课程知识库和个人知识库。

在父节点发起 RAG 检索时：

- 课程知识库：默认检索当前节点及所有子孙节点的课程资料。
- 个人知识库：只检索当前节点直属个人资料。

也就是说，在父节点检索时，可以正确检索到子节点的课程资料，但不会检索到子节点的个人资料。

推荐在问答区显示检索范围提示：

- 课程知识库：当前节点 + 子知识点
- 个人知识库：仅当前节点

如果后续需要更强控制，可以增加一个开关：

- 包含子知识点课程资料：默认开启。
- 仅检索当前节点课程资料：教师手动切换。

个人知识库不建议增加“包含子节点个人资料”开关，除非未来明确要做教师个人资料全局聚合。当前阶段保持隔离更安全。

## 5. 父节点导入规则

父节点导入并不冲突，只要明确“导入发生在哪个库、哪个节点”。

在问答界面导入或爬取：

- 永远进入个人知识库。
- 归属于当前工作域节点。
- 如果当前在父节点，则资料挂在父节点个人知识库下。
- 不自动分发到子节点。
- 不要求用户选择子节点。

在知识图谱界面导入：

- 进入课程知识库。
- 如果选中某个知识点节点上传，则资料挂在该知识点课程知识库下。
- 如果选中课程总目录上传，则资料挂在课程总目录课程知识库下。

个人资料转入课程知识库：

- 从当前节点个人知识库复制到当前节点课程知识库。
- 默认采用“复制/晋升”，不做破坏性移动。
- 原个人资料保留，便于追溯和再次编辑。
- 课程知识库中的新资料记录来源信息，例如 `promoted_from_document_id`。

## 6. 数据模型建议

资料记录至少需要包含以下字段。

```ts
type LibraryType = "course" | "personal";
type ScopeType = "course" | "knowledge_point";

interface KnowledgeDocument {
  id: string;
  courseId: string;
  scopeType: ScopeType;
  scopeId?: string;
  scopeLabel: string;
  libraryType: LibraryType;
  ownerUserId?: string;
  title: string;
  sourceType: "upload" | "crawl" | "generated" | "legacy";
  fileType?: string;
  createdAt: string;
  updatedAt: string;
  promotedFromDocumentId?: string;
  promotedByUserId?: string;
  promotedAt?: string;
}
```

字段含义：

- `libraryType = "course"` 表示课程知识库资料。
- `libraryType = "personal"` 表示个人知识库资料。
- `ownerUserId` 只对个人知识库必填，课程知识库可以为空。
- `scopeType = "course"` 表示课程总目录。
- `scopeType = "knowledge_point"` 表示具体知识点。
- `scopeId` 在课程总目录下为空，在知识点下为知识点 ID。

## 7. 接口设计建议

查询资料列表：

```http
GET /api/courses/:courseId/knowledge-documents
```

推荐参数：

```ts
interface ListKnowledgeDocumentsQuery {
  libraryType: "course" | "personal";
  scopeType: "course" | "knowledge_point";
  scopeId?: string;
  includeDescendants?: boolean;
  limit?: number;
  offset?: number;
}
```

列表规则：

- 查询课程知识库树时，`libraryType=course`，父节点可使用 `includeDescendants=true`。
- 查询个人知识库时，`libraryType=personal`，固定 `includeDescendants=false`。
- `limit` 默认 20。
- 每个节点的资料列表都要支持“加载更多”。

上传到课程知识库：

```http
POST /api/courses/:courseId/knowledge-documents/course
```

上传到个人知识库：

```http
POST /api/courses/:courseId/knowledge-documents/personal
```

个人资料转入课程知识库：

```http
POST /api/courses/:courseId/knowledge-documents/:documentId/promote-to-course
```

推荐请求体：

```ts
interface PromoteToCourseRequest {
  targetScopeType: "course" | "knowledge_point";
  targetScopeId?: string;
}
```

默认情况下，`targetScopeType` 和 `targetScopeId` 使用当前工作域，不让用户额外选择，减少误操作。

## 8. 目录树加载策略

课程知识库树不能一次性加载全部资料，尤其课程总目录下可能有大量知识点和资料。

推荐策略：

- 初始只加载当前节点的一级子节点和当前节点直属课程资料。
- 展开某个子节点时，再加载该子节点的课程资料和下一级子节点。
- 每个节点资料默认加载 20 条。
- 点击“加载更多”再加载下一组 20 条。
- 树节点上显示资料数量时，可以先显示已加载数量，再异步补充总数。

个人知识库不需要树形加载。

- 只请求当前节点直属个人资料。
- 默认加载 20 条。
- 点击“加载更多”再加载下一组 20 条。

## 9. 生成物展示规则

生成物继续按照当前工作域归属。

在知识点工作域生成的内容：

- 归属于当前知识点。
- 进入该知识点的生成物列表。
- 不自动显示到其他兄弟知识点。

在课程总目录工作域生成的内容：

- 归属于课程总目录。
- 显示在课程总目录生成物列表。

父节点生成物展示可以采用与课程知识库类似的聚合规则。

- 当前节点可展示当前节点及子孙节点历史生成物。
- 默认每次加载 20 条。
- 列表项标注来源知识点，避免教师不知道内容来自哪个子节点。

如果后续希望更严格隔离，也可以切换为“只显示当前节点生成物”。当前设计推荐聚合展示，因为用户之前明确希望父级能汇总所有知识点数据，但要分页加载。

## 10. 历史数据迁移规则

已有资料需要兼容，不应该在升级后消失。

历史课程级 RAG 文档：

- 如果没有知识点归属，迁移或映射到课程总目录个人知识库。
- 如果能从已有元数据判断知识点归属，则迁移到对应知识点个人知识库。

历史课程资料或正式教学资料：

- 如果没有知识点归属，迁移或映射到课程总目录课程知识库。
- 如果能判断知识点归属，迁移到对应知识点课程知识库。

历史生成物：

- 如果没有知识点归属，归到课程总目录生成物列表。
- 如果已有知识点归属，归到对应知识点生成物列表。

## 11. 验收标准

- 从知识图谱叶子节点跳转到问答页后，工作域名称显示为该知识点。
- 叶子节点左侧资料区能看到课程知识库和个人知识库两个分区。
- 非叶子节点左侧课程知识库按目录树展示，个人知识库平铺展示。
- 在父节点检索时，可以检索到子节点课程知识库资料。
- 在父节点检索时，不会检索到子节点个人知识库资料。
- 在父节点问答界面上传或爬取资料后，资料只进入父节点个人知识库。
- 在知识图谱节点上传资料后，资料进入该节点课程知识库。
- 个人知识库资料可以转入课程知识库，转入后课程知识库可检索到该资料。
- 课程总目录能展示历史课程级资料和生成物。
- 所有大列表默认每次加载 20 条，支持继续加载。

## 12. 当前明确决策

- 课程知识库按知识点目录结构展示。
- 个人知识库不使用目录树，当前阶段只平铺展示当前节点个人资料。
- 父节点课程知识库检索默认包含子节点。
- 父节点个人知识库检索默认不包含子节点。
- 问答界面上传或爬取的资料进入个人知识库。
- 知识图谱界面上传的资料进入课程知识库。
- 个人资料转入课程资料采用复制晋升，不做移动删除。

## 13. 后续实现顺序建议

1. 先补齐前端工作域状态，确保课程总目录和知识点节点识别稳定。
2. 再改资料接口参数，加入 `libraryType`、`scopeType`、`scopeId`、`includeDescendants`。
3. 再实现左侧资料区双知识库展示。
4. 再实现课程知识库树形展示和懒加载。
5. 再实现个人资料转入课程知识库。
6. 最后接入 RAG 检索范围，确保父节点检索课程子节点资料但不检索子节点个人资料。
