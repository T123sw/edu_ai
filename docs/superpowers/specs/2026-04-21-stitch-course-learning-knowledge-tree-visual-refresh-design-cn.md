# 课程学习知识点树样式重设计方案

## 1. 背景

当前 `课程学习` 页左侧的知识结构列表已经具备树形数据和展开收起能力，但视觉上仍然更接近“同级卡片列表”而不是“知识树”：

- 父节点和子节点基本使用同一张大卡片样式，只靠 `padding-left` 轻微偏移，层级关系不明显。
- 节点标题与摘要很多时候重复显示两次，增加噪音，降低扫读效率。
- 节点类型标签、展开按钮、标题、摘要都处于相近视觉权重，用户第一眼无法快速定位“当前层级、当前选中节点、子节点归属关系”。

这次重设计只聚焦 `VideoPlayer.tsx` 左侧“学习路径 / 知识结构列表”区域，不改变右侧课程内容联动逻辑。

## 2. 目标

本次重设计希望达成以下结果：

- 父节点与子节点的层级关系一眼可见。
- 节点树保留当前页面的圆角面板风格，但不再把所有层级都做成同样重的卡片。
- 去掉重复信息，让用户先看到结构，再看到说明。
- 当前选中节点和展开路径更清晰，便于定位“现在学到哪里”。
- 改动范围聚焦在前端展示层，不影响现有知识点选择、课程资源联动和展开收起数据结构。

## 3. 方案对比

### 方案 A：卡片树混合型（推荐）

- 根节点与一级节点保留卡片感。
- 二级及以下节点改成更轻的缩进列表项。
- 子树区域增加浅色引导线，形成明显树结构。

优点：

- 能保留当前页面已有的圆角、玻璃面板风格。
- 父节点像“章节分组”，子节点像“章节内部目录”，结构最清楚。
- 改动集中在节点渲染函数，风险可控。

缺点：

- 相比纯列表结构，样式实现略复杂。

### 方案 B：全树列表型

- 所有节点都变成统一列表行。
- 主要通过缩进、连接线、状态点区分层级。

优点：

- 最简洁、最像传统树控件。

缺点：

- 会明显偏离当前页面已有的卡片式视觉语言。

### 方案 C：全卡片型优化

- 所有层级继续使用卡片。
- 通过不同尺寸、不同缩进和更轻子卡片来区分层级。

优点：

- 改动最小。

缺点：

- 层级清晰度仍然不如方案 A。

结论：采用方案 A。

## 4. 最终视觉设计

### 4.1 层级结构

- 根节点：保留一张主卡片，作为当前课程结构入口。
- 一级节点：使用中等卡片，展示章节或主要知识分组。
- 二级及以下节点：改为轻量列表项，不再使用完整大卡片。
- 子节点整体相对父节点向内缩进，并通过浅色竖向引导线串联。

### 4.2 信息结构

每个节点只保留以下信息：

- 节点类型：低权重 pill，例如 `章节` / `节点` / `小节`
- 节点标题：主信息，作为主要视觉焦点
- 辅助说明：仅在 `summary` 与 `label` 明显不同且有补充信息时显示

以下信息删除：

- 与标题重复的第二行节点名
- 对结构理解没有帮助的重复摘要

### 4.3 视觉权重

- 标题：深色、粗体，作为主视觉。
- 类型标签：保留但降权，尺寸更小、颜色更浅。
- 摘要：更小字号与更淡颜色，只作为辅助。
- 展开按钮：固定在左侧，仅承担展开收起含义，不与正文抢主次。

### 4.4 状态设计

- 选中节点：
  - 浅蓝底
  - 深蓝标题
  - 左侧强调条
  - 更清晰的边框
- 父链节点：
  - 比普通节点略亮
  - 帮助用户理解当前节点属于哪条学习路径
- 普通节点：
  - 白底或极浅灰蓝底
  - hover 轻微提亮，不抢选中态

## 5. 关键布局规则

### 5.1 缩进

- 一级节点：`0px`
- 二级节点：`18px`
- 三级节点：`36px`
- 更深层级继续按固定步长递增

### 5.2 容器形态

- 一级卡片圆角：`18-20px`
- 子节点列表项圆角：`12-14px`
- 一级节点之间间距：`12px`
- 子节点之间间距：`6-8px`

### 5.3 文本节奏

- 一级节点标题：`16-18px`
- 子节点标题：`14-15px`
- 辅助说明：`12px`

## 6. 交互设计

### 6.1 展开与选中

- 点击左侧箭头按钮：只负责展开/收起。
- 点击节点正文区域：负责选中并联动右侧课程资源。

### 6.2 动画

- 展开/收起使用轻量高度 + 透明度过渡。
- 时长控制在 `160-220ms`。
- 不使用弹跳或复杂运动，保持稳重清晰。

### 6.3 可读性

- 展开后，父节点下方出现带竖线的内收子树。
- 子节点不再继续平铺成同宽大卡片，从结构上避免“同级错觉”。

## 7. 前端实现范围

本次实现仅修改 `frontend/src/stitch/pages/VideoPlayer.tsx` 中的知识树渲染逻辑与样式，主要包括：

- 重构 `renderStructureNode`
- 引入按层级差异化的节点容器
- 增加子树引导线与缩进规则
- 增加“是否显示辅助说明”的判断，去掉重复标题文案
- 优化选中态、父链态与 hover 态的样式权重

不包含：

- 后端知识图谱数据结构改动
- 课程资源数据联动逻辑改动
- 右侧课程内容区布局改动

## 8. 验证方式

实现完成后需要确认：

- 父节点与子节点存在明显缩进关系。
- 展开后用户能立即看出子节点归属。
- 标题重复内容不再出现。
- 选中节点明显、未选中节点安静。
- 原有展开/收起与知识点选择联动不回归。

建议增加前端回归测试，锁定：

- 节点层级差异化容器存在
- 子树引导线存在
- 重复摘要被过滤
- 选中节点样式分支仍然保留

## 9. 风险与控制

### 风险

- 样式改动集中在递归渲染函数，容易影响多层级节点显示一致性。
- 如果摘要过滤条件过于激进，可能误删有价值说明。

### 控制方式

- 保持数据结构与事件处理逻辑不变，仅调整展示结构。
- 辅助说明只在“确实不同于标题”时隐藏，避免误伤。
- 用前端文本匹配测试锁定关键层级与状态分支。
