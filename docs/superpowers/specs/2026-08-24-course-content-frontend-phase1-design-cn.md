# 课程内容体系前端收口（阶段一）设计

**日期：** 2026-08-24

**状态：** 已确认，可进入实施

**阶段定位：** 今天先完成不依赖数据库迁移的双端前端调整；课程标准资源、批量生成、审核发布、任务资源快照和学习证据增强等数据库相关能力，在明天导入真实 PostgreSQL 数据及文件目录并完成核验后进入阶段二。

## 1. 背景

现有“课程知识”同时展示“知识图谱”和“课程知识库”。课程知识库本身已经按照课程结构组织资料，独立图谱画布与其功能重叠，并且学生端复用同一页面。后端知识结构仍被文档作用域、知识点资源、学习任务、测评分析和后续分层 RAG 使用，因此本阶段只删除双端前端图谱页面和入口，不删除任何知识结构 API、数据库模型或作用域语义。

原“课程资源”同时混合个人生成资源与课程共享副本。已经确认的新产品边界是：

- 课程标准资源以后由课程知识库按叶子知识点承载；
- 用户生成内容统一归入“个人资源”；
- 教师需要把个人内容发给学生时，通过学习任务发布；
- 旧课程共享副本不在本阶段清理，等明天导入真实数据库后核对个人原件、任务引用和文件完整性再制定迁移规则。

右下角主题按钮目前以固定悬浮方式出现，并使用映射为齿轮的 `manage_accounts` 图标，容易被理解为系统设置。本阶段把外观选择收进个人中心，并改用调色盘语义。

## 2. 目标

1. 教师端和学生端不再出现知识图谱标签、图谱画布或默认进入图谱的行为。
2. 双端“课程知识”直接呈现现有课程知识库文档视图。
3. 教师端历史 `#graph` 链接安全重定向到课程知识库，避免书签或旧入口失效。
4. 原“课程资源”在双端统一改名为“个人资源”，页面默认且仅展示当前用户的个人生成资源。
5. AI课堂双端入口和个人/课程列表继续保留；它与个人资源共用同一资源记录，不复制数据。
6. 移除全局右下角主题悬浮按钮，在个人中心增加“外观设置”，保留现有主题持久化行为。
7. 所有修改不新增数据库表、不运行数据迁移、不修改后端业务接口。

## 3. 非目标

本阶段不实现：

1. 删除或修改后端知识结构、知识点作用域、知识图版本或相关接口。
2. 课程知识库中的标准学习资源卡片、叶子知识点批量生成、审核发布和覆盖率。
3. `origin_type`、`review_status`、生成批次、任务资源快照或学习任务类型等数据库字段。
4. 旧课程共享副本的删除、归档或所有者修复。
5. 本地文件目录、PostgreSQL、课程文件和向量索引的正式迁移。
6. 分层 RAG 或 Agentic RAG；该能力按用户要求放到最后实施。
7. 删除或重构 AI课堂页面。

## 4. 已确认的产品决策

### 4.1 课程知识入口

- `CourseKnowledgePage` 不再维护 `structure/documents` 标签状态。
- 页面直接渲染 `KnowledgeDocumentsView`。
- 教师端仍向 `KnowledgeDocumentsView` 提供编辑能力；学生端继续传入只读语义。
- 前端不再加载 `KnowledgeStructureView`，但后端图结构数据保持不变。
- 双端构建课程知识链接时不再主动附加 `view=structure`。
- 对历史 `view=structure` 参数采取兼容忽略：仍展示课程知识库，不报错，不保留图谱入口。

### 4.2 历史图谱路由

- 教师历史路由 `#graph?course_id=...` 暂时保留在路由解析器中作为兼容别名。
- `LegacyKnowledgeGraphRedirect` 改为跳转到 `#knowledge?course_id=...`，不再附加 `view=structure`。
- 新导航、按钮和页面不得继续生成 `#graph` 链接。
- 学生端没有独立 `graph` 路由；其 `student-course-knowledge` 直接展示课程知识库。

### 4.3 个人资源页面

- 教师侧栏“课程资源”改为“个人资源”。
- 学生侧栏“资源管理”改为“个人资源”。
- 页面标题、空状态、提示文案统一使用“个人资源”。
- 课程概览与首页课程卡中的资源数量也按 `space=mine` 统计，并统一标注为“个人资源”，不得继续混入课程共享副本。
- 页面初始化只请求 `space=mine`，不再并行请求 `space=course`。
- 删除“我的资源/课程共享”空间切换和课程共享数量。
- 删除发布到课程共享、更新课程共享、从课程共享撤回等主界面操作。
- 保留个人资源的搜索、类型筛选、排序、置顶、预览、重命名、内容编辑和删除。
- 历史深链接如果指向非本人私有资源，本阶段显示“该资源不在个人资源中或无权访问”，不得为了打开它恢复课程共享页。
- 内部路由键继续使用 `resources/student-resources`，避免无意义的路由迁移。

### 4.4 AI课堂兼容

- 教师端“AI课堂”和学生端“AI课堂”侧栏入口保留。
- AI课堂继续维护自己的个人/课程列表。
- 个人资源页中的 AI课堂只是同一资源的聚合视图；点击后沿用现有打开目标进入 AI课堂播放或编辑能力。
- 本阶段不改变 AI课堂接口、存储或发布逻辑。

### 4.5 外观设置

- 删除 `App` 根组件中的全局 `ThemeCustomizer` 悬浮挂载，避免右下角齿轮常驻。
- 个人中心增加“外观设置”卡片，展示海蓝、森绿、日落、暗色四个主题。
- 主题选项使用颜色样本、名称和简短说明；当前选项具有可感知的选中状态。
- 图标语义使用 `palette`。`MaterialIcon` 字形映射增加调色盘字形，不再以 `manage_accounts` 表示主题。
- 继续通过 `AppShellContext` 的 `theme/setTheme` 更新主题，继续使用现有 `stitch-theme` 本地存储；不调用后端。
- 教师、学生和管理员均通过共享个人中心访问外观设置。
- 主题选项必须支持键盘焦点，颜色不能作为唯一选中标识。

## 5. 页面行为与数据流

### 5.1 课程知识

```text
教师/学生点击“课程知识”
→ 角色路由携带 course_id
→ CourseKnowledgePage 直接渲染 KnowledgeDocumentsView
→ 教师根据现有权限管理资料
→ 学生以 readOnly 模式浏览资料
```

页面不创建任何图谱请求，也不渲染图谱画布。课程知识库内部如果使用后端知识点结构组织文档，仍沿用现有实现。

### 5.2 个人资源

```text
用户进入“个人资源”
→ 请求 GET course materials(space=mine)
→ 前端按现有类型、关键词、置顶和排序展示
→ 用户预览或维护自己的资源
```

本阶段不请求 `space=course`。任何发布/撤回能力只从此页面移除，不删除后端接口，避免在明天核对旧数据前破坏兼容性。

### 5.3 主题

```text
用户进入个人中心
→ 选择外观主题
→ setTheme 更新 AppShell 状态
→ App 写入 localStorage 并设置 documentElement.dataset.theme
→ 全局样式即时切换
```

## 7. 兼容性与错误处理

1. 历史 `#graph` 教师链接必须稳定跳转到课程知识库。
2. 历史 `view=structure` 或未知 `view` 参数不得导致空白页。
3. 个人资源加载失败沿用现有可重试错误状态；不得回退到课程共享数据。
4. 个人资源深链接指向课程共享副本时显示明确无权/不属于个人资源提示。
5. 主题本地存储值非法时继续回落到 `ocean`。
6. 不因移除悬浮主题入口而清空现有 `stitch-theme`，用户原主题应继续生效。
7. AI课堂的 `mine/course` 空间行为保持现状，避免将个人资源页的收口误扩散到 AI课堂。

## 9. 阶段一验收边界

只有同时满足以下条件，才能宣称今天的无数据库阶段完成：

1. 双端课程知识页面均无知识图谱并可正常浏览课程知识库。
2. 后端知识结构相关代码和接口未被删除或修改。
3. 双端导航和页面统一使用“个人资源”。
4. 个人资源页只展示当前用户资源，且核心个人资源操作无回归。
5. AI课堂双端入口和现有个人/课程列表无回归。
6. 右下角齿轮主题按钮消失，个人中心能够切换四种主题。
7. 前端测试、类型检查和构建通过。
8. 工作树中没有数据库、迁移、存储目录或密钥的意外改动。

## 10. 阶段二接口边界（明天）

明天导入真实数据库、`storage`、`course_data` 和向量索引后，先完成只读核验，再单独设计和实施：

1. 旧课程共享副本与教师个人原件的映射及安全清理。
2. `origin_type`、审核状态和生成批次等模型及 Alembic 迁移。
3. 仅对叶子知识点生成 AI课堂、学习讲义和练习测评。
4. 单项审核、批量通过、版本替换和失败项重试。
5. 课程知识库的标准学习资源区域及学生发布视图。
6. `reading/assessed` 两类学习任务和个人资源任务快照。
7. `self_reported/activity_evidenced/assessment_verified` 完成证据展示。
8. 教师端学习进度与知识点掌握分析。
