# 模拟实验与 PBL 实现及进度汇报

更新日期：2026 年 10 月 14 日

**1. 当前采用的两条技术路线**

项目的互动实践分为模拟实验和 PBL 编程练习，两者分别实现：

- **模拟实验：** 接入 THU-MAIC/MAIC-UI 的科学建模与可视化生成提示词，由大模型生成能够直接运行的实验网页，学生通过调整参数观察变化。
- **PBL 编程练习：** 使用 CodeSandbox Sandpack 提供代码编辑和预览环境，由本项目生成练习材料、组织代码执行和测试，学生亲自完成算法。

目前模拟实验已上线，PBL 首版已完成开发及独立环境验证，正式环境接入尚未完成。两条路线共用平台的模型服务、用户管理和后台任务能力，实验内容的生成和运行则分别实现。

**2. MAIC-UI 如何将一个主题变成模拟实验**

MAIC-UI 在当前项目中提供的核心能力，是通过两阶段提示词，让大模型先整理实验规则，再把规则实现为交互网页。本项目实际复用了它的“科学建模提示词”和“可视化生成提示词”，模型调用、实验步骤设计、运行检查和学习记录由本项目接入。

以已经生成的“摩擦力与小车滑行距离”实验为例，生成过程如下：

- **第一步，设计实验任务。** 用户输入主题后，系统先调用大模型，生成知识点介绍、学习目标、交互设计和 3—5 个操作步骤。例如，先观察小车滑行，再改变初速度，随后改变摩擦系数，比较停车距离。
- **第二步，利用 MAIC-UI 提示词整理计算规则。** 系统把上述设计交给科学建模提示词，要求模型输出核心公式、运动机制、适用条件和需要避免的错误。对这个实验，需要明确摩擦造成减速、速度如何随时间变化、什么时候停止，以及停车距离如何计算。这里的产物是一份结构化的规则说明。
- **第三步，把规则交给网页生成提示词。** MAIC-UI 的可视化生成提示词同时接收实验设计和规则说明，要求模型生成完整网页，并要求网页中的 JavaScript 计算遵守这些规则。本项目进一步规定：页面必须包含可调参数、运行和重置按钮，使用原生网页技术和 Canvas／SVG 绘图，参数必须参与计算，计算结果必须上报给平台。
- **第四步，得到可执行的实验页面。** 最终产物包含三部分：HTML 放置滑块、按钮和结果区域；CSS 控制布局和样式；JavaScript 实现公式计算、操作响应和动画绘制。生成完成后，平台保存这份网页，供学生反复打开和操作。

正常生成包含“实验设计、科学建模、网页生成”三次模型调用；检查失败时，还会追加修复调用。实际使用的是本平台配置的大模型，MAIC-UI 提供的是组织生成任务的提示词模块。

**3. 生成后的实验具体怎样运行**

仍以小车滑行为例，实际生成的页面提供“初速度”和“摩擦系数”两个滑块，以及开始、暂停和重置按钮。

在水平面、摩擦系数恒定的简化模型下，学生点击开始后，浏览器根据当前参数计算：

- 加速度：a = −μg。
- 停止前的速度：v = v₀ − μgt。
- 停止前的位移：s = v₀t − ½μgt²。
- 摩擦系数大于零时的停车距离：s停 = v₀² ÷（2μg）。

其中，v₀ 为初速度，μ 为摩擦系数，g 取 9.8 m/s²。网页程序随着时间推进，不断更新速度和位移，再用 Canvas 重画小车位置、速度曲线和数值结果。到达停止条件后结束运动；摩擦系数为零时，单独按匀速运动处理。学生改变参数时，程序重新计算并更新显示。

因此，**动画是由网页中的计算结果驱动的，实验运行阶段由浏览器执行。** 大模型主要参与前面的设计和网页生成，以及后面的答疑。

已经核对的实际结果包括：

- 摩擦系数保持 0.2，初速度为 4 m/s 时，停车距离约为 4.082 m。
- 摩擦系数保持 0.2，初速度改为 8 m/s 时，停车距离约为 16.327 m，是前者的四倍。
- 初速度保持 4 m/s，摩擦系数改为 0.4 时，停车距离约为 2.041 m，是第一组的一半。

这三组结果与公式一致。快速排序实验采用同样的生成方式，但网页中执行的是排序算法，展示的是数组变化、比较和交换等过程。

**4. 本项目如何检查实验并支持 AI 答疑**

生成的网页会先进入自动化浏览器检查。系统实际加载页面、调整控件并点击运行，检查是否出现脚本错误、是否有初始结果、操作后结果是否变化，以及重置和页面布局是否正常。检查失败后，会把原页面和具体问题一起交给模型，当前支持一次自动修复；再次不通过则不交付。

学生使用时，实验在页面内的隔离窗口中运行。本项目为其加入了状态上报机制：实验程序提交计算结果，平台同时读取控件参数，从而获得当前实验状态。

例如，学生问“为什么初速度翻倍，距离变成四倍”，AI 接收到的内容包括当前初速度、摩擦系数、停车距离、所在实验步骤和最近保存的观察，因此可以结合本次结果解释，并建议下一组验证参数。

目前已实现实验生成、交互操作、状态问答和观察保存，快速排序样例已在线成功交付。实验页面采用左侧步骤、中间操作、右侧问答的布局。保存的观察和对话可以再次查看，重新打开实验时从初始参数开始，不恢复运行中的动画。

“识别一轮操作结束后主动发起教学引导”尚未接入。自动浏览器检查主要证明页面可运行，公式正确性仍需单独核验。

**5. PBL 的实现方式与当前进度**

PBL 当前以 JavaScript 快速排序为首个完整任务，使用 Sandpack 提供网页内的代码编辑器和预览环境。

其实现流程如下：

- **生成练习材料。** 模型生成任务说明、教程、提示、待补全代码和测试用例，同时生成一份仅用于内部校验的参考实现。
- **验证材料。** 平台核对用例的预期结果，并实际运行参考实现，验证材料后再交给学生。参考实现不会放入学生的初始代码中。
- **编辑和执行。** 学生在 Sandpack 编辑器中补全算法，点击运行或检查后，系统固定当时的代码版本，在浏览器独立执行线程中运行。
- **检查并反馈。** 平台展示实际输出、预期输出、错误或超时信息，并检查重复元素、空数组、原数组是否被修改等情况。
- **保存和恢复。** 学生代码与检查记录分别保存，支持刷新后继续。代码修改后，需要重新检查，旧报告不能代表新版本正确。

Sandpack 负责编辑和预览基础环境；练习生成、测试逻辑、执行控制、代码保存和检查记录由本项目实现。当前已经验证了错误代码检查、修正后通过、死循环停止、刷新恢复和多标签编辑冲突处理。

首版目前只支持 JavaScript 快速排序单任务，尚未接入 AI 辅导和多阶段项目。前端已提供实践方式选择，后端加载、生产数据库迁移及正式环境复验仍待完成。现阶段测试通过表示当前代码满足已检查的功能要求，不能直接证明其采用了指定算法或学生已经掌握相关知识。

**6. 下一步具体安排**

- **先补齐实验操作的完成条件。** 例如，快速排序以本轮排序结束和统计结果产生作为结束证据，小车实验以小车停止并形成最终测量结果作为结束证据；对于不会自然停止的情形，另设明确的采样条件，避免把一次点击或拖动直接视为完成。
- **再接入教学 Skills。** 将教学引导组织成可复用的流程：学生完成有效操作后，读取本轮参数和结果，与此前记录比较，提出一个具体问题。例如：“初速度翻倍后距离变为四倍，你认为它们是什么关系？”随后根据学生回答给出解释或建议再次验证。
- **补充计算正确性检查。** 从摩擦力、排序等已有样例开始，增加边界参数和对照结果检查，逐步提高实验生成的可靠性。
- **完成 PBL 上线验证。** 先确认正式环境中的生成、运行、检查和保存恢复稳定，再基于学生代码及失败用例增加针对性辅导，并扩展其他算法任务。
