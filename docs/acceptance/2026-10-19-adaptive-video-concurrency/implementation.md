## 修改

- 每课资源上限保持 8，视频默认上限 8。首节视频优先，其后报告/习题优先；按本次范围未完成轻资源数量保留最多 2 个名额，排队中和运行中也计入。报告、习题结束后可用全部 8 个名额。局部重试不提交其他节点。
- 主服务新增 2 个轻资源专用执行线程，原有 3+5 个通用线程及 2 个调度线程保留。SQLite 与 PostgreSQL 在原子领取之前过滤任务类型；补充 worker 明确排除 preparation_step，避免调度再次占用通用生成线程；新资源及审阅恢复任务写入 resource_type，旧任务命令仍可读取。旧无类型标记任务继续由通用线程执行。
- 场景每视频 6 路，同机所有进程合计 16；渲染同机最多 4 个任务，每任务 4 worker，默认低于 2 GiB 可用内存时等待。
- 同凭据配音同机最多 8 路（同账号多个 key 可设置相同 TTS_REMOTE_LIMIT_GROUP），默认每秒启动 4 个合成请求。HTTP 429 共享冷却，遵守 Retry-After、指数退避和抖动，最多 4 次尝试。等待不占合成名额；取消可中止等待。下载请求不占合成配额。
- 阶段配额使用 Linux flock，所有进程必须共享 EDU_STAGE_LIMIT_DIR；默认 `/tmp/edu-ai-stage-limits-UID`。异常退出由内核释放，渲染进程继承锁描述符。跨机器部署需要将配音账号限流迁移到共享服务；目前不是集群全局配额。
- 原生 render_project、宿主 CLI shim、Node 原生 CLI 预加载入口及独立 NativeRuntime.render 接入渲染配额。完整上游仓库未修改。
- 习题审阅输出绑定原文的 calculation_checks，采用 source_field 与片段起止编号由服务端回填原文，避免模型抄写公式造成格式重试；受限 AST 计算器支持标量/向量/矩阵运算、softmax、矩阵乘法、转置等。数值错误不能被模型 pass 覆盖；解析中的直接 softmax 数值还通过独立窄语法抽取。保留具体复算证据；不声称穷尽任意自然语言数学断言。
- 新场景 HTML 写入时检查数字 ID 直接用于 CSS/GSAP 选择器的问题；允许逐步修复旧文件。壳命令写文件仍由原生集中检查兜底。课程简报增加统一字体/字号/配色建议，用户显式风格及既有修订设计优先。
- 记录加载时构建指纹、PID、配置及续跑历史；无法追溯的旧工程明确标记 unrecorded。此前 v1/v2 工程沿用原身份和讲稿，不因新增视觉建议重做。
