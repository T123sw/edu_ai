## 数组的内存布局：连续存储

数组是编程中最基础的数据结构之一，其核心特征在于内存布局的连续性与规则性。当我们声明一个数组时，系统会在内存中分配一块连续的区域来存放所有元素。这里的“连续”意味着元素之间没有任何间隙或空洞，第一个元素的地址紧跟着第二个元素，第二个紧跟着第三个，以此类推。这种布局方式与散落在内存各处的独立变量形成鲜明对比。

每个元素占用相同大小的内存空间，这是由数组的“同质”特性决定的——数组中的所有元素必须具有相同的数据类型。例如，一个`int`数组中的每个元素都恰好占用4字节（在大多数32位或64位系统上），一个`char`数组中的每个元素都恰好占用1字节。元素大小的一致性使得地址计算变得极其简单和可预测：如果我们知道数组的起始地址和元素大小，就能精确推算出任意元素的位置，而无需存储额外的指针或元数据。

这种连续存储的设计并非偶然。它带来了两个直接好处：一是内存利用率高，没有碎片化的管理开销；二是访问速度快，因为现代CPU对连续内存的读取有缓存优化的天然优势。理解这一布局是掌握数组一切操作的基础。

## 索引访问：从0开始的偏移计算

数组索引从0开始，这是许多初学者感到困惑的设计选择，但其背后有着深刻的工程理由。索引本质上不是元素的“编号”，而是元素相对于数组首元素的“偏移量”。第一个元素的偏移为0，第二个为1，第n个为n-1。这种设计直接映射到硬件的寻址方式，使得地址计算只需一次乘法和一次加法，无需额外的减1操作。

具体的地址计算公式为：**元素地址 = 起始地址 + 索引 × 元素大小**。以`double`数组为例，若起始地址为5000，每个`double`占8字节，则`b[3]`的地址为5000 + 3×8 = 5024。这个公式适用于所有数组访问，无论是读取还是写入。当程序执行`x = a[i]`时，编译器生成的机器代码会先计算上述地址，然后从该地址读取数据；执行`a[i] = value`时，则先计算地址再写入数据。

索引从0开始还有一个重要的安全含义：合法的索引范围是0到长度减1。访问`a[5]`（当数组长度为5时）意味着访问起始地址偏移5个元素大小的位置，这已经超出了数组的分配范围，属于越界访问。越界访问不会触发语言层面的错误提示，而是直接操作了相邻内存区域，可能导致程序崩溃或产生难以追踪的逻辑错误——这正是C语言中许多安全漏洞的根源。

## 固定大小与读写操作

数组的大小在创建时就必须确定，并且在程序的整个生命周期中不可改变。这一特性源于数组的内存分配方式：系统在创建数组时一次性分配整块连续内存，而这块内存的大小无法在运行时动态调整。例如，声明`int scores[3]`后，系统分配12字节（3×4字节），此后无论程序如何运行，这12字节的边界都不会变化。

读写操作通过索引直接进行，时间复杂度为O(1)——即无论数组有多大，访问任意一个元素所需的时间都是恒定的。写操作如`scores[0] = 90`，读操作如`int x = scores[1]`。这种高效性正是数组的核心优势：我们不需要遍历数组来查找元素，只需一次地址计算即可直达目标。

然而，固定大小也是一把双刃剑。如果程序员在运行时发现需要更多空间，数组本身无法扩展。此时只能声明一个更大的新数组并复制旧数据，或者改用其他支持动态扩容的数据结构（如链表或动态数组，但不在本报告讨论范围内）。此外，由于大小固定，程序员必须自行确保索引不越界——语言本身不会提供保护。写入越界索引（如`scores[3]`当大小为3时）会覆盖数组之外的内存，可能破坏其他变量的值，这种错误在大型程序中极难排查。理解数组的固定性，是安全使用数组的前提。
