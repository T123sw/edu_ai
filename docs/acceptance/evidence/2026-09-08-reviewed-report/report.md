## 递归的出口：基线条件必须覆盖输入域的最小值

递归函数必须包含基线条件（base case），当输入满足该条件时直接返回结果，不再进行递归调用。对于输入域为自然数（含0）的阶乘函数 `factorial(n)`，基线条件必须覆盖输入域的最小值0。具体实现如下：

```python
def factorial(n):
    # 输入域：n 为非负整数（n ≥ 0）
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

当 `n=3` 时，调用链为 `factorial(3) → factorial(2) → factorial(1) → factorial(0)`，最终在 `n=0` 处直接返回1，递归正确终止。

初学者常犯的错误是将基线误写为 `if n == 1: return 1`。此时若调用 `factorial(0)`，由于 `n` 不等于1，函数会继续递归调用 `factorial(-1)`。而 `-1` 不在输入域（自然数含0）内，从数学角度看，这构成了无限递归——函数永远不会命中任何基线条件。在实际的Python运行中，这种无限递归会因调用栈不断增长而最终抛出 `RecursionError` 异常，而非真正永远运行下去。

基线可达性指：输入域内的所有值经过有限次递归后必须能命中某个基线条件。基线缺失或与输入域不匹配，都会导致递归无法终止。检查基线可达性的实用方法是手动模拟输入域的最小值：列出输入域的最小值（如0），验证该值是否直接命中基线条件。若不能直接返回，则说明基线条件未覆盖全部输入域，需要修正。

## 规模递减：每次递归调用必须严格向基线靠近

在本报告讨论的非负整数递归中，递归调用的参数必须在每次调用时严格减小1，确保函数向基线条件单调逼近。以倒计时函数 `countdown(n)` 为例，其输入域为 `n ≥ 0`，实现如下：

```python
def countdown(n):
    # 输入域：n 为非负整数（n ≥ 0）
    if n == 0:
        print(0)
        return
    print(n)
    countdown(n - 1)
```

当 `n=2` 时，调用序列为 `2 → 1 → 0`，到达基线 `if n == 0` 后停止。这里每次递归调用都将参数从 `n` 变为 `n-1`，即严格减少1。

常见的错误写法包括 `countdown(n)`（参数不变）和 `countdown(n+1)`（参数增大）。前者会导致无限递归——每次调用都处理相同的 `n`，永远无法到达基线；后者使参数远离基线0，同样无法终止。这两种错误都违反了本报告所讨论的规模递减原则：对于非负整数输入，递归调用的参数必须比当前值小，且每次至少减少1。

需要澄清的是：在下降递归过程中，调用栈的深度实际上是随每次调用而增加的（从 `countdown(2)` 到 `countdown(1)` 再到 `countdown(0)`，栈中累积了3个帧）。真正减少的是问题规模——即到达基线所需的剩余步数。`countdown(2)` 还需2步到达基线，`countdown(1)` 还需1步，`countdown(0)` 则0步到达。

验证规模递减的方法是观察递归语句的参数表达式，并写出 `n=1` 时的调用链。若递归调用为 `countdown(n-1)`，则 `n=1` 时调用 `countdown(0)`，能直接命中基线，证明递减方向正确。

## 下界与输入域一致：终止条件必须显式处理最小值

非负整数的下界为0，基线条件必须显式处理这一下界。阶乘函数 `factorial(n)` 的输入域为 `n ≥ 0`，基线 `if n == 0: return 1` 明确覆盖了下界。递归调用 `factorial(n-1)` 在 `n=1` 时调用 `factorial(0)`，恰好到达下界并终止，不会产生负数参数。

然而，仅保证参数严格递减且基线覆盖0，并不足以确保终止。递归调用还必须保持参数在合法输入域内，且不跳过基线。例如，若将递归调用改为 `factorial(n-2)`，基线仍为 `if n == 0: return 1`，则当 `n=1` 时调用 `factorial(-1)`，`-1` 不在输入域内；当 `n=3` 时调用链为 `3 → 1 → -1`，同样越过下界。即使对于奇数输入 `n=5`，调用链为 `5 → 3 → 1 → -1`，也永远无法命中基线0。这说明：递归调用必须保证每次减少的量恰好能落在基线上，不能跳过。

递减过程不能越过下界。若从0减到-1，则 `-1` 不在输入域内，导致无限递归。例如，将阶乘基线误写为 `if n == 1: return 1`，递归调用仍为 `factorial(n-1)`，当 `n=0` 时调用 `factorial(-1)`。虽然参数在递减，但越过了下界0，且 `-1` 永远不等于1，函数无法终止。这一误区说明：仅保证参数递减并不足够，还必须确认递减过程终止于输入域的下界，且该下界被基线条件显式处理。

检查方法是对输入域最小值0运行函数，确认其直接返回。若不能，则需检查递归调用是否会产生小于0的参数，并相应调整基线条件或递归逻辑。下界与基线条件的一致性是递归终止的保证，它确保所有递归路径最终都落在输入域内，不会产生非法参数。对于非负整数输入，只要满足以下三个条件，终止性就能得到保证：（1）基线覆盖输入域最小值0；（2）每次递归调用的参数严格减少1；（3）递归调用不会产生小于0的参数。
