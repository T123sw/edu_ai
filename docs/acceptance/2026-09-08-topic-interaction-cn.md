# 教学助手对话与知识点自动定位修复

用户反馈：普通知识提问被能力清单打断；明确说“数组的实现”后仍被要求自行选择知识点。

## 修改

- 根角色和报告 Skill 区分知识解释、备课讨论、明确报告请求。直接提供相应教学内容；不在开头或结尾主动展示能力、技术名词和服务菜单，不擅自恢复历史报告。
- 工作区解析从只处理生成扩展到普通对话与备课。匹配课程节点名称、配置别名和合并节点中的概念；“数组”“数组的实现”可定位“数组与链表”。明确换题时优先新主题，同名节点无法唯一定位时仍保留澄清。
- 已识别的范围随回复返回并记录到对话状态，下一轮由前端发送该范围。根角色同时接收可信工作区标题与路径。
- 自动更新顶部“当前讨论范围”时保留当前消息、会话 ID 和检索开关，释放回复中的输入锁；“调整”仅由用户主动打开。手动切换仍保留原有隔离和迟到回复保护。
- 内容组织和大纲工具保留“数组的实现”等子主题，不因课程目录合并而扩大成“数组与链表”。

## 验证与边界

- 隔离数据的后端 123 项回归通过，覆盖普通提问、备课、报告请求、同名节点澄清、跨用户/课程隔离与报告主题保持。
- 浏览器 knowledge-context 六项用例通过，包括自动切换后第二条消息沿用会话 ID、旧消息保留、检索开关不变，以及手动切换隔离。
- 前端生产构建通过。
- 真实主系统 DeepSeek 调用：数组随机访问问题直接解释；数组备课直接提供教学目标、先修、重难点与课堂安排；均定位 array-linked-list，无知识点选择阻塞。回复样本见 evidence/2026-09-08-topic-interaction/teaching-dialogue.json。
- 识别基于当前课程目录与别名，并非任意自然语言语义匹配；歧义不随机选节点。模型风格通过提示约束，本轮实测通过不代表所有输入都保证一致。

- 截图原句“帮我生成一份有关于数组的实现的报告”已通过主系统实测：自动定位 array-linked-list，调用内容组织和大纲工具，保存“数组的实现”大纲并进入正常确认步骤，无知识点选择阻塞。未在此次交互回归中提交正文。
- 实测还发现原生 Harness 的 6000 token 上限会使报告回合在加载 Skill 后截断；已增至 16000，并成功完成上述复测。
