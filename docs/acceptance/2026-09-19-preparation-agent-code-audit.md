## 1. 当前真实流程与 Harness 边界

装配入口：[pipeline.py](../../backend/src/app/course_preparation/pipeline.py)。最外层是持久化的 `PreparationRunner` 阶段状态机，并非一个贯穿所有阶段的 Harness 会话。

| 环节 | 实际实现与输出 | 原生 Harness / Skills 状态 |
| --- | --- | --- |
| 接收输入 | API 接收 goal、上传版本、来源限制、覆盖参数；校验身份、权限、请求幂等性 | 确定性服务逻辑 |
| 文件解析 | MinerU 支持的格式交给 MinerU；文本文件 UTF-8；按内容哈希缓存解析结果 | 普通工具适配器，不需要模型执行解析 |
| 文件理解 | `normalize` 先按 12,000 字符分块分析附件；保存用途、要点、引用、缺口 | 原生 Harness，`understand-learning-request` |
| 需求理解与记忆 | 读取全局/课程记忆，生成 brief：学习基础、目标、需求 ID、时长、限制等；记忆版本绑定消费者 | 需求理解使用同一 Skill 的独立会话；记忆读取/失效检查是程序逻辑 |
| 材料登记 | `ingest` 登记来源候选与解析回执，复用缓存，不再次调用 MinerU | 确定性阶段 |
| 检索、阅读、整合、路径草案 | 上传正文与网页正文 → 引文/结论 → 需求覆盖表 → 有先修关系、活动、自测的路径 | `build-learning-path` 在一个连续原生 Harness 会话中执行工具 |
| 独立路径审阅 | 校验需求、证据、时长、顺序；必要时退回研究/规划 | `review-learning-path`，独立 Harness 会话 |
| 节点依据检查 | 每个节点检查教学目标、活动、自测是否有充分证据；输出 `node_evidence` | 同一审阅 Skill，逐节点独立会话 |
| 资源清单 | `produce` 创建 `resource_specs`，目前统一节点 × 资源类型 | Python 固定规则，没有独立资源规划 Skill |
| 资源生成与单资源审阅 | 耐久子任务生成报告、习题、课堂，保存带摘要校验的私有草稿 | `GenerationGateway` 直接请求模型，没有运行原生 Harness SDK |
| 节点/整课验收 | 每个节点读取完整资源正文审阅，再根据节点审阅摘要做整课检查 | `course_review` 未列入 `PHASE_SKILLS`，回退普通模型适配器 |
| 局部修复 | 找出受影响资源，规格 revision + 1，最多两轮，再生成/审阅 | Python 状态机 + 上述普通生成流程 |
| 提交与学习端衔接 | 单事务保存材料、不可变 manifest、当前指针、事件及成功状态；学习端按确切版本读取 | 确定性事务，不应让模型代替事务控制 |

依据：[workflow_skills.py](../../backend/src/app/course_preparation/workflow_skills.py:7)、[harness_adapter.py](../../backend/src/app/course_preparation/harness_adapter.py:66)、[generation.py](../../backend/src/app/course_preparation/adapters/generation.py:82)、[generation_gateway.py](../../backend/src/app/course_preparation/generation_gateway.py:18)、[quality.py](../../backend/src/app/course_preparation/quality.py:141)。目录名包含 `harness`、调用 DeepSeek 模型或使用 `harness_execution_context` 字段，都不等于已经运行 Harness SDK。

这次完整真实测试共 34 次模型调用：16 次记录为 `deepseek-harness`，18 次是普通调用，和上述代码边界一致。

## 2. 已确认的问题，按优先级排列

### P1：规划信息在资源生成入口丢失，已经影响最终内容

路径包含 `learning_activities`、先修关系和需求映射；`ResourceSpec` 没有承接完整教学活动、逐项用户约束、有效偏好内容。虽然保留了记忆引用用于失效校验，但生成 payload 没有接收偏好值和完整节点教案。

同时，`automatic_payload()` 将所有报告固定成“概念与机制 → 案例与面试表达 → 学习检查”。这不仅是标题不好看，而是在覆盖上游教学设计。

**真实反例：**用户要求“先用 12 加 30 的例子，再解释原理”，路径第一项也明确写“报告：先用……成功例演示完整流程”。最终报告却从概念讲起，第二节加入用户未要求的面试话术；节点、整课审阅仍然通过。

依据：[ResourceSpec](../../backend/src/app/course_preparation/generation_contracts.py:6)、[规格构建](../../backend/src/app/course_preparation/production_stages.py:48)、[固定章节](../../backend/src/app/course_preparation/adapters/generation.py:57)。完整反例含用户输入、路径、资源与通过回执，保存在 [quality-counterexamples.json](artifacts/2026-09-19-preparation-agent-audit/quality-counterexamples.json)。

### P1：资源清单是统一组合，没有逐节点规划及时间分配

创建课程默认给每个节点生成报告和习题；如果整体要求课堂，则每个节点都再生成课堂，默认都标记必学。各资源都收到完整的节点分钟数，没有分别安排阅读、观看、练习用时，也没有区分替代性讲解与必做活动。

真实样本为 20 分钟、两个节点，每个节点各 10 分钟：每节点生成报告、8/10 道习题、5/6 页课堂，三种资源都按本节点 10 分钟生成。代码没有证明它们能共同在 10 分钟内完成。

交付清单里又将每份资源关联到该节点全部目标，检查项只定位报告的“学习检查”章节，未将习题的具体题目建立为目标对应的练习检查。因此目前清单的“覆盖”主要是元数据覆盖，不能代表教学效果已验证。

依据：[production_stages.py](../../backend/src/app/course_preparation/production_stages.py:20)、[candidate_manifest](../../backend/src/app/course_preparation/quality.py:63)。

### P1：审阅通过仍会漏掉具体错误，不能作为唯一质量依据

本次已交付习题的第一题，选项 C 写“模型和程序都负责执行工具，只是先后顺序不同”，解析却说“选项 C 错误地认为程序也参与工具选择”。解析反驳的是选项没有说过的话，应该指出错误地让模型承担真实工具执行职责。该题经过逐选项审阅、节点审阅、整课审阅，仍然通过。

这证明当前“逐题独立求解＋逐选项核验”的提示虽然必要，却没有足够的稳定性证据。应把这个真实失败样本纳入验收集，要求解释引用并回应对应选项原文；用户要求的教学顺序也应输出可核验的资源位置，不能只输出总体 `pass`。

课堂最后一页直接显示答案并由旁白读出，没有作答暂停或用户响应判定。它可以作为复习提示，不能等同于已完成互动检测。

### P1：后半程没有统一到 Harness 与 Skills

需要补齐资源规划、资源生成、课堂设计、交付审阅的 Harness 能力入口。统一的是智能决策、上下文契约、工具调用和执行记录；已有队列、预算、权限、内容哈希、事务提交应继续由后端提供确定性保障。没有必要为了“都接入”而把 SQL 提交改成模型自由操作。

### P2：课堂实现限制了效果，现有完整生成能力尚未被备课链路复用

当前备课课堂采用 `TeachingScript`：2–6 页，每页标题、1–3 条要点、80–1000 字讲解；再转换成统一白底、两个文本框、一个 speech 动作。没有资源级分镜/版式规划，没有插图、过程图、交互题、仿真或预合成音频。审阅后的修复也只允许替换文字，不能改变场景结构。

本次两份真实课堂分别为 5 页/6 页、1192/1246 字旁白。主要事实和演示流程可用，但实际结构仍是静态文字投屏加讲解；没有真实播放计时或视觉渲染检查。

项目另一条课堂链路已有视觉规划 `_plan_classroom_visuals` 和 OpenMAIC sidecar 生成、TTS 配置。备课用的是单独的 `generate_classroom_draft`，并没有调用那条完整链路。不能把另一入口的能力、测试结果算作备课课堂已经具备。

依据：[classroom.py](../../backend/src/app/course_preparation/adapters/classroom.py:15)、[课堂文本修复](../../backend/src/app/chat/harness/reviewed_resource.py:312)、[另一条视觉规划链路](../../backend/src/app/services/platform_task_handlers.py:19)。

### P2：异常恢复有效，但故障分类和成本控制还不够精细

真实完整测试中，第二节点习题的审阅连续未覆盖全部选项，抛出 `quiz_review_option_coverage_incomplete`。子任务失败后，父流程进入 repair，新生成 revision 2 后交付成功，说明恢复链路确实工作。

但父流程收到的修复反馈只有 `RESOURCE_GENERATION_FAILED`，没有保留“审阅响应漏选项”的具体原因，最终重生成整份习题。对于这类情况，更合适的是保留正文、修复审阅响应；内容错了才修内容。这会减少时间和不必要的内容漂移。

依据：[异常转换](../../backend/src/app/course_preparation/adapters/generation.py:102)、[修复流程](../../backend/src/app/course_preparation/quality.py:171)。

### P2：共享报告工具仍有 3 项回归失败

`test_reviewed_report.py` 中三个适配/发布守卫测试使用 `harness_outline_id` 作为必须审阅的条件；当前实现改用 `review_policy=required` 或 `harness_review_required`。测试与运行契约未统一，分别落入普通报告生成分支或没有提前触发审阅守卫。

备课入口直接调用强制审阅的生成器，本次备课没有因此绕过审阅；但不能声称整个共享工具测试全部通过。应确认旧命令兼容要求，再修实现或测试，不能仅删除失败用例。

依据：[报告生成分支](../../backend/src/app/services/generation_task_handlers.py:227)、[发布守卫](../../backend/src/app/services/generation_task_handlers.py:819)、[失败日志](artifacts/2026-09-19-preparation-agent-audit/tools.log)。

## 4. 建议的逐节点资源规划

应在“节点依据通过”与 `produce` 之间增加明确的资源规划输出，由 Harness 加载资源规划 Skill 生成，程序校验后交给现有耐久队列执行。

每个节点的规划至少包含：

- 学习目标及先修关系、当前基础、约束和有效偏好。
- 本节点唯一的学习时间预算，具体活动分配，必学/选学及可替代关系。
- 每份资源的类型、用途、覆盖目标 ID、顺序、时间、题数/页数、内容组织、证据引用。
- 课堂的逐场景任务：讲什么、展示什么、学员做什么、何时停顿/反馈。
- 每个目标的检查方式、题目/场景位置和通过标准。

不要给所有节点机械生成所有资源。可按节点用途选择：

| 节点目标 | 建议核心资源 | 条件触发的补充 |
| --- | --- | --- |
| 理解概念 | 简明讲解＋概念辨析检查 | 关系复杂时补图解课堂；报告与课堂可作为替代入口 |
| 理解过程/机制 | 分步演示课堂＋追踪练习 | 报告作可检索参考，避免重复必学 |
| 实现操作/编程 | 有前提和验收步骤的实操材料＋实践检查 | 演示课堂、错误案例；没有运行工具时不能声称代码经过实测 |
| 对比/决策 | 对比材料＋情境题 | 用图表展示维度与取舍 |
| 综合应用 | 完整任务、验收标准、参考解法 | 复习材料按需提供 |

上表中的实操、图解等先作为现有 report/quiz/classroom 内的内容与活动组织；新资源类型需要配套原生契约、生成器和验收，不能只在清单里写一个类型就算支持。

例如本次 10 分钟节点可以分配为“课堂 4 分钟＋手动追踪 3 分钟＋两道检查 3 分钟，报告为选读参考”。这只是具体设计示例，需由实际讲稿、播放时长和试学反馈验证，不应继续给三份材料各自写 10 分钟。

## 5. AI 课堂的改进顺序

1. **先保证意图贯穿。**去掉固定面试模板，将上游教学活动、教学顺序、基础、偏好、节点预算完整传入生成和审阅。
2. **先分镜再成课。**根据教学目标安排案例、机制、过程演示、学员尝试、反馈；每页确定视觉内容和讲解职责。
3. **复用已有课堂能力。**通过有预算和回执的工具接入现有 OpenMAIC/视觉能力；流程图、代码高亮、步骤对照优先服务于理解，图片按需使用。
4. **把检查变成活动。**题目先出现，允许停顿与作答，再显示答案和解释；记录检查与学习目标的对应关系。
5. **补实物验收。**检查文字溢出、字号、视觉与旁白一致性、音频可用性、实际时长和互动可执行性。内容审阅与渲染验收分别给证据。

建议优先解决信息传递和分镜结构，再扩大视觉工具使用；换模型或堆更多审阅轮次无法自动修复当前契约断点。
