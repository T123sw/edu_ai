## 六类配置的真实用途

| 工具 | 可见配置与去向 | 约束程度与限制 |
| --- | --- | --- |
| 学习报告 | 主题成为 question；模板、对象、深度、结构重点、补充要求进入完整报告提示 | 写作指导。模板是提示中的风格/结构选项，并非程序渲染的固定模板；无严格逐项内容校验。图片功能已删除，本轮同步更新旧测试断言 |
| 习题 | 主题、题量、题型、难度、对象进入生成提示；附答案/解析进入提示并在保存前落实 | 题量由裁剪/不足补题维持；不足时现有生成器会用通用题补齐，因此数量符合不代表质量符合。题型/难度属于模型指导，题型选择没有逐项覆盖保证。关闭答案只清空答案字段，保留解析时解析仍可能讲出答案；不是考试答案保密功能 |
| 闪卡 | 标题、数量、难度、更多补充进入模型提示；来源开关控制输出与展示 | 数量不足会明确失败，多余裁剪；难度与补充要求依赖模型遵守。来源仅在返回的引用能匹配已提供资料时显示，不编造引用 |
| 思维导图 | 主题、关系侧重点、最大层级进入提示 | 最大层级由树归一化硬限制，是上限，不保证一定生成到该层；侧重点是提示要求；目前产物是树形导图，并非任意跨节点关系图 |
| 播客 | 主题、目标时长、讲解重点作为 settings 进入提示；时长换算为约 300 字/分钟的正文预算 | 影响讲稿篇幅，配音后不裁剪到目标时长。上次 3 分钟实际 4:03，因此只能说近似目标 |
| 情景案例 | 主题、难度、情景设定进入提示 | 场景图严格校验可达、无循环、决策及结局；难度、设定和教学质量依赖模型，不等同于结构校验 |

调用链：StudioHome.submit → definition.serialize → personal-studio 的冻结任务 config → PersonalStudioTaskHandler → GenerationTaskHandler 的对应 payload → direct report / quiz / flashcard / graph 服务；播客、案例走 StudioLearningResourceGenerator。

结论：不是仅靠界面字段就认定生效。原先存在漏传、后处理覆盖与展示缺失，已修复；当前可见字段均有实际消费位置，但模型指导不能宣称是确定性执行。未调用仍繁忙的真实模型作配置对比，不宣称各档难度、模板、时长或侧重点的生成质量已实测保证。
