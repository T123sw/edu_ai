# 模型负责规划与执行：验收记录

## 已实施

普通文本对话与报告的 Harness 主入口只校验身份、课程和显式工作区。跳过旧的关键词知识点澄清、切换和资料修订预判；主编排直接交给 Harness。报告专用 HTTP 入口也不再按固定确认语分支。

模型通过 select_workspace 决定知识点 / 课程归属，topic 保留用户的具体主题；通过 update_working_memory 保存目标、已确认事实、假设、计划、下一步与阻塞原因。大纲、提交决定和任务状态为独立结构化事实，查询任务以服务真实状态为准。

Harness 会话按用户 / 课程 / 对话隔离，不因知识点切换分裂。旧版本会话按持久化请求身份核对后迁移，保留旧文件；旧大纲、检索证据和组织内容补齐原知识点范围，不能跨范围误用。无归属证明的旧状态不盲目导入。

submit_report 不分析用户语言或匹配口令。调用意味着模型依据用户意图决定推进指定版本。代码校验权限、当前版本、资料范围和幂等性，记录本轮消息及模型决定；提交中断保留 confirmed 状态和同一幂等键。模型负责判断不调用、修改、暂停或继续，不再用关键词“兜底”改变决定。

根角色与报告 Skill 同步以上职责。大纲仅标题与每章 1–3 个短要点；内部目标、解释、例子和检查仍随组织数据供正文使用。正文生成与审阅收到当前执行阶段、推进消息和工作记忆，区分历史“先给大纲”与当前正文阶段。

## 范围与限制

本次移除的是已接入 Harness 的普通文本对话与报告决策规则。图片 / 视频、显式引用的旧资料编辑、其他生成工厂及课程知识库正式发布仍是独立入口，不应宣称整个系统的所有流程已迁移。

模型负责语义判断意味着模型仍可能误解请求，不能以固定口令被移除推断理解永远正确。工具保留权限、范围、版本和防重边界；模型审阅也不等于人工或全面事实核验。验收中的否定与中英文推进为实际模型测试，异常重试和版本变更为隔离回归。
