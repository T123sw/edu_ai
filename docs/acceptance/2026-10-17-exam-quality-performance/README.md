## 事件处理

过程事件的游标改为独立小记录，保留全部事件；只有蓝图或最终结果到达才更新含原始图片的大记录。写入仍锁定所属生成记录并验证 attempt，蓝图、结果、事件与游标在同一事务提交，重复 seq 不重复写入。读取结果和游标使用单条 SQL，避免并发提交导致读取旧结果和新游标。

控制状态按 250 ms 检查，持久写入前仍检查租约；批量上限由 100 调整为 500，时间刷新间隔仍为 500 ms。状态接口不加载全部历史事件，历史列表仅查询显示所需字段。

真实 PostgreSQL 临时 schema 回放 34,769 条原始事件、约 3.68 MB 来源载荷：旧逻辑前 1,000 条 7.435 秒，新逻辑 1.051 秒；新 handler 完整回放 32.679 秒，全部事件及 32 题结果保留。**这是事件消费基准，不包含 MinerU 与模型生成时间，不能当作整卷耗时。**负载影响绝对值，基准脚本保留，可重跑。

## 答案核验

保留 DeepTutor 原有生成、语义核对、最多两次逐题修复与检查点恢复。在核对前加入不包含候选答案/解析的独立解题；模型提供计算表达式，程序计算并核对期望值，计算不一致时给独立解题器一次纠错机会。最后对照题目、独立解和候选答案/解析判定。明确的数字等式也在调用模型前校验。

计算器只解释受限 AST，禁止 eval/exec、导入、属性访问和任意函数，限制表达式长度、序列长度、幂和操作数量。内置通用二分查找轨迹、首元素枢轴两种划分、完全二叉树路径和子树计算，无特定试卷答案。

无图题的生成、修复和核验使用用户冻结的文本模型配置；带图题保持视觉模型与图片，原卷抽取仍使用视觉模型。两个配置均经内部受信请求传输，进入上游持久消息前移除；跨用户并发、秘密不落消息及冻结身份已有回归。原有出题、修复、语义核对、逐题恢复核心流程保留。计算类单选还要求每个选项的布尔计算检查，程序确认唯一答案，并核对答案字母。

真实模型八案例回归：五个历史错误、一个新发现的多答案最小堆错误样例均被拦截，两个正确对照题均通过。注意：审查模型的理由本身仍可能错误（如树叶子计数），此结果仅证明这些样例的放行/拦截，不证明所有推导可靠。`deterministic-counterexamples.json` 给出独立程序事实：原树题编号 1024 位于左子树，前置叶子为 18 个，模型某些审查理由中的 274 等数值不可信。

整卷的“仅分流审查”版本发现最小堆多答案漏检，已取消并保留 `review-only-full-canceled.json`；改为无图题全过程走文本模型并加入逐项计算后重新测试。

早期盲解、算式、high/medium reasoning 方案的失败证据保留。提高 reasoning 曾导致输出预算耗尽且没有最终答案，所以不作为最终配置。当前沿用系统冻结的 reasoning 配置。
