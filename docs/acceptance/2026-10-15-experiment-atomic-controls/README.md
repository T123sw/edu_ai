# 演示粒度与探索参数修复

针对生产样例发现的“最后一步执行多次比较”和“提示要求修改数组但没有输入控件”，修复通用实验生成 Skill 及页面接入约定。未修改 MAIC-UI 原生仓库，未针对某份产物手写替换页面。

## 修复

- 演示按一次实际操作拆分，以小场景控制篇幅；明确操作对象与停止位置，禁止在 next 内循环推进剩余步骤、直接跑完整轮或强制完成，轮次边界单独呈现。绘图遍历不受限制。
- 完整探索页首次生成就必须提供实际参与计算的初始条件编辑。排序使用数组输入和应用按钮；其他学科按机制提供参数或连接操作。应用时停止旧动画、更新重置基准、清零过程计数；非法输入给出提示并保留实验。
- 教学拆分根据原 HTML 中真实控件及事件处理生成探索任务，使用页面实际控件名称。
- 进一步明确静止状态应原样恢复，仅运行中快照转为暂停；恢复检查失败会给出具体字段的期望值和实际值，使已有的局部修复有可用诊断。

仍采用原来的五阶段模型调用，未添加审查 Agent 或新增审查轮次。成功样例实际调用六次，因为完整探索页一次初始化错误经原有的一次局部修复处理后通过。第一次独立生成因静止快照被改为暂停失败，修正约定后从线上重试创建了新任务；失败记录保留。

## 上线方式

生成器每次读取 Skill 和页面约定；浏览器校验脚本每次以新进程执行。因此修改已对新生成生效，无需重启后端或重新构建前端。源文件校验值及线上入口哈希记录在 [verification.json](verification.json)。旧实验不自动重写，保留版本和运行记录。

新验收实验：`job_1f682b31a94146a6`，主题“冒泡排序”，9 步演示、3 道练习。服务端生成耗时约 110 秒。

## 真实验证

从生产页面提交和重试，使用真实模型与保存接口；桌面 1440px、手机 390px 均不模拟业务 API。两种宽度都通过：

- 逐步读取服务器实际快照，9 步比较次数增量为 `1,1,1,0,1,1,0,1,0`；每次最多一次相邻交换，未合并多次比较。回放恢复正确。
- 应用 `[3,1,2]` 后单步得到 `[1,3,2]`，重置回最近应用的 `[3,1,2]`。
- 非法输入 `3, abc, 2` 显示错误并保留数组和计数。
- 已排序 `[1,2,3,4]` 执行 3 次比较、0 次交换；逆序 `[4,3,2,1]` 执行 6 次比较、6 次交换；重复值 `[3,1,3,2]` 正确排序。
- 探索提示中提到的随机、有序、逆序预设均存在且可操作。
- 全新浏览器上下文从服务器恢复自定义参数、比较计数；恢复后重置仍使用最近应用的数组。
- 无页面异常和横向溢出；相关 9 项回归测试通过，Skill 校验通过。
