# 课程知识库方案：新建与补充分流

## 用户流程

新建先填写需求并按需上传教材，模型生成简明、标准、完整三份实际目录。三份保留共同核心，差异由课程内容和教学要求决定，不按固定节点数量凑数。目录默认展开，允许点击章节收回、展开，选择后仍可编辑，最后确认当前版本并进入原有后台构建流程。

补充读取现有完整目录、课程资料清单及可用摘要、教材摘要，返回带理由与资料引用的补充项。用户可以取消任意项目，仅所选知识点进入发现、教材映射、生成与质量检查。已有目录和资料引用保留；新增资料使用本次构建命名空间，避免覆盖以前的生成文件。

模型的推断必须注明依据，当前规划输入不是全部文档正文，因此不能声称已经逐篇检查现有资料。实际资料发现、质量检查与入库仍由原有执行服务承担。

## 接口与 Skill

- `POST /api/courses/{course_id}/knowledge-builds/{build_id}/proposal`：生成并保存方案。
- `POST /api/courses/{course_id}/knowledge-builds/{build_id}/proposal/select`：将选项应用到可编辑草稿，不代表确认。
- `edu-course-knowledge` Skill 的 `plan_course_knowledge` 工具与页面复用同一服务和持久化方案，并返回页面审核链接。
- 工具从会话取课程与操作者，实际权限由课程权限服务重新核验。模型没有确认或发布工具。
- 当前方案修订号、基线图谱版本和规划输入资料清单参与校验；重新规划清除旧选择与确认。模型审查通过与教师确认分别记录。

## 验证

隔离临时存储执行后端测试，禁止使用生产数据库：原有构建、发现、覆盖率、质量检查、图谱、API、Harness 等回归共 80 项通过；新增权限与版本边界后，方案服务 7 项通过，方案加构建器组合 18 项通过。测试次数有重叠，不累加计数。

浏览器测试覆盖桌面与手机的新建、补充、需求输入、章节展开收回、取消补充项及确认后执行。前端构建和修改组件 ESLint 通过。

真实 DeepSeek 调用仅使用内存测试课程：生成三份分别含 5、14、24 个叶节点的大纲；限定只补循环练习时返回一个补充项。使用独立模型审查检查教学范围与证据表述；审查不替代教师判断。未对生产课程发起知识库构建。
