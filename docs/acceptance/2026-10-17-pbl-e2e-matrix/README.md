# PBL 多项目端到端验证

结论：基础运行链路正常，但整体稳定性与验收覆盖尚未通过。本轮 5 次真实生成，4 次成功、1 次失败；另有两处重试缺陷、5 个验收漏检反例，以及一处窄屏预览溢出。问题保持可复现，本轮没有修改产品逻辑或生成提示。

## 已确认的问题

### 1. 高：新增定位方式破坏前序定位，修复失败

购物清单 B 前序检查通过 `role=button, name="切换状态"` 精确定位。后续为解决多商品重复按钮问题，模型把按钮文字改成 `切换状态：{item.name}`，前序场景即使只有一件商品也找不到按钮。最终两项旧检查失败，修复次数达到 3（初始尝试及两次修复），未发布。

根因是定位兼容性没有完整保留：当前修复提示强调保留既有 testId 并添加对象名称，但旧检查也可能依赖 role/name。补唯一名称不能无条件改变旧可访问名称。不是验收模型没有拿到上下文；记录证明前后代码、旧检查和具体失败均已传入。

证据：`shop_b-generation.json`、`context-and-failure-audit.json`。提示入口：`backend/src/app/pbl/project_generator.py:82`。

### 2. 高：参考实现通过不代表验收覆盖完整

对成功项目作 8 项定向缺陷注入。每项先证明原实现通过独立需求检查，再证明变异实现确实违反需求；随后运行模型生成的全部累计验收。5 个真实缺陷仍全部通过：

| 注入缺陷 | 生成验收结果 | 独立需求检查 |
| --- | --- | --- |
| 蓝队减分按钮不改变分数 | 全部通过 | 蓝队从 2 减到 1 失败 |
| 红队可以从 0 减到 -1 | 全部通过 | 零分下限失败 |
| 修改姓名后仍保留旧错误提示 | 全部通过 | 错误提示应清除但仍存在 |
| 商品只能切到已购买，不能切回待购买 | 全部通过 | 双向状态切换失败 |
| “全部”筛选按钮无作用 | 全部通过 | 从已购买筛选返回全部失败 |

另外 3 个反例（重置遗漏蓝队、姓名不 trim、统计错误使用筛选后数据）被正确识别。证据：`mutation-audit.json`。这些是有针对性的覆盖反例，不是随机抽样，不用 5/8 推算整体漏检率。

主要缺口是对称功能、状态往返、正数与边界分支没有逐一覆盖。需求 ID 和检查 ID 关联完整，仍不能证明业务分支完整。不宜仅增加一层“审阅通过”；应在生成验收时把需求拆成可观察行为并逐项落实操作与结果。

### 3. 高：页面重试跳转使用了任务 ID，导致 404

在已发布前端点击“重试生成”，重试 API 返回 202 并创建新 job。页面随后进入 `/#/practice/code/job_7d187fd05e8c40b5`，将新任务 ID 当作项目 ID；`GET /api/pbl/job_...` 返回 404，页面显示“暂时无法读取练习，请检查连接”并继续重连。项目实际仍是原来的 `pbl_47181002134d22ab660729f21da842ee`。

证据：`ui-retry-routing.json`、`ui-retry-routing.png`。定位：`frontend/src/practice/PracticeGenerationProgress.tsx:39`。应按资源 ID 路由，重试任务 ID 只用于任务跟踪。

### 4. 高：修复次数耗尽后，手动重试不会再调用模型

对上述失败项目通过真实 API 发起重试，新 job 成功创建；29.73 秒后再次失败。模型调用数前后均为 11，新增调用为 0。检查点保存了 `repairs[stepId]=3`，新 job 继续执行 `range(3,3)`，直接跳过失败步骤生成与修复，只重验前面的步骤。界面仍提供重试，并提示“请重试”，但无法产生新的修复机会。

证据：`exhausted-retry.json`。定位：`backend/src/app/pbl/project_service.py:97`。需要区分同一执行的中断恢复与用户显式发起的新重试，为新尝试提供有界修复机会，并保留历史计数。

### 5. 低：极窄预览存在横向溢出

记分牌在外层窗口 320px 时，预览 iframe 宽 279px，内容宽 284px，溢出 5px；外层应用本身没有横向溢出。390px 与桌面窗口正常，其余三个成功项目的预览在 1440/390/320px 均未横向溢出。此项属于生成代码的窄屏适应问题。证据：`independent-preview.json`。

## 已通过的链路

- 4 个成功项目全部完成真实页面的起始空工程失败、逐步编辑、累计检查、最终完成提示、自动保存、刷新保留代码与步骤、改坏后失败、恢复后通过；共 10 个步骤。见 `browser-summary.json` 和各项目 `*-browser.json`。
- Sandpack 确实显示生成页面；独立执行 19 组业务场景，覆盖多个商品独立操作、数量边界、购买状态往返、筛选与全局统计、双方比分、报名提示、作品区域几何关系，正确参考代码均通过。见 `independent-preview.json`、`*-interaction.png`。
- 真实生成期间取消后没有发布；重试保留同一项目并复用代码，调用序列为 plan → build_step → build_checks（取消）→ build_checks（继续），成功交付。见 `real-cancel-retry.json`。
- 匿名请求 401、跨账号项目/工程/运行记录与检查请求 404；重复 runId 返回相同报告，冲突内容 409；越界文件 422；两次并发保存一成一败（200/409）。见 `api-contracts.json`。
- AI 辅导实际读取当前代码与已保存检查证据，正确指出“蓝队正数减分未被验收覆盖”；同 requestId 幂等且历史可读取。见 `tutor.json`。
- 真实 PostgreSQL 并发/CAS/租约、迁移、取消与恢复专项 17 项通过，没有跳过。见 `recovery-postgres.log`。

浏览器捕获到 Sandpack 遥测请求超时和刷新时 iframe 请求取消，没有 pageerror，预览与操作成功；这些网络记录未误算为产品逻辑失败。首次测试对 CodeMirror 虚拟化内容的断言未先滚动到文件尾，误报注释缺失；数据库确认保存存在，修正测试滚动后复跑通过，保留 `score-browser-harness-scroll-failure.json` 说明其来源。

优先处理两处重试缺陷，再完善通用定位契约兼容与验收行为覆盖；对生成参考代码通过的判断应继续与“验收能发现错误”分开。
