- 真实模型 SSE 增量展示、心跳与取消；聊天不阻塞实验，不执行模型生成的 HTML，不修改本地判定或推进步骤。模型响应过长/截断不能伪装成完成。
- 右侧学习助手替换原保存问题占位区，保留本步反馈与操作按钮；消息独立滚动、回答关联、刷新恢复、历史操作入口、未确认发送的本地备份。服务器已接收但客户端未收到确认时，以历史记录核销待发送消息。

## 实测中发现并处理的问题

1. 用户回答只埋在大段 JSON 里时，模型曾先肯定再否定，或把用户“仍要交换”读成“不交换”。改用真实对话角色，将原教学回复和用户最新原话放在输入末尾，并明确评价假设问题的规则；复测能指出结论和方向错误。
2. 合成适配器只有 `count` 状态，但设计文字含 `[3,1]`，模型曾把设计起点说成当前数组。常规教学上下文移除任务的预设 `initial/checkpoint`，保留实际前后快照；完整设计仍可用工具查阅。补测改为引用“演示阶段说明 3 大于 1”，未再把设计起点冒充本次快照，见 [补测](grounding-results.json)。生成页面漏报状态仍会降低讲解可靠性，本次没有增加实验生成审查门槛，也不承诺模型永不误判。
3. 刷新可能发生在服务接收问题后、浏览器接收 SSE 确认前。通过请求编号对照服务器历史清理待发送副本，重试不新增消息；恢复回应对象覆盖历史分页之外的消息。
4. 初次联通验证中，`core.config` 重新载入 `.env` 覆盖了测试存储环境变量，导致专用临时账号 `experiment-tutor-test` 的 30 条测试记录进入共享应用状态存储。已备份并仅删除该账号、本次三个实验前缀下的测试记录，核验剩余为 0；未修改真实用户产物、操作记录或任务。后续在导入配置后设置独立存储，并强制断言 `store.repository is None`，全部联通流程在隔离文件存储中重跑。见 [清理核验](test-namespace-cleanup.json)。私有备份留在 `.runtime/experiment-tutor`。

## 边界与后续接入

- “看到每一步”指生成页面已上报的语义操作；不代表模型逐帧观看，也不在每个动作后调用模型。动画采样和系统演示有独立来源，不能算作学生已掌握。
- 现有每轮 2000 事件、约 1.5 MB 上限保持不变；完整原始记录持久化，模型按需载入。未实现无限历史、主动连续讲课或模型自动推进任务。
- 教学评价用于对话。旧版 rubric 任务的自动评分/推进仍未实现；模型“你理解对了”不写成实验通过。
- 本次覆盖独立实验会话；课程内跨资料统一知识点会话需后续按课程学习 Agent 规范接入。
- 旧产物中的 `teaching.status=reserved` 是生成时的历史描述，本次运行时接入不改写产物或 revision；可用性由新教学接口与前端决定。
