# 教学资源接入：交互与内容质量自检（2026-09-09）

9 月 8 日的验收证明了生成、保存、回读和预览链路能运行，但把所有资源都套进报告大纲确认流程，对教学结构和成品质量的检查不够。本次以真实多轮对话、生成内容和页面操作重新检查，直接修正发现的问题。本文替代上一份记录中“七类资源都应先确认大纲”的设计结论。

## 各资源的交互与结构

| 资源 | 正常交互 | 成品与检查重点 |
| --- | --- | --- |
| 教案 | 教学方案 → 修改/确认 → 完整教案 | 可观察目标、重难点、准备、按时间展开的师生活动与评价、课后任务和待填写反思；时间总和与课时一致 |
| 博客 | 默认先确认简短文章结构；明确要求直接写成稿时由模型直接推进 | 场景引入、连贯正文、具体实例、自然结尾，遵守篇幅与读者需求，不套教案栏目 |
| 习题 | 需求足够直接生成；只有用户明确要方案时才停在方案 | 原生题型、数量和难度；逐题独立求解、逐个核对选项解析；答案默认折叠 |
| 闪卡 | 需求足够直接生成 | 每张一个主要记忆点，问题自足、答案简洁、正反面准确配对；可以只生成一张 |
| 思维导图 | 需求足够直接生成 | 主题、分类维度、层级和同层粒度合理，节点说明使用界面读取的 `summary` |
| 互动游戏 | 主题/玩法明确直接生成；未指定玩法由模型选模板，实质有歧义才澄清 | 真实模板、可操作规则、正确答案与反馈，验证实际通关操作 |
| AI 课堂 | 逐场景方案和媒体设置 → 修改/确认 → OpenMAIC 原生课堂 | 学习目标、投屏内容、讲解、互动和时长；保留 stage/scenes/actions、播放器、媒体与导出路径 |

结构与质量标准集中在 `backend/src/app/chat/harness/skills/edu-resources/SKILL.md`。`resource_profiles.py` 读取相应资源章节，内部组织、方案生成、成品生成、独立审阅与课堂提交使用同一来源。报告仍保留 `edu-report` 的专有结构。

## 本次修正的实际问题

1. **短资源被迫确认大纲。** 新增 `submit_resource_direct`，模型明确选择创建时可直接提交已组织的需求；不展示伪大纲、不多问一次是否开始。保留权限、范围、证据、幂等、失败恢复和审阅门槛。
2. **教案/课堂方案只有报告式知识标题。** 提示词不足以可靠保证结构，改为独立 schema：教案环节必须有时间、教师活动、学生任务、评价；课堂场景必须有目标、投屏、讲解、互动、时间。页面展示这些真实字段，并校验各环节时长之和；教案/课堂方案展示前再独立核验要求、媒体、活动/评价与具体事实。校验的是数据契约，不是用关键词决定用户意图。
3. **课时修改被旧规则截走。** 实测“把教案课时改成 12 分钟”被旧入口当作文档修改，要求用户重新选择资料。移除该关键词入口；当前方案交给 Harness 模型修改。已有成品由模型查询并选择具体任务，通过 `select_resource_for_revision` 进入原有修改稿预览与确认保存流程，不需要用户重复手动引用已明确的对象。
4. **课堂媒体选项遗漏后默认开启。** 用户要求无外部配图，模型曾漏填而使用默认开启值。课堂生成现在要求显式填写语音、外部配图和总时长；说明文字/公式/原生图形无需开启外部配图。验收核对真实选项与用户要求。
5. **简单资源被强加三个模块和两个目标。** 资源组织 schema 允许一个目标、一个模块；不需要的示例/误区/检查可留空。报告约束保持独立。
6. **习题答案正确掩盖错误解析。** 人工式逐项复核发现数值干扰项解析不成立，但原来的六项模型审阅通过。增加逐题独立解答与逐选项审阅记录；缺少任何题目/选项的核验、解析错误，即使正确答案对也不能交付。成品审阅改用项目已配置的深度模型角色（当前为 deepseek-v4-pro），不再复用快速执行/写作角色或关闭推理设置，并为推理与完整 JSON 预留 32768 token 上限（逐场景课堂审阅另设 65536）；较小上限实测曾导致审阅 JSON 截断，失败记录没有被当作通过。DeepSeek 的默认推理行为与参数依据[官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。Skill 要求干扰项对应可解释的实际错误，并区分复杂度上界、紧确量级和真实硬件耗时。
7. **审阅标准过度报告化。** 保留六个审阅维度以兼容交付记录，但按资源契约解释：闪卡检查问答、导图检查关系、游戏检查任务。不要求每张卡扩成报告或凭空增加例子。
8. **导图说明字段不匹配。** 统一输出 `summary`，避免生成了说明却在页面丢失。
9. **习题/闪卡导出空内容。** 导出读取旧顶层字段，也兼容新的 `content.questions` / `content.cards`，保留原生内容。
10. **选项标号和翻卡状态不合理。** 习题选项显示字母，与答案一致；切换同类资源重置答案展开/翻面状态，不沿用上一份资源的状态。
11. **直接生成未纳入任务历史判断。** 将新提交工具纳入生成动作集合，避免同轮查询旧资源并生成新资源时误判为纯读取。

12. **旧查询工具误用报告标准核验导图。** 真实模型曾选用兼容名称 query_report_job 读取导图，导致真实成品被错误判为未通过。报告查询入口现在先校验权限并返回明确的资源类型错误，引导模型改用原生资源查询；不再返回“调用成功但报告审阅失败”的误导结果；回归和实际回读重验覆盖此问题。

13. **深度审阅超出旧任务预算、进度停留在生成。** 普通非报告 Harness 任务为最多两次修订预留 900 秒任务预算；课堂为最多三次跨场景修订预留 1800 秒，并在实际写作、审阅、修订时更新进度；报告预算不变。网络中断后向模型提供仍符合当前来源范围的已保存内容组织，支持复用，不必重做已完成步骤。

14. **阶段标准混用。** 内容组织审阅曾要求完整教案的作业/反思栏目，引起无意义退回。Skill 和读取器现在明确分开“内容组织阶段、方案阶段、成品阶段”；相应生成和审阅读取各自标准，完整成品要求不降低。
15. **课堂后处理失败的恢复。** 课堂场景已经生成，修订 JSON 的输出预算不足却使任务失败。修订使用独立写作网关与完整输出预算；通过真实任务重试 API，权限、课程和原始需求一致的后处理重试复用已成功的 sidecar 产物，重新审阅/修订/保存，不重复生成课堂。保存前进度最多 90%，明确显示核对内容，完成后才到 100%。

16. **方案校验错误没有反馈给生成器。** 真实教案修改中，越界模块索引和环节数量错误反复出现。现在将具体失败原因和上一份候选方案交回生成模型，同时在本轮 schema 中明确实际索引范围；仅用户明确要求数量时严格固定环节数。已保存的方案可用 `show_resource_outline` 原样展示，不无故重生成或增加版本，重展示当轮仍不能直接提交。

17. **审阅通过仍存在缺少前提的知识结论。** 二次人工抽查发现早期博客将常数复杂度等同实际耗时恒定，闪卡泛化链表二分查找复杂度，导图省略操作前提。撤回这些样本的质量通过结论；增加所有资源共享的准确性标准，要求主动寻找反例、区分理论与实际、注明实现/操作前提。重新生成并核验受影响资源，保留被否决样本。

18. **教案混入课堂默认时长。** 课堂专用默认选项被带入教案生成/审阅，与用户改课时的要求冲突。非课堂的生成与审阅不再传递课堂选项，保存为空，避免无关默认值影响模型判断。
19. **课堂审阅漏掉讲解中的错误。** 增加逐场景投屏与逐个讲解动作的完整审阅记录，漏查任意场景/讲解或任何一项不通过均阻断；还须交叉核对检测题与讲解中的下标、序数及具体数据，不能孤立审查每句；不能因忠于已确认方案而接受知识错误。课堂早期样本撤回质量通过结论。
20. **审阅 JSON 偶发不完整。** 在真实博客任务中复现。最多让同一审阅模型重新核验并输出一次完整 JSON，保留实际否决项；仍不完整则失败，不用格式修补假造通过结果。

21. **课堂文字修订路径无效。** 深度审阅指出错误后，模型把包装层误写入原生 JSON 路径，修订中断。最终修订协议从已有修改系统的 `editable_paths` 枚举文字，为其分配当前候选内的字段编号。模型选择编号和完整新文字，代码解析原生路径；校验失败回传真实错误，最多修正三次，原内容保持不变，只有合法修改并重新审阅通过才保存。

22. **模型复制原文片段不可靠。** 课堂修订曾连续三次无法唯一匹配原文。内部修订改为模型选择当前候选内的字段编号和完整新字段文字，代码将修改绑定到当前不可变候选的完整旧字段，再使用已有编辑校验；保留身份/媒体保护，重复字段编号拒绝，修改后继续独立审阅。语义改动仍完全由模型选择。

23. **审阅遗漏覆盖记录没有重试。** 课堂曾漏掉一个讲解动作。现在向模型提供实际必须覆盖的场景/讲解下标清单，结构、覆盖与 JSON 格式错误统一反馈重试；未补齐仍失败，不把漏检视为通过。
24. **快速执行模型被用于深度审阅。** 多次抽查证实即使提示词已说明边界，快速模型仍可能放过明确事实错误。成品审阅使用项目已配置的深度模型角色，生成继续使用写作网关；保留显式网关注入供回归测试。使用含已知错误的真实课堂验证深度模型的发现、修订与复审能力。

25. **报告式全量覆盖与固定环节数强加给教案。** 教案重跑因建议5环节实际生成4环节、未照搬全部准备模块而反复退回。资源环节数默认是模型建议，只有模型明确识别用户指定数量时才严格校验；非报告只校验索引合法，知识取舍与必要目标覆盖交给模型审阅。准备材料不等于必须展开的教学任务，报告原有覆盖规则保持独立。

26. **导图首屏全部展开、分支被挤出视野。** 默认只显示主题和一级分支，细节由用户按需展开；复位同时恢复缩放和折叠状态，切换导图不残留旧状态。完整导出仍包含折叠的节点，五种视口和真实导图均验证展开、复位与导出。

27. **课堂适配层覆盖任务预算，验收脚本也过早退出。** 上层设置 30 分钟，但提交适配层写死 900 秒，实际 durable task 没收到新预算。改为透传命令预算并补提交边界回归。原脚本 20 分钟退出时课堂已生成、仍在深度审核，造成验收进程中断。课堂等待上限改为 35 分钟，高于应用 30 分钟预算；补充等待既有任务的模式，保留原始超时记录。超时或工作器中断后的公开重试，也只在用户、课程、原始需求一致且 sidecar 确实成功时复用产物，重新审核再保存。

## 验证方式与环境

- `scripts/verify-harness-resources.py` 启动隔离 FastAPI、合成教师和课程，使用真实模型、真实 durable worker、真实存储、HTTP SSE 与资料回读。
- 习题/闪卡/导图/游戏首轮断言已提交且没有大纲；教案验证“先不要生成”的讨论、15 → 12 分钟方案修改、版本递增与后续英文确认；课堂核对三场景、五分钟、无语音、无外部配图。
- 浏览器请求真实隔离 API，验证答案展开、闪卡翻面、导图、游戏拖拽配对通关和课堂下一页。另验证原生习题/闪卡/导图下载内容与成品一致。
- 回归覆盖原报告确认、证据/权限/版本保护、原有修改稿保存及新模型交接；浏览器模拟 SSE 的流程测试与真实模型验收分别记录，不互相替代。
- 初次实测出现多次上游 502。诊断确认终端代理连接官方 DeepSeek 时出现 `SSL: UNEXPECTED_EOF_WHILE_READING`；提供 `--direct-deepseek`，仅在隔离验收进程对同一官方接口绕过终端代理，不修改全局网络配置、模型或密钥。直连仍有个别连接超时，失败轮次保留，不能算作通过。

最终逐资源状态、测试日志与抽查证据见本目录的 `evidence/2026-09-09-resource-quality/`。模型审阅是可追溯的质量门槛，不能作为永不漏检的保证；本次明确保留了被额外复核发现问题的早期样本和改进原因。

## 回归结果

- 相关后端检查：176 项通过，覆盖报告原流程、七类资源、权限/范围/版本、方案反馈、课堂后处理恢复、审阅缺项与错误阻断。
- 修改流程回归：251 项通过（与上项部分重叠，不相加）。
- 浏览器五种视口：本轮 48/50 通过；2 项在资源尚在加载时超过 5 秒断言期限。补充显式等待页面就绪后，该用例在全部五种视口复跑 5/5 通过。保留原失败与复跑日志，未把原始运行改写成全通过。
- 原生导出与预览数据单元检查：5 项通过；前端生产构建通过。
- 真实教案：15 分钟初稿 → 讨论但不生成 → 12 分钟新版本（2+4+4+2）→ 英文确认 → 包含专用教学栏目的完整教案 → 回读和页面预览，通过。
- 真实博客：初次审阅 JSON 不完整导致任务失败，修复后经公开任务重试 API 生成、审阅、保存、回读、预览通过。

- 真实课堂：三场景、五分钟、无语音/外部配图；首次生成后验收进程中断，公开重试复用同一个 sidecar。深度模型发现投屏高亮与讲解下标不一致、int 大小缺少示例假设，两次原生文字修订后第三轮复审通过，保存、真实模型回读和播放器下一页均通过。首次不中断运行未通过，未篡改为通过；三轮深度审阅累计约 600 秒，课堂等待时间仍是明确的体验改进项。

- 本轮真实样本集中在“数组随机访问”。已核对教案课时与计算、习题各选项及解析、闪卡问答、博客前提、导图层级和游戏通关；这不等于覆盖所有学科、语言与难度。教案跨语言举例采用 C 风格声明，授课时应统一目标语言；该表达改进记录在样本的 `manual_audit_notes` 中。

完整日志与样本的 `passed` 表示自动流程断言；`accepted_by_manual_audit` 和汇总文件记录内容抽查结论。它们可能不同，不能将运行成功当作质量通过。
