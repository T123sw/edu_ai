三、最有价值的三个发现

1️⃣ 原在线 Embedding 服务已经故障

实测原配置的中转站 api.relayrouter.ai 对标准 OpenAI 格式返回 HTTP 400：

Invalid JSON payload received. Unknown name "requests": Cannot find field.

说明在我接手前，项目的知识库入库/检索链路就是断的。 本地化部署同时修复了这个故障。

2️⃣ 项目曾因"本地 TTS 太慢"而放弃

项目在 2026-10-13 曾启用本地 TTS 并验收通过，但当时的性能数据是：

synthesis_seconds: 14.7    audio: 4.464s    →  RTF ≈ 3.3

之后被改回 TTS_LOCAL_ONLY=false（改用阿里云）。本次优化后 RTF 降到 0.89，已重新启用。

3️⃣ 索引维度与配置不符，必须重建

.env 里的 GEMINI_EMBEDDING_DIMENSIONS=768 是死配置（代码仅在 backend=="gemini" 时传递，实际为 openai），实际索引是 3072 维。切换向量模型必须重建索引，本次采用"新建独立索引 + 验证 + 切换"方式，295 秒完成 11,249 条重建。

3.1 NVML 驱动不匹配问题（任务书第 1 条）—— ✅ 已修复

项修复前修复后
nvidia-smi❌ Failed to initialize NVML: Driver/library version mismatch✅ 正常

# 本地 Qwen3-TTS 开关：true=用本地，false=用阿里云远程
TTS_LOCAL_ONLY=true

# 本地 TTS 服务（TTS_LOCAL_ONLY=true 时生效）
TTS_PROVIDER_NAME=local-qwen-tts
TTS_API_BASE=http://127.0.0.1:8188/v1
TTS_API_KEY=
TTS_MODEL=qwen3-tts
TTS_VOICE=vivian
TTS_TIMEOUT_SECONDS=120
TTS_SPEED=1.0
TTS_RESPONSE_FORMAT=mp3

# 以下仅供本地 TTS 服务进程使用
QWEN_TTS_MODEL=/home/zxqs_ep/data/models/qwen3-tts
QWEN_TTS_DEVICE=cuda:0
QWEN_TTS_MAX_CONCURRENCY=1

# ---- 性能优化参数（2026-10-16 新增）----
QWEN_TTS_BATCH_SIZE=16        # 批量合成条数，1=退回旧的逐条模式
QWEN_TTS_CACHE_SIZE=256       # 结果缓存条数，0=关闭缓存
QWEN_TTS_MAX_CHUNK_CHARS=40   # 分块上限（字），越大越少切分
QWEN_TTS_CHUNK_MODE=sentence  # sentence | none

> ⚠️ TTS_LOCAL_ONLY=true 时项目会强制校验地址必须是回环地址（127.0.0.1），否则启动即报 > TTS_LOCAL_ONLY requires a loopback TTS endpoint。

三、故障处理

3.1 【已解决】GPU 驱动与 NVML 库版本不匹配

现象

$ nvidia-smi
Failed to initialize NVML: Driver/library version mismatch
NVML library version: 595.99

torch.cuda.is_available() 仍为 True，但 nvidia-smi 完全不可用，无法读取显存。

根因 驱动包已升级到 595.99.02，但内核中仍加载着旧模块 595.91.07（升级后未重启/未重载模块）。

验证方法：

cat /proc/driver/nvidia/version        # 看内核模块版本 → 595.91.07
dpkg -l | grep nvidia-driver           # 看已安装包版本 → 595.99.02

两者不一致即为本故障。

修复步骤（2026-10-16 实际执行，全程约 90 秒，无需重启服务器）

# 1) 确认谁在占用 GPU（若只有本项目 TTS，可直接停）
sudo fuser -v /dev/nvidia*

# 2) 停掉占用 GPU 的服务
sudo systemctl stop edu-ai-tts

# 3) 卸载旧内核模块（顺序不能反）
sudo rmmod nvidia_drm nvidia_modeset nvidia_uvm nvidia

# 4) 加载新模块
sudo modprobe nvidia && sudo modprobe nvidia_uvm

# 5) 验证
cat /proc/driver/nvidia/version       # 应显示 595.99.02
nvidia-smi                            # 应正常输出两张卡

# 6) 恢复服务
sudo systemctl start edu-ai-tts

修复结果

项修复前修复后
内核模块595.91.07595.99.02
nvidia-smi报错正常
CUDA Version—13.2
GPU0 / GPU1读不出24576 MiB / 24576 MiB

风险与注意事项

  • 该服务器是共享服务器（/data 下还有 cbw、dxx、huanxu、lizixu、lzs 等其他用户）。执行前务必用 fuser -v /dev/nvidia* 确认没有他人在用 GPU。
  • 本次执行时 GPU 上只有 edu-ai-tts 一个进程，且项目当时使用在线 TTS（TTS_LOCAL_ONLY=false），因此停服务不影响业务。
  • 若 rmmod 提示 Module is in use，说明仍有进程持有 GPU，用 fuser -v /dev/nvidia* 找出后处理。
  • 若重载失败，终极手段是 sudo reboot（systemd 服务会自动拉起，约 2 分钟）。
