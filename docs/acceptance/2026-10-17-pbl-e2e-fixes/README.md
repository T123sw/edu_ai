# PBL 端到端问题修复

针对上一轮[多项目验证](../2026-10-17-pbl-e2e-matrix/README.md)发现的问题，修改生成上下文、声明式验收接口、持久任务恢复和前端重试。没有增加独立模型审阅，也没有按计算器、清单等项目名称分流。

## 修改

- PBL 重试保留项目 URL，只更新任务，避免使用 `job_…` 作为项目 ID 导致 404；模拟实验沿用其自身路由规则。
- 同一任务恢复保留有限修复预算；用户明确重试产生新任务时重新获得初次尝试加两次修复的预算。保存任务身份、累计修复次数和失败上下文，已通过步骤重新执行验证后复用。
- 定位支持 `target.within` 和从 0 开始的 `index`。既有 role/name、testId 和文本边界保持兼容，重复控件可在真实容器内或按场景确定的顺序定位；越界、范围缺失或重复不会空通过。错误报告说明实际匹配数量。
- 验收调用先输出私有 `behaviorCases`，再生成检查动作，展开需求中的对象、状态、边界、可逆方向和互不干扰关系。行为清单属于同一次生成，不是额外审核，也不作为运行通过证据。输出 schema 直接绑定本步 ID，允许在既有检查里补充场景。
- 宽容处理含义确定的格式差异：验收材料省略字段时继承已保存 unit；忽略服务商回显的 `type: json_object`；动作层的 within/index 转为标准 target 字段。冲突、未知标识、无法执行或不符合需求的结果仍拒绝。
- 需求关联允许检查同时观察共享需求的初始状态，不因说明性关联超过本步需求集合而重新生成；未知需求、遗漏本步覆盖等关联错误仍检查。
- 参考代码生成增加窄容器布局指导，允许子项收缩与换行，不靠隐藏内容消除溢出。已发布学生工程不被静默改写。
- 压测另外发现默认 5 分钟时限从入队起算，后排项目实际执行时间被压缩，而且超时被误报成取消。PBL 使用现有队列的独立排队/执行时限：排队最长 30 分钟，领取后重新计执行的 30 分钟；显式重试旧任务也补齐配置。执行器按实际原因报告超时，保留真正的取消语义。

## 复现

`reproduction/original` 保存原始隔离项目候选，`reproduction/regenerated` 保存重新生成的验收，均不含登录 token 或模型密钥。运行以下命令重放八个反例，无需调用模型：

```sh
node docs/acceptance/2026-10-17-pbl-e2e-fixes/reproduction/audit.mjs
node docs/acceptance/2026-10-17-pbl-e2e-fixes/reproduction/audit-shopping.mjs
```

后端测试使用隔离入口，禁止直接加载生产 `.env`：

```sh
python scripts/pbl/isolated.py pytest backend/src/tests/pbl backend/src/tests/test_durable_task_executor.py -q
node --test frontend/scripts/pbl-project-validation.test.mts
```

PostgreSQL 专项需将 `PBL_TEST_DATABASE_URL` 显式指向测试数据库。本次使用本机 55441 的 `pbl_acceptance_20261017_fixes` 与 `pbl_acceptance_20261017_final`，后者仅用于真实模型端到端数据。其余复现脚本保留本次隔离目录、端口和调用过程，真实模型重跑需要本地模型配置。

## 上线

前端基于上一版已发布源码快照，只叠加三个相关文件构建；481 个发布文件与 Nginx 入口校验一致，线上 8 项页面回归通过。后端修复已保存并验证，当前账号执行 `sudo -n systemctl restart edu-ai-backend` 返回需要管理员密码，尚未重启。生成侧修复在管理员执行以下命令后生效：

```sh
sudo systemctl restart edu-ai-backend
```

旧提示目录保留，正在运行的旧进程不会读取新版提示契约。已发布项目不会静默替换验收版本；新版能力用于新生成和未发布任务的重试。Skill 版本变化时旧草稿会重新验证或重建。
