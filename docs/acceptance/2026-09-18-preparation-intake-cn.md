# 课程准备 Agent：输入与需求理解优化验收

本次范围是第一阶段：把前端输入、附件理解、需求归纳接通，并将理解结果交给已有研究阶段。未改变后续研究、路径审阅、制作和交付的状态机。

## 用户可见行为

- 首页支持描述目标、上传文件或两者一起提供；描述长度与后端统一为 2000 字符。
- 文件支持 PDF、DOC、DOCX、Markdown、TXT；最多 30 份，每份最多 30 MB。扫描件等无法提取正文的文件仍可能解析失败，不承诺 OCR 能力。
- 上传后展示文件名，允许移除，不要求用户选择主资料、参考资料或用途。
- 学习时长、语言、深度、讲解课堂放在可选设置中。默认不提交 60 分钟，避免覆盖“两小时”等用户原话。
- 只有附件时直接进入理解，推断的学习目标记录为假设，不增加确认步骤。
- 任务中间产物展示附件摘要、需求理解、已有基础、预期能力、时长、来源限制和假设。

## 执行链路与约束

`用户描述/附件 → normalize 内逐段理解附件 → 形成 brief → ingest 登记研究候选 → research_scope`

每个文件按 12000 字符逐段理解，每段单独保存 checkpoint，全部读完才归纳需求。文件理解工具只有 `record_input_document`；模型调用计入任务原有预算。恢复时复用已完成片段并重新检查访问权限。文件理解不写入长期记忆；需求归纳继续读取有效学习偏好，优先级为本次明确设置、用户原话、有效偏好、合理默认值。

需求新增学习目标、已有基础、预期能力、深度、来源范围和资料形式。来自附件的要求必须引用文件理解阶段已核验的原文并标明 document_id；来自用户的要求必须匹配本次原话。虚构引用最多自动修复两次，不能静默当作已理解。文件中的操作指令不构成用户授权。

“只根据附件”等自然语言限制由模型归纳并附用户原话，进入研究时通过 effective_request 传到工具挂载和 PolicySources。原请求禁止网络时不能放宽。附件用途是模型判断，不要求用户分类；判断正确性仍需持续用真实场景评估。

日志目录：[2026-09-18-preparation-intake](artifacts/2026-09-18-preparation-intake/)。测试数据库使用隔离 PostgreSQL 的临时 schema 和 SQLite；不迁移业务数据库。

- TypeScript 检查通过；前端生产构建通过，存在 Vite 大分包提醒。
- 输入与交接：5 项通过，覆盖长文尾部、断点恢复、权限撤销、虚构引用拒绝、附件先于需求归纳以及研究阶段的来源限制。
- 完整课程准备回归：232 项通过、5 项跳过（仅 SQLite 并发锁场景；对应 PostgreSQL 场景通过）。新增交接用例在该轮收集后加入，另由上述 5 项输入测试验证。
- 最终输入与研究定向复验：29 项通过。
- 共享调用回归：33 项通过（学习 Agent 的课程准备适配及报告准备调用）。

真实模型使用 deepseek-v4-pro，输入两份合成附件（岗位要求、个人背景，岗位文件含恶意指令测试文字），需求为“我会 Python，准备 Agent 开发岗位面试，有两小时。只根据上传资料，不要联网，也不要模型训练。”

结果：正确识别两类附件、基础与面试目标，得到 120 分钟、仅附件、不涉及模型训练，并进入 research。调用 3 次（文件理解 2 次、需求归纳 1 次），合计 6885 tokens。没有搜索外部资料。原始模型响应、用量、附件理解和 brief 保存在 [real-model.json](artifacts/2026-09-18-preparation-intake/real-model.json)。

验证边界：真实模型测试止于需求归纳与研究权限交接，没有在本次重跑完整真实模型课程制作。两份合成附件是需求依据，不能替代技术教材；后续阶段仍须做证据充分性检查。完整流程的回归使用测试模型。超长文件仍受总预算和模型上下文限制，解析失败或预算耗尽会明确失败。
