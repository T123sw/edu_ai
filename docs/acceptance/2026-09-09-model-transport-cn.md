# 教案确认后 502 与错误页泄露（2026-09-09）

截图 `image copy 22.png` 对应会话 `conv-bc3e86f6625d`。日志显示原任务 `job_b4568181cca64efb` 已进入教案后台生成，07:47 UTC 正文模型连续返回 502，任务失败。它没有被错误路由为报告修改。

502 页面由 `deepseek_key_failover.py` 的异常分支生成，说明本地转发向上游请求发生连接/读取异常；当时未记录异常类型，不能据此确定是系统代理、网络还是远端连接问题。主服务环境配置了 HTTP/HTTPS 代理；排查时直连与代理的小型真实 completion 探测均已恢复 200。

修复：

- DeepSeek 密钥转发默认使用直连，隔离其他服务的系统代理。确需代理可显式设置 `DEEPSEEK_TRUST_ENV_PROXY=true`。只调整该转发层，不全局删除代理环境变量。
- 直连连接建立失败最多重试一次；仅 402 切换备用密钥，保持原有凭据边界。流式响应开始后不重播请求或整个 Agent 任务。
- 转发失败返回固定 JSON 错误及稳定错误码，日志记录异常类型及响应是否已经开始，不返回 HTML。
- 同步、文本流式、工具流式模型网关统一使用简洁用户提示；上游错误页和网络异常文本不拼入用户消息。

验证：17 项传输专项测试通过，271 项资源/任务回归通过。专项包含故障代理、连接中断、402 切换、同一次 completion 不重跑 Agent、三种网关错误展示。证据见同名 evidence 目录。

部署前确认没有活跃用户任务，重启后 `/health` 为 ok。通过公开重试 API 恢复原失败任务，保留原确认方案与归属 `knowledge_point/array-linked-list`，未另写新方案。

真实恢复任务：`job_93206e5c70364805`，`retry_of_job_id=job_b4568181cca64efb`。正文首次实际调用成功，用时约 42.6 秒。浏览器读取真实教师账户的生成工厂，确认《数组的实现》显示“进行中”，见 [运行中页面](evidence/2026-09-09-model-transport/running-factory.png)。

## 恢复测试揭示的修订缺陷

首次重试的全部模型调用成功，但三轮审核、两次全文重写后仍因课时分配偏离确认方案、课堂任务与附录的插入位置不一致而失败，未落库。没有将传输恢复等同于内容生成通过。

继续修复教案修订：审核后的修订输出精确片段补丁，由模型选取 before/after，程序唯一匹配原文再应用；不再每轮重新输出整份教案。无效补丁保持原稿，保留原审核意见并附加匹配错误后交回模型。教案 Skill 明确保留已确认核心环节的各自用时，正文与附录共用练习数据、位置和答案。最终仍由独立模型审核，不绕过质量门槛。
