# 恢复大纲确认步骤及检索按钮语义

用户截图 image copy 11.png：同一轮依次调用 rag_search、organize_report_content、draft_report_outline、submit_report，导致大纲没有交给用户确认即生成正文。上一轮将取消固定口令扩大为允许跳过确认，现纠正此行为。

## 当前行为

- 完整报告必须先展示当前大纲，用户在后续消息确认后，模型再调用正文提交工具。
- 不匹配确认关键词；“开始”“Go ahead”等是否表达确认，仍由模型判断。
- 大纲记录生成轮次与已展示版本。未展示、本轮生成 / 修改或本轮刚展示的大纲不能提交正文。修改后不复用旧版本的展示事实。
- 兼容从历史成功回复恢复已展示大纲版本，不要求重做旧大纲。
- RAG / Web 按钮开启表示本轮必须调用对应检索工具；未开启表示模型可以自行决定，工具保持可用。模型漏掉强制检索时运行时要求其补充调用，不由代码代替模型选择查询内容。
- 强制检索失败时不得冒充检索成功生成报告；必须反馈失败。
- 移除切换知识点时自动打开 RAG 的行为，按钮由用户控制；更新按钮提示。

## 验证

150 项后端隔离测试通过，包含本轮提交拦截、展示后下一轮自然确认、修订失效、四种按钮组合与强制检索。6 项浏览器知识点交互用例及前端生产构建通过。

此次修复没有删除或重放用户已生成的报告。此前允许同轮直接提交、按钮表示权限的说明已被本记录取代。

主系统真实模型验证通过：RAG 开启，首轮仅要求“生成数组的实现的报告”（未提示只给大纲），模型先检索、组织并展示三章简短大纲，无 task_id、无 submit_report；第二轮“开始”再次按按钮要求检索后成功提交正文任务。证据见 evidence/2026-09-08-outline-confirmation/live-rag.json。

未开启检索按钮且用户说明无需检索的真实模型对话也通过：首轮仅展示大纲，后续“开始”才提交正文，未强制检索。

## 大纲标题与进度文案修正（截图 image copy 12.png）

原大纲提示词要求短要点，导致小标题位置出现摘要和结论。现在结构化输出要求 section_titles（兼容旧 points），生成章标题及名词性小节标题，并渲染为二、三级标题；详细教学组织仍供正文生成使用。真实主系统生成“数组的实现”三章大纲，其中“索引与地址计算”下为“索引从零开始、地址计算公式、随机访问原理”，首轮没有提交正文任务。

前端原后台任务分支提前返回，未用后端最终文案覆盖模型流式文字，造成编号外露。现在提交事件立即显示普通进度、停止追加该任务的后续回复片段，并应用最终用户文案。任务编号仍保留在内部元数据，供轮询使用。根角色与报告 Skill 同时要求隐藏内部编号及原始状态。

验证：151 项后端隔离测试通过；7 项浏览器测试通过（新增内部编号隐藏用例）；前端生产构建通过，保留既有体积警告。主系统真实模型大纲验证通过，服务已重启加载修改。本次未重复生成正文。

应用 MCP 注册 10 个业务工具：rag_search、web_search、organize_report_content、draft_report_outline、submit_report、query_report_job、cancel_report_job、select_workspace、update_working_memory、plan_course_knowledge。最后一项仅对具有课程上下文的教师或管理员开放；检索工具还检查对应服务是否可用。Skill 加载器不计入该业务工具数量。

## 大纲显示一致性与对话字体（截图 image copy 13.png）

原链路将 Harness 模型的 text-delta 直接显示，再以工具保存的 markdown 替换最终消息。模型可能重新表述章节，造成生成结束前后的大纲不同。现在工具成功生成大纲后，后端不再转发模型重新表述的文字；前端从大纲工具开始调用起只显示进度，最终展示保存的大纲，确认版本及正文提交仍引用同一份存储记录。普通对话继续流式显示，不改用意图关键词匹配。

对话 Markdown 的各级标题继承普通段落字体、字号、字重和行高，不再放大加粗；保留语义层级和编号。报告资料预览样式不受该对话样式修改影响。

后端新增回归模拟“工具保存大纲后模型另写不同章节”，验证不泄漏第二版文字，最终消息与已展示版本绑定的存储大纲一致。浏览器新增用例核对正式大纲、标题与段落计算样式，以及后续确认回复不替换原大纲。

本轮结果：152 项后端隔离测试、8 项浏览器测试通过；前端生产构建通过（既有体积警告）。主系统前后端已重启，后端健康访问返回 HTTP 200。本轮未调用真实模型重复生成正文。

## 任务完成后的对话同步（截图 image copy 16.png）

补齐三处缺口：最终结果带任务编号但没有 task_submitted 事件时，前端仍建立任务跟踪；持久化任务与对话消息的关联，打开历史对话时按授权任务状态投影消息并恢复运行中任务的跟踪；任务账本已成功而结果接口尚未提交完成状态时继续同步，不提前丢弃跟踪。

旧 Harness 对话使用持久化请求及最终回复的精确、无歧义匹配恢复关联，不匹配“开始”等意图关键词。读取任务时校验所有者，不修改原始历史记录；新消息直接使用保存的消息编号关联任务。模型现有 planning_context 已包含任务实时状态，继续保留，未增加模型调用来模拟完成通知。

验证：155 项后端测试通过；正式 Nginx 页面上的 9 项浏览器测试通过，进一步增加结果接口延迟完成情形并复测通过。现有真实已完成报告可正确投影为“任务已完成”，未重放任务或生成新报告。正式前端构建已更新。
