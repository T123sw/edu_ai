## 问题与实现

旧流程先生成含 before/after 的教学计划，再改造 HTML。计划步数和真实算法状态机可能不同，例如交换后索引未推进，下一条解释却已经描述另一对元素。

新流程保持 MAIC-UI：科学建模 → 完整探索 HTML → 仅动作设计 ActionPlan → 演示 HTML → 练习 HTML → 实际执行记录驱动的 Narration → 拼装。正常 6 次模型调用，比旧流程多一次讲解生成；不增加模型审查，也不恢复预测终态严格比对。

- 演示 `next` 返回实际 `action_id/done/facts`，本地浏览器执行到真实 done，记录每次 before/after。最终步骤来自该轨迹，而非设计动作列表的长度。设置 256 次执行保护，避免生成代码死循环，不限制教学题数。
- 后置讲解按宿主 demo id 绑定实际轨迹。模型多写的步骤不进入结果，顺序变化不改变绑定；缺失或无法解析的文字使用通用提示，不能串用其他步骤。
- 练习页面注册实际动作目录，并返回 `action_id/verdict/facts`。后置模型根据目录和最终代码生成反馈模板，运行时填入实际参数及状态，不调用模型即时判题。仅支持普通字段替换，未知字段或模板语法安全降级，不执行表达式。
- 回看和重播重新执行真实动作；完成依赖 done。错误操作只回退本次变化，之前正确进度保留。
- 旧协议与旧实验保留兼容；旧未完成草稿只复用科学模型和完整探索页，重新生成动作与教学页；新草稿可从讲解阶段续跑。
- 教学 Skill 仍独立预留。动作目录保存在 design.action_catalog，用户实际动作 ID、facts、前后快照进入原有事件历史；冻结提问上下文及只读工具可以读取这些数据。
