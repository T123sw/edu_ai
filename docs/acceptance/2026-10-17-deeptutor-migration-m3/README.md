# DeepTutor 迁移 M3：仿卷结构与恢复

日期：2026-10-17。M3 主体改造已实现，整个阶段尚未验收，未部署，`exam_ready=false`。保留固定版本上游的完整源码、Explore/Plan/Quiz、工具和运行层，没有改成简化出题器。

## 实现

- 生成第一题前冻结 `ExamBlueprint`，记录原文档 ID、原件及解析正文 hash、原编号、顺序、分区、考点、来源行、已知页码、选项键、空位、图片和递归子题。后端从独立私有事件持久化，不允许终态结果改写蓝图。
- 去掉抽题前 15,000 字符截断。按完整行和重叠窗口读取全文；跨窗口未完成题补读完整范围，原题编号重复时用来源位置去重。缺失行号最多修复一次，无法解决的残题明确失败。
- 仿卷支持多选、不同数量的选项、多个填空和复合子题。未知题型、空题、丢失资产不静默转成 `written` 或忽略。
- 原生成和修复入口都携带用户要求、参考题、蓝图和图片。单独模型调用核对实际考点、实质性变化、答案与要求；一次修复后仍失败就保留问题状态。已知不支持视觉的模型不能承担题目关联图片的解读。
- 保存成功题检查点。显式任务重试沿用原请求的私有 lineage，保留全部成功题；重写失败位置时，把前后已成功题都作为避重上下文。新请求、其他用户、变化的输入/模型/补丁版本不会复用。服务固定使用启动时验证的补丁版本。
- 后端检查来源绑定、逐题 ID 与顺序、题型、选项、填空及子题结构；缺题、重复题、改写蓝图、未通过单题检查均不能以“总数够了”报成功。答案仍留在内部接口和私有记录。

补丁为累计 `0003-exam-blueprint.patch`；旧的 0001、0002 保留用于识别升级，不能和 0003 叠加应用。当前版本与 SHA 见 [源码校验](source-verification.json)。没有部署新服务或改写用户考试数据。

## 真实样本与验收边界

样本是 [两页合成试卷](sample-paper.txt)：10 道单选、5 道填空。通过现有模型快照、持久任务处理器和真实独立服务调用已配置的模型。解析使用显式 `pypdf-validation-only`，不是生产 MinerU 降级；此前 MinerU 返回 401 的问题没有解决。

最终固定版本实测：首轮约 **91.21 秒**，37 次模型调用，12 题通过、3 题未通过。一次显式重试约 **22.92 秒**，10 次模型调用；12 道成功题的内容和元数据完全不变，只重写第 11、13、14 题。重试后自动检查为 15/15，通过独立结构核对并保存内部生成结果。

**这不是整卷质量验收通过。** 逐题复核又发现：第 1 题选项答案成立，但解析把枢轴下标 5 说成 6，并算错两侧元素数量；第 3 题声称给定数组是最大堆，实际父节点 10 小于子节点 20，前提不成立；第 11 题仍有近似原题的问题。确定性计算与原题证据见 [人工复核及计算](manual-quality-audit.json)。自动核对仍存在误放行，不能将该样本发布为已验收考试。

详细结果见 [验证汇总](verification.json)、[真实运行测量](real-generation.json)、[首轮结果](mimic-result.json)和[重试结果](mimic-retry-result.json)。测试未写生产任务、个人文档或考试；临时服务和数据库在结束后清理。

开发中发现并保留了模型核对的反例：

- [早期两题样本误放行](earlier-false-positive.json)：填空题仍在问原来的归并排序复杂度，题干还泄露公式，但自动核对判为通过。
- [早期 15 题样本问题](earlier-fifteen-issues.json)：基数排序题把首个数位排序的不稳定性错误推广成必然破坏最终数值顺序，自动核对未发现；另两题因近似原题被拦下。
- [早期重试测量](earlier-retry-measurement.json)：当时只复用成功前缀，修复前题导致后续成功题重生成；现已改为先装载所有成功位置，再重写失败位置。

后续增强了要求具体差异证据和独立答案核对的提示，并修复完整检查点复用。这些改动不等于模型能可靠判定所有题目正确性，也不能用一次成功样本证明任意试卷稳定生成。
