# 教案请求被旧报告引用带入修改流程（2026-09-09）

用户在保存《数组的实现》报告修改后发送“帮我生成数组的实现的教案”。后端 05:46:12 UTC 收到请求，05:48:37 左右完成处理。会话实际返回“按要求将报告调整为教案”的未保存修改稿，未提交 generate_lesson_plan 任务。因此本次是流程进入错误且同步修改等待约 145 秒，不是教案后台工作器卡死。

## 原因

- 引用或待处理修改稿存在时，入口进入 ArtifactRevisionService，绕过 Harness 资源规划。
- 修改 Skill 的动作只有阅读、澄清、修改、保存、放弃，且预设用户正在修改文档。模型没有“新建资源”的合法交接动作，只能对报告打补丁；资料类型仍是报告。
- 独立的界面错误：生成工厂请求最近资源使用 `sort=created_desc`，材料接口只接受 updated/name 排序，日志反复出现 422。该错误影响列表，不是这次错误修改报告的根因。

## 修复

- 修改 Skill 先判断当前意图，提供模型决定的 `new_resource` 动作，不用关键词匹配新建/编辑。
- 新建意图交回 Harness，沿用原始本轮问题。原引用的授权内容可作为参考，不能成为编辑指令；旧修改稿保留为 suspended_artifact_revision，不自动保存或删除；用户重新选中原文档时可恢复旧稿继续修改。
- 交接后清除当前修改模式与前端旧引用，使教案方案的后续确认进入生成流程；直接生成类资源同样在进入后台等待前清理引用。
- 生成工厂使用材料接口支持的 `updated_desc` 排序，修复最近资源列表 422。
