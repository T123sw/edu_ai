# 教案快速方案与后台生成交互验收

日期：2026-09-09。

## 改变了什么

原流程在展示教案方案前，串行组织内容、审阅组织、生成方案、审阅方案；确认虽然已提交 durable job，前端仍等整段模型回复结束才释放输入。

现在模型根据当前意图直接调用教案方案工具，不需要 organization_id；一次生成可观察目标、总课时及每个环节的时长、教师活动、学生任务和评价概述。结构和时长之和仍即时校验，独立的知识正确性、目标覆盖与任务量核验在后台完整教案中完成。Skill 明确区分方案和成品，不把教学方案变成报告式知识标题，也不声称简洁方案已独立审阅。

用户后续确认才提交指定版本；同轮刚生成/修改的方案不能提交，重复确认幂等复用任务。新建、修改、暂停、切题和确认仍由模型理解，没有新增口令或关键词匹配。用户开启的检索要求、来源范围与权限校验仍执行。

任务提交事件到达即绑定后台任务、恢复输入并显示可继续交流；后台阶段更新对应消息，完成后自动读取结果。模型迟到的文字、状态或回复流断开不覆盖任务，也不覆盖后续对话；最终回复不能再次清空用户随后选择的文档引用。结果重放/无提交事件的传输仍保留兼容处理。

同一课程、同一范围内恢复之前模型选择的资料归属，并重新校验权限与目录；用户切换范围时不覆盖其选择。提交后的模型回复尚在收尾时，下一轮会话最多短暂等待 10 秒取得锁，避免刚恢复输入就返回会话忙；其他只读锁默认行为不变。

完整生成仍使用原有深度审阅与最多两次修订，不降低质量标准，也不把移到后台等同于总生成耗时消失。

## 验证

- 后端相关回归：154 项通过，含快速方案单次调用、必需检索、时长校验、后续确认、幂等提交、范围恢复和连续消息串行保存。
- 对话状态保护单测：17 项通过。
- 七类资源提交交互及后台异常浏览器测试：9 项通过。
- 延迟回复与断流两种情形，在 5 种窗口尺寸验证：10 项通过。用户可在前一个回复流仍打开时发送下一条消息，任务完成消息与下一条回答均保留。最终引用保护/运行状态调整后再测这两项：2 项通过（与上述用例重叠）。
- 前端构建与 git diff --check 通过。
- 真实模型与 HTTP：教案方案 → 暂停问答 → 修改为 12 分钟 → 英文确认 → durable job → 生成 → 审阅 → 修订 → 复审 → 保存 → API 读取校验 → 模型查询 → 浏览器原生预览，全部通过。真实任务成功，最终内容的审阅记录与内容版本匹配。

## 实测耗时与边界

首轮完整链路中，首次教学方案约 25.7 秒返回；该次方案实际生成调用约 6.7 秒。确认后约 28.8 秒收到任务提交事件，整段回复约 32.6 秒结束。这次采样发生在增加资料归属恢复之前，确认包含一次范围未恢复的工具失败及模型重选，不把它当作最终优化后的提交性能。

最终代码另做真实 HTTP 方案验收：只调用 select_workspace 和 draft_resource_outline，无预组织/独立方案审阅，约 43.9 秒返回；其中方案生成约 5.4 秒。模型规划及网络耗时仍有波动，不能承诺固定几秒。该补充样本只验证到待确认方案，没有再次生成正文。

完整后台任务约 423.4 秒：初稿 17.8 秒、第一次审阅 187.6 秒、修订 13.7 秒、第二次审阅 204.0 秒。此次主要收益是缩短展示前的串行步骤和解除交互等待；后台深度审阅仍需数分钟。语义选择与权限恢复由测试覆盖，不能将单个数组主题样本推广为所有学科质量保证。
