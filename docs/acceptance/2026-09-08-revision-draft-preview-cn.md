# 文档中的迭代修改预览

本次替代“先口头讨论方案、确认后提交修改任务”的交互。模型读取目标文档后直接产生未保存修改稿；右侧完整文档用黄色标出定位上下文，红色删除线展示拟删除片段，蓝色下划线展示拟新增片段。按 Markdown 块比较，代码围栏保持完整。对话说明修改原因与优势，询问是否保存或继续调整。关键目标歧义仍先澄清。

后续修改基于当前修改稿，差异始终比较最初基准原文。修改稿保存在当前账号、当前会话的 pending_operation 中，刷新可以恢复；不增加资料版本，不创建生成任务。保存按钮提交 draft_id/revision，过期草稿不能保存；确认保存直接使用已展示内容，不再次调用模型生成正文。支持对话中明确保存，也支持放弃当前修改稿；保存后创建带“（修改稿）”标题的独立新文档，原文档保持不变。新文档从 v1 开始，记录来源文档标识、版本和哈希；重复保存请求返回同一文档。保存时沿用权限、基准版本/哈希、结构校验检查，不覆盖外部新版本。

预览显示在生成工厂区域并适配桌面和抽屉布局。保存或放弃后刷新文档内容，账号/会话不匹配时不显示其他修改稿。长文档仅滚动右侧到修改区域，对话位置不变。取消后的旧修改稿不会因刷新重新出现。

初版验证（当时保存为同一资料的 v2，后续已调整为独立文档）：159 项后端回归通过，后续保存/放弃边界的 16 项定向检查通过；三种窗口尺寸的修改稿浏览器流程通过，后续与原文件引用/预览合并验证 8 项通过；前端构建、技能格式与 diff 检查通过。真实模型使用独立合成文档完成原文问答、生成修改预览、确认保存：预览保持 v1，保存生成 v2，其余文字及 v1 内容不变。未修改用户实际报告。证据见 [live.json](evidence/2026-09-08-revision-draft/live.json)。

后续调整：右侧最近生成列表合并当前用户的已保存资源与生成任务，按创建时间排序，按资源标识去重。保存后、返回工厂和刷新后均可读取修改稿，点击后在右侧查看，可继续引用。对话不再显示额外的保存结果卡片。

独立文档保存验证：99 项后端回归通过；补充列表与重复保存断言后，16 项定向检查通过。1366、1920、1024 三种宽度共 12 项浏览器检查通过，覆盖修改、保存、刷新、原文/修改稿分别打开与引用；前端构建和技能格式检查通过。本次未调用真实模型或修改用户文档。
