# 文档中的迭代修改预览

本次替代“先口头讨论方案、确认后提交修改任务”的交互。模型读取目标文档后直接产生未保存修改稿；右侧完整文档用黄色标出定位上下文，红色删除线展示拟删除片段，蓝色下划线展示拟新增片段。按 Markdown 块比较，代码围栏保持完整。对话说明修改原因与优势，询问是否保存或继续调整。关键目标歧义仍先澄清。

后续修改基于当前修改稿，差异始终比较最初基准原文。修改稿保存在当前账号、当前会话的 pending_operation 中，刷新可以恢复；不增加资料版本，不创建生成任务。保存按钮提交 draft_id/revision，过期草稿不能保存；确认保存直接使用已展示内容，不再次调用模型生成正文。支持对话中明确保存，也支持放弃当前修改稿；保存后新增同一资料的版本，保留原版本副本。保存时沿用权限、基准版本/哈希、结构校验和 CAS 保护，不覆盖外部新版本。

预览显示在生成工厂区域并适配桌面和抽屉布局。保存或放弃后刷新文档内容，账号/会话不匹配时不显示其他修改稿。长文档仅滚动右侧到修改区域，对话位置不变。取消后的旧修改稿不会因刷新重新出现。

验证：159 项后端回归通过，后续保存/放弃边界的 16 项定向检查通过；三种窗口尺寸的修改稿浏览器流程通过，后续与原文件引用/预览合并验证 8 项通过；前端构建、技能格式与 diff 检查通过。真实模型使用独立合成文档完成原文问答、生成修改预览、确认保存：预览保持 v1，保存生成 v2，其余文字及 v1 内容不变。未修改用户实际报告。证据见 [live.json](evidence/2026-09-08-revision-draft/live.json)。
