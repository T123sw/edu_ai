# 多步骤 PBL 接入验收

用户入口保持「互动实验 → 编程练习（PBL）」。输入项目目标，系统调用 `build-pbl-project` Skill 完成计划、审阅、逐步材料与检查制作，真实执行参考代码、前一步代码和故意错误代码；累计检查通过才发布。快速排序仍使用原来的单步算法流程。

项目共用一个 Sandpack 工程，左侧切换步骤只切换教程和检查范围，不覆盖代码。每步检查包含前序功能，结果绑定整份代码快照；编辑后提示复查。保存、离线草稿、冲突备份和「我的项目」沿用原持久化。

本轮支持本地 React 页面（App.jsx + styles.css），不支持依赖后端、外部 API 或额外第三方库的工程；运行能力不匹配时明确拒绝，不虚构可执行项目。

验证：

- 后端完整 PBL 测试：102 项通过，包含独立 PostgreSQL 的保存竞争与租约，以及旧算法浏览器运行器。
- 新浏览器检查器：3 项通过，覆盖真实 DOM 点击、错误实现、检查间隔离、主机模块拒绝与网络阻断。
- 新项目页面：2 项通过，覆盖同工程切步、预览、检查失效、离线刷新和手机布局。
- 真实模型计算器：4 步、11 项累计检查；初始骨架与故意错误均未通过，逐步参考和最终工程通过。
- 真实页面端到端：实际登录、PostgreSQL、逐步输入代码、服务端浏览器检查、官方 Sandpack 预览交互、除零恢复、故意破坏前序功能、刷新与手机布局，全部通过，见 `real-flow.json`。

参考实现仅存在后端私有检查点和 `/tmp` 验收夹具，不在公开项目产物中。页面检查是功能证据，不判定学生是否真正掌握知识。

部署状态与原入口回归见 `verification.json` / `deployment.json`。后端需要管理员重启 `edu-ai-backend` 才加载新接口；本轮 `sudo -n` 因需要密码未执行成功，未绕过权限重启。无需新增数据库迁移。
