# 需求理解引用与资料缺口修复

针对 [真实端到端失败记录](2026-09-18-intake-e2e-assessment.md) 修复两类问题：模型重复抄写 MinerU Markdown 导致引用校验失败，以及把资料未覆盖的内容当作用户不想学的范围。

## 实现

- 附件片段由程序切成带 `source_ref` 的原文段落；模型选择 ID，程序回填 `source_quote`。引用绑定 document ID、版本、内容哈希、片段偏移和原文，其他文档/版本/片段的 ID 不可冒用。
- 最终需求中的附件依据继续引用已核验要点的 `source_ref`，不再次生成引文。用户要求仍校验本次原话。兼容旧检查点中的原文引用，并为旧要点生成稳定 ID，不强制重新理解已完成附件。
- 错误提示指出具体 requirement 或 point，未知 ID 和错误文档归属均被拒绝；不通过模糊匹配放宽原文校验。
- 附件理解与 brief 增加 `material_gaps`，与用户 `exclusions` 分开；Skill 和工具字段说明要求保留原目标，禁止借 assumptions 将资料缺失改成课程范围排除。研究阶段将无法补齐的缺口写入 limitations，不能声称资料已完全覆盖目标。
- 前端需求理解结果单独显示“资料缺口”。没有增加复审模型调用、确认步骤或数据库迁移。

## 验证方法

沿用失败测试的 DOCX 内容、用户原话、空全局记忆及真实 MinerU/DeepSeek。执行真实上传和任务 API、文件权限/版本存储、记忆读取、Harness Skill、SQL 计量和 runner，直到研究读取附件并保存带引用的汇总，停在 plan 入口，不生成课程。

应用身份和存储在独立测试环境，不访问真实用户文件，也不是生产登录页的浏览器测试。全局记忆前后为空；非空记忆冲突不由这个样例证明。

新增单元验证覆盖 Markdown 转义原文回填、跨版本和跨文档引用拒绝、空白依据拒绝、旧要点兼容，以及引用和资料缺口向研究阶段传递。

首轮探索已跑通业务交接，但测试脚本错误地要求 `research_summary.unresolved_gaps` 非空；现有增量汇总工具通过 `limitations` 表达材料限制。修正断言后仍发现自然语言中的范围缩减，因此继续收紧 assumptions 和研究概述规则。最终验收以最后一轮完整执行及人工核对为准，未用此前探索结果宣称全部修复。

## 最终结果

最终完整测试通过。需求理解正式保存 brief，附件理解和需求归纳各执行一次，无引用重试；随后 ingest、研究读取和汇总实际完成，停在 plan 入口。原始[执行报告](artifacts/2026-09-18-intake-reference-fix/report.json)、[正式 brief](artifacts/2026-09-18-intake-reference-fix/brief.json)、[研究汇总](artifacts/2026-09-18-intake-reference-fix/research_summary.json)和[指标](artifacts/2026-09-18-intake-reference-fix/metrics.json)均已保存。

| 指标 | 修复前失败样例 | 最终重跑 |

完整执行到研究汇总共 **155.18 秒**。单次样例的时间和 token 数不代表普遍性能保证。研究阶段另有 3 次 function-calling 协议错误和 1 次重复结论提交，已由原有机制恢复，见指标记录；不能将“需求理解零重试”表述为整个研究流程零重试。

研究汇总以“资料尚不足以完整达成用户目标”开头，保留可运行助手的目标及尚缺的 SDK/鉴权/消息格式等信息。测试证明能够交接到研究阶段，不代表这些技术资料已经补齐，也没有验收最终课程生成。

最终代码回归 **194 passed、78 skipped**，针对性测试 **46 passed**，Skill 格式校验与前端生产构建通过。
