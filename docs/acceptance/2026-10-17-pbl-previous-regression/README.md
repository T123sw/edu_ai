# PBL 在设计新增验收前执行前序回归

最终全量测试 196 项通过、6 项跳过。从零真实生成通过：4 个步骤、11 项累计检查，11 次模型调用（正常 9 次加一轮代码/验收修复），121.48 秒。下面保留此前失败证据，未将测试中的失败尝试省略为“首次全部通过”。后端重启需要管理员密码，新流程尚未激活。

每步现在按“生成并保存代码 → 程序运行前序检查 → 设计本步验收 → 运行累计检查”推进。前序回归失败只调用代码修复，输入同时保留前一步累计代码、本步失败代码、原有检查及逐项运行证据；通过后才调用验收模型。首步没有前序检查时明确标记跳过。

验收模型能读取需求、完整计划、本步实际代码、前序累计代码、全部前序检查和绑定源码哈希的回归报告。已有需求可以复用前序检查覆盖，本步新增检查不必重复全部前序需求；未覆盖的新需求不能借用未来检查。前序检查保留，本步错误的定位、动作和断言仍允许修复。

真实回放发现“正确代码可以保持不变”的提示容易让模型把代码中的定位缺陷也留给验收阶段。修复提示现区分前序回归与本步验收错误：旧文字目标受新增子控件影响时调整部件边界与标记；重复控件缺少可区分目标时，可以保留旧 testId 并补充可访问名称。这些均为通用 DOM 语义，没有项目关键词分支、专用答案或新模型审阅调用。

正常 N 步仍为 1+2N 次模型调用，增加的是程序运行前序检查。原有修复上限不变。验收模型/运行环境中断后保留代码，恢复时重新执行前序检查；失败不发布，取消与租约保护仍生效。生产任务、用户代码和学习记录没有被测试修改。
