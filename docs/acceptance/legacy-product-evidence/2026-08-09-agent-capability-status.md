# 教师端 Agent 能力现状与端到端验收基线

日期：2026-08-09
范围：教师端问答、RAG、Web 检索、资源生成工具调用与耐久任务落库
结论：基础工具型 Agent 已达到本阶段目标；PPT 按产品决策延期，不计入本轮失败。

## 1. 本阶段能力结论

Agent 目前能够完成以下基础任务：

- 普通问答；
- 指定文档 RAG；
- 使用知识库全部数据进行 RAG；
- Web 检索；
- RAG 与 Web 联合检索；
- 通过对话生成报告、教案、练习题、教学博客、闪卡、思维导图、课堂小游戏和 AI 课堂；
- 在报告/教案生成前展示大纲并等待确认；
- 在用户要求“先查网络再生成报告”时，先完成 Web 检索，再调用报告工具；
- 将 Web/RAG 证据传入报告正文生成，并记录来源数量和 grounding 状态；
- 将资源任务提交到统一后台任务中心，等待最终材料落库。

本阶段不以复杂自主推理为目标。当前设计优先使用确定性护栏保证工具是否调用、调用顺序、确认边界和任务终态正确。

## 2. 实测环境与验收口径

- API：`http://127.0.0.1:8000`，第二实例 `http://127.0.0.1:8001`；
- 课程：`computational-thinking`；
- 身份：本机教师账户；
- 模式：真实鉴权、真实 SSE 对话、真实模型、真实 Bocha Web、真实 RAG、真实后台 Worker、真实材料落库；
- 验收不以“收到 202”或“出现工具名”为成功：必须同时满足正确规划顺序、成功工具结果、Job 终态 `succeeded`、`result_ref` 存在及材料可读取；
- Web→报告还额外检查 Job 快照中的 `research_context`/`research_sources`，以及最终材料 `generation_state.grounding`。

## 4. 已落地的确定性护栏

### 4.1 检索优先

只要用户在界面启用了 RAG 或 Web，检索就是执行指令而不是“可选工具”。检索步骤固定为计划第一步，不依赖模型把后续步骤识别为 `answer_question`、`generate_resource` 还是 `other`。

这解决了原先“已勾选文档，但 Agent 先生成回答、检索被排在末尾”的问题。

### 4.2 大纲确认边界

报告、教案和 PPT 首轮只能完成检索、大纲与确认展示。首轮计划中的 `generate_*` 会被移除；生成工具在用户确认后的下一轮才可见。

这避免了模型在同一轮自行起草大纲后立即提交不可逆后台任务。

### 4.3 明确资源类型优先

用户明确说“教学博客、闪卡、思维导图、小游戏、AI 课堂”等资源类型时，关键词分类结果覆盖模型的概率性分类，并生成对应的单步资源工具计划。

这解决了“教学博客被误规划成报告大纲”的问题。

### 4.4 Web/RAG 证据进入报告

`web_search`、`rag_search` 的摘要与来源会从当前工具上下文进入报告命令；生成 Worker 同时合并知识库解析正文和对话检索证据。最终材料记录：

- `knowledge_base_context_used`；
- `retrieval_context_used`；
- `research_source_count`。

真实 Web→报告任务携带约 5KB 研究上下文和 10 条来源，最终正文出现来源引用，`retrieval_context_used=true`。

### 4.5 模型故障切换

Agent 规划器和执行器现在与报告正文生成一样具备模型故障切换。本机主模型账户当前返回欠费类 HTTP 400，但 Agent 能自动切换到已配置的 OpenRouter/DeepSeek 兼容模型，避免退化成绕过工具的直接回答。

## 5. 本轮发现并修复的问题

1. Agent 规划器/执行器没有模型 fallback，主模型 400 时直接走文本回退，资源工具完全不调用；
2. Web 调用顺序表面正确，但检索结果没有进入报告任务与正文；
3. 选中文档后，非标准计划步骤会让强制 RAG 落到计划末尾，Agent 先回答后结束；
4. 模型可能跳过大纲确认，在首轮直接提交报告；
5. 教学博客等资源会被模型误分类成报告流程；
6. Agent 原先只暴露报告、PPT、教案、练习题，缺少博客、闪卡、思维导图、小游戏和 AI 课堂；
7. 初版验收脚本读取旧版 `/api/chat/tasks` 紧凑状态，误判 Web 上下文缺失；已改为读取教师后台任务实际使用的 `/api/jobs/{id}` 账本。

## 6. 当前限制与后续优化重点

### P0：运行配置

- 修复主模型供应商账户状态。当前 fallback 可用，但主模型持续失败会增加首轮延迟，并削弱故障冗余。

### P1：证据泛化

- 报告和 AI 课堂已经实际消费 Web/RAG 研究上下文；其他资源虽然会先检索并在命令快照中保存研究上下文，但各生成器对 Web 证据的消费方式尚未统一；
- 应抽取统一的 `ResearchBundle`，让博客、练习题、闪卡、思维导图、小游戏和教案都使用同一份摘要、来源与引用规则；
- Web 来源当前存在博客、社区和聚合站点，缺少权威性排序、去重和来源分级；
- 报告提示词会要求保留来源标题/URL，但还没有强制结构化逐段引用和事实—来源覆盖率评估。

### P1：图文生成链路

- 当前报告支持图片搜索结果累积、审核、本地化与正文注入；博客和 AI 课堂有自己的视觉流程；
- 其他资源尚未统一使用“大纲/内容计划 → 图片需求 → Web/知识库找图 → 图片合格性审查 → 正文/资源装配”的视觉资产管线；
- 需要将图片来源、版权/可访问性、尺寸、相关性和最终使用位置纳入统一材料 provenance。

### P1：性能

- 普通资源通常为几十秒到数分钟；
- Web→报告实测约 80 秒；
- AI 课堂实测约 13 分钟，必须保留异步任务中心、进度展示、取消和重试，不应改成同步等待。

### P2：Agent 智能与评测

- 当前偏确定性工具编排，不追求复杂自主推理；
- 后续可增加资源参数抽取准确率、检索充分性、引用覆盖率、工具错误恢复、重规划稳定性和多轮编辑能力评测；
- 建议把本文矩阵作为 Agent 变更后的固定回归基线。
