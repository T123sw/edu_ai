## 1. 决策总览（已拍板）

1. **放弃数字人**：不再做唇形同步/虚拟人讲师。讲解形态 = 浏览器动画幻灯片 + 聚焦 + TTS 旁白。
2. **彻底放弃 html2ppt 和 AI_Lecturer**，改用 OpenMAIC 的课件/媒体能力。
3. **采用 OpenMAIC 的数据契约 `Stage / Scene / Action / Slide(@openmaic/dsl)` 作为课件源数据**，不再以 content_markdown 为源。
4. **复用方式 = Node sidecar（后端能力）+ 前端 npm 包（播放/聚焦/导出）**，edu_ai 负责编排、存储、业务、知识源。
5. **不照搬流程**：内容来源换成 edu_ai 自己的 RAG/教材/知识图谱；MP4 成片作为一等交付物自建（OpenMAIC 不提供）。
6. **统一入口 + 平行导出**：一个生成入口产出结构化课件，互动播放 / PPTX / MP4 都是它的平行导出物。PPT 不是视频的输入。
7. **优先级：先交互课堂，再 MP4。**
8. **MP4 走「先 A 后 B」**：A=无头实时回放录屏（MVP）；B=确定性逐帧渲染（产品化）。以 B 为目标，先落地 A，用 LessonTimeline 焊住。
9. **许可**：OpenMAIC 为 MIT，可 fork/改造/商用，保留版权声明即可。
10. **保留 OpenMAIC 的前端 API Key 配置页**（BYOK 自带 key + 服务端托管 的混合模型），含其安全边界；edu_ai 采用混合 key 模型（见 4.7）。

## 3. 从 OpenMAIC 搬什么、怎么搬

### 3.1 前端：直接引入 npm 包（MIT）

| 包 | 用途 | 必要性 |
| --- | --- | --- |
| `packages/@openmaic/dsl` | 数据契约（`slides.ts/action.ts/stage.ts/guards.ts`），纯类型零依赖 | **必引** |
| `packages/@openmaic/renderer` | `SlideCanvas` + 元素渲染 + 聚焦效果（`effects/SpotlightOverlay/LaserOverlay/ZoomWrapper/HighlightOverlay`）| **必引** |
| `packages/@openmaic/importer` | 上传 PPTX → Slide DSL（用户已有课件导入）| 可后置 |
| `packages/pptxgenjs`、`packages/mathml2omml` | 浏览器导出 PPTX（latex→OMML）| Phase 4 |

**搬运方式（建议演进）**：

1. 起步：把 OpenMAIC 作为 **git submodule**，前端 `package.json` 指向 workspace 包路径（或 vendor 复制源码为本地包）。最快，能立刻用。
2. 稳定后：fork 出来发到**私有 registry**，按版本消费，便于跟上游 diff。

> 播放编排逻辑（`lib/playback/engine.ts` + `lib/action/engine.ts`）也要一并搬到前端，但**要按第 6 章/时间线文档改造成「ClockSource 注入 + 消费 LessonTimeline」**，不要原样照抄实时态机。

### 3.2 后端：OpenMAIC 作为裁剪版 sidecar

复用它现成的 Next.js route（已核对存在）：

| sidecar 端点 | 复用实现 | 状态 |
| --- | --- | --- |
| `POST /api/generate-classroom` → 轮询 `pollUrl` | `lib/server/classroom-generation.ts`(574) + `classroom-media-generation.ts`(289) + `lib/generation/scene-generator.ts`(1746) | 开箱即用 |
| `POST /api/parse-pdf`（multipart: pdf/providerId/apiKey/baseUrl）| `lib/pdf/pdf-providers.ts`(379) + `mineru-cloud.ts`(339) | 开箱即用 |
| `POST /api/tts`（薄封装）| `lib/audio/tts-providers.ts`(953) 的 `generateTTS` | 需包一层 route |
| `POST /api/media/video`（薄封装）| `lib/media/video-providers.ts`(210) 的 `generateVideo` | 需包一层 route |
| `/api/verify-*-provider` | 已存在 | 开箱即用 |

**裁剪/容器化**：保留 `app/api/*`、`lib/*`、`packages/*`；去掉与 edu_ai 重叠的页面 UI（前端在 edu_ai 自己做）。用仓库自带 `Dockerfile`/`docker-compose.yml` 起服务，配 `.env`。

### 3.3 .env（sidecar，全在线 API，无本地权重）

最小闭环先配：

```
DEFAULT_MODEL / <LLM>_API_KEY / <LLM>_BASE_URL          # 1 个 LLM 即可启动
PDF_MINERU_API_KEY / PDF_MINERU_BASE_URL                # MinerU Cloud
TTS_<provider>_API_KEY / TTS_<provider>_BASE_URL        # 1 个在线 TTS
```

后续按需开图片/视频 provider（`IMAGE_* / VIDEO_*`）。完整变量名见 v2 文档第 2.1 节。

## 4. 接口设计

### 4.1 sidecar 对外契约（edu_ai 调用）

**生成课件（统一入口 + feature flags）**

```
POST /api/generate-classroom
body: {
  requirement: string,                 // 需求文本
  pdfContent?: { text, images[] },     // 或解析后的教材
  researchContext?: string,            // ★ edu_ai 注入的 RAG/教材/知识图谱片段（见 4.6）
  enableImageGeneration?: bool,        // L? 媒体
  enableVideoGeneration?: bool,
  enableTTS?: bool,                    // L3 配音
  agentMode?: 'default'|'generate'
}
→ 202 { jobId, pollUrl, pollIntervalMs }
轮询 GET {pollUrl} → { step, progress, message, ...，完成时含 stage + scenes[] }
```

生成深度由 flags 控制（同一条流水线、同一份结构化数据）：

| 深度 | flags | 产物 |
| --- | --- | --- |
| L1 只要课件 | 全关 | Slide DSL → PPTX |
| L2 要讲解 | +actions | 互动播放（含聚焦）|
| L3 要成片 | +media +TTS | → MP4 |

**解析文档**

```
POST /api/parse-pdf  (multipart: pdf, providerId='mineru'|'mineru-cloud'|'unpdf', apiKey?, baseUrl?)
→ { data: { markdown, images, content_list, metadata } }
```

### 4.2 edu_ai ↔ sidecar Python 客户端

edu_ai 侧写一个 `OpenMaicClient`（httpx），方法：`generate_classroom() / poll_job() / parse_pdf() / tts() / video()`。统一处理超时、重试、错误码。把 sidecar 的 `jobId/poll` 适配到 edu_ai 自己的任务表。

### 4.3 核心数据契约（直接用 @openmaic/dsl，不自造）

```
Stage   { id, name, languageDirective, videoManifest, agents, style }
 └ Scene[] { id, type('slide'|'quiz'|'interactive'|'pbl'), order, content, actions[] }
     content(slide) = Slide { viewportSize, viewportRatio, theme, elements: PPTElement[], background }
       PPTElement = text|image|shape|line|chart|table|latex|video|audio|code（均带稳定 id + 几何）
     actions: Action[] = speech|spotlight|laser|play_video|wb_*|widget_*
```

> 取代 v1 设想的自建 TeachingDeck/TeachingAction —— 直接用上游契约，随上游演进。

### 4.4 LessonTimeline 契约（视频导出共享地基）

`Scene.actions[]` 编译成显式多轨时间线 `Lesson → SceneSegment[] → TimelineClip[]`，每 clip 有 `startMs/durationMs/track/durationSource`。**A 用观测填充、B 用预算填充，契约不变。** 完整定义见时间线文档第 1–4 章。

### 4.5 异步任务模型（全系统统一）

复用 sidecar 的 `{jobId, pollUrl, pollIntervalMs}` + `{step, progress, message}`。edu_ai 的 PPT/解析/视频/知识图谱长任务**统一成这一种协议**，前端统一展示阶段进度。

### 4.6 内容来源注入（这就是「不照搬」的关键）

OpenMAIC 默认来源是 web search + PDF。edu_ai 把自己的 **RAG 检索片段、教材正文、知识图谱节点、本地化图片** 拼成 `researchContext` 注入大纲/场景生成阶段。即「**OpenMAIC 流水线骨架 + edu_ai 知识源**」。

### 4.7 Provider 与配置层（含前端 BYOK 配置页 —— 保留）

mineru、LLM、TTS、图片、视频**全部走同一套 provider 配置 + key 解析**，所以这是**贯穿所有阶段的横切层**，不归属某一桶：服务端部分跟 mineru 一起先搭最小版，前端配置页随交互课堂（Phase 3）出现，之后每接一类 provider 就往里加一项。

OpenMAIC 这块设计值得**整体保留** —— **BYOK（用户自带 key）+ 服务端托管** 的混合模型：

- 用户可在**前端配置页**填自己的 provider key，按请求带给后端；配 `verify-*-provider` 端点实时校验连通性（参考 `components/settings/*-settings.tsx`、`app/api/verify-*-provider`）。
- 运营方可在 `.env` / `server-providers.yml` 配「托管 provider」，此时**忽略客户端传入的 key**（`isServerConfiguredProvider`），并对客户端 baseUrl 做 **SSRF 校验**（`validateUrlForSSRF`，生产环境）。
- ⚠️ **保留配置页 = 一并保留这套安全边界**（托管优先 + 忽略客户端 key + SSRF），两者一体，不能只要页面不要边界。

**edu_ai 的 key 模型决策（推荐：混合）**：运营方配默认（MinerU + 默认 LLM 等），用户可选覆盖/补充自己的 key。前端配置页 + `verify-*-provider` 端点可直接复用。两个极端——纯服务端（自营简单、key 不暴露）/ 纯 BYOK（自助多租户）——按业务取舍。

## 6. 视频导出（先 A 后 B）——摘要

详见时间线文档；这里只给收口要点。

### 6.1 A（MVP）：无头实时回放 + 录屏

把「生成任务尾部」追加一步：内容+TTS 完成后，**单独起一个无头 Chromium 干净 1x 回放**已生成课件并录屏。三条铁律：

1. **录专用无头回放，不录学生真实会话**（学生会暂停/打断/不看）。
2. **音频拼不录**：只录画面；音轨用预生成 TTS（`audioRef`）按事件时间戳放置后 mux。
3. **按 scene 分段录** → 可重试 + ffmpeg concat。

A 的副产物 = **视频 + 一份完整 LessonTimeline（durationSource='measured'）**，即 B 的输入。

### 6.2 B（产品化）：确定性逐帧渲染（Remotion 式）

满足任一即升级：吞吐撑不住 / 要广播级质量 / 编辑后要超实时重渲。

### 6.3 A 阶段就要留好的三个接缝（否则 B 要重写）

1. **ClockSource 注入**：播放器只认 `currentTimeMs()`。A=墙钟，B=虚拟帧钟。
2. **效果组件加可选 `localTimeMs` prop**（先加不接线）：A 让 framer-motion 实时跑，B 传入即帧驱动。把 B 最大工作量前置成「加一个入参」。
3. **视频元素始终走 `renderVideo` 插槽**：A 返回原生 `<video>`，B 返回 `<OffthreadVideo>`。

A 明确不做：帧驱动、动画帧化接线、OffthreadVideo、渲染农场。

## 7. 分阶段实施路线

> **三段式心智模型 ↔ Phase 映射**：常说的「**mineru → ppt → video**」对应——
> **mineru** = Phase 1；**ppt** = Phase 2（生成结构化数据）+ Phase 3（交互课堂，**聚焦/语音就在这里**）+ Phase 4（PPTX 导出）；**video** = Phase 5（A）→ B。
> 关键认知：**聚焦和语音讲解不是独立阶段，它们随 Phase 3 交互课堂一起到来**（时间线上的 spotlight/speech 动作），**不属于 video 阶段**。
> 另有一条**贯穿所有阶段的 Provider/配置层 + 前端 BYOK 配置页**（见 4.7）：服务端部分跟 mineru 一起先搭，前端页随 Phase 3 出现。

| Phase | 目标 | 关键交付 | 验收 |
| --- | --- | --- | --- |
| **0 立项/打底** | sidecar 可行性 | fork OpenMAIC → 裁剪容器化 → 配最小 .env | 本地 `POST /api/parse-pdf` 解析一份教材成功 |
| **1 解析替换** | 最独立链路先换 | edu_ai `OpenMaicClient.parse_pdf()`，替换 `scripts/mineru.py` | RAG 入库走 MinerU Cloud，结果对齐 |
| **2 课件生成** | 主链路接通 | 调 `generate-classroom`，注入 `researchContext`，落库 Stage/Scene | 用 edu_ai 知识源生成一节结构化课件 |
| **3 交互课堂** | A、B 共同地基 | 前端引 `@openmaic/dsl`+`renderer`；建 **LessonTimeline 编译器** + **ClockSource(墙钟)** 播放器；聚焦/语音/视频元素播放 | 在线播放一节课，聚焦+旁白同步，三接缝就位 |
| **4 导出 PPTX** | 可下载课件 | 接 `use-export-pptx` + pptxgenjs | 导出 PPTX，公式/备注正确 |
| **5 视频 A** | 自动出 MP4 | 无头回放录屏 + TTS 音轨 mux + 分段 concat + SRT；产出 LessonTimeline | 提交任务后台自动得到 MP4+字幕 |
| **6 下线旧模块** | 收口 | 删/归档 html2ppt、AI_Lecturer、teaching_video_bridge；更新部署清单 | 旧链路无引用，部署去 GPU |
| **B（择机）** | 产品化视频 | 帧驱动 ClockSource + 动画接 localTimeMs + OffthreadVideo + Remotion 分段并行 | 1080p 无丢帧、可超实时重渲 |

> Phase 1/2 可与 3 部分并行；3 是 A/B 的共同前置，务必扎实。
>

## 8. 关键细节与策略

- **id 不可变**：scene/action/element/clip id 稳定，编辑不重生成 → 支撑 B 增量重渲、A 分段、聚焦寻址、局部重生成。
- **并发语义**：sync 动作（speech/play_video/wb_*/widget_*）推进时钟；fire-and-forget（spotlight/laser）叠在伴随 speech 时间窗。源 DSL 的 spotlight **无 duration**，时长是时间线层派生（A 观测 / B 绑定 speech 时长），A、B 必须一致。
- **音频永远拼不录**：TTS 产稳定 `audioRef`；视频只录/渲画面，音轨另拼后 mux。
- **嵌入演示视频默认 mute**，旁白承载讲解；需要时按 `duckOnClipAudio` 处理。
- **MP4 是线性讲课版**：`discussion` 等 live-only 动作跳过或用预生成内容给固定时长；实时互动是播放器独有。
- **字幕**：speech 文本+时间线 → SRT/VTT 纯函数，A 即可支持。
- **安全边界**：若开放用户自配 baseUrl（MinerU/TTS），照搬 OpenMAIC 的 server-managed provider 忽略客户端 key + `validateUrlForSSRF`（生产）。
- **中文适配**：TTS 音色、slide 字体、公式/竖排需按中文实测；MinerU `language:'ch'`；`languageDirective` 已支持。
- **第三方 API 合规**：Seedance/Kling/Veo/MiniMax/ElevenLabs/MinerU 各有条款与计费，逐家确认配额与商用授权。
