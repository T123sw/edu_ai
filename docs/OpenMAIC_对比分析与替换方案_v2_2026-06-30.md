## 0. TL;DR（先看这一段）

1. **放弃决策成立。** OpenMAIC 在「PPT 结构化、聚焦、语音、视频、在线 Provider、PDF 解析」六个方向都是体系化的，edu_ai 现有 html2ppt（黑盒 markdown→外部服务）和 AI_Lecturer（Wav2Lip/LiveTalking/FFmpeg 本地重链路）确实是两套落后且割裂的实现，没有继续投入的价值。
2. **复用方式：Node sidecar + 前端包，而不是「塞进 FastAPI」。** OpenMAIC 是 TS/Next.js，edu_ai 后端是 Python。最现实的复用是把 OpenMAIC 当作一个独立 Node 服务（sidecar），edu_ai 后端通过 HTTP 调它的 `/api/generate-classroom`、`/api/parse-pdf` 等；前端直接引入 `@openmaic/dsl` + `@openmaic/renderer` 做播放/聚焦。
3. **一个必须正视的功能缺口：OpenMAIC 没有「数字人/唇形同步讲师」。** 我已全仓搜索，OpenMAIC 没有任何 Wav2Lip / avatar / talking-head 代码。它的「讲解」= 浏览器里幻灯片动画 + 聚焦 + TTS 旁白，不是一张会说话的人脸。如果 edu_ai 的卖点里有「数字人老师」，放弃 AI_Lecturer 等于放弃这个功能，需要单独决策（见 §6.1）。
4. **MIT 许可，随便用。** 可 fork、改造、二次封装、商用，仅需保留版权声明。
5. **MinerU 在线 API 真实可用。** OpenMAIC 已实现 MinerU Cloud v4 全流程（`lib/pdf/mineru-cloud.ts`），可直接照搬到 edu_ai 的 Python 端，或直接走 sidecar。

## 1. 为什么 html2ppt 和 AI_Lecturer 该放弃（事实依据）

### 1.1 html2ppt 的根本问题：黑盒、无元素级结构

`Edu_AI/api/src/app/chat/workflows/ppt/html2ppt_client.py` 证实，edu_ai 的 PPT 路线是：

```text
LLM 产出 content_markdown
  -> POST 给外部 html2ppt 服务（create_job_payload: content_markdown + theme_id + metadata）
  -> 轮询拿 PPTX / HTML / manifest
```

源数据是一段 markdown，最终产物是文件。系统拿不到「第 3 页第 2 个元素在哪、是什么」。后果是：聚焦、讲稿对齐、局部重生成、插入可控视频、做交互题——全都没有抓手。这不是「再优化一下 prompt」能解决的，是数据模型层缺失。

### 1.2 AI_Lecturer 的根本问题：本地重链路 + 重复理解 PPT

`Edu_AI/api/src/modules/AI_Lecturer/` 证实它依赖：

- `Wav2Lip_Offline/`、`LiveTalking-main/`（本地唇形同步，需 GPU）
- `assets/avatar_white.mp4`（固定数字人底板）
- `offline_video_maker.py` 里 `FFMPEG_EXE`、`subprocess` 合成

链路是「PPT 压成图片 → 重新生成讲稿 → TTS → Wav2Lip 数字人 → FFmpeg 叠加拼接」。两个致命点：(a) PPT 被压成图片后元素结构彻底丢失，聚焦只能靠后期特效硬怼；(b) 讲稿在视频阶段**重新生成**，和 PPT 生成阶段不是同一份脚本，改一页要重走整条 GPU 链路。

### 1.3 OpenMAIC 为什么是另一个量级

它不是「PPT 工具 + 视频工具」的拼装，而是一套**统一的教学场景模型 + 动作时间线**，PPT/聚焦/语音/视频/互动都消费同一份结构化数据：

```text
Stage（一节课）
 └─ Scene[]（一页/一个场景：slide | quiz | interactive | pbl）
     ├─ content（slide = 一份可编辑的 Slide DSL，含 PPTElement[]）
     └─ actions: Action[]（speech / spotlight / laser / play_video / whiteboard / widget ...）
```

`lib/playback/engine.ts` 注释明确写道：「Consumes Scene.actions[] directly via ActionEngine. **No intermediate compile step** — actions are executed as-is.」——讲解、聚焦、播放视频是同一条时间线上的动作，不是三套相互转换的产物。这正是 edu_ai 现在最缺的东西。

## 2. 四个重点方向的对比（均带代码证据）

### 2.1 全在线 API：部署门槛被打掉

OpenMAIC `.env` 里**每一种能力都是 `XXX_API_KEY + XXX_BASE_URL` 的 Provider 对**，没有任何本地权重：

| 能力 | Provider（来自 .env / 代码核对） |
| --- | --- |
| LLM | OpenAI、Anthropic、Google、DeepSeek、Qwen、Kimi、GLM、Doubao、Tencent、MiniMax、Grok、SiliconFlow、OpenRouter、Xiaomi |
| 图片 | OpenAI、Grok、MiniMax、NanoBanana、Qwen-Image、Seedream |
| 视频 | Seedance、Kling、Veo、Sora、MiniMax-Video、Grok-Video、HappyHorse（见 `lib/media/video-providers.ts`）|
| TTS | OpenAI、Azure、GLM、Qwen、MiniMax、ElevenLabs、VoxCPM（见 `lib/audio/tts-providers.ts`，953 行）|
| ASR | OpenAI、Azure、Qwen |
| PDF | MinerU(self-host)、MinerU Cloud、unpdf |
| 联网 | Tavily、Brave、Baidu、Bocha、MiniMax |

对照之下，edu_ai 的 AI_Lecturer 还绑死 `QWEN_API_KEY` + 本地 Wav2Lip/LiveTalking。**换成 OpenMAIC 路线后，「装显卡、配本地模型权重」这件事可以从部署清单里删掉。** 这对「换机器部署」（你 docs 里专门有 `换机器部署清单.md`）是质的简化。

### 2.2 PPT 生成：可编辑 Slide DSL 贯穿生成/渲染/导出/导入

核对 `packages/@openmaic/dsl/src/slides.ts`（964 行）后，OpenMAIC 的 PPT 是一套**完整的、可编辑的对象模型**，不是 markdown 副产物：

- `Slide`：`viewportSize` / `viewportRatio` / `theme` / `elements[]` / `background` / `animations[]` / `script`（演讲备注）。
- `PPTElement` 联合类型，10 种元素：`text / image / shape / line / chart / table / latex / video / audio / code`，每个都有稳定 `id` + `left/top/width/height/rotate` 几何。
- 这份 DSL 是「单一事实源」，三个消费方共用：
  - `packages/@openmaic/renderer`：浏览器实时渲染（含聚焦效果）。
  - `lib/export/use-export-pptx.ts`（1236 行）+ `packages/pptxgenjs` + `packages/mathml2omml`：导出 PPTX（latex 走 OMML 进 Office 公式）。
  - `packages/@openmaic/importer`：把**已有 PPTX 反向导入**成 Slide DSL（用户上传课件 → 系统获得可编辑结构）。

> 对 edu_ai 的意义：有了元素级稳定 id，「聚焦第 3 页那个公式」「让这句讲稿绑定那张图」「只重生成这一页」全部变成可寻址操作。这正是 html2ppt 给不了的。

### 2.3 视频 / 语音 / 聚焦：三者统一在 Action 时间线

这是 OpenMAIC 最该抄的设计。核对 `packages/@openmaic/dsl/src/action.ts`：

- **聚焦（focus）= 两个 fire-and-forget 动作**：
  - `SpotlightAction { elementId, dimOpacity }`：聚焦某元素、压暗其余。
  - `LaserAction { elementId, color }`：激光点示。
  - 实现是**前端实时几何计算**，不是视频后期特效。`SpotlightOverlay.tsx` 直接用 `document.getElementById('slide-element-'+id)` 拿 DOM 矩形，换算成 0–100 百分比坐标，用 SVG mask + framer-motion 画聚光罩。零 GPU、零渲染管线、零后处理。
  - 另有 `effects/LaserOverlay`、`effects/ZoomWrapper`、`effects/HighlightOverlay` 一整套。
- **语音（speech）= `SpeechAction { text, audioId, audioUrl, voice, speed }`**：音频**挂在动作上**。服务端 `generateTTSForClassroom`（`lib/server/classroom-media-generation.ts`）预生成 mp3 写盘，把 `audioUrl` 回填到 action；播放时 `PlaybackEngine` 执行到 speech 就放音频，没有就回退浏览器 TTS。还会 `splitLongSpeechActions` 把长句切短，逐句配音。
- **视频（video）= `PPTVideoElement`（slide 元素）+ `PlayVideoAction { elementId }`（时间线动作）**：视频是「课件里的一个媒体元素」，由在线 provider（Seedance/Kling/Veo…）异步生成、下载落盘、`mediaRef`/`src` 回填，播放时由 `play_video` 控制何时播。一个化学反应/算法演示就是 slide 里的一个 video，讲到那里自动播。

对照 edu_ai：聚焦只能在最终视频里做后期，语音埋在 AI_Lecturer 内部，视频是「整课导出的 MP4」而非课件元素。**三者各做各的、互不共享脚本。** OpenMAIC 把它们收敛成一条 `actions[]`，是结构性的领先。

### 2.4 MinerU：在线 Cloud API 已落地，可直接抄

核对 `lib/pdf/mineru-cloud.ts`（339 行），MinerU Cloud v4 全流程清晰可照搬：

```text
POST {base}/file-urls/batch   （body: files[].name, enable_formula, enable_table, model_version:'vlm', language:'ch'）
  -> 拿 batch_id + 预签名上传 URL
PUT 预签名URL 上传 PDF（注意：不能带 Content-Type，OSS 签名敏感）
轮询 GET {base}/extract-results/batch/{batch_id}  （每 2.5s，最长 15min）
  -> state=done & full_zip_url
下载 ZIP -> 解出 full.md + content_list.json + images/
  -> 统一成 ParsedPdfContent（markdown + images(base64) + content_list）
```

默认 `MINERU_CLOUD_DEFAULT_BASE`、env 用 `PDF_MINERU_API_KEY` / `PDF_MINERU_BASE_URL`。edu_ai 现在是 `scripts/mineru.py` 本地脚本，完全可以替换成调用 MinerU Cloud（或直接走 sidecar 的 `/api/parse-pdf`）。

## 3. 复用 OpenMAIC 的核心：先吃透它的数据模型

无论走 sidecar 还是搬包，**真正要复用的是这套数据契约**（全在 `@openmaic/dsl`，MIT，纯类型零依赖）：

```text
Stage      课程级：id, name, languageDirective, videoManifest, agents, style
  └─ Scene 场景级：id, type('slide'|'quiz'|'interactive'|'pbl'), order, content, actions[]
       content(slide) = Slide DSL
         └─ elements: PPTElement[]  // text/image/shape/line/chart/table/latex/video/audio/code
       actions: Action[]
         ├─ SpeechAction   { text, audioUrl, voice, speed }        // 语音讲解
         ├─ SpotlightAction{ elementId, dimOpacity }               // 聚焦
         ├─ LaserAction    { elementId, color }                    // 指示
         ├─ PlayVideoAction{ elementId }                           // 播放视频元素
         ├─ Wb*Action      { ... }                                 // 白板（写字/画形/公式/图表/代码）
         └─ Widget*Action  { ... }                                 // 互动组件
```

生成流水线 `lib/server/classroom-generation.ts`（574 行）是分阶段的，每阶段可独立重试/回退/报进度：

```text
1. resolveModel（选在线模型）
2. （可选）web search -> researchContext
3. generateSceneOutlines  -> SceneOutline[]（type/title/keyPoints/teachingObjective/mediaGenerations…）
4. 逐个 outline： generateSceneContent -> generateSceneActions -> createSceneWithActions
5. （可选）generateMediaForClassroom（图片/视频，在线 provider，落盘回填）
6. （可选）generateTTSForClassroom（speech 配音，回填 audioUrl）
7. persistClassroom（持久化 stage+scenes）
```

API 入口 `app/api/generate-classroom/route.ts` 立即返回 `{ jobId, pollUrl, pollIntervalMs }`（异步任务 + 轮询进度），长任务在 `after()` 里跑——这套异步任务模型 edu_ai 也该统一用。

**只要 edu_ai 接受这套 `Stage/Scene/Action/Slide` 作为「课件源数据」，PPT、聚焦、语音、视频、互动、导出、再编辑就全部打通了。** 这是整个替换的地基。

## 4. 怎么换：把 OpenMAIC 封装成 API（推荐架构）

### 4.1 现实约束

OpenMAIC = Next.js + TS monorepo（`packages/@openmaic/*` + `pptxgenjs` + `mathml2omml`，pnpm workspace）。edu_ai 后端 = FastAPI/Python。**不可能零成本塞进 Python 进程。** 两条可行路径，建议组合使用：

### 4.2 路径 A（后端能力）：OpenMAIC 作为 Node sidecar 服务

把 OpenMAIC（或裁剪版）作为独立容器跑起来，edu_ai FastAPI 通过 HTTP 调用。它本来就是 Next.js API 服务，天然就是这个形态。直接复用它现成的 route：

| edu_ai 需求 | 直接调用 OpenMAIC 端点 | 对应实现 |
| --- | --- | --- |
| 生成互动课件（PPT+动作+媒体+配音） | `POST /api/generate-classroom` → 轮询 `pollUrl` | `lib/server/classroom-generation.ts` |
| PDF/教材解析（含 MinerU Cloud） | `POST /api/parse-pdf`（multipart: pdf, providerId, apiKey, baseUrl） | `lib/pdf/*` |
| 导出 PPTX | 复用 `lib/export/use-export-pptx.ts`（前端侧）或包成 route | pptxgenjs |
| TTS 单独调用 | 包一层 `/api/tts`（`generateTTS`） | `lib/audio/tts-providers.ts` |
| 视频生成单独调用 | 包一层 `/api/media/video`（`generateVideo`） | `lib/media/video-providers.ts` |
| 校验 provider 连通性 | 已有 `/api/verify-*-provider` | — |

> 工作量主要在「裁剪 + 配 .env + 容器化 + 在 edu_ai 侧写 Python 客户端」。`POST /api/parse-pdf`、`/api/generate-classroom` 是开箱即用的。

### 4.3 路径 B（前端播放/聚焦/编辑）：直接引入 npm 包

edu_ai 前端是 Vite/React，可直接把这几个 MIT 包加入工作区或 fork 进来：

- `@openmaic/dsl`：数据契约（类型 + 守卫），纯 TS 零依赖，**必引**。
- `@openmaic/renderer`：`SlideCanvas` + 聚焦效果（`SpotlightOverlay`/`LaserOverlay`/`ZoomWrapper`/`HighlightOverlay`）+ 各元素渲染。课件播放、聚焦、语音同步全靠它。
- `@openmaic/importer`：上传 PPTX → Slide DSL（用户已有课件导入）。
- `pptxgenjs` + `mathml2omml` + `lib/export/use-export-pptx.ts`：浏览器侧导出 PPTX。
- 播放编排：`lib/playback/engine.ts` + `lib/action/engine.ts`（PlaybackEngine 消费 `Scene.actions[]`，驱动音频播放器 + canvas 状态 + 聚焦 overlay）。

### 4.4 推荐组合

```text
edu_ai 前端(React) ──引入──> @openmaic/dsl + renderer + playback engine   （播放/聚焦/语音/导出）
        │
        ▼ 调用
edu_ai FastAPI ──HTTP──> OpenMAIC Node sidecar
                          /api/generate-classroom  （生成课件：Stage/Scene/Action）
                          /api/parse-pdf           （MinerU Cloud 解析）
                          /api/tts、/api/media/video（按需封装）
```

edu_ai 负责：账号/权限、教材库/知识图谱、业务编排、把 sidecar 产出的 `Stage/Scene` 落到自己的存储与前端。OpenMAIC sidecar 负责：内容生成 + 媒体 + 解析这条「教学场景流水线」。

## 5. OpenMAIC 其他值得一并拿走的亮点

1. **异步任务 + 进度模型**：`{jobId, pollUrl, pollIntervalMs}` + `step/progress/message`（`ClassroomGenerationStep`）。edu_ai 的 PPT/视频/解析/知识图谱可统一成这一种长任务协议。
2. **Prompt 模块化**：`lib/prompts/snippets/*`、`lib/prompts/templates/*`（video-instructions、slide-video-instructions、slide-actions/system…）。比 edu_ai 集中式超长 prompt 更可维护。
3. **Provider 安全边界**：server-managed provider 忽略客户端传入 key/baseUrl；`parse-pdf` 对客户端 baseUrl 做 `validateUrlForSSRF`（生产环境）。edu_ai 若开放用户自配 MinerU/TTS 地址，必须照做。
4. **多场景类型**：除 slide 外还有 `quiz / interactive(widget) / pbl`，以及白板动作（写字/画形/公式/图表/代码/逐行改代码）。edu_ai 后续做「随堂练习、互动模拟、项目式学习」时不用从零设计。
5. **importer 反向导入 PPTX**：用户上传课件即可获得可编辑结构，再叠加讲解/聚焦/视频——这是很强的获客点。

## 6. 风险与缺口（换之前必须知道）

### 6.1 ⚠️ 最大缺口：OpenMAIC 没有「数字人/唇形同步讲师」

全仓搜索 `wav2lip / digital-human / 数字人 / talking-head / avatar.*video` 在 `lib/ packages/ app/` 中**零命中**。OpenMAIC 的「讲解」是：浏览器里幻灯片动画 + 聚焦 overlay + TTS 旁白，**没有一张会说话的人脸**。

- 如果 edu_ai 当前/规划卖点包含「数字人老师讲课视频」，那么放弃 AI_Lecturer = 放弃这个能力，OpenMAIC 不会替你补上。
- 建议决策：(a) 接受「无数字人、改为动画课件 + 旁白」这一产品形态（多数在线教育其实够用，且体验更轻更快）；或 (b) 保留一个**极薄的数字人渲染器**作为可选导出后端，让它消费 OpenMAIC 的 `Scene.actions[]`（speech 文本/音频 + focus 目标 + play_video 时段），只做最终 MP4 合成，**不再让它重新理解 PPT**。即「砍掉 AI_Lecturer 的大脑，可选保留它的嘴」。
- 请就这一点单独拍板（见文末问题）。

### 6.2 离线 MP4 导出能力会变化

OpenMAIC 强在「浏览器实时播放 + 互动」，它的导出重点是 **PPTX** 和 classroom zip，而非「一镜到底的讲课 MP4」。若仍需要可下载的成片视频（无网播放、上传第三方平台），需要补一个「场景时间线 → MP4」的渲染器（可用 Playwright 录屏 + 音轨合成，或保留 6.1(b) 的薄数字人）。这是放弃 AI_Lecturer 后要补的一块。

### 6.3 技术栈双语：TS sidecar + Python 后端

运维上多了一个 Node 服务。好处是隔离清晰、可独立扩缩容；成本是 CI/部署/监控要覆盖两套 runtime。相比现在 AI_Lecturer 拖着 GPU + Wav2Lip + LiveTalking + FFmpeg 的本地重依赖，这笔账整体是**省的**。

### 6.4 中文适配

代码里有中文友好的痕迹（`CJK_LANG_THRESHOLD`、MinerU `language:'ch'`、`languageDirective`），但 TTS 音色、slide 字体、公式/竖排等需要按中文场景实测。属于可控的适配工作，不是架构风险。

### 6.5 许可与合规

OpenMAIC 为 **MIT**（THU-MAIC），fork/改造/封装/商用均可，仅需保留版权与许可声明。注意：你接入的**第三方在线 API**（Seedance/Kling/Veo/MiniMax/ElevenLabs/MinerU 等）各有自己的服务条款与计费，需逐家确认配额与商用授权。

## 7. 替换实施路线（明确「删什么、接什么」）

### Phase 0：立项与冻结

## 10. 结论

放弃 html2ppt 和 AI_Lecturer、改用 OpenMAIC，是把 edu_ai 从「文件转换链路（markdown→PPT 文件→图片→GPU 数字人→FFmpeg）」升级为「教学场景编排系统（Stage/Scene/Action + 在线 Provider）」。这条路：

- **架构上更对**：元素级结构 + 统一动作时间线，聚焦/讲解/视频/互动/再编辑全部可寻址。
- **部署上更轻**：全在线 API，去掉 GPU 与本地权重。
- **法律上没障碍**：MIT，可商用。

唯一需要你主动决策的实质问题，是**「数字人讲师」要不要保留**——这是 OpenMAIC 唯一不替你覆盖的能力。其余 PPT 生成、视频生成、聚焦、语音讲解、PDF 解析，OpenMAIC 都已经有成体系、可直接封装/复用的实现。

> 与 v1 的关系：v1 的「TeachingDeck/TeachingAction 自建中间层」思路在本方案中被「直接采用 OpenMAIC 的 `@openmaic/dsl`（Stage/Scene/Action/Slide）」取代——不必再造一套等价 DSL，直接用上游的、并随上游演进。
