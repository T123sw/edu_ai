# 教师端基础可用性审计与整改优先级

**审计日期：** 2026-08-06
**审计目标：** 暂停扩展大功能，优先把教师端收敛到“美观、可理解、可操作、可恢复、数据不丢”的基本可用状态。
**优先级原则：** 先解决界面可见性与核心路径阻断，再完善 RAG、生成工厂、资源存储与 API 配置，最后优化主 Agent 的智能和记忆。

**配套规格：**

- [课程中心架构与教师端全链路优化 SPEC](superpowers/specs/2026-08-06-course-centered-teacher-experience-design.md)
- [教师端 P0：基础可用性与统一任务中心 SPEC](superpowers/specs/2026-08-06-teacher-p0-usability-and-job-center-design.md)
- [教师端 P1：可信生成、RAG、资源治理与配置中心 SPEC](superpowers/specs/2026-08-06-teacher-p1-trusted-generation-and-configuration-design.md)

## 1. 结论先行

教师端并不是“底层能力很少”，而是**已有能力没有被组织成教师能放心使用的完整闭环**。在线课堂已经具备场景渲染、时间线、语音降级、PPTX/MP4 导出等能力；生成工厂也已经能生成并保存多类资源；RAG 已有导入、检索、来源和用户过滤机制。但当前界面无法清楚回答教师最关心的五个问题：

1. 我现在在哪个课程、课时和资源范围内操作？
2. 我上传的资料是否真的解析并进入了检索？
3. 生成任务进行到哪一步，失败后能否重试或恢复？
4. 生成结果保存在哪里，刷新或换设备后是否还在？
5. 系统当前使用的是哪套模型/API，配置是否有效？

因此，本轮整改不建议重写底层或增加新的大型模块，而应把重点放在**界面重构、状态透明、失败可恢复、数据一致和配置可管理**上。

### 1.1 优先级总表

| 优先级 | 整改项 | 当前影响 | 建议结论 |
|---|---|---|---|
| P0 | 在线课堂播放器与课堂列表重设计 | 当前更像技术验收页，无法支持教师自然授课 | 完整重做交互外壳，复用现有渲染与导出能力 |
| P0 | 教师工作台三栏响应式裁切 | 1440px 等常见宽度下生成工厂最右列被直接裁掉 | 修复布局“死区”，保证所有入口始终可见 |
| P0 | PPT、闪卡生成入口回归 | 两项既有功能在加入 AI 课堂入口后的界面调整中消失 | 恢复卡片及原配置／生成链路，并完成端到端回归 |
| P0 | 课程内容入口出现 `#undefined` | 用户点击后无法到达课程内容 | 立即修复并补路由回归验证 |
| P0 | 核心页面加载、空状态、失败状态不完整 | 用户不知道是“无数据、仍在处理、处理失败还是权限问题” | 统一状态语言和恢复操作 |
| P0 | 后台生成任务由各页面分别轮询 | 页面刷新或跳转后任务状态可能丢失，同一用户无法集中查看任务 | 扩展现有 `EduJob`，建立后端任务账本和前端全局任务管理器 |
| P0 | 左侧导航缺少“课程资源” | 课程知识库输入、AI 课堂和生成结果的关系不清楚 | 保留“课程知识库”，新增“课程资源”，AI 课堂继续作为并列专用入口 |
| P1 | RAG 知识库最小可用闭环 | 上传成功不等于可检索，教师无法判断资料是否生效 | 增加索引状态、失败原因、检索测试和引用证据 |
| P1 | 生成工厂配置、质量与结果闭环 | 入口恢复后，各类型的配置、质量验证和结果状态仍不统一 | 八类正式资源统一四步流程；只隐藏未形成独立闭环的音频 |
| P1 | 生成资源持久化与权限边界 | 存储非原子、删除可能残留、课程/资源归属校验不足 | 先保证不丢、不串、不留孤儿文件 |
| P1 | 前端 API 配置中心 | 当前必须修改环境变量或源码旁配置，普通用户无法完成 | 增加后端托管、加密、可测试、可切换的配置界面 |
| P1 | 用户中心的模拟数据与模拟改密 | 页面显示静态个人信息，改密只是假成功 | 接入真实账户数据；未完成前不要伪装成功 |
| P2 | 主 Agent 记忆真正进入回答上下文 | 当前记忆会提取和保存，但普通回答链路基本不消费 | 将摘要、偏好、任务状态受控注入提示词并可观察 |
| P2 | 大组件与双路由体系治理 | 多个核心组件超过千行，旧/新路由并存，回归风险高 | 在 P0/P1 稳定后拆分，不作为本轮首要目标 |
| P2 | 性能、无障碍和依赖告警清理 | 首屏包体大、卡片键盘不可操作、存在组件弃用告警 | 纳入基本质量门禁 |

### 1.2 优先级定义

- **P0：阻断基本使用。** 页面不可见、核心入口打不开、课堂无法自然播放或错误状态无恢复路径。应先处理。
- **P1：影响结果可信与长期使用。** 功能看似可用但用户无法判断是否成功，或资源可能丢失、串用、难以配置。
- **P2：提升智能、性能与可维护性。** 不阻断当前基本流程，但会持续限制体验和迭代速度。

## 2. 审计范围与证据

本次检查覆盖：

- 教师工作台：知识库、对话、生成式工厂三栏页面；
- 在线课堂：生成入口、课堂列表、课堂播放器、PPTX/MP4 导出入口；
- RAG：上传、导入、索引、检索、来源、所有者过滤；
- 生成工厂：报告、教案、博客、习题、小游戏、思维导图、PPT、闪卡、视频等能力与入口；
- 课程生成资源：保存、列表、置顶、删除、刷新恢复；
- API 配置：大模型、Embedding、Reranker、语音、搜索、PDF 解析和 OpenMAIC sidecar；
- 主 Agent：会话摘要、记忆提取、上下文构建、普通回答和 ReAct 回答；
- 用户中心、路由、响应式、无障碍、前端构建与定向测试。

验证方式包括：实际登录并操作本地教师端、在 1908×945 与 1440×900 视口下复现、检查前后端实现与存储结构、执行现有自动化测试和生产构建。

**验证基线：**

- 前端自动化测试：89 项通过；
- 后端定向测试：RAG、会话记忆、资源存储、在线课堂持久化共 60 项通过；
- 前端生产构建：成功；
- 构建警告：存在超过 500 kB 的大块资源，主入口压缩前约 3.1 MB。

这说明本轮问题更偏向产品闭环和界面治理，并非底层完全不可运行。

## 3. P0：先保证美观与基本可用

## 3.1 P0-01 在线课堂：从“技术验收播放器”改成“教师授课控制台”

### 当前问题

当前播放器主体为固定 960×540 舞台，页面主要提供“上一页／下一页”和导出按钮。界面直接展示 `scene_id`、`type=slide` 等内部字段，缺少教师熟悉的播放与授课控制。课程标题、场景信息和导出操作之间的层级不清晰；在较小屏幕上空间利用较差。

实际底层已经存在时间线、语音、焦点动作、视频控制、字幕和导出能力，但没有形成可见的教师操作面板。当前页面更适合开发验收，不适合课堂展示。

经产品讨论确认，**在线课堂继续采用“按页／场景授课”的交互模型，不建设面向教师的全课程时间线编辑或拖拽控制**。全局时间线只服务于无头浏览器的视频导出；在线课堂只需要翻页，以及当前页确实包含配音、聚焦动作或嵌入媒体时的“播放／暂停当前页”。

### 目标界面

建议保持现有生成、渲染和导出服务不变，只重构教师端交互外壳：

```text
┌ 返回 / 课程名 / 课时名 ───────── 保存状态 ── 导出 PPTX / MP4 / 更多 ┐
├──────────────┬─────────────────────────────┬──────────────────┤
│ 场景目录      │                             │ 教师辅助面板      │
│ 缩略图 + 标题 │       自适应 16:9 舞台       │ 讲稿 / 互动 / 状态 │
│ 当前场景高亮  │                             │ 可折叠            │
├──────────────┴─────────────────────────────┴──────────────────┤
│ 上一场景  播放/暂停当前页  音量  字幕  全屏  下一场景              │
└──────────────────────────────────────────────────────────────┘
```

### 必须具备的基本交互

- 自适应 16:9 舞台，不固定死宽高；在窗口变化时保持完整可见；
- 左侧场景缩略图、标题、序号和当前场景高亮；
- 上一场景／下一场景，以及当前页有动作或媒体时的播放／暂停；
- 当前页音量、静音、字幕开关和全屏；
- 不显示全课程时间轴、总时长拖拽和跨页倍速；这些只属于视频导出内部流程；
- 清楚展示“语音生成中／使用服务端语音／已降级到浏览器语音／无语音”；
- 导出任务展示进度、取消、失败原因、重试和完成后的下载入口；
- 隐藏内部 `scene_id` 和技术类型；必要时放到“诊断信息”中；
- 加载、空课堂、场景损坏、媒体加载失败均有明确恢复动作；
- 提供演示模式：进入后隐藏编辑性信息，只保留课堂控制；
- 支持方向键翻页、空格播放暂停、Esc 退出全屏，并在界面中可发现。

### 课堂列表与生成入口

当前课堂生成页偏“一个输入框 + 任务轮询”。至少应补齐：

- 课堂名称、主题、创建时间、场景数、总时长、语音状态、最近导出状态；
- 打开、继续生成、重试、重命名、复制、删除；
- 生成中卡片可在刷新后恢复，显示阶段和最近更新时间；
- 失败卡片保留错误摘要和“一键重试”，不要直接消失；
- 空状态提供示例主题和明确的第一步，而不是只显示空白。

### 验收标准

- 1366×768、1440×900、1920×1080 三种尺寸下，舞台与主控制完整可见；
- 教师不阅读说明即可完成“打开课堂 → 翻页 → 播放当前页讲解 → 调音量 → 全屏 → 导出”；
- 任一媒体或语音失败时，课堂不被永久卡住，并能看到降级状态；
- 页面不再展示内部 ID、内部类型和开发式状态文本；
- 在线课堂没有全课程时间轴；视频导出仍能根据内部时间线生成完整 MP4；
- 播放器自动化测试之外，增加三种视口的视觉回归和键盘操作验收。

## 3.2 P0-02 修复生成工厂卡片被遮挡

### 已复现原因

问题不是简单的卡片层级，而是父级三栏布局宽度计算不成立：

- 左右栏使用 `clamp(320px, 24vw, 520px)`；
- 中间栏最小宽度为 520px；
- 父级同时使用 `overflow: hidden`；
- 仅在 992px 以下切换移动布局。

在 1440px 视口中，工作区可用宽度约 1111px，但三栏实际需要约 1239px。最右侧面板溢出的部分被直接裁切，第三列卡片因此不可见。992px 到约 1530px 之间形成了明显的响应式“死区”。

### 修复原则

- 不允许核心操作依赖横向溢出；
- 优先保证对话区和生成入口完整可用，侧栏可折叠；
- 生成卡片使用自适应列数：宽屏 3 列、中屏 2 列、窄屏 1 列；
- 当三栏无法同时满足最小宽度时，知识库或生成工厂应进入可切换抽屉／标签模式；
- 去掉会裁掉交互内容的上层 `overflow: hidden`，保留必要的纵向滚动；
- 避免页面、面板、列表三层嵌套滚动条。

### 验收标准

- 1280、1366、1440、1600、1920px 宽度下，八张正式资源卡（含恢复的 PPT、闪卡）和 AI 课堂主入口都能看见并点击；
- 页面无横向滚动，任何卡片、弹窗触发器和按钮不被裁掉；
- 折叠或展开左右栏时，中间输入区不跳出视口；
- 增加自动化布局断言：主要面板 `scrollWidth <= clientWidth`。

## 3.3 P0-03 修复 `#undefined` 课程内容入口

课程详情页实际出现“打开视频与课程内容”指向 `#undefined`。这是明确的核心路径阻断。

### 验收标准

- 链接必须由显式路由构造函数生成，缺少课程或内容 ID 时禁用并解释原因；
- 从课程列表进入课程详情，再进入课程内容，返回后课程上下文不丢失；
- 为链接增加路由单元测试和浏览器回归测试，禁止字符串拼接出 `undefined`。

## 3.4 P0-04 统一所有核心状态

知识库、生成任务、课堂、导出和资源列表应使用同一套状态语言：

| 状态 | 用户需要看到 | 必须提供的动作 |
|---|---|---|
| 未开始 | 下一步是什么、需要什么输入 | 开始、查看示例 |
| 处理中 | 当前阶段、已耗时、最近更新 | 后台运行、取消 |
| 成功 | 结果摘要、保存位置、完成时间 | 打开、下载、继续使用 |
| 部分成功 | 哪些已完成、哪些降级 | 查看详情、补做失败部分 |
| 失败 | 可理解的原因、是否可恢复 | 重试、修改配置、查看诊断 |
| 无权限 | 缺少什么权限 | 返回、联系管理员 |
| 离线／服务不可用 | 哪个服务异常 | 重试、检查配置 |

禁止用永久转圈、“No data”或空白区域代替状态。

## 3.5 P0-05 明确左侧导航与资源关系

经确认，“课程知识库”管理的是教师上传并供 RAG 使用的输入资料，不是 AI 生成结果，因此必须保留。左侧导航建议按工作流排列为：

```text
问答
课程知识库
知识图谱
AI 课堂
课程资源
课程设置
```

- **课程知识库：** 原始资料、解析、索引、检索范围；
- **知识图谱：** 由课程资料抽取的结构化关系；
- **AI 课堂：** 课堂创建、课堂列表、按页授课、PPTX/MP4 导出；
- **课程资源：** 统一管理报告、教案、习题、PPT、小游戏、思维导图、博客和 AI 课堂；
- **课程设置：** 替代含义模糊的“详情编辑”。

AI 课堂在数据层是 `material_type=classroom` 的课程资源，在前端同时拥有两个入口：

1. “AI 课堂”提供专用创建、播放和导出体验；
2. “课程资源”在“全部”和“AI 课堂”筛选中显示同一资源。

两处必须引用相同的课程 ID、资源 ID 和后端记录。重命名、删除、权限、导出状态不得各自维护。

### 验收标准

- 左侧同时出现“课程知识库”“AI 课堂”“课程资源”，名称与职责不混淆；
- “详情编辑”更名为“课程设置”；
- 从 AI 课堂或课程资源打开同一课堂时，使用相同 `material_id`；
- 任一入口重命名或删除课堂，另一入口刷新后立即一致；
- 课程资源“全部”列表包含 AI 课堂，并支持按 `classroom` 类型筛选。

## 3.6 P0-06 建立统一后台任务中心

当前课堂生成、视频导出、报告、习题、小游戏、博客和 RAG 导入分别由不同组件轮询。部分任务只保存在组件状态或浏览器 `localStorage`，刷新、跳转或多标签页使用时容易丢失状态。

项目已有文件持久化的 `EduJob` 和 `/api/jobs/{edu_job_id}` 查询接口，应扩展为统一任务账本，而不是重新设计另一套任务系统。

### 目标架构

- 所有耗时生成接口先创建后端任务并返回 `202 + edu_job_id`；
- 后端任务记录所有者、课程、任务类型、阶段、进度、结果资源引用和错误；
- 新增按当前用户列出任务的接口，使刷新后能够恢复；
- 前端只有一个全局任务管理器负责轮询，业务组件只订阅任务；
- 任务成功时根据 `result_ref` 刷新统一课程资源库；
- 顶部右侧提供任务中心入口，显示运行中数量、最近失败和完成结果；
- 第一阶段继续使用统一轮询，不强制引入 SSE 或 WebSocket。

### 验收标准

- 用户在生成课堂、报告或视频后立即刷新，重新登录后仍能看到任务进度；
- 从问答页切换到课程资源页，任务持续运行且不重复提交；
- 同一浏览器多标签页不会为同一任务产生失控的重复轮询；
- 任务完成后，对应资源自动出现在课程资源列表；
- 失败任务保留输入摘要、错误原因和重试入口；
- 用户不能查询其他用户的任务。

## 4. P1：让核心功能真正可信

## 4.1 P1-01 RAG 知识库最小可用闭环

### 当前能力

现有 RAG 支持文档导入、进度、查询、统计、文档详情、内容读取、来源返回、按所有者过滤和指定文档检索。普通问答链路会把 RAG 返回内容与来源加入回答上下文。

### 当前缺口

1. 课程知识库先保存文件和索引，再调用 RAG 导入；RAG 导入异常只写日志，接口仍继续返回上传结果。教师看到“上传成功”时，资料可能尚未可检索。
2. 前端未展示解析阶段、分块数量、索引状态、失败原因、最近更新时间、Embedding 模型或重建状态。
3. 缺少“用一个问题测试此资料”的入口，教师无法验证检索效果。
4. 检索结果虽有来源，但工作台缺少稳定、清晰的引用证据展示和定位。
5. Reranker 与查询改写默认关闭；图片检索仍是后续项。当前不应在界面宣传为完整多模态知识库。
6. 兼容旧数据的“无所有者记录”逻辑需要迁移审计，避免多用户上线后产生边界不清。

### 建议最小闭环

每个文档显示：

- 文件名、大小、页数／时长、上传者、所属课程／课时；
- `上传中 → 解析中 → 分块中 → 向量化中 → 可检索`；
- 分块数、索引版本、最近更新时间；
- 失败原因和重试／重新索引；
- “测试检索”：输入问题后显示命中的片段、相关度、页码／时间码；
- 删除时明确同时删除原文件、索引、向量和派生媒体；
- 对话引用中显示资料名、页码／段落、命中片段，并可展开原文。

### 一致性要求

- 上传接口只能在创建了可追踪的索引任务后返回；前端显示“已接收，处理中”，不能提前显示“可用”；
- 文件、课程索引和向量库之间使用统一文档 ID；
- 任何一步失败都保留可重试状态，不生成“文件在列表但永远检索不到”的静默孤儿；
- 删除和重新索引必须幂等；
- 课程资料、个人资料和共享资料必须有明确所有者和权限策略。

### 效果验收

建立 10～20 个固定教师问题的“小型黄金集”，至少覆盖：

- 精确事实、跨段总结、概念解释、相似概念区分；
- 只检索指定资料；
- 无答案时明确说资料中没有；
- 引用页码／片段可定位；
- 文档更新后旧答案不再被命中；
- 中文 PDF、PPTX、DOCX 和图片型 PDF 的解析质量。

每次调整分块、Embedding、Reranker 或查询改写都跑同一黄金集，记录命中率、引用正确率、无答案误答率和响应时间。

## 4.2 P1-02 生成工厂：入口清单、生成过程与结果必须一致

优先级拆分：PPT、闪卡入口恢复和不被裁切属于 P0；八类资源的配置一致性、输出质量、版本与来源信息完善属于 P1。本节矩阵同时记录两阶段边界。

### 当前入口与能力矩阵

| 能力 | 当前直接卡片 | 后端保存 | 当前判断 |
|---|---:|---:|---|
| 报告 | 有 | 有 | 可保留，补过程、预览和失败恢复 |
| 教案 | 有 | 有 | 可保留，补参数确认和版本 |
| 教学博客 | 有 | 有 | 可保留，补来源与导出 |
| 习题 | 有 | 有 | 可保留，补草稿恢复、答案与适用场景 |
| 小游戏 | 有 | 有，但落入通用 `others` 目录 | 可保留，统一类型映射和安全预览 |
| 思维导图 | 有 | 有 | 可保留，补编辑、导出和来源 |
| AI 课堂 | 顶部独立入口 | 有 | 保持独立，生成后进入课堂列表 |
| PPT | 当前版本入口回归，历史版本已有直接卡片 | 有生成、预览、导出和保存基础 | P0 恢复直接卡片及原有配置流程，并接入统一任务中心 |
| 视频 | 无直接卡片 | 作为课堂导出派生物 | 归入课堂导出，不建议重复放一个未独立闭环的工厂卡 |
| 音频 | 无直接卡片 | 未发现独立资源保存链路 | 未形成闭环前隐藏，不做“半成品入口” |
| 闪卡 | 当前版本入口回归，历史前端已有入口与配置 | 已有类型、路由和生成基础，需回归验证保存链路 | P0 恢复直接卡片；生成、预览、保存任一环节失败均视为 P0 阻断 |

用户提出的“有几个卡片没有展示”应定性为已有功能的前端回归：

1. **当前动作注册表只保留了六张资源卡；**
2. **加入 AI 课堂主入口后，PPT 和闪卡入口从可见操作区消失；**
3. **现有布局在常见桌面宽度下还会继续裁切后续卡片。**

因此必须同时恢复动作注册、接回原有生成链路并修复自适应布局，不能只改 CSS 或只增加按钮后宣告解决。视频仍是 AI 课堂的派生导出，音频仍不作为本轮正式独立入口。

### 生成流程统一规范

所有生成能力使用同一套四步结构：

1. **选择来源：** 当前课程、课时、资料、是否允许 Web；
2. **配置：** 标题、受众、难度、长度、格式等少量关键参数；
3. **生成：** 阶段、进度、后台运行、取消、失败原因、重试；
4. **结果：** 预览、编辑、保存位置、版本、导出、添加到对话、删除。

卡片不要“点击整个区域立即生成”；主点击进入配置，次级按钮可用于快速生成。所有卡片必须支持键盘焦点和 Enter/Space 操作。

### 可用性验收

- 八个正式资源入口各跑三次固定样例，记录成功率、平均耗时、结果完整度和可编辑性；
- PPT、闪卡必须分别覆盖“配置 → 生成 → 任务恢复 → 预览 → 保存 → 刷新后重开”，不能只验收卡片重新出现；
- 所有结果刷新页面后仍可从课程资源中找到；
- 失败后不丢输入和资料选择；
- 结果明确标注使用的资料、生成时间、模型和版本；
- 未形成保存与预览闭环的能力不出现在正式入口。

## 4.3 P1-03 生成资源：先保证“不丢、不串、不残留”

### 当前问题

- 生成资源采用本地 JSON 与附件文件保存，直接写目标文件，缺少临时文件 + 原子替换；并发写入时有丢更新或文件损坏风险。
- 保存失败多数只打印日志，生成接口仍可能把结果返回给前端；用户刷新后可能找不到刚生成的内容。
- 删除逻辑主要删除一个 JSON 和一个 `file_path`，课堂媒体、多附件或派生目录可能留下孤儿。
- 资源记录没有统一的 `owner_user_id`；课程资源列表、删除和置顶虽然要求登录，但没有按资源所有者或课程成员做授权校验。
- 课程增删改查接口本身未统一要求认证，无法作为多用户教师端的可靠边界。
- `game` 未进入正式类型目录映射，落入通用目录，后续统计、迁移和清理容易出现差异。

### 最小整改

- 每条资源统一字段：资源 ID、类型、课程、课时、所有者、状态、版本、来源资料、模型、创建／更新时间、文件清单；
- 写入采用临时文件、校验、原子替换；多文件资源使用清单或资源目录；
- 生成接口只有在保存成功后才返回“已完成”；若内容生成成功但保存失败，返回“部分成功”并允许重新保存；
- 删除按资源清单清理所有派生文件，后台定期扫描孤儿；
- 课程和资源接口统一认证与课程成员授权；
- 用户只能看到、下载、置顶和删除自己有权限的课程资源；
- 为 `game` 等所有正式类型建立明确映射；
- 提供导出备份和基本迁移脚本后，再考虑数据库化。

### 验收标准

- 同一课程并发生成 10 个资源，不丢记录、不产生损坏 JSON；
- 刷新、重新登录、换浏览器后资源仍可见；
- 删除课堂资源后相关音频、视频、字幕、时间线和元数据均被清理；
- A 教师无法读取或删除无权限课程的资源；
- 人为模拟磁盘写入失败时，前端不会显示虚假成功。

## 4.4 P1-04 新增“模型与服务配置”界面

### 目标

让授权用户无需打开源码或手工编辑环境变量，即可在前端配置模型与外部服务，并让系统实际使用所保存的配置。

### 配置分类

1. **对话与 Agent：** 默认对话模型、深度模型、Planner、Executor、ReAct、Vision、PPT 模型；
2. **RAG：** Embedding、Reranker、查询改写、PDF 解析；
3. **语音：** ASR 与 TTS，包含百度语音、Qwen TTS 或其他供应商；
4. **搜索：** Web 搜索、图片搜索、视频检索；
5. **课堂服务：** OpenMAIC sidecar 地址、相关服务端模型；
6. **本地服务：** Ollama 或兼容 OpenAI 协议的自定义地址。

每个配置项至少包含：供应商、Base URL、模型名、API Key、超时、启用状态、最近验证时间。

### 安全与实现边界

- API Key 不保存在浏览器 `localStorage`，也不由前端直接调用第三方；
- 前端只把密钥提交给经过认证的后端，后端加密保存；
- 保存后只返回掩码，如 `sk-****9a2f`，不得再次回传明文；
- 按角色限制配置权限，并记录修改人、时间和配置版本；
- 提供“测试连接”，分别验证鉴权、模型存在、简单请求和响应时间；
- 支持“保存草稿”和“启用此配置”，避免一保存就让全站中断；
- 支持回滚到上一个可用版本；
- 运行时统一从配置注册中心读取，能热更新的立即生效；不能热更新的明确显示“需要重启哪个服务”；
- 主 API 与 OpenMAIC sidecar 的配置应由后端安全同步，不能让浏览器携带 sidecar 密钥。

### 页面状态

- 未配置、已配置未验证、验证成功、验证失败、已停用；
- 显示最近验证时间、响应时间、错误摘要；
- 提供“恢复默认值”和“查看使用此配置的功能”；
- 不在错误提示、日志、浏览器 DOM 或网络响应中泄漏密钥。

### 验收标准

- 教师／管理员可以在不改源码的情况下配置一套新的对话模型和语音服务；
- 测试通过后启用，下一次请求实际使用新配置；
- 错误 Key 能得到明确的 401/403 提示，不影响其他已工作的服务；
- 页面刷新后只显示掩码；
- 非授权用户不能查看或修改配置。

## 4.5 P1-05 用户中心必须真实可信

当前用户中心显示硬编码邮箱、电话、部门、角色和简介，资料只保存在浏览器；“修改密码”是延迟后直接提示成功，没有调用后端。这会让用户误以为账号安全设置已经生效。

建议：

- 接入真实当前用户信息和后端修改密码；
- 暂时未实现的字段显示“暂未接入”，不要填充模拟个人数据；
- 修改密码需要旧密码、强度校验、服务端确认和登录态处理；
- API 配置入口可放在用户中心，但建议单独作为“模型与服务配置”，避免与个人资料混在一起。

## 5. P2：主 Agent、性能与可维护性

## 5.1 P2-01 会话记忆不是“完全没有”，但没有真正进入普通回答

### 实际链路

系统会提取并持久化 `conversation_summary` 和 `conversation_memory`，上下文构建器也会把它们放入会话快照；相关单元与流水线测试存在并通过。

但普通快速回答链路只使用最近消息和检索结果，没有把 `snapshot.summary` 或 `snapshot.conversation_memory` 注入模型消息。ReAct 链路的系统提示词只在存在已确认的大纲时加入“工作记忆”，也没有消费一般会话摘要和偏好。

因此，用户感受到的“记忆约等于没有”是合理的：记忆**被计算和保存了，但对大多数回答没有产生直接影响**。

### 后续优化建议

- 只注入可验证且仍有效的记忆：当前目标、课程范围、教师偏好、已确认约束、活跃资源；
- 为记忆增加来源、更新时间、置信度和失效条件；
- 将摘要和记忆以短结构化段落注入普通回答和 ReAct 两条链路；
- 避免把模型猜测当作用户事实；用户可查看、纠正、删除记忆；
- 增加可观察信息：本轮使用了哪些记忆、为什么使用；
- 建立长对话回归集，验证第 1 轮约束在第 20、40 轮仍被遵守。

优先级保持 P2，待 P0/P1 稳定后再做。

## 5.2 P2-02 拆分超大组件，收敛双路由与旧页面

核心教师组件规模较大：

- `StudioPanel.tsx` 约 3531 行；
- `ChatPanel.tsx` 约 2120 行；
- `SourcePanel.tsx` 约 1897 行。

同时存在当前 Hash 页面壳和旧 React Router 页面／占位页。结果是同一功能可能有两套入口、两套状态和不同程度的完成度，容易产生“修了一个页面，实际用户走的是另一个页面”的问题。

建议在 P0/P1 完成后：

- 将生成卡片、配置弹窗、任务状态、资源列表、预览器拆成独立模块；
- 为当前正式路由建立唯一清单；
- 删除或明确标记旧页面，避免占位页进入正式导航；
- 所有路由使用同一构造函数和课程上下文模型。

## 5.3 P2-03 性能、无障碍与告警

- 生产构建主入口块较大，应对编辑器、语法高亮、PPT 导出等重模块按需加载；
- 登录背景图片约 2.1 MB，可压缩并按设备提供尺寸；
- 生成卡片使用可点击 `div`，键盘和屏幕阅读器支持不足，应改为语义按钮或补齐 role、tabIndex 和键盘行为；
- 实际操作观察到 Ant Design `destroyOnClose` 弃用和 Form 实例未连接告警，应清理；
- 空状态中存在中英文混用（如 `No data`），课堂中出现技术英文，应统一教师语言；
- 建立基础质量门禁：无控制台错误、无弃用告警、核心页面键盘可达、常见宽度无裁切。

## 6. 建议实施顺序

## 阶段 A：界面与核心路径止血（P0）

建议按一个完整开发迭代实施，并在统一任务中心完成任务类型盘点后再锁定工期。目标不是补功能，而是让教师端第一眼可用，并保证后台任务不会因为刷新或跳转而失联。

1. 修复三栏响应式死区和卡片裁切；
2. 修复 `#undefined` 路由；
3. 调整左侧导航，增加“课程资源”，明确知识库输入与资源输出；
4. 重构在线课堂外壳：目录、自适应舞台、按页控制、状态、导出进度；
5. 扩展 `EduJob` 并接入前端全局任务管理器；
6. 统一加载、空、失败、部分成功状态；
7. 补 1366／1440／1920 三档视觉与交互验收。

**阶段出口：** 教师能无说明完成“选资料 → 对话 → 生成 → 刷新页面 → 在任务中心恢复 → 找到资源 → 打开课堂 → 按页授课／导出”。

## 阶段 B：功能可信与配置可用（P1）

P1 涉及 RAG、资源一致性、权限和密钥安全，不建议压缩成一个短周期。应按配套 SPEC 拆为 RAG 状态、生成与资源、配置中心、用户设置四个可独立验收的小阶段，再分别评估工期。

1. RAG 文档索引状态、失败重试、测试检索和引用定位；
2. 生成工厂能力矩阵收敛，统一四步流程；
3. 资源原子保存、所有者／课程授权、完整删除；
4. 模型与服务配置中心的最小版本；
5. 用户中心去除模拟信息和假改密。

**阶段出口：** 教师能判断资料是否生效、生成是否保存、服务配置是否有效；失败后能恢复。

## 阶段 C：智能与工程质量（P2）

1. 把受控会话记忆接入普通回答与 ReAct；
2. 用长对话回归集验证记忆；
3. 拆分超大组件，收敛正式路由；
4. 按需加载大模块，清理无障碍和控制台告警。

## 10. 最终建议

本轮最合理的方向是：**不扩张功能面，先把已有能力包装成稳定、透明、可恢复的教师工作流。**

第一步必须是在线课堂与工作台布局；第二步是 RAG、生成资源和 API 配置的可信闭环；主 Agent 的智能和记忆放在第三阶段。这样既符合“先美观可用，再优化功能”的要求，也能最大限度复用已经通过测试的底层能力，避免重新造一套更大的半成品。
