# 课程创建、凭码加课与知识库构建验收

**状态：** 已完成实现与端到端验收
**日期：** 2026-08-11  
**设计规格：** `docs/superpowers/specs/2026-08-11-course-enrollment-and-knowledge-build-design.md`  
**实施计划：** `docs/superpowers/plans/2026-08-11-course-enrollment-and-knowledge-build.md`

## 1. 验收目标

验证以下链路不是孤立接口或静态界面，而是在真实 PostgreSQL、真实教师页面、真实学生页面和正式后台任务中端到端成立：

```text
教师创建课程
  → 系统生成唯一课程码
  → 教师查看统一成员列表
  → 学生凭课程码加入
  → 教师一键构建小型课程知识库
  → 中文资料优先、英文补充、模型兜底
  → 三层或更深知识图谱通过质量门禁并发布
  → 教师与学生读取同一图谱和资料
```

## 2. 强制验收口径

### 2.1 课程与成员

- 新课程必须有八位、全局唯一、可复制和可重置的课程码；
- 课程码与内部 `course_id` 不相同；
- 创建后只有创建教师是 `owner`；
- 系统内其他教师和学生不会自动加入；
- 学生输入正确课程码后成为 `viewer`；
- 重复输入同一码保持一条成员关系；
- 错误或已重置课程码不能加入；
- 课程所有者能查看、添加、调整和移除允许管理的成员；
- 学生和协作教师不能调用所有者成员管理接口；
- 学生被移除后立即失去课程访问权。

### 2.2 知识图谱

- 图谱只有一个根节点；
- 最短根到叶路径至少包含三个节点；
- 最少形态为“课程根节点 → 真实课程模块 → 叶级知识点”；
- 节点 ID 唯一、无环、全部可达；
- 不允许出现仅为凑层级而存在的空壳模块；
- 允许课程内容需要时出现第四层或更深结构；
- 资料只关联叶节点；
- 每个叶节点至少关联三个不同的 ready 文档。

### 2.3 来源与质量

- 每个叶节点先执行中文来源发现；
- 中文成功入库不足三份时才执行英文来源发现；
- 中文和英文成功入库后仍不足三份时才生成 AI 中文补充资料；
- 搜索到但抓取失败或索引失败的资料不计入覆盖；
- AI 补充资料不伪造网址、作者、许可证或引用；
- AI 补充资料明确标记 `model_generated`；
- AI 补充资料至少 800 个中文字符并包含规定教学结构；
- 每份 AI 补充资料独立审查得分至少 80；
- 任一叶节点不足三份资料时，本次构建不得发布；
- 构建失败时旧的活动图谱保持可用。

## 3. 真实验收课程

执行者必须通过教师前端创建课程，不直接插入数据库。

建议输入：

| 字段 | 值 |
| --- | --- |
| 课程名称 | Python 控制流程入门 |
| 课程简介 | 面向零基础学习者，理解条件判断与循环控制，并能完成简单程序设计。 |
| 教学对象 | 大学一年级零基础学生 |
| 课程目标 1 | 条件判断 |
| 课程目标 2 | 循环控制 |
| 授课语言 | 中文 |
| 难度 | 入门 |

规划器可以根据语义生成更自然的模块和知识点名称，但不得增加与课程无关的节点。小型验收课程至少包含两个叶级知识点，因此至少形成六个叶节点—资料关联。

验收课程在完成后保留，便于用户在教师端和学生端复查。最终证据记录：

## 5. API 端到端验收

自动化场景必须使用两个不同身份：教师和学生。

### 场景 A：教师创建课程

1. 教师调用正式创建接口；
2. 响应含课程 ID、课程码和 `owner`；
3. 查询课程列表可见新课程；
4. 查询成员列表只有教师本人；
5. 查询数据库确认没有自动加入其他账号。

通过证据：HTTP 状态、响应字段、成员行数、数据库课程码唯一性。

### 场景 B：学生凭码加入

1. 学生使用带小写和短横线的等价课程码加入；
2. 返回课程且角色为 `viewer`；
3. 再次加入不产生第二条成员关系；
4. 学生课程列表出现该课程；
5. 错误课程码返回 404；
6. 教师使用学生加入接口返回 403。

### 场景 C：成员管理

1. 所有者看到学生成员；
2. 所有者添加另一位教师为 `editor`；
3. 所有者可以把协作教师调整为 `viewer`；
4. 学生不能被调整为 `editor`；
5. 所有者不能移除或降级课程创建者；
6. 所有者移除学生后，学生读取课程返回 403；
7. 学生重新凭有效课程码加入后恢复 `viewer` 访问；
8. 重置课程码后旧码失败、新码成功。

### 场景 D：知识库构建

1. 教师生成构建方案；
2. 方案包含图谱草案和所有叶节点；
3. 正式任务进入后台队列；
4. 任务记录中文、英文、模型三个阶段的实际执行顺序；
5. 至少一个自动化受控叶节点只提供两份合格网络资料，证明模型只补一份；
6. AI 补充资料通过结构和质量审查；
7. 图谱通过结构、叶覆盖、来源顺序、生成资料和索引完整性检查；
8. 发布创建新图谱版本；
9. 构建结果逐叶列出中文、英文和 AI 资料数量。

### 场景 E：失败不污染

1. 准备一个已有活动版本；
2. 让某叶节点资料不足且模型审查连续失败；
3. 构建状态为 `blocked`；
4. 没有调用发布；
5. 活动图谱版本和旧资料仍可读取；
6. 错误信息明确指出失败叶节点和资料缺口。

## 6. 真实浏览器验收

真实页面验收必须使用正式 UI，不通过浏览器存储伪造登录或课程状态。

### 6.1 教师端

- 登录教师账号；
- 首页“创建课程”按钮可见；
- 创建表单字段和错误提示正常；
- 创建成功进入新课程概览；
- 页面显示课程码并可复制；
- 课程成员区只显示创建者；
- 知识库构建入口可见；
- 构建方案显示至少三层结构摘要；
- 构建过程中显示真实进度；
- 成功后显示每个叶节点的资料数量与语言/AI 分类；
- 知识图谱页面可逐层展开到叶节点；
- 每个叶节点资料视图至少显示三份资料；
- 页面控制台无未处理错误。

### 6.2 学生端

- 退出教师并正常登录学生账号；
- 学生首页显示“加入课程”；
- 输入课程码后成功加入并进入课程；
- 学生能看到与教师相同的课程标题和发布图谱版本；
- 学生能展开至少三层知识图谱；
- 学生能读取所有叶节点资料；
- 学生看不到构建、上传、成员管理、重置课程码和课程编辑按钮；
- 页面控制台无未处理错误。

### 6.3 返回教师验证成员

- 重新登录教师；
- 课程成员区显示已加入学生；
- 学生角色为 `viewer`；
- 加入时间和添加方式正确；
- 成员数量与数据库一致。

## 8. 最终阻断条件

出现以下任一情况不得签署验收：

- 新课程自动出现非创建者成员；
- 课程码重复、为空或与内部课程 ID 混用；
- 学生无法凭码加入或能凭错误码加入；
- 非所有者可以管理成员；
- 图谱不足三层；
- 为凑层级出现无教学语义的节点；
- 任一叶节点只有零到两份 ready 资料；
- 英文搜索早于中文缺口确认；
- 网络资料尚足三份时仍生成 AI 资料；
- AI 资料伪造来源或审查分数低于 80；
- blocked 构建覆盖当前活动版本；
- 教师和学生读取不同图谱版本；
- 学生端出现教师写操作；
- 自动化测试、生产构建或浏览器控制台存在未处理失败。

## 10. 实施决策与异常记录

- 首轮构建因模型审查误把“改进建议”当作否决而阻断，已改为 `approved=true` 且分数不低于 80 即通过，同时保留建议供审计。
- 后续构建出现 DashScope 120 秒超时，质量门禁正确阻断在 35 分，没有发布不完整图谱。实现增加最多 3 次有限重试，并允许后续构建恢复已独立审查通过的暂存资料；最终构建 100 分发布。
- 未发布/失败资料对 student viewer 隐藏；教师 owner/editor 可保留诊断视图。正式发布时文档状态与图谱版本原子切换。
- 文档正文服务原先只解析根级资料，叶级资料点击会 404；已改为跨全课程层级按稳定文档 ID 查询并增加回归测试。
- 课程码设为非空后，旧数据导入与直接 ORM 建课需要兼容默认值；旧课程采用确定性课程码，新增 ORM 课程使用安全随机码。
- 浏览器入课临时课程和一条早期乱码测试课程已在验证后删除，不可恢复；保留的验收课程为 `Python 控制流程入门`。
