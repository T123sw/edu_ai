## 3. 问题清单

### P1-01 Agent 混淆“课程学习任务”和“后台生成任务”

影响：教师和学生均无法通过 Agent 获取可信的学习反馈，Agent 记忆增强的产品目标尚未真正落地。

教师端复现：

1. 教师打开计算思维课程的“问答与生成”。
2. 输入：“当前这门课刚发布的学习任务完成情况怎样？只根据系统里的学习进度回答。”
3. Agent 将问题路由到 `query_task_status`。
4. 工具返回 `task_not_found`，最终回答“本次任务因质量问题已中止”。

学生端复现：

1. 学生完成 `E2E 双端学习闭环 2026-08-10`。
2. 打开课程 AI 问答，输入：“我刚刚完成了哪个学习任务？结合我的学习记录告诉我下一步应该做什么。”
3. Agent 查询旧的后台任务 `job_317c20f7fffa42ed`。
4. Agent 错误回答学生刚完成的是“生成 5 张递归停止条件复习闪卡”。

初步原因：系统同时使用“任务”指代课程学习任务与内容生成后台任务。学习上下文虽以 system context 注入，但规划器仍优先选择只支持后台任务的 `query_task_status`，历史对话中的后台任务 ID 又进一步覆盖了当前课程学习事实。

建议：

- 将概念和工具明确拆为“课程学习任务”与“内容生成任务”。
- 新增只读的课程学习工具，例如 `get_course_learning_progress`、`get_my_learning_progress`。
- 在规划器中，当问题包含“学习进度、学生完成情况、我刚完成、知识点掌握”等语义时，禁止路由到后台生成任务工具。
- Agent 回答前校验任务类型、课程 ID、用户角色和事实时间，避免历史后台任务覆盖当前学习事实。

### P1-02 当前记录只能代表学生自报，不能代表真实掌握

影响：教师看到的“完成率 20%”只能说明 1 名学生点击了“标记完成”，不能说明学生读完资源或掌握了 `kp-agent-basics`。

实际表现：

- “标记完成”在未开始、未打开资源时也是可点击状态。
- 打开资源只记录 1%，没有阅读时长、页面/场景完成度、测验结果或知识点证据。
- 知识点 ID 目前只随任务保存，没有根据学习行为形成掌握度变化。

建议：短期在教师端明确标注“学生自报完成”；中期引入资源阅读事件、课堂场景完成、测验成绩和知识点证据，再计算掌握度。

### P2-01 课程首页的“进行中任务”没有统计学习任务

复现：教师发布任务后，学生课程首页的计算思维卡片仍显示“进行中任务 0”。

初步原因：首页该数字来自全局内容生成 `jobs`，不是课程学习任务。现在产品中已经出现两类“任务”，该文案会使教师和学生误以为没有待完成的学习任务。

建议：改成两个独立指标：“待完成学习任务”和“后台生成中”；学生首页优先展示待完成学习任务数。

### P2-02 进行中进度文案显示为“已完成 1%”

复现：学生打开任务资源后回到学习任务页，状态文案显示“已完成 1%”。

影响：容易被理解为任务已经完成，而不是完成度为 1%。

建议：未到 100% 时使用“进行中 · 1%”或“学习进度 1%”，仅在状态为 completed 时显示“已完成”。

### P2-03 教师选择资源时无法区分重名资源

复现：新建任务的资源列表中存在多个相同标题，例如多个“快速排序算法原理”“测验-2026-03-09”和“汉字编码：从 ASCII 到 UTF-8 的演进”。列表只显示标题和类型。

影响：教师无法确认选中的是哪一个资源，可能给学生发布错误内容。

建议：增加搜索、类型筛选、创建时间、创建者或资源短 ID，并对完全相同的资源做去重提示。

### P2-04 Agent 页面加载历史对话时出现 `Failed to fetch`

复现：教师和学生进入课程 AI 问答时，浏览器记录到“加载对话详情失败”，教师端页面还出现可见的 `Failed to fetch`。

影响：旧对话可能未完整恢复，且会干扰 Agent 对当前学习上下文的判断。

建议：检查对话详情请求的失败原因；加载失败时不要继续把残缺历史当作当前上下文，并提供明确的重试入口。

### P3-01 双角色登录页仍以教师为中心

复现：退出后登录页显示“教师账号”，且本地页面曾预填 `admin/admin123`，但同一入口实际也用于学生登录。

建议：统一为“平台账号”或根据入口展示角色；不应默认展示可直接使用的管理员凭据。

### P3-02 个人中心的可访问课程数量与课程首页不一致

复现：教师课程首页显示 6 门可访问课程，但教师个人中心显示“可访问课程 0”。

建议：个人中心复用课程成员关系的真实统计，避免双数据源。

## 4. 自动化测试补充

本轮同时运行了现有学习闭环、学习上下文和 Agent 记忆恢复测试：

- 后端：18 项通过。
- 前端相关单元测试：24 项通过。

自动化测试通过但真实 Agent 对话失败，说明当前测试主要验证“上下文已注入”和“数据结构正确”，尚未验证模型在真实规划中是否选对任务领域、是否依据学习事实回答。

建议增加两条稳定的端到端验收用例：

1. 教师询问“这门课最新学习任务完成情况”，答案必须包含任务标题、课程学生数、已完成数和完成率，且不得调用后台生成任务工具。
2. 学生询问“我刚完成了什么学习任务”，答案必须引用当前用户自己的课程学习记录，不得返回其他学生数据或历史生成任务。
