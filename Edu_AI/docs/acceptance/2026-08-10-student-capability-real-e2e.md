# 学生端能力真实端到端验收报告

> 验收日期：2026-08-10  
> 验收环境：本机真实前后端，前端 `http://localhost:5173`，后端 `http://127.0.0.1:8001`  
> 验收账号：学生 `student`；教师账号仅用于反向权限校验  
> 验收课程：`computational-thinking`（计算思维）

## 1. 验收结论

学生端的页面主流程、Agent 工具调用、资源生成和个人资源隔离已经可以工作；但知识能力闭环尚未达到可验收状态，不建议把当前版本认定为“学生端基础能力全部可用”。

当前有 3 个发布阻断问题：

1. 学生上传个人知识库文档后，索引任务立即失败，文档保持“已接收、0 个可检索片段”，无法用于问答。
2. 深度研究后端虽然成功抓取并入库，但结果写入旧版 RAG 文档存储，没有进入新的个人知识库列表，学生无法在个人知识库中管理或选择这些资料。
3. 课程 RAG 检索到了学生个人深度研究文档，说明课程知识与个人知识的检索范围没有正确隔离。

因此，本轮总体判定为：**部分通过，知识库/RAG 主链路不通过，暂不具备发布条件。**

## 2. 测试范围与方法

本轮不是仅调用接口或检查静态页面，而是同时执行了：

- 真实启动的前后端登录、页面操作、文件上传、深度研究、RAG 对话和资源生成；
- 学生身份的真实 SSE Agent 对话与工具轨迹验证；
- 学生身份的资源生成 Agent 验证；
- 学生/教师双身份的资源和个人知识权限反向验证；
- 后端任务、文档索引和运行日志的结果核对。

个人知识库使用独有测试资料：

- 文件：`tests/fixtures/student-e2e-personal-knowledge-20260810.md`
- 唯一标识：`E2E-STUDENT-20260810-RAG-ALPHA`
- 唯一校验短语：`蓝鲸在第七码头等待`

该资料用于判断 RAG 是否真正读取到了上传内容，而不是依靠模型常识作答。

## 4. 详细问题清单

### STU-E2E-001：个人知识库索引立即失败，且真实错误被覆盖

- 级别：**P0**
- 影响：学生上传的资料无法用于个人 RAG；个人知识库主能力不可用。
- 复现步骤：
  1. 学生登录；
  2. 进入“个人知识库”；
  3. 上传 `student-e2e-personal-knowledge-20260810.md`；
  4. 查看文档状态和任务中心。
- 实际结果：
  - 文档 ID：`doc-216aebf97f464164a6c4e16531458fb9`
  - 任务 ID：`job_6b6aa96fbedd4a95`
  - 文档状态一直为 `received`
  - `chunk_count = 0`
  - 页面显示“已接收 · 0 个可检索片段”，“用于问答”不可用
  - 任务约 112 ms 后失败，错误码为 `TASK_EXECUTION_FAILED`
- 额外发现：任务错误信息被覆盖为此前的进度文本“正在读取文档内容”，没有保留真正的索引异常；文档索引记录也没有落下可诊断的 `error_code`、`error_message`。
- 建议：先修复索引失败的原始原因，再保证文档状态、任务状态和真实异常原子化落盘；任务执行器不得用通用错误覆盖 RAG 层已经写入的具体错误。

### STU-E2E-002：深度研究结果进入旧存储，未进入学生个人知识库

- 级别：**P0**
- 影响：深度研究看似执行完成，但学生无法管理、选择或明确复用研究资料；“研究 → 个人知识 → RAG”闭环断裂。
- 测试问题：比较 Python 官方资料中 `list` 与 `tuple` 的可变性、性能和适用场景，要求至少 3 个可访问来源。
- 实际结果：
  - 后端完成搜索、网页抽取和 RAG 导入，并返回 200；
  - 抽取结果保存为批次 `batch_1786292207613`；
  - 实际只成功导入 2 个网页文档，共 45 个片段；
  - 两个文档位于旧 `/api/rag/documents` 体系，`owner=student`，但 `course_id`、`library_type`、`scope_type` 均为空；
  - 新 `/api/personal-knowledge/documents` 列表中没有这两个文档，个人知识标签数量仍为 0；
  - 深度研究弹窗完成后直接复位，没有展示成功结果、来源列表或“已进入个人知识库”的入口。
- 建议：深度研究必须统一写入个人知识服务，并明确写入 `owner_user_id`、`scope_type=personal`、来源和索引版本；旧 RAG 文档不得绕过新知识库的所有权和范围模型。

### STU-E2E-003：课程 RAG 检索到个人深度研究资料

- 级别：**P0**
- 影响：课程知识与个人知识边界失效；回答可能被无关的个人资料污染，也无法保证“仅基于课程知识库”的承诺。
- 复现步骤：
  1. 新建 AI 对话；
  2. 打开 RAG；
  3. 要求仅根据当前课程知识库回答回溯法相关问题；
  4. 查看实际引用来源。
- 实际结果：RAG 返回的 5 条证据来自前一步个人深度研究生成的 Python `list`/`tuple` 网页，其中同一博客被重复引用 4 次；回答也明确承认没有找到相关课程资料。
- 判断：这是 STU-E2E-002 中缺失范围元数据的直接下游影响。当前 `course_auto` 检索没有把无课程归属的学生私有文档排除。
- 建议：检索入口必须按显式 scope 白名单过滤；课程模式只允许当前课程已发布知识，个人模式只允许当前用户个人知识，组合模式也必须在引用中标明来源空间。

### STU-E2E-004：`StudentShell` 持续触发 React 更新深度超限

- 级别：**P1**
- 影响：页面控制台持续出现 `Maximum update depth exceeded`，可能导致 CPU 占用、重复渲染、重复请求和交互不稳定。
- 实际结果：登录后的多个学生页面均周期性出现该错误，堆栈指向 `StudentShell.tsx:41`。
- 建议：检查课程选择同步 effect 的依赖和对象引用稳定性，避免每次渲染都写入等价但引用不同的课程对象。

### STU-E2E-005：RAG 开关与立即发送存在状态竞争

- 级别：**P1**
- 影响：用户点击 RAG 后立即发送，界面看似已选择 RAG，但会话能力策略仍为 `allow_rag=false`，Agent 随后因工具契约拒绝 `rag_search`。
- 复现会话：`conv-107058d1561a`
- 实际错误：`rag_search 违反工具契约：capability 不允许此工具`
- 对照结果：新建会话后点击 RAG 并等待约 600 ms 再发送，工具可以正常执行。
- 建议：发送动作读取同一个已提交的能力状态；切换能力时禁用发送直到状态写入完成，或把本轮选择随消息请求原子提交。

### STU-E2E-006：Agent 已输出最终答案，但计划仍显示“0/4 步完成 · 进行中”

- 级别：**P1**
- 影响：学生无法判断任务是否真的结束，也容易重复操作或取消已完成任务。
- 实际结果：RAG 最终回答已经完整显示，Agent 活动面板仍未进入完成状态。
- 建议：SSE 最终事件必须统一收口消息、计划和工具状态；断线/降级路径也要补发终态。

### STU-E2E-007：深度研究 UI 缺少可验证的进度和完成态

- 级别：**P1**
- 影响：数分钟运行过程中仅显示通用等待；完成后不展示结果、来源、失败网页或入库状态。
- 实际结果：后端已完成时，弹窗复位为“点击开始研究”；关闭弹窗还提示“已取消深度研究”，与真实状态相反。
- 建议：展示搜索、抽取、索引三个阶段及成功/失败来源数；完成后保留结果摘要和“查看个人知识库”；取消动作必须区分运行中与已完成。

### STU-E2E-008：深度研究来源质量和提供商降级不可见

- 级别：**P1**
- 影响：用户要求“官方资料、至少 3 个来源”，最终仅导入博客和知乎两个来源，结果不满足任务约束。
- 后端证据：
  - Bocha 搜索返回 5 条；
  - Bocha rerank 接口返回 404，系统静默降级；
  - Tavily 抽取 5 个地址，仅 2 个成功、3 个失败；
  - 成功文档均非 Python 官方文档。
- 建议：修复 rerank 配置；把来源约束纳入完成条件；未达到来源数量或官方性要求时，不应显示为无条件成功，应明确提示“部分完成”。

### STU-E2E-009：学生在“课程知识库”标签下仍看到上传按钮

- 级别：**P1**
- 影响：与“学生只读课程知识库”的产品规则冲突，用户无法判断上传会进入课程还是个人空间。
- 建议：课程知识标签下隐藏上传按钮；上传入口只放在个人知识标签，并在提交前明确显示目标空间为“个人知识库”。

### STU-E2E-010：RAG 引用去重和相关性不足

- 级别：**P2**
- 影响：5 个引用中同一博客重复出现 4 次，而且所有引用均与问题无关，降低可读性和可信度。
- 建议：按文档和 URL 去重，设置最低相关性门槛；没有合格证据时应返回“课程资料不足”，而不是展示无关引用。

### STU-E2E-011：个人知识库页面出现过一次瞬时 `Failed to fetch`

- 级别：**P2**
- 影响：首次刷新时出现错误提示，重试后恢复。
- 建议：结合 `StudentShell` 重复更新问题排查是否存在请求取消或页面重挂载；对瞬时失败提供明确重试状态。

## 7. 建议修复与复测顺序

1. **先修个人知识索引**：保留真实错误，完成上传、切片、索引、激活的完整状态机。
2. **统一深度研究归档**：所有研究产物只进入新个人知识库，禁止继续生成无 scope 的旧 RAG 文档。
3. **强制 RAG 范围过滤**：课程、个人、组合三种模式分别建立服务端白名单，不接受空 scope 文档参与课程检索。
4. **修复学生壳层重复渲染**：消除 `Maximum update depth exceeded` 后再复测页面稳定性。
5. **修复 AI 页面状态同步**：解决 RAG 开关竞争、Agent 计划终态和深度研究完成态。
6. **完善来源质量门槛**：修复 rerank，校验来源数量、官方性、可访问性和去重。
7. **最后重跑全链路**：个人上传 → 个人 RAG；深度研究 → 个人知识 → 个人 RAG；课程 RAG 不得命中个人资料；资源仍保持私有。

## 8. 复测通过标准

下一轮至少需要同时满足：

- 上传测试文档后状态为可检索，片段数大于 0；
- 个人 RAG 能准确返回唯一测试标识和校验短语；
- 教师和其他学生均不能读取该个人文档；
- 深度研究结果出现在个人知识库，可查看来源和索引状态；
- 课程 RAG 对同一问题不得引用任何个人知识文档；
- RAG 开关点击后立即发送也不会发生能力策略竞争；
- Agent 最终回答出现时，计划和工具状态同步完成；
- 学生生成资源仍只进入“我的资源”，课程共享数量不变；
- 学生页面不再出现 React 更新深度超限错误。
