# 专业多模态课程知识库设计 SPEC

**状态：** 待评审  
**日期：** 2026-08-08  
**目标课程：** 计算思维  
**优先级：** P0 数据与检索正确性；P1 课程图谱与内容质量；P2 多模态增强与运营审查  
**适用范围：** 用户上传、深度研究、课程建库、文档解析、分块、向量化、检索、预览、知识图谱、内容质量评测与迁移。

---

## 1. 背景与结论

当前课程知识库已经具备课程文档目录、知识图谱、RAG 索引和前端预览等基础能力，但尚不满足专业课程知识库要求。已确认的问题包括：

1. 当前知识图谱主要照搬单本教材目录，算法与数据结构占比过高，缺少计算思维核心能力；
2. 多数文档只是短小教材片段，缺少完整教学目标、概念解释、案例与练习；
3. 课程建库资料曾通过用户 owner 写入旧 RAG 索引，导致前端可被误认为个人资料；
4. Markdown、公式、表格、提示框与图片在解析、索引或展示过程中存在信息损失；
5. 当前分块为标题切分加字符切分，默认 2000 字符、重叠 400 字符，但 embedding 输入又被截断为 1500 字符；
6. 当前活动课程索引 244 份文档、827 个文本块，图片块为 0；其中 180 个块超过 embedding 截断长度，125 个块短于 300 字符，48 个块存在代码围栏被切断；
7. 向量召回在精排前按整份文档去重，可能丢弃同一文档的多个相关片段；
8. 当前单文档“检索测试”只计算词项重合率，没有测试真实 dense、BM25、融合和 reranker 链路。

本 SPEC 采用以下总方案：

```text
权威来源与原创教学材料
  → 轻量结构化解析 ContentBlock（不部署完整 Docling）
  → 结构保护的父子分块
  → 文本 / 图片 / 视频多表示向量
  → 课程/个人访问域隔离
  → Dense + BM25 + RRF + Rerank
  → 父块与相邻块扩展
  → 可引用、可预览、可评测的课程知识库
```

## 2. 产品目标

### 2.1 核心目标

1. 构建面向“计算思维课程”的专业知识图谱，不以某一本书的目录代替课程结构；
2. 每个原子知识点至少拥有 3 份高质量、有实际教学内容的资料；
3. 中文资料优先，每个知识点的核心讲解必须是中文，英文只作为补充；
4. 综合多本开放教材、官方文档、大学课程资源和经审查的网络资料；不足部分由系统原创编写；
5. 保留教材中的图片、表格、公式、代码和必要视频，不将所有信息压平成纯文本；
6. 使用 Gemini Embedding 2 将文本、图片和视频表示放入兼容的统一向量空间；
7. 修复分块、召回、融合、重排和测试方法，使检索质量可量化、可回归；
8. 保证课程资料、个人资料和用户显式发布行为边界清晰；
9. 课程知识库页面与问答页面均可稳定打开资料，公式、表格和媒体可读；
10. 构建过程可恢复、可审计、可回滚，不用一次性破坏现有可用索引。

### 2.2 成功闭环

```text
课程能力框架审定
  → 建立稳定知识点 ID 与关系
  → 为每个叶子节点收集/编写至少 3 份资料
  → 自动质量门禁与人工抽检
  → 结构化解析并保留媒体
  → 父子分块与多模态索引
  → 使用标准问题集评测
  → 指标达标后原子切换为新版本
  → 前端可查看、问答可命中、引用可追溯
```

## 3. 非目标

- 不在主服务中安装或运行完整 Docling PDF/VLM/OCR 管线；
- 不用 RAGFlow 整体替换现有产品、课程存储和问答服务；
- 第一阶段不迁移到 Qdrant、Elasticsearch 等新数据库；
- 不抓取或入库许可证不明确、明确禁止 AI ingestion、需要绕过登录或付费墙的内容；
- 不将序言、前言、后记、参考文献目录、购买说明、纸质书信息作为知识点或教学资料；
- 不把用户上传和用户发起的深度研究自动发布为课程公共资料；
- 不以文档数量或字符长度单独代表质量；
- 不在没有评测证据的情况下直接删除旧索引或覆盖全部课程数据。

## 4. 资料归属与访问边界

### 4.1 归属规则

| 来源 | 默认知识库 | 是否自动进入课程库 |
| --- | --- | --- |
| 用户上传文档 | 个人知识库 | 否 |
| 用户发起深度研究 | 个人知识库 | 否 |
| 用户上传图片或视频 | 个人知识库 | 否 |
| 用户明确“加入课程知识库” | 课程知识库副本 | 是，显式操作 |
| 系统课程建库爬取资料 | 课程知识库 | 是 |
| 系统课程建库原创资料 | 课程知识库 | 是 |
| 教师直接在课程知识库上传 | 课程知识库 | 是，显式课程操作 |

### 4.2 RAG 访问域

不能继续只依赖 `owner=username` 表达所有文档。新增稳定访问域：

```text
personal:<user_id>
course:<course_id>
```

每个索引点至少保存：

```text
access_scope
course_id | null
owner_user_id | null
library_type: personal | course
document_id
index_version
```

规则：

- 个人索引只允许当前用户访问；
- 课程索引按课程成员权限访问，与构建任务由哪位教师触发无关；
- 系统课程建库调用必须直接写入 `course:<course_id>`；
- 个人资料发布到课程时创建课程副本并生成课程域索引，不复用个人 source key；
- 前端列表不再通过路径字符串猜测归属，路径过滤只作为历史兼容措施；
- 后端必须测试跨用户、跨课程、直接文档 ID 和直接媒体 URL 的访问边界。

## 5. 计算思维课程知识图谱

### 5.1 组织原则

- 课程模块和学习能力是一级结构，教材章节只是来源映射；
- 叶子节点必须是可教学、可评测、不可再无损拆分的原子知识点；
- 同义概念使用一个规范名称，别名写入 `aliases`，不得创建重复节点；
- 教材中的“小结”“练习”“前言”等不是知识点；
- 资料只挂载到叶子节点，课程说明可挂载到根节点；
- 节点 ID 一旦发布保持稳定，重命名不得改变 ID；
- 树结构用于课程浏览，语义边用于先修关系、比较关系和应用关系。

### 5.2 建议课程骨架

第一版目标为 10 个模块、约 45～50 个叶子知识点：

1. **计算思维与问题求解**：问题定义与约束、分解、模式识别与泛化、抽象、算法化表达、建模与仿真、评价与迭代；
2. **数据与信息表示**：二进制与进制、数值表示、文本表示、图像/音频/视频表示、编码压缩与检错、数据质量；
3. **程序与可执行模型**：变量/类型/状态、控制流、函数与模块化、递归、测试与调试；
4. **算法基础**：算法表示、正确性与终止性、查找、排序、遍历；
5. **复杂度与权衡**：输入规模与增长率、时间复杂度、空间复杂度、实验分析与渐近分析、可处理性；
6. **核心数据结构**：数组与链表、栈与队列、哈希、树与堆、图；
7. **算法设计策略**：分治、贪心、回溯、动态规划；
8. **计算模型与可计算性**：逻辑与形式语言、自动机、图灵机、可计算性与不可判定性；
9. **计算系统与网络抽象**：计算机抽象层、进程与并发、网络与协议、分布式计算；
10. **负责任的计算**：隐私与安全、偏见与公平、知识产权与开放许可、社会与环境影响。

最终节点清单必须结合课程目标、现有教学大纲和来源覆盖审定。模块可以调整，但不得退回“照搬一本教材目录”。

### 5.3 图谱数据模型 v2

```json
{
  "schema_version": 2,
  "root": {"id": "ct-root", "label": "计算思维", "children": []},
  "nodes": {
    "ct-abstraction": {
      "label": "抽象",
      "aliases": ["信息隐藏", "忽略非本质细节"],
      "summary": "从问题中保留关键属性并建立可操作模型",
      "learning_objectives": [],
      "assessment_evidence": [],
      "status": "approved"
    }
  },
  "edges": [
    {"from": "ct-decomposition", "to": "ct-abstraction", "type": "supports"}
  ]
}
```

允许的关系类型：`prerequisite_of`、`part_of`、`supports`、`applies_to`、`contrasts_with`。前端初期继续用 `root.children` 展示树，问答和质量审计使用完整关系。

## 6. 来源与内容建设策略

### 6.1 来源优先级

1. 中文开放教材、中文国家级/大学课程资源；
2. 官方中文技术文档；
3. 有明确开放许可的中文专业社区或大学项目；
4. 有明确许可的英文开放教材和官方材料；
5. 经审查的其他网页；
6. 基于多来源事实和教学目标编写的原创中文教学文档。

来源必须记录标题、作者/机构、URL、许可证、版本/获取日期、语言、使用限制和内容哈希。明确禁止 AI ingestion 的来源不得入库，即使网页可以访问。

### 6.2 每个知识点的最低内容组合

每个叶子节点至少 3 份独立文档，并至少包含：

1. **概念讲义**：中文，包含目标、定义、机制、边界、常见误区和小结；
2. **案例或实验**：中文优先，包含完整问题、逐步分析、可运行代码或可观察过程；
3. **练习与评价**：中文优先，包含分层任务、答案或评价标准和错误诊断。

最低要求：

- 每个节点至少 2 份中文资料；核心概念讲义必须是中文；
- 至少 1 份文档由审查通过的外部权威来源支撑；
- 单纯摘要、元数据页、标题页和少于 500 个有效字符的页面不得计入 3 份；
- 概念讲义建议不少于 1500 个有效中文字符，案例不少于 1000，练习不少于 800；长度只是门禁之一；
- 有公式、表格或图示更适合解释时必须保留或重建对应视觉材料；
- 原创文档标记 `authority_tier=self_authored_reviewed`，列出参考依据，不伪装成外部出版物。

### 6.3 去重与审查

- 节点级：规范名称、别名和定义相似度联合判重；
- 文档级：来源 URL、内容哈希、MinHash/文本相似度联合判重；
- 片段级：精确哈希和高相似片段只保留一个检索表示，但原始文档仍可独立展示；
- 同一教材的连续小节不应机械生成大量只有一两段的“文档”；
- 自动质量报告必须列出覆盖不足、内容过短、重复、乱码、断裂公式、缺失媒体、许可证缺失和来源失效；
- 自动评分只能决定“阻断/待审”，不能把明显有问题的内容自动判定为高质量。

## 7. 轻量结构化解析

### 7.1 不部署完整 Docling

主运行链路不安装完整 Docling，不运行本地 PDF 视觉模型、OCR 模型或版面模型。原因是本项目已有 MinerU Cloud，且完整 Docling 曾出现内存溢出风险。

借鉴 Docling 的设计原则，但实现轻量内部结构：

- 在结构对象上分块，而不是先压平再按字符切；
- 标题、段落、列表、代码、公式、表格和图片分别建模；
- 分块时保留标题路径、图注、页码、阅读顺序和相邻关系；
- 超长表格切分时重复表头；
- 过小同级内容在不跨主题的前提下合并。

### 7.2 格式适配

| 格式 | 解析方式 |
| --- | --- |
| PDF | MinerU Cloud 输出 Markdown、图片映射和页码；解析为 ContentBlock |
| Markdown | Markdown AST，禁止仅用正则识别全部结构 |
| HTML/深度研究网页 | 清理导航后解析 DOM，保留标题、表格、代码和媒体 |
| DOCX | 读取 Word 标题样式、段落、表格和内嵌图片 |
| TXT | 段落与中文句子回退解析 |
| 旧 `.doc` | 明确拒绝或先转换为 DOCX，不再按文本直接读取二进制 |
| 图片 | 独立 Asset，保存原图、图注、OCR/说明和来源 |
| 视频 | 独立 Asset，保存时间段、字幕、关键帧和来源 |

### 7.3 ContentBlock

```text
ContentBlock
- block_id
- document_id
- kind: heading | paragraph | list | code | formula | table | image | video | callout
- order
- heading_path[]
- text
- markdown
- page_start / page_end
- bbox | null
- asset_refs[]
- source_span
- parent_block_id | null
- previous_block_id | null
- next_block_id | null
- language
- parser_name / parser_version
```

原始文件、结构化 block manifest 和展示用 Markdown 分开保存。Markdown 是展示产物，不再是唯一事实来源。

### 7.4 内存约束

- 默认单文档解析并发为 1；课程批量构建并发可配置但默认不超过 2；
- 图片使用路径引用，禁止把 base64 数据复制进每个 block/chunk；
- 嵌入按有界批次生成，完成一批立即写入向量库；
- 图片读取后及时关闭，超过像素或文件大小上限时先生成受控缩略图；
- PDF 页面图不一次性全部常驻内存；
- 单文档失败不得拖垮 worker，任务记录最后成功阶段并可重试；
- 验收需记录进程峰值 RSS，500 页教材处理不得出现 OOM。

## 8. 父子分块策略

### 8.1 分块层级

```text
Document
  └─ ParentChunk：完整小节或完整教学单元
       └─ ChildChunk：用于精确向量与关键词召回
```

建议初始参数：

- ChildChunk：目标 350～700 tokens，硬上限 900 tokens；
- ParentChunk：目标 900～1800 tokens，硬上限 2400 tokens；
- 普通文本重叠不超过 10%～15%；
- 已有明确语义边界的相邻块默认不重复；
- 参数按评测集调优，不能再使用与 embedding 输入不一致的字符截断。

### 8.2 原子结构保护

- 代码围栏、行内/块级公式、短表格、图片与图注不得从内部切开；
- 超长代码按函数/类/语句边界切分并重复必要签名；
- 超长公式与推导按等式组切分，并保留定义上下文；
- 超长表格按行切分，每块重复表头和表题；
- 列表优先保持完整，超长列表按同级项目切分；
- 提示框保留类型、标题和正文；
- 图片 chunk 必须关联最近标题、图注和邻近解释；
- 每个 child 保存 parent、previous、next ID。

### 8.3 嵌入文本

`embedding_text` 与 `display_content` 分开：

```text
embedding_text = 文档标题 + 标题路径 + 内容类型 + 完整 child 内容 + 必要图注
display_content = 原始可读 Markdown/结构化内容
```

约束：

- `embedding_text` 必须整体发送给 embedding 服务，不得静默截断；
- 超过模型/网关限制时回到分块阶段重新切分；
- 保存 token_count、embedding_input_hash、embedding_model、dimensions；
- query 与 document 的 task 类型如网关支持必须显式设置；不支持时记录降级状态；
- 重新分块或模型变化必须生成新 `index_version`。

## 9. 多模态索引

### 9.1 图片

每张有效教学图片至少产生：

1. 图片本体向量；
2. 图注/邻近解释的文本向量；
3. 指向所属 child、parent、知识点和原文档的关联。

纯装饰图、站点图标、追踪像素和低分辨率无意义图片不参与检索。OCR 结果默认不混入正文，只有质量通过时作为独立字段使用。

### 9.2 视频

- 优先使用章节/字幕时间码切分；无章节时按 30～80 秒语义窗口；
- 每段保存字幕、起止时间、1～3 张关键帧和视频路径；
- 网关支持视频 embedding 时写入视频段向量；不支持时使用字幕文本向量与关键帧图片向量；
- 返回结果必须携带时间码，前端可以跳转播放；
- 视频不得只按固定 80 秒机械切分而忽略句子和场景边界。

### 9.3 Chroma 表示

第一阶段继续使用 Chroma，同一语义单元可写入多个 point：

```text
child:<id>:text
asset:<id>:image
video-segment:<id>:video
video-segment:<id>:transcript
```

不同 point 通过 `semantic_unit_id` 聚合。未来只有在规模、过滤或多向量需求经基准证明 Chroma 无法满足时才评估 Qdrant。

## 10. 召回与上下文构建

### 10.1 检索流程

```text
权限与课程/节点过滤
  → 原问题 dense 召回
  → 原问题中文 BM25 召回
  → 可选改写问题 dense 召回
  → 图片/视频兼容向量召回
  → RRF 融合
  → reranker 精排
  → 结果多样性控制
  → parent 与相邻块扩展
  → 上下文预算装配与引用
```

### 10.2 关键规则

- 原问题始终参与召回，查询改写只能增加一路，不能替换原问题；
- 每路先召回 30～50 个候选，再融合和精排；
- 禁止在精排前按 source 去重；
- 精排后同一文档默认最多保留 2～3 个 child，可由多个高相关命中触发 parent 合并；
- dense 和 BM25 使用 RRF 或经评测的 DBSF，不再对每次查询的 min/max 距离做不稳定线性归一化；
- 距离阈值必须通过验证集按模型版本校准，不能硬编码为通用真值；
- 权威性和质量分只做轻量排序修正，不能让不相关的“权威文档”越过相关内容；
- 最终上下文去除重复标题、重复相邻段和无意义媒体元数据；
- 引用必须包含 document_id、chunk_id、节点、来源、页码或时间码。

### 10.3 失败与降级

- reranker 不可用时返回 RRF 结果并标记降级；
- BM25 不可用时使用 dense 多路召回，不伪装成混合检索；
- 图片 embedding 失败时保留资料和文本图注，但记录 `image_embedding_failed`，不得用虚拟文件名文本冒充成功图片向量；
- 没有通过最低置信门槛的资料时，回答应说明证据不足，不拼接低质量内容。

---

## 11. 前端展示与可用性

- 课程知识库和知识图谱中的文档行必须可点击、可键盘打开；
- 使用稳定 document ID 获取正文，不暴露或依赖本地绝对路径；
- Markdown 采用安全渲染，未知 HTML 不执行；
- 使用 KaTeX 渲染 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`；
- 支持 GFM 表格、代码高亮、图片图注、提示框和媒体占位；
- 课程媒体通过课程权限保护的 API 读取；个人媒体通过个人权限读取；
- 图片加载失败时显示图注和明确错误，不显示空白破图；
- 视频显示时间码并支持跳转；
- 展示标题使用 `display_name/source_title`，不显示内部哈希文件名；
- 预览正文与实际进入检索的 source span 可相互定位。

## 12. 构建、版本与回滚

### 12.1 构建版本

```text
CourseKnowledgeBuild
- build_id
- course_id
- graph_version
- parser_version
- chunker_version
- embedding_model / dimensions
- retrieval_config_version
- source_manifest_hash
- status
- quality_report_path
- started_at / completed_at
```

### 12.2 原子发布

1. 在 staging 目录和 staging index version 中构建；
2. 完成图谱、资料、媒体、分块和向量一致性检查；
3. 运行离线检索评测；
4. 指标达标后切换 active build pointer；
5. 旧版本保留一个回滚窗口；
6. 删除旧版本必须是单独、显式、可审计操作。

构建失败不得留下“图谱已更新但文档未完成”或“文档可见但向量缺失”的半成品状态。

## 13. 质量评测

### 13.1 分块质量

- 0 个静默 embedding 截断；
- 0 个被切断的代码围栏、块级公式或短表格；
- 0 个无正文的标题块进入活动索引；
- 小于 120 tokens 的 child 必须有明确原因或被合并；
- 所有媒体引用可解析，缺失资产为阻断错误；
- 结构化解析结果与原文抽样对照，文字、公式、表格和图注无实质丢失。

### 13.2 检索评测集

每个叶子知识点至少建立 5 个问题，覆盖：

- 定义与概念；
- 原理与机制；
- 比较与辨析；
- 应用与案例；
- 公式、图表或代码相关问题。

每题记录相关知识点、相关文档、相关 child/asset 和可接受证据。测试必须调用生产同款 dense、BM25、RRF、reranker 和权限过滤，不得用词项重合率代替。

### 13.3 第一版门槛

- 叶子节点资料覆盖率：100%；
- 每节点合格资料数：至少 3；
- 每节点中文资料数：至少 2；
- Recall@10：不低于 0.85；
- MRR@10：不低于 0.65；
- 知识点命中率@5：不低于 0.90；
- 有视觉证据问题的图片/视频命中率@10：不低于 0.75；
- 跨用户、跨课程资料泄漏：0；
- 引用可解析率：100%；
- 人工抽检答案证据支持率：不低于 0.90；
- 检索 P95 延迟在目标开发机上不高于 2.5 秒，不含生成模型耗时。

若当前 baseline 明显低于目标，可以分阶段提升，但新版本不得低于 baseline，且未达到正式门槛时不得标记“专业课程知识库已完成”。

## 14. 安全、许可与隐私

- 网络抓取遵守 robots.txt、站点条款和来源许可证；
- 只下载课程需要的正文和媒体，不镜像整个站点；
- 限制允许域名、重定向次数、响应大小和 MIME 类型，防止 SSRF 与恶意文件；
- SVG 默认不直接作为可执行媒体展示，转换为安全位图或拒绝；
- Markdown 不启用不受控 raw HTML；
- 媒体接口验证访问域和路径边界；
- 所有来源保留署名与许可证，不因内部使用而删除许可信息；
- 个人资料不作为系统课程建库训练材料或自动公共来源；
- 日志不得输出 API Key、认证令牌或完整私有正文。

## 15. 可观测性

每次构建和检索至少记录：

- 文档、block、parent、child、图片和视频段数量；
- 各阶段耗时、失败数、重试数和峰值内存；
- chunk token 分布和异常结构计数；
- embedding 模型、维度、批次、失败与降级；
- dense/BM25 各自候选数、RRF 候选数、rerank 输入/输出数；
- 查询是否改写、使用哪些访问域和知识点过滤；
- 最终引用和置信度；
- 质量评测版本及指标。

不得记录原始 API Key 或完整用户问题历史。

## 16. 验收标准

### 16.1 自动化验收

1. 用户上传与深度研究默认只进入个人域；
2. 系统课程建库资料只进入课程域，个人文档列表和个人 RAG source 中均不出现；
3. 显式加入课程后产生独立课程副本和课程域索引；
4. Markdown、HTML、DOCX、PDF 均能产生 ContentBlock manifest；
5. `.doc` 不再被当作普通文本读取；
6. 代码、公式、表格、图片与图注通过结构保护测试；
7. embedding 输入没有静默截断，超限时构建失败或重新分块；
8. 同一文档的多个相关 child 可以进入 reranker；
9. RRF、reranker、parent 扩展和相邻块扩展均有确定性测试；
10. 图片和视频可产生真实多模态向量或明确降级记录；
11. 课程/个人媒体 URL 不能跨权限读取；
12. 真实检索测试端点与生产检索管线一致；
13. 图谱无重复叶子、无非课程节点、稳定 ID 和关系校验通过；
14. 每个叶子至少 3 份合格资料，至少 2 份中文；
15. 构建失败不切换 active build，旧库继续可用；
16. 重复执行同一构建不会产生重复文档或重复向量。

### 16.2 人工验收

1. 随机抽取至少 10 个知识点，教师能够打开并阅读全部资料；
2. 抽取至少 20 个公式、10 个表格和 20 张图片，对照来源确认可读且归属正确；
3. 对每个模块执行概念、案例和比较型问答，引用可以跳转到正确正文；
4. 使用教师 A、教师 B 和课程外用户验证个人/课程隔离；
5. 在目标开发机处理一份大型教材，记录峰值内存且无 OOM；
6. 关闭 reranker、BM25 或图片 embedding，确认降级行为清晰且不会伪报成功；
7. 回滚到上一 build，页面和问答均恢复一致版本。

## 17. 完成定义

只有同时满足以下条件，才可以宣布“完整课程知识库”完成：

- 课程图谱通过课程结构审查且无重复、无书籍附属节点；
- 所有叶子节点达到资料数量、中文比例和质量要求；
- 图表、公式、代码和媒体通过抽检；
- 分块、索引与检索指标达到本 SPEC 门槛；
- 资料归属和跨账号权限测试全部通过；
- 前端课程知识库与问答预览均可使用；
- 来源、许可证、版本与构建报告完整；
- 有可重复的构建命令、评测命令、回滚步骤和验收证据；
- 未把序言、前言、参考文献目录、纸质书信息或空壳文档重新引入课程库。
