# 个人资源与课程发布设计 SPEC

**状态：** 待评审

**日期：** 2026-08-07

**优先级：** P0 数据边界与权限；P1 资源中心交互；P2 审计增强

**适用范围：** 生成资源的保存、读取、发布、更新发布、撤回与资源中心展示。学生端页面本期不实现，但学生权限边界必须由后端保证。

**覆盖与修订关系：** 本文细化并修订 `2026-08-06-course-centered-teacher-experience-design.md` 中“课程资源全部共享”的约定。课程仍是一级组织边界，但用户生成的资源默认属于个人；只有显式发布的课程快照属于课程成员共享结果。

---

## 1. 目标

建立 NotebookLM 式的个人创作空间，并保留教师向课程沉淀正式教学成果的能力：

1. 用户生成的资源默认仅创建者可见，其他教师和学生不可通过列表、详情或直接 URL 获知其存在；
2. 教师可以把自己的个人资源发布为课程快照；
3. 课程快照对当前课程所有成员可见，学生只读，教师按课程权限管理；
4. 个人原稿与课程快照相互独立，修改原稿不会静默改变课程内容；
5. 教师可以主动更新发布或撤回课程快照；
6. 发布只复制最终成果与安全元数据，不泄露私有对话、提示词、API 配置、个人文档路径或未发布的 RAG 上下文；
7. 保持现有课程、知识库、生成任务和正式资源类型兼容，不重写生成 Agent。

### 1.1 成功定义

最小成功闭环为：

```text
教师 A 生成资源
  → 资源只出现在教师 A 的“我的资源”
  → 教师 B 与学生不可见
  → 教师 A 点击“发布到课程”
  → 生成稳定的课程快照
  → 教师 B 与学生在“课程共享”中可见
  → 教师 A 修改个人原稿，课程快照保持不变
  → 教师 A 点击“更新发布”，课程快照才更新
```

## 2. 非目标

- 本期不实现学生端生成界面、作业提交、评分或班级管理；
- 本期不增加学校、学院、租户等组织层级；
- 本期不实现多人实时协同编辑；
- 本期不允许学生发布课程资源；
- 本期不公开生成对话、完整提示词、模型配置或私有知识库原文；
- 本期不增加审批流。教师发布立即生效，后续如需教研组审核另立 SPEC；
- 本期不迁移或重写所有历史资源文件，只保证兼容读取和可控迁移。

## 3. 当前状态

### 3.1 已有基础

- 生成资源清单已包含 `owner_user_id`、`created_by` 与 `visibility`；
- `visibility=private` 时，资源列表和详情已经能够按当前用户过滤；
- 课程权限已有 `owner/editor/viewer` 与 `read/manage_resources` 能力；
- 知识库已有 `personal/course` 与 `promoted_from_document_id`，可参考其领域表达；
- 前端课程资源中心已经支持列表、预览、搜索、筛选、置顶、重命名和删除。

### 3.2 必须修正的问题

1. 新生成资源当前默认 `visibility=course`，与“默认个人资源”相反；
2. 读取接口只能返回“课程资源 + 当前用户私有资源”的混合列表，前端无法稳定区分两个空间；
3. 当前没有发布、更新发布与撤回接口；
4. 当前资源修改接口仅依赖通用 `manage_resources`，没有区分私有所有权和课程管理权限；
5. 课程资源可能继续引用个人资源的文件路径或生成上下文，存在隐私泄露风险；
6. 前端所有生成完成提示仍暗示“已保存到课程资源”，没有说明默认仅自己可见。

## 4. 方案比较

### 方案 A：原记录直接从 `private` 改为 `course`

**优点：** 改动最小，不产生副本。

**缺点：** 发布后个人原稿消失；继续编辑会实时影响所有成员；撤回与版本恢复困难；私有元数据容易随记录一起公开。

**结论：** 不采用。

### 方案 B：保留个人原稿，发布独立课程快照（推荐）

**优点：** 私有创作和课程正式成果边界清晰；发布稳定；支持更新发布、撤回、审计；符合用户对 NotebookLM 式个人空间的预期。

**缺点：** 需要复制成果文件并维护来源关系。

**结论：** 采用。

### 方案 C：个人资源与课程资源使用两套完全独立的存储和 API

**优点：** 物理边界最强。

**缺点：** 重复实现所有资源类型、预览、下载与管理逻辑，迁移成本高，当前阶段收益不足。

**结论：** 暂不采用；沿用同一资源领域，通过清单字段、路径隔离和授权服务建立边界。

## 5. 领域模型

### 5.1 PersonalMaterial（个人资源）

个人资源是用户生成后的默认落点：

```text
PersonalMaterial
- material_id
- material_type
- course_id
- visibility: private
- owner_user_id: 当前用户
- created_by: 当前用户
- version
- title / content / artifact_paths
- source_job_id
- scope_type / scope_id
- published_material_id: 可空
- published_version: 可空
- published_at: 可空
```

约束：

- 新生成资源必须有 `owner_user_id`；
- `visibility=private` 的记录只允许所有者读取和修改；
- 课程负责人、其他教师和管理员不得因为拥有课程管理权限而绕过个人资源隔离；
- 内部迁移工具如需读取私有资源，必须走显式的内部调用，不得复用公开 HTTP 接口。

### 5.2 CourseMaterialSnapshot（课程发布快照）

课程快照是从个人资源发布出的独立记录：

```text
CourseMaterialSnapshot
- material_id: 独立且稳定的课程资源 ID
- material_type
- course_id
- visibility: course
- owner_user_id: null
- created_by: 首次发布教师
- version: 课程快照版本
- title / content / artifact_paths
- published_by
- published_at
- published_from_material_id
- published_from_owner_user_id
- published_from_version
- publication_status: published
```

约束：

- 课程快照 ID 根据 `course_id + source owner + material_type + source material_id` 生成稳定标识；重复发布同一来源时更新同一课程快照，不创建重复记录；
- 首次发布写入 `version=1`；更新发布递增课程快照版本；
- 个人资源的版本和课程快照版本分别维护；
- 发布快照不包含 `source_snapshot`、`config_snapshot`、完整提示词、会话内容、API 密钥、个人文件绝对路径或仅个人可见的文档正文；
- `artifact_paths` 必须指向课程发布目录中的独立副本，不得继续引用个人成果目录；
- 复制文件前后都必须校验路径位于课程根目录内，拒绝路径穿越和外部绝对路径。

### 5.3 历史资源兼容

- 已明确标记 `visibility=course` 的历史资源继续作为课程资源；
- 缺少 `visibility` 的历史清单按旧规则读取为课程资源，避免升级后内容消失；
- 新保存逻辑默认 `private`，不得通过修改历史清单归一化默认值来完成；
- 缺少所有者的历史资源不得自动转为私有；如需迁移，使用现有显式迁移工具并记录报告。

## 6. 权限矩阵

| 操作 | 私有资源所有者 | 其他教师 | 学生/只读成员 | 课程负责人/编辑者对课程快照 |
|---|---:|---:|---:|---:|
| 查看个人资源 | 是 | 否 | 否 | 否 |
| 重命名/置顶/删除个人资源 | 是 | 否 | 否 | 否 |
| 发布自己的个人资源 | 教师是 | 否 | 否 | 仅限自己的来源 |
| 查看课程快照 | 是 | 是 | 是 | 是 |
| 更新发布 | 来源教师是 | 否 | 否 | 必须能读取来源私有资源 |
| 重命名/置顶课程快照 | — | — | 否 | 是 |
| 撤回/删除课程快照 | — | — | 否 | 是 |

补充规则：

- “所有人可见”仅指该课程当前成员，不是系统全部用户；
- 发布同时要求：当前用户是来源私有资源所有者，且课程角色具有 `manage_resources`；
- 课程负责人和编辑者可以管理已发布快照，但不能打开或读取他人的私有来源；
- 学生端未来开放个人生成时，应新增“生成个人资源”能力，不得复用 `manage_resources`。本期保持 `viewer` 只读。

## 7. 后端接口

### 7.1 列表

```http
GET /api/courses/{course_id}/materials?space=mine
GET /api/courses/{course_id}/materials?space=course
GET /api/courses/{course_id}/materials?space=all
```

规则：

- `mine`：仅返回当前用户的 `private` 资源；
- `course`：仅返回 `course` 快照；
- `all`：返回当前用户私有资源与课程快照的并集，用于兼容现有调用；
- 未传 `space` 时暂按 `all` 处理，前端改造完成后再评估是否改默认；
- `space` 不接受任意用户 ID，所有者只能来自认证身份；
- 分页总数必须在权限和空间过滤之后计算。

### 7.2 发布或更新发布

```http
POST /api/courses/{course_id}/materials/{material_type}/{material_id}/publish
```

请求体为空。来源版本从服务端实际读取，不接受前端伪造。

返回：

```json
{
  "action": "published",
  "source_material_id": "private-id",
  "material": {
    "material_id": "published-stable-id",
    "visibility": "course",
    "published_from_version": 3,
    "version": 1
  }
}
```

重复调用同一来源时：

- 如果来源版本高于 `published_from_version`，返回 `action=updated` 并更新快照；
- 如果来源版本没有变化，返回 `action=unchanged`，不重复复制文件、不递增版本；
- 同一来源并发发布必须在存储锁内串行化，最终只存在一个课程快照。

### 7.3 撤回

```http
DELETE /api/courses/{course_id}/materials/{material_type}/{published_material_id}/publication
```

规则：

- 只接受 `visibility=course` 且具有发布来源字段的快照；
- 要求 `manage_resources`；
- 删除课程快照及其发布文件副本；
- 不删除、不修改来源个人资源；
- 将来源记录的 `published_material_id/published_version/published_at` 清空；如果操作者不是来源所有者，只通过内部受控写入清理链接，不向操作者返回来源内容。

### 7.4 详情和修改

- 详情接口继续返回 404 隐藏无权访问的私有资源，不使用 403 暴露资源存在性；
- 重命名、置顶、删除改为资源感知授权：私有资源检查所有权，课程快照检查 `manage_resources`；
- 下载、预览和完整性检查使用同一授权判断，不允许通过附件 URL 绕过清单权限；
- 所有错误返回稳定 `detail.code`：
  - `MATERIAL_NOT_FOUND`
  - `MATERIAL_PUBLISH_FORBIDDEN`
  - `MATERIAL_NOT_PRIVATE`
  - `MATERIAL_PUBLICATION_INVALID`
  - `MATERIAL_ARTIFACT_UNSAFE`

## 8. 发布服务边界与数据流

新增聚焦的领域服务，避免把复制、脱敏、权限与路由逻辑继续堆入 `courses.py`：

```text
MaterialPublicationService.publish(...)
  1. 在当前用户身份下读取来源私有资源
  2. 验证课程管理权限与来源所有权
  3. 计算稳定课程快照 ID
  4. 构造允许字段清单，不做黑名单式脱敏
  5. 校验并复制成果文件到课程发布目录
  6. 在存储锁内原子写入或更新课程快照
  7. 写回个人资源的发布链接
  8. 返回发布动作与课程快照
```

### 8.1 允许发布的字段

基础允许字段：

- `material_type`、`title`、`topic`、`summary`；
- 资源最终内容字段，如 `final_markdown`、`report`、`questions`、`plan`、`stage/scenes`、`flashcards`；
- 安全的展示统计，如场景数、页数、题目数；
- 相对课程发布路径；
- `course_id`、发布版本与发布审计字段。

明确禁止字段：

- API Key、令牌、模型服务地址中的凭据；
- 对话历史、内部思考、完整系统提示词；
- `config_snapshot` 与原始 `source_snapshot`；
- 个人知识库的绝对路径、原始 RAG 文件路径；
- 未单独发布的源文档全文；
- 后台任务执行栈、内部错误详情。

不同资源类型如需额外字段，在资源类型适配器中显式加入允许清单，不允许直接复制整个原始字典。

### 8.2 原子性与失败处理

- 先复制到临时发布目录，全部成功后再替换正式目录；
- 清单写入使用现有原子 JSON 写入能力；
- 任一步骤失败都清理临时文件，保留旧课程快照和个人原稿；
- 更新发布失败不得使旧课程快照不可用；
- 撤回采用先移出正式路径、再更新清单的可恢复顺序，并记录错误日志。

## 9. 前端资源中心

### 9.1 信息架构

课程资源中心顶部增加一级空间切换：

```text
[我的资源] [课程共享]
```

- 默认进入“我的资源”；
- “我的资源”只展示当前用户生成结果，并显示“仅自己可见”；
- “课程共享”展示已发布快照，并显示发布教师与更新时间；
- 现有资源类型、搜索、排序、置顶筛选作为二级筛选保留；
- 两个空间分别显示数量，避免把个人资源数量误认为课程成果数量。

### 9.2 操作

个人资源详情：

- 教师显示主操作“发布到课程”；
- 已发布且个人版本未变化时显示“已发布”；
- 个人版本高于发布来源版本时显示“更新发布”；
- 删除个人资源前，如果存在课程快照，明确提示“不会删除已发布的课程版本”。

课程共享详情：

- 学生只显示查看、下载与预览；
- 教师按权限显示重命名、置顶和“撤回课程”；
- 不显示“查看个人原稿”给非来源教师；
- 撤回必须二次确认，文案说明个人原稿仍会保留。

### 9.3 生成完成反馈

将现有“结果已保存到课程资源”统一修改为：

> 生成完成，已保存到“我的资源”，仅你可见。

提供次级操作“查看资源”。不在生成完成时自动发布，也不弹出强制发布确认。

### 9.4 响应式与无障碍

- 1024×768 下空间切换、搜索与筛选不得横向溢出；
- 发布、撤回按钮必须有文字标签，不能只使用图标；
- 切换空间后焦点保留在对应 tab，使用 `role=tablist/tab` 与 `aria-selected`；
- 发布过程中禁用重复提交并显示明确进度；
- 发布错误保留当前资源和选择状态，允许重试。

## 10. 分阶段优先级

### P0：数据边界与发布闭环

**目标：** 确保新资源默认私有，跨账号不可见，教师能够发布稳定课程快照。

**范围：** 存储默认值、空间过滤、资源感知授权、发布服务、发布/撤回接口、附件路径隔离、后端测试。

**阻断条件：** 任一私有资源可被其他账号读取，或课程快照引用个人文件路径，均不得进入 P1。

### P1：资源中心交互

**目标：** 用户能清楚区分个人成果和课程共享成果，并完成发布、更新发布与撤回。

**范围：** API 客户端、类型、空间 tab、状态标签、权限操作、生成完成文案、组件测试与视觉验收。

### P2：审计与运营增强

**目标：** 提高长期管理和问题追溯能力。

**范围：** 发布历史列表、版本恢复、批量发布、课程资源审核。本期只预留字段，不实现页面。

## 11. 验收标准

### 11.1 P0 自动化验收

以下用例必须由后端真实存储与 API 测试覆盖：

1. 教师 A 新生成资源默认是 `private`，且具有 `owner_user_id=teacher-a`；
2. 教师 A 能在 `space=mine` 看到资源；教师 B 和学生在列表、详情、下载中均不可见；
3. 教师 A 发布后，课程快照出现在 `space=course`，教师 B 和学生可读；
4. 课程外用户不可读取课程快照；
5. 教师 B 不能发布教师 A 的私有资源；学生不能发布任何资源；
6. 修改教师 A 的个人原稿后，课程快照内容和版本保持不变；
7. 更新发布后，同一课程快照 ID 保持不变，快照版本递增且内容更新；
8. 未修改来源时重复发布返回 `unchanged`，不创建重复文件和记录；
9. 撤回后所有课程成员不再看到快照，教师 A 的个人原稿仍存在；
10. 发布清单和文件中不包含测试夹具里的 API Key、绝对个人路径、提示词与私有文档正文；
11. `../`、绝对路径和课程根目录外路径发布失败，旧快照保持可用；
12. 历史 `course` 资源升级后仍可见，缺少 `visibility` 的旧资源不被错误转为他人私有资源；
13. 两次并发发布最终只产生一个课程快照；
14. 私有资源的重命名、置顶、删除无法由其他教师借助课程管理权限执行。

### 11.2 P1 自动化与视觉验收

1. 资源中心存在“我的资源／课程共享”两个一级 tab，调用正确的 `space` 参数；
2. 教师在个人资源上看到“发布到课程／更新发布／已发布”的正确状态；
3. 学生不渲染发布、更新、撤回、重命名或删除课程资源的操作；
4. 发布成功后课程共享列表可见，个人资源仍保留；
5. 撤回成功后课程共享列表移除，个人列表不受影响；
6. 生成完成提示明确说明默认仅自己可见；
7. 1024×768、1366×768、1440×900、1920×1080 下无横向溢出、按钮遮挡或详情区裁切；
8. 键盘可以完成空间切换、选择资源、发布与关闭确认框；
9. 前端单元测试、ESLint、生产构建和课程资源视觉回归全部通过。

### 11.3 人工跨账号验收脚本

1. 使用教师 A 生成一份报告，记录标题与个人版本；
2. 使用教师 B 打开同一课程，确认看不到该报告；
3. 切回教师 A 发布到课程；
4. 教师 B 刷新“课程共享”，确认可以预览但无法访问教师 A 的个人原稿；
5. 教师 A 修改个人报告，教师 B 确认课程版本未变化；
6. 教师 A 更新发布，教师 B 确认课程版本变化；
7. 使用学生账号确认只读；
8. 教师 B 撤回课程快照，教师 A 的个人报告仍存在。
