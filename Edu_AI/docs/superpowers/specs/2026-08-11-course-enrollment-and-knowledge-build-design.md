# 课程加课、成员管理与课程知识库构建设计

**状态：** 已确认，待实施  
**日期：** 2026-08-11  
**代码基线：** `1656e35`  
**数据库基线：** `20260810_0010`

## 1. 目标

打通以下正式产品闭环：

1. 教师创建并初始化一门课程；
2. 系统为课程生成与内部 `course_id` 分离的唯一课程码；
3. 课程所有者在同一页面统一管理教师和学生成员；
4. 学生在学生首页输入课程码加入课程；
5. 教师根据课程语义一键构建知识库；
6. 系统生成至少三层、结构合理的知识图谱；
7. 每个叶级知识点至少关联三份通过质量检查的资料；
8. 学生加入后可以读取与教师端一致的课程知识图谱和课程资料。

本设计在现有课程创建、课程权限、知识库构建记录、后台任务、质量门禁、版本发布和回滚能力上增量实现，不建立第二套课程或知识库系统。

## 2. 当前基线与缺口

合并后的系统已经具备：

- 教师首页创建课程入口和创建表单；
- `POST /api/courses` 创建课程并把创建者设为 `owner`；
- 创建成功后的课程初始化引导；
- 按课程标题、目标、学段和语言生成知识主题；
- 开放来源预审、后台抓取、RAG 入库、质量检查、原子发布与版本回滚；
- 教师端构建卡片和学生端只读知识库页面。

当前缺口：

- `courses` 没有课程码；
- 没有学生凭码加入接口和界面；
- 没有课程成员列表、添加、调整角色和移除能力；
- `DEV_AUTO_ENROLL_ALL_COURSES` 默认开启，新课程会自动加入全部已有用户；
- 中文课程只执行一轮中文来源搜索，没有中文不足时再搜索英文；
- 只要存在一个审核通过来源即可启动构建；
- 当前质量门禁只检查总体入库和部分主题覆盖，没有逐叶节点三份资料门槛；
- 当前图谱只有根节点和主题节点两层；
- 没有模型生成补充资料的兜底链路。

## 3. 核心设计原则

### 3.1 课程身份与加课身份分离

- `course_id` 是内部稳定主键，用于路由、权限和数据归属。
- `course_code` 是给教师和学生使用的加课标识，不进入内部文件路径。
- 课程码可以重置；重置后旧课程码立即失效，但现有成员关系不变。
- 课程码不是登录凭证。只有已登录学生可以使用课程码加入课程。

### 3.2 成员关系只有一个事实来源

- 正式运行只读写 PostgreSQL 的 `course_memberships`。
- 不恢复 JSON 双写，不建立前端本地成员列表。
- 创建课程时只写入创建者的 `owner` 关系。
- 关闭自动把全部用户加入课程的默认行为。

### 3.3 图谱结构以课程语义为主

- 图谱至少包含根节点在内的三层结构：课程根节点、课程模块或主题域、叶级知识点。
- 可以根据课程内容继续增加层级，但所有节点必须有明确教学语义。
- 不规定每个非叶节点必须有多少子节点，不允许用“模块一”“其他知识”等空壳节点拼凑层级。
- 叶级知识点是资料覆盖和 RAG 作用域的最小单元。

### 3.4 资料补齐顺序固定

每个叶级知识点都按以下顺序补齐资料：

1. 优先搜索、审核和抓取中文资料；
2. 中文合格资料不足三份时，再搜索英文资料；
3. 中文和英文资料成功入库后仍不足三份时，调用模型生成缺失数量的中文补充资料；
4. 模型生成资料通过结构检查和独立质量审查后，才计入三份门槛。

模型生成资料不得伪造网址、作者、许可证或引用。界面和数据中必须明确标记为“AI 生成补充资料”。

## 4. 数据模型

### 4.1 `courses.course_code`

新增 Alembic 迁移 `20260811_0011_course_codes_and_membership`：

- `courses.course_code VARCHAR(16)`；
- 非空；
- 建立大小写无关的唯一约束或保存前统一大写并建立普通唯一索引；
- 为现有课程回填稳定且唯一的课程码；
- 新课程使用密码学安全随机数生成器生成八位课程码。

新课程码字符集为：

```text
ABCDEFGHJKLMNPQRSTUVWXYZ23456789
```

排除 `I`、`O`、`0`、`1`，降低人工输入错误。接口接收时去除首尾空格和中间短横线并转为大写。

### 4.2 `course_memberships`

沿用现有联合主键 `(course_id, user_id)` 和角色：

- `owner`：课程所有者，可管理成员、重置课程码、删除课程；
- `editor`：协作教师，可编辑课程并构建知识库；
- `viewer`：学生或只读成员，只能读取课程内容。

MVP 不提供所有权转移。创建者的 `owner` 关系不可被成员管理接口降级或移除。系统角色为 `student` 的用户只能成为 `viewer`；`teacher/admin` 可以成为 `editor` 或 `viewer`。

### 4.3 构建计划扩展

知识库构建计划新增并持久化：

- `graph_draft`：至少三层的待发布图谱草案；
- `leaf_topics`：所有叶节点及其检索查询；
- `source_strategy`：每个叶节点中文、英文和模型补充阶段的状态；
- `coverage`：每个叶节点成功入库的不同文档 ID；
- `generation_audit`：模型、提示版本、生成时间、审查结果和重试次数。

现有 `knowledge_builds.plan_snapshot`、`metrics` 和 `knowledge_quality_checks` 可以承载这些结构，不新增并行业务存储。

## 5. 后端接口

### 5.1 课程创建

`POST /api/courses` 保持现有请求格式，响应增加仅对创建者可见的可选字段：

```json
{
  "id": "course-...",
  "course_code": "K7M9Q2WP",
  "membership_role": "owner"
}
```

创建事务的业务结果必须包含：课程记录、唯一课程码、创建者 `owner` 成员关系。任何一步失败都不得留下可见的半成品课程。

### 5.2 学生凭码加入

```http
POST /api/courses/join
Content-Type: application/json

{"course_code":"K7M9Q2WP"}
```

规则：

- 仅已登录且系统角色为 `student` 的用户可调用；
- 有效课程码创建 `viewer` 成员关系；
- 重复加入返回现有关系，保持幂等；
- 无效或已重置课程码返回统一的 404 业务错误，不泄露相似课程；
- 成功响应包含课程摘要和 `viewer` 角色，前端随后进入学生课程详情页。

### 5.3 课程成员管理

仅课程 `owner` 可调用：

```text
GET    /api/courses/{course_id}/members
POST   /api/courses/{course_id}/members
PATCH  /api/courses/{course_id}/members/{user_id}
DELETE /api/courses/{course_id}/members/{user_id}
POST   /api/courses/{course_id}/course-code/rotate
```

成员列表返回 `user_id`、用户名或显示名、系统角色、课程角色、加入时间和添加人，不返回密码哈希或完整用户原始数据。

添加成员按用户名查找现有用户；系统角色与课程角色不匹配时返回 422。重复添加保持幂等。不能降级或删除课程创建者。重置课程码返回新课程码，并留下结构化审计信息。

## 6. 前端流程

### 6.1 教师端

1. 教师在首页点击“创建课程”；
2. 完成初始化表单；
3. 创建成功后进入课程概览；
4. 初始化区域显示课程码，并提供复制按钮；
5. 课程设置新增“课程成员”区域：
   - 展示课程码；
   - 复制或重置课程码；
   - 查看成员；
   - 添加协作教师或学生；
   - 调整 `editor/viewer`；
   - 移除非所有者成员；
6. 教师进入课程知识页生成方案并开始构建。

成员管理拆成独立组件和样式文件，避免继续扩大当前 `CourseEdit.tsx` 和全局 `styles.css`，并减少与当前未提交前端优化的冲突。

### 6.2 学生端

学生首页在课程列表上方提供“加入课程”入口：

1. 输入课程码；
2. 前端规范化并提交；
3. 成功后刷新“我的课程”；
4. 自动进入该课程；
5. 学生只能查看课程知识图谱、资料、学习任务和已发布资源，不显示成员管理或知识库构建控件。

## 7. 知识图谱规划

### 7.1 结构约束

发布前图谱必须同时满足：

- 恰好一个课程根节点；
- 最短根到叶路径包含至少三个节点；
- 至少存在一个模块或主题域节点；
- 所有节点 ID 唯一；
- 不存在环；
- 除根节点外所有节点都可从根节点到达；
- 只有叶节点关联资料；
- 所有叶节点都能映射到课程目标或课程描述中的明确主题。

课程较小时允许：一个课程根节点、一个真实模块节点和若干叶级知识点；不因层级约束虚构不相关知识点。课程目标不足以形成合理结构时，构建计划应要求教师补充课程信息，而不是生成空壳层级。

### 7.2 规划输出

规划器输出稳定 JSON：

```json
{
  "root": {
    "id": "course-root",
    "label": "Python 控制流程入门",
    "children": [
      {
        "id": "module-control-flow",
        "label": "控制流程基础",
        "children": [
          {
            "id": "topic-conditional",
            "label": "条件判断",
            "children": [],
            "data": {"type": "knowledge_point"}
          }
        ]
      }
    ]
  }
}
```

模型规划失败或输出无效时，允许从课程目标构造确定性三层图谱：根节点下按课程目标的主题归组为真实模块，再在模块下放置叶级知识点。确定性兜底同样必须通过结构与语义检查。

## 8. 来源获取与模型补充

### 8.1 中文阶段

每个叶节点独立执行中文查询。候选来源必须满足：HTTPS、允许抓取、域名或来源许可可验证、正文长度达标、与知识点相关。优先级依次为官方文档、高校开放课程、开放教材、可信教育社区和经过审核的参考资料。

### 8.2 英文阶段

中文资料成功入库不足三份时，才执行英文查询。英文资料沿用原文，记录 `source_language=en` 和许可信息，并在界面明确标记语言。英文来源不覆盖或冒充中文来源。

### 8.3 模型生成阶段

抓取和索引结束后按叶节点计算缺口。每缺一份生成一份互补类型的中文材料，类型按以下顺序选择：

1. 核心概念讲义；
2. 示例与推导；
3. 常见误区与练习。

每份生成资料必须：

- 聚焦一个叶级知识点；
- 使用课程学段和难度；
- 不少于 800 个中文字符；
- 包含学习目标、核心内容、示例或练习、总结；
- 不包含虚构引用和虚构来源；
- 记录 `source_type=model_generated`、模型标识、提示版本和生成时间；
- 通过确定性结构检查；
- 通过独立质量审查，得分至少 80/100。

质量审查失败时只允许再生成一次；仍不合格则阻止发布，并向教师显示具体叶节点和失败原因。

## 9. 质量门禁与发布

新增质量检查：

- `graph_structure`：三层、唯一 ID、无环、全部可达；
- `leaf_semantic_alignment`：叶节点与课程语义一致；
- `leaf_document_coverage`：每个叶节点至少三个不同的 ready 文档；
- `source_priority_trace`：证明按中文、英文、模型顺序补齐；
- `generated_material_quality`：所有模型资料结构和审查通过；
- `rag_index_integrity`：图谱引用的文档均已成功建立索引。

只有所有强制检查通过才允许 `publish_build()` 创建新图谱版本。失败构建保留计划、候选来源、失败详情和质量结果，不替换当前活动版本。

构建结果按叶节点展示：中文资料数、英文资料数、AI 补充资料数、总数和警告。AI 生成占比较高不自动伪装为高可信来源，教师可以清楚识别。

## 10. 错误处理与权限边界

- 学生创建课程：403；
- 教师或管理员通过学生加课接口加入：403；
- 非所有者查看或修改成员：403；
- 无效课程码：404；
- 学生被移除后访问课程：403；
- 学生直接调用知识库构建：403；
- 图谱不足三层：构建 blocked，不发布；
- 任一叶节点不足三份合格资料：构建 blocked，不发布；
- 模型不可用且资料不足：构建 blocked，返回缺口；
- 构建失败不清空旧图谱和旧资料。

## 11. 端到端验收课程

验收时由执行者通过真实教师页面创建一门小型课程，例如：

```text
课程名称：Python 控制流程入门
教学对象：零基础大学一年级学生
模块：控制流程基础
叶级知识点：条件判断、循环控制
```

实际图谱可由规划器根据课程信息调整名称和分组，但必须至少三层、结构合理，并至少包含两个有教学意义的叶级知识点。每个叶节点至少关联三份合格资料，因此该小型课程至少有六个叶节点—文档关联。

验收通过教师创建、复制课程码、学生凭码加入、教师查看成员、教师启动构建、图谱发布、教师读取和学生读取全流程完成。测试课程保留供用户复核，最终报告记录课程 ID、课程码、构建 ID、图谱版本和质量指标。

## 12. 非目标

本阶段不实现：

- 多个并行邀请码、邀请码过期时间或班级分组；
- 邮件或短信邀请；
- 学生自助退出课程；
- 所有权转移；
- 强制每个模块包含固定数量的子节点；
- 为了达到三层而创建无语义节点；
- 自动删除端到端验收课程。

## 13. 完成标准

只有以下条件全部满足才算完成：

- 数据库迁移可升级，Alembic 无漂移；
- 新课程有唯一课程码，且只自动加入创建者；
- 学生可凭码加入，错误课程码不会加入；
- 所有者可统一管理成员和重置课程码；
- 课程知识图谱至少三层且无拼凑节点；
- 每个叶级知识点至少三个不同的合格资料；
- 中文优先、英文补充、模型兜底的顺序有可审计证据；
- AI 资料有明确标记并通过质量审查；
- 教师端和学生端读取同一发布版本；
- 自动化测试、前端构建和真实浏览器端到端验收通过。
