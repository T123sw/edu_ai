# 教师端 P0：基础可用性与统一任务中心 SPEC

**状态：** 待评审
**日期：** 2026-08-06
**适用范围：** `Edu_AI` 教师端
**目标版本：** 教师端基础可用版本
**依赖：** 复用现有课程、课程资源、OpenMAIC 课堂、`EduJob`、认证和 Hash 路由
**不包含：** RAG 效果升级、API 配置中心、Agent 记忆升级、数据库化重构

---

## 1. 文档目的

本 SPEC 将 P0 从“问题清单”落实为可直接设计、开发和验收的系统方案，解决五类基本可用性问题：

1. 教师工作台在常见桌面宽度下发生横向裁切；
2. 在线课堂仍是技术验收页，缺少适合教师授课的按页交互外壳；
3. 左侧导航缺少“课程资源”，课程知识库输入与生成结果输出概念混淆；
4. 后台任务由各页面分别轮询，刷新、跳转、多标签页时可能丢失；
5. 路由、加载、空状态和错误恢复缺少统一标准。

P0 完成后的最低体验是：

> 教师可以上传或选择资料、发起生成、刷新页面、从任务中心恢复进度、在课程资源中找到结果，并进入 AI 课堂按页授课或导出。

## 2. 已确认的产品决策

以下决策已经确定，实施时不得重新解释为另一套方向。

### 2.1 在线课堂采用按页模型

- 课堂的基本单位是 `scene/page`；
- 教师通过场景目录、上一页、下一页控制授课；
- 当前页存在配音、焦点动作或嵌入媒体时，可播放／暂停当前页；
- 在线课堂不提供全课程时间轴、总时长拖拽和跨页倍速；
- 视频导出继续通过无头浏览器执行所有页面动作，并生成内部全局时间线；
- 全局时间线是视频渲染产物，不是教师在线授课界面。

### 2.2 AI 课堂属于课程资源

- 数据层：AI 课堂是 `material_type=classroom` 的课程资源；
- 导航层：“AI 课堂”和“课程资源”并列；
- AI 课堂入口负责创建、播放和导出；
- 课程资源入口负责统一搜索、筛选、预览、重命名、置顶和删除；
- 两处使用相同 `course_id + material_id`，不得产生两份课堂记录。

### 2.3 课程知识库与课程资源分开

- 课程知识库是教师上传并供 RAG 使用的输入资料；
- 课程资源是 AI 或教师产生的输出成果；
- 左侧同时保留两者，不能把课程知识库改名成课程资源。

### 2.4 后台任务统一管理

- 后端任务记录是任务状态的唯一可信来源；
- 前端组件不得各自拥有独立轮询体系；
- 浏览器 `localStorage` 只能作为显示缓存，不能作为任务是否存在的依据；
- 第一阶段统一使用轮询，不强制引入 SSE 或 WebSocket；
- 页面刷新、跳转或重新登录后必须能从后端恢复未完成任务。

## 4. 当前实现基线

## 4.1 可复用能力

- Hash 路由已经包含 `resources`、`classroom-studio` 和 `classroom-player`；
- `CourseResourcesPage` 已能读取 `/api/courses/{course_id}/materials`；
- AI 课堂已经作为 `classroom` 类型落入课程生成资源；
- 课堂生成与视频导出已经使用 `EduJob`；
- `EduJob` 已按 JSON 文件持久化到 `Config.STORAGE_ROOT/jobs/`；
- `/api/jobs/{edu_job_id}` 已支持鉴权查询单个任务；
- 课堂页面已有刷新恢复的局部 `localStorage` 方案；
- 前端已有课堂生成、视频导出、时间线和语音降级测试。

## 4.2 必须补齐的缺口

- `SidebarNav` 没有课程资源入口；
- 课程设置仍显示为“详情编辑”；
- `CourseResourcesPage` 类型标签不完整，没有 `classroom`、`graph`、`game` 等；
- 资源预览按钮无论资源类型都跳到视频页；
- 前端 `GeneratedFile` 类型未包含 `classroom`；
- 当前教师端 `STUDIO_ACTIONS` 只注册六张资源卡；PPT 和闪卡是既有能力，加入 AI 课堂入口后的界面调整造成入口回归，不应按新功能处理；
- PPT 的历史直接入口、配置面板与生成链路可作为恢复基线；当前仍保留 PPT 预览、导出和课程资源读取能力；
- 闪卡已有前端类型、配置形态及后端资源路由／槽位基础，恢复入口时必须回归生成与保存闭环，不能用占位结果代替；
- `EduJob` 只声明 `generate_classroom` 和 `render_video`；
- 任务接口只能按 ID 查询，不能恢复“当前用户的所有未完成任务”；
- `EduJob` 缺少课程 ID、输入摘要、父任务、重试关系、取消状态和版本；
- `list_jobs()` 没有所有者过滤；
- `_write()` 直接写目标 JSON，缺少原子替换和并发保护；
- 报告、习题、小游戏、博客和 RAG 仍有各自的前端轮询；
- 工作台三栏在 992～约 1530px 存在布局死区；
- 在线课堂播放器固定 960×540，并显示内部场景字段。

## 5. 总体系统架构

```text
┌────────────────────────────── 教师端 App Shell ──────────────────────────────┐
│ 左侧导航                    顶部任务入口                   当前课程上下文      │
│ 问答 / 知识库 / 图谱 /      运行数 / 失败数 / 最近完成     course_id / scope   │
│ AI课堂 / 课程资源 / 设置                                               │
├──────────────────────────────────────────────────────────────────────────────┤
│ 业务页面                                                               │
│ Workspace / Classroom / CourseResources / KnowledgeBase / Graph / Settings  │
│      │ 只提交任务和订阅状态                                                │
│      ▼                                                                      │
│ GlobalJobManager + CourseResourceStore                                     │
└──────┬───────────────────────────────┬───────────────────────────────────────┘
       │统一任务 API                    │课程资源 API
       ▼                               ▼
┌──────────────────┐          ┌────────────────────────┐
│ Job API          │          │ Course Material API    │
│ create/list/get  │          │ list/get/pin/delete    │
│ cancel/retry     │          │ classroom 同一记录      │
└────────┬─────────┘          └────────────┬───────────┘
         ▼                                ▼
┌──────────────────┐          ┌────────────────────────┐
│ Job Store        │          │ Course Storage         │
│ 持久化任务账本    │          │ 课程生成资源与附件       │
└────────┬─────────┘          └────────────────────────┘
         ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ Worker / Services：报告、教案、习题、小游戏、课堂生成、视频导出、RAG 导入     │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.1 架构原则

1. **任务和资源分离：** 任务描述“过程”，资源描述“结果”；
2. **后端为准：** 刷新后从后端恢复任务与资源；
3. **统一身份：** 课程资源统一使用 `course_id + material_type + material_id`；
4. **组件订阅：** 页面组件不自行实现轮询；
5. **传输可替换：** 业务页面不感知轮询、SSE 或 WebSocket；
6. **渐进迁移：** 先接入课堂、视频和直接生成任务，再迁移其余任务；
7. **不伪装成功：** 只有任务完成且资源持久化成功，状态才是 `succeeded`。

## 6. 左侧信息架构

## 6.1 正式导航顺序

```text
问答
课程知识库
知识图谱
AI 课堂
课程资源
课程设置
```

### 6.2 路由映射

| 导航名称 | 现有／目标路由 | 数据范围 | 主要动作 |
|---|---|---|---|
| 问答 | `#ai` | 当前课程与知识点 | 问答、选择资料、生成 |
| 课程知识库 | `#knowledge` | 当前课程 RAG 文档 | 上传、索引、删除、测试 |
| 知识图谱 | `#graph` | 当前课程图谱 | 浏览、导入、问答 |
| AI 课堂 | `#classroom-studio` | `material_type=classroom` | 创建、打开、播放、导出 |
| 课程资源 | `#resources` | 当前课程全部材料 | 搜索、筛选、预览、管理 |
| 课程设置 | `#edit` | 当前课程元数据 | 基础信息、结构设置 |

### 6.3 导航行为

- 每个导航项必须保留当前 `course_id`；
- 没有课程上下文时跳回课程选择页，不得使用默认伪课程继续写入；
- 当前路由高亮；
- 收起状态只显示图标，但提供 Tooltip 和可访问名称；
- 1280px 以下允许侧栏收起，不能压缩主内容到不可用；
- “课程资源”使用资源／文件夹图标，不与“课程知识库”的书本图标混淆；
- “AI 课堂”继续使用播放／课堂图标；
- “课程设置”使用齿轮图标。

### 6.4 验收标准

- 六个入口全部可达；
- 课程知识库和课程资源的页面标题、空状态和说明文案不混用；
- 在任一路由刷新后，当前课程不丢失；
- 无有效课程 ID 时不发生数据写入；
- 侧栏收起后仍可通过键盘访问全部入口。

## 7. 教师工作台响应式设计

## 7.1 布局目标

工作台包含知识来源、对话、生成工厂三个主要区域。布局优先级为：

1. 对话输入和回答始终可用；
2. 生成入口全部可见；
3. 知识来源可折叠或进入抽屉；
4. 不产生横向滚动和不可见操作。

## 7.2 断点策略

| 可用内容宽度 | 布局 | 生成卡片列数 |
|---:|---|---:|
| ≥ 1540px | 三栏同时展开 | 3 |
| 1200～1539px | 对话固定居中，左右栏至少一个折叠；用户可切换 | 2 |
| 992～1199px | 对话主区 + 右侧／左侧抽屉 | 2 |
| 768～991px | 单主区 + 顶部标签切换三面板 | 2 |
| < 768px | 单列，面板全屏切换 | 1 |

断点以主工作区实际 `clientWidth` 为准，不直接以浏览器 `vw` 推算。

## 7.3 CSS 和容器约束

- 三栏容器不得使用无法满足的固定最小宽度组合；
- 主区域使用 `minmax(0, 1fr)`；
- 所有 Grid/Flex 子项必须允许 `min-width: 0`；
- 页面根节点禁止横向溢出；
- `overflow: hidden` 只用于明确需要裁切的装饰层；
- 页面最多保留一个主纵向滚动区；
- 卡片区域使用 `repeat(auto-fit, minmax(...))` 或等效布局；
- 弹窗和下拉菜单不得被父级 overflow 裁切。

## 7.4 生成卡片

P0 正式展示八个既有资源能力，PPT 与闪卡属于入口恢复，不属于新增资源类型：

- 报告；
- 教案；
- 教学博客；
- 习题；
- PPT；
- 闪卡；
- 小游戏；
- 思维导图。

AI 课堂作为独立主卡放在八个资源卡片上方；数据层仍与其他资源一样进入课程资源总列表。视频继续作为 AI 课堂派生导出，音频不在 P0 新增直接入口。

固定展示顺序：

```text
AI 课堂（独立主卡）
报告 | 教案 | 教学博客
习题 | PPT  | 闪卡
思维导图 | 小游戏
```

布局规则：

- 生成区可用宽度 ≥ 420px 时优先 3 列，280～419px 为 2 列，更窄时为 1 列；
- 8 张资源卡允许形成 `3 + 3 + 2`，最后一行左对齐，不通过缩小字号、隐藏说明或负间距“塞进一屏”；
- 生成区自身可纵向滚动，AI 课堂主卡固定在资源卡网格之前但不遮挡网格；
- 卡片数量来自显式能力注册表，布局不得用固定高度、固定两行或 `nth-child` 隐藏超出项；
- 恢复 PPT、闪卡后同步更新空状态文案、键盘顺序、埋点、任务类型和资源筛选。

卡片要求：

- 卡片主操作进入配置，不直接无确认生成；
- 快速生成作为明确次级按钮；
- 卡片使用语义按钮或支持 `role/button + tabIndex + Enter/Space`；
- 标题、说明和状态在 1440px 下不得隐藏；
- 不用 hover 作为唯一信息入口。

PPT 恢复要求：

- 复用既有“资料选择 → 参数配置 → 大纲确认 → 后台生成 → 预览／导出 → 保存”的产品流程；
- 不重新实现第二套 PPT 引擎；若当前主链路已切换到 AI 课堂／Agent 工具，则卡片通过统一命令适配该链路；
- 任务类型统一为 `generate_ppt`，成功结果保存为 `material_type=ppt`；
- 已生成 PPT 可在生成工厂预览，也可从课程资源重新打开和导出。

闪卡恢复要求：

- 复用既有配置语义，至少包含标题／主题、卡片数量、难度或受众、可选分类和资料范围；
- 输出采用稳定结构（至少含正面、背面、顺序，可选分类／来源），禁止用“开发中”占位文件表示成功；
- 任务类型统一为 `generate_flashcard`，成功结果保存为 `material_type=flashcard`；
- 预览支持逐张翻阅、正反面切换，并可从课程资源刷新后重新打开。

## 7.5 验收标准

- 1280、1366、1440、1600、1920px 下 `scrollWidth <= clientWidth`；
- 八张资源卡和 AI 课堂入口全部可见；
- PPT、闪卡入口在首次加载、侧栏展开／收起及浏览器缩放后都不消失；
- PPT、闪卡均完成配置、生成、后台恢复、预览、保存和刷新重开的一次端到端验收；
- 侧栏折叠、展开时对话输入框不离开视口；
- 页面只出现预期的纵向滚动；
- 键盘可以依次访问所有生成入口。

## 8. 课程资源页设计

## 8.1 页面职责

课程资源页是当前课程所有生成结果的统一管理入口，不负责创建复杂资源。创建动作仍位于问答／生成工厂或 AI 课堂入口。

### 8.2 资源类型

P0 前端必须识别：

```text
report
lesson_plan
blog
quiz
game
graph
ppt
flashcard
classroom
video（若已有独立记录）
audio（只兼容已有记录，不开放生成）
```

前端类型定义必须加入 `classroom`，不能把课堂降级成 `unknown`。

### 8.3 页面结构

```text
┌ 课程资源 ─ 搜索 ─ 类型筛选 ─ 排序 ─ 仅看置顶 ┐
│ 全部  AI课堂  教案  报告  PPT  闪卡  习题  互动  其他 │
├──────────────────────┬────────────────────────┤
│ 资源卡片列表／网格     │ 资源详情／预览           │
│ 类型、标题、时间、状态 │ 标题、来源、预览、操作    │
└──────────────────────┴────────────────────────┘
```

### 8.4 AI 课堂卡片

AI 课堂在资源列表显示：

- 标题；
- 场景数；
- 创建时间／更新时间；
- 语音状态；
- 最近视频导出状态；
- 来源资料数量；
- 打开课堂；
- 导出 PPTX；
- 导出 MP4；
- 重命名；
- 删除。

点击课堂主区域必须进入 `#classroom-player?course_id=...&classroom_id=...`，不能跳到通用 Markdown 预览或固定视频页。

### 8.5 同一资源规则

- AI 课堂页和课程资源页都从课程材料接口读取课堂；
- 课堂列表不得维护第二份 index；
- 课堂资源的 `material_id` 就是 `classroom_id`；
- 删除、重命名、置顶均调用课程资源通用接口；
- 视频导出结果作为课堂的派生信息或关联资源，不复制课堂本体；
- 任务 `result_ref` 必须能定位此资源。

### 8.6 P0 基础筛选

- 全部；
- AI 课堂；
- 文稿：报告、博客；
- 教学设计：教案；
- 课件：PPT；
- 学习卡：闪卡；
- 测评：习题；
- 互动：小游戏、思维导图；
- 其他。

### 8.7 验收标准

- 左侧导航可进入课程资源页；
- “全部”包含 AI 课堂；
- AI 课堂筛选只显示 `classroom`；
- 同一课堂从两个入口打开时 ID 一致；
- 课堂卡片不会出现“去视频页”这种错误通用操作；
- 未知类型仍可显示基本元数据，但不会执行错误预览；
- 资源加载失败提供重试；
- 空状态引导用户去问答／生成工厂或 AI 课堂创建。

## 9. 在线课堂按页授课设计

## 9.1 页面模式

在线课堂包含两个明确模式：

1. **浏览模式：** 显示标题、场景目录、舞台、教师辅助信息和导出；
2. **演示模式：** 隐藏管理信息，保留舞台、翻页、当前页媒体控制和退出。

P0 不提供页面内容编辑器。

## 9.2 页面布局

```text
┌ 返回 AI课堂  /  课堂标题 ─ 保存状态 ─ 导出PPTX ─ 导出MP4 ─ 演示 ┐
├──────────────┬─────────────────────────────┬─────────────────┤
│ 场景目录      │                             │ 当前页信息       │
│ 01 标题页     │       自适应 16:9 舞台       │ 讲稿 / 媒体状态   │
│ 02 核心概念   │                             │ 可折叠           │
│ 03 互动练习   │                             │                 │
├──────────────┴─────────────────────────────┴─────────────────┤
│ 上一页   播放/暂停当前页   音量   字幕   3 / 10   全屏   下一页 │
└─────────────────────────────────────────────────────────────┘
```

## 9.3 按页执行模型

### 9.3.1 场景进入

当用户进入一个场景：

1. 取消上一场景仍在运行的动作；
2. 渲染当前场景；
3. 等待场景 ready；
4. 显示当前页可用动作状态；
5. 默认不自动跨页；
6. 是否自动播放当前页由明确的用户设置决定，默认关闭。

### 9.3.2 播放当前页

“播放当前页”只执行当前场景的动作：

- 配音；
- spotlight／laser 等焦点动作；
- 受控嵌入视频；
- 当前场景定义的同步动作。

当前页动作结束后：

- 状态变为“当前页讲解完成”；
- 不自动跳到下一页；
- 用户可以重播当前页或手动翻页。

### 9.3.3 翻页

- 上一页／下一页；
- 点击目录场景；
- 键盘左右方向键；
- 到达首尾时按钮禁用；
- 翻页立即取消当前页音频、焦点和受控视频；
- 当前页索引保存在 URL 或短期 UI 状态中，不写入课堂资源。

### 9.3.4 不提供的控制

- 全课程时间轴；
- 拖动到某一全局秒数；
- 跨场景倍速；
- 自动连续播放整套课堂；
- 在线课堂时间线编辑。

这些能力仅保留在无头视频渲染流程内部。

## 9.4 当前页控制状态

| 状态 | 主按钮 | 辅助信息 |
|---|---|---|
| 无动作 | 隐藏或禁用 | 当前页无配音或媒体 |
| 可播放 | 播放当前页 | 配音可用／含媒体 |
| 加载中 | 加载中 | 正在准备当前页媒体 |
| 播放中 | 暂停 | 当前页讲解中 |
| 已暂停 | 继续 | 已播放时间可选显示为页内时间 |
| 已完成 | 重播当前页 | 当前页讲解完成 |
| 降级 | 播放当前页 | 使用浏览器语音或跳过损坏媒体 |
| 失败 | 重试当前页 | 显示可理解错误 |

### 9.5 场景目录

- 显示序号、标题和缩略图；
- 显示当前页高亮；
- 可选显示“有配音／有互动／有视频”的小图标；
- 不显示 `scene_id`、`type=slide` 等内部字段；
- 无标题时显示“第 N 页”，不能显示技术 ID；
- 场景较多时目录独立滚动，并自动将当前项滚入视图。

### 9.6 舞台

- 使用容器测量实现自适应 16:9；
- 最大化利用可用空间，但始终完整显示；
- 不固定 960×540；
- 加载时使用与舞台相同尺寸的骨架；
- 场景错误只影响当前页，不让整个课堂白屏；
- 演示模式支持浏览器全屏；
- 退出全屏后恢复原场景和状态。

## 9.7 导出

### PPTX

- 直接导出可编辑 PPTX；
- 导出期间显示任务状态；
- 成功后提供下载；
- 失败提供错误和重试。

### MP4

- 创建 `render_video` 任务；
- 无头浏览器使用内部全局时间线；
- 在线课堂 UI 不复用视频进度条；
- 导出任务进入全局任务中心；
- 完成后在课堂卡片和课程资源中显示最近导出；
- 导出失败不影响课堂本体可继续打开。

## 9.8 错误与降级

| 故障 | 在线课堂行为 |
|---|---|
| 场景 DSL 无效 | 当前页显示错误卡，可跳过到其他页 |
| 配音文件缺失 | 标记“无服务端配音”，允许浏览器 TTS 或无声播放 |
| 浏览器 TTS 失败 | 使用确定性停留或直接完成当前页，不阻塞翻页 |
| 嵌入视频失败 | 显示海报／错误提示，当前页其他内容继续可用 |
| 导出服务失败 | 任务中心标记失败，课堂仍可使用 |
| 网络短暂断开 | 当前已加载页继续显示，恢复后可重试读取状态 |

## 9.9 验收标准

- 1366×768、1440×900、1920×1080 下舞台与翻页控制完整；
- 能通过目录、按钮和键盘跳到任意页；
- 播放当前页不会自动进入下一页；
- 翻页时上一页音频和焦点动作停止；
- 无动作页不显示误导性的播放进度；
- 页面中不出现内部场景 ID 和类型；
- MP4 导出仍能生成跨页完整视频；
- 刷新播放器后可重新加载同一课堂；
- 单页媒体失败不会导致整套课堂不可用。

## 10. 统一任务中心系统设计

## 10.1 目标

将所有耗时操作统一建模为后端持久化任务，解决：

- 页面刷新后任务消失；
- 页面切换后轮询终止；
- 多个组件重复实现轮询；
- 任务完成后资源列表不一致；
- 用户无法集中查看失败任务；
- 前端需要了解 sidecar 或不同服务的任务协议。

## 10.2 任务类型

P0 必须支持：

```text
generate_classroom
render_video
generate_report
generate_quiz
generate_game
generate_blog
generate_lesson_plan（仅耗时异步路径）
generate_ppt
generate_flashcard
build_knowledge_graph（若当前为后台任务）
rag_import（P0 建模，P1 完整接入）
```

P0 允许部分类型先通过适配器接入，但统一枚举和前端展示必须一次确定。

## 10.3 任务状态

```text
queued
running
succeeded
partially_succeeded
failed
cancel_requested
canceled
```

### 允许状态转换

```text
queued  -> running | canceled | failed
running -> succeeded | partially_succeeded | failed | cancel_requested
cancel_requested -> canceled | succeeded | partially_succeeded | failed
failed -> 终态；重试创建新任务
succeeded -> 终态
partially_succeeded -> 终态
canceled -> 终态
```

不得将失败任务重新原地改成 queued；重试必须创建新任务并记录 `retry_of_job_id`。

## 10.4 `EduJob` 目标数据模型

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `schema_version` | integer | 是 | 任务记录结构版本 |
| `edu_job_id` | string | 是 | 稳定任务 ID |
| `kind` | enum | 是 | 统一任务类型 |
| `status` | enum | 是 | 统一状态 |
| `step` | string | 是 | 当前机器可读阶段 |
| `progress` | integer | 是 | 0～100 |
| `message` | string | 是 | 用户可读状态 |
| `owner_user_id` | string | 是 | 任务所有者 |
| `course_id` | string/null | 否 | 所属课程 |
| `scope_type` | string | 是 | `course` 或 `knowledge_point` |
| `scope_id` | string/null | 否 | 知识点 ID |
| `input_summary` | object | 是 | 可安全展示的输入摘要，不保存密钥 |
| `result_ref` | object/null | 否 | 结果资源引用 |
| `error_code` | string/null | 否 | 稳定错误码 |
| `error_message` | string/null | 否 | 用户可读错误 |
| `retryable` | boolean | 是 | 是否允许重试 |
| `cancelable` | boolean | 是 | 当前是否允许取消 |
| `retry_of_job_id` | string/null | 否 | 重试来源 |
| `parent_job_id` | string/null | 否 | 复合任务父任务 |
| `provider_job_ref` | object/null | 否 | sidecar 等内部引用，不直接回前端敏感字段 |
| `created_at` | ISO datetime | 是 | 创建时间 |
| `started_at` | ISO datetime/null | 否 | 开始时间 |
| `finished_at` | ISO datetime/null | 否 | 结束时间 |
| `updated_at` | ISO datetime | 是 | 最近心跳／更新 |

### 10.4.1 `result_ref`

课程资源结果统一为：

```json
{
  "resource_type": "course_material",
  "course_id": "course-id",
  "material_type": "classroom",
  "material_id": "classroom-id"
}
```

非课程资源可使用其他明确的 `resource_type`，但不得只返回无法解析的任意字典。

### 10.4.2 `input_summary`

只保存恢复和展示所需信息：

- 主题；
- 资源类型；
- 选择资料数量；
- 参数摘要；
- 发起页面。

不得保存 API Key、完整认证头或不必要的完整文档内容。

## 10.5 后端接口

### 10.5.1 查询任务列表

`GET /api/jobs`

查询参数：

- `status`：可重复；
- `kind`：可重复；
- `course_id`；
- `active_only=true|false`；
- `updated_after`；
- `limit`，默认 50，最大 200；
- `cursor`。

规则：

- 只返回当前认证用户的任务；
- 普通教师不能通过参数查询其他用户；
- 默认按 `updated_at desc`；
- `active_only=true` 返回 queued、running、cancel_requested；
- 返回分页和服务器时间。

### 10.5.2 查询单个任务

`GET /api/jobs/{edu_job_id}`

- 保留现有接口；
- 使用 `owner_user_id` 统一字段；
- 非所有者返回 403；
- 404 和 403 不泄露任务是否属于他人。

### 10.5.3 取消任务

`POST /api/jobs/{edu_job_id}/cancel`

- 仅 `cancelable=true` 时有效；
- 返回最新任务；
- 无法立即停止的下游任务先进入 `cancel_requested`；
- 后处理和资源写入必须检查取消状态。

### 10.5.4 重试任务

`POST /api/jobs/{edu_job_id}/retry`

- 只允许 failed、partially_succeeded 或 canceled；
- 使用原任务安全输入创建新任务；
- 新任务记录 `retry_of_job_id`；
- 返回 `202 + 新任务`；
- 不覆盖旧任务历史。

### 10.5.5 创建任务

现有各生成接口继续保留业务语义，但统一返回：

```json
{
  "job": {
    "edu_job_id": "...",
    "kind": "...",
    "status": "queued",
    "progress": 0
  }
}
```

HTTP 状态使用 202。

## 10.6 持久化要求

P0 可以继续使用文件存储，但必须：

- 写入临时文件；
- 完成 JSON 序列化和 flush；
- 原子替换目标文件；
- 同一任务更新使用进程内锁；
- 读取损坏文件时记录诊断并跳过，不能导致整个列表 500；
- 列表按 owner 和更新时间过滤；
- 为未来数据库迁移保留 `JobRepository` 接口；
- 不让业务服务直接拼接任务文件路径。

建议边界：

```text
JobRepository
├─ create(job)
├─ get(job_id)
├─ list(query)
├─ update(job_id, expected_version, patch)
└─ mark_terminal(job_id, result/error)
```

`expected_version` 或等价机制用于避免并发更新覆盖。

## 10.7 前端全局任务管理器

### 10.7.1 组件边界

建议模块：

```text
JobApi
  只负责 HTTP 和数据验证

JobStore
  保存任务实体、索引、未读完成数

JobPollScheduler
  决定何时轮询、批量查询和退避

GlobalJobProvider
  登录后启动，登出时停止

TaskCenter
  任务列表和操作 UI

useJob / useCourseJobs
  业务页面订阅接口
```

业务组件不得调用 `setInterval` 轮询任务。

### 10.7.2 启动恢复

用户登录且认证成功后：

1. 请求 `GET /api/jobs?active_only=true`；
2. 将任务写入 JobStore；
3. 启动唯一 PollScheduler；
4. 同时请求最近 20 条终态任务，用于展示刚完成和失败；
5. 根据任务 `course_id` 和 `result_ref` 更新页面徽标；
6. 页面组件通过 selector 订阅。

### 10.7.3 轮询策略

| 场景 | 间隔 |
|---|---:|
| 有 running 任务，页面可见 | 2 秒 |
| 只有 queued 任务 | 3 秒 |
| 页面隐藏 | 8 秒 |
| 连续网络失败 | 2、4、8、15、30 秒退避 |
| 无活跃任务 | 停止轮询；创建任务或窗口重新聚焦时检查 |

优先使用列表接口一次更新所有任务，不为每个任务创建单独 interval。

### 10.7.4 多标签页

P0 推荐：

- 使用 `BroadcastChannel` 广播任务快照和“新任务已创建”事件；
- 选举一个可见标签页作为主动轮询者，其他标签页消费广播；
- 若不实现选举，至少保证每个标签页只有一个批量轮询器，并设置服务端限流；
- `localStorage` 只记录最近看过的任务 ID 和未读状态，不记录权威进度。

### 10.7.5 任务完成

检测到任务从非终态进入终态：

1. 更新 JobStore；
2. 显示一次全局通知；
3. 若 `result_ref.resource_type=course_material`，刷新对应课程资源缓存；
4. 当前页面若正在等待该任务，自动显示结果入口；
5. 将完成任务标记为未读；
6. 不自动强制跳转页面。

### 10.7.6 任务失败

- 保留失败任务；
- 展示类型、主题、失败阶段、错误摘要；
- 可重试时提供重试；
- 配置类错误提供“前往配置”的预留动作，P1 接入；
- 不弹出重复错误通知；
- 错误详情可复制诊断 ID，不暴露堆栈和密钥。

## 10.8 任务中心 UI

### 10.8.1 入口

- 放在 App Shell 顶部右侧；
- 显示任务图标；
- 徽标显示运行中任务数；
- 有失败未读时显示红点；
- 在任何课程页面均可打开；
- 不占用左侧导航。

### 10.8.2 面板

```text
生成任务
├─ 进行中
│  ├─ AI课堂 · 计算思维 · 生成场景 62%
│  └─ 报告 · 课程总结 · 排队中
├─ 需要处理
│  └─ 视频导出失败 · 可重试
└─ 最近完成
   └─ 习题已生成 · 打开资源
```

每个任务显示：

- 类型图标；
- 安全的输入标题；
- 所属课程；
- 状态与阶段；
- 进度；
- 更新时间；
- 取消／重试／打开结果。

### 10.8.3 页面内任务卡

业务页面可显示与当前页面相关的任务卡，但数据来自全局 JobStore。

例如 AI 课堂页：

- `useCourseJobs(courseId, generate_classroom)`；
- 显示所有正在生成的课堂；
- 刷新不丢失；
- 不再使用组件私有 `job` 作为唯一状态。

## 10.9 幂等与重复提交

- 每次创建任务允许客户端传 `idempotency_key`；
- 同一用户、同一业务接口、同一 key 在有效期内返回同一任务；
- 生成按钮提交后立即禁用，直到收到任务 ID；
- 网络超时重试创建请求时复用相同 key；
- 任务重试使用新的 key 和新的任务 ID；
- 后端不得因前端重复点击生成两个不可区分任务。

## 10.10 任务中心验收标准

- 刷新页面后 5 秒内恢复所有当前用户活跃任务；
- 退出 AI 课堂页后任务继续运行；
- 重新登录后能看到仍在运行的任务；
- 同一页面只有一个批量轮询器；
- 三个并发任务可以分别更新进度；
- 任务成功只发送一次完成通知；
- 成功资源在 5 秒内出现在课程资源页；
- 403 用户不能查看、取消或重试他人任务；
- 服务端短暂不可用时前端退避，恢复后继续；
- 任务 JSON 并发更新不会产生损坏文件；
- 重试产生新任务并保留旧失败记录。

## 11. 统一状态组件

## 11.1 状态类型

前端提供统一组件或设计规范：

```text
InitialState
LoadingState
EmptyState
RunningState
PartialSuccessState
ErrorState
PermissionState
OfflineState
```

### 11.2 必要字段

每个状态必须回答：

1. 发生了什么；
2. 用户是否需要等待；
3. 用户可以做什么；
4. 数据是否已经保存；
5. 下一步在哪里。

### 11.3 禁止项

- 只有 `No data`；
- 只显示内部异常文本；
- 失败后清空用户输入；
- 成功但不说明保存位置；
- 使用绿色成功提示掩盖部分失败；
- 无权限和不存在共用含糊文案。

### 11.4 状态验收

- 所有 P0 页面均有加载、空、失败和重试；
- 后台任务离开页面后不显示为失败；
- 部分成功明确列出已完成与未完成项；
- 错误信息不出现堆栈、路径或密钥；
- 状态组件支持键盘和屏幕阅读器。

## 12. 路由与课程上下文

## 12.1 路由构造

所有跳转使用统一路由函数：

- 明确 route key；
- 明确必填参数；
- 自动 URL 编码；
- 缺失参数时返回不可导航结果，而不是 `#undefined`；
- 课堂播放器必须同时包含 `course_id` 和 `classroom_id`。

### 12.2 课程上下文

- App Shell 保存当前课程；
- URL 中涉及资源时仍传显式 `course_id`；
- 页面加载时校验 URL 课程和 App Shell 课程；
- 冲突时以 URL 显式资源所属课程为准，并更新 App Shell；
- 不使用 `defaultCourse` 为真实写入兜底；
- 课程不存在时显示 404 状态和返回课程列表。

### 12.3 验收标准

- 全项目不存在可生成 `#undefined` 的正式入口；
- 直接打开课堂 URL 可正确恢复课程；
- 刷新课程资源页不会切到默认课程；
- 缺少课堂 ID 时显示错误状态，不发无效请求；
- 路由测试覆盖参数缺失、中文 ID、特殊字符和返回导航。

## 13. 安全、权限与隐私

P0 至少要求：

- 任务列表、详情、取消、重试都必须认证；
- 后端按 `owner_user_id` 过滤任务，不接受前端传入任意 owner；
- `result_ref` 指向的课程资源必须再次执行资源权限校验；
- 任务 `input_summary` 不保存完整文档、密钥或认证信息；
- 内部 `sidecar_job_id` 可保存在后端，但不作为前端业务 ID；
- 错误返回不包含本机绝对路径和堆栈；
- 课程资源页不能仅凭猜测 ID 读取他人课程资源；
- 演示模式不显示诊断信息和用户敏感信息。

资源完整授权治理在 P1 完成，但 P0 不得新增更宽松的入口。

## 17. 迁移与发布策略

### 17.1 任务记录迁移

- 读取旧任务时填充 `schema_version=1`；
- 旧 `owner` 映射到 `owner_user_id`；
- 旧 `result_ref` 通过适配器规范化；
- 旧任务不支持的字段使用安全默认值；
- 写入新任务全部使用新结构；
- 迁移完成前保留兼容读取，不做批量破坏性删除。

### 17.2 前端轮询迁移

建议顺序：

1. 先让课堂生成和视频导出改用 GlobalJobManager；
2. 移除对应组件私有 interval，但保留显示组件；
3. 接入报告、习题、小游戏直接生成；
4. 接入博客、PPT、闪卡和其他现有任务；
5. 删除课堂 `localStorage` 权威恢复逻辑，只保留显示缓存；
6. 加入任务中心入口；
7. 最后启用刷新恢复验收。

迁移过程中不得同时由私有轮询和全局轮询触发资源保存或完成通知。

### 17.3 功能开关

建议使用：

- `VITE_ENABLE_GLOBAL_JOB_CENTER`；
- 后端任务 schema 兼容开关；
- 课堂新播放器路由开关。

灰度期间允许回退 UI，但任务数据必须保持向前兼容。

### 17.4 发布出口

P0 只有在以下条件全部满足时才能进入 P1：

1. 工作台常见宽度不裁切；
2. 在线课堂按页授课稳定；
3. 课程资源入口和 AI 课堂同源；
4. 所有 P0 长任务刷新后可恢复；
5. 课程和任务权限没有明显越权；
6. 路由与状态回归通过。

## 19. 最终设计结论

P0 不通过增加更多功能解决问题，而是建立三条可靠主线：

1. **教师看得见：** 导航清楚、布局不裁切、课堂按页可授课；
2. **任务找得回：** 所有后台任务由后端账本和前端全局任务中心统一管理；
3. **结果放得对：** AI 课堂与其他生成结果统一进入课程资源，同时保留专用课堂入口。

这三条主线完成后，P1 才有稳定基础继续建设 RAG、生成效果、资源可靠性和 API 配置中心。
