# 课程中心架构与教师端全链路优化 SPEC

**状态：** 待评审
**日期：** 2026-08-06
**适用范围：** 当前教师端、课程数据模型、课程知识库、课程知识图谱、问答工作台、生成工厂、课程资源、AI 课堂；学生端仅预留权限与数据边界，本期不实现学生界面。

- `docs/教师端基础可用性审计与整改优先级_2026-08-06.md`
- `docs/superpowers/specs/2026-08-06-teacher-p0-usability-and-job-center-design.md`

> 本文是课程组织方式、知识模块边界、页面信息架构和资源生成体验的上位设计。既有任务中心、持久化任务和可信生成 SPEC 继续作为实现细节；若既有文档中的“资源仅按创建者可见”“所有资源必须先选文档”等约定与本文冲突，以本文为准。

---

## 1. 文档目的

当前系统已经具备课程、问答、RAG、知识图谱、报告、教案、博客、习题、PPT、闪卡、小游戏、思维导图和 AI 课堂等能力，但这些能力尚未被组织为一个一致的“课程工作空间”。主要表现为：

1. 课程信息是全局共享的，但课程资源、AI 课堂和任务又按创建者账号隔离；
2. 系统没有课程成员关系，无法表达两位教师共同维护一门课程，也无法限制学生只读；
3. 课程知识库与知识图谱重复管理资料，问答侧看到的资料数量与课程知识库页面不一致；
4. 页面跳转同时依赖 URL 和 `localStorage`，刷新、复制链接或切换课程时可能进入错误上下文；
5. 资源生成被“必须先勾选文档”阻断，同时已勾选的文档仍可能在正式任务中解析为空；
6. 不同资源使用不同配置流程，部分配置字段没有真正传入后端；
7. 页面视觉质量不一致，知识图谱、长配置弹窗和资源结果存在明显的裁切、超界和信息表达问题。

本 SPEC 的目标不是继续堆叠新功能，而是把现有功能收敛成：

> **以课程为组织边界、以课程成员为权限边界、以课程知识为内容来源、以课程资源为结果归宿的教师工作空间。**

## 2. 已确认的产品决策

### 2.1 课程是系统的一级组织单位

用户登录后先看到自己可访问的课程，再进入某一门课程完成知识管理、问答、生成和授课操作。问答、知识库、知识结构、生成任务、生成资源和 AI 课堂都必须归属于明确的 `course_id`。

### 2.2 正式模型采用课程成员制

引入课程成员关系，不再以“资源创建者就是唯一可见者”代替课程权限：

| 成员角色 | 课程读取 | 课程编辑 | 知识编辑 | 资源生成 | 资源管理 | 成员管理 |
|---|---:|---:|---:|---:|---:|---:|
| `owner` 负责人 | 是 | 是 | 是 | 是 | 是 | 是 |
| `editor` 协作教师 | 是 | 是 | 是 | 是 | 是 | 否 |
| `viewer` 只读成员/学生 | 是 | 否 | 否 | 本期否 | 否 | 否 |

系统管理员可以执行系统级管理，但不以管理员身份替代课程成员审计信息。

### 2.3 小范围开发阶段自动加入全部课程

当前阶段不要求教师逐门邀请，采用可关闭的开发策略：

- 已有教师自动成为所有课程的 `editor`；
- 已有学生自动成为所有课程的 `viewer`；
- 新建课程时，为当前所有教师和学生建立对应成员关系；
- 新用户注册时，自动加入当前所有课程；
- 学生界面本期不实现，但后端必须从现在开始执行只读权限；
- 自动加入行为必须由显式运行配置控制，例如 `DEV_AUTO_ENROLL_ALL_COURSES=true`，不得永久写死在业务接口中；
- 关闭该配置后，系统切换为负责人邀请成员，不改变既有课程和资源数据结构。

### 2.4 生成资源不再强制选择文档

所有正式资源统一提供三种资料范围：

1. `course_auto`：自动使用当前课程中已完成索引的相关资料，默认选项；
2. `selected_documents`：仅使用用户明确勾选的文档；
3. `none`：不使用知识库，仅根据主题、配置和用户要求生成。

只有当用户选择“总结指定文档”“严格依据教材”“根据选中文档出题”等明确材料型任务时，才强制要求至少一份已索引文档。

### 2.5 课程知识库与知识图谱合并为“课程知识”领域

前端可以保留两个视图，但两者不再分别拥有资料：

- **资料库：** 管理文件、网页、解析、索引、分类、预览和检索；
- **知识结构：** 管理章节、知识点、关系、课时和资料关联。

资料库是唯一资料事实来源。知识结构中的节点只能关联资料库文档，不再单独上传和复制文档。

### 2.6 “知识图谱”和“思维导图”是不同产物

- 课程知识图谱：课程级、长期维护、可编辑的知识结构；
- 思维导图：从某个主题或资料生成的一份课程资源快照。

生成工厂中的 `graph` 类型在用户界面统一称为“思维导图”，不得与课程知识图谱混用。

## 3. 当前状态与实测证据

### 3.1 课程与权限

- 课程列表、详情、创建、修改和删除接口当前未统一依赖登录用户；
- 课程信息使用全局文件保存，因此不同账号看到的是同一份课程信息；
- 课程资源接口按 `owner_user_id` 过滤，同一课程中的另一位教师看不到资源；
- 当前没有 `CourseMembership` 或等价数据模型；
- 前端登录后只保存“是否已认证”，没有根据角色切换页面权限；
- 使用学生账号实际打开课程设置页，可以看到课程编辑输入框和保存按钮。

结论：当前不是完整的共享课程，而是“课程信息共享、课程成果按用户分裂、权限缺失”的混合状态。

### 3.2 课程上下文与跳转

- `selectedCourse` 主要由 `localStorage` 的 `stitch-course` 提供；
- 带 `course_id` 的路由需要异步加载课程，加载完成前可能短暂展示上一次课程；
- `#course-detail` 不携带课程 ID，无法可靠复制链接或刷新；
- 知识图谱进入问答时会遗漏 `course_id`；
- AI 课堂中的“返回课程详情”实际返回问答页；
- AI 课堂和播放器没有统一课程侧栏，页面外壳与其他课程页面不一致。

### 3.3 课程知识

- 课程知识库页面实际展示 12 份资料；
- 问答工作台的课程知识库显示 0 份，个人知识库显示 23 份；
- 课程知识库中的部分资料处于 `received`、`chunk_count=0`，尚未形成可检索内容；
- 知识图谱页面重复提供教材上传；
- 知识图谱根节点重复展示课程知识库的全部资料，并提供语义重复的“导入到课程总知识库”。

### 3.4 资源生成端到端检查

| 资源类型 | 配置检查 | 正式链路实测结果 | 主要问题 |
|---|---|---|---|
| 报告 | 完成 | 失败 | 已选文档仍提示“内容为空”；打开入口即调用模型生成推荐，增加等待 |
| 教案 | 完成 | 超过 45 秒，后端随后不可响应 | 配置过长；推荐生成慢；自动预填质量不稳定；同步调用阻塞服务 |
| 教学博客 | 完成 | 长期停留 5% | 描述和篇幅未传入生成请求；取消长期停留在 `cancel_requested`；阻塞后续任务 |
| 习题 | 完成 | 失败 | 已选文档仍提示“内容为空”；弹窗底部在常见视口略超界 |
| PPT | 完成 | 大纲接口 500 | 提示“选中文档摘要为空”；弹窗过长；大纲使用原始 JSON 编辑；部分风格字段未绑定 |
| 闪卡 | 完成 | 失败 | 已选文档仍提示“内容为空”；结果页一次性展开全部正反面；标题可能被错误识别为链接 |
| 思维导图 | 完成 | 失败 | 已选文档仍提示“内容为空”；“描述”字段没有传给后端；按钮仍写“保存配置” |
| 小游戏 | 完成 | 失败 | 已选文档仍提示“内容为空”；配置仅有游戏类型，缺少数量、难度、时长和预览 |
| AI 课堂 | 完成 | 已有成功产物可播放 | 工厂入口与独立页面配置不一致；工厂入口忽略资料范围并强制启用语音 |

额外实测：一个博客任务卡在 5% 后，其余报告、习题、游戏、闪卡和思维导图任务全部停留在排队状态；请求取消后重启服务仍显示 `cancel_requested`。这证明当前需要任务隔离、超时和取消收敛，而不只是前端进度条。

### 3.5 页面与响应式

- 登录页整体清晰，但缺少账号帮助、角色说明和找回入口；
- 教师首页文案偏学生视角，课程卡缺少角色、更新时间和待办信息；
- 首页课程轮播和“我的课程”列表重复；
- 课程进度由课程 ID 计算，是装饰性数据，不代表真实教学状态；
- 课程详情主按钮存在白底白字，核心入口不可读；
- 课程详情缺少课程知识和知识结构的直接入口；
- 生成工厂覆盖在问答区上方，背景整体变灰，容易被理解为问答已禁用；
- 1024×768 下知识图谱中心画布被压缩到约 55px，基本不可操作；
- 教案、PPT和部分配置弹窗高于视口，底部操作需要长距离滚动；
- AI 课堂播放器的底部控制在 1280×720 首屏之外；
- 页面存在多层滚动、Ant Design 弃用属性和未连接表单警告。

## 4. 目标与非目标

### 4.1 目标

1. 两位教师进入同一课程时，看到并维护同一份课程信息、课程知识和课程资源；
2. 学生即使通过直接 URL 或 API 请求，也只能读取课程，不能修改；
3. 所有课程页面以 URL 中的 `course_id` 为权威上下文；
4. 课程资料在资料库、问答和生成工厂中使用同一文档 ID、状态和数量；
5. 用户不选择文档也能生成资源，选择文档时能可靠限定来源；
6. 任一慢任务、失败任务或取消任务不阻塞其他资源生成；
7. 每类资源的配置字段都真实参与生成，结果保存到同一课程资源中心；
8. 从登录开始逐页统一视觉层级、页面外壳、状态反馈和响应式行为；
9. 为后续学生端复用课程页面和只读数据打好基础；
10. 完成这些基础工作后，再进入 Agent 性能和记忆优化。

### 4.2 非目标

- 本期不实现完整学生端页面、作业提交、成绩和班级教学管理；
- 本期不建设学校/学院/租户的多级组织模型；
- 本期不要求课程内容实时多人协同编辑，先保证刷新后同步和冲突保护；
- 本期不重写所有生成 Agent，只统一输入、任务、结果和错误契约；
- 本期不新增独立资源类型；
- 本期不建立复杂的课程审批或邀请工作流。

## 5. 目标领域模型

### 5.1 Course

课程是所有业务对象的聚合根，至少包含：

```text
Course
- id
- title
- description
- icon
- color
- objectives
- revision
- created_by
- created_at
- updated_at
```

`revision` 用于多人编辑冲突检测。更新课程时必须提交当前版本；版本不一致返回稳定的冲突错误，不允许静默覆盖。

### 5.2 CourseMembership

```text
CourseMembership
- course_id
- user_id
- role: owner | editor | viewer
- joined_at
- added_by
```

`(course_id, user_id)` 唯一。课程列表只返回当前用户拥有成员关系的课程。开发期自动加入也必须实际创建成员记录，不得绕过授权服务。

### 5.3 KnowledgeDocument

```text
KnowledgeDocument
- id
- course_id
- library_type: course | personal
- owner_user_id: personal 时必填
- scope_type: course | knowledge_point
- scope_id
- filename
- source_type
- status
- active_index_version
- chunk_count
- page_count
- error_code
- error_message
- created_by
- created_at
- updated_at
```

课程资料对课程成员共享；个人资料仅创建者可见。文档 ID 是跨资料库页面、问答、生成工厂、任务处理器和引用结果的稳定公共 ID，不再让前端传物理路径。

### 5.4 KnowledgeNode 与文档关联

```text
KnowledgeNode
- id
- course_id
- parent_id
- title
- description
- hours
- sort_order
- revision

KnowledgeNodeDocument
- course_id
- node_id
- document_id
- relation_type
```

节点只关联文档，不复制文档。删除文档时必须处理关联关系并提示影响。

### 5.5 CourseMaterial

```text
CourseMaterial
- id
- course_id
- material_type
- title
- created_by
- visibility: course | private
- source_mode
- source_snapshot
- artifact_manifest
- status
- created_at
- updated_at
```

默认生成结果为 `course` 可见，同一课程的教师均可查看和管理；`created_by` 用于审计，不再用于默认可见性过滤。未来如需要个人草稿，可显式使用 `private`。

### 5.6 GenerationCommand 与 EduJob

所有资源生成共享稳定输入：

```text
GenerationCommand
- course_id
- resource_type
- created_by
- source_mode: course_auto | selected_documents | none
- selected_document_ids
- scope_type
- scope_id
- config
- idempotency_key
```

任务记录必须包含课程、创建者、资源类型、来源快照、配置快照、阶段、超时、重试和最终资源引用。

## 6. 授权与开发期自动加入

### 6.1 统一授权入口

课程 CRUD、知识库、知识结构、问答、生成任务、课程资源、AI 课堂和导出必须调用同一课程授权服务。前端隐藏按钮只是体验优化，不能代替后端校验。

### 6.2 最低权限行为

- 未登录：课程相关接口返回 401；
- 已登录但不是课程成员：返回 403；
- `viewer`：允许课程和公开课程内容 GET，修改请求返回 403；
- `editor`：允许课程内容编辑和资源生成，不允许成员管理；
- `owner`：允许课程与成员管理；
- 删除课程属于高风险操作，仅 `owner` 或系统管理员可执行，并要求二次确认。

### 6.3 开发模式自动加入验收

开启自动加入配置时：

1. 现有教师和学生都拥有所有课程的成员记录；
2. 新建课程后，当前教师自动为 `editor`、学生自动为 `viewer`；
3. 新注册教师/学生自动加入所有已有课程；
4. 学生仍不能通过接口修改课程；
5. 关闭配置后，不再自动增加成员，但已有成员关系不丢失。

## 7. 课程上下文与导航架构

### 7.1 URL 是唯一课程权威来源

所有课程内页面必须携带 `course_id`：

```text
#course-detail?course_id=...
#ai?course_id=...
#knowledge?course_id=...
#graph?course_id=...
#classroom-studio?course_id=...
#resources?course_id=...
#edit?course_id=...
```

`localStorage` 只能记录“最近访问课程”，用于登录后的便捷跳转，不能覆盖 URL。路由课程加载完成前显示骨架，不得先渲染旧课程。

### 7.2 建议的课程内导航

```text
课程概览
问答与生成
课程知识
  ├─ 资料库
  └─ 知识结构
AI 课堂
课程资源
课程设置
```

“生成工厂”作为问答工作台内的工具面板，不再单独成为一级页面。“资料库”和“知识结构”可以使用二级标签或同一页面内的明确切换。

### 7.3 跳转规则

- 课程列表进入课程概览，URL 必须包含课程 ID；
- 课程概览提供问答、课程知识、AI 课堂和课程资源四个核心入口；
- 知识节点进入问答时同时携带 `course_id`、`scope_type` 和 `scope_id`；
- AI 课堂“返回课程详情”必须回到课程概览；
- AI 课堂播放器返回 AI 课堂列表，并保留课程 ID；
- 课程资源打开产物后，返回列表时保留筛选条件和滚动位置；
- 找不到课程或无权限时显示独立错误状态，不回退到最近访问课程。

## 8. 课程知识：资料库与知识结构

### 8.1 资料库职责

- 上传本地文档、导入网页或添加已有个人资料；
- 展示解析、分块、索引和检索状态；
- 预览内容和元数据；
- 分类、移动、删除、重试索引和测试检索；
- 管理课程资料与个人资料边界；
- 为问答、生成和知识节点关联提供同一文档选择器。

资料列表不得把“文件已经落盘”表达为“已接入知识库”。只有处于可检索状态的资料才能进入 `course_auto` 或 `selected_documents` 生成。

### 8.2 知识结构职责

- 展示与编辑章节、知识点和父子关系；
- 编辑节点说明、课时和排序；
- 将资料库中的文档关联到节点；
- 从资料库教材辅助生成初始结构；
- 从节点进入限定作用域的问答或生成。

知识结构页面不再提供独立教材存储。根节点可以显示“已关联资料数量”，但不能再次展开全部资料列表制造重复入口。

### 8.3 一致性要求

- 资料库、问答来源面板和生成工厂显示的课程文档数量一致；
- 文档状态和名称一致；
- 同一文档在所有页面使用同一 `document_id`；
- 删除、重命名、重新索引后，各页面刷新能看到一致结果；
- 节点关联不复制文件，不产生第二份索引；
- 知识结构生成失败不影响资料库中的原始资料。

---

## 9. 统一的资料范围与 RAG 行为

### 9.1 `course_auto`

- 不要求用户手动选文档；
- 仅从当前课程中状态为可检索的课程资料召回；
- 结合资源主题、目标、重点和当前知识节点构造检索查询；
- 保存实际命中的文档、分块、版本和引用快照；
- 如果课程没有可检索资料，界面明确提示，并允许切换到 `none`，不得永久阻断。

### 9.2 `selected_documents`

- 必须至少选择一份可检索且有权限的文档；
- 检索严格限定在选中文档；
- 长文档生成不能只取单次 top-k 片段，应使用分层摘要、章节覆盖或分批读取，避免遗漏主要内容；
- 任一文档 ID 无法解析时，任务提交前返回具体文档名称和原因；
- 不允许把“选中文档内容为空”作为后台任务中的模糊终态。

### 9.3 `none`

- 不调用课程 RAG；
- 根据主题、配置和用户补充要求生成；
- 结果明确标记“未使用课程资料”；
- 不伪造课程资料引用。

### 9.4 默认交互

- 默认选择“自动使用课程资料”；
- 用户在左侧勾选文档后，界面自动建议切换为“仅使用选中文档”，但允许改回；
- 页面使用“资料范围”而不是仅面向技术用户的“开启 RAG”；
- 提交前展示课程、知识点、资料模式和选中文档数量；
- 结果页展示本次实际使用的资料，而不是只展示配置时的候选资料。

## 10. 生成工厂统一流程

### 10.1 五步闭环

```text
选择资源类型
→ 确认资料范围
→ 配置内容
→ 预览/确认（需要时）
→ 后台生成并进入课程资源
```

报告、教案、PPT等需要结构确认的资源可以包含“预览大纲”；闪卡、习题和小游戏可以直接提交，但仍使用同一任务和结果模型。

### 10.2 配置页通用要求

每个配置页必须显示：

- 当前课程和知识点；
- 资料范围及可用资料状态；
- 必填项、默认值和字段说明；
- 预计产物类型，而不是不可靠的精确完成时间；
- “开始生成”或“生成大纲”，不得使用“保存配置”代替生成动作；
- 可取消、可关闭且不会丢失已填内容；
- 高于视口时内容区滚动、标题和底部操作固定；
- 1024×768 下操作按钮仍可直接到达，不出现页面外裁切。

### 10.3 推荐配置延迟加载

固定模板立即展示；AI 推荐异步加载并允许跳过。打开配置页不得强制等待一次模型调用后才能继续填写。推荐失败时保留固定模板和手动配置。

### 10.4 任务可靠性

- 所有正式生成都通过后台任务执行；
- 任一外部模型调用必须有连接、读取和总时长上限；
- 一个任务超时不得阻塞其他课程或资源任务；
- 取消请求应在规定时间内进入 `canceled`，或明确显示“远端请求无法立即停止但结果将被丢弃”；
- 服务重启后，`queued`、`running`、`cancel_requested` 按稳定规则恢复；
- 只有资源已经原子保存并可读取后，任务才能标记完成；
- 错误必须区分资料不可用、模型超时、配置错误、权限错误、保存失败和外部服务不可用。

## 11. 各资源类型专项设计

### 11.1 报告

保留简要报告、详细报告、学习计划和自定义方向。固定模板立即可用，推荐方向延迟加载。配置至少包含主题、目标读者、结构深度和补充要求；最终显示资料范围和引用。

**验收重点：** 三种资料模式均能提交；选中文档时严格限定来源；推荐接口失败不阻断手动生成。

### 11.2 教案

将长表单整理为“基本信息、教学目标、教学过程、补充要求”四个分组或两步式配置。自动预填必须可编辑，并标明来自资料推断，不能把抽取错误直接当最终课题。

**验收重点：** 1024×768 下底部操作始终可达；45 秒等长调用不阻塞服务；大纲确认后生成正式教案并进入课程资源。

### 11.3 教学博客

配置至少包含主题、目标读者、语气、篇幅、文章结构和补充要求。当前已有的描述和篇幅必须真实进入命令配置和最终提示词。

**验收重点：** 修改篇幅和语气能够在任务配置快照及最终产物中观察到；取消能收敛；博客任务不能阻塞其他类型任务。

### 11.4 习题

保留主题、难度、题量、题型、答案和解析设置，并补充适用对象。资料范围为 `none` 时也能根据主题生成。

**验收重点：** 题目数量和题型严格符合配置；答案与解析开关生效；来源模式正确记录。

### 11.5 PPT

配置保留标题、副标题、受众、目标、页数、重点和风格。模板必须提供可辨识的视觉预览。大纲使用结构化编辑器，不直接暴露原始 JSON。`style_hint`、`special_requirements` 等字段要么全部接入，要么从界面删除。

**验收重点：** 大纲生成失败返回可理解错误；用户可以逐页增删改并再次生成；配置弹窗无超界；产物在课程资源中可预览和下载。

### 11.6 闪卡

保留标题、数量、难度、分类和来源显示设置。结果默认使用一张一张翻转或列表折叠，不一次展开全部正反面。

**验收重点：** 标题不被误解析成外部链接；数量范围准确；正反面交互可用；教师 B 可以看到教师 A 生成的课程闪卡。

### 11.7 思维导图

配置包含主题、补充说明、层级和资料范围。补充说明必须传入后端。生成结果是课程资源，不修改课程知识结构，除非用户后续主动执行“应用到知识结构”。

**验收重点：** “开始生成”语义正确；描述和层级生效；页面始终称为“思维导图”。

### 11.8 小游戏

保留分类、拖拽匹配和记忆翻牌，增加题目/卡片数量、难度、课堂时长和内容预览。游戏类型卡必须是可键盘操作的按钮。

**验收重点：** 配置真实影响产物；生成后可直接预览；键盘能够选择游戏类型；失败时保留配置重试。

### 11.9 AI 课堂

生成工厂入口和独立 AI 课堂页面使用同一配置组件、同一资料范围和同一任务接口。语音是否启用必须显式展示，不能在某一入口硬编码。

**验收重点：** 两个入口生成结果一致；课程资料能参与课堂生成；已有课堂可播放、翻页、导出并在课程资源中打开。

## 12. 页面级体验优化

### 12.1 登录页

**保留：** 当前左右分栏和整体视觉风格。
**优化：** 增加系统名称、账号帮助、角色说明、登录失败原因；开发模式可提供演示账号提示，但不得在正式环境暴露默认密码。

### 12.2 课程首页

合并重复的首页课程轮播和“我的课程”列表，形成唯一课程入口。课程卡展示课程名称、用户角色、最近更新时间、待处理任务和资源数量。删除虚假的随机进度；没有真实指标时宁可不显示。

教师端文案统一使用“课程建设、备课、资料与教学资源”，不使用“开启智能学习之旅”等学生视角表达。

### 12.3 课程概览

课程概览承担进入课程后的总览，不重复大段课程名称和描述。核心区域展示：

- 课程简介和教学目标摘要；
- 资料索引状态；
- 最近生成资源；
- 进行中的任务；
- 问答、课程知识、AI 课堂和课程资源快捷入口。

主按钮在明暗主题下必须达到可读对比度。

### 12.4 问答与生成

问答是主工作区，知识来源和生成工厂是可切换侧面板。打开生成工厂时，不用遮罩把问答区表现为禁用；中等宽度下使用抽屉或标签切换，不能把三栏同时硬塞进页面。

来源面板统一展示课程资料和个人资料，但默认课程资料优先，状态不可用的文档不可勾选并说明原因。

### 12.5 课程知识

资料库默认使用紧凑列表，上传区保持可发现，不放在长列表底部。文档可以预览、查看索引状态和错误详情。知识结构在中等宽度下切换为“设置/画布/节点详情”标签或可折叠面板，画布必须拥有可操作的最小宽度。

### 12.6 AI 课堂与播放器

AI 课堂列表使用统一课程外壳。返回入口语义正确。播放器在 1280×720 首屏内显示完整舞台和核心控制；场景目录、讲稿和辅助信息可以折叠。内部 ID 和技术类型不直接展示给教师。

### 12.7 课程资源

保持“筛选、列表、预览”思路，但中等宽度改为列表在上、预览在下或抽屉预览。每类资源使用匹配的预览方式；闪卡可翻转、小游戏可试玩、习题可折叠答案、PPT可逐页预览。

### 12.8 课程设置

仅 `owner` 和 `editor` 显示可编辑表单；`viewer` 显示只读课程信息。保存时显示版本冲突、保存成功和失败原因。系统服务配置不与课程设置混在同一信息层级。

### 12.9 个人中心

显示真实用户名、角色和课程数量。系统配置入口按权限展示。昵称与登录用户名可以不同，但需要清晰标注，避免“页面显示 Tang、任务所有者是 teacher”的混淆。

## 13. 视觉与响应式规范

### 13.1 页面外壳

- 所有课程页面使用同一侧栏、顶部课程上下文和任务入口；
- 标题、说明、主操作和次操作保持固定层级；
- 每页只保留一个最主要的高强调操作；
- 不使用随机或无业务含义的数据装饰页面；
- 加载、空状态、失败、无权限和离线状态使用统一组件。

### 13.2 视口基线

必须验证：1024×768、1280×720、1366×768、1440×900、1920×1080。

验收要求：

- 页面级无横向滚动；
- 主操作不被裁切；
- 弹窗标题和底部操作固定可达；
- 知识结构画布在桌面模式下不小于可用区域的 50%，中等宽度无法满足时切换标签布局；
- AI 课堂核心播放控制在 1280×720 首屏可见；
- 长标题使用省略、换行或悬浮说明，不撑破卡片；
- 资源预览中的 Markdown、表格、代码、链接和图片不突破容器；
- 页面不出现三层以上嵌套滚动。

### 13.3 可访问性

- 所有可点击卡片使用按钮或链接语义；
- 键盘可以完成课程进入、资料选择、资源类型选择和弹窗提交；
- 焦点状态清晰；
- 文字与背景对比度满足 WCAG AA；
- 图标按钮具有可读名称；
- 错误不只依赖颜色表达。

## 14. 分阶段优化路线、优先级与验收标准

## 阶段 0：冻结基线与快速止血

**优先级：P0**
**目标：** 在结构调整前修复最明显的阻断，并建立后续回归基线，避免继续在不稳定页面上扩展功能。

### 范围

- 修复课程详情主按钮不可读；
- 修复 AI 课堂返回地址和知识结构进入问答时遗漏课程 ID；
- 所有课程详情链接补齐 `course_id`；
- 移除虚假课程进度或明确改成真实指标；
- 为登录、课程、问答、知识、资源、AI 课堂和设置保存当前截图基线；
- 建立九类资源的固定小样本和测试账号；
- 暂停新增资源类型和新的独立页面。

### 验收标准

- [x] 所有已知核心链接均不会进入错误页面或依赖旧课程状态；
- [ ] 课程详情主操作在明暗主题下清晰可见；
- [ ] 页面不再展示随机生成的课程进度；
- [x] 九类资源均有固定输入、期望配置和期望结果类型；
- [ ] 五个基准视口均保留可对比截图。

## 阶段 1：课程工作空间与权限基础

**优先级：P0**
**目标：** 让课程真正成为共享业务边界，使两位教师看到同一课程内容，学生只能读取。

### 范围

- 建立 CourseMembership 和统一课程授权服务；
- 为现有用户和课程补齐成员数据；
- 实现开发期自动加入全部课程配置；
- 课程 CRUD、知识、资源、任务和 AI 课堂接入统一授权；
- 课程资源从“owner 默认可见”改为“课程成员可见，created_by 仅用于审计”；
- 课程信息增加 revision 冲突控制；
- 前端保存用户身份和课程内角色，按权限渲染编辑操作；
- URL 成为课程上下文唯一权威来源。

### 验收标准

- [x] 教师 A 和教师 B 登录后都能看到全部开发期课程；
- [x] 教师 A 修改课程名称或目标后，教师 B 刷新可看到同一结果；
- [x] 教师 A 生成的课程资源，教师 B 可以查看和管理；
- [x] 学生能读取全部开发期课程，但课程修改、知识编辑、资源生成和删除接口均返回 403；
- [x] 未登录访问课程 CRUD 返回 401；
- [x] 新课程自动添加现有教师和学生，新用户自动加入已有课程；
- [x] 关闭自动加入配置后不再创建自动成员关系；
- [x] 两位教师基于同一 revision 编辑时，后提交的过期版本返回 409，不覆盖最新内容；
- [x] 复制任一课程内 URL 到新窗口并刷新，始终打开 URL 指定课程；
- [x] 无权限或不存在的课程不会回退到 `localStorage` 中的旧课程。

## 阶段 2：课程知识与资料来源闭环

**优先级：P0**
**目标：** 建立唯一的课程资料事实来源，修复“页面有资料、问答为 0、正式生成取不到内容”的核心故障。

### 范围

- 统一 KnowledgeDocument 公共 ID；
- 迁移或兼容当前物理路径和用户前缀 ID；
- 统一资料库、问答和生成工厂的文档列表与状态；
- 将现有 `received/chunk_count=0` 文档推进到明确终态或显示失败原因；
- 实现三种资料范围；
- 生成提交前验证文档权限、索引状态和内容可用性；
- 知识结构删除重复上传入口，改为关联资料库文档；
- 保存真实来源快照和引用。

### 验收标准

- [ ] 同一课程在资料库、问答和生成工厂显示相同的课程文档数量；
- [ ] 同一文档在所有页面使用同一 ID；
- [ ] 文档从上传到解析、索引、可检索的状态变化可见；
- [x] 不可检索文档不能被静默选入正式生成；
- [x] `course_auto` 能从当前课程召回相关资料；
- [x] `selected_documents` 只使用选中文档，并能生成可引用结果；
- [x] `none` 在课程没有资料时仍可完成资源生成；
- [x] 已选有效文档不再出现笼统的“内容为空”或“摘要为空”；
- [ ] 知识结构节点关联文档不会复制文件或新增重复索引；
- [ ] 删除文档前能够展示受影响的知识节点和资源来源记录。

## 阶段 3：生成任务可靠性

**优先级：P0**
**目标：** 保证任何一个慢任务或失败任务都不会拖垮整个生成工厂或后端服务。

### 范围

- 所有资源生成迁移到持久化后台执行；
- 增加任务并发隔离、租约、心跳、超时和重启恢复；
- 为同步的教案、PPT大纲等长调用提供异步任务或明确的短请求边界；
- 取消状态收敛；
- 统一任务错误分类和前端恢复动作；
- 完成资源发布与任务完成状态的一致性检查。

### 验收标准

- [ ] 一个博客任务人工注入超时后，报告、习题和闪卡任务仍能开始执行；
- [ ] 所有外部模型请求都有明确总超时，超时后释放工作能力；
- [x] 取消普通任务后 10 秒内进入 `canceled`；无法中断的远端调用会停止发布结果并给出明确说明；
- [x] 服务重启后不存在永久 `running` 或 `cancel_requested` 任务；
- [ ] 教案和 PPT 大纲生成期间，健康检查和其他 API 正常响应；
- [x] 任务显示完成时，对应课程资源一定可以被打开；
- [ ] 失败任务保留课程、资料范围和配置，可修改后重试；
- [x] 教师 B 可以看到课程级任务产生的最终资源，但不能冒充教师 A 重试其个人私有任务。

## 阶段 4：课程知识与页面信息架构重构

**优先级：P1**
**目标：** 在数据和权限稳定后，统一教师端页面外壳、导航和课程知识体验。

### 范围

- 合并首页课程入口；
- 建设课程概览；
- 课程知识采用资料库/知识结构双视图；
- 统一课程侧栏和顶部上下文；
- 中等宽度下将三栏和知识结构改为抽屉、标签或折叠布局；
- 重做加载、空、失败、无权限和离线状态；
- 清理重复页面和不可达的旧配置代码。

### 验收标准

- [ ] 登录后只有一个明确的课程入口；
- [ ] 教师在不阅读说明的情况下能找到资料、知识结构、问答、AI课堂和资源；
- [ ] 课程知识中不存在两套教材上传和两份资料列表；
- [ ] 1024×768 下知识结构画布不再被压缩到不可操作宽度；
- [ ] 五个基准视口没有页面级横向滚动和被裁切的核心按钮；
- [ ] 所有课程页面使用一致的返回逻辑和课程上下文；
- [ ] 页面状态组件用语和恢复操作一致；
- [ ] 旧页面或旧配置入口有明确迁移或删除清单，不保留两套同时维护的主流程。

## 阶段 5：九类资源配置与结果体验

**优先级：P1**
**目标：** 逐类校正配置逻辑、配置页面和结果展示，使“填了什么、生成什么、保存在哪里”保持一致。

### 范围

- 统一五步生成流程和资料范围控件；
- 固定模板立即加载，AI 推荐异步可跳过；
- 重构教案、PPT等长配置页面；
- 修复博客篇幅/描述、思维导图描述、PPT风格、AI课堂语音和资料范围等失效字段；
- 为每类资源建设匹配的结果预览；
- 清理重复 quiz 分支、旧配置弹窗和不可达逻辑；
- 增加九类资源端到端回归矩阵。

### 验收标准

- [x] 九类资源均可在 `course_auto`、`selected_documents` 和 `none` 三种模式下得到明确成功或前置校验结果；
- [x] 对声明支持的模式，资源能够成功生成、保存、刷新恢复并被另一位课程教师查看；
- [ ] 每个可见配置字段都能在任务配置快照中找到，并实际影响提示词或生成器参数；
- [ ] 不生效的字段已接入或从界面移除；
- [ ] 教案、习题和 PPT 弹窗在 1024×768 下底部操作可见或通过固定底栏直接可达；
- [ ] PPT 大纲不再要求教师直接编辑 JSON；
- [ ] 闪卡可以逐张翻转，标题不会误变成 URL；
- [ ] 小游戏可通过键盘完成类型选择并预览；
- [ ] AI 课堂两个入口使用同一配置和任务链路；
- [ ] 资源名称、类型、创建者、来源模式和创建时间在资源中心清晰展示。

## 阶段 6：全页面视觉完善与质量门禁

**优先级：P1**
**目标：** 在核心结构稳定后完成系统性美化，而不是逐页打补丁。

### 范围

- 统一色彩、排版、间距、圆角、阴影、按钮和表单规范；
- 优化登录、课程首页、课程概览、问答、课程知识、AI 课堂、资源、设置和个人中心；
- 完成资源内容超界、Markdown、表格、代码和图片的容器约束；
- 完成明暗主题和五个基准视口视觉回归；
- 修复无障碍和组件弃用告警；
- 建立页面截图差异和关键尺寸断言。

### 验收标准

- [ ] 所有核心页面通过五个基准视口的人工和自动视觉检查；
- [ ] 页面级 `scrollWidth <= clientWidth`；
- [ ] 所有弹窗和抽屉的主操作都不会离开可达区域；
- [ ] 长标题、长路径、长引用、代码块、表格和图片不突破资源预览容器；
- [ ] 关键文字对比度达到 WCAG AA；
- [ ] 仅使用键盘可以完成主流程；
- [ ] 浏览器控制台没有已知的表单连接和弃用属性警告；
- [ ] 教师端文案保持角色一致，不混用学生视角表达。

## 阶段 7：学生端最小接入

**优先级：P2**
**前置条件：** 阶段 1–6 验收通过。
**目标：** 复用课程、知识、问答和资源基础，只增加学生需要的只读视角与学习工具，不复制教师端系统。

### 范围轮廓

- 学生课程列表和课程概览；
- 只读课程知识和教师发布资源；
- 学生问答；
- 学生工具：闪卡、练习和个人学习记录；
- 隐藏课程编辑、知识管理、教师资源生成和系统配置。

### 验收标准

- [ ] 学生与教师读取同一课程事实数据；
- [ ] 学生界面不存在教师编辑和管理入口；
- [ ] 直接调用写接口仍返回 403；
- [ ] 学生个人学习数据与课程公共资源明确分离；
- [ ] 不复制第二套课程、知识库或资源存储。

## 阶段 8：Agent 性能、记忆与工程治理

**优先级：P2**
**前置条件：** 教师端和课程数据闭环稳定。
**目标：** 提升回答速度、长任务效率和跨会话连续性，同时降低大组件和重复链路的维护成本。

### 范围轮廓

- 优化模型路由、超时、并行工具调用和缓存；
- 将可控记忆真正注入问答上下文，并提供可见和可删除机制；
- 增加 Agent 质量、延迟和成本指标；
- 拆分超大组件，删除旧路由和重复生成代码；
- 优化前端包体和首屏加载。

### 验收标准

- [ ] 普通问答和生成任务分别建立 P50/P95 延迟基线并达到约定目标；
- [ ] 记忆的写入、读取、使用和删除均可观察；
- [ ] 课程 A 的记忆和资料不会进入课程 B；
- [ ] 模型超时不会拖垮 API 服务；
- [ ] 主入口包体和关键页面加载时间有可量化下降；
- [ ] 旧路由、旧配置弹窗和重复生成分支完成清理。

## 15. 端到端验收矩阵

### 15.1 多用户课程协作

1. 教师 A 登录并进入课程；
2. 教师 B 登录并进入同一课程；
3. A 修改课程目标，B 刷新后看到更新；
4. A 上传并索引资料，B 能在资料库和问答来源中看到；
5. A 生成资源，B 能在课程资源中打开；
6. 学生读取相同课程，但所有写操作均被拒绝；
7. A、B 同时修改旧版本，后提交者收到冲突提示。

### 15.2 资料到资源

每类资源至少覆盖以下场景：

1. `course_auto`：不勾选文档，根据主题自动检索课程资料；
2. `selected_documents`：勾选一份已索引文档，严格限定来源；
3. `none`：关闭资料，根据主题直接生成；
4. 选中文档未索引：提交前阻止并提供重试索引；
5. 任务生成中刷新页面：任务可恢复；
6. 生成成功：资源可打开并显示来源模式；
7. 生成失败：配置保留并可修改后重试。

### 15.3 故障隔离

1. 人工让博客模型调用超时；
2. 同时提交报告、习题和闪卡；
3. 验证其他任务仍能执行；
4. 取消博客任务；
5. 重启后端；
6. 验证任务进入稳定终态，资源列表没有半成品；
7. 验证健康检查和普通问答始终可用。

### 15.4 页面与路由

1. 从登录进入课程首页；
2. 打开课程概览；
3. 依次进入问答、资料库、知识结构、AI课堂、资源和设置；
4. 在每一页刷新并复制链接到新窗口；
5. 验证课程上下文不变；
6. 在五个基准视口检查按钮、弹窗、画布和资源内容；
7. 使用键盘重复核心操作。

## 16. 发布与迁移原则

### 16.1 兼容读取，单向迁移

- 现有课程文件可以作为迁移输入，但新逻辑只通过统一课程仓储读取；
- 现有 owner 资源迁移为 `created_by=owner`、`visibility=course`，必要时允许管理员选择保留为私有；
- 现有课程知识库文档转换为统一 KnowledgeDocument，并重新确认索引状态；
- 现有知识图谱资料关联转换为文档关联，不复制文件；
- 旧 URL 在过渡期重定向到带 `course_id` 的新 URL。

### 16.2 功能开关

至少保留：

- 开发期自动加入全部课程；
- 新课程授权服务；
- 新课程知识页面；
- 三种资料范围；
- 新生成配置流程。

开关用于分阶段发布和回滚，不允许长期并行维护两套写入事实来源。

### 16.3 数据安全

- 迁移前备份课程信息、知识库索引、知识结构、任务账本和资源清单；
- 所有迁移支持 dry-run 和重复执行；
- 发现孤儿资源或失效文档时生成报告，不自动删除；
- 课程和成员变更保留审计记录。

## 17. 完成定义

本轮“课程中心架构与教师端优化”只有同时满足以下条件才算完成：

- 课程成员和权限真实生效；
- 开发期教师、学生默认进入全部课程，但学生保持只读；
- 两位教师共享同一课程信息、课程知识和课程资源；
- URL 能独立、稳定地表达课程上下文；
- 课程知识只有一份资料事实来源；
- 三种资料范围都具有明确、可靠的行为；
- 九类资源的可见配置全部生效，并通过端到端回归；
- 一个生成任务不能阻塞其他任务或整个后端；
- 登录到资源结果的全部核心页面通过响应式、视觉、状态和键盘验收；
- 学生端可以在不复制底层能力的前提下开始建设；
- Agent 性能和记忆优化拥有稳定、可信的课程上下文作为前提。

最终用户应当能够形成清晰心智：

```text
我进入一门课程
→ 管理这门课程的资料与知识结构
→ 在当前课程中问答或生成教学资源
→ 在任务中心查看进度
→ 在课程资源中继续使用结果
→ 其他课程教师看到相同内容
→ 学生只读取教师发布的课程内容
```
