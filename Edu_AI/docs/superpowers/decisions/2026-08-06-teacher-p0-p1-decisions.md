## D-001：使用独立全局 worktree

- **背景：** 主工作区位于 `main`，且有本轮新建但尚未提交的三份 SPEC。
- **选择：** 在 `C:\Users\Tang\.config\superpowers\worktrees\edu_ai\teacher-p0-p1` 创建 `codex/teacher-p0-p1` 分支；SPEC 复制到功能分支，主工作区原件保持不动。
- **理由：** 避免直接在 `main` 开发，也不覆盖主工作区可能存在的本地状态。
- **影响：** 所有阶段提交推送到远端同名分支。
- **回滚：** 删除 worktree 和功能分支即可；主工作区不受影响。

## D-002：执行顺序按“先美观可用，再可靠可信”

- **背景：** P0/P1 横跨前端体验、任务架构、RAG、资源治理、配置和账户。
- **选择：** 顺序为：信息架构与工作台 → 在线课堂 → 统一任务中心 → 状态与路由 → RAG → 资源与生成 → 配置中心 → 真实用户中心 → 总体验收。
- **理由：** 符合用户明确的优先级，同时让后续架构改造建立在已确定的正式入口和页面职责上。
- **影响：** 任务中心完成前，早期 UI 提交仍暂时复用已有轮询；最终必须迁移并删除组件私有轮询。
- **回滚：** 各批次均为独立提交，可按阶段回退。

## D-003：AI 课堂的双重入口保持同源

- **背景：** AI 课堂在数据层属于课程资源，但教师需要快速进入课堂专用工作流。
- **选择：** 左侧导航中“AI 课堂”和“课程资源”并列；课程资源总列表也展示 `material_type=classroom`。两个入口使用同一 `classroom_id/material_id`。
- **理由：** 同时满足快速授课和统一资源管理，不复制数据。
- **影响：** 禁止创建第二份课堂资源索引或前端本地课堂副本。
- **回滚：** 可隐藏专用导航，但数据模型无需变化。

## D-004：PPT、闪卡按入口回归处理

- **背景：** 两项能力曾有前端入口，当前教师端动作注册表只剩六项。
- **选择：** P0 恢复为八张正式资源卡；PPT、闪卡必须通过配置、生成、任务恢复、预览、保存和刷新重开的端到端验收。
- **理由：** 只恢复视觉卡片会再次形成“看似可用”的半成品。
- **影响：** 统一任务枚举增加 `generate_ppt`、`generate_flashcard`，课程资源增加 `flashcard` 正式类型。
- **回滚：** 若生成链路故障，可通过功能开关暂时隐藏单项入口，但不得返回占位成功资源。

## D-005：依赖安装以仓库锁文件为准

- **背景：** 前端声明 `pnpm`，但 `Edu_AI` 实际提交 `package-lock.json`；OpenMAIC sidecar 单独提交 `pnpm-lock.yaml`。
- **选择：** `Edu_AI` 使用 `npm ci`；`openmaic-sidecar` 使用冻结的 pnpm 安装并构建本地包。
- **理由：** 分别遵循各目录已提交的锁文件，避免隐式更新依赖。
- **影响：** Windows 上 sidecar 后置构建会在 `rm -rf` 处失败，但此前已成功生成前端测试所需的 `mathml2omml` 和 `pptxgenjs` 产物；该跨平台脚本问题不混入教师端提交。
- **回滚：** 删除未跟踪的依赖目录即可。

## D-006：无人值守期间默认选择兼容性优先

- **背景：** 用户授权在需要决策时自行选择并记录。
- **选择：** 数据结构采用版本化兼容读取、增量迁移和功能开关；不做破坏性批量迁移，不删除旧资源，不更换课堂渲染引擎。
- **理由：** P0/P1 的目标是基本可用和可靠，兼容优先能降低长时间无人值守执行风险。
- **影响：** 可能保留少量旧适配器，待全部验收通过后再清理。
- **回滚：** 关闭对应功能开关并继续读取旧格式。
