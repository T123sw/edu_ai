## D-001：使用独立全局 worktree

- **背景：** 主工作区位于 `main`，且有本轮新建但尚未提交的三份 SPEC。
- **选择：** 在 `C:\Users\Tang\.config\superpowers\worktrees\edu_ai\teacher-p0-p1` 创建 `codex/teacher-p0-p1` 分支；SPEC 复制到功能分支，主工作区原件保持不动。
- **理由：** 避免直接在 `main` 开发，也不覆盖主工作区可能存在的本地状态。
- **影响：** 所有阶段提交推送到远端同名分支。
- **回滚：** 删除 worktree 和功能分支即可；主工作区不受影响。

## D-002：执行顺序按“先美观可用，再可靠可信”

- **背景：** P0/P1 横跨前端体验、任务架构、RAG、资源治理、配置和账户。
- **选择：** 顺序为：信息架构与工作台 → 在线课堂 → 统一任务中心 → 状态与路由 → RAG → 资源与生成 → 配置中心 → 真实用户中心 → 总体验收。
- **理由：** 符合用户明确的优先级，同时让后续架构改造建立在已确定的正式入口和页面职责上。
- **影响：** 任务中心完成前，早期 UI 提交仍暂时复用已有轮询；最终必须迁移并删除组件私有轮询。
- **回滚：** 各批次均为独立提交，可按阶段回退。

## D-003：AI 课堂的双重入口保持同源

- **背景：** AI 课堂在数据层属于课程资源，但教师需要快速进入课堂专用工作流。
- **选择：** 左侧导航中“AI 课堂”和“课程资源”并列；课程资源总列表也展示 `material_type=classroom`。两个入口使用同一 `classroom_id/material_id`。
- **理由：** 同时满足快速授课和统一资源管理，不复制数据。
- **影响：** 禁止创建第二份课堂资源索引或前端本地课堂副本。
- **回滚：** 可隐藏专用导航，但数据模型无需变化。

## D-004：PPT、闪卡按入口回归处理

- **背景：** 两项能力曾有前端入口，当前教师端动作注册表只剩六项。
- **选择：** P0 恢复为八张正式资源卡；PPT、闪卡必须通过配置、生成、任务恢复、预览、保存和刷新重开的端到端验收。
- **理由：** 只恢复视觉卡片会再次形成“看似可用”的半成品。
- **影响：** 统一任务枚举增加 `generate_ppt`、`generate_flashcard`，课程资源增加 `flashcard` 正式类型。
- **回滚：** 若生成链路故障，可通过功能开关暂时隐藏单项入口，但不得返回占位成功资源。

## D-005：依赖安装以仓库锁文件为准

- **背景：** 前端声明 `pnpm`，但 `Edu_AI` 实际提交 `package-lock.json`；OpenMAIC sidecar 单独提交 `pnpm-lock.yaml`。
- **选择：** `Edu_AI` 使用 `npm ci`；`openmaic-sidecar` 使用冻结的 pnpm 安装并构建本地包。
- **理由：** 分别遵循各目录已提交的锁文件，避免隐式更新依赖。
- **影响：** Windows 上 sidecar 后置构建会在 `rm -rf` 处失败，但此前已成功生成前端测试所需的 `mathml2omml` 和 `pptxgenjs` 产物；该跨平台脚本问题不混入教师端提交。
- **回滚：** 删除未跟踪的依赖目录即可。

## D-006：无人值守期间默认选择兼容性优先

- **背景：** 用户授权在需要决策时自行选择并记录。
- **选择：** 数据结构采用版本化兼容读取、增量迁移和功能开关；不做破坏性批量迁移，不删除旧资源，不更换课堂渲染引擎。
- **理由：** P0/P1 的目标是基本可用和可靠，兼容优先能降低长时间无人值守执行风险。
- **影响：** 可能保留少量旧适配器，待全部验收通过后再清理。
- **回滚：** 关闭对应功能开关并继续读取旧格式。

## D-008：课程级导航把课程 ID 写入 hash

- **背景：** 仅依赖 `localStorage` 的课程选择无法可靠支持直接链接和跨页面刷新，历史代码还会生成不存在的 `#undefined` 视频路由。
- **选择：** 所有教师课程级导航使用 `#<route>?course_id=<encoded>`；缺失、`undefined` 或 `null` ID 时安全返回课程列表，AppShell 根据 URL 从后端恢复课程。
- **理由：** URL 成为可分享的导航上下文，`localStorage` 只保留体验缓存。
- **影响：** 旧的无查询参数 hash 继续兼容；无课程 ID 不进入可能写数据的课程页面。
- **回滚：** 路由解析器可忽略查询参数，不影响已有 route key。

## D-009：工作台按实际内容宽度切换三栏、紧凑栏和抽屉

- **背景：** 浏览器宽度 1280px 时，固定的 `320 + 520 + 320` 三栏最小宽度超过扣除课程侧栏后的可用空间，生成工厂被挤出视口；仅按浏览器媒体查询无法反映主工作区的真实宽度。
- **选择：** 使用 `ResizeObserver` 读取工作台容器宽度：`>=1540px` 保持三栏，`1200～1539px` 强制左右至少折叠一个，`<1200px` 以对话为主并通过“知识库／生成工厂”抽屉切换。
- **理由：** 与 SPEC 的内容宽度断点一致，优先保证对话输入可用，同时让两侧能力始终可达，并消除横向滚动。
- **影响：** 1280px 浏览器下主工作区宽度约 966px，默认只展示对话；生成工厂以 420px 右侧抽屉打开，内部八类入口按两列并可纵向滚动。
- **回滚：** 删除布局模式解析和抽屉样式即可恢复原三栏，但会重新出现窄屏裁切。

## D-010：生成入口由纯数据能力注册表驱动

- **背景：** PPT、闪卡入口因 UI 代码内硬编码六项而回归，卡片顺序、文案和图标耦合在大型组件中。
- **选择：** 将八类正式资源的类型、顺序、标题、说明和颜色抽到 `studioActions.ts`；组件只负责图标与行为适配，AI 课堂仍作为独立主卡置于网格之前。
- **理由：** 能力清单可以被测试、任务枚举和资源筛选复用，新增或恢复入口不会再依赖固定行数。
- **影响：** 当前小结只恢复入口和可访问布局；PPT、闪卡正式生成、任务恢复、预览和持久化仍在 Task 11 完成，期间不允许以占位成功资源冒充闭环。
- **回滚：** 可将元数据内联回组件，但会失去注册表级回归保护。

## D-011：课程资源采用“统一列表 + 类型适配器”，未知类型只展示元数据

- **背景：** 旧资源页按后端目录分组，只识别五种类型，并把所有资源的主操作错误地导向固定视频页；这会破坏 AI 课堂的资源身份，也会让未来类型执行错误行为。
- **选择：** 建立统一的类型元数据、筛选和打开目标适配器；`classroom` 使用 `course_id + material_id` 打开课堂播放器，其他正式类型进入自身预览，未知类型只展示基础元数据。
- **理由：** 列表继续兼容未来类型，但不会通过猜测把未知资源交给错误播放器；课堂页和资源页可共享同一个材料 ID。
- **影响：** “全部”包含所有课程材料，新增 AI 课堂、文稿、教案、PPT、闪卡、习题、互动和其他筛选；错误状态可重试，空状态提供生成入口。
- **回滚：** 类型适配器可回退为全部通用预览，但不得恢复固定视频页跳转。

## D-012：在线课堂按页硬隔离播放，不提供课程级时间轴

- **背景：** 教师在线授课以翻页和当页互动为主，完整课程时间轴只在无头浏览器导出 MP4 时有确定用途；现有播放引擎也无法可靠地从一条语音动作的中间时间点恢复。
- **选择：** 在线课堂只提供当前页的播放、暂停、重播和翻页。翻页、暂停和重播都先销毁当前页运行时，统一停止语音、视频、聚焦效果和计时器；播放完成停在当前页，不自动进入下一页。暂停后按钮明确写为“重新播放当前页”，不伪装为断点续播。完整 `LessonTimeline` 继续保留在 MP4 导出链路内部，不在教师课堂界面展示全局拖动条。
- **理由：** 课堂控制的关键是可预测和不串页。硬隔离比不完整的断点恢复更可靠，也符合用户确认“在线课堂不需要按时间线控制”的判断。
- **影响：** 课堂目录、键盘左右翻页、16:9 自适应舞台、当前页提词/字幕和演示全屏成为在线使用主路径；视频导出仍使用原有全课时间线，二者互不改变数据格式。
- **回滚：** 若未来底层媒体适配器提供可验证的暂停时间戳与恢复协议，可在保持按页所有权边界的前提下增加真正的“继续播放”，但不得引入跨页自动播放或复用上一页媒体实例。

## D-013：P0 任务账本继续使用文件存储，但建立版本化仓储边界

- **背景：** 现有 `EduJob` 已经按单任务 JSON 落盘，直接迁移数据库会扩大本轮范围；但旧实现使用普通覆盖写且没有 owner 列表、并发版本或损坏隔离。
- **选择：** 保留 `Config.STORAGE_ROOT/jobs/`，将读写统一收敛到 v2 JobRepository 风格接口；每次更新在同目录写临时文件、flush + fsync 后原子替换，并用目录级可重入锁和递增 `version` 防止进程内并发覆盖。读取 v1 时映射 `owner -> owner_user_id` 并规范化课堂结果引用，不批量改写旧文件。
- **理由：** 在不引入数据库迁移风险的情况下满足刷新恢复、用户隔离和故障安全；仓储接口也为后续替换数据库保留边界。
- **影响：** 列表接口只返回当前认证用户，支持状态/类型/课程/活跃任务过滤及游标分页；单个损坏 JSON 被记录并跳过，不再拖垮整个任务列表。
- **回滚：** 可将仓储实现替换为数据库，但必须保留 v2 API 字段、旧记录兼容读取和原子状态转换语义。

## D-014：取消采用协作式语义，重试创建新任务且不覆盖历史

- **背景：** OpenMAIC sidecar 和无头视频子进程并非所有阶段都能立即中断，强行把取消请求直接标记为完成会造成后台仍写入资源；覆盖原失败任务也会丢失诊断历史。
- **选择：** queued 任务可直接进入 `canceled`；running 任务先进入 `cancel_requested`，业务编排在结果发布前再次检查并放弃落库，最终进入 `canceled`。重试仅允许 failed、partially_succeeded、canceled，创建新 `edu_job_id` 并记录 `retry_of_job_id`；当前可执行重试先覆盖 AI 课堂生成与课堂视频导出，其余类型在接入统一生成命令时注册。
- **理由：** 明确区分“用户要求停止”和“后台已安全停止”，避免取消后仍把产物发布为成功；新任务保留完整失败链路。
- **影响：** 取消可能短暂显示“取消中”；旧失败任务永久保留，新任务复用经过脱敏的 `input_summary`，不复制密钥、令牌或认证头。
- **回滚：** 若下游提供原生 cancel API，可缩短 `cancel_requested` 阶段，但不得恢复覆盖旧任务或在取消后发布资源。

## D-015：全局轮询采用浏览器多标签页单主租约

- **背景：** 每个页面、每个生成组件各自轮询会在刷新后丢失状态；同一用户同时打开多个标签页时，如果每个标签页都固定轮询，还会重复请求和重复弹出完成通知。
- **选择：** 认证后的应用根节点只挂载一个 `GlobalJobManager`；标签页通过带过期时间的 `localStorage` 租约竞选唯一轮询者，由主标签页请求用户任务账本，再通过 `BroadcastChannel` 向其他标签页广播快照。主标签页关闭或租约过期后，其他标签页自动接管；新建任务、页面重新获得焦点或重新可见时立即唤醒。
- **理由：** 不引入 WebSocket 和额外基础设施即可消除组件私有轮询，并将多标签页请求量控制在单标签页水平；租约与广播均为浏览器原生能力，失效时仍可由定时竞选恢复。
- **影响：** 活跃任务按前台/后台和 queued/running 状态自适应轮询，网络失败采用有上限的退避；只对本次会话中从活跃态转为终态的任务通知一次，加载历史记录时不补发旧通知。登出或进入无头视频渲染路由会清空内存态，避免用户间数据串联。
- **回滚：** 可将领导者选举替换为服务端推送，但全局单一任务状态源、owner 隔离和“历史不补通知”的语义必须保留。

## D-016：后台完成后不自动跳页或下载，改为显式打开结果

- **背景：** 旧课堂生成组件完成后会强制跳转播放器，视频导出完成后会立即触发下载；刷新恢复或教师正在其他页面操作时，这两种行为都会打断当前工作，而且浏览器通常会拦截非用户手势触发的恢复后下载。
- **选择：** 课堂与视频组件只负责提交任务并注册到全局任务源。完成时由任务中心通知并提供“打开资源”，原组件在重新进入页面后展示“立即播放”或“下载 MP4/SRT”；不自动改变路由，也不自动下载。
- **理由：** 后台任务的核心承诺是允许用户离开当前页。显式消费结果使刷新、跨页和多标签页行为一致，也避免完成回调重复执行。
- **影响：** 课堂列表与生成弹窗直接订阅全局 store，不再写 `localStorage` 恢复记录或启动私有轮询；视频按钮同样从 owner 任务账本恢复，并以 `course_id + classroom_id` 选择正确任务。
- **回滚：** 可在同一页面、同一会话内增加一次性的“完成后自动打开”用户偏好，但不得把自动行为作为恢复任务的默认语义。

## D-017：保留生成结果仓储，旧 ChatTask 只作为结果载荷兼容层

- **背景：** 报告、教案、习题、小游戏等流程原本写入独立 SQLite `TaskStore`，前端按 task ID 私有轮询；该表只有一小时 TTL、没有 owner 字段，也没有全局列表，因此既不能安全跨用户查询，也无法承担刷新恢复。
- **选择：** 后台 runner 在认证用户发起受支持工作流时先创建同 ID 的 `EduJob`，再把 queued/running/progress/succeeded/failed 状态同步到全局账本；`TaskStore` 增加 owner 字段并继续短期保存完整响应载荷，供同页完成后一次性读取，不再作为任务状态权威。课程资源仍由各生成服务按既有路径持久化。
- **理由：** 完整聊天响应可能很大且包含会话 UI 信息，不适合复制进轻量任务账本；“账本管状态与资源引用、业务仓储管产物”能在不破坏现有生成链路的情况下完成统一恢复和权限隔离。
- **影响：** ChatTask 查询必须匹配当前用户名；报告、教案、习题、小游戏以及对话触发的 PPT 等受支持工作流会出现在全局任务中心。旧任务载荷过期后，用户仍可从课程资源打开已保存产物。
- **回滚：** 后续可以删除兼容 TaskStore，把完整结果读取改为资源 API；不得再把任务状态和 owner 权限退回到短 TTL 结果表。

## D-018：RAG 文档采用“稳定身份 + 活动索引版本”生命周期

- **背景：** 旧知识库上传接口在文件落盘后同步尝试入库，即使解析或向量化失败也可能向前端返回成功；重建时先删除旧向量还会让原本可用的文档突然不可检索。
- **选择：** 课程知识库索引继续保存稳定的 `document_id` 和文件元数据，耗时处理统一创建 `rag_import` 任务；文档按 `received → parsing → chunking → embedding → indexing → ready/failed` 展示状态。重建索引先写入带版本后缀的新向量源，成功保存活动索引记录后再清理旧源；失败时继续保留旧 `active_index_version`。单文档“测试检索”只展示原始命中片段、页码、匹配度和耗时，不调用大模型组织答案。
- **理由：** 把“上传完成”和“知识可用”分开，教师能理解当前阶段并自行重试；先写后切换避免重建失败中断正在使用的课程问答；无大模型的检索测试能直接验证索引质量且不产生答案幻觉。
- **影响：** 上传、个人资料转入课程库、重试和重建都进入全局任务中心；相同文档只允许一个活动处理任务；私有文档的详情、删除和任务均校验当前用户。旧文档在首次重建前仍可显示“已接收”，不会被假定为已经成功索引。
- **回滚：** 可替换底层向量库或将文档元数据迁入数据库，但必须保留稳定文档身份、活动版本原子切换、状态可见和 owner 隔离语义。

## D-019：课程资源以单资源 manifest 为事实来源

- **背景：** 现有生成器直接在不同目录写 JSON 或附件，缺少统一 owner、来源任务、配置版本与完整性信息；PPT、闪卡和小游戏还可能落入 `others`，删除只清理一个文件。
- **选择：** 保留当前按课程/类型分目录的兼容结构，但把每份资源 JSON 升级为 v2 manifest，统一补齐稳定 ID、版本、owner、`source_job_id`、`config_snapshot_id`、来源摘要、内容哈希和附件清单。JSON 通过同目录临时文件 + fsync + 原子替换发布，附件先暂存、manifest 失败时回滚；PPT、闪卡、小游戏和 AI 课堂使用独立正式目录。资源 API 的列表、详情、重命名、置顶、删除和完整性检查均执行 owner 校验，旧的无 owner 资源按课程共享数据兼容读取。
- **理由：** 单资源 manifest 能复用现有业务生成器，同时为任务恢复、结果追溯、配置快照和附件清理提供统一契约；无需在本轮引入数据库迁移或全局索引双写。
- **影响：** 新资源逐次更新 `version`，文件附件和课堂媒体随资源完整删除；前端资源详情提供真实重命名、置顶和删除操作。内部可信调用不传 owner 时仍可做兼容读取，所有 HTTP 路由必须显式传入当前用户。
- **回滚：** 后续可把 manifest 仓储迁入数据库/对象存储，但必须保留字段语义、原子发布、完整删除和旧资源兼容读取。

## D-020：PPT 恢复旧入口，闪卡补齐可信生成闭环

- **背景：** 用户确认 PPT 和闪卡都是既有能力，不应作为新增功能；代码历史显示 PPT 的配置／大纲／导出链路曾存在，后续在切换 AI 课堂主链路时被移除，而闪卡保留了类型和配置外形但缺少正式后端资源保存。
- **选择：** 不以占位卡片冒充恢复。PPT 按历史知识库直达链路恢复配置、大纲确认、后台生成、预览与导出；闪卡复用现有文档内容提供器和模型客户端，并通过统一 `GenerationCommand` 接入 owner、课程、来源、幂等键、EduJob 和 CourseMaterial。资源保存失败使用 `partially_succeeded`，不把“内容生成成功”误报为完整成功。
- **理由：** 最大限度复用已验证的生成器和已有资源预览协议，同时把入口回归造成的断链补齐为刷新后仍能恢复的正式任务。
- **影响：** 闪卡现在是独立正式资源，支持数量、难度、分类、来源开关及逐张翻面预览；PPT 的恢复继续沿用现有 html2ppt 业务引擎，不另建第二套生成器。
- **回滚：** 若未来统一由 AI 课堂提供 PPT，可将 PPT 命令适配到该引擎，但仍须产出独立 `ppt` CourseMaterial 并满足同一验收链路。

## D-021：生成工厂博客自动确认大纲，专用博客流程保留人工审核

- **背景：** 既有教学博客引擎包含章节和详细大纲两次人工审核，原前端依靠组件私有轮询推进；这与“生成工厂提交后可离开页面、由全局任务中心恢复”的交互契约冲突。
- **选择：** 在生成工厂的博客入口中，将教师填写主题并点击生成视为授权使用模型生成的大纲继续执行，两次审核节点由适配器自动确认；既有专用博客页面及其人工修改、确认接口保持不变。思维导图则使用选中知识库文档生成真实层级 JSON，校验节点标题、最大深度和同级重复后保存为正式 `graph` 资源。
- **理由：** 生成工厂保持统一的非阻塞后台任务体验，同时不删减需要精细编辑时可用的人工审核能力；图谱不再由前端创建占位资源。
- **影响：** 博客和图谱都进入 owner 隔离的 `EduJob`，刷新后可恢复，完成后从课程资源列表打开；博客若需要逐级调整，应从专用编辑流程发起。
- **回滚：** 若未来任务中心支持可恢复的人机审核节点，可把博客审核状态直接呈现在任务详情中，但不得恢复组件级私有轮询。

## D-022：运行配置采用“环境默认 → 系统启用版 → 个人启用版”三层解析

- **背景：** 模型、Embedding、语音、搜索、PDF 解析和课堂 sidecar 原先分散读取环境变量；直接让前端修改环境文件既不安全，也无法给运行中的任务提供稳定版本。
- **选择：** 配置以不可变 revision 保存，生命周期为草稿、验证成功／失败、启用、被替代；密钥使用由独立主密钥派生的 AES-GCM 密文落盘，API 永远只返回掩码。解析优先级固定为个人启用版高于系统启用版、高于环境默认；系统配置只允许管理员管理。每个认证请求和生成任务在开始时冻结各 provider 的 revision ID，任务结果继续记录组合配置快照 ID。
- **理由：** 用户无需接触源码即可配置服务，同时切换或回滚不会让正在执行的任务中途换模型；环境变量继续作为无迁移成本的部署默认值。
- **影响：** 对话模型、Embedding、Web 搜索、PDF 解析和 OpenMAIC 客户端均改为读取解析器；OpenAI-compatible TTS 在课堂落库前为缺少音频的 speech 动作补配音并保存到课程附件，密钥不会发送到浏览器或 sidecar。配置必须真实验证后才能启用，历史启用版可回滚。
- **回滚：** 可把文件仓储迁移到数据库或 KMS，但必须保留 revision、加密、权限、掩码、解析优先级和任务快照语义。

## D-023：配置中心从账号中心进入，不占用课程工作区侧栏

- **背景：** 教师课程工作区侧栏已经固定为六个高频教学目的地，服务配置属于低频账户／部署操作；把它加入课程侧栏会削弱当前课程上下文，也会再次挤压窄屏导航。
- **选择：** 在真实账号中心的快捷入口增加“AI 服务配置”，配置页按六类服务卡片展示；普通用户只见个人配置，管理员可在个人／系统配置间切换。每张卡严格遵循“保存草稿 → 测试连接 → 启用”，仅存在历史启用版时显示回滚。
- **理由：** 保持教学导航稳定，同时让配置入口可发现；状态和操作按服务拆分，失败不会阻塞其他 provider。
- **影响：** 密钥输入禁用明文切换和浏览器旧值回填，卡片只展示模型名、掩码和生效来源；新建配置必须重新填写密钥，避免把掩码当成真实密钥提交。
- **回滚：** 若未来增加全局管理后台，可迁移页面入口，但个人配置仍应从账号中心可达，且不得将密钥字段放入前端持久化。

## D-024：账号中心只展示后端事实，密码哈希在使用时渐进升级

- **背景：** 原个人主页使用固定姓名、邮箱、手机和头像，重置密码与更换头像按钮也没有真实行为；旧用户文件中的密码是无盐 SHA-256。
- **选择：** `/api/auth/me` 成为账号资料事实来源，并提供本人资料更新、旧密码校验后的改密、2MB 内 JPG/PNG/WebP 头像上传与本人读取。新密码使用带随机盐的 PBKDF2-SHA256；旧 SHA-256 记录只为兼容登录保留，并在首次成功验证时自动升级。公开注册不再允许请求 `admin` 角色。
- **理由：** 不做一次性破坏迁移即可提升现有账户安全，页面刷新后仍显示真实资料；头像由鉴权请求转成临时 Blob URL，不暴露公共静态路径。
- **影响：** 用户名和角色不可由本人资料表单修改；错误旧密码不会改变任何记录，改密时间和头像路径随账户保存。管理员创建和授权后续应由独立管理接口承担。
- **回滚：** 可迁移到数据库和更强的密码库，但必须继续校验旧密码、隐藏哈希与内部头像路径，并禁止公开注册管理员。

## D-025：视频入库归入统一任务账本，上传页面不等待处理完成

- **背景：** 视频上传仍把任务保存在进程内字典中，并由知识库面板每 1.5 秒私有轮询；刷新页面或重启后端会丢失任务状态，也与 P0 的单一任务状态源冲突。
- **选择：** 增加 `ingest_video` 正式任务类型。上传完成后只在持久化任务账本写入用户、课程、用户目录内相对路径、切片参数及模型配置 revision 快照，前端立即唤醒全局任务中心并允许教师离开页面。旧视频任务查询接口保留为只读兼容适配器；失败重试创建新任务并复用原始脱敏参数。
- **理由：** 视频入库与文档索引具有同样的长耗时和恢复需求，不应形成第二套轮询与易失状态；相对路径既足以安全重建源文件位置，也不会把服务器绝对路径暴露到任务 API。
- **影响：** 视频完成、失败、取消和重试均在全局任务中心可见；任务执行使用提交时冻结的 Embedding 配置版本。合作式取消在开始前阻止执行，运行中收到取消请求时由统一状态机阻止成功结果发布。
- **回滚：** 旧 `/api/video/jobs/{id}` 状态接口仍可供旧客户端查询，但不得恢复进程内任务字典或页面私有轮询。

## D-026：配置中心的“停用”表示撤销当前层覆盖，运行时超时属于版本参数

- **背景：** 首版配置中心已经支持保存、验证、启用和回滚，但未提供 SPEC 要求的停用／恢复默认；供应商和超时也未进入配置版本，教师无法判断服务身份或控制异常请求的等待上限。
- **选择：** 每个 provider 版本统一增加 `provider_name` 和 1～120 秒的 `timeout_seconds`，验证记录稳定错误码、耗时和时间。停用当前版本时清除该 scope 的活动指针并保留历史版本，解析器自动回落到系统配置或部署环境；需要恢复该版本时通过回滚重新启用。超时实际传入对话、Embedding、TTS、Web 搜索、视频入库和 OpenMAIC 客户端。
- **理由：** “恢复默认”不应删除经过验证的历史或复制环境变量，而应撤销本层覆盖；把超时冻结在任务配置版本中，才能让界面设置与实际执行一致，并避免配置变更影响已运行任务。
- **影响：** 页面显示供应商、最近验证时间／延迟和明确的“停用并恢复默认”；验证失败以 `timeout`、`endpoint_unreachable`、`authentication_failed`、`model_not_found`、`quota_exceeded` 或 `invalid_response` 诊断，且不返回响应体或密钥。
- **回滚：** 可隐藏停用按钮但不删除后端历史状态；若某个下游不支持独立超时，应继续使用该版本参数的安全上限，不得让字段退化为纯展示。
