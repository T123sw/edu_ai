EXECUTION PIPELINE
原理解析：工具调用的完整生命周期
1
意图解析与规划
输入：用户自然语言请求
动作：客户端识别意图并匹配工具。
输出：工具名、参数槽位和调用计划。
讲解提示：强调“模型判断意图，客户端负责执行边界”。
User: “帮我查最近的 Git 记录”
→ 匹配工具：git_log
2
发起标准 RPC 调用
输入：工具名与结构化参数
动作：客户端封装 JSON-RPC 报文并发送到服务。
输出：标准方法名、参数对象和授权上下文。
讲解提示：把“协议格式”和“传输通道”分开讲，避免混为一谈。
{ "method": "tools/call",
"name": "git_log" }
3
资源访问与上下文回传
输入：已授权的工具调用请求
动作：服务执行命令或查询并整理返回内容。
输出：模型可读的文本、图片或结构化数据。
讲解提示：强调工具只返回上下文，最终表达仍由模型生成。
Result: [Commit 8a2b3]
→ LLM 生成摘要
