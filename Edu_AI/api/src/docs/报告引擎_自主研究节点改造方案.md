## 一、背景与目标

### 1.1 现状

当前报告引擎 `universal_report_engine.py` 的状态机流程：

```
extractor → evaluator → focus_assessor → confirmer(软确认) → outliner → generator
```

必填槽位（core_topic + focus_area）填完、focus 评估通过后，直接进入软确认。生成的报告完全依赖 LLM 自身知识，没有利用已有的 RAG 知识库和 Web 搜索工具来补充事实和数据。

### 1.2 目标

在 focus 评估通过后、软确认前，插入一个 `researcher` 节点。该节点由 LLM 自主判断是否需要调用 RAG/Web 工具：

- **不需要** → 跳过，直接进入软确认（行为与改造前一致）
- **需要** → 执行检索，将结果存入状态，供下游大纲生成和正文生成使用

### 1.3 改造后流程

```
extractor → evaluator → focus_assessor → researcher → evaluator → confirmer → outliner → generator
                                            ↓(不需要检索)
                                         直接跳过 → evaluator → confirmer
```

### 3.2 universal_report_engine.py 核心改动

#### 3.2.1 新增 Pydantic 模型

```python
class ResearchDecisionOut(BaseModel):
    """LLM 研究决策输出模型"""
    model_config = ConfigDict(extra="forbid")

    needs_rag: bool
    needs_web: bool
    rag_queries: List[str] = Field(default_factory=list)
    web_queries: List[str] = Field(default_factory=list)
    reason: str = ""
```

#### 3.2.2 新增辅助函数 `_decide_research_needs`

LLM 根据 core_topic + focus_area 判断是否需要 RAG/Web 检索，并生成查询语句。

**Prompt 判断标准：**

| 条件 | 决策 |
|------|------|
| 主题可能在本地知识库有相关文档（教育类、课程类） | `needs_rag=true` |
| 需要最新数据、案例、或超出知识库范围的信息 | `needs_web=true` |
| 通用常识且不需要特定数据支撑 | 两者都 `false` |

**输出：** 1-3 个 RAG 查询 + 1-2 个 Web 查询

**失败兜底：** 返回 `needs_rag=False, needs_web=False`（不检索，不阻断流程）

#### 3.2.3 新增 `researcher_node` 函数

```python
def researcher_node(
    state: ReportState,
    *,
    researcher_llm: Optional[Any] = None,
    tool_registry: Optional[ToolRegistry] = None,
) -> Dict[str, Any]:
```

**执行逻辑：**

```
1. research_done=True? → 直接返回 phase="evaluating"（防重入）
2. 无 LLM 或无 tool_registry? → 跳过，设 research_done=True
3. 调用 _decide_research_needs 获取 LLM 决策
4. needs_rag=False and needs_web=False? → 跳过
5. 按决策调用工具：
   - RAG: tool_registry["rag_search_tool"]，最多 3 个查询，每个 top_k=5
   - Web: tool_registry["web_search_tool"]，最多 2 个查询
   - 每个调用独立 try/except，单个失败不影响其他
6. 汇总结果到 research_context，设 research_done=True，返回 phase="evaluating"
```

**research_context 数据结构：**

```json
{
  "rag_results": [
    {"query": "...", "answer": "...", "sources": [...]}
  ],
  "web_results": [
    {"query": "...", "payload": {...}}
  ]
}
```

#### 3.2.4 修改 `evaluator_node` 路由逻辑

在 focus 评估通过后、软确认检查前，插入研究门禁：

```python
# 现有：focus_sufficient 检查之后
# 新增：
if not state.get("research_done"):
    _trace("evaluator", ["research 未完成 → researching"])
    return {"phase": "researching"}

# 然后才是现有的 soft_confirmed 检查
```

#### 3.2.5 修改 `phase_router`

mapping 新增 `"researching": "researcher"`，返回类型增加 `"researcher"`。

#### 3.2.6 修改 `focus_router`

focus 充分时路由到 `"researcher"` 而非 `"confirmer"`：

```python
def focus_router(state) -> Literal["researcher", "asker"]:
    if state.get("focus_sufficient"):
        return "researcher"
    return "asker"
```

#### 3.2.7 修改 `_build_soft_confirm_question`

新增 `research_decision` 参数，在确认话术前加上研究结果提示：

| research_decision | 前缀话术 |
|-------------------|---------|
| `"rag_only"` | "我已经从知识库中找到了相关参考资料，" |
| `"web_only"` | "我已经从网上搜集了相关参考资料，" |
| `"both"` | "我已经从知识库和网上搜集了相关参考资料，" |
| `"none"` | 无前缀（与改造前一致） |

#### 3.2.8 修改 `confirmer_node`

调用 `_build_soft_confirm_question` 时传入 `state.get("research_decision")`。

#### 3.2.9 修改 `_generate_outline`

新增 `research_context` 参数，将 RAG/Web 结果摘要注入大纲生成 prompt：

```
【本地知识库参考】...
【网络检索参考】...
如果有参考资料，请在大纲中体现相关内容的覆盖。
```

#### 3.2.10 修改 `outliner_node`

调用 `_generate_outline` 时传入 `state.get("research_context")`。

#### 3.2.11 修改 `build_universal_report_graph`

1. 新增 `"researcher"` 节点（使用 `extractor_llm or shared_llm` + `tool_registry`）
2. evaluator 条件边增加 `"researcher": "researcher"`
3. focus_assessor 条件边改为 `"researcher": "researcher"`（原 `"confirmer"`）
4. 新增 `researcher → evaluator` 边（researcher 完成后回到 evaluator 重新路由）

**新拓扑：**

```
                    ┌──────────────────────────────────────────────┐
                    │                                                │
                    ▼                                                │
extractor → evaluator → [asker | focus_assessor | researcher       │
                         | confirmer | outliner | generator]        │
                                          │                         │
                                          └── researcher ───────────┘
                                               (research_done=True
                                                后不会再进入)
```

#### 3.2.12 修改 `make_initial_report_state`

新增初始值：

```python
"research_done": False,
"research_context": {},
"research_decision": "",
```

#### 3.3.2 在每个 section 的 prompt 末尾注入研究资料

```python
if research_context:
    context_lines = []
    for r in research_context.get("rag_results", []):
        answer = str(r.get("answer", "")).strip()
        if answer:
            context_lines.append(answer[:500])
    for w in research_context.get("web_results", []):
        payload = w.get("payload", {})
        summary = str(payload.get("summary", "") or "").strip()
        if summary:
            context_lines.append(summary[:500])

        section_prompt += (
            "\n\n【可参考的研究资料】\n"
            + "\n---\n".join(context_lines[:5])
            + "\n请在写作中适当引用上述资料中的事实和数据，但不要逐字复制。"
        )
```

## 四、错误处理与降级

| 场景 | 处理方式 |
|------|---------|
| LLM 决策调用失败 | 兜底返回 `needs_rag=False, needs_web=False`，跳过研究 |
| 单个 RAG 查询失败 | try/except 捕获，继续执行其他查询 |
| 单个 Web 查询失败 | try/except 捕获，继续执行其他查询 |
| 所有工具调用都失败 | `research_decision="none"`，流程正常继续 |
| tool_registry 为空 | 跳过研究，设 `research_done=True` |
| 无 LLM | 跳过研究，设 `research_done=True` |

核心原则：**研究节点的任何失败都不应阻断报告生成流程。**

## 五、验证方案

1. **路由测试**：evaluator 在 `research_done=False` 时路由到 `researching`；在 `research_done=True` 时跳过到 `confirming`
2. **focus_router 测试**：focus 充分时路由到 `researcher`
3. **集成测试**：启动完整报告流程，观察 trace 日志确认 researcher 节点被正确触发
4. **降级测试**：模拟 tool_registry 为空或工具调用失败，确认流程不中断
5. **内容验证**：对比有/无研究上下文时生成的大纲和正文，确认研究资料被正确引用
