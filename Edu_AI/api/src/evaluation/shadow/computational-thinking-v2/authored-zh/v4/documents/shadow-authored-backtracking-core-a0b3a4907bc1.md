## 学习目标
1. 理解回溯搜索作为系统性枚举策略的本质，区分其与普通深度优先搜索（DFS）的异同。
2. 掌握状态空间树的构建方法，能够识别决策节点与约束条件。
3. 学会设计剪枝函数，在搜索过程中提前排除无效分支，优化时间复杂度。

## 概念与边界
回溯搜索（Backtracking）是一种通过逐步构建候选解并在发现当前候选解不可能成为有效解时放弃该候选解（即“回溯”）的算法技术。它本质上是带有状态恢复的深度优先搜索。

**边界界定**：
- **与 DFS 的区别**：DFS 侧重于遍历图或树的所有节点，而回溯侧重于构建满足特定约束的“解路径”。回溯必须在递归返回时显式撤销选择（状态恢复）。
- **与贪心的区别**：贪心算法在每一步选择局部最优且不可回退，而回溯允许试错，若当前路径不通则返回上一步尝试其他选择。
- **适用场景**：组合优化问题、约束满足问题（CSP）、排列组合生成。不适用于具有最优子结构且可多项式求解的问题（如最短路径）。

## 机制与步骤
回溯算法的核心流程可概括为“选择 - 探索 - 撤销”。在状态空间树中，每个节点代表一个部分解，边代表决策。

1. **终止条件判断**：检查当前路径是否满足完整解的条件。若满足，记录结果。
2. **遍历选择列表**：对于当前状态，列出所有可能的决策选项。
3. **约束检查（剪枝）**：在递归深入前，判断当前选择是否违反约束。若违反，则跳过（剪枝）。
4. **做出选择**：将选项加入当前路径，更新状态。
5. **递归探索**：基于新状态调用自身。
6. **撤销选择**：递归返回后，将选项从路径移除，恢复状态至递归前，以便尝试下一选项。

## 完整示例：组合总和
**问题**：给定候选数字集合 $C = [2, 3, 5]$ 和目标值 $T = 7$，找出所有和为 $T$ 的组合（数字可重复使用）。

**搜索树分析**：
- 根节点：目标剩余 7。
- 第一层：选 2（剩 5），选 3（剩 4），选 5（剩 2）。
- 第二层（以选 2 为例）：再选 2（剩 3），再选 3（剩 2）...
- **剪枝点**：若当前数字大于剩余目标值，后续更大数字无需尝试（假设数组有序）。

## 伪代码与实现
```python
def combination_sum(candidates, target):
    res = []
    candidates.sort()  # 排序以便剪枝
    
    def backtrack(start, path, remaining):
        if remaining == 0:
            res.append(path[:])  # 记录有效解
            return
        for i in range(start, len(candidates)):
            # 剪枝：若当前数已大于剩余值，后续更大数必不满足
            if candidates[i] > remaining:
                break 
            path.append(candidates[i])
            backtrack(i, path, remaining - candidates[i])  # 可重复使用，故传 i
            path.pop()  # 撤销选择
            
    backtrack(0, [], target)
    return res
```

## 复杂度与权衡
- **时间复杂度**：最坏情况下为 $O(b^d)$，其中 $b$ 是分支因子（候选选择数），$d$ 是树的深度（解的长度）。剪枝能显著减少实际访问的节点数，但最坏复杂度仍为指数级。
- **空间复杂度**：$O(d)$，主要用于递归栈和存储当前路径。
- **权衡**：剪枝逻辑本身需要计算时间。若剪枝判断过于复杂，可能得不偿失。通常要求约束检查的时间复杂度为 $O(1)$ 或 $O(d)$。

## 常见误区
1. **忘记状态恢复**：递归返回后未执行 `pop` 或状态重置，导致后续分支污染当前路径。
2. **剪枝时机错误**：应在递归调用前进行剪枝，而非进入递归后再判断，否则浪费了栈空间。
3. **重复解问题**：在排列问题中未处理重复元素，导致生成重复解。需通过排序和跳过相同元素解决。

## 自测题与答案
| 问题 | 答案 |
| :--- | :--- |
| 1. 回溯算法中“撤销选择”步骤缺失会导致什么后果？ | 导致状态污染，后续搜索分支基于错误的前置状态，产生错误解或漏解。 |
| 2. 若候选数组无序，能否使用 `if candidates[i] > remaining: break` 剪枝？ | 不能。必须先排序，否则后续可能存在较小数字满足条件，break 会误删解。 |
| 3. 回溯法适合解决 NP 完全问题吗？ | 适合。虽然不能改变指数级复杂度的本质，但能在可接受时间内找到中小规模问题的解。 |
