## 学习目标
1. 能够将实际工程中的不确定性问题抽象为蒙特卡洛模拟模型。
2. 掌握使用编程语言实现多次独立实验并收集统计数据的技能。
3. 学会通过直方图分析模拟结果的分布特征，而非仅关注单一数值。
4. 能够评估模拟结果的可信度并识别边界条件。

## 真实问题情境
**背景**：某软件开发团队计划开发一个新模块，包含 3 个串行任务。由于需求波动和技术难点，每个任务的耗时是不确定的。项目经理需要评估项目总工期的风险，以便向客户承诺交付日期。
**问题**：如果简单地将每个任务的最可能耗时相加，往往会低估风险。我们需要知道在 90% 的置信度下，项目最多需要多少天完成。
**情境价值**：这是典型的利用随机性模拟确定性计划中不确定性的场景，体现了计算思维中的“抽象”与“自动化”能力。

## 输入输出与材料
**输入材料**：
任务清单（CSV 格式或列表）：
| 任务 ID | 乐观耗时 (天) | 最可能耗时 (天) | 悲观耗时 (天) |
| :--- | :--- | :--- | :--- |
| Task A | 2 | 4 | 6 |
| Task B | 3 | 5 | 10 |
| Task C | 1 | 2 | 5 |

**输出要求**：
1. 项目总工期的模拟分布数据（列表）。
2. 90% 置信度下的工期上限值（单个数值）。
3. 工期分布直方图（可选可视化）。

## 分步任务
1. **定义分布模型**：采用三角分布（Triangular Distribution）来模拟每个任务的耗时。三角分布由最小值 $a$、最大值 $b$ 和众数 $c$ 定义，适合描述缺乏大量历史数据但专家可估算极值的情况。
2. **构建单次模拟函数**：编写函数 `simulate_once()`，在该函数中分别为 Task A、B、C 生成随机耗时，并求和得到总工期。
3. **执行批量模拟**：调用 `simulate_once()` 函数 10,000 次，将结果存入列表。
4. **统计分析**：对结果列表排序，找到第 90 百分位数（即 90% 的模拟结果小于该值）。
5. **结果可视化**：使用绘图库绘制直方图，观察分布是否对称。

## 参考实现
```python
import random
import matplotlib.pyplot as plt

def get_task_duration(min_t, mode_t, max_t):
    # 使用三角分布生成随机耗时
    return random.triangular(min_t, max_t, mode_t)

def simulate_project():
    # 定义任务参数 (min, mode, max)
    tasks = [
        (2, 4, 6),
        (3, 5, 10),
        (1, 2, 5)
    ]
    total_days = 0
    for t in tasks:
        total_days += get_task_duration(*t)
    return total_days

# 主程序
N = 10000
results = [simulate_project() for _ in range(N)]
results.sort()

# 计算 90% 置信度上限
index_90 = int(N * 0.9)
confidence_90 = results[index_90]

print(f"平均工期：{sum(results)/N:.2f} 天")
print(f"90% 置信度工期上限：{confidence_90:.2f} 天")
```

## 测试与边界情况
1. **种子一致性测试**：在代码开头设置 `random.seed(42)`，多次运行程序，确认输出结果完全一致。这是验证代码确定性的关键。
2. **边界值测试**：修改某个任务的乐观、最可能、悲观耗时全部为相同值（例如均为 5）。此时模拟结果的标准差应接近 0，总工期应为固定值。
3. **极端分布测试**：将某个任务的悲观耗时设为极大值（如 100 天），观察直方图是否出现长尾效应。这验证了模型对极端风险的敏感性。
4. **样本量敏感性**：分别尝试 $N=100$ 和 $N=10000$，对比 90% 分位数的波动情况，体会大数定律的作用。

## 拓展问题
1. **任务并行化**：如果任务 B 和任务 C 可以并行执行，总工期的计算逻辑应如何修改？（提示：取最大值而非求和）。
2. **相关性影响**：现实中，若任务 A 延期，往往导致任务 B 也延期（正相关）。如何在模拟中引入相关性系数？（提示：使用共同的基础随机变量）。
3. **资源约束**：如果团队只有 2 名开发人员，任务之间存在资源竞争，模拟模型需要增加什么状态变量？（提示：增加队列或资源池状态）。
4. **分布选择**：如果有历史数据支持，为何正态分布或对数正态分布可能比三角分布更合适？请查阅相关统计特性。
