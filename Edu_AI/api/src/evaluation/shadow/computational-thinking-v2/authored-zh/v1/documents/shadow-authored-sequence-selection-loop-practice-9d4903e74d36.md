## 真实问题情境
某智能水务公司需要开发一个简易的“管网压力监测脚本”。传感器每小时上传一次管道压力值（单位：MPa）。系统需要处理一天的 24 个数据点，完成以下任务：统计平均压力，找出压力超过安全阈值（0.8 MPa）的时刻，并计算超标次数。若全天无数据，需报错提示。

## 输入输出或材料
**输入材料**：一个包含 24 个浮点数的列表，代表 24 小时压力值。例如：`[0.5, 0.6, ..., 0.9]`。
**输出规范**：
1. 打印平均压力（保留 2 位小数）。
2. 打印超标时刻列表（小时索引，0-23）。
3. 打印超标总次数。
4. 若输入列表为空，打印"Error: No Data"。

## 分步任务
1. **数据验证**：首先检查输入列表是否为空。
2. **初始化变量**：设定累加器、超标计数器及记录列表。
3. **遍历处理**：使用循环遍历 24 个数据点。
4. **条件判断**：在循环内判断当前压力是否大于 0.8。
5. **结果输出**：循环结束后，计算平均值并格式化输出所有统计结果。

## 参考实现/推导
以下是基于 Python 的参考实现，展示了顺序、分支与循环的综合运用。

```python
def monitor_pressure(readings):
    # 步骤 1：分支结构处理边界
    if not readings:
        print("Error: No Data")
        return

    # 步骤 2：顺序结构初始化
    total_pressure = 0.0
    alarm_hours = []
    threshold = 0.8
    
    # 步骤 3 & 4：循环与嵌套分支
    for hour, pressure in enumerate(readings):
        total_pressure += pressure
        if pressure > threshold:
            alarm_hours.append(hour)
            
    # 步骤 5：计算与输出
    avg_pressure = total_pressure / len(readings)
    print(f"平均压力：{avg_pressure:.2f} MPa")
    print(f"超标时刻：{alarm_hours}")
    print(f"超标次数：{len(alarm_hours)}")

# 测试数据
data = [0.5] * 23 + [0.9]  # 23 个正常，1 个超标
monitor_pressure(data)
```

## 测试与边界情况
为确保逻辑严密，必须设计以下测试用例：
1. **正常情况**：包含正常值与超标值的混合列表。
2. **全超标情况**：所有数据均大于 0.8，验证计数器是否等于 24。
3. **空列表情况**：输入 `[]`，验证是否触发"Error: No Data"分支，防止除以零错误。
4. **边界值**：压力值恰好等于 0.8，验证是否被计入超标（根据需求，通常大于才算超标）。
5. **异常数据类型**：若列表中包含负数（物理上不可能），虽本例未处理，但应意识到这是潜在的扩展需求。

## 拓展问题
1. **加权平均**：若不同时间段的重要性不同（如用水高峰期权重为 1.5），如何修改循环内的累加逻辑？
2. **连续超标检测**：不仅需要统计次数，还需检测是否存在“连续 3 小时超标”的情况，这需要如何在循环中增加状态记录变量？
3. **数据流处理**：如果数据不是列表，而是实时流式输入（无法预先知道长度），循环的终止条件应如何设计？（提示：使用特定终止符或异常捕获）。
