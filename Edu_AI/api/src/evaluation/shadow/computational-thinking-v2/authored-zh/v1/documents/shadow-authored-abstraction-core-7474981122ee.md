## 学习目标
1. 理解抽象、建模与信息隐藏的定义及其相互关系，能够区分三者在不同计算场景下的作用。
2. 掌握通过信息隐藏设计接口的具体步骤，能够编写符合封装原则的代码结构。
3. 识别违反信息隐藏原则的设计模式，并评估其对系统维护性的影响。

## 核心概念与边界
**抽象（Abstraction）** 是指忽略细节、提取本质特征的过程。在计算思维中，抽象意味着将具体问题映射为计算对象，例如将“苹果”抽象为“整数”。**模型（Model）** 是抽象的结果，是对现实世界某一方面特征的形式化描述，如数学公式或数据结构。**信息隐藏（Information Hiding）** 是一种设计原则，指模块内部的具体实现细节对外部不可见，外部仅能通过定义的接口进行交互。

三者的边界在于：抽象是思维过程，模型是思维产物，信息隐藏是保护模型内部稳定性的机制。抽象决定了模型包含哪些信息，而信息隐藏决定了哪些信息不暴露。例如，在设计地图导航时，抽象出“路口”和“道路”是建模过程，而将“道路修建成本”隐藏起来只暴露“通行时间”则是信息隐藏。

## 机制与实施步骤
实施信息隐藏通常遵循以下四个步骤：
1. **需求分析**：确定模块需要对外提供哪些功能。
2. **接口定义**：设计函数签名或类方法，明确输入输出类型。
3. **内部实现**：编写完成功能的代码，包含私有变量和辅助逻辑。
4. **访问控制**：利用语言特性（如 `private` 关键字或命名约定）限制内部成员访问。

这一机制的核心在于降低**耦合度（Coupling）**。若模块 $A$ 依赖模块 $B$ 的内部细节，当 $B$ 变化时 $A$ 必须修改。通过隐藏 $B$ 的实现，$A$ 仅依赖接口，从而隔离变化。

## 完整示例：银行账户系统
以下 Python 代码展示了一个简单的银行账户模型。其中余额 `__balance` 被隐藏，外部只能通过 `deposit` 和 `withdraw` 操作，确保了数据一致性。

```python
class BankAccount:
    def __init__(self, initial_balance=0):
        # 双下划线开头表示私有成员，外部无法直接访问
        self.__balance = initial_balance 
    
    def deposit(self, amount):
        """存款接口：隐藏了具体的余额更新逻辑"""
        if amount > 0:
            self.__balance += amount
            return True
        return False
    
    def withdraw(self, amount):
        """取款接口：隐藏了余额充足性检查逻辑"""
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            return True
        return False
    
    def get_balance(self):
        """查询接口：只读访问，不可直接修改"""
        return self.__balance

# 使用示例
acc = BankAccount(100)
acc.deposit(50)
# acc.__balance = 1000000  # 此行会报错或无效，体现了信息隐藏
print(f"Current Balance: {acc.get_balance()}")
```

## 复杂度与权衡
信息隐藏并非没有代价。主要权衡在于**灵活性 vs. 性能**。
1. **维护性提升**：内部算法优化（如将余额存储从整数改为定点数）不影响外部调用。
2. **调用开销**：每次访问私有变量需通过方法调用，可能增加微小的运行时开销。
3. **调试难度**：黑盒特性使得内部状态难以直接观察，需要专门的调试接口。

公式化描述模块依赖关系：设系统总复杂度为 $C$，模块数为 $n$，若模块间耦合度为 $k$，则 $C \propto n \times k$。信息隐藏旨在最小化 $k$。

## 常见误区
1. **误区一：信息隐藏等于数据加密**。信息隐藏是软件工程概念，旨在管理依赖；加密是安全概念，旨在防止未授权访问。私有变量在内存中仍可被特定手段读取。
2. **误区二：抽象越高层越好**。过度抽象会导致模型脱离实际，增加理解成本。例如将“用户”抽象为“对象”是合适的，但抽象为“比特流”则失去了业务语义。
3. **误区三：所有细节都必须隐藏**。频繁访问的只读数据提供 `public` 属性可能更高效，关键在于是否允许外部修改状态。

## 自测题与答案
1. **问**：如果在 `BankAccount` 类中将 `__balance` 改为 `balance`（公开），会有什么风险？
   **答**：外部代码可直接修改余额（如设为负数），绕过 `withdraw` 中的逻辑检查，破坏数据一致性。
2. **问**：信息隐藏是否意味着完全不知道模块内部做了什么？
   **答**：不是。外部需要知道接口的功能语义（做什么），但不需要知道实现算法（怎么做）。
3. **问**：抽象与信息隐藏的主要区别是什么？
   **答**：抽象关注“保留什么特征”，信息隐藏关注“屏蔽什么细节”。抽象是建模的前提，隐藏是维护的手段。
