## 学习目标
1. 理解计算机为何采用二进制而非十进制进行底层数据存储。
2. 掌握十进制与二进制之间的整数转换方法。
3. 深刻理解补码（Two's Complement）机制及其在表示有符号整数中的作用。
4. 能够识别并解释定点整数表示中的溢出问题。

## 准确概念与边界
**二进制（Binary）**：计算机硬件基于双稳态电路（开/关、高电平/低电平），因此采用基数为 2 的计数系统。每一位称为比特（bit），8 比特构成 1 字节（Byte）。
**数值表示边界**：在固定位宽（如 8 位、16 位、32 位）下，数值表示范围是有限的。无符号整数范围为 $[0, 2^n - 1]$，有符号整数（补码）范围为 $[-2^{n-1}, 2^{n-1} - 1]$。超出此范围即发生溢出（Overflow）。
**补码定义**：正数的补码是其本身；负数的补码是其绝对值的二进制表示按位取反后加 1。补码的核心优势在于将减法运算转化为加法运算，简化硬件设计。

## 机制与步骤
### 1. 十进制转二进制（整数部分）
采用“除 2 取余，逆序排列”法。
步骤：
1. 将十进制数除以 2，记录余数。
2. 将商继续除以 2，记录余数。
3. 重复直至商为 0。
4. 将余数从下往上排列。

### 2. 二进制转十进制
采用“按权展开求和”法。
公式：$N = \sum_{i=0}^{n-1} b_i \times 2^i$，其中 $b_i$ 为第 $i$ 位的值。

### 3. 负数补码计算（以 8 位为例）
步骤：
1. 写出该负数绝对值的二进制原码。
2. 对所有位按位取反（0 变 1，1 变 0）。
3. 结果加 1。
4. 最高位（符号位）自然变为 1。

## 完整示例
**任务**：在 8 位系统中表示十进制数 -13。
1. **绝对值二进制**：$13 = 8 + 4 + 1$，即 `0000 1101`。
2. **按位取反**：`1111 0010`。
3. **末位加 1**：`1111 0010` + `0000 0001` = `1111 0011`。
4. **验证**：`1111 0011` 转十进制。符号位为 1，表示负数。数值部分求补码还原：取反 `0000 1100`，加 1 得 `0000 1101`（即 13）。故结果为 -13。

## 代码实现
以下 Python 代码模拟 8 位有符号整数的补码转换过程：
```python
def to_twos_complement(decimal_num, bits=8):
    if decimal_num < 0:
        # 计算正数部分
        positive = abs(decimal_num)
        # 转换为二进制字符串，去掉 '0b' 前缀，并补零
        bin_str = bin(positive)[2:].zfill(bits)
        # 按位取反
        inverted = ''.join('1' if bit == '0' else '0' for bit in bin_str)
        # 加 1 处理
        result = bin(int(inverted, 2) + 1)[2:].zfill(bits)
        # 截断超出位宽的部分（模拟溢出）
        return result[-bits:]
    else:
        return bin(decimal_num)[2:].zfill(bits)[-bits:]

print(to_twos_complement(-13))  # 输出：11110011
```

## 复杂度与权衡
**空间权衡**：位宽决定了精度与范围。8 位整数范围小但节省内存，64 位整数范围大但消耗更多存储。
**运算权衡**：补码表示法允许 CPU 使用同一套加法电路处理加减法，牺牲了人类直观阅读的便利性（负数二进制不易直接看出数值），换取了硬件效率的提升。
**溢出风险**：固定位宽下，$127 + 1$ 在 8 位有符号数中会变成 $-128$，这是计算思维中必须警惕的边界错误。

## 常见误区
1. **误区一**：认为负数二进制只是最高位变 1。这是“原码”表示法，计算机内部运算不使用原码，因为存在 +0 和 -0 两种零的形式。
2. **误区二**：认为补码取反加一后符号位不变。实际上，补码运算过程中符号位参与运算，自然形成结果符号。
3. **误区三**：忽略位宽限制。脱离位宽谈补码无意义，例如 -1 在 8 位下是 `11111111`，在 16 位下是 `1111111111111111`。

## 自测题与答案
1. **问题**：8 位无符号二进制 `1000 0000` 对应的十进制是多少？
   **答案**：128。
2. **问题**：8 位补码 `1000 0000` 对应的十进制是多少？
   **答案**：-128（这是 8 位有符号数的最小值）。
3. **问题**：为什么计算机不使用原码表示负数？
   **答案**：原码存在两个零（+0 和 -0），且减法电路复杂，需要额外的符号判断逻辑。
