## 概念与边界
**分治法（Divide and Conquer）** 是一种算法设计范式，其核心是将一个复杂问题分解为若干个规模较小的相同问题，递归求解后再合并结果。它适用于具备“最优子结构”且子问题独立的问题。
**边界界定**：分治法不同于减治法（如二分查找只处理一侧），分治通常需要处理所有子问题。归并排序与快速排序是分治策略在排序问题上的典型应用，但二者在“分解”与“合并”的侧重上截然不同。

## 机制与步骤
**归并排序（Merge Sort）** 侧重于“合”。
1. **分解**：将数组从中间划分为两个子数组。
2. **解决**：递归地对子数组进行排序。
3. **合并**：将两个有序子数组合并为一个有序数组。
**快速排序（Quick Sort）** 侧重于“分”。
1. **分解**：选取基准值（Pivot），将数组划分为小于基准和大于基准的两部分。
2. **解决**：递归地对两部分进行排序。
3. **合并**：无需显式合并，分区操作已完成排序。

## 完整示例
假设待排序数组为 $[3, 1, 4, 1, 5]$。
**归并排序过程**：
1. 分解：$[3, 1]$ 和 $[4, 1, 5]$。
2. 递归分解至单个元素，如 $[3]$ 和 $[1]$。
3. 合并：$[1, 3]$ 与 $[1, 4, 5]$ 合并。比较首位，1 小于 1（视稳定性策略），最终得 $[1, 1, 3, 4, 5]$。
**快速排序过程**（设基准为首元素）：
1. 分区：基准 3。小于 3 的 $[1, 1]$，大于 3 的 $[4, 5]$。
2. 递归：对 $[1, 1]$ 排序得 $[1, 1]$；对 $[4, 5]$ 排序得 $[4, 5]$。
3. 组合：$[1, 1] + [3] + [4, 5]$ 得 $[1, 1, 3, 4, 5]$。

## 代码实现
```python
def merge_sort(arr):
    if len(arr) <= 1: return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result = []
    while left and right:
        if left[0] <= right[0]: result.append(left.pop(0))
        else: result.append(right.pop(0))
    result.extend(left if left else right)
    return result
```
快速排序代码略，重点在于 `partition` 函数的原地交换逻辑。

## 复杂度与权衡
| 特性 | 归并排序 | 快速排序 |
| :--- | :--- | :--- |
| 平均时间 | $O(n \log n)$ | $O(n \log n)$ |
| 最坏时间 | $O(n \log n)$ | $O(n^2)$ |
| 空间复杂度 | $O(n)$ | $O(\log n)$ (递归栈) |
| 稳定性 | 稳定 | 不稳定 |
| 适用场景 | 外部排序、要求稳定 | 内部排序、内存敏感 |

归并排序的递归式为 $T(n) = 2T(n/2) + O(n)$，根据主定理可得 $O(n \log n)$。快速排序最坏情况发生在每次划分极不平衡时（如数组已有序且选首元素为基准）。

## 常见误区
1. **基准选择**：快速排序固定选第一个元素作为基准在有序数组下会退化。应使用随机基准或三数取中法。
2. **递归终止**：忘记处理长度为 0 或 1 的数组会导致无限递归。
3. **稳定性混淆**：误认为快速排序是稳定的。实际上分区交换过程会改变相同元素的相对位置。
4. **空间消耗**：忽视归并排序需要额外 $O(n)$ 辅助空间，在内存受限嵌入式系统中需谨慎。

## 自测题与答案
1. **问**：若数组长度为 $n$，归并排序最多需要进行多少次合并操作？
   **答**：$n-1$ 次（每次合并减少一个子序列）。
2. **问**：快速排序在最坏情况下的时间复杂度是多少？触发条件是什么？
   **答**：$O(n^2)$。条件是每次划分都极不平衡，例如数组已有序且基准选在端点。
3. **问**：为什么归并排序适合链表排序？
   **答**：链表插入操作为 $O(1)$，归并排序不需要随机访问，且可避免数组归并时的额外空间拷贝。
