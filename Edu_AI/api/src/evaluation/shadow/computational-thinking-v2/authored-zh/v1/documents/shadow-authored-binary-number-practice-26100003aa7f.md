## 学习目标
1. 能够在真实数据流中识别二进制编码格式。
2. 应用补码知识解析传感器传来的有符号原始数据。
3. 设计测试用例验证数据解析程序的边界处理能力。
4. 评估数据转换过程中的精度损失与溢出风险。

## 真实问题情境
某物联网团队开发了一款工业温度传感器，该传感器通过串口每秒发送一次数据。数据包格式为固定 2 字节（16 位）的有符号整数，采用大端序（Big-Endian），单位为 0.1 摄氏度。例如，发送 `00 64` 表示 $100 \times 0.1 = 10.0^\circ C$。然而，现场工程师发现当环境温度低于零度时，接收端软件显示的数值异常巨大（如显示 65535），导致报警系统误触发。你需要修正数据解析逻辑，确保负温正确显示。

## 输入输出或材料
**输入材料**：
1. 十六进制数据流字符串，如 `"FF9C"`。
2. 数据位宽定义：16 位有符号整数。
3. 比例因子：0.1。

**预期输出**：
1. 正确的十进制温度值（浮点数），如 `-10.0`。
2. 异常状态报告（如发生溢出或数据格式错误）。

## 分步任务
1. **数据解析**：将十六进制字符串转换为 16 位二进制序列。
2. **符号判断**：检查最高位（第 15 位）是否为 1。
3. **数值还原**：若最高位为 1，按照补码规则还原为负数；否则直接转换。
4. **单位换算**：将整数结果乘以 0.1 得到实际温度。
5. **边界检查**：判断数据是否超出传感器物理极限（如 -50.0 至 150.0）。

## 参考实现/推导
以下 Python 函数模拟嵌入式网关的数据处理逻辑：
```python
import struct

def decode_temperature(hex_string):
    try:
        # 将 hex 字符串转为字节
        data_bytes = bytes.fromhex(hex_string)
        if len(data_bytes) != 2:
            return None, "Error: Invalid length"
        
        # 使用 struct  unpack 解析有符号短整数 ('>h' 表示大端有符号 16 位)
        # 这里直接利用语言特性处理补码，若手动实现需按位运算
        raw_int = struct.unpack('>h', data_bytes)[0]
        
        # 应用比例因子
        temperature = raw_int * 0.1
        
        # 边界检查
        if temperature < -50.0 or temperature > 150.0:
            return temperature, "Warning: Out of physical range"
            
        return temperature, "OK"
    except Exception as e:
        return None, f"Error: {str(e)}"

# 测试用例
print(decode_temperature("FF9C"))  # 预期 -10.0
print(decode_temperature("03E8"))  # 预期 100.0
```
**手动推导验证（针对 FF9C）**：
1. `FF9C` 二进制：`1111 1111 1001 1100`。
2. 最高位为 1，确认为负数。
3. 求补码还原：取反得 `0000 0000 0110 0011`，加 1 得 `0000 0000 0110 0100`。
4. 二进制 `0110 0100` 等于十进制 $64 + 32 + 4 = 100$。
5. 加上符号为 -100，乘以 0.1 得 -10.0。

## 测试与边界情况
为确保系统鲁棒性，必须覆盖以下测试场景：
1. **零值测试**：输入 `0000`，预期输出 `0.0`。验证零的补码表示唯一性。
2. **正数边界**：输入 `7FFF`（16 位有符号最大值 32767），预期 `3276.7`。
3. **负数边界**：输入 `8000`（16 位有符号最小值 -32768），预期 `-3276.8`。此案例常因误用无符号解析而出错。
4. **溢出模拟**：若传感器故障发送 `FFFF`，解析为 -1，温度 -0.1，需结合物理范围判断是否合理。
5. **格式错误**：输入 `123`（奇数位）或 `GG00`（非法字符），程序应捕获异常而非崩溃。

## 拓展问题
1. **浮点数表示**：如果传感器直接传输 IEEE 754 标准的 32 位浮点数，解析逻辑应如何调整？这与定点数表示有何优劣？
2. ** endian 问题**：若传感器改为小端序（Little-Endian），输入 `9C FF` 代表什么数值？如何在代码中适配不同架构？
3. **精度损失**：使用整数乘以 0.1 表示小数，在多次累加运算后是否会产生误差？如何避免？（提示：考虑定点数运算策略）。
