## 真实问题情境
某实验室保险柜采用电子锁系统，为了防止单人舞弊，设计了多重授权机制。系统有三个密钥传感器：管理员密钥（$M$）、操作员密钥 1（$K1$）、操作员密钥 2（$K2$）。
**开锁规则**：
1.  必须插入管理员密钥 $M$。
2.  在此基础上，至少还需要插入一把操作员密钥（$K1$ 或 $K2$）。
3.  若只插入操作员密钥而无管理员密钥，触发警报但不开锁。
本任务要求设计控制逻辑，输出“开锁信号”（$Open$）和“警报信号”（$Alarm$）。

## 输入输出或材料
*   **输入**：三个布尔变量 $M, K1, K2$（1 表示插入，0 表示未插入）。
*   **输出**：两个布尔变量 $Open$（1 开，0 关），$Alarm$（1 警报，0 正常）。
*   **材料**：Python 编程环境，逻辑推导草稿纸。

## 分步任务
1.  **逻辑抽象**：根据规则写出 $Open$ 和 $Alarm$ 的自然语言逻辑描述。
2.  **真值表构建**：列出 3 个输入变量的所有 8 种组合，填写期望输出。
3.  **表达式生成**：写出布尔表达式，并尝试化简。
4.  **代码实现**：编写一个类 `VaultController`，包含 `check_status` 方法。
5.  **测试验证**：设计测试用例覆盖所有分支。

## 参考实现与推导
**逻辑推导**：
*   $Open$ 条件：$M$ 为真 且 ($K1$ 或 $K2$ 为真)。
    表达式：$Open = M \land (K1 \lor K2)$
*   $Alarm$ 条件：($K1$ 或 $K2$ 为真) 且 $M$ 为假。
    表达式：$Alarm = (K1 \lor K2) \land \neg M$

**Python 参考代码**：
```python
class VaultController:
    def __init__(self):
        pass
    
    def check_status(self, m, k1, k2):
        # 强制转换为布尔值以防输入整数 2 等异常情况
        m, k1, k2 = bool(m), bool(k1), bool(k2)
        
        open_signal = m and (k1 or k2)
        alarm_signal = (k1 or k2) and (not m)
        
        return int(open_signal), int(alarm_signal)

# 实例化与测试
vc = VaultController()
# 测试用例：管理员 + 操作员 1
print(vc.check_status(1, 1, 0))  # 期望 (1, 0)
# 测试用例：仅操作员 1
print(vc.check_status(0, 1, 0))  # 期望 (0, 1)
```

## 测试与边界情况
为确保系统安全，必须测试以下边界情况：
1.  **全空状态**：$M=0, K1=0, K2=0$。期望：$Open=0, Alarm=0$。系统应静默。
2.  **全满状态**：$M=1, K1=1, K2=1$。期望：$Open=1, Alarm=0$。权限充足时不应警报。
3.  **非法输入类型**：如果输入不是 0/1 而是字符串或负数，代码应具备健壮性（参考实现中使用了 `bool()` 转换）。
4.  **单操作员误触**：仅 $K1=1$ 而无 $M$。这是主要的攻击场景，必须触发警报。

## 评价量规
| 维度 | 优秀 (5 分) | 良好 (3 分) | 需改进 (1 分) |
|---|---|---|---|
| **逻辑正确性** | 真值表与表达式完全符合需求，无逻辑漏洞。 | 主要功能正确，但边界情况（如全满）处理有误。 | 核心逻辑错误，无法正确开锁或误报。 |
| **代码质量** | 封装良好，有类型检查，变量命名清晰。 | 能运行但缺乏封装，硬编码严重。 | 代码无法运行或语法错误频发。 |
| **测试覆盖** | 覆盖所有 8 种输入组合及异常输入。 | 仅覆盖正常开锁情况，未测试警报逻辑。 | 无测试代码或仅测试了一种情况。 |

## 拓展问题
1.  **时序影响**：如果管理员密钥 $M$ 比操作员密钥 $K1$ 晚插入 0.1 秒，系统会短暂触发警报吗？这在实际硬件中如何解决？（提示：引入延时电路或时序逻辑）。
2.  **扩展性**：若操作员增加到 10 人，逻辑表达式会变得复杂吗？如何用编程结构（如循环）代替硬编码的逻辑门连接？
3.  **安全性**：如果攻击者通过功耗分析监测电路状态，能否推断密钥组合？这引出了侧信道攻击的概念，说明纯逻辑设计不足以保障物理安全。
