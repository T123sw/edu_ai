4. 识别并避免常见的作用域与副作用错误。

## 准确概念与边界
**函数（Function）** 在计算思维中具有两层含义。数学上，它是集合 $X$ 到集合 $Y$ 的映射 $f: X \rightarrow Y$，强调确定性，即相同输入必得相同输出。编程中，函数是封装特定逻辑的可复用代码块，包含函数名、参数列表、函数体和返回值。

**接口（Interface）** 此处指函数的“契约”。它规定了调用者需要提供什么（参数类型、含义、前置条件）以及能获得什么（返回值类型、含义、后置条件），而不暴露内部实现细节。接口是模块间通信的唯一合法通道。

**模块化（Modularization）** 是将复杂系统分解为独立、可管理单元的过程。其核心边界在于“高内聚、低耦合”。内聚指模块内部元素联系紧密，耦合指模块间依赖程度低。模块化不等于简单的代码拆分，若拆分后模块间依赖混乱，反而增加复杂度。

## 机制与步骤
函数调用的底层机制涉及栈帧管理。当主程序调用函数时，系统执行以下步骤：
1. **压栈**：将当前执行位置、局部变量保存入调用栈。
2. **传参**：将实参的值或引用复制给形参。
3. **执行**：跳转至函数体执行逻辑。
4. **返回**：将返回值传回调用处，弹出栈帧，恢复现场。

数据流遵循“输入 - 处理 - 输出”模型。理想情况下，函数应通过返回值传递结果，而非修改全局变量。设函数 $f$ 的状态空间为 $S$，输入为 $x$，输出为 $y$，纯函数满足 $y = f(x)$ 且 $S_{after} = S_{before}$。

## 完整例子
以下代码对比了“过程式堆砌”与“模块化设计”的区别。任务：计算多个圆的面积之和。

```python
#  bad 设计：逻辑耦合，难以测试
radius_list = [1.0, 2.0, 3.0]
total_area = 0
PI = 3.14159
for r in radius_list:
    area = PI * r * r
    total_area += area
print(total_area)

# good 设计：模块化，接口清晰
def calculate_circle_area(radius):
    """计算单个圆面积，接口契约：输入非负浮点数，返回浮点数"""
    if radius < 0:
        raise ValueError("半径不能为负")
    return 3.14159 * radius ** 2

def sum_areas(radius_list):
    """计算面积总和，依赖 calculate_circle_area"""
    return sum(calculate_circle_area(r) for r in radius_list)

# 主程序
if __name__ == "__main__":
    data = [1.0, 2.0, 3.0]
    result = sum_areas(data)
    print(f"总面积：{result}")
```
Good 设计中，`calculate_circle_area` 是独立模块，可单独测试。`sum_areas` 通过接口调用它，无需知道面积公式的具体实现。

## 复杂度与权衡
模块化引入了一定的**调用开销**（函数压栈出栈的时间成本），但在现代计算机上通常可忽略。主要的权衡在于**抽象泄漏**与**过度设计**。
- **过度模块化**：将一个简单公式拆分为五个函数，导致阅读跳转成本高于逻辑理解成本。
- **抽象泄漏**：模块接口暴露了内部实现细节（如返回内部数据结构引用），导致调用者依赖内部状态，一旦内部修改，外部全部崩溃。

权衡原则：当一段逻辑被复用超过两次，或逻辑复杂度使得单函数超过 50 行时，应考虑模块化。

## 常见误区
1. **打印即返回**：在函数内使用 `print` 输出结果而非 `return`。这导致结果无法被后续计算使用，违背了数据流原则。
2. **隐式依赖**：函数内部直接读取全局变量而非通过参数传入。这使得函数行为依赖外部环境，不可预测。
3. **可变参数陷阱**：使用可变对象（如列表）作为默认参数，导致多次调用间状态污染。

## 自测题与答案
1. **问**：为什么建议函数通过返回值传递结果，而不是修改全局变量？
   **答**：返回值使数据流显式化，便于追踪调试；修改全局变量产生副作用，导致模块间耦合，难以并行开发或测试。
2. **问**：若函数 $f(x)$ 内部调用了随机数生成器，它还是纯函数吗？
   **答**：不是。纯函数要求相同输入必得相同输出，随机性破坏了这一确定性。
3. **问**：模块化设计的核心指标是什么？
   **答**：高内聚（模块内部功能相关性强）与低耦合（模块间依赖少）。
