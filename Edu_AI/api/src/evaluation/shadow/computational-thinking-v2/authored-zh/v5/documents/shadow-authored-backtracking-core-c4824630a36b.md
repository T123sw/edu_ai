## 学习目标
1. 理解回溯搜索（Backtracking）作为深度优先搜索（DFS）在解空间树上的系统性枚举本质。

3. 能够手写回溯算法框架，并针对具体问题设计有效的剪枝策略。

## 准确概念与边界
回溯搜索是一种通过尝试分步选择来构建解决方案的算法。当发现当前步骤的选择无法导致有效解时，算法取消上一步的选择（即“回溯”），尝试其他可能性。其核心载体是**状态空间树（State Space Tree）**，树的每一层代表一个决策阶段，每一条路径代表一个候选解。

**边界界定**：
- **与穷举的区别**：回溯是“有组织的穷举”，通过剪枝避免无效搜索，而纯穷举遍历所有组合。
- **与贪心的区别**：贪心算法在每一步做出局部最优选择且不回退；回溯允许回退修正错误决策。
- **与动态规划的区别**：动态规划适用于具有重叠子问题和最优子结构的问题；回溯适用于解空间离散且需找出所有解或特定解的问题，通常无重叠子问题优化。

## 机制与步骤
回溯算法的标准执行流程包含以下四个步骤：
1. **定义状态**：确定解的向量形式 $(x_1, x_2, ..., x_n)$ 及当前搜索深度。
2. **扩展节点**：按照深度优先策略，生成当前状态的所有可能子节点。
3. **约束检查**：判断当前部分解是否满足约束条件（Constraint Function）。
4. **剪枝或回溯**：
   - 若满足约束且达到目标，记录解。
   - 若满足约束但未达目标，递归进入下一层。
   - 若不满足约束，执行**剪枝**，不再搜索该分支。

数学上，若解空间大小为 $S$，剪枝函数为 $B(x)$，则实际搜索空间 $S' \subseteq S$。理想情况下 $|S'| \ll |S|$。

## 完整示例：子集和问题
**问题描述**：给定正整数集合 $A = \{a_1, a_2, ..., a_n\}$ 和目标值 $T$，找出所有子集，使得子集元素之和等于 $T$。

**状态空间树设计**：
- 根节点：初始状态，和为 0。
- 第 $i$ 层：决策是否选取 $a_i$。
- 分支：左分支表示“选 $a_i$"，右分支表示“不选 $a_i$"。

**剪枝策略**：
1. **约束剪枝**：若当前和 `current_sum` > $T$，则后续无论怎么选都会超标，直接剪枝。
2. **可行性剪枝**：若 `current_sum` + 剩余所有元素之和 < $T$，则即使全选也无法达标，直接剪枝。

## 伪代码与实现
```python
def subset_sum(nums, target):
    res = []
    nums.sort()  # 排序有助于剪枝
    
    def backtrack(start, path, current_sum):
        # 终止条件：找到解
        if current_sum == target:
            res.append(path[:])
            return
        # 剪枝 1：当前和已超过目标
        if current_sum > target:
            return
        
        for i in range(start, len(nums)):
            # 剪枝 2：当前数加上剩余和仍不足（需预计算后缀和，此处简化演示）
            # 若 nums[i] 导致超标，后续更大的数也会超标（因已排序）
            if current_sum + nums[i] > target:
                break 
            
            path.append(nums[i])
            backtrack(i + 1, path, current_sum + nums[i])
            path.pop()  # 回溯状态
            
    backtrack(0, [], 0)
    return res

# 测试
print(subset_sum([2, 3, 5, 7], 10)) 
# 输出：[[3, 7], [2, 3, 5]]
```

## 复杂度与权衡
- **时间复杂度**：最坏情况下为 $O(2^n)$，因为每个元素都有选或不选两种可能。但在强剪枝条件下，平均性能远优于指数级。
- **空间复杂度**：$O(n)$，主要用于递归调用栈和存储当前路径。
- **权衡**：剪枝判断本身需要计算开销。若剪枝条件过于复杂，可能导致“剪枝开销 > 搜索节省开销”，反而降低效率。因此剪枝条件应轻量且高效。

## 常见误区
1. **忘记状态重置**：在递归返回后未恢复现场（如 `path.pop()`），导致后续分支污染。
2. **剪枝逻辑错误**：误将“可能解”当作“无效解”剪掉，导致漏解。
3. **混淆层次**：在循环内回溯与在递归前回溯逻辑混淆，导致状态树结构错误。

## 自测题与答案
1. **问**：回溯算法一定比动态规划慢吗？
   **答**：不一定。对于 NP 完全问题，两者通常都是指数级。但若子问题重叠严重，DP 更优；若需输出所有具体解，回溯更直接。
2. **问**：在子集和问题中，若输入包含负数，上述剪枝策略 `current_sum > target` 是否依然有效？
   **答**：无效。因为负数可能使总和再次降低，不能仅凭当前和超标就剪枝。
3. **问**：回溯法的核心操作是什么？
   **答**：试错与回退（Try and Backtrack）。
