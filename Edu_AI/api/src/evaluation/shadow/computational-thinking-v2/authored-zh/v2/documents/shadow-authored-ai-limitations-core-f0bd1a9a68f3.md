## 概念与边界
智能系统在本课程中特指基于数据驱动的计算模型（如机器学习、深度学习系统）。其核心能力是在特定任务上模拟人类的决策或生成行为，例如图像识别、文本分类或内容生成。必须明确其边界：智能系统不具备意识、情感或真正的理解能力，其表现依赖于训练数据的分布与质量。系统只能在已知任务分布附近有效工作，超出此边界则性能急剧下降。

## 核心机制与局限
智能系统的工作机制通常分为训练与推理两个阶段。训练阶段通过优化算法最小化损失函数，推理阶段则利用 learned 参数处理新输入。在此机制下，存在三大固有局限：
1. **泛化（Generalization）**：指模型在未见过的测试数据上的表现能力。若训练误差低但测试误差高，称为过拟合，意味着泛化能力弱。泛化误差可表示为 $E_{gen} = |E_{test} - E_{train}|$。
2. **幻觉（Hallucination）**：主要出现在生成式系统中。模型基于概率预测下一个 token，而非检索事实库，因此可能生成看似合理但事实错误的内容。这是概率生成机制的必然副产品。
3. **偏差（Bias）**：源于训练数据的社会性偏差或采样偏差。若数据中某群体代表性不足，系统对该群体的判断准确率将显著降低，导致不公平决策。

## 评价体系与公式
评价智能系统需结合定量指标。对于二分类任务，基于混淆矩阵（TP, FP, TN, FN）定义以下指标：
- 准确率（Accuracy）：$Acc = \frac{TP+TN}{TP+TN+FP+FN}$
- 精确率（Precision）：$P = \frac{TP}{TP+FP}$，预测为正的样本中真正的比例。
- 召回率（Recall）：$R = \frac{TP}{TP+FN}$，真正例中被正确预测的比例。
- F1 分数：$F1 = 2 \cdot \frac{P \cdot R}{P + R}$，综合衡量精确率与召回率的调和平均数。

## 示例：垃圾邮件分类
假设一个邮件过滤系统，测试集共 100 封邮件，其中垃圾邮件 20 封（正例），正常邮件 80 封（负例）。系统预测了 25 封为垃圾邮件，其中 15 封确实是垃圾邮件。
- TP = 15, FP = 10 (25-15), FN = 5 (20-15), TN = 70 (80-10)。
- 精确率 $P = 15/25 = 0.6$。
- 召回率 $R = 15/20 = 0.75$。
- F1 分数 $F1 = 2 \cdot \frac{0.6 \cdot 0.75}{0.6 + 0.75} \approx 0.67$。
此例表明系统宁可错杀（FP）也不愿放过（FN 较低），但精确度有待提高。

## 代码实现
以下 Python 代码用于计算上述评价指标，依赖 `sklearn` 库，若环境受限可手动实现公式。
```python
from sklearn.metrics import precision_score, recall_score, f1_score, accuracy_score

def evaluate_system(y_true, y_pred):
    acc = accuracy_score(y_true, y_pred)
    pre = precision_score(y_true, y_pred)
    rec = recall_score(y_true, y_pred)
    f1 = f1_score(y_true, y_pred)
    return {"Accuracy": acc, "Precision": pre, "Recall": rec, "F1": f1}

# 模拟数据：1 代表垃圾邮件，0 代表正常
y_true = [1]*20 + [0]*80
y_pred = [1]*15 + [0]*5 + [1]*10 + [0]*70 
# 注意：实际使用时需打乱顺序，此处仅为逻辑演示
print(evaluate_system(y_true, y_pred))
```

## 常见误区
1. **误区一：高准确率等于好系统**。在不平衡数据集中（如欺诈检测），全预测为负例即可获得高准确率，但召回率为 0，系统无用。
2. **误区二：智能系统完全客观**。算法由人设计，数据由人产生，偏差不可避免，需人工干预校正。
3. **误区三：幻觉可以完全消除**。只要基于概率生成，幻觉只能降低无法根除，需通过检索增强生成（RAG）等技术缓解。

## 自测题与答案
1. **问**：为什么生成式模型容易产生幻觉？
   **答**：因为其本质是预测下一个 token 的概率分布，目标是语句通顺而非事实真实，缺乏外部事实校验机制。
2. **问**：在医疗诊断中，应更关注精确率还是召回率？
   **答**：应更关注召回率。漏诊（FN）的代价远高于误诊（FP），需尽可能找出所有患病者。
3. **问**：泛化能力差的直接表现是什么？
   **答**：训练集表现优异，但测试集或实际应用场景中性能大幅下降。
