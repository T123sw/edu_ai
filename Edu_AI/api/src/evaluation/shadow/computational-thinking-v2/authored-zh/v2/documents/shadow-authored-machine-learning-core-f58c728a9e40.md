## 学习目标
本讲义旨在帮助学生建立机器学习工程化落地的宏观视角。学习完成后，学生应能：
1. 准确复述机器学习的标准工作流程，区分训练集、验证集与测试集的功能边界。
2. 辨析分类任务与回归任务在流程中的差异点（主要是输出形式与评估指标）。
3. 理解模型训练中的过拟合现象及其与验证机制的关系。

## 准确概念与边界
机器学习（Machine Learning, ML）并非魔法，而是一个基于数据优化数学函数参数的过程。其核心边界在于：传统编程是“规则 + 数据 -> 答案”，而机器学习是“数据 + 答案 -> 规则”。在本知识点中，我们关注的是“基本流程”，不涉及具体的神经网络架构或深层数学推导。

关键概念界定：
- **训练（Training）**：模型通过算法读取训练数据，调整内部参数以最小化误差的过程。
- **验证（Validation）**：使用未参与训练的数据评估模型表现，用于调整超参数（如学习率、树深度），防止模型死记硬背。
- **分类（Classification）**：输出为离散类别标签（如“垃圾邮件”/“正常邮件”）。
- **回归（Regression）**：输出为连续数值（如“房价”、“温度”）。

## 机制与步骤
标准机器学习流程包含以下闭环步骤：

1. **数据收集与预处理**：清洗缺失值，标准化数值特征，编码类别特征。
2. **数据集划分**：通常将数据划分为训练集（约 60-80%）、验证集（约 10-20%）和测试集（约 10-20%）。注意：测试集必须在整个开发过程中“不可见”，仅用于最终评估。
3. **模型选择**：根据任务类型选择算法。分类任务常用逻辑回归、支持向量机；回归任务常用线性回归、决策树回归。
4. **模型训练**：利用训练集数据，通过优化算法（如梯度下降）求解参数 $\theta$。
   对于线性回归，损失函数通常为均方误差（MSE）：
   $$ J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} (h_\theta(x^{(i)}) - y^{(i)})^2 $$
   其中 $h_\theta(x)$ 为预测值，$y$ 为真实值，$m$ 为样本数。
5. **模型验证与调优**：在验证集上评估模型。若训练误差低但验证误差高，说明发生**过拟合**，需增加正则化或减少模型复杂度。
6. **模型测试与部署**：使用测试集得到无偏估计，达标后部署至生产环境。

## 完整示例：房屋价格预测
假设我们要预测房屋价格（回归任务）。
- **输入**：房屋面积、房龄、卧室数量。
- **输出**：价格（万元）。
- **流程**：
  1. 收集 1000 条历史交易数据。
  2. 划分 800 条训练，100 条验证，100 条测试。
  3. 选择线性回归模型。
  4. 训练得到参数：价格 = 0.5 * 面积 - 0.2 * 房龄 + 5 * 卧室。
  5. 验证集发现房龄权重过大导致误差高，调整正则化参数。
  6. 测试集最终误差为 5%，模型上线。

若是垃圾邮件检测（分类任务），流程相同，但输出变为 0 或 1，损失函数变为交叉熵，评估指标变为准确率或 F1 分数。

## 复杂度与权衡
在流程中主要面临**偏差 - 方差权衡（Bias-Variance Tradeoff）**。
- **高偏差（欠拟合）**：模型太简单，训练集和验证集误差都高。解决方法：增加特征、增加模型复杂度。
- **高方差（过拟合）**：模型太复杂，训练集误差低，验证集误差高。解决方法：增加数据量、正则化、简化模型。
验证集的存在正是为了监控方差，确保模型具有泛化能力。

## 常见误区
1. **混淆验证集与测试集**：如果在调参过程中使用了测试集，测试集就变成了验证集，导致最终评估结果过于乐观，失去公正性。
2. **忽视数据分布**：训练集与测试集分布不一致（如训练集全是白天数据，测试集全是夜晚数据），会导致流程失效。
3. **任务类型混淆**：对分类任务使用 MSE 评估，或对回归任务使用准确率评估，这是概念性错误。

## 自测题与答案
1. **问**：为什么不能只用训练集和测试集，而需要验证集？
   **答**：因为超参数调整需要依据评估反馈。若直接用测试集调参，会导致模型间接“记住”测试集特征，丧失对未知数据的泛化评估能力。
2. **问**：预测股票明日收盘价属于分类还是回归？
   **答**：回归。因为收盘价是连续数值。若预测“涨”或“跌”，则属于分类。
3. **问**：过拟合时，训练误差与验证误差的关系通常是？
   **答**：训练误差显著低于验证误差。
