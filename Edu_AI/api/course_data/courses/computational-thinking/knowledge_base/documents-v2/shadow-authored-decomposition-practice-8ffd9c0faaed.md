## 学习目标
1. 能够在真实情境中应用分解策略，识别关键子问题。
2. 通过定义输入输出规范，实践子问题边界的划定。
3. 利用测试用例验证边界条件的健壮性。

## 真实问题情境
某社区需要开发一个“智能停车费计算模块”。规则如下：
- 基础费率：每小时 5 元。
- 昼夜差异：20:00 至次日 8:00 期间半价。
- 封顶规则：单日最高收费 50 元。
- 特殊车辆：电动车免收前 1 小时费用。

直接编写一个包含所有 `if-else` 的函数会导致逻辑混乱，难以维护。我们需要将其分解为独立的计算单元。

## 输入输出或材料
- **输入材料**：车辆入场时间字符串（如 "2023-10-01 14:30"），出场时间字符串，车辆类型（"normal" 或 "ev"）。
- **预期输出**：应收金额（浮点数）。
- **数据结构约定**：时间统一转换为时间戳或标准 datetime 对象进行传递。

## 分步任务
1. **任务一：逻辑分解**。画出流程图，将计费过程划分为“时长计算”、“时段识别”、“费率应用”、“封顶处理”四个子问题。
2. **任务二：接口定义**。为每个子问题编写函数签名（Function Signature），注释明确输入输出类型。
3. **任务三：模块实现**。独立编写每个子问题的代码，确保不访问全局变量。
4. **任务四：集成测试**。编写主程序调用各模块，并针对边界情况设计测试用例。

## 参考实现与推导
以下是基于分解策略的参考代码结构：

```python
from datetime import datetime

def calc_duration(start_str, end_str):
    # 子问题 1：计算原始时长（小时）
    fmt = "%Y-%m-%d %H:%M"
    start = datetime.strptime(start_str, fmt)
    end = datetime.strptime(end_str, fmt)
    return (end - start).total_seconds() / 3600

def is_night_period(start_time, end_time):
    # 子问题 2：判断是否跨越夜间优惠时段（简化逻辑：仅判断开始时间）
    # 边界定义：返回布尔值或夜间小时数
    hour = start_time.hour
    return 20 <= hour or hour < 8

def calc_base_fee(duration, vehicle_type):
    # 子问题 3：根据时长和车型计算基础费用
    rate = 5.0
    if vehicle_type == "ev" and duration <= 1.0:
        return 0.0
    # 此处简化，实际需结合夜间逻辑
    return duration * rate

def apply_cap(fee):
    # 子问题 4：应用封顶规则
    return min(fee, 50.0)

def main_parking_system(start, end, v_type):
    duration = calc_duration(start, end)
    # 注意：此处展示了子问题如何通过接口数据串联
    base = calc_base_fee(duration, v_type) 
    final = apply_cap(base)
    return final
```
*注：实际教学中需引导学生完善夜间逻辑的分解，例如将“夜间时长计算”作为一个独立子问题，而非混入费率计算中。*

## 测试与边界情况
分解后的模块便于单独测试。需重点验证边界条件：
1. **时长边界**：停车 0 小时、0.5 小时、刚好 1 小时（电动车免费边界）。
2. **时间边界**：入场时间 19:59 与 20:00 的费用差异。
3. **封顶边界**：计算费用为 49 元与 51 元时的最终输出。

| 测试用例 ID | 输入 (时长，车型) | 预期输出 | 测试子问题 |
| :--- | :--- | :--- | :--- |
| T01 | 0.5h, normal | 2.5 | calc_base_fee |
| T02 | 1.0h, ev | 0.0 | calc_base_fee (边界) |
| T03 | 12h, normal | 50.0 | apply_cap (边界) |
| T04 | 20:00 入场 | 触发半价逻辑 | is_night_period |

## 评价量规
| 维度 | 优秀 (5 分) | 合格 (3 分) | 待改进 (1 分) |
| :--- | :--- | :--- | :--- |
| **分解合理性** | 子问题功能单一，无逻辑重叠 | 存在少量功能耦合 | 模块间逻辑混乱，难以区分 |
| **接口清晰度** | 参数类型明确，无隐式依赖 | 部分参数含义模糊 | 依赖全局变量或外部状态 |
| **边界处理** | 覆盖所有关键边界测试用例 | 覆盖主要功能路径 | 未考虑边界情况，易报错 |
| **代码规范** | 函数命名清晰，注释完整 | 命名一般，注释较少 | 命名随意，无注释 |

## 拓展问题
1. 若规则变更为“阶梯计价”（前 1 小时 5 元，之后每小时 3 元），哪个子问题需要修改？是否影响其他子问题？
   *提示：应仅修改 `calc_base_fee`，验证分解的独立性。*
2. 如果需要支持多种货币结算，如何在分解结构中增加“货币转换”子问题？它应位于哪个边界之前？
3. 尝试将“夜间时段判断”细化为精确计算夜间小时数，而非简单布尔值，重新定义该子问题的输入输出接口。
