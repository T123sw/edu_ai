## 学习目标
本讲义旨在帮助学生掌握基础排序算法的核心机制及其稳定性特征。学习完成后，学生应能够：准确复述排序稳定性的数学定义；手动模拟冒泡、选择、插入排序的执行过程；判断给定排序实现的稳定性；理解不同算法在时间复杂度与稳定性之间的权衡；识别并纠正常见的稳定性误区。

## 准确概念与边界
排序是将无序序列调整为有序序列的过程。设序列中存在两个元素 $a_i$ 和 $a_j$，若在排序前 $i < j$ 且 $a_i = a_j$，排序后 $a_i$ 仍然位于 $a_j$ 之前，则称该排序算法是**稳定**的。反之，若相等元素的相对位置可能发生交换，则为**不稳定**。

稳定性是算法的固有属性，而非数据的属性。边界情况包括：所有元素均相等（稳定算法应保持原序）、所有元素均不等（稳定性无影响）、空序列或单元素序列（天然有序）。稳定性在处理多关键字排序时至关重要，例如先按次要关键字排序，再按主要关键字排序，若第二次排序稳定，则最终结果同时满足两个关键字的有序性。

## 机制与步骤
1. **冒泡排序**：重复遍历序列，比较相邻元素。若前者大于后者则交换。每一轮将当前最大元素“浮”至末尾。若比较条件严格为 `>` 而非 `>=`，则相等元素不交换，算法稳定。
2. **选择排序**：每轮从未排序部分选出最小元素，与该部分首元素交换。即使实现正确，交换操作可能跨越相等元素，导致相对位置改变，故通常不稳定。
3. **插入排序**：将当前元素插入已排序序列的适当位置。通过向后移动大于当前值的元素腾出空间，相等元素不移动，故算法稳定。

## 完整例子
考虑序列 $S = [5, 2_a, 2_b, 1]$，其中 $2_a$ 和 $2_b$ 值相等但初始位置不同。
- **冒泡排序**：比较 $2_a$ 与 $2_b$ 时，因 $2_a \ngtr 2_b$，不交换。最终顺序仍为 $2_a, 2_b$。稳定。
- **选择排序**：第一轮选最小值 $1$，与首位 $5$ 交换，序列变 $[1, 2_a, 2_b, 5]$。第二轮选最小值 $2_a$，与首位 $2_a$ 交换（无变化）。若在另一场景 $[2_a, 5, 2_b, 1]$，第一轮 $1$ 与 $2_a$ 交换，序列变 $[1, 5, 2_b, 2_a]$，此时 $2_b$ 跑到了 $2_a$ 前面。不稳定。
- **插入排序**：处理 $2_b$ 时，已排序部分为 $[2_a, 5]$。因 $2_b \ngtr 2_a$，插入到 $2_a$ 之后。最终顺序 $2_a, 2_b$。稳定。

## 代码实现
```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(0, n-i-1):
            if arr[j] > arr[j+1]:  # 严格大于，保证稳定性
                arr[j], arr[j+1] = arr[j+1], arr[j]
    return arr

def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        min_idx = i
        for j in range(i+1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]  # 交换可能破坏稳定性
    return arr

def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and key < arr[j]:  # 小于才移动，相等停止，保证稳定性
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr
```

## 复杂度与权衡
三种算法的平均与最坏时间复杂度均为 $O(n^2)$，空间复杂度为 $O(1)$。
- **冒泡**：代码简单，但交换次数多，实际性能通常最差。适用于几乎有序的序列。
- **选择**：交换次数最少（最多 $n$ 次），但比较次数固定。适用于写入成本高的场景，但牺牲了稳定性。
- **插入**：在序列基本有序时效率接近 $O(n)$。稳定且原地，是简单排序中综合性能最好的，常作为高级排序（如快速排序）的子过程。

## 常见误区
1. **误区一**：“只要相等时不交换就是稳定的。”
   **纠正**：选择排序即使比较时不交换，最后的 swap 操作也可能破坏稳定性。
2. **误区二**：“稳定性可以通过修改代码轻易修复。”
   **纠正**：选择排序的交换机制决定了其本质不稳定，强行修复需增加额外空间或逻辑，失去原地排序优势。
3. **误区三**：“数据量小时不需要考虑稳定性。”
   **纠正**：若业务逻辑依赖原始顺序（如排队系统），即使数据量小，不稳定排序也会导致逻辑错误。

## 自测题与答案
1. **问**：若将插入排序的 `while` 条件改为 `key <= arr[j]`，算法是否仍稳定？
   **答**：不稳定。相等时会继续移动，导致后出现的相等元素跑到前面。
2. **问**：序列 $[3, 3, 2]$ 经选择排序后，两个 $3$ 的相对位置会变吗？
   **答**：会变。第一轮最小值 $2$ 会与第一个 $3$ 交换，序列变为 $[2, 3, 3]$，原第一个 $3$ 移到了第二个 $3$ 之后。
3. **问**：为何冒泡排序相邻交换能保持稳定性？
   **答**：因为相邻相等元素不会触发交换条件，它们的相对顺序永远不会被逆转。
