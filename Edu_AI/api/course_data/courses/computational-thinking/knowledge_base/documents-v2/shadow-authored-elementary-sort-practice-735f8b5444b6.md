## 学习目标
本案例旨在通过真实情境应用排序稳定性知识。学习完成后，学生应能够：分析多关键字排序需求；设计基于稳定排序的解决方案；编写可验证的代码；处理边界测试数据；依据量规评估实现质量。

## 真实问题情境
某大学教务处需要生成奖学金名单。规则如下：首先按“综合得分”降序排列；若得分相同，则按“学号”升序排列（学号小者优先，代表入学早）。现有数据未排序，且存储在学生对象列表中。系统底层库仅提供一个简单的排序函数，该函数支持自定义比较规则，但为了教学演示，要求使用基础插入排序实现，并利用稳定性特性简化多关键字排序逻辑。

## 输入输出与材料
- **输入**：包含字典的列表，每个字典代表一名学生，键包括 `name` (字符串), `score` (整数), `id` (整数)。
  示例：`[{"name": "A", "score": 90, "id": 102}, {"name": "B", "score": 90, "id": 101}]`
- **输出**：排序后的列表。上述示例应输出 `B` 在前，`A` 在后（因分数相同，学号 101 < 102）。
- **材料**：提供基础插入排序模板，学生需修改比较逻辑或排序策略。

## 分步任务
1. **任务一：策略设计**。分析若直接按“分数降序、学号升序”复合规则排序，代码较复杂。如何利用稳定排序特性，通过两次单次关键字排序达到相同目的？请写出排序顺序。
2. **任务二：代码实现**。编写稳定的插入排序函数。注意：若先按学号升序排，再按分数降序排，第二次排序必须是稳定的，才能保留学号的顺序。
3. **任务三：验证测试**。构造三组测试数据：普通情况、分数全相同情况、分数全不同情况。运行代码并记录结果。

## 参考实现与推导
利用稳定性进行多关键字排序的标准策略是：**先按次要关键字排序，再按主要关键字排序**。
1. 第一次排序：按学号 `id` 升序。此时序列中学号有序。
2. 第二次排序：按分数 `score` 降序。使用**稳定**的插入排序。当分数相等时，插入排序不会改变元素相对位置，因此学号升序得以保留。

```python
def stable_insertion_sort(arr, key_func, reverse=False):
    for i in range(1, len(arr)):
        current = arr[i]
        current_key = key_func(current)
        j = i - 1
        while j >= 0:
            prev_key = key_func(arr[j])
            # 根据 reverse 决定比较方向，相等时不移动以保稳定
            if (not reverse and prev_key > current_key) or \
               (reverse and prev_key < current_key):
                arr[j + 1] = arr[j]
                j -= 1
            else:
                break
        arr[j + 1] = key_func(current) and current or current # 修正赋值
        arr[j + 1] = current
    return arr

# 主逻辑
students = [{"name": "A", "score": 90, "id": 102}, {"name": "B", "score": 90, "id": 101}]
stable_insertion_sort(students, key_func=lambda x: x['id'], reverse=False)
stable_insertion_sort(students, key_func=lambda x: x['score'], reverse=True)
```

## 测试与边界情况
1. **空列表**：输入 `[]`，程序不应报错，返回空列表。
2. **单元素**：输入 `[ {...} ]`，顺序不变。
3. **全同分数**：输入多个分数相同但学号不同的学生，最终顺序应严格按学号升序。这是检验稳定性的关键用例。
4. **逆序对**：输入完全逆序的数据，检查算法是否正确处理最大移动距离。
5. **数据类型错误**：若 `score` 包含非数字，程序应有适当处理或报错提示（本案例假设输入合法）。

## 评价量规
| 维度 | 优秀 (100%) | 合格 (60%) | 待改进 (0%) |
| :--- | :--- | :--- | :--- |
| **稳定性实现** | 两次排序逻辑正确，相等元素绝不交换位置 | 实现了排序，但未利用稳定性导致学号顺序混乱 | 无法完成排序或代码无法运行 |
| **代码规范** | 函数命名清晰，有注释，变量语义明确 | 代码可运行，但命名随意，无注释 | 代码结构混乱，难以阅读 |
| **测试覆盖** | 包含边界测试，有断言验证结果正确性 | 仅测试了普通情况，无边界测试 | 无测试代码或测试用例无效 |
| **问题分析** | 能清晰解释为何先排学号后排分数 | 能完成代码但无法解释原理 | 策略错误，试图一次排序解决 |

## 拓展问题
1. 若数据量达到百万级，无法一次性装入内存，上述原地插入排序是否适用？若不适用，应思考何种排序策略（提示：外部排序）。
2. 若要求三次关键字排序（分数、学号、姓名），需要进行几次稳定排序？顺序如何？
3. 尝试修改代码，若检测到数据已基本有序，如何优化插入排序的性能（提示：提前终止或二分查找插入位置）？
4. 如果底层提供的排序函数是不稳定的（如快速排序），上述“多次排序”策略是否依然有效？为什么？
