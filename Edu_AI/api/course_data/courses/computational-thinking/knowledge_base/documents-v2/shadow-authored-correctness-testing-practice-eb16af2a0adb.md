## 学习目标
本实践环节要求学生在真实业务情境中应用测试与调试技术。学生需能够识别需求中的边界条件，编写覆盖关键路径的测试用例，并通过调试工具定位逻辑缺陷。重点在于培养“防御性编程”意识与系统化排错能力。

## 真实问题情境
某电商平台正在开发“阶梯运费计算模块”。规则如下：
- 订单金额 $< 50$ 元：运费 10 元。
- $50 \le$ 订单金额 $< 100$ 元：运费 5 元。
- 订单金额 $\ge 100$ 元：免运费。
- 特殊规则：若订单包含“易碎品”标记，无论金额多少，运费额外增加 5 元。
- 输入金额必须为非负数。

开发团队提交了一个初始版本，但测试人员反馈在特定金额下运费计算错误。你的任务是验证代码、找出缺陷并完善测试集。

## 输入输出与材料
- **输入**：`amount` (浮点数，订单金额), `is_fragile` (布尔值，是否易碎)。
- **输出**：`shipping_fee` (浮点数，最终运费)。
- **初始代码材料**：
```python
def calculate_shipping(amount, is_fragile):
    if amount < 50:
        fee = 10
    elif amount < 100:
        fee = 5
    else:
        fee = 0
    
    if is_fragile:
        fee += 5
    return fee
```

## 分步任务
1.  **代码审查**：阅读上述代码，找出潜在的逻辑漏洞或边界处理缺失。
2.  **测试设计**：设计至少 5 个测试用例，必须包含正常值、边界值和异常值。
3.  **调试修复**：运行测试，若发现失败，使用打印语句或调试器定位问题，修复代码。
4.  **防御性增强**：增加对负数金额输入的合法性检查。

## 参考实现与推导
**缺陷分析**：初始代码未处理 `amount < 0` 的情况。若输入 `-10`，程序会判定为 `< 50`，收取 10 元运费，这不符合业务逻辑。
**修复后的代码**：
```python
def calculate_shipping(amount, is_fragile):
    if amount < 0:
        raise ValueError("订单金额不能为负数")
    
    if amount < 50:
        fee = 10
    elif amount < 100:
        fee = 5
    else:
        fee = 0
    
    if is_fragile:
        fee += 5
    return float(fee)
```
**推导过程**：首先检查输入合法性（前置条件），然后按照互斥的区间逻辑计算基础运费，最后叠加附加费用。注意浮点数比较在实际金融场景中通常建议使用整数（分）计算以避免精度误差，此处为简化逻辑保留浮点，但需知晓其局限性。

## 测试与边界情况
下表列出了必须通过的测试用例集，用于验证正确性：

| 用例 ID | 输入金额 | 是否易碎 | 预期运费 | 测试类型 | 说明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| T1 | 49.9 | False | 10.0 | 边界值 | 接近第一档上限 |
| T2 | 50.0 | False | 5.0 | 边界值 | 恰好进入第二档 |
| T3 | 99.9 | False | 5.0 | 边界值 | 接近第二档上限 |
| T4 | 100.0 | False | 0.0 | 边界值 | 恰好免运费 |
| T5 | 200.0 | True | 5.0 | 组合测试 | 免运费 + 易碎附加 |
| T6 | -5.0 | False | 报错 | 异常测试 | 负数输入合法性 |

## 评价量规
作业将根据以下标准评分：

| 维度 | 优秀 (90-100) | 合格 (60-89) | 待改进 (<60) |
| :--- | :--- | :--- | :--- |
| **边界覆盖** | 覆盖所有临界点（50, 100, 0）及邻域 | 仅覆盖部分临界点 | 未覆盖临界点，仅测普通值 |
| **调试深度** | 能解释错误根源并提出防御性方案 | 仅修复了表面错误 | 未能修复错误或引入新 bug |
| **测试规范** | 用例表格清晰，包含预期结果与类型 | 有用例但描述模糊 | 无测试用例或无法运行 |
| **代码健壮性** | 包含输入验证与异常处理 | 逻辑正确但无输入验证 | 代码无法运行或逻辑错误 |

## 拓展问题
1.  若金额采用浮点数，`amount = 49.9999999` 在计算机中可能因精度问题被判定为 `50.0` 吗？如何避免？（提示：使用 Decimal 库或转换为整数分）。
2.  如果规则变为“满 100 元减 20 元后再计算运费”，测试用例应如何调整？请列出新的边界值。
3.  尝试编写一个自动化测试脚本，使用 `assert` 语句批量运行上述表格中的用例，并输出测试报告。
