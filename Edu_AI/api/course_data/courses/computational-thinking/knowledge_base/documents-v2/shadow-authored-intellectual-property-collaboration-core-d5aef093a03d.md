## 学习目标
1. 理解著作权（Copyright）的自动保护原则及其在软件中的边界。
2. 区分开源许可（Open Source License）与公共领域（Public Domain）的差异。
3. 掌握主流开源许可证（MIT、Apache-2.0、GPL-3.0）的核心义务与权利。
4. 能够在协作项目中正确声明许可、引用他人代码并处理许可冲突。

## 概念与边界
著作权是知识产权的核心，依据《伯尔尼公约》，作品一旦创作完成并固定于某种有形介质（如保存为代码文件），作者即自动享有著作权，无需登记。在计算思维中，代码既是功能实现工具，也是受法律保护的表达形式。

开源许可是著作权人授予用户的一系列权限。需注意，“开源”不等于“无版权”，也不等于“免费”。开源软件通常保留著作权，仅通过许可证授权他人使用、修改和分发。公共领域（如 CC0）则意味着作者放弃所有权利，任何人都可无条件使用。

边界界定：
- **使用权**：是否允许商业使用？
- **修改权**：是否允许修改源码？
- **分发权**：是否允许再分发？是否必须公开修改后的源码？

## 许可机制与选择步骤
选择许可证是一个权衡过程。设项目依赖集为 $D = \{d_1, d_2, ..., d_n\}$，每个依赖项 $d_i$ 带有许可证 $L_i$。项目最终许可证 $L_{out}$ 必须满足兼容性约束：
$$ L_{out} \in \bigcap_{i=1}^{n} Compatible(L_i) $$
其中 $Compatible(L_i)$ 表示与 $L_i$ 兼容的许可证集合。

选择步骤：
1. **盘点依赖**：列出所有第三方库及其许可证。
2. **确定意图**：希望代码被广泛复用（选宽松许可），还是希望改进回馈社区（选著佐权许可）？
3. **检查兼容性**：确保所选许可证不与依赖项冲突。
4. **声明版权**：在源码头部及根目录添加 LICENSE 文件。

以下是一个符合规范的 Python 模块示例，包含版权声明与许可信息：

```python
def calculate_entropy(data):
    """计算数据熵值"""
    if not data:
        return 0.0
    # 简化实现，实际应引用具体算法库
    total = len(data)
    entropy = 0.0
    for item in set(data):
        p = data.count(item) / total
        if p > 0:
            entropy -= p * (p.__log__(2))
    return entropy

# 引用说明：本函数灵感来源于 Shannon 信息论公式，未直接复制特定库代码
```

## 权衡分析
不同许可证代表不同的协作策略权衡：

| 许可证类型 | 代表许可证 | 商业友好度 | 代码传染性 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| 宽松许可 | MIT, BSD | 高 | 无 | 希望被广泛采用，包括专有软件 |
| 弱著佐权 | LGPL, MPL | 中 | 仅限库文件 | 希望库的改进被开源，但不限制调用者 |
| 强著佐权 | GPL-3.0 | 低 | 强 | 确保衍生作品始终开源，保护社区自由 |

**权衡核心**：宽松许可最大化传播效率，但可能失去对衍生作品的控制；著佐权许可（Copyleft）保护社区协作成果，但可能阻碍商业集成。公式化表达协作成本 $C$：
$$ C = C_{legal} + C_{integration} $$
著佐权许可通常降低 $C_{legal}$（合规清晰），但可能增加 $C_{integration}$（集成限制）。

## 常见误区
1. **“ GitHub 上的代码都能随便用”**：错误。若无明确许可证，默认保留所有权利，擅自使用构成侵权。
2. **“开源就是免费”**：错误。开源指源码可见且可修改，商业分发仍可收费（如提供技术支持）。
3. **“修改少量代码就不算衍生作品”**：风险极高。法律判定基于“实质性相似”，而非行数比例。
4. **“注明出处就可以商用”**：错误。除非许可证明确允许（如 CC-BY），否则注明出处不等同于获得商用授权。

## 自测题与答案
1. **问**：若项目依赖了 GPL-3.0 库，项目能否使用 MIT 许可证发布？
   **答**：不能。GPL 具有传染性，衍生作品必须同样使用 GPL 兼容许可证，MIT 不允许此限制。
2. **问**：著作权保护的是代码的功能还是表达？
   **答**：保护表达（具体代码实现），不保护思想或功能算法。
3. **问**：CC0 协议的主要特点是什么？
   **答**：作者放弃所有著作权，作品进入公共领域，使用者无需署名即可商用。
4. **问**：在协作项目中，提交 PR 前未签署 CLA（贡献者许可协议）可能带来什么风险？
   **答**：可能导致项目维护者无法合法重新许可或分发该贡献，引发法律纠纷。
