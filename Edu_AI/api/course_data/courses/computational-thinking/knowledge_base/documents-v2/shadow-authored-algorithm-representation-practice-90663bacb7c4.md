## 学习目标
本案例通过“个人所得税计算”情境，训练学生运用流程图与伪代码解决实际逻辑问题。学习完成后，学生应能够：
1. 在真实业务场景中提取算法逻辑。
2. 独立设计包含多重分支的算法表示。
3. 依据评价量规自检设计成果，并处理边界测试用例。

## 真实问题情境
某单位需要开发一个简单的个税计算模块。规则如下：
1. 月收入低于 5000 元，免税。
2. 月收入在 5000 至 8000 元之间，超出 5000 部分税率 3%。
3. 月收入高于 8000 元，5000 至 8000 部分税率 3%，超出 8000 部分税率 10%。
请设计算法表示，供程序员后续编码实现。

## 输入输出与材料
- **输入**：员工月收入 `income`（浮点数，单位：元）。
- **输出**：应缴税额 `tax`（浮点数，保留两位小数）。
- **材料**：标准流程图符号表、伪代码关键字规范表。

## 分步任务
1. **逻辑分析**：列出所有收入区间及其对应的计算公式。
2. **流程图绘制**：使用绘图工具或纸笔，绘制包含双重判断结构的流程图。
3. **伪代码编写**：依据流程图逻辑，书写结构化伪代码，注意缩进。
4. **逻辑验证**：手动代入数值验证算法路径是否正确。

## 参考实现与推导
**逻辑推导**：
设税额为 $T$，收入为 $I$。
- 若 $I < 5000$，则 $T = 0$。
- 若 $5000 \le I \le 8000$，则 $T = (I - 5000) \times 0.03$。
- 若 $I > 8000$，则 $T = (3000 \times 0.03) + (I - 8000) \times 0.10$。

**伪代码参考**：
```text
算法 CalculateTax
输入：income
输出：tax
开始
    如果 income < 5000 则
        tax <- 0
    否则 如果 income <= 8000 则
        tax <- (income - 5000) * 0.03
    否则
        tax <- 90 + (income - 8000) * 0.10
    结束如果
    输出 tax
结束
```

## 测试与边界情况
算法设计必须覆盖边界值，以确保鲁棒性。请执行以下测试用例：
1. **正常情况**：`income = 6000`，预期 `tax = 30.00`。
2. **边界情况**：`income = 5000`，预期 `tax = 0.00`。
3. **边界情况**：`income = 8000`，预期 `tax = 90.00`。
4. **异常情况**：`income = -100`，算法应提示输入错误或输出 0（视具体需求定，此处建议增加输入验证）。

在伪代码中增加输入验证步骤：若 `income < 0`，则输出“错误”并终止。

## 评价量规
学生提交的设计方案将依据以下标准评分：

| 维度 | 优秀 (90-100) | 合格 (60-89) | 需改进 (<60) |
| :--- | :--- | :--- | :--- |
| **逻辑正确性** | 所有分支覆盖完整，计算公式无误 | 主要逻辑正确，个别边界遗漏 | 逻辑混乱，公式错误 |
| **规范符合度** | 流程图符号标准，伪代码缩进清晰 | 符号偶有混用，缩进不一致 | 符号错误，无缩进 |
| **可读性** | 变量命名语义化，结构清晰 | 命名一般，结构尚可 | 命名随意，难以阅读 |
| **边界处理** | 主动处理负数等非正常输入 | 仅处理正常输入 | 未考虑边界情况 |

## 拓展问题
1. **规则变更**：若税率调整为阶梯累进制（即不同段落不同税率，而非全额），算法结构需如何调整？请尝试修改伪代码。
2. **多条件组合**：若还需考虑“专项附加扣除”金额 `deduction`，应纳税所得额变为 `income - 5000 - deduction`，请重新设计输入与处理流程。
3. **自动化测试**：思考如何编写一个脚本，自动生成 100 个随机收入值，对比你的算法结果与官方计算器结果，验证一致性。

通过本案例实践，学生应将计算思维从理论认知转化为解决具体工程问题的能力，注重逻辑的严密性与表达的标准性。
