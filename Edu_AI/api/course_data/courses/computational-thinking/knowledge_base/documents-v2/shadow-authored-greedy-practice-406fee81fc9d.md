## 真实问题情境
某自动售货机系统需要设计找零模块。为了提升用户体验并减少硬币磨损，系统目标是使用**最少数量的硬币**完成找零。假设硬币供应充足，给定一组硬币面额体系 $C = \{c_1, c_2, ..., c_n\}$ 和找零金额 $V$，请设计算法计算所需硬币总数。

这是一个典型的优化问题。直觉上，我们应优先使用面额最大的硬币，这正是贪心策略。然而，不同的货币体系（面额组合）会导致贪心策略的有效性不同。本实践将验证这一结论。

## 输入输出与材料
- **输入**：
  1. 硬币面额列表 `coins`（正整数，降序排列），例如 `[10, 5, 1]`。
  2. 找零金额 `amount`（非负整数），例如 `27`。
- **输出**：
  1. 所需硬币总数 `count`。
  2. 各面额硬币使用数量详情 `details`。
  3. 若无法找零（虽本题假设供应充足，但需考虑面额无法整除情况），返回 -1。
- **材料**：Python 编程环境，测试用例表。

## 分步任务
1. **任务一：实现贪心算法**。编写函数 `greedy_change(coins, amount)`，逻辑为：从最大面额开始，尽可能多地使用当前面额，然后处理剩余金额。
2. **任务二：标准体系测试**。使用常见面额 `[10, 5, 1]` 测试金额 `27`，记录结果。
3. **任务三：构造反例**。设计一组非标准面额（如 `[4, 3, 1]`），寻找一个金额，使得贪心算法得出的硬币数多于最优解。
4. **任务四：分析与报告**。解释为何在该反例中贪心失效，并简述若需保证任意面额下最优应采用何种思路（仅简述，不要求实现）。

## 参考实现与推导
```python
def greedy_change(coins, amount):
    if amount < 0:
        return -1, {}
    
    count = 0
    details = {c: 0 for c in coins}
    remaining = amount
    
    for coin in coins:
        if remaining <= 0:
            break
        # 当前面额可用数量
        num = remaining // coin
        details[coin] = num
        count += num
        remaining %= coin
        
    if remaining != 0:
        return -1, details # 无法完全找零
        
    return count, details

# 测试调用
coins_standard = [10, 5, 1]
coins_special = [4, 3, 1]
print(greedy_change(coins_standard, 27)) 
print(greedy_change(coins_special, 6))
```
**推导分析**：
对于 `coins_special = [4, 3, 1]` 和 `amount = 6`：
- **贪心执行**：
  1. 选 4，剩余 2。
  2. 4 不可用，选 3，不可用（2<3）。
  3. 选 1，用 2 个，剩余 0。
  4. 结果：4+1+1，共 3 枚。
- **实际最优**：
  1. 选 3，用 2 个，剩余 0。
  2. 结果：3+3，共 2 枚。
- **结论**：$3 < 3$ 不成立，贪心解（3 枚）劣于最优解（2 枚）。证明贪心策略不适用于该面额体系。

## 测试与边界情况
为确保程序健壮性，需覆盖以下测试场景：

| 测试类型 | 输入 (coins, amount) | 预期行为 | 说明 |
| :--- | :--- | :--- | :--- |
| 正常场景 | `[10, 5, 1]`, 27 | 返回 4 枚 | 10x2 + 5x1 + 1x2 |
| 边界值 | `[10, 5, 1]`, 0 | 返回 0 枚 | 金额为 0 无需找零 |
| 无法找零 | `[5, 2]`, 3 | 返回 -1 | 无面额 1，无法凑整 |
| 贪心失效 | `[4, 3, 1]`, 6 | 返回 3 枚 | 需识别此结果非全局最优 |
| 大数值 | `[100]`, 10000 | 返回 100 枚 | 测试性能与整数溢出 |

**边界分析重点**：
1. **金额为 0**：逻辑是否直接返回 0 而不进入循环。
2. **最小面额 > 1**：当剩余金额小于最小面额时，是否正确报告无法找零。
3. **贪心失效识别**：学生需明白代码返回 3 枚在逻辑上是“贪心解”，但在数学上不是“最优解”，这是算法适用性问题而非代码 Bug。

## 拓展问题
1. **动态规划引入**：若要求在任何面额体系下都能得到最少硬币数，应如何修改算法？提示：考虑记录 `dp[i]` 为金额 `i` 的最少硬币数，状态转移方程为 $dp[i] = \min(dp[i], dp[i-coin] + 1)$。
2. **现实约束**：若每种面额的硬币数量有限（如售货机缺币），贪心策略是否依然适用？若不适用，应如何调整？
