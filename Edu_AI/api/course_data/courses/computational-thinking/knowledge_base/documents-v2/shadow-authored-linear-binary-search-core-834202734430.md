## 概念与边界
查找（Search）是指在数据集合中寻找满足特定条件的目标元素的过程。
**线性查找（Linear Search）**：是最基础的查找方法。它不要求数据有序，从集合的第一个元素开始，逐个比较，直到找到目标或遍历完所有元素。其边界在于数据无序或数据量极小时适用。
**二分查找（Binary Search）**：是一种高效查找算法。其核心前提是**数据集合必须有序**（通常为升序或降序）。它通过不断将查找区间缩小一半来定位目标。其边界在于必须维护数据的有序性，若数据动态频繁插入删除，维护有序的成本可能抵消查找优势。

## 机制与步骤
二分查找体现了“分治法”思想。假设在升序数组 $A$ 中查找目标值 $target$，步骤如下：
1. 初始化指针：$low = 0$, $high = n - 1$。
2. 循环条件：当 $low \le high$ 时执行循环。
3. 计算中点：$mid = \lfloor (low + high) / 2 \rfloor$。
4. 比较与缩小：
   - 若 $A[mid] == target$，查找成功，返回 $mid$。
   - 若 $A[mid] > target$，目标在左半区，令 $high = mid - 1$。
   - 若 $A[mid] < target$，目标在右半区，令 $low = mid + 1$。
5. 若循环结束未返回，则查找失败。

## 完整示例
假设有序数组 $A = [2, 5, 8, 12, 16, 23, 38, 45]$，查找目标 $target = 23$。
| 轮次 | low | high | mid | A[mid] | 比较结果 | 操作 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 0 | 7 | 3 | 12 | $12 < 23$ | $low = 4$ |
| 2 | 4 | 7 | 5 | 23 | $23 == 23$ | 返回 5 |

若查找目标 $target = 10$：
| 轮次 | low | high | mid | A[mid] | 比较结果 | 操作 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 0 | 7 | 3 | 12 | $12 > 10$ | $high = 2$ |
| 2 | 0 | 2 | 1 | 5 | $5 < 10$ | $low = 2$ |
| 3 | 2 | 2 | 2 | 8 | $8 < 10$ | $low = 3$ |
| 4 | 3 | 2 | - | - | $low > high$ | 结束，未找到 |

## 代码实现
```python
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] > target:
            high = mid - 1
        else:
            low = mid + 1
    return -1
```

## 复杂度与权衡
线性查找的最坏情况需要遍历所有 $n$ 个元素，时间复杂度为 $O(n)$。
二分查找每次将问题规模减半，设最坏比较次数为 $k$，则 $n / 2^k = 1$，解得 $k = \log_2 n$。因此时间复杂度为 $O(\log n)$。
**权衡**：当 $n=1000$ 时，线性查找最多需 1000 次比较，而二分查找仅需约 10 次。但二分查找要求数据有序，排序本身通常需要 $O(n \log n)$ 时间。若仅查找一次，先排序再二分可能不如直接线性查找划算；若需多次查找，则二分查找优势巨大。

## 常见误区
1. **无序使用二分**：在未排序数组上使用二分查找会导致结果错误。
2. **死循环**：更新边界时错误地写成 $high = mid$ 或 $low = mid$，导致区间无法缩小。
3. **溢出问题**：在某些语言中，$(low + high)$ 可能整数溢出，建议写作 $low + (high - low) // 2$。
4. **终止条件**：混淆 $low < high$ 与 $low \le high$，前者可能漏掉最后一个元素。

## 自测题
1. 二分查找是否适用于链表结构？为什么？
2. 数组长度为 1024，二分查找最坏情况下需要比较多少次？
3. 若数组中有重复元素，上述代码返回的是哪一个索引？

**答案**：
1. 不适用。二分查找需要随机访问中间元素（$O(1)$），链表访问中间元素需 $O(n)$，失去效率优势。
2. $\log_2 1024 = 10$ 次。
3. 返回任意一个匹配值的索引，不保证是第一个或最后一个。
