# 知识图谱页教材导入复用已存图谱设计

日期：2026-04-22

## 1. 背景

当前知识图谱页左侧“上传教材并解析”按钮始终走教材解析与重建图谱链路。后端在每次导入教材时都会：

- 保存原始教材到课程知识库目录
- 解析教材正文
- 生成新的知识图谱
- 覆盖保存课程知识图谱
- 将教材按章节切分并向量化

这与目标行为不一致。目标行为要求：

- 课程首次上传教材时，根据教材生成知识图谱并保存到后端
- 后续再次上传教材时，不再重建知识图谱
- 后续教材仅按已保存的知识图谱结构做规则匹配与切分归档
- 前端之后读取知识图谱时，始终按后端已保存的知识图谱渲染

右侧“导入到课程总知识库/当前知识点导入”链路已经用于按用户当前选中的节点直接上传资料，不在本次改动范围内。

## 2. 目标

本次改动目标如下：

1. 左侧教材导入支持“首次建图，后续复用图谱”
2. 首次生成的课程知识图谱持久化保存，后续页面加载直接读取该图谱
3. 后续教材导入时，教材切片按已保存知识图谱节点规则匹配归档
4. 匹配失败的切片统一归入课程根节点
5. 保持右侧知识库导入链路不变
6. 保持现有前端接口入口不变，避免页面交互回归

## 3. 非目标

本次不包含以下能力：

- 不引入 LLM 语义分类作为兜底
- 不自动扩充或修改已有知识图谱节点结构
- 不为知识图谱节点增加人工维护别名表
- 不调整右侧“按当前知识点导入”按钮逻辑
- 不改造课程知识图谱编辑器的交互形式

## 4. 现状问题

当前后端 `POST /api/courses/{course_id}/knowledge-graph/textbook-import` 直接调用 `import_textbook_into_knowledge_graph(...)`，该函数每次都会重新构建知识图谱。

同时，教材切分后的文档目前只会写入 `knowledge_base/derived/textbook_graph/...` 目录并送入向量库，不会以课程知识库文档索引的形式挂到具体知识点 `scope_id` 下。因此：

- 后续教材导入无法复用已存图谱
- 课程知识点下看不到这些切分文档
- 知识图谱与教材归档关系未显式落盘到课程知识库索引

## 5. 目标行为

### 5.1 首次教材导入

当课程当前不存在已保存的知识图谱时：

1. 保存原始教材文件
2. 解析教材正文
3. 生成课程知识图谱
4. 保存课程知识图谱到课程存储
5. 根据新生成图谱切分教材
6. 按纯规则将切片归档到匹配的知识点，未命中则归到课程根节点
7. 对归档后的切片执行向量化入库
8. 返回当前生效知识图谱给前端

### 5.2 后续教材导入

当课程已经存在已保存的知识图谱时：

1. 保存原始教材文件
2. 解析教材正文
3. 不再生成或覆盖课程知识图谱
4. 读取当前已保存知识图谱
5. 按已保存知识图谱切分和匹配教材内容
6. 将匹配结果写入课程知识库索引
7. 对切片执行向量化入库
8. 返回当前已保存知识图谱给前端

### 5.3 前端渲染

知识图谱页前端继续通过现有接口读取 `knowledge_graph.root` 并渲染。首次导入后和后续导入后都使用接口返回的当前生效图谱，不再依赖“每次上传都会重建图谱”的隐含假设。

## 6. 方案选择

### 方案 A：每次都用 LLM 重新分类教材切片

优点：

- 语义弹性强

缺点：

- 成本高
- 时延高
- 分类结果易漂移
- 与当前“先完全采用规则”的要求不一致

### 方案 B：纯标题精确匹配

优点：

- 轻量
- 易实现

缺点：

- 对“第1章/第一章/Chapter 1/1.1”等标题格式差异过于敏感

### 方案 C：纯规则归一化匹配

优点：

- 仍是纯规则，无模型成本
- 比原始精确匹配更稳
- 易测试、易解释

缺点：

- 规则覆盖有限，仍会存在未命中内容

### 选型结论

采用方案 C：

- 先做标题归一化
- 再执行纯规则匹配
- 未命中统一落到课程根节点

## 7. 详细设计

### 7.1 接口层

保留现有接口不变：

- `POST /api/courses/{course_id}/knowledge-graph/textbook-import`

这样前端左侧按钮无需修改调用路径，只修改后端行为与返回字段。

### 7.2 服务层分流

对 `import_textbook_into_knowledge_graph(...)` 进行重构，使其内部按“是否已有已保存知识图谱”分流。

新增主流程：

1. 保存原始教材到课程知识库目录
2. 解析教材正文
3. 查询 `manager.get_knowledge_graph(course_id)`
4. 若为空：
   - 执行原有目录抽取与建图流程
   - 保存知识图谱
   - 使用新图谱参与切片归档
5. 若非空：
   - 跳过建图流程
   - 使用现有图谱参与切片归档

### 7.3 教材切片

继续复用现有教材切分能力，输出稳定切片结构。每个切片至少保留：

- `id`
- `title`
- `section_titles`
- `content`
- `file_path`
- `preview`

为避免一次教材在不同流程中出现两个不一致的数据源，规则匹配与正式入库都应基于同一批切片结果。

### 7.4 知识图谱节点遍历

新增一个图谱节点展开步骤，将知识图谱树拍平成可匹配节点表。每个节点记录：

- `node_id`
- `label`
- `normalized_label`
- 是否为课程根节点

课程根节点必须加入可用节点表，并作为最终兜底落点。

### 7.5 纯规则匹配

匹配只采用纯规则，不调用模型。

#### 7.5.1 归一化规则

对教材切片标题和知识图谱节点标题统一执行：

- 去除前后空白
- 统一大小写
- 全角标点转半角或统一清洗
- 去除常见章节编号前缀，例如：
  - `第1章`
  - `第一章`
  - `Chapter 1`
  - `1.1`
  - `（一）`
  - `一、`
- 压缩连续空格

#### 7.5.2 匹配顺序

对每个切片按以下顺序匹配：

1. 使用切片主标题归一化后与节点标题精确匹配
2. 若未命中，则使用 `section_titles` 中的各级标题归一化后依次匹配
3. 若仍未命中，则归入课程根节点

不做模糊匹配，不做子串匹配，不做语义分类。

#### 7.5.3 匹配输出

匹配结果统一输出：

- `matched_scope_type`
- `matched_scope_id`
- `matched_node_label`
- `fallback_to_course_root`

### 7.6 正式归档到课程知识库

这是本次设计和现状最大的行为变化。

当前切片只写入 `knowledge_base/derived/...` 目录并向量化，不会登记为课程知识库文档。本次改为：

1. 切片仍可保留派生目录文件，作为解析中间产物
2. 每个切片额外调用课程知识库存储能力，写入课程知识库索引
3. 写入时根据匹配结果设置：
   - 命中知识点：
     - `scope_type = knowledge_point`
     - `scope_id = matched_node_id`
   - 未命中：
     - `scope_type = course`
     - `scope_id = None`
4. `library_type` 保持 `course`

这样右侧节点资源区和后续基于课程知识库索引的范围查询都能直接读取这些教材切片。

### 7.7 向量化入库

对每个切片在正式归档后继续执行现有 `rag_system.import_document(...)`。

本次不对 RAG 元数据结构做额外扩展要求，范围过滤仍通过课程知识库索引中的 `scope_type/scope_id` 管理前端与业务侧可见范围。

### 7.8 图谱持久化与读取

首次建图后保存到课程知识图谱存储：

- `manager.save_knowledge_graph(course_id, graph)`

后续页面读取仍通过：

- `GET /api/courses/{course_id}/knowledge-graph`

如果课程存在知识图谱，则直接返回该已保存图谱，前端按该图谱渲染。

## 8. 返回结构调整

接口仍返回原有字段，并补充以下信息：

- `graph_reused: boolean`
  - 首次建图时为 `false`
  - 复用已存图谱时为 `true`
- `knowledge_graph`
  - 始终返回当前最终生效图谱
- `split_documents`
  - 每项新增：
    - `matched_scope_type`
    - `matched_scope_id`
    - `matched_node_label`
    - `fallback_to_course_root`
- `import_summary`
  - `total_split_count`
  - `matched_node_count`
  - `fallback_to_course_root_count`
- `warnings`
  - 继续保留

这样前端可以在不改入口的前提下更准确地反馈本次导入结果。

## 9. 前端改动范围

前端只需最小化调整：

- 左侧按钮仍调用 `importTextbookKnowledgeGraph(courseId, file)`
- 成功后继续使用返回的 `knowledge_graph.root` 更新画布
- 可选地读取 `graph_reused` 和 `import_summary` 展示提示文案

右侧“导入到课程总知识库/当前知识点导入”相关逻辑完全不修改。

## 10. 错误处理

需要覆盖以下场景：

- 教材保存失败
- 教材正文解析失败
- 首次建图时建图失败
- 已有图谱但图谱结构非法
- 切片归档失败
- 向量化单个切片失败

处理原则：

- 建图失败时整个左侧导入失败并返回错误
- 切片归档或向量化失败时，优先返回明确错误；如果当前实现已经允许部分成功，则必须在 `warnings` 中给出清晰说明
- 任何情况下都不能在“已有图谱”分支里覆盖现有知识图谱

## 11. 测试设计

至少补充以下测试：

### 11.1 首次教材导入生成图谱

- 课程原本没有知识图谱
- 导入后生成并保存知识图谱
- 返回 `graph_reused = false`
- 切片按新图谱归档

### 11.2 二次教材导入复用图谱

- 课程已有知识图谱
- 再次导入时不再调用建图逻辑
- 返回 `graph_reused = true`
- 返回图谱与已保存图谱一致

### 11.3 规则命中知识点

- 切片标题与某知识点归一化后匹配
- 写入课程知识库索引时 `scope_type = knowledge_point`
- `scope_id` 为对应节点 ID

### 11.4 未命中回落课程根节点

- 切片与所有节点均不匹配
- 写入课程知识库索引时 `scope_type = course`
- `fallback_to_course_root_count` 正确

### 11.5 右侧导入链路无回归

- 现有 `upload_knowledge_base_document` 相关测试保持通过
- 确认按当前知识点上传文件逻辑不受本次改动影响

## 12. 实施计划概要

实现时建议按以下顺序推进：

1. 为左侧教材导入新增测试，覆盖首次建图与后续复用图谱
2. 抽出“图谱节点展开与标题归一化匹配”纯规则函数
3. 重构教材导入主流程，增加“是否已有图谱”分流
4. 将切片正式写入课程知识库索引并保留向量化
5. 调整接口返回结构
6. 运行后端相关测试与前端知识图谱页最小回归验证

## 13. 风险与取舍

主要风险：

- 纯规则匹配覆盖有限，部分教材标题会落到课程根节点
- 同名知识点若在不同分支重复出现，纯标题匹配可能产生歧义
- 现有切片粒度若过粗，单个切片可能同时覆盖多个知识点

本次取舍：

- 先选择轻量、稳定、可解释的规则方案
- 暂不处理同名节点歧义的复杂策略
- 暂不引入模型分类或别名表
- 允许未命中内容先落课程根节点，保证内容不丢失

## 14. 后续可扩展方向

如果后续需要更高命中率，可在本设计上继续扩展：

- 为知识点增加人工别名表
- 引入“规则优先，模型兜底”的混合分类
- 将切片粒度从章节级细化到小节级
- 为未命中内容增加“待归类”视图

当前版本先以“首次建图、后续复用图谱、纯规则归档、根节点兜底”为准。
