这个子图**永远只有三个核心节点**：

#### 🧠 Node 1: Planner (规划者)
* **职责**：大模型的大脑。它纵观全局（用户的要求、已经收集的信息、手里的工具），写出一份包含 N 个步骤的 **JSON 执行计划（Plan）**。

    * 如果信息齐备了，写：`[{"step": 1, "tool": "generate_outline", "args": {...}}]`。

#### 🦾 Node 2: Executor (执行者)
* **职责**：一个纯粹的 Python 机器手。它读取 Planner 写的当前步骤（Current Step），提取对应的 `tool` 和 `args`，**盲目且精准地去执行那个工具**。
* **动作**：执行完毕后，把工具返回的结果（Observation）塞进状态里。

#### 🕵️ Node 3: Reviewer (评估/复盘者)
* **职责**：检查 Executor 刚做完的动作。
* **决策**：
    * **继续**：结果拿到了（比如搜到了资料），标记当前 Step 完成，流转回 `Planner`，让大脑思考下一步。
    * **挂起 (Interrupt)**：如果刚才 Executor 调用的是 `ask_human` 或 `submit_outline_for_review`，图在这里**立刻冻结（Interrupt）**，把提问或大纲推给前端，等待老师输入。老师输入后，状态解冻，继续流转回 `Planner`。
    * **完工**：所有步骤全部执行完毕，报告生成结束。

**内部流转风暴图：**
`Planner` ➡️ `Executor` ➡️ `Reviewer` ➡️ `Planner` ➡️ `Executor` ... (直到任务完成)。

# 1. 定义单个执行步骤的结构 (大模型的计划清单上的每一行)
class PlanStep(TypedDict):
    step_id: str              # 步骤编号，如 "step_1"
    description: str          # 步骤描述，如 "调用 Web 搜索查询 2025 AI 教育现状"

class ReportState(TypedDict):
    # ==========================================
    # 模块 A: 基础通信层 (Input & Output)
    # ==========================================
    messages: Annotated[list[BaseMessage], operator.add] # 存放底层对话消息流
    user_input: str            # 用户当前轮次的输入内容

```python
import json
from typing import Dict, Any, List, Literal
from pydantic import BaseModel, Field
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, END

# --- 引入我们上一轮定义的 ReportState 和 Tools ---
from .report_state import ReportState
from ..tools.agent_tools import (
    ask_human_for_clarification, 
    submit_outline_for_review, 
    analyze_multimodal_content,
    rag_search_tool,
    web_search_tool,
    generate_long_report_content
)

# ==========================================
# 1. 强制大模型输出标准 JSON 的结构体 (Pydantic)
# ==========================================
class PlanStep(BaseModel):
    step_id: int = Field(description="步骤序号，如 1, 2, 3")
    tool_name: str = Field(description="必须是可用工具列表中的一个准确名称")
    tool_args: Dict[str, Any] = Field(description="传给该工具的参数字典")
    description: str = Field(description="简述这一步的思考逻辑和目的")

class Plan(BaseModel):
    steps: List[PlanStep] = Field(description="接下来要执行的步骤清单")

# ==========================================
# 2. 节点 A：大脑 (Planner Node)
# ==========================================
def planner_node(state: ReportState) -> Dict:
    """大脑节点：负责统筹全局，阅读记忆草稿本，制定下一步计划。"""
    
    # 如果已经有计划且没有被打断（或者发生错误需要 replan），则跳过规划直接去执行
    if state.get("plan") and state.get("status") == "executing":
        return {} 
        
    llm = state.get("llm") # 获取你的网关大模型
    user_input = state.get("user_input", "")
    human_feedback = state.get("human_feedback", "")
    context_str = json.dumps(state.get("gathered_context", {}), ensure_ascii=False)
    
    # 【最核心的系统提示词，注入灵魂】
    sys_prompt = f"""你是知识报告生成引擎的【主控大脑(Planner)】。
    你的任务是分析用户的诉求，并制定一步一步的工具调用计划。

    【当前全局状态】
    用户原始诉求：{user_input}
    用户最新反馈/修改意见：{human_feedback}
    已收集的草稿本记忆：{context_str}

    【可用工具库】
    1. ask_human_for_clarification(question, reason) - 当核心主题宽泛，或需确认参数时必须调用。
    2. web_search_tool(query) - 查最新网络资料。
    3. rag_search_tool(query, top_k) - 查本地知识库。
    4. analyze_multimodal_content(instruction) - 如果判定用户意图涉及图片/视觉，必须先调此工具看图。
    5. submit_outline_for_review(outline_json_str) - 收集完信息后，必须用它生成大纲给用户确认！
    6. generate_long_report_content(confirmed_outline_json) - 只有用户确认大纲后才能调，生成正文。

    【规划铁律】
    - 绝不要一次性乱写10个步骤！根据现有情报，只规划当前最需要的 1-2 步。
    - 发现情报不够 -> 规划 search 或 ask_human。
    - 发现情报齐了 -> 规划 submit_outline_for_review。
    - 不要编造数据，严格基于工具返回的草稿本记忆进行决策。
    """
    
    print("🧠 [Planner] 大脑正在深思熟虑中...")
    structured_llm = llm.with_structured_output(Plan)
    plan_output = structured_llm.invoke([
        SystemMessage(content=sys_prompt),
        HumanMessage(content="请根据当前情况输出你的执行计划。")
    ])
    
    # 将 Pydantic 对象转为字典存入 State
    steps = [step.dict() for step in plan_output.steps]
    for step in steps:
        step["status"] = "pending"
        
    print(f"🧠 [Planner] 制定了新计划，共 {len(steps)} 步。")
    
    # 状态变更为 executing，且步骤指针归零
    return {"plan": steps, "current_step_index": 0, "status": "executing", "human_feedback": ""}


# ==========================================
# 3. 节点 B：四肢 (Executor Node)
# ==========================================
def executor_node(state: ReportState) -> Dict:
    """四肢节点：一个无情的执行机器，只负责执行当前 Step 指定的 Tool。"""
    
    plan = state.get("plan", [])
    idx = state.get("current_step_index", 0)
    context = state.get("gathered_context", {})
    
    # 工具路由字典
    tools_map = {
        "ask_human_for_clarification": ask_human_for_clarification,
        "submit_outline_for_review": submit_outline_for_review,
        "analyze_multimodal_content": analyze_multimodal_content,
        "web_search_tool": web_search_tool,
        "rag_search_tool": rag_search_tool,
        "generate_long_report_content": generate_long_report_content
    }
    
    step = plan[idx]
    tool_name = step["tool_name"]
    tool_args = step["tool_args"]
    
    print(f"🦾 [Executor] 正在执行步骤 {idx+1}: 调用 {tool_name} 工具...")
    
    try:
        tool_func = tools_map.get(tool_name)
        if not tool_func:
            raise ValueError(f"不存在的工具: {tool_name}")
            
        # 执行工具！
        result = tool_func.invoke(tool_args)
        
        # 判断是否触发了挂起护栏
        new_status = "executing"
        if tool_name in ["ask_human_for_clarification", "submit_outline_for_review"]:
            new_status = "awaiting_human" # 触发挂起！
            
    except Exception as e:
        result = f"Error 执行失败: {str(e)}"
        new_status = "replanning" # 执行出错，打回大脑重新规划
        print(f"❌ [Executor] 工具执行失败: {result}")
        
    # 忠实记录执行结果到草稿本
    context[f"step_{idx+1}_{tool_name}_result"] = result
    plan[idx]["status"] = "completed"
    plan[idx]["observation"] = result
    
    return {
        "gathered_context": context,
        "plan": plan,
        "current_step_index": idx + 1,
        "status": new_status
    }


# ==========================================
# 4. 路由边：控制流转 (Controller Edge)
# ==========================================
def controller_edge(state: ReportState) -> Literal["executor", "planner", "__end__"]:
    """红绿灯：根据当前状态决定去向。"""
    status = state.get("status")
    
    if status == "awaiting_human":
        # 🚨 极其关键：一旦遇到需要人类交互的工具，直接结束当前图的运行，返回给 service.py
        print("🚦 [Controller] 触发人工挂起 (Human-in-the-loop)，等待前端输入。")
        return "__end__"
        
    elif status == "replanning":
        # 工具报错了，回去找大脑重新想办法
        print("🚦 [Controller] 工具报错，回退给 Planner 重新规划。")
        return "planner"
        
    elif state.get("current_step_index", 0) >= len(state.get("plan", [])):
        # 当前计划的步骤全做完了，回去问问大脑还有没有下一步
        print("🚦 [Controller] 当前计划执行完毕，返回 Planner 检查是否彻底完工。")
        return "planner"
        
    else:
        # 计划还没做完，继续执行下一步
        return "executor"


# ==========================================
# 5. 编译万能生成引擎
# ==========================================
def build_universal_report_graph() -> StateGraph:
    workflow = StateGraph(ReportState)
    
    workflow.add_node("planner", planner_node)
    workflow.add_node("executor", executor_node)
    
    # 设定起点
    workflow.set_entry_point("planner")
    
    # Planner 永远把任务交给 Executor
    workflow.add_edge("planner", "executor")
    
    # Executor 做完后，走到十字路口看红绿灯
    workflow.add_conditional_edges("executor", controller_edge)
    
    return workflow.compile()
```

### 🏛️ 终极引擎架构图：真正的 Plan-Execute-Analyze 闭环

在新的引擎中，状态机循环是这样的：
1. **Planner（规划师）**：读取用户的输入和 `Skills (.md)`，生成一个待办清单（Plan）。
2. **Executor（执行者）**：其实是一个小型的“代理（Agent）”，它接手清单上的**第一个任务**，自主调用工具（RAG/Web/Ask）去完成它。
3. **Analyzer/Replanner（分析与重规划师）**：拿到执行结果后，进行**灵魂拷问**：*“这个结果解决了当前步骤吗？有没有偏离大纲要求？”* - 如果解决了：将任务从清单中划掉，更新进度。
   - 如果没解决/报错：**修改计划**，生成新的步骤。
   - 如果全部完成：输出最终结果。

```python
import operator
from typing import Annotated, List, Tuple, TypedDict, Union, Dict, Any
from pydantic import BaseModel, Field

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI

# 引入你的工具
from ..tools.search_tools import rag_search_tool, deep_research_tool
from ..tools.agent_tools import ask_human_for_clarification, submit_outline_for_review

# ==========================================
# 1. 引擎专属的全局状态 (State)
# ==========================================
class EngineState(TypedDict):
    user_input: str               # 用户的核心诉求
    skill_prompt: str             # 🚀 从 .md 文件读取的专属业务规则 (教案/报告等)
    
    plan: List[str]               # 当前的待办步骤清单 (动态增删)
    past_steps: Annotated[List[Tuple[str, str]], operator.add] # 历史记录：[(执行的步骤, 执行的结果)]
    
    final_response: str           # 最终输出的内容
    status: str                   # 系统状态: running, awaiting_human, finished

# ==========================================
# 2. Pydantic 结构体：强制大模型输出严谨格式
# ==========================================
class Plan(BaseModel):
    """规划师的输出结构"""
    steps: List[str] = Field(description="为了完成目标，接下来需要执行的详细步骤清单。")

class AnalyzeAndReplan(BaseModel):
    """分析师的输出结构：要么输出最终结果，要么更新计划"""
    response: str = Field(description="如果所有任务已完成，或者需要挂起等待用户，在这里输出回复给用户的话。否则为空。")
    status: str = Field(description="状态标记：'running', 'awaiting_human', 'finished'")
    updated_plan: List[str] = Field(description="如果任务未完成，根据刚才的执行结果，输出接下来还需要执行的步骤清单。")

# ==========================================
# 3. 核心节点 A：规划师 (Planner)
# ==========================================
def planner_node(state: EngineState, llm: ChatOpenAI):
    """首次接到任务时，制定初始计划"""
    print("🧠 [Planner] 正在根据 Skill 规则制定初始计划...")
    
    planner_prompt = ChatPromptTemplate.from_messages([
        ("system", """你是智能体执行中枢(Planner)。你的职责是读取【专属业务指令】，并将其拆解为执行计划。
        
        【专属业务指令 (Skill)】
        {skill_prompt}
        
        【要求】
        1. 严格遵守业务指令中的步骤顺序。
        2. 步骤必须具体，例如："调用 web_search 搜索 2024 AI 趋势" 或 "调用 ask_human 询问用户具体的章节"。
        """),
        ("user", "用户的请求是：{user_input}\n请输出你的初始执行计划。")
    ])
    
    planner = planner_prompt | llm.with_structured_output(Plan)
    result = planner.invoke({"skill_prompt": state["skill_prompt"], "user_input": state["user_input"]})
    
    print(f"📋 [Planner] 初始计划制定完毕：{result.steps}")
    return {"plan": result.steps, "status": "running"}

# ==========================================
# 4. 核心节点 B：执行者 (Executor - 实际上是一个 Tool Calling Agent)
# ==========================================
def executor_node(state: EngineState, llm: ChatOpenAI):
    """拿取计划清单的【第一项】去无情执行"""
    current_task = state["plan"][0]
    print(f"🦾 [Executor] 开始执行当前任务: {current_task}")
    
    # 挂载所有可用工具
    tools = [rag_search_tool, deep_research_tool, ask_human_for_clarification, submit_outline_for_review]
    agent = llm.bind_tools(tools)
    
    # 将过去的所有执行结果作为上下文喂给 Executor，防止它像无头苍蝇
    context_str = "\n".join([f"步骤: {step}\n结果: {res}" for step, res in state.get("past_steps", [])])
    
    prompt = f"""执行以下任务：{current_task}
    【之前的执行记录】:
    {context_str}
    
    请根据任务描述，调用合适的工具，并返回工具的执行结果总结。"""
    
    response = agent.invoke([HumanMessage(content=prompt)])
    
    # 这里为了演示，我们假设工具执行成功并返回了结果字符串。
    # 真实的工业代码中，这里会通过 ToolNode 执行工具，并将结果拼接。
    task_result = str(response.content) if response.content else f"已调用工具: {response.tool_calls}"
    
    print(f"✅ [Executor] 任务执行完毕。结果已记录。")
    return {"past_steps": [(current_task, task_result)]} # 将结果追加到历史记录中

# ==========================================
# 5. 核心节点 C：分析与重规划 (Analyzer / Replanner)
# ==========================================
def analyzer_node(state: EngineState, llm: ChatOpenAI):
    """【整个架构的灵魂】分析刚才的执行结果，决定下一步"""
    print("🕵️ [Analyzer] 正在分析执行结果并重规划...")
    
    analyzer_prompt = ChatPromptTemplate.from_messages([
        ("system", """你是智能体质量审计员(Analyzer)。
        
        【专属业务指令 (Skill)】
        {skill_prompt}
        
        【当前状态】
        用户目标: {user_input}
        原始计划: {plan}
        已完成的步骤与结果: {past_steps}
        
        【你的任务】
        仔细分析最后一步的执行结果：
        1. 如果工具报错或返回空（例如RAG没搜到），你必须生成**新的补救计划**（如改用 Web 搜索）。
        2. 如果调用了挂起工具（如 ask_human 或 submit_outline），你必须将 status 设置为 'awaiting_human'，并在 response 中输出给用户的话。
        3. 如果任务顺利完成，从原始计划中移除该步骤，并保留剩余步骤。
        4. 如果所有业务指令要求的步骤都已完成，将 status 设为 'finished'，在 response 输出最终结果。
        """),
    ])
    
    replanner = analyzer_prompt | llm.with_structured_output(AnalyzeAndReplan)
    result = replanner.invoke({
        "skill_prompt": state["skill_prompt"],
        "user_input": state["user_input"],
        "plan": state["plan"],
        "past_steps": "\n".join([f"- {s}: {r}" for s, r in state.get("past_steps", [])])
    })
    
    print(f"🔄 [Analyzer] 状态判定: {result.status}, 剩余计划: {result.updated_plan}")
    return {"plan": result.updated_plan, "final_response": result.response, "status": result.status}

# ==========================================
# 6. 图的流转逻辑 (Edges)
# ==========================================
def should_end(state: EngineState) -> str:
    """红绿灯决策"""
    if state["status"] == "awaiting_human":
        print("🚦 [Router] 触发人工介入，引擎挂起。")
        return "end"
    elif state["status"] == "finished":
        print("🚦 [Router] 任务彻底完成。")
        return "end"
    else:
        print("🚦 [Router] 计划未完成，继续执行下一步。")
        return "continue"

# ==========================================
# 7. 拼装引擎大图
# ==========================================
def build_universal_engine(llm: ChatOpenAI):
    workflow = StateGraph(EngineState)
    
    # 使用 functools.partial 注入 llm 依赖
    from functools import partial
    workflow.add_node("planner", partial(planner_node, llm=llm))
    workflow.add_node("executor", partial(executor_node, llm=llm))
    workflow.add_node("analyzer", partial(analyzer_node, llm=llm))
    
    workflow.set_entry_point("planner")
    
    workflow.add_edge("planner", "executor")
    workflow.add_edge("executor", "analyzer")
    
    # Analyzer 决定是结束、挂起，还是继续执行更新后的 Plan
    workflow.add_conditional_edges(
        "analyzer",
        should_end,
        {
            "continue": "executor",
            "end": END
        }
    )
    
    return workflow.compile()
```

### 💡 为什么这份 Skills 如此强大？（原理解析）

你仔细观察这份文档，它完美利用了我们刚才写的 `universal_engine.py` 的特性：

#### 1. 教 Planner 怎么做计划 (SOP 的力量)

> *“上一步搜不到东西。不行，不能直接出大纲，必须补救。我生成新的 Plan：`[{tool_name: web_search_tool, tool_args: {query: "西游记 孙悟空 人物分析"}}]`”*
**系统自动完成了容错降级！**

#### 3. 完美实现 Human-in-the-loop (挂起)
我们在 **“阶段 3”** 里给 Analyzer 下了死命令：只要调用了 `submit_outline`，状态必须切为 `awaiting_human`。这就确保了引擎每次走到出大纲的节点，都会乖乖停下来，绝对不会“脱缰”直接把长文写出来。

### 🎬 场景设定

### 🚪 第一阶段：前台接入与灵魂注入 (Gateway & Injection)

1. **意图路由 (`service.py`)**：
   - 接收到用户的文字 + 图片。
   - 极轻量的 `IntentRouter` 判断意图为 `generate_report`。
2. **装载“游戏卡带” (Skill Injection)**：
   - `service.py` 从本地读取 `.cursor/skills/edu-report-agent.md`。
   - 初始化 `EngineState`（全新状态机字典），将这段 Markdown 文本原封不动地塞进 `skill_prompt` 变量中。
3. **点火启动 (Graph Invoke)**：
   - `service.py` 调用万能引擎图：`universal_engine.invoke(state)`。

---

### 🧠 第二阶段：初始规划与多模态感知 (Plan & Vision)

4. **进入 Planner 节点 (大脑)**：
   - Planner 读取全局状态。
   - **思考过程**：*“我读了 Skill 的 SOP，第一步是信息收集。我发现用户上传了图片！但我纯文本大脑看不见。我必须先调工具。”*
   - **输出 Plan**：
     `[{"tool": "analyze_multimodal_content", "args": {"instruction": "提取关系图中的人物核心特征"}}]`
5. **进入 Executor 节点 (四肢)**：
   - 取出 Plan 的第一项，调用底层的 Qwen 视觉模型。
   - Qwen 返回结果：“图中显示孙悟空与唐僧存在权威冲突，具有反抗精神...”。
   - 将结果写入 `gathered_context`（草稿本记忆）。
6. **进入 Analyzer 节点 (复盘)**：
   - **思考过程**：*“看图任务圆满完成，图片信息已入库。目前信息足够生成大纲了吗？不，SOP 规定必须有明确的长度和深度要求。”*
   - **更新 Plan**：
     `[{"tool": "ask_human_for_clarification", "args": {"question": "孙悟空的反抗精神是个好切口！请问报告需要多长篇幅？深度按研报级可以吗？"}}]`

---

### ⏸️ 第三阶段：状态挂起与人类介入 (Human-in-the-loop 1)

7. **进入 Executor 节点**：
   - 执行 `ask_human_for_clarification` 工具。
8. **进入 Analyzer 节点**：
   - **检测到特殊工具**：*“警报！刚才调用了人类互动工具。”*
   - **动作**：将状态 `status` 变更为 `awaiting_human`，将要问的话写入 `final_response`。
9. **图流转红绿灯 (Controller Edge)**：
   - 看到 `awaiting_human` 标志，直接执行 `return END`。
   - **底层引擎物理休眠！**
10. **前端展现**：
    - 用户在界面上看到系统发来的问题：“孙悟空的反抗精神是个好切口！请问报告需要多长篇幅？...”
    - 用户回复：“按短篇幅写，通俗点。”

---

### 🔍 第四阶段：唤醒与外脑检索 (Resume & Research)

11. **重新点火 (`service.py`)**：
    - 带着用户的最新回复（`human_feedback`），再次调用 `universal_engine.invoke(state)`，引擎从沉睡中苏醒，直接进入 Planner。
12. **进入 Planner 节点**：
    - **思考过程**：*“用户要求短篇幅、通俗。现在主题、切口、格式全齐了。根据 Skill SOP 的阶段 2，对于专业分析，我需要外部知识支撑。”*
    - **输出 Plan**：
      `[{"tool": "web_search_tool", "args": {"query": "西游记 孙悟空 反抗精神 现代解读"}}]`
13. **进入 Executor 节点**：
    - 执行网页搜索。
    - **【触发极端 Edge Case：断网或搜不到】**：假设搜出来的全是垃圾广告。
14. **进入 Analyzer 节点 (容错自愈启动)**：
    - **思考过程**：*“上一步搜索结果毫无价值。SOP 说绝对不能凭空捏造。我必须换词重搜。”*
    - **更新 Plan**：
      `[{"tool": "rag_search_tool", "args": {"query": "西游记原著 孙悟空 性格"}}]`（从查全网降级为查本地库）。
    - 循环回 Executor 重新查，直到拿到有效资料放入草稿本。

---

### 📝 第五阶段：出大纲与二次挂起 (Outline Review)

15. **进入 Analyzer 节点**：
    - **思考过程**：*“资料搜齐了。进入 Skill SOP 的阶段 3。我必须生成大纲给用户看。”*
    - **更新 Plan**：
      `[{"tool": "submit_outline_for_review", "args": {"outline_json_str": "{...}"}}]`
16. **进入 Executor 节点**：
    - 执行大纲提交工具。
17. **进入 Analyzer 节点**：
    - 发现大纲已提交，状态再次切为 `awaiting_human`。图再次 `END` 挂起。
18. **前端展现**：
    - 侧边栏弹出 AST 大纲树。
    - 用户不满意，发送指令：“把第二章删掉。”

### 🚀 第六阶段：精准修改与终极生成 (Patch & Generate)

19. **最终苏醒 (`service.py`)**：
    - 用户修改指令传入引擎，唤醒 Planner。
20. **进入 Planner 节点**：
    - **思考过程**：*“用户要求删第二章。我这就修改内存里的 AST JSON 草稿。修改完毕。SOP 阶段 4 说，大纲确认后，可以开始写正文了。”*
    - **输出 Plan**：
      `[{"tool": "generate_long_report_content", "args": {"confirmed_outline_json": "{最新大纲}"}}]`
21. **进入 Executor 节点**：
    - 调用长文生成大杀器。
    - 工具内部启动纯 Python 的“按章循环”逻辑，耗时 30 秒，最终拼装出 3000 字长文。
22. **进入 Analyzer 节点**：
    - **思考过程**：*“正文生成完毕！SOP 规定的所有流程已彻底走完。”*
    - **动作**：状态切为 `finished`。
23. **图彻底结束**：
    - 返回完整的 Markdown 报告。
