# 深度搜索超时问题诊断

## 问题现象

1. ✅ API服务可以启动
2. ❌ 深度搜索API请求超时（即使180秒）
3. ❌ 完整流程请求超时（即使600秒）

## 可能原因

### 1. Agent执行时间过长
- Agent的递归限制是49步，可能执行时间很长
- 每次工具调用（web_search）可能需要10-30秒
- 多次工具调用累积时间可能超过HTTP超时

### 2. 深度搜索函数本身卡住
- LLM响应慢
- 结构化输出失败导致重试
- 工具调用失败导致重试

### 3. 服务端没有正确响应
- FastAPI可能没有正确处理长时间请求
- 需要检查服务端日志

## 诊断步骤

### 步骤1: 直接测试深度搜索函数（不通过API）

```powershell
cd D:\Edu_AI_1\EduAgent
python test_deepsearch_direct.py
```

这会直接调用 `deepsearch_large_llm()` 函数，不经过HTTP，可以看到：
- 是否真的卡住
- 卡在哪个步骤
- 实际执行时间

### 步骤2: 检查服务端日志

在运行API的服务端终端中，应该能看到：
- `[API] 开始处理请求...`
- `[API] 步骤1/4: 开始深度搜索...`
- 如果看不到这些日志，说明请求没有到达服务端

### 步骤3: 测试简单的深度搜索API

```powershell
# 测试原有的深度搜索API（不爬取）
python -c "import requests; r=requests.post('http://127.0.0.1:8848/agent/deepsearch', params={'query': '测试'}, timeout=300); print(r.json())"
```

## 解决方案

### 方案1: 增加HTTP超时时间（临时）

修改测试脚本的超时时间到更长（如15分钟）

### 方案2: 优化深度搜索（推荐）

1. 减少递归限制（从49改为20）
2. 添加Agent执行超时控制
3. 优化工具调用超时

### 方案3: 改为异步处理

将深度搜索改为异步任务，立即返回任务ID，客户端轮询结果

## 快速诊断命令
