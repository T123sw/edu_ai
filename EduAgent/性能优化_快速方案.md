# 深度搜索性能优化 - 快速方案

## 问题

深度搜索耗时过长（690秒），主要原因是：
1. SearxNG全部失败，每次尝试都浪费10-20秒
2. HTML解析可能失败，导致Agent不断重试
3. Agent递归限制过大，执行步骤过多

## 已实施的优化

### ✅ 1. 跳过SearxNG，直接使用HTML解析

**修改**: `web_search` 函数直接使用HTML解析，跳过SearxNG尝试

**效果**: 
- 节省每次搜索10-20秒的SearxNG尝试时间
- 直接使用稳定的HTML解析

### ✅ 2. 优化HTML解析逻辑

**改进**:
- 增强DuckDuckGo选择器（尝试更多变体）
- 添加URL去重逻辑
- 优化Bing解析逻辑

### ✅ 3. 减少Agent递归限制

**修改**: 从20减少到10

**效果**: 
- 减少Agent执行步骤
- 加快完成任务

### ✅ 4. 优化Agent Prompt

**改进**: 
- 明确指示"尽快完成任务"
- 限制搜索次数（最多2-3次）
- 减少重复搜索

### ✅ 5. 减少超时时间

**修改**: 
- web_search超时从15秒减少到12秒
- search函数超时从12秒减少到10秒

**效果**: 加快失败回退速度

## 预期性能改善

### 优化前
- 每次web_search: 10-20秒（尝试SearxNG失败）
- Agent递归: 20步
- 总耗时: 690秒（11.5分钟）

### 优化后预期
- 每次web_search: 3-5秒（直接HTML解析）
- Agent递归: 10步
- 总耗时: **150-250秒（2.5-4分钟）**

**改善幅度**: 减少60-70%

## 工作流程

### 新的流程

```
1. web_search被调用
   ↓
2. 直接使用HTML解析（跳过SearxNG）
   ↓
3. 优先DuckDuckGo HTML解析
   ↓ 成功
4. 返回结果（3-5秒）
```

### 如果DuckDuckGo失败

```
1. DuckDuckGo HTML解析失败
   ↓
2. 尝试Bing HTML解析
   ↓ 成功
3. 返回结果（3-5秒）
```
